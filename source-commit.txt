    ci: accept broker request v2 frames in the #1162 slice consumers
    
    #881-C (#1878) grew BqBrokerRequest from 176 to 184 bytes, but the hosted
    broker evidence validator, which the per-activation entry consumer reuses,
    still required recv == 176. Every v2 REQUEST record is therefore refused:
    replaying run 36635011178's two real records gives "parsed request has wrong
    frame size". The validator now requires REQUEST_FRAME_BYTES (184); its
    frozen producer capture is normalized to the v2 size like its pid and uid,
    and the version-1 size is a new negative case. The slice's failure-path
    broker-state probe also built a version-1 request, so it always printed
    request=0 state=0; it now uses BQ_BROKER_VERSION.
