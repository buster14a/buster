## Reading this table

`supported` has positive evidence, `partial` has bounded evidence and a note, `unsupported-diagnostic` records an explicit rejection, and `not-applicable` marks a separate boundary. `unknown` is not a pass. Evidence levels: `validate` → Parse/validate; `encode` → Exact encode; `object-link` → Object/link; `oracle` → Independent oracle; `execute` → Executed semantics; `integration` → Self-host/real project.

Evidence marked **requires X** depends on tool X. If X is missing, a `skip` requirement means the evidence is skipped, not passed. A `fail` requirement records a test failure. Requirements: `node` (missing: skip): Node.js with WebAssembly support on PATH; `clang` (missing: skip): Clang on PATH as the independent LLVM bitcode consumer; `gcc-and-clang` (missing: fail): Both GCC and Clang on PATH for the Linux scalar ABI oracle (mandatory on supported Linux); `gpu-toolchains` (missing: fail): Pinned toolchains for the selected profile in .github/workflows/gpu-toolchains.yml; an omitted profile reports SKIP_NOT_CONFIGURED and provides no evidence; `clang-native-reference` (missing: fail): Clang on PATH as an independent native reference compiler and link driver; a missing clang records a failure; `gcc-or-clang-tls` (missing: skip): GCC and/or Clang on PATH to build foreign initial-exec TLS objects; each missing compiler is skipped with a message, so with neither present no foreign evidence is produced; `host-c-compiler` (missing: skip): A configured non-MSVC BUSTER_HOST_C_COMPILER on a matching native host (x86-64 Linux/macOS, or AArch64) acting as the independent caller/callee and link driver. When none is configured, or it is MSVC, the leg is compiled out and provides no oracle/execute evidence; a configured compiler whose compile, link or run fails records a failure.; `linux-bpf-kernel` (missing: skip): Linux kernel that permits BPF_PROG_LOAD/BPF_PROG_TEST_RUN of a sleepable BPF_PROG_TYPE_SYSCALL program (Linux 5.14+, CAP_BPF+CAP_PERFMON or root). Codegen fixtures report 'unavailable, VM only' and still pass without it. The Linux x86-64 CI ebpf_kernel step (tools/ci_ebpf_kernel_oracle.py) turns unavailability into a failure.; `uefi-firmware` (missing: fail): Pinned QEMU 8.2.2 (qemu-system-x86_64, qemu-system-aarch64) and EDK2 2024.02 OVMF/AAVMF code and variable images with matching SHA-256, plus sha256sum on PATH, as installed by the UEFI firmware boot CI job; absent prerequisites print status=unavailable runtime_validated=0 and fail test_uefi.

A registered target or emitted bytes are not a support claim. Direct code generation and external GPU orchestration are separate rows.
