## Ownership and behavior

`IrType.abi` previously pointed to an 848-byte `IrTypeAbi` containing every
convention and use. Moving the original inline object behind a pointer had
already reduced the type row, but native preparation still allocated/zeroed
that object and computed argument/result decomposition for every resolved type.
Type clones also had to remember to clear a copied mutable ABI pointer.

The type row now contains no ABI cache and shrinks from 136 to 128 bytes on
this 64-bit host. Explicit `IrAbiContext` objects own one convention each;
independent contexts can share immutable language types. The existing
`ir_type_abi_value` service selects a context and preserves every consumer's
API, including the aggregate LLVM queries proposed by open PR #250. Its
classification algorithms are unchanged. `IrTypeLayout.abi_class` remains a
legacy descriptive layout field; it is neither read nor mutated by ABI
classification.

One context has 64-type pages per ABI use, each 3,592 bytes including its
resolution mask. Argument and variadic use share storage except for Windows
AArch64, preserving the previous classification rule. Payloads are initialized
before their resolution bits. New ids work within the type table's fixed
capacity; published immutable tables with count but zero builder capacity work
too. Unresolved layouts are not cached. An explicit invalidation operation
clears all convention facts after a layout change, including aggregates that
contain the changed type.

Native preparation reserves page storage before opening code-buffer retry
checkpoints. It reserves the default convention, explicit SysV/Win64 function
conventions, and contexts already requested during frontend lowering. Later
queries classify lazily without retaining allocations from a discarded retry.
The type table cannot grow inside that checkpoint. Consumers that never query
native ABI data do not create extra target contexts.

## Exact storage and query measurements

The existing 23-type scalar/aggregate test corpus needs 19,504 bytes of old
all-convention ABI objects. One new SysV context uses 7,200 bytes: two 3,592-byte
pages plus two eight-byte directory entries, a 63.1% reduction. Allocation count
for that cache falls from 23 per-type objects to four allocations (two pages,
two directories). Occupied language type rows fall from 3,128 to 2,944 bytes.
Arena headers, reserve rounding and OS page overhead are outside those counts.
Large active-convention tables have much smaller tail overhead: one complete
64-type argument/result tile occupies 7,184 payload/mask bytes plus its directory
entries, versus 54,272 bytes for the old 64 all-convention objects.

The opt-in `BUSTER_ABI_CACHE_BENCH` uses this corpus and the unchanged uncached
classifier. A representative Release run measured 60 ns reservation, 2,644 ns
for 46 cold classifications, 1,424,633 ns for 188,416 warm queries, and
4,420,751 ns for the same number of uncached queries. The 188,416 warm queries
caused zero new classifications: measured hit rate 100%. These are a small
service microbenchmark, not an old-cache/new-cache throughput comparison or a
claim about total compiler speed. Timings never gate tests.

## Same-source compiler comparison

Both compiler executables were built with genuine Clang 21.1.8 through the
TCC-bootstrapped project driver, using `./build.sh generate --linker DEFAULT`.
Both compiled frozen main source with identical flags and target. Other agents
paused CPU-heavy work during this local measurement window. The shared virtual
Zen 4 host remains noisy and was not core-pinned. Hardware cycles, instructions,
branches, branch misses and cache misses are unavailable in this environment.
No Zen 5 result is claimed.

are retained. The three source cases are the complete frozen compiler unity
translation unit, 5,000 simple record declarations plus `main`, and

## Validation and reproduction

From the repository root, with the documented toolchain on `PATH`:

```sh
./build.sh generate --linker DEFAULT
./build.sh test_self_host --config Release
BUSTER_ABI_CACHE_BENCH=1 ./build.sh build --config Release -t test_all
./build.sh test_mode_matrix --config Release
python tools/new_audit.py --check
```

The final Release suite passes 398,221/398,221 assertions and 40/40 modules
with the optional benchmark assertion enabled (398,220 without it). The mode
matrix passes all 24 legs: four native execution legs and twenty external
assembler/disassembler oracle legs. The final self-host fixed point produces
39,191,336 byte-identical stage-1/stage-2 bytes, with MIR_STACK and canonical
NONE gates also passing. Stage times were 2.357099 s and 12.071504 s; the source
of these stages differs from the frozen-input A/B case and those numbers are
not a performance comparison to main.

The audit-index check reports one pre-existing historical format error:
`2026-08-24T131821Z` does not open with its id and a parenthetical. The identical
check on unchanged main reports the same error; this change leaves that older
audit untouched.

Regression coverage includes all five conventions and three use classes over
the existing scalar/aggregate corpus, independent contexts sharing types,
different pools with identical ids, zero-capacity published type tables,
unresolved-then-resolved layouts, page growth, explicit mixed conventions,
allocation-free cache fills across retry rewinds, and dependent aggregate
invalidation. The expected bytes come directly from the unchanged uncached
classifier, bypassing the new cache.

The [focused sanitizer harness](2026-09-07T231507Z-sanitizer.c) includes the real
production IR/cache/arena implementation. It checks 11,700 queries across
260 types, five conventions, three uses and three retry passes, then tests
invalidation. Build and run it independently:

```sh
clang -Isrc -O1 -g -Werror -fwrapv -fno-strict-aliasing -funsigned-char -ffunction-sections -fdata-sections -fsanitize=address,undefined -fno-sanitize-recover=all -fno-omit-frame-pointer -Wl,--gc-sections docs/performance-audits/2026-09-07T231507Z-sanitizer.c -lm -lpthread -ldl -o /tmp/buster-abi-sanitizer
ASAN_OPTIONS=halt_on_error=1:detect_leaks=0 UBSAN_OPTIONS=halt_on_error=1 /tmp/buster-abi-sanitizer
python docs/performance-audits/2026-09-07T231507Z-compare.py /path/to/baseline/ide /path/to/candidate/ide /path/to/frozen/main /tmp/buster-abi-compare
```

ASan/UBSan pass the focused harness. LeakSanitizer's first attempt fails because
this environment cannot open `/proc/<pid>/task`; the successful repetition
disables only leak detection, with address/undefined checks still fatal. A full
sanitized compiler/configuration matrix and non-Linux host execution were not
run locally. CI must validate the submitted revision on supported hosts.
