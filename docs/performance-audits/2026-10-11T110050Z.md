## Workload

Every arm compiles the same input, the base revision's unity self-host source,
from the base checkout:

```sh
ide cc -Isrc -I<base build>/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -fsyntax-only \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

Four arms:
- A: base, default flags;
- B: base with `-fc-ast-pilot`;
- C: candidate with `-fc-ast-pilot`;
- D: candidate, default flags.

C − B is the change's effect on the pilot. D − A is the default path, also
measured on `-c` (`-g0`, the same input with `-c -o`). Each arm also wrote
`-g0` and `-g` objects for comparison. Callgrind ran with
`--cache-sim=no --branch-sim=no`.

## Census that chose the design

On this base, `c_ast_types_type_body` costs 329.24 M Ir inclusive, 3.50% of
the pilot's compile. Bodies account for 276.39 M (6,639 calls) and
initializers for 52.85 M (2,725 calls). Its named callees take only 92 M of
that. The other 237 M is the loop and the rules inlined into it.

**Per rule.** A throwaway build kept the span and every rule out of line
(not committed; it inflates the pass to 415 M, so only the shape is used):
- the loop visits 1,927,177 nodes, of which 1,257,063 are expression nodes it
  types and 670,114 are not;
- `c_ast_types_span` took 101 M. Only 648,398 of the typed nodes need its
  rules. The other 608,665 are single-token leaves whose span is their token;
- by count, the rules are:
  - identifiers 417,230;
  - number and character literals 191,435;
  - binary operators 157,172;
  - members 119,436;
  - calls 51,444;
  - assignments 43,090;
  - `sizeof`/`alignof` 42,043;
  - subscripts 40,214;
  - casts 34,540;
  - unary operators 16,635;
  - compound literals 15,435;
  - `&` 14,547;
  - conditionals 10,415;
- the literal rule called the machine's `c_parse_expression_leaf_without_cast`
  191,435 times, at about 105 Ir each (20.0 M). It takes the whole
  `CPreprocessResult` by value. For a cached integer fact, its answer is one
  table read;
- `c_parse_expression_arithmetic_type` took 13.2 M over 67,387 calls;
- `c_ast_types_binary_safe` evaluated every operator test eagerly, even for
  two integer operands, which pass every one of them.

**Per instruction.** On the inlined base binary, the pass's self cost was
spread thin. The loop reloaded the body's arrays and bounds from the stack
after every rule, because the rules write through the body pointer.

**The member memo is not the limit.** A second throwaway census counted the
47,237 member lookups the memo misses. Only 6,417 of them repeat a pair
already looked up in the same pass. A larger memo could save about 2 M at
most, so it is not part of this change.

**Design steps.** Each step's pass cost, inclusive (diagnostic, before the
budgets):

| Step | `c_ast_types_type_body` | Compile |
| --- | ---: | ---: |
| B, base | 329.24 M | 9,394.46 M |
| one class load per node; leaf spans without the span rules; integer literals from their cached fact | 312.96 M | 9,378.06 M |
| two loops: leaves and spans, then the operator rules over a list | 308.52 M | 9,374.42 M |
| operator spans moved into the second loop | 298.09 M | 9,363.99 M |
| arithmetic memo held in the region struct | 293.89 M | 9,379.16 M |
| memos moved to reserved scratch; `(` tested after the closer in `c_ast_types_expand` | 294.08 M | 9,360.09 M |
| the closer test reverted; integer fast path in `c_ast_types_binary_safe` | 274.25 M | 9,340.26 M |

Two steps were rejected:
- **The memo in the struct.** Once the memos were inside `CAstTypeBody`, the
  struct passed 2 KiB. The compound literal that creates a region then cleared
  it with glibc's `rep stosb`, which Callgrind counts per byte, so `memset`
  rose by 19.9 M. The memos now live in their own reserved scratch, cleared
  once per pass.
- **Testing the closer first.** In `c_ast_types_expand`, testing the closer
  before the `(` token cost about 3 M more, so it was reverted.

## The change

Each item is exact: every node keeps the type and flags it had.
- **One table load classifies a node.** `c_ast_types_kind_classes` has a row
  for every `u8` kind, so the load needs no bounds check. It separates
  untyped kinds, the three single-token leaves that have rules, the two
  leaves that have none (`true`/`false`, `nullptr`), and every other
  expression kind.
- **Two loops.**
  - The first loop gives each single-token leaf the span rule's answer,
    `[token, token + 1)`, links it into its start chain and runs its rule.
    It lists every other expression node.
  - The second loop takes that list in index order: it computes each node's
    span from its operands' spans, links it, and runs its rule.
  - Children still come before parents. A leaf's rule reads no other node.
  - The start chains end up as they were. A node that starts at a leaf's
    token contains the leaf, so it follows the leaf in index order, and it is
    linked after the leaf in either order.
  - The loops keep the arrays and bounds in locals.
  - The accepted count is taken in one scan of the flags.
- **Cached integer literals.** When the syntax pass cached a non-floating
  literal's kind for this data model (`c_number_fact`,
  `c_number_fact_kind`), the leaf's first answer is the published row of that
  kind. The pass reads it directly. Every other literal still calls the leaf.
- **An arithmetic memo (`c_ast_types_arithmetic`).** It has 64
  direct-mapped entries, keyed by both operand rows and both bit-field widths.
  Within a pass, `c_parse_expression_arithmetic_type` reads only the rows'
  kinds and returns a published scalar row. The pass appends no row, so the
  memo is exact. It answered 52,867 of 67,387 calls.
- **The memos live outside the region struct.** They are reserved in scratch
  beside the per-node arrays, so creating a region no longer clears them. The
  pass still clears them once.
- **Two integer operands are settled at once.** `c_ast_types_binary_safe`
  returns safe before its other tests, which such operands always pass: they
  are not aggregates, `void`, `nullptr`, complex, vectors or pointers.

## Validation on `3d7129f7`

- Tests-on builds, `ide test --module=c_ast_tests,c_frontend_tests,compiler_driver_tests`:
  1,656,679 of 1,656,679 pass in Release and in Debug. With the probe cases
  below (`8b597ab8`), 1,656,694 of 1,656,694 pass in both.
  - The two `TEST_PREREQUISITE_FAILURE` lines are GCC reference controls for
    `-std=gnu23`, which this container's GCC does not accept. They are
    prerequisites, not test failures, and they are the same in both
    configurations.
- `test_self_host --config Release` reaches its fixed point at 40,881,552
  bytes. Base `a6705764` reaches its own at 40,886,472 bytes in the same
  container.
- `source_size --base a6705764`: production +8,291 bytes, within the
  32,768-byte limit.
- Three probe cases were added after the measured runs. They are in tests
  only, so the tests-off arms are unaffected:
  - two whose arithmetic memo keys differ only in bit-field widths, one in
    each order, over one typedef row;
  - one whose key differs only in the right operand's row.

  Two mutations were tried, and both were reverted. With the widths dropped
  from the memo's key and comparison, the two width cases fail, checked and
  unchecked, and the corpus gate does not catch it. With the right row
  dropped, the right-row case and the corpus gate both fail. Dropping the
  widths from the comparison alone is not caught, because the key still
  hashes them, so the entries rarely meet.
- Not run here:
  - the sanitizer tree;
  - the Clang analyzer;
  - the full `test_all`.

## Reading

- The eager pass is 16.7% cheaper, and the pilot's compile 0.58% cheaper, on
  this host's Callgrind counts. No answer changed, and the default path's
  work did not change.
- Organizing the loop did most of it. Splitting leaves from operators and
  reading cached literal facts took the pass from 329 M to 298 M. The
  integer fast path and the arithmetic memo took it the rest of the way.
- What is left is spread across the rules. `c_ast_types_member` costs
  32.4 M, about half of it in `c_parse_member_type`'s first lookups of each
  pair. `c_ast_types_type_name` costs 14.2 M. The operator spans cost about
  30 M with `c_ast_types_expand`.
- Hosted wall time was not measured. These counts are diagnostic, and no
  9700X comparison was requested, so performance validation is incomplete
  (#2761). The hook stays opt-in.
