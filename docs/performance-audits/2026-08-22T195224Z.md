Three restructurings, one commit, all inside the acyclic direct-run rule:

- `c_ir_lower_expression_core_step` direct-runs the `PLACE` children of its
  four update/identifier sites and consumes a completed place in place,
  through two extracted resume helpers
  (`c_ir_lower_expression_core_consume_place`,
  `c_ir_lower_expression_core_root_update_resume`) that the loop arms now
  share with the push sites.
- `c_ir_lower_body_step` self-loops: a yielded child whose kind is in the
  direct-run set (`EXPRESSION`, `BODY_ASSIGNMENT_STATEMENT`, `CONDITION`,
  `COMPOUND_LITERAL`) runs immediately, and a completion continues the
  statement walk without a dispatch round trip.
- `c_ir_lower_assignment_statement_step` becomes a self-loop over a bool
  `advance`: the request helpers run the pushed `EXPRESSION`/`PLACE` child
  off the loop and report a completion, which re-enters the `CHILD` arm
  directly.

A suspension always resumes through the loop unchanged, so the resumable
shape is untouched.  The direct-run edge set stays acyclic at static depth
six (`BODY -> BODY_ASSIGNMENT_STATEMENT -> EXPRESSION -> LOGICAL_VALUE` or
`CONDITION -> CONDITION_LEAF`, `-> EXPRESSION_CORE -> PLACE` or a prepare
step), and the `2026-08-22T141319Z` boundary is untouched: the prepare
steps and `PREPARED_CALL` never direct-run the `EXPRESSION` children they
push — that cycle is what would recurse on the C stack.
