The issue's duplicated address-fact ownership remains real: both selectors
independently derive storage, field offsets, index scale, and index extension.
Its original x86 definition-chasing premise is partly obsolete: the current x86
selector already uses place kinds. AArch64 still follows definitions for these
facts and for scalar/aggregate loads and stores. The shared implementation removes
that duplication from both targets; the diagnostic counts below explicitly retain
the extra normalization work introduced on x86.

`MachineSelectionAddressCache` lazily allocates a 64-entry direct-mapped table
(4096 arena bytes at most) in each selection attempt. It performs no whole-function
prepass and expires with that attempt, after canonical IR validation. Iterative
normalization has a fixed 64-step bound. Facts carry base, index, scale, displacement,
symbol, alignment, exact expression identity, object identity, storage opcode,
and provenance flags. Both selectors consume the shared storage/field/index facts
and normalized constant-offset addresses. AArch64 memory helpers also consume the
cached place opcode. x86 reuses its existing type-class projection.

Only LOCAL/GLOBAL definitions establish object identity. Loads, casts, atomics,
block parameters, labels, and pointer/integer arithmetic stay opaque; the exact
expression identity preserves subobject and label distinctions. Multiple indices,
cache collisions, excessive depth, and displacement overflow fall back to an
already materialized expression. Global/function symbols retain their original
target materialization and TLS/GOT/relocation handling. No canonical IR mutation,
public `MachineFunction` layout change, or new scheduler alias claim is involved.
This keeps #40's earlier canonical transforms, #38's CFG publication, and #41's
later memory certification independent. The overlapping TLS implementation in
PR #438 was inspected; its global-address selectors and encoders are untouched.
