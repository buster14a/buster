## Census before the change

A throwaway build of the base (sha256 prefix `2132f6e47b6e510a`, not
committed) routed each machine call in `c_parse_type_name_specifiers` through
one no-inline wrapper per shape. The shape came from the tree:
- whether a `TYPE_NAME` begins at the run's first token;
- if so, what its `DECL_SPECIFIERS` hold.

this base.

## Negative and unproven parts

- **The failure path's two calls are unobservable on every input tried.** In
  the skip, `c_parse_type_identity_prepare` and the `typeof` aggregate
  definition never change a result. Earlier passes have already settled every
  identity answer and defined every `typeof` body in a skipped range.
  - `retries=0` on the self-host and in every probe, including file-scope
    initializers, static assertions and control-statement headers.
  - A mutation that dropped the identity prepare passed every test.
  - Both calls stay, about 1.9 M in C. The skip is then the machine's failure
    path rather than a claim that the path does nothing. Removing them is a
    separate decision that would need its own proof.
- **What the tests do catch.** A mutation that skipped type names whose lists
  are not word-only (`sizeof (struct S)`) failed three ways:
  - the case table;
  - corpus verify (the machine answered skipped runs);
  - the model differential (a type row missing).
- **Found in passing.** An enumerator whose `sizeof` operand defines an
  aggregate, such as `enum { E = sizeof(*(struct { int a; } *)0) };`, is
  rejected on the default path and the pilot alike, where GCC accepts it.
  This is outside this change; the evidence was added to #1258.

## What is left with the machine

- The 26 `input` runs here: type names whose list is not word-only (a tag,
  `typeof`, an attribute) or that are read with a machine frame open. The
  nested `c_parse_typed_constant` runs are of the second kind.
- File-scope tag definitions and their members: 46.5 M over 1,346 runs. A
  tree read would have to replay member rows and aggregate attributes in the
  machine's order.
- Declarator derivations, below any useful gate on this input.
- Casts and other type names typed in machine frames under expression
  queries: the typer's territory.

## Validation and limits

- Callgrind counts instructions, not time, on `-march=x86-64-v3` builds whose
  AVX-512 kernels are compiled out.
- One input, one host, single process, no pinning and no `perf` counters. Wall
  time was not measured; on this host it cannot resolve an effect of this size
  in the whole compile.
- No 9700X comparison is requested for this slice. Zen 5 validation stays
  **incomplete** (#2761), and the hook stays opt-in.
- Correctness of the measured candidate is in the pull request's validation
  record.
