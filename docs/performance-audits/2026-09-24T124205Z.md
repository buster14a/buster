## Decision

Keep a narrow traversal elimination for #1028: `c_parse_infer_initializer_array_count_core`
now computes each explicit frame's slot count once and reuses it for every element
and designator in that frame. On the frozen self-host unity compile it removes
~533 M retired user instructions in every mode, and the objects stay byte-identical.

## Hypothesis and producer/consumer map

In the local unity profile, ordinary compilation spent ~21 % of samples in
`c_parse_validate_lowering_constraints`. About 6.9 % of that was inclusive
in `c_parse_validate_initializer_shape`, mostly in
`c_parse_infer_initializer_array_count_core` (~6.2 %).

- **Producer:** `c_parse_initializer_type_slots(frame)`. It depends only on
  `frame->root`, `frame->type`, the type's layout or array bound, the scope and
  `machine->semantic_constant_queries`. For a non-inferred array bound it
  constant-evaluates the bound tokens again (`c_parse_typed_constant`).
- **Consumers:** the frame loop, once per initializer element, and
  `c_parse_initializer_designator`, once per positional designator step.
  Every element therefore re-folded the same array-bound expression.
  `int t[N] = {...}` with K elements folded `N` K times.
- **Lowering:** it does not consume this fact. Lowering has its own
  aggregate walk, which answers a different question (emission) and stays
  intact as the defensive check. This slice therefore removes repetition
  *inside* validation, not validation→lowering duplication. The alternatives
  below cover cross-phase reuse.

## Validity conditions of the reused fact

- **Source identity / lexical scope:** the frame belongs to a single
  initializer and inference call. The scope is a function parameter and is
  fixed for the call.
- **Target/data model:** a single call runs under one target. Target-dependent
  bounds (`sizeof(long)`) are evaluated in that target, and the test matrix covers
  LP64 and LLP64.
- **Type completion / packing:** `frame->type` is set when the frame is created
  and is never mutated afterwards (every construction site is a compound
  literal, so `slots_known` starts false). The member count and vector layout of
  a complete type cannot change during inference of its own initializer.
- **Evaluation context:** `semantic_constant_queries` is toggled only inside
  `c_parse_initializer_index`, which restores it before returning. The value is
  the same at every consumer.
- **Mutation:** the root frame returns `UINT64_MAX` without reading the bound
  it infers. Nested frames never have an incomplete bound.
- **Storage/lookup:** 9 bytes per frame in an array that already exists and is
  already bounded by the token span. The lookup is one branch. There is no new
  cache and no new lifetime, and nothing enters canonical IR.
- **Failure:** if the first computation fails, the function still returns
  false immediately, as before. Diagnostics are unchanged.

## Alternatives considered

- **Recomputation (base):** measured above.
- **Ordinary hoisting (this change):** the chosen option.
- **Reusing the checked source type in `c_parse_initializer_expression_constraint`
  for aggregate compatibility (narrow fact reuse):** a prototype changed the
  `.debug_info` output of the unity object (257c70 → 255bdf bytes, 39,333 →
  38,936 DWARF array types). It therefore does not preserve artifact
  equivalence without more work on query flags. It was rejected and not kept.
- **Cross-phase reuse of validation facts by lowering:** not attempted. Lowering
  must stay usable by direct callers and must not take frontend IDs, and the
  contract in `docs/agents/frontend/semantic-validation.md` keeps its defensive
  checks. No lowering consumer of this fact was found.

## Limitations

- These are not dedicated-hardware wall-time measurements. The 9700X
  confirmation is NOT RUN.
- The saving comes from repeated bound folding inside validation. It does not
  reduce the validation→lowering duplication that #860 introduced.
  Cross-phase reuse is still open under #1028.
