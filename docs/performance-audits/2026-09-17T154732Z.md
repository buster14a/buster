# Ext80 live-limb operations

This audit completes the census and measurement requirements of
[issue #561](https://github.com/buster14a/buster/issues/561) for the
implementation merged by
[PR #650](https://github.com/buster14a/buster/pull/650). The implementation
replaces whole-`CIrExt80Big` zeroing and copies with live-prefix operations. It
retains the 1,024-limb fixed capacity, stack storage, overflow refusals, false
returns, rounding behavior, and diagnostics.

## Revisions and method

- Baseline: `2507a4568e786777f98a92512c948ea1ed3a6b6b`.
- Candidate and frozen source tree: `095e9f9402ec0adef3380618c0a5f97a17387ef4`.
- Host: `Linux-7.0.0-1012-azure-x86_64-with-glibc2.43`.
- Toolchain: `Ubuntu clang version 21.1.8 (6ubuntu1)`; Python `3.14.4 (main, Jun 18 2026, 14:25:02) [GCC 15.2.0]`.
- Timing used independent, uninstrumented Release compilers. A separate
  instrumented candidate compiler collected the census and was never timed.
- Each workload had a preflight/warm-up followed by seven alternating
  baseline/candidate pairs. `/usr/bin/time` recorded wall time, user-plus-system
  CPU time, and peak RSS. Every pair compiled the same frozen source tree.

The compiler builds were:

```sh
clang -Isrc -Wall -Werror -Wno-unused-function \
  -Wno-unused-variable build.c -o .issue-561-build
.issue-561-build generate --ci --cc clang --linker DEFAULT
.issue-561-build build --config Release -t ide
```

The unity workload was:

```sh
build/Release/ide cc -Isrc -Ibuild/generated \
  -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 -g \
  -fsource-metrics=<metrics> src/buster/apps/ide/ide.c -lm -o <output>
```

The targeted workload compiled a deterministic source containing 4,096 decimal,
4,096 hexadecimal, and 1,024 tie-adjacent `long double` literals:

```sh
build/Release/ide cc -g0 -O0 -fsource-metrics=<metrics> \
  -c build/issue-561/float-heavy.c -o <output>
```
