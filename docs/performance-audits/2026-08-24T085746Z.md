`2026-08-24T085746Z` (Linux x86_64, Zen 4 7940HS; **a constant array bound is
not a variable-length array: the array-parameter layout stops emitting a
multiply of two constants into every entry block**).

A follow-up to `codegen: capture the canonical emitter's arguments at entry`,
which fixed the miscompile that interleaving caused. This entry removes the
interleaving itself, for the parameters that never needed it.

**Budgets before** (clang Release `ide`, unity stage-1 compile, `main` plus the
argument-capture commit): 9.642.941.200 instructions, 1.761.201.822 branches,
21,5 M branch misses, 3.423.860.570 L1d loads, 89,5 M L1d load misses.

**The finding.** `c_ir_generate`'s parameter loop treats every parameter written
with array syntax as needing a VLA layout, and the only escape is
`fixed_inner_array` — the adjusted type being a pointer *to an array*, which is
what a `u8 a[2][3]` becomes. A plain one-dimensional constant bound like
`u8 slots[2]` adjusts to `u8*`, misses that escape, and goes down
`c_ir_prepare_vla_layout`, which builds a CONSTANT element count, a CONSTANT
element size and a MULTIPLY of the two — into the entry block, between the
parameter homes. Both operands are known at compile time and the result,
`local->runtime_size`, is never read: `CIntegerIrLocal::runtime_size` is written
at both of its assignment sites and read at none, and
`c_ir_lower_expression_core_step`'s `sizeof` arm refuses suffix 0 for an
`is_vla_parameter` local on purpose, because `sizeof slots` is the pointer's.

The escape is now a second test beside `fixed_inner_array`: an array C type
reaches `c_type_ir_map` **only** when every one of its bounds is a constant
expression, so a mapped type in that loop is not a variable-length array at
all. The local stays unflagged and every consumer reaches the same answer
through the pointer type `local->type` already holds. This adds only the
one-dimensional case: a mapped array of two or more dimensions is a pointer to
a mapped array, hence `fixed_inner_array` above.

**The population, from a probe at the decision site.** The whole self-host unit
declares **17 array-syntax parameters** across 10 functions. **15 have constant
bounds** and are now skipped — `machine_x64_exact_gpr_variant_slots` (the
function whose miscompile started this), `link_x86_build_elf_entry_stub`,
`link_x86_build_pe_entry_stub`, `ir_system_v_abi_classes`,
`buster_x86_metadata_canonical_query` and
`buster_x86_metadata_coverage_canonical_query` (3 each),
`a64_typed_scalar_recipe_decode` (2), and three more with one each. The
remaining 2 are `main`'s `argv[]`/`envp[]`, whose bound is absent rather than
constant. Zero parameters in the unit hit `fixed_inner_array`, and zero are
genuine VLAs.

**Two leads left open, both larger than this one.**

- **A parameter's outermost product is dead in every case, not only the
  constant one.** `CIrVlaLayout::runtime_size` is `suffix_sizes[0]`, and its
  only readers are the automatic-declaration path's `ALLOCATE` operand
  (`c_ir_lower_automatic_declaration_step`) and the `sizeof` arm that refuses
  suffix 0 for parameters. So for `void f(long n, unsigned char a[n])` the
  `n * 1` multiply is emitted and discarded exactly as `slots[2]`'s was — it
  simply cannot be folded, so it costs generated code rather than compile time.
  Suppressing `suffix_sizes[0]` when `state->parameter` would take it, and the
  `vla_param` fixture is the guard that says whether the reasoning holds.
- **The absent bound.** `u8 a[]` has no constant to detect, so it keeps its
  layout and its one CONSTANT element size. Two sites in the self-host unit,
  both in `main`; worth about 18 K instructions by the per-site number, against
  a change that would alter the most load-bearing signature in the tree.
