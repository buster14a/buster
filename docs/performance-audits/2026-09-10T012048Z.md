## Population, ownership and deterministic assembly

`-fcompile-jobs=N` requests workers only for consecutive native C link inputs.
Default/API zero is one. Cap by logical CPUs and input population, and disable
nested fanout inside an embedding multi-lane caller. Objects, archives and
assembly remain ordered serial boundaries, including forced `-x c` inputs.
LLVM/GPU/Wasm/eBPF and other actions remain on their existing paths.

A cohort retains at most one full TU per active lane. Each stable slot owns an
explicit arena and diagnostic collector; TLS scratch is never a result carrier.
After `lane_run` joins, the original serial driver consumes slots in input order,
copies compact objects including initializer priorities, and releases the cohort.
The first input error wins; discard later completed diagnostics and clean every
unconsumed arena. No worker writes output files. Serial and single-threaded
builds invoke this same unit kernel. Compact object accumulation for linking is
unchanged; no extra whole-TU stream survives publication.

`compiler_parallel_prewarm` prepares both native families before workers start,
including all x86 forms/exact plans and AArch64 encoding/semantic tables. Both
are needed for later target-switching invocations with parked workers. This
full cold preparation is an opt-in cost. External lane owners must call it
before their own first gang. Ordinary serial prewarm/startup stays lightweight.

Existing SIMD consumers run unchanged inside each lane; there is no new ISA,
primitive, vector kernel, permutation/scatter stream, canonical/MIR row, or
function-level heuristic in this patch. No universal Zen 5 throughput premise
is assumed.

## Scheduling hypotheses, not accepted optimizations

| Question | Bounded choice / evidence still needed |
| --- | --- |
| Claims and grain | One TU per cohort slot; no second queued item exists, so an atomic claim counter cannot rebalance this cohort. More pending work needs measured dynamic claims plus bounded durable results. |
| Load balance | Large/unequal TUs can leave lanes idle at the cohort barrier. No adaptive policy or scaling benefit is claimed. |
| Locality | Compilation state stays private; ordered object copying remains in the caller. Caller-side arena retirement may affect reuse locality and needs measurement. |
| False sharing | Slots are written by distinct lanes, but are not padded speculatively. Task records contain cold result data; cache-line traffic and padding tradeoffs are unmeasured. |
| Memory | Full-TU count is bounded, not each TU's resident bytes. Automatic free-RAM/cgroup admission is absent. The virtual 32-GiB reservation is not physical memory. Default one worker avoids silently multiplying outer build budgets. |
| One worker / SIMD | Same unit algorithm; existing scalar/SIMD dispatch unchanged. Added publication/prewarm cost must be measured separately from multicore gains. |
| SMT / NUMA | Logical-CPU clamp does not identify physical cores or affinity/NUMA placement. No topology or exclusivity evidence is inferred. |

## Performance admission remains closed

The existing native harness is authoritative. Its current single-input object
workloads cannot certify multi-TU scaling by merely adding this flag; do not
invent a second measurement stack or pass single-input timings off as scaling.
Calling-thread allocation snapshots exclude worker bumps; the existing separate
exit census includes worker records with a different snapshot/teardown scope.

Before accepting a performance change: freeze identical inputs and output paths;
require exact output, unchanged portability and single-worker correctness;
compare one through available physical cores before SMT, then NUMA separately;
include serial prewarm, private allocation, cohort barriers, ordered copy and
teardown. Reuse the existing paired protocol with raw samples and uncertainty,
phase and whole-compiler times, input/output hashes, CPU/OS/compiler/flags,
affinity/SMT, work-normalized counters, peak RSS and text size. Predeclare the
memory/text/scaling budget for the actual representative corpus before running
that experiment. A bounded opt-in prototype alone does not satisfy admission.

build-time improvement is established. Unavailable values remain unavailable.
