## Implemented experiment

`build.c` builds the standalone native C utility through `bench_throughput`.
`bench_throughput_ci` builds two separately checked-out compiler revisions
sequentially with one build policy, then measures identical deterministic
inputs on that runner. Normal compiler builds preprocess allocation hooks away.
`BUSTER_BENCH_ALLOCATIONS=ON` enables separate, calling-thread arena request
counts and cumulative requested bytes. Those are not malloc totals or live RAM.

The six generated workload classes cover fresh-process tiny-file startup,
large single functions, many functions, large symbol tables, control flow and
backend/register pressure. Four allocator modes are separate series. Optional
frozen-source stage 1 and stage 2 experiments retain stage 2 == stage 3 fixed
point checks without changing the canonical own-source self-host gate.

All observations retain exact argv, source and output hashes, work counts,
wall/user/system time and OS child peak RSS. Separate PMU/arena replays cannot
contaminate guarded timing. Generic Linux user-space PMU events are explicitly
not a Zen 5 cache hierarchy or IBS measurement. Unsupported events are NA,
with errors/scheduling fractions retained, never synthetic zeroes.

The guard takes two fixed rounds of twenty adjacent, balanced-order A/B pairs
per case/mode. Each pair must cross both practical margins: 15% and 2 ms for
wall time; 20% and 16 MiB for peak RSS. An exact one-sided sign test uses
Bonferroni correction across cases and the two metrics. The same case/metric
must qualify in both rounds to fail. Broad intervals and single-round signals
are warnings, not claims of equivalence. Independent-pair assumptions and
shared-runner limitations are documented; no sample is trimmed or rerun until
it passes. Incomplete or corrupted evidence fails separately.

## Validation and a harness defect caught during validation

The initial invocation appended `-O0` after `-fregister-allocator=MODE`.
Buster's ordered option parser resets the allocator on `-O0`, so those early
runs exercised FAST even when their labels said otherwise. They are **not
four-mode evidence** and must not be used as such. The final command builder
places the selected allocator after all default and user optimization flags;
new tests cover all four modes at all three stage settings and prohibit the
conflicting `-fno-register-allocator` override.

After that repair, the complete smoke cross-product compiled successfully
using both the original and the uninstrumented patched compiler: six cases,
four actual modes, two rounds, one pair and one warmup per variant/case.
All repeated and A/B artifacts were byte-identical. These few samples are
explicitly diagnostic, not a powered performance comparison. Independent
`-v` probes reported the requested modes and zero fallback functions. For the
eight-function backend-pressure input, emitted code bytes were 331,517 for
NONE, 312,695 for MIR_STACK, and 175,101 for FAST and QUALITY.

The final native harness tests pass:

- Clang 17: 30 core checks and 81 integration checks.
- GCC: the same checks pass with `-Wall -Wextra -Werror`.
- Clang ASan+UBSan: the same checks pass with leak detection and halting UB.

Coverage includes hashes, deterministic generators, argument preservation,
allocator flag ordering, missing/failed compilers, timeout/process cleanup,
per-child peak memory rather than a cumulative maximum, malformed metrics,
corrupted/incomplete/duplicate samples, changed workload/output identity,
injected substantial timing and memory regressions, and inconclusive noise.

The Clang-built instrumented Debug compiler passes **395,072/395,072 assertions
and 40/40 modules**, including the new exact arena request-count regression.
The first run had one failure because the installed Node 22.16.0 requires
`--experimental-wasm-memory64`. The passing run uses a validation-only PATH
wrapper invoking that same Node with its feature enabled; no repository test
was changed, skipped, or marked expected-failing.

Frozen-source self-host validation, using Clang-built compilers, passed both
stages, stage-2 allocation probes, and stage 2 == stage 3 byte equality. The
output was 36,385,120 bytes. A stage-2 probe counted 10,569,143 arena requests
and 153,945,997,937 cumulative requested bytes; peak RSS was approximately
992 decimal MB. The much larger cumulative request total includes scratch
rewinds and reuse, and must not be called simultaneous memory consumption.
The stage experiment used FAST, which was unaffected by the earlier mode-label
error. Its small, noisy timing sample is not a speedup claim.

The complete `bench_throughput_ci` compiler-build orchestration also ran locally
using two independent directories and a permitted CPU selected by `--cpu auto`.
The final same-binary twenty-pair, two-round, actual four-mode A/A run completed
1,920 timed compilations with zero confirmed regressions and 13 inconclusive
cases. All repeated/A-B artifacts matched, and all allocation probes matched
their uninstrumented artifacts. Raw evidence is retained with the PR validation
bundle. It calibrates this shared host only, not a dedicated Zen 5 machine or
all GitHub runner images.

## Reproduction and limits

```sh
./build.sh bench_throughput self-test
./build.sh bench_throughput run --baseline /base/ide --candidate /candidate/ide --output build/throughput-aa --profile ci --mode all --pairs 20 --warmups 2 --cpu auto --pmu --require-identical-output
./build.sh bench_throughput compare --output build/throughput-aa
```

The canonical `./build.sh test_self_host --config Release` attempt stops because
TCC is absent. The local application build used Clang and LLD; it is not a
claim of canonical TCC-bootstrap validation. `perf_event_open` returns EPERM
in this container, so no actual cycles/instructions/cache/branch event counts
or Zen 5 conclusions are claimed. The collector's unavailable-event handling
is exercised; successful hardware collection needs a permitted physical host.
Windows/macOS native harness checks and fresh GitHub platform CI are separate
published-revision gates, not inferred from Linux results. Full compiler
sanitizer validation was not rerun; only the native harness sanitizer run above
is claimed. See `tools/throughput/README.md` for the complete data/metric contract.
