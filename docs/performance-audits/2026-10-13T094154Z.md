## Mechanism

`c_preprocess_run` defines 229 object-like macros per x86-64 Linux compile
through `c_macro_define_object_text`. Each one ran `c_lex_space` on a short
constant text, for example `1`, `unsigned long long`, `(-1021)` or
`1.18973149535723176502e+4932L`. Each run did a translation pass, checkpoint
arrays, a 17-row-padded token reservation and two row trims, the SIMD
intern pass, and the lexer itself.

On the empty x86-64 unit, `c_macro_define_object_text` was 632,635 Ir
inclusive (`callgrind-prelude-functions.txt`). 117,747 of that was the lazy
`c_punctuator_dispatch_build`, which the first `(-N)` text triggered. The
remaining 514,888 Ir is **2,248 Ir per macro**.

**Change.** `c_predefined_text_tokens` builds the lexer's tokens directly when
a text uses only:
- identifiers;
- preprocessing numbers, exponent signs included;
- single spaces;
- `(`, `)` and `-`.

It writes the same spelling bytes, the text plus its terminator, and the same
token rows with the end marker. It interns identifiers in the same order.

Any other text goes through `c_lex_space`, including any byte outside that
set, a `.` or `+` outside a number, `--`, and anything 64 bytes or longer.
Only the four string literals fall back in practice: `__clang_version__`,
`__DATE__`, `__TIME__` and `__TIMESTAMP__`. The direct path also falls back
whenever the lexer's own spelling-capacity check would fail, so that case
keeps the lexer's diagnosis.

**Equivalence.** Two `c_frontend_tests` fixtures hold the two paths equal:
- `c_test_predefined_text_direct_tokens` compares all 69,905 strings of up
  to four bytes over a 16-symbol alphabet with `c_lex_space` in a fresh
  space. The alphabet covers both exponent letters in both cases, `.`, `+`,
  `-`, the parentheses, space, and fallback bytes (`$`, `'`, `"`). The
  fixture also checks the prelude's own shapes and texts that must fall back.
- `c_test_predefined_text_prelude_identity` covers 16 target configurations
  (14 triples plus two I386 CPU models) × {GNU89, GNU17, C17, GNU17 + PIC 2}.
  For each, every prelude text is compared with the lexer in a verify mode,
  and no text other than a string literal may fall back. The unit, which
  stringifies multi-token, signed and string predefined macros, is then
  preprocessed with every text lexed. Tokens, the whole spelling space and
  the identifier table must match byte for byte.

## Results

**Corpus identity and work** (`work-ledger-base-vs-candidate.md`; 359
fixtures plus the self-host input):

- 360/360 plain artifacts are byte-identical to the base.
- Ledger and plain builds agree on all 360 units for both subjects.
- Fixture processes:
  - Ir: 9,592,177,702 → 9,487,669,542 (−1.09%, about 292 K per unit).
  - Minor faults: −0.08%.
- Preprocess phase over the corpus:
  - Arena calls: 4,891,119 → 4,486,119 (−8.28%).
  - Arena bytes: −2.08%.
- Self-host: −97,900 Ir (−0.00%).
  - One prelude is 292 K of its 26.4 G Ir.
  - The self-host compile runs on several lanes, so its count is not expected
    to reproduce to that precision. Repeated runs were not made to verify
    this.

- **Per unit.** A unit that lexes any punctuator saves about 292 K Ir: the

- **Per macro.** `c_macro_define_object_text` falls from 2,248 to about 985 Ir
  per macro, including interning, the macro definition and the replacement
  spacing it still performs.
- **Where the saving comes from** (`callgrind-prelude-functions.txt`):
  `c_lex_dispatch` −158 K, the SIMD intern pass −102 K, row trimming −35 K,
  and the arena and integer helpers inlined into the lexer.
- **Warm compiles.** The 64-input process is the warm, in-process
  population: after the first unit, every compile repeats the prelude. It
  shows the same ≈294 K Ir per unit.

change.

## Finding outside the scope

On baseline x86-64 without cx16, a 128-bit `__c11_atomic_store` whose value
operand is a call fails with "could not lower logical expression core". This
was found while choosing the four-input workload, and is filed as
[#3998](https://github.com/buster14a/buster/issues/3998). The corpus pins
`-march=znver3`, so the corpus does not reach it.
