## Revision, defect, and change

Baseline: `ebfdd11705bc470564e726857e498f1c82aa746c`, rechecked against live
`main` before publishing. This is a correctness fix for GitHub issue #191,
not a claim of an encoding-throughput optimization. The other open assembler,
allocator, verifier, and CI work was inspected and left untouched.

The shared EVEX address encoder computed compressed displacement N from the
unbroadcast vector tuple even when EVEX.b selected a scalar broadcast. For
`vaddps 64(%rdi){1to16},%zmm1,%zmm0`, baseline emits
`62 f1 74 58 58 47 01`, which addresses rdi+4, instead of
`62 f1 74 58 58 47 10`, which addresses rdi+64. A native AVX-512 fixture with
2.0 at offset 4 and 16.0 at offset 64 returned bits `0x40000000` before the
fix and the expected `0x41800000` after it. The Clang-assembled control returns
the expected value.

Pass the broadcast state into the existing address helper; FULL and HALF
broadcast tuples use the element width. Non-broadcast addressing, forced
32-bit relocations, and the legacy machine-fast path retain their behavior.
The same boundary tests exposed a related validation defect: HALF broadcast
counts describe the source tuple, not the destination vector. For example,
`vcvtps2pd zmm0{k1},dword ptr [rax+64]{1to8}` is valid; `{1to16}` is not.
The count helper now uses the half-width source for HALF tuples.

## Regression and independent oracle coverage

The existing metadata test module gains 1,620 direct and exact-query cases:
`vaddps`, `vaddpd`, `vpaddd`, `vfmadd132ps`, and `vcvtps2pd`; XMM, YMM, and
ZMM; broadcast and non-broadcast; 18 signed displacement values; and RAX,
RBP, and RAX+RCX*4 addressing. Expected bytes are independently constructed
from explicit family opcodes and displacement rules, not from the production
tuple helper. Fifteen invalid broadcast counts must be rejected without
writing output. Source assembly is also checked for 1,458 of these cases.

The independently assembled 1,620-case corpus matches both Clang 17 and GNU
as 2.44, byte for byte (14,268 text bytes). The fixed Buster assembler matches
all 1,458 supported source cases (12,816 bytes). Baseline's 1,296 FULL-tuple
source cases contain 372 byte mismatches; HALF broadcast source cases are not
silently counted as passes when baseline rejects their valid count.

HALF source tests deliberately use explicitly sized Intel operands. The
pre-existing AT&T `vcvtps2pd` source adapter infers the wrong memory element
width, independently of displacement scaling. The 162 HALF non-broadcast
source cases are therefore not claimed as passing source tests; their direct
and exact-query encodings are covered. No source-syntax support is removed.

## Environment and performance

Linux x86-64 on AMD EPYC 9V74, four-CPU cgroup quota, five available affinity
CPUs, 4 GiB memory. Clang 17.0.0, GNU binutils 2.44, split Release build,
`-O2 -DNDEBUG`, frame pointers enabled, debug information disabled. Both
compilers use the same feature target, source path and output path convention.
Native AVX-512 execution works on this host; no APX execution is assumed.

The three assembly inputs contain 24,000 instructions each. The scalar cycle
is `movq %rax,%r8`; `addq $7,%rax`; `leaq 24(%rbx,%rcx,4),%rdi`;
`xorq %r9,%r10`. The vector cycle is
`vaddps 64(%rax),%zmm1,%zmm0{%k1}`;
`vaddpd -128(%rbp),%ymm1,%ymm0{%k1}`;
`vpaddd 32(%rax,%rcx,4),%xmm1,%xmm0{%k1}`. The broadcast cycle is
`vaddps 64(%rax){1to16},%zmm1,%zmm0{%k1}`;
`vaddpd -1024(%rbp){1to4},%ymm1,%ymm0{%k1}`;
`vpaddd 508(%rax,%rcx,4){1to4},%xmm1,%xmm0{%k1}`.
Each source starts with `.text`, repeats its cycle to 24,000 instructions,
and ends with a newline. Compile with `ide cc -c -march=native input.s -o out.o`.

Each compiler is pinned to logical CPU 4. Two warm-up pairs precede nine
measured pairs, alternating which compiler runs first. Measurements use
monotonic wall time and child `wait4` CPU time/peak RSS. Every repeated output
hash is checked for determinism. These are process-level compile measurements,
not a counter-based encoder-only microbenchmark.

| Input | Baseline wall median | Fixed wall median | Baseline CPU median | Fixed CPU median | Peak RSS median, both | Object bytes before -> after |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Scalar | 1.380619 s | 1.387028 s | 1.376861 s | 1.383705 s | 93,352 KiB | 90,448 -> 90,448 |
| Vector | 0.567687 s | 0.578178 s | 0.567452 s | 0.577976 s | 94,376 KiB | 176,448 -> 176,448 |

Medians of the nine paired fixed/baseline wall ratios are 1.0058, 1.0323,
and 1.0021 respectively. Their 95% bootstrap intervals, resampling pairs
10,000 times, are [0.9336,1.0434], [0.9720,1.0599], and [0.9505,1.0663].
These intervals all include no change. This noisy run cannot resolve a
small regression or establish a speedup. Part of the experiment overlapped
compilation on other affinity CPUs; the shared CPU quota is another reason
not to overinterpret the estimates. The broadcast size reduction follows
correct scalar disp8 compression, not equivalent behavior from baseline's
incorrect encodings. No allocation-count or hardware-counter claim is made:
`perf` is absent, and allocation counting was not instrumented.

## Build and verification commands

TCC is absent: the required initial `./build.sh test_self_host --config Release`
failed with `tcc: command not found`. The following explicit Clang bootstrap is
an environment adaptation, not evidence that the canonical TCC script passed.
Commands are run from the corresponding worktree root. Separate worktrees
were used for baseline, fixed Release, and sanitized Debug; generation never
ran over an active build directory.

```sh
clang -Isrc -Wall -Werror -Wno-unused-function -Wno-unused-variable -g build.c -o /mnt/data/buster-build
/mnt/data/buster-build generate --cc clang --config Release --linker DEFAULT -DBUSTER_UNITY_BUILD=OFF -DCMAKE_C_FLAGS_RELEASE='-O2 -DNDEBUG' -DBUSTER_DEBUG_INFO=OFF -DBUSTER_FRAME_POINTERS=ON
cp /mnt/data/buster-build build/build
/mnt/data/buster-build build --config Release -t ide -- -j2
/mnt/data/buster-build build --config Release -t test_all -- -j2
/mnt/data/buster-build test_self_host --config Release
/mnt/data/buster-build test_mode_matrix --config Release
```

Baseline full suite: 395,585/395,585 unit tests and 40/40 modules. Fixed:
395,586/395,586 and 40/40. The new module regression was observed failing
before the production fix. Baseline self-host reaches a byte-identical
39,201,584-byte fixed point; fixed self-host reaches a byte-identical
39,201,800-byte fixed point. Both mode matrices pass all 24 legs: four native
Linux x86-64 legs and twenty compile/link/disassembly-oracle legs because
other native platforms and emulators are unavailable locally. The four
allocators are `none`, `mir-stack`, `fast`, and `quality`.

An additional native fixture compiled, linked, and executed with all seven
optimization settings (`-O0`, `-O1`, `-O2`, `-O3`, `-Os`, `-Oz`, `-Ofast`)
and all four allocators passes 28/28. Put the allocator flag after the
optimization flag, since an optimization selection resets allocator defaults.
The fixture zeroes zmm1, broadcasts the scalar at offset 64 into zmm0, moves
the low float bits to eax, executes vzeroupper, and returns; its C caller
checks the exact expected bits rather than a tolerance.

same Node binary with that flag; no repository test or coverage was disabled.
