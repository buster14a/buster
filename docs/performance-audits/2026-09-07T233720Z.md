## Result and tradeoff

The new service avoids most cold classification work when only a few types are
queried. It is slower on this fully warm, L1-sized corpus and slightly slower
when the cold trace needs every type. This is an explicit cost of the measured
implementation; lazy classification is not a general throughput improvement.

| Trace and phase | Old service median | New service median |
| --- | ---: | ---: |
| Dense: cold preparation | 1,372.382 ns | 60.337 ns |
| Dense: first 46 queries | 63.272 ns | 1,722.169 ns |
| Dense: preparation + first trace | 1,438.315 ns | 1,781.990 ns |
| Dense: warm time per query | 1.202 ns | 13.865 ns |
| Sparse: cold preparation | 1,444.397 ns | 60.359 ns |
| Sparse: first 8 queries | 29.783 ns | 271.523 ns |
| Sparse: preparation + first trace | 1,474.194 ns | 338.997 ns |
| Sparse: warm time per query | 1.252 ns | 13.519 ns |

Dense cold total rises 23.9%; sparse cold total falls 77.0%. Medians of totals
are computed per sample, so they need not equal the sum of phase medians.
Dense total ranges are 1,379.288–1,772.913 ns old and
1,670.574–2,890.320 ns new; sparse ranges are 1,338.925–1,579.086 ns old and
323.854–355.466 ns new. Warm ranges are 1.154–1.352 ns old and
11.627–37.356 ns new for dense, and 1.252–1.448 ns old and
11.218–17.522 ns new for sparse. Shared-host interference remains visible, but
the hot-query regression in this harness is far larger than the observed
variation. The new context checks, page lookup and compilation/inlining choices
are included in these public-service measurements; no isolated instruction-cost
attribution is claimed.

This small ABI-service result is not an end-to-end compiler regression estimate.
The previous audit's same-source unity timing ranges overlap broadly; its
17,060 KiB median peak-RSS reduction and exact cache-storage reduction remain
the demonstrated whole-compiler/memory evidence. Further hot-query optimization
would need to retain independent contexts, immutable type identity and retry-safe
ownership, and then repeat both this service trace and whole-compiler measurement.

## Same work and measured phases

The [single C harness](2026-09-07T233720Z-service.c) includes each source
revision's real production `ir.c`, arena and target implementation. The same
harness is compiled by genuine Clang 21.1.8 with identical `-O3 -march=native`
and project-required C flags. Its conditional adapter only resets/inspects the
different cache representations; it does not replace either implementation.

Both versions use the same 23-type corpus copied from `ir_tests`: f32, f64,
f80, integer/enum, complex and ordinary aggregates, packed/unaligned fields,
and homogeneous/mixed unions. The dense trace requests argument and result for
every id. The sparse trace requests those uses for ids 0, 2, 6 and 14: f32,
f80, complex f80 and a two-double record. All queries use System V x86-64.

Each process creates the common type/field corpus outside the timed spans, then
runs one cold preflight and 2,048 measured empty-cache iterations. Each iteration
rewinds only cache allocation storage and resets cache ownership outside timing;
allocator and scratch pages are already warm. Thus **cold** means an empty ABI
cache, not cold hardware caches or fresh OS page faults. `CLOCK_MONOTONIC`
separately brackets `ir_prepare_program_abi` and the first public
`ir_type_abi_value` query trace. Reported cold totals include both phases and
clock overhead. Warm timing repeats the same complete trace 32,768 times on
its retained cache: 1,507,328 dense queries or 262,144 sparse queries per sample.
Checksums consume the returned values, and disassembly inspection confirms both
warm loops call the non-inlined trace function on every iteration.

The work difference is intentional and measured:

| Property per compilation | Old dense | New dense | Old sparse | New sparse |
| --- | ---: | ---: | ---: | ---: |
| Classifications during preparation | 46 | 0 | 46 | 0 |
| Classifications after first trace | 46 | 46 | 46 | 8 |
| New classifications during warm trace | 0 | 0 | 0 | 0 |
| Warm cache hit rate | 100% | 100% | 100% | 100% |
| Allocated ABI cache bytes | 19,504 | 7,200 | 19,504 | 7,200 |
| ABI cache allocations | 23 | 4 | 23 | 4 |
| Occupied type-row bytes | 3,128 | 2,944 | 3,128 | 2,944 |

The old service prepares argument/result for all 23 types and copies arguments
into variadic slots. Its classification count follows from resolved entries and
those two unchanged classifier calls per SysV entry. The new service reserves
two use pages before any queries, then increments its actual miss counter for
needed `(TypeId, AbiUse)` pairs. This 23-type corpus fits in one 64-type page
per use, so dense and sparse storage are equal; larger sparse type populations
can have a different storage shape. Bytes include page masks and directory
entries, excluding fixed context headers embedded in `IrProgram`, arena headers
and reserve rounding. The previous whole-compiler peak-RSS measurement includes
those costs too.

The [runner](2026-09-07T233720Z-run.py) pins its children to permitted logical
CPU 0, performs one whole-process warm-up per case/version, and records 12
alternating A/B pairs per case. [All 48 measured samples](2026-09-07T233720Z-samples.json)
are retained. Pinning prevents migration; it does not reserve a shared VM core.
The run took about half a second without requesting a pause in integration
builds. Hardware counters remain unavailable; no Zen 5 measurement is claimed.

Every process checks the first trace byte-for-byte against its production
uncached classifier outside timing. Old/new trace fingerprints and checksums
agree in every sample: dense fingerprint `1f07eef246e10ab4` and checksum
17,895,938; sparse fingerprint `fe2350f5403159f0` and checksum 3,551,334.

## Reproduction and validation

Use frozen source checkouts of the two revisions above. From the directory
containing this audit, with genuine Clang 21.1.8 on `PATH`:

```sh
clang -I/path/to/old/src -DBUSTER_ABI_BENCH_BEFORE=1 -O3 -march=native -Werror -fwrapv -fno-strict-aliasing -funsigned-char -ffunction-sections -fdata-sections -Wl,--gc-sections 2026-09-07T233720Z-service.c -lm -lpthread -ldl -o /tmp/buster-abi-before

python 2026-09-07T233720Z-run.py /tmp/buster-abi-before /tmp/buster-abi-after /tmp/buster-abi-samples.json
```

Both builds completed without warnings/errors. All 48 sample processes and
all preflight warm-ups passed, and the runner checked fingerprints, checksums
and zero warm misses. Python syntax, retained JSON, local links and

historical `2026-08-24T131821Z` opening-format error, already reproduced on
unchanged main. No previous audit was edited, and no compiler suite was rerun
