## Census that chose the design

On the base, `c_ast_types_lookups_agree` costs 52.48 M Ir inclusive over
138,798 calls. Only 17.75 M of that is the 191,178 entity lookups it makes
(`c_parse_lookup_entity_symbol`, about 93 Ir each). The rest is the walk and
the per-mark work: the backward walk over the subtree, each mark's token and
binding, and the comparison.

A throwaway census build of the base (not committed) counted, over the same
input:
- 138,804 checks, 712,144 nodes walked (5.1 per check), 191,184 lookups, and
  **no disagreement**;
- 77,874 lookups (41%) repeat the previous lookup of the same node in the same
  scope with the same entity count;
- the entity count changes once during all the queries.

A second census, on a candidate that already stamped lookups (below), found:
- once rollbacks that take nothing away stop counting, the lookup generation
  never changes between queries;
- every query scope's parent chain reaches the file scope;
- 138,650 of 138,798 checks (99.9%) involve only marks whose symbol no entity
  outside the file scope has, and whose binding is a file-scope entity or
  none. 218,685 of their 218,833 marks are of that kind.

## The change

All of it is under `-fc-ast-pilot`, except for the stamp in `c_parse.c`.
- **`c_parse_lookup_generation`.** A `u64` on the scope cursor, which lives
  behind a pointer, so a rollback of the result by value leaves it alone.
  - It moves with every entity that `c_parse_scope_add_entity` adds.
  - It moves with every `c_type_parse_rollback` that takes entities, scopes or
    identifier uses away.
  - Those are the only writers of what a by-spelling lookup reads, so while it
    is unchanged a lookup of one symbol in one scope gives one answer.
  - Identifier uses are only appended, so a binding is unchanged while the
    use count is too.
- **`c_ast_types_locals_build`.** Built once per generation, in the machine's
  scratch beside the body index:
  - a byte per symbol, set when some entity outside the file scope has that
    symbol;
  - a byte per scope, set when the scope's parent chain reaches the file
    scope.

  A rebuild waits until the nodes settled since the last build reach the
  entity count, so rebuilding never costs more than settling.
- **`c_ast_types_lookups_settled`.** It settles a region at its first query
  that needs the check: a scan of the region's flags for lookup marks, eight
  bytes at a time. Each mark is checked once at the file scope against its
  binding (`c_ast_types_mark_resolves_at_file`). Up to 16 marks per region
  that a non-file-scope entity also spells are recorded. A later check costs
  a few loads:
  - the generation and the use count still match;
  - no recorded mark lies in the node's subtree;
  - the query scope's chain reaches the file scope.

  Anything else walks the subtree as before (`c_ast_types_lookups_agree`,
  unchanged).

**Why it is exact.** A symbol that no entity outside the file scope has is
found in no scope before the file scope. So a lookup from any scope whose
chain reaches the file scope returns what the file scope returns.
`c_parse_lookup_entity_chain` and its two shortcuts agree on that, under
`BUSTER_REFERENCE_CHECKS`. A settled region checks every mark in it, which
includes every mark the walk would visit. So a settled check can agree only
where the walk would also agree.

Two statistics, `lookups_settled` and `lookups_walked`, are added to the
typer's `-v` line. They are written only after a check.

## Correctness probes

`c_ast_test_type_lookups` analyzes seven sources twice: with the tree and its
statistics, then with every tree answer verified against the machine. Each
must have 0 mismatches and the expected paths. The sources cover:
- file-scope callees, a typedef name and an enumerator in a body, which
  settle;
- a callee through a parameter, which walks, beside a file-scope callee in the
  same body, which settles;
- a local declared after the call, which shadows the callee in the query's
  scope: it walks and declines;
- a local of another function with the callee's name, which walks;
- 17 callees through a parameter, more than a region records, so every check
  walks;
- file-scope initializers that settle, and one whose name a local elsewhere
  spells, which walks.

**Mutation check.** With the local-symbol condition removed from
`c_ast_types_mark_resolves_at_file`, three cases fail. The shadowing case
settles and answers the call that the base declines.

**A defect found by the mutation run.** The first version left the new
`CAstTypeBodyIndex` fields uninitialized, because the index comes from an
uncleared arena allocation. The tables were then never built, and settlement
read whatever the arena held. The design rows above were measured before the
fix. Every budget row, arm and probe result is from the fixed code,
`552bf225`.
