#545 — skip the fresh template-cache memset with an arena dirty watermark

## Change

The canonical x86 template cache can reserve 262,144 entries (32 bytes each,
8 MiB). `Arena.dirty_position` now retains the high-water mark across logical
rewinds, while `arena_dirty_position` takes the maximum of that saved mark and
the live cursor. Allocations therefore add no watermark store to the arena's
hot path. Fresh mappings start at `arena_minimum_position`; logical and
temporal rewinds save the cursor, and pooled reuse carries the mark through the
header rewrite. Parking an arena accounts for the pool link written into the
first payload bytes. A successful decommit clamps the mark to its decommit
boundary, since recommitted pages are fresh again.

Codegen snapshots the mark immediately before allocating the metadata header,
then allocates the template array as before.  It clears only
`[template_start, min(dirty_position, template_end))`; the suffix above the
watermark is zero from a fresh mapping or a successful decommit.  A watermark
that lands inside an entry is intentionally cleared bytewise through the
boundary.  The lookup probe window, insertion, replacement, and eviction
choice are unchanged.

The invariant is therefore: every byte below
`max(dirty_position, position)` may contain contents from an earlier arena
generation, while every byte at or above it in a newly committed suffix has
not yet been handed out by this generation. The mark is conservative
(alignment padding and pool metadata may extend it), so a false positive costs
a smaller memset but can never expose stale cache fields.

## Measurement

The pinned (CPU 0) changed build's one direct stage-1 compile measured:

```
instructions                 9,699,008,398
cycles                       3,675,082,948
L1-dcache-loads              3,435,118,665
L1-dcache-load-misses           89,486,593
cache-misses                    8,253,801
elapsed                           0.888 s
```

This is the first combined-build reading, not an isolated A/B claim. A clean paired baseline
could not be made without replacing other workers' uncommitted compiler and
test changes in the shared tree; the aggregate instruction shift on this host
is already several hundred thousand instructions for source edits below that
scale.  The source-level upper bound is nevertheless explicit: a fresh
8,388,608-byte template suffix no longer receives a full memset, while a pooled
arena clears only its dirty prefix.  A later isolated baseline/null-control run
should use the repository's pinned, order-alternated audit protocol before
claiming a stage-1 delta.

Central integration caught and removed one bad first implementation detail:
updating the watermark on every arena allocation measured 9,698,202,540
stage-1 instructions in the same combined tree. Moving the update to rewinds
and pool transitions reduced the final count to 9,667,016,394, a 31,186,146
instruction correction. This is a single hardware-counter comparison, not the
paired cache-memset A/B still requested above.
