## Census that chose the design

Which rows each declined shape appends, and who reads them:
- **Casts to primitive or pointer type names, and `&`.**
  `c_parse_primitive_type`, `c_parse_pointer_chain` and the machine's
  `ADDRESS_OF` each append a fresh row per read, and a cast's type name is read
  once per operator-scan level and again by its leaf. At the end of body
  validation on the unity self-host, 93.8% of the 96,717 pointer rows and
  nearly all of the 37,000 primitive rows were copies.
- **String literals.** The string leaf appends one array row and one bound per
  literal.

Downstream readers:
- A primitive or pointer row is never completed in place, and no side table
  keys on its index: alignment records, the definition index and the aggregate
  lookup key rows by tag or unqualified link, and lowering keys its per-type
  tables on array rows. Lowering maps such a row to a scalar, qualified-scalar
  or pointer IR type, and interns those itself. So a copy is observable only as
  table size, **except** through lowering's order. Lowering maps rows in passes,
  in table order, and a struct resolves only once its members' rows are mapped.
- An array row lowers to an IR array type of its own, and `-g` describes every
  IR type. String rows are therefore observable, and are not interned.
- The verify gate compares type-table sizes with and without the tree. In the
  final version every run of the gate interns, so it compares interned tables.

Design: (a) interning for primitive and pointer rows, (b) an exact replay for
the one array row a tree answer needs (a checked cast's string-literal
operand). Two observability failures shaped the interning window:
- **Interning everywhere** reordered the self-host's `-g` type entries. A
  struct member's interned `char *` row moved ahead of its struct, and the
  struct resolved a pass earlier. Interning is therefore confined to
  `c_parse_validate_lowering_constraints`' loop over function bodies, after
  every declaration has its rows.
- **Inside the window**, a body query can still define an aggregate. The machine
  reads most definitions written in expressions back from rows the declaration
  pass made, but one whose type name puts a qualifier before the tag
  (`(const struct { char *p; })`) it defines itself, with its row ahead of its
  members'. A probe of that shape kept its `-g0` object and changed its `-g`
  object. The self-host defines no aggregate inside the window. The c_ast
  corpus and the frontend fixtures define a few, but none had a member that
  interning moved ahead of its aggregate. Interning is now suspended while the
  machine reads an aggregate's member segments. `c_test_type_interning_objects`
  requires identical objects with the window shut and open; with the
  suspension removed it fails on that source at `-g`.

Under interning, type rows at the end of body validation on the self-host,
identical with and without the tree, were 190,076 at the base and 133,389 in
the first candidate (−56,687, −29.8%), from a log of 1,302 distinct interned
rows. Array bounds were 39,651 in both.

## Final version: interning only under the pilot

Review held the first version: it changed the default path, and hosted
counts cannot accept a default-path change (#2761). The final version keeps
the interning header only when the caller asks for it
(`CParserResult.type_interning`), and the driver asks only with the tree. The
default path appends every row, as before. The corpus gate and the probe
harness ask for interning in every run, and `c_test_type_interning_objects`
compares the default, the pilot, and the pilot with the window shut.

## What the typer still declines

A throwaway census build of the first version (not committed) recorded why
each declined query's node was refused, on the self-host under
`-fc-ast-pilot`:

| Declined shape | Queries | Why |
| --- | ---: | --- |
| string literal | 10,940 | its array row is observable; not interned, not replayed |
| `&` | 3,034 | its `ptr(T)` row is not interned yet when the body is typed |
| cast, pointer level | 590 | a `*` level's row is not interned yet |
| cast, checked, operand declined | 561 | the operand is a member access, call, index and so on; 27 are literal runs |
| cast, checked, operand not safe | 291 | the operand's own checked rule could fire |
| `&`, operand declined | 80 | |
| cast, other type names | 46 | a tag, a qualified typedef, a declarator |
| cast, other | 47 | an unaccepted operand holding a type name (20), an uninterned base row (14), an unclean conversion (13) |

The eager pass types a body before any of its queries, so a row first minted
in that body is not yet interned when its `&` or `*` is typed. Interning the
declarations' rows too would change the `-g` order (above). The final
version's typer rules are the first version's; this census was not repeated
on it. On its base it declines 35,403 queries, against the first version's
35,072.

- The string literal path answered a run of string literals before the machine,
  in both arms. On the self-host it took 6,650 queries and saved about 1 M
  instructions in machine runs, while its check on each of the 2.19 million
  queries, and the codegen change around it, cost about 28 M. It was dropped,
  and string queries stay with the machine.
- `S8()` spells its cast `(char8*)("text")`. The first replay took only a bare
  literal, and declined 10,088 checked casts over a parenthesized one. The
  machine's operand task strips enclosing parentheses before it probes the memo
  and calls the string leaf, so the replay now does the same. That answers about
  10,060 more queries and accounts for most of the pilot's gain.
