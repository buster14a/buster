## Scope and provenance

Baseline main: `44a90fcbff44988624878aff9db3346a8bc6550b`.
Implementation/test commit: `164c93981f0589731d80b502a8a82acdd12853b0`.
Initial measurements used `b4082388ac20a31cc2d49f3a34724b636067b660`, which
adds an explicit unsigned cast for Clang 21's sign-conversion warning.
They exposed a MIR_STACK compiler-cost regression, addressed before closure
by source-policy commit `6f44deeff289873df6a8d7c6a328f6d7aa92e778`. Final measurements use that corrected code. Both trusted
compilers use TCC-bootstrap, Clang 18.1.3, Release, `--ci --linker DEFAULT`,
and `-DBUSTER_UNITY_BUILD=OFF`. Actual compile-command flags match after
normalizing worktree paths: the last optimization flag is `-O2`, debug
information and frame-pointer options are absent, and both use `-march=native`.
The [build provenance](evidence/2026-09-11T194651Z/build-provenance.json)
retains the complete commands. This audit adds documentation and evidence. Archived text normalizes line endings
and trailing whitespace; numeric observations and compiler inputs are unchanged.
The corresponding GitHub source trees were checked for exact equality with
the local commits before their branch references were published.

The patch gives x86 MASK values a separate seven-register allocator with
k0 reserved. GPR/ZMM IDs, 48-entry allocator tiles and existing replay opcode
numbers remain unchanged. Thirteen appended MIR rows expose integer bridges,
predicate copies/logic and allocated-mask producers/consumers. The prepared
metadata cache grows from 173 to 193 shapes; selection does not scan the full
x86 instruction database in compiler workers.

The source finishing pass keeps compare, sign-mask, copy, and AND/OR/XOR
chains in predicate registers when their inputs are known predicates. It
creates scalar representations for genuine integer, storage, call and CFG
language boundaries. Mixed integer constants and C integer complement still
use scalar bridges; they are correct existing integer operations and remain
possible conversion optimizations. Predicate block parameters and parallel
copies are supported in MIR, while the current source selector retains its
integer representation at source CFG joins. Byte masks carry 64 bits and
16-lane dword comparisons return through a zero-extending KMOVW.

FAST and QUALITY retain block-local K residency independently of GPR/ZMM
placement. Calls and legacy fixed-k1 rows spill live predicates. The separate
bank handles fixed physical operands before picking reload registers; all
outgoing edge sources are captured before publishing any destination. Dead
predicate homes are removed, and zero/all-ones bridge values rematerialize
with KXORQ/KXNORQ, including as edge arguments. Explicit MASK MIR under MIR_STACK flushes residency at every row. The final
source selector uses the allocator's `predicate_residency` policy: FAST and
QUALITY enable predicate promotion; MIR_STACK preserves its existing integer
bridge rows because it cannot retain predicates across rows. This prevents
unnecessary source K spill/reload generation without dropping explicit MASK
MIR support. None of these changes assert optimal global register allocation.

## Initial measurement and correction

All task-owned builds, tests and other benchmarks were paused for one
coordinated slot. The generated-code experiment ran first, followed by the
ordinary compiler-throughput harness. Both use the same uninstrumented,
trusted Clang-built binaries; binary and input hashes are retained. No CPU
pinning, PMU or allocation replay was used. The shared Intel Xeon host and
small samples make these diagnostic observations, with no isolated causal
speedup or Zen 5 result claimed. `-march=znver5` selects the kernel's instruction
contract; the machine running it is Intel.

The [reproducible measurement script](evidence/2026-09-11T194651Z/measure.py)
compiles 512 copies of the two-function source fixture (1024 definitions,
320,041 source bytes) with `-c -g0 -O0 -march=znver5
-fregister-allocator=MODE -fno-machine-fallback`. Each mode has one warmup
and eight alternating A/B pairs. It then times ten million external calls to
the generated mask-chain kernel, checking every output byte and the separate
16-lane integer result. No compiler or linker runs inside kernel timings.
The [runtime harness](evidence/2026-09-11T194651Z/runtime.c),
[raw samples](evidence/2026-09-11T194651Z/predicate-samples.csv),
[commands](evidence/2026-09-11T194651Z/predicate-commands.json), and
[hashes/host facts](evidence/2026-09-11T194651Z/predicate-metadata.json)
retain all 96 observations.

| Allocator | Compile baseline/candidate ms | Kernel baseline/candidate ns per call | Chain KMOV baseline/candidate |
|---|---:|---:|---:|
| MIR_STACK | 82.172 / 238.610 | 9.571 / 8.074 | 4 / 10 |
| FAST | 86.381 / 82.477 | 3.153 / 2.380 | 4 / 0 |
| QUALITY | 118.171 / 64.676 | 3.383 / 2.389 | 4 / 0 |

These are medians, not an acceptance test. FAST/QUALITY reduce the chain from
35 to 25 nonpadding instructions, using k1–k5 and no integer mask bridge.
The retained [baseline FAST assembly](evidence/2026-09-11T194651Z/baseline-fast.asm)
and [candidate FAST assembly](evidence/2026-09-11T194651Z/candidate-fast.asm)
show the exact change. Both still bridge the word result to its public integer
return; the candidate uses KMOVW. Generated 1024-function FAST/QUALITY objects
shrink from 217,208 to 200,824 bytes.

**The initial MIR_STACK implementation compiled this predicate-heavy fixture
materially slower:
2.90x wall time, and median CPU time rises from 81.374 to 233.178 ms.** Its
row-by-row residency policy produces more K spill/reload moves: 84 versus 78
nonpadding kernel instructions and 397,432 versus 389,240-byte scaled objects.
Peak compiler RSS remains about 42.5 MiB. More K moves and their metadata
emission are a plausible contributor, not an isolated attribution. This
result triggered the source-policy correction above; the generated kernel's
lower runtime did not justify retaining the compiler regression. FAST and QUALITY compilation/RSS observations are
reported separately and cannot establish the cause of their measured changes.
