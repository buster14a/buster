## Decision

Request four bounded workers for the ordinary hosted Unix native differential
corpus. The existing runner remains authoritative: it admitted four workers on
both Linux images and Intel macOS, and clamped the three-CPU Apple Silicon image
to three. The one-worker default and an explicit `--jobs 1` reproduction path
remain unchanged.

On the current source tree, the sum of per-platform median full-corpus wall
times fell from 3272.291 seconds at one worker to 1425.389 seconds at requested
four, a 56.4% reduction. Requested four was 19.5% below requested two. The
critical Intel macOS corpus fell from 1577.136 to 688.745 seconds, 56.3%. Every
requested-four sample on every platform was faster than every matching
one-worker sample. Maximum sampled process-tree RSS was 422.824 MiB.

These are corpus-phase measurements, not complete native-job or end-to-end
workflow claims. The production rollout still requires exact-head integration
and complete-job repetitions before it can be called merge-ready.

## Interpretation and rollout requirements

This current-source cohort supersedes the absolute timing claims in
`2026-09-14T075058Z`, while retaining that audit as historical policy-selection
evidence. In particular, current Linux x86_64 and Intel macOS were slower than
the older source-mismatched cohort, which confirms that historical timings
could not safely stand in for a current qualification. The selected budget is
still four because it wins both aggregate corpus occupation and the longest
corpus on every current platform, with explicit CPU and quota clamps and a
small memory footprint.

The production patch changes only the ordinary native corpus invocation to
request `--jobs 4`. It does not change the runner default, self-test, corpus,
independent O0/O2 references, caller-reuse boundary, sanitizer/reducer policy,
seed, evidence, compiler source, producer profile, unity translation unit or
native object. It does not touch #36 or use #437 resources.

Before merge-readiness, validate the exact rollout head and applicable
integration tree with the full Buster CI completion gate, companion
fixed-point/GPU/iOS and compiler-throughput checks, and at least three
equivalent complete native-job samples per Unix lane for selected and
one-worker reference policies. Report complete-job latency, aggregate runner
seconds and the recomputed workflow critical path separately from this corpus
phase. Operational rollback is the one-line removal of `--jobs 4`; the
unchanged runner then returns to one worker, while `BUSTER_TEST_JOBS` can clamp
an individual environment.
