## Workload

Every arm compiles the same input: the base revision's unity self-host source,
from a base worktree, with that tree's generated headers.

```sh
ide cc -Isrc -I<base generated> -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -fsyntax-only \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

There are four arms:
- A: base, default flags;
- B: base with `-fc-ast-pilot`;
- C: candidate with `-fc-ast-pilot`;
- D: candidate, default flags.

`-c` arms swap `-fsyntax-only` for `-c -o <object>`. Callgrind ran with
`--cache-sim=no --branch-sim=no`. Function figures are call-site inclusive.

## Change

Under `-fc-ast-pilot`, `c_parse_local_declarations` reads three facts of a
block declaration from its `DECLARATION` node (`c_parser_local_split`):
- the storage-class set, from the `DECL_SPECIFIERS` words;
- whether `c_parse_auto_declaration_info` must run, which it must only when an
  `auto` or `__auto_type` word stands in the specifiers or the first
  declarator;
- each declarator's segment end, the `,` before each later `INIT_DECLARATOR`.

Every type-machine call keeps the walker's token ranges. A per-unit hash of
`DECLARATION` nodes by first token (`c_parser_local_index_build`) is built
once before the body binding loop.

  - `c_parse_local_declarations` falls from 336,164,769 to 309,970,483

    - `c_parse_auto_declaration_info` (19.19 M over 41,608 calls) no longer

    - the storage-class scan and the comma scan through every initializer
      are gone;

  `4c8d203b` loads whole windows unmasked and masks only the last one. Nothing
  else changed, and the budgets were not revised. On an AVX-512 build both
  loads are single instructions.

## Correctness

- **Self-host differential.** A one-off throwaway build, not committed, added
  the unity self-host input to the hosted sources of the corpus gate. With the
  fixtures it compared 958,066 model rows, 832,384 of them from the self-host,
  with 0 differences. 45,580 block declarations took the tree split, and the
  6 fallbacks were the fixtures' own.
- **Corpus.** The committed gate covers about 125,700 model rows from the
  fixtures and 497,400 with the four frontend sources. It tree-splits 3,993
  and 20,942 block declarations. The six fixture fallbacks are four `comma`
  and two `node`, the latter C23 `[[...]]` declarations.
- **Tests and self-host.** At `f5556c5c`, `c_ast_tests`, `c_frontend_tests`
  and `compiler_driver_tests` pass 1,656,777 of 1,656,777 in Release (unity)
  and in Debug. `test_self_host --config Release` reaches its fixed point at
  40,891,952 bytes. `4c8d203b` failed stage 1 of the self-host: the
  self-hosted compiler refuses a conditional between two `Simd512` builtin
  results ([#3482](https://github.com/buster14a/buster/issues/3482)).
  `f5556c5c` writes the window load as an if/else.

## Limits

- Callgrind counts instructions, not time, on `-march=x86-64-v3` builds whose
  AVX-512 kernels are compiled out. The index's hosted cost is therefore an
  upper bound. No wall time was taken: a 20 M-instruction change is below
  this host's paired-run noise for the whole compile.
- One input, one host, a single process, no pinning and no `perf` counters.
- The 9700X pull-request comparison runs default flags only and cannot time
  the hook, so Zen 5 validation stays **incomplete** (#2761). No PR benchmark
  request was added.
