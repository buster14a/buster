## The change

Under the pilot, the interning window (`CTypeInterning`) opened only for
`c_parse_validate_lowering_constraints`' loop over function bodies, after
`c_parse_validate_static_initializers`. So in a file-scope initializer
`c_ast_types_interned` read no interned row, and every cast to primitive
words or a typedef name under plain `*`s, every `&`, and `S8()`'s
`(char8*)("text")` declined there. #3304's census put those declines at
16,394 queries and about 57 M machine Ir (10,436 of them `S8()` casts).

Of the three options (open interning for the initializer walk, pre-intern the
needed rows, or extend the replay), the candidate takes the first. The window
now opens just before the initializer walk, and `c_ast_types_interned`
reads the log in initializers as in bodies. The initializer replay was
already exact at file scope: there is no memo slot, so it calls the string
leaf, as the machine's operand task does there.

Why lowering's order is unchanged:
- Every declaration has its rows before `c_parse_validate_lowering_constraints`
  starts, and the initializer walk rewrites none of them.
- So every row the walk interns follows every row that can refer to it, and
  an interned row still replaces only a later copy of itself. Before, the
  first copy of `char8 *` minted in an initializer was appended at the same
  index, so the first IR pointer type lowering creates for it is unchanged.
- The walk can define an aggregate inside a type name
  (`&(const struct { char *s; }){ 0 }`). The existing suspension covers it as
  it does in bodies.
- The objects confirm it. `c_test_type_interning_objects` gains a file-scope
  source with `S8()`-style casts, `&` of objects and aggregates defined in
  initializer type names. It is compiled at `-g0` and `-g` by default, under
  the pilot, and under the pilot with the window shut.

The default path has no interning header, so it runs none of the changed
behaviour.

## Reading

- The initializer `S8()` casts, and the initializer `&` and casts whose rows
  an earlier initializer has interned, now answer from the tree under the
  pilot. That removes 10,296 machine runs and 0.47% of the pilot's
  instructions on this input. #3304 estimated about 57 M machine Ir for all
  16,394 initializer declines. The measured saving in machine runs is
  52.9 M, and 45.0 M whole-compile once the extra answers are charged.
- The remaining 42,239 declines were not censused by shape here. By the
  rules, an initializer still declines a string literal, and the first `&` or
  cast of each row before any machine run has interned it.
- With this slice the hook is 8.76% below the default in instructions on
  this input. These counts are diagnostic. Hosted wall time was not measured,
  because earlier audits found this host's noise larger than effects of this
  size. Zen 5 validation is **incomplete** (#2761), no PR benchmark request was
  made, and the hook stays opt-in.
