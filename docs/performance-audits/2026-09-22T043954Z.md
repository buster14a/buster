# Decision

**Start with an allocation-free, source-order switch-interval proof.** Normalize
the existing endpoint arrays once, then avoid all earlier-case probes when the
new interval is outside the minimum/maximum bounds of the prior population.
Keep the exact old comparison loop for inconclusive intervals. This removes
work before choosing vector width and preserves diagnostic timing.

The second survivor is **PDB stable-survivor lineage**: replace repeated
original-to-current ID-map rewrites with one link per retired record and one
final ascending materialization. It changes neither hashing nor type equality.

Two distinct opportunities survived the screen; a third was not manufactured
to fill the shortlist. Neither is established as a substantial whole-compiler
hotspot. In particular, the static switch population is modest. The most useful
negative result is concrete: GCC did **not** preserve the intended independent
AVX-512 comparison masks; its generated masked comparison depends on the first
comparison and extracts a scalar mask per tile.

# 1. Switch validation: make success cheap without changing failure semantics

## Existing work, callers and actual exposure

The semantic validator
[`c_parse_validate_one_switch`][switch-parse] evaluates cases in source order,
checks dialect/constant/range validity, truncates to the promoted switch width,
then compares each valid inclusive interval against every earlier interval.
For signed ordering it repeatedly XORs endpoints with the sign bit.
It appends an interval even after reporting overlap and continues the semantic
scan; invalid/nonconstant/reversed ranges are excluded.

[`c_parse_validate_switch_duplicates`][switch-driver] invokes this per switch
from function semantic validation. Current
[`c_analyze_semantics_only` / `c_analyze_with_options`][analysis-route]
are used by syntax-only and ordinary C compilation respectively
([driver route][driver-route]). Consequently this is frontend work shared
before native or direct nonnative code generation, when the source reaches it.
It does not accelerate preprocessing-only or assembly-input commands.

Lowering independently folds/converts its larger `CIrSwitchCase` records, then
[repeats overlap checking][switch-lower]. That loop stops at the earliest
offending current case. Direct lowerer callers intentionally retain these
defensive checks. Current codegen modes include `none`, `mir-stack`,
`fast` and `quality`; the first semantic slice precedes that choice.
No generated switch dispatch or generated-program optimization is proposed.

For n valid cases, valid input performs P=n(n−1)/2 prior-pair probes in a
verifier. The incumbent is stronger than an unconditional “two loads and two
compares per pair” description: its short circuit can avoid the second load.
Ascending disjoint values usually make its first comparison false and its branch
predictable. Small arrays often fit in L1. These are serious reasons the
existing implementation may already be cheap.

## Smallest useful algorithm

The parser's two temporary endpoint arrays are used only by this overlap test.
After existing validation, store unsigned ordered endpoints:

```c
L = (low  & value_mask) ^ sign_bit;
H = (high & value_mask) ^ sign_bit;
```

Here sign_bit is zero for unsigned types and the promoted width's sign bit
otherwise. Keep the exact existing target conversion and range checks.

Maintain the minimum low and maximum high of all inserted intervals. Then

```text
H < minimum_low  OR  L > maximum_high
```

proves disjointness from **every** preceding interval. An inconclusive result
does not prove overlap: the new interval may lie in a hole. Run the existing
source-order comparison in that case. Update extrema and append at exactly the
old point, including after an overlap diagnostic.

```c
/* All original label validation has already run. */
u64 L = (low & value_mask) ^ sign_bit;
u64 H = (high & value_mask) ^ sign_bit;
bool outside = value_count == 0 || H < minimum_low || L > maximum_high;
if (!outside)
{
    for (u32 p = 0; p < value_count; p += 1)
    {
        if (L <= highs[p] && lows[p] <= H)
        {
            /* Existing consider() call, with original case token and priority. */
            report_existing_overlap();
            break;
        }
    }
}
if (value_count == 0)
{
    minimum_low = L;
    maximum_high = H;
}
else
{
    minimum_low = BUSTER_MIN(minimum_low, L);
    maximum_high = BUSTER_MAX(maximum_high, H);
}
lows[value_count] = L;
highs[value_count] = H;
value_count += 1;
```

This is insertion pseudocode, not a production patch. It requires two live
scalar values, no extra allocation, no transposition, no selection-vector
traffic, no output reconstruction and no persistent metadata. Ascending,
descending and outward-extending sequences become linear. Interior-gap/random
orders can remain quadratic. The scalar extrema recurrence is acceptable
because it replaces the larger search; it does not justify wide arithmetic.

A separate normalization-only control is mandatory. The experiment's scalar
baseline already normalizes once, so it deliberately does not credit the new
algorithms with eliminating repeated source-level XORs.

## Competing designs and full cost

| Design | Work after existing conversions | Extra representation cost | Where it should lose |
|---|---|---|---|
| Incumbent scalar | Up to P short-circuit probes | Existing arrays only | Large unfavorable valid populations |
| Normalize-only scalar | Same P, ordered endpoints | Same parser arrays, different contents | If compiler already removes equivalent cost |
| Online bounds | n proof/update steps plus residual P_f probes | Two scalar extrema | Tiny n; frequent interior insertions |
| Sorted success certificate | Private iterative sort + adjacent comparisons; original scan if failure | Two 16n-byte pair buffers, copy and merge traffic | Small/error-heavy calls |
| AVX2 / EVEX256 / AVX512 pair scan | Same triangular algorithm, 4/4/8 lanes | Two broadcasts per current interval; tails/dispatch | Short predictable scalar probes; prepacking costs |
| Interval tree or block index | Better arbitrary-order query scaling | Construction, updates, indirection | Current tiny populations |

For the bounds algorithm, a useful empirical break-even condition is

`a × (P − P_f) > h × (n−1) + d`,

where a is effective probe cost, h is bounds/update overhead and d is setup
difference. It is not a sum of serial instruction latencies. The resource
lower bound is the maximum of relevant memory, execution, frontend and
dependency requirements. Actual overlap between resources belongs in measured a
and h. The realistic estimate remains symbolic because neither is measured.

Incumbent prior-array logical reads are approximately 8P to 16P bytes depending
on short circuit; vector scans demand both endpoints, 16P. These are repeated
cache accesses, not DRAM-byte counts. The bounds success path eliminates those
prior-array reads. Its likely residual bottleneck is token walking, typed
constant evaluation, or inconclusive scalar search—not SIMD arithmetic.

The standalone pipeline charges 16n raw bytes read, normalization and 16n
normalized bytes written, per-call allocation/free, dispatch and result
materialization. The sorted version adds 32n peak scratch, an initial 16n read
plus 16n write copy, about 32n logical bytes per merge level, and final scan.
Raw input generation, input hashing and warmup are outside timing. Production parser arrays already
exist; lowerer AoS extraction does not. Thus the reproducer is an honest
endpoint pipeline, not the complete compiler producer/consumer chain.

## Sorted certificate: remove an unnecessary recurrence

Sorting by low endpoint makes a Boolean no-overlap proof exceptionally simple:
every adjacent pair must satisfy `high[i] < low[i+1]`. No prefix maximum is
needed. If interval i overlaps any later j, sorted lows imply
`low[i+1] <= low[j] <= high[i]`, so an adjacent overlap exists.

The scalar iterative mergesort is the principal general-order competitor.
After sorting, adjacent comparisons could be independent SIMD blocks, but
sorting/copy traffic dominates unless census and timing say otherwise.
Do not optimize a prefix-max scan that the question does not require.

The first sorted collision is **not** the first source diagnostic. For example
source order [0,10], [3,4], [1,2] first fails on source item 1, while sorted
adjacency first exposes source item 2. On a failed certificate, replay original
source order and original diagnostic calls. The online proof avoids this
whole reordering problem and is the preferred first slice.

## SIMD lane and mask design, and the observed failure of the intended lowering

For each current interval, an eight-pair tile uses one ZMM of prior lows and
one ZMM of prior highs. Two unsigned LE comparisons form overlap predicates; their
AND indicates any collision. No selected values need materializing and no
compression is useful. Maintain current-case source order; only comparisons
against already-inserted intervals are independent. Scalar tails avoid invalid
memory and keep partial-mask logic out of the first implementation.

In principle, independent comparisons plus KAND keep predicate depth shorter
than feeding one comparison mask into the second. In the **actual GCC 13.3
binary**, however, the compiler emitted:

```asm
vpcmpleuq k1, zmm2, zmm1
vpcmpleuq k0{k1}, zmm0, [previous_high]
kmovw     ecx, k0
test      cl, cl
```

The second comparison has a real mask dependency. The 2/4/8-tile controls
also use one KMOVW per tile and scalar ORs, not one persistent k-register
reduction. U8 names ZMM0–7 and all k0–7, with a k0-to-k1 move because k0 cannot
be a writemask; it saves extra scalar registers. No vector spills were found.
The scalar/hull predicates remain scalar; the sort uses XMM for 16-byte record
copies. Autovectorization was disabled explicitly.

This is a validated **lowering negative**, not a measured slowdown. Intrinsics
are not proof that a mask remains in k registers. The trusted Clang producer
must be disassembled separately before an integration claim.

## Correctness and observable behavior

- Inclusive equality is overlap. Never use `high+1`, signed subtraction or
  host signed overflow to test it.
- Preserve promoted target width/sign, truncation, enum/bit-field rules,
  GNU-dialect refusal and all constant-evaluation ordering.
- Empty/singleton cases initialize state explicitly; defaults and malformed
  cases are not ordinary intervals. Nested switches own their cases.
- The semantic loop continues after diagnostics. Its selector keeps the earlier
  diagnostic on equal order tokens; no new early return is permitted.
- Sorted proof copies do not reorder dispatch cases, labels, CFG blocks or
  canonical immediates. Existing arrays remain available for failure replay.
- Full vector loads require an in-bounds block; tails use scalar reads. There
  is no gather, speculative invalid pointer or masked-off C evaluation to
  justify. Guard-page tests exercise exact allocation/page ends.
- Reproducer raw inputs may alias read-only; normalized work arrays and sort
  scratch are separate. A future in-place/overlapping API is not established.
- Portable scalar fallbacks remain required; production SIMD must use
  `simd.h`, feature/compiler guards and self-host-compatible vocabulary.
  The isolated host experiment uses intrinsics to compare exact widths; it is
  not a proposed new production dependency.

## Speculative extension: carry a proof, not an unqualified boolean

Normal compilation checks interval validity again in lowering. A per-switch
C-owned plan could retain normalized pairs, ordered label tokens and a proof,
then lowerer conversion could compare the exact pairs while already visiting
them, eliminating its quadratic scan.

**Do not use `analysis_complete` for this.** Current legacy
`c_analyze_semantics(validate_lowering_constraints=false)` also sets that bit.
Moreover parser and lowerer use different typed-constant conversion paths.
A plan must bind token-stream/range identity, target/dialect, promoted
width/sign, ordered labels and model lifetime; copied/unvalidated/direct
lowering models require fallback. A hash-only equality is insufficient.

This costs at least 16n retained endpoint bytes plus token identities and
ownership metadata unless existing storage is made persistent. There is
normally one reuse; retaining scratch can increase peak RSS and parallel
working sets. The break-even is saved lowerer probes minus retained-memory,
exact-pair comparison and lifetime bookkeeping. Reusing folded constants as
well is a separate, stronger semantic claim.

Falsify this extension by tracing actual repeated conversions and comparing
parser/lowerer normalized pairs on all target data models and both frontend
SSA forms. Any mismatch or insufficient duplicate cost stops the reuse design.
It remains speculative and is not the first implementation experiment.

# 2. PDB merging: stable lineage instead of repeated map composition

## Current computation and why it might already be good

[`pdb_build`][pdb-merge] normalizes per-module type records, then performs
at most eight rounds of stable equality merging. Each round keeps the first
equal record, rewrites surviving record references through `round_map`, and
updates every original `final_index` entry through that map. Later it
[composes module-local maps][pdb-consumer] and rewrites symbols.

This is Windows/PDB-producing link/debug work, with callers at
[hosted PE linking][pdb-link1] and [the second PE link path][pdb-link2].
It does not accelerate ordinary Linux object compilation or ELF linking.
No present N/round-count distribution or exclusive cost has been measured.
Hashing and record-byte rewriting may dominate; an eight-round limit already
bounds the repeated work. Most inputs may merge in zero or one round.

The novel application is the **lifetime of the final renumbering map**, not a
new hash table, interner, equality policy, type graph or recursive-type solver.
Prior SSA root-flattening proposals concern different representative semantics
and do not establish this stable ordinal invariant.

## Proposed computation and proof

`live[]` starts in original order. Each round visits it in order and preserves
first representatives, so every subsequent `live[]` is an ascending subsequence
of original record IDs. When a child merges into an earlier survivor,
`parent_original < child_original`. A retired record never returns to live.

Reuse `final_index` as a link array, without its eager identity fill:

```c
/* Only for an existing match, before creating any new survivor. */
final_index[live[position]] = 0x1000 + survivors[match];

/* After the same termination/cap; live[] is ascending original IDs. */
u32 root_cursor = 0;
for (u32 original = 0; original < total_type_record_count; original += 1)
{
    if (root_cursor < live_count && live[root_cursor] == original)
    {
        final_index[original] = 0x1000 + root_cursor;
        root_cursor += 1;
    }
    else
    {
        u32 parent = final_index[original] - 0x1000;
        final_index[original] = final_index[parent];
    }
}
```

A surviving root is written before any greater child reads it. A parent that
retired in a later round is likewise finalized earlier in the ascending walk.
Every nonroot link was assigned exactly once when it retired. Therefore one
indexed read resolves each child, including chains; no pointer-jumping rounds
or recursion are necessary. Keep `round_map` for the existing survivor record
rewrites. Do not merge more recursive records or run more rounds.

This reuses the existing 4N-byte allocation and requires no N-sized parent
sidecar, transposition, sorting, compaction or reconstruction beyond the map
that callers already consume. Hash collisions still take the same exact
byte-equality path and stable first representative.

## Cost, alternatives and SIMD boundary

For N originals, R merging rounds and F final survivors:

- Current final-map writes: N(1+R).
- Proposed writes: N+(N−F), including one link write per retirement.
- Current composition loop's logical traffic is roughly 12NR bytes
  (map read, round-map read, final-map write), plus 4N initialization bytes.
- Proposed link/finalization traffic is approximately 4F+16(N−F) bytes,
  excluding live/survivor-list reads and unchanged merge work. This is cache-level
  logical access accounting, not DRAM traffic.

An empirical break-even is

`N×R×c_compose + N×c_init > (N−F)×c_link + N×c_finish`,

with instruction, branch and cache effects included in those costs.
Bandwidth bounds use the maximum of loads/stores and scalar dependency
requirements; do not add all resources as independent serial costs.

The strongest no-merge scalar control is important. Current identity fill is
fused with live-array initialization; a separate final walk can regress it.
Use an explicit no-merge identity path when measuring, or separately prove
that the consumer can skip identity composition. The model does not assume
that follow-up is free. One-round all-at-once merging also saves almost nothing.

A vectorized current composition is a fair width competitor if this phase is
material: load current IDs, gather round_map and store. But it retains R full
passes and irregular map traffic. The final parent walk has within-block
dependencies; a gather of unresolved parents is incorrect. Masking parent<tile
and scalar-fixing other lanes adds classification/extraction and can erase the
work-elimination advantage. Do not force SIMD on a linear scalar result.

The optimistic improvement removes R−1 bulk passes when R is large. Realistic
limits are the final earlier-parent load chain and unchanged hashing/record
rewrites, with cold parent cache lines potentially exposing latency. Parallel
partitioning must respect the ascending parent dependency and is unnecessary
for the first slice. The design does not amplify retained memory.

## Executed falsification and limits

The independent Python model compares exact current round-map composition
against poisoned-storage retirement links over arbitrary stable equality
partitions:

- 18,972 exhaustive complete transcripts for N=0..6.
- 20,000 deterministic randomized transcripts with N<=512, reaching eight rounds.
- Zero map mismatches, repeated retirements or poisoned reads.
- Controls include empty/no merges, one-round collapse and an eight-round
  retiring-root chain.

| Model control | N / R / F | Current writes | Proposed writes |
|---|---|---:|---:|
| No merge | 16 / 0 / 16 | 16 | 16 |
| One round, all equal | 128 / 1 / 1 | 256 | 255 |
| Eight-round retiring-root chain | 128 / 8 / 120 | 1,152 | 136 |

These are **model write counts**, not instruction counts, bandwidth or timings.
The one-round result is a retained negative control. The model does not parse
PDB records or validate real PDB bytes. Preserve u32 bias/count overflow checks,
zero records, exact eight-round cap, error return order, module identity and
invalid references in any future C implementation. Failed rewrites still exit
before map consumers; no success result may read partially established links.

Next falsifier: count N/R/F and map-exclusive time during current PDB-producing
workloads, then compare whole PDB emission including normalization, merge,
rewrites and final output. If zero/one round dominates or map-exclusive cost is immaterial, defer.
Treat cold-parent latency as an experiment dimension, not a reason alone to reject.

# Focused Zen 5 model

AMD's [optimization guide 58455 revision 1.00, released 2024-08-15][amd-guide]
and its included latency spreadsheet were inspected and hashed.
[uops.info][uops-background] identifies its Zen 5 CPU as **Ryzen 7 9700X**.
Those measurements apply to the desktop implementation, but are not
measurements of this user's host, firmware or binaries.

The guide describes four 512-bit FP/packed-integer execution pipes. Eligible
resources vary by instruction. It permits at most two vector loads/cycle and
one 512-bit store/cycle, not four arbitrary 512-bit operations or loads.
The hardware appendix distinguishes documentation, original measurements and
unknowns; its source identities are retained.

|---|---|---|---|---|

| VPCMPUQ k{k},zmm,zmm,imm8 | F | Vector or mask→k 6 | 0.50 | 1 / FP12 |
| VPCMPUQ k,ymm,ymm,imm8 (EVEX) | F+VL | Vector→k 4 | 0.50 | 1 / FP12 |
| VPCMPUQ k,zmm,m512,imm8 | F | Register→k 6; load→k not asserted | 0.50 | 2, compare plus load |
| VPCMPUQ k{k},zmm,m512,imm8 | F | Register or mask→k 6; load readiness separate | 0.50 | 2 |
| VPCMPUQ k{k},ymm,m256,imm8 | F+VL | Register or mask→k 4; load readiness separate | 0.50 | 2 |
| KANDW / KORW k,k,k | F | 1 | 0.50 | 1 / FP03 |

| VPBROADCASTQ zmm,r64 | F | Upper bound <=8; AMD aggregate 1 | 1.00 | 2 |

Exact-form URLs and resource/dependency qualifications are in
[hardware.md](evidence/2026-09-22T043954Z/hardware.md). Site labels are not a
one-to-one physical-pipe map; “FP45” does not contradict the four arithmetic
pipes by implying two additional arithmetic pipes. Required mask extraction in
the actual binary is KMOVW; KMOVB would additionally require DQ.

For an ideal normalized eight-pair tile with two loads, two independent
comparisons and mask AND/OR, a steady-state resource bound is

`max(2/2 loads, 2/2 compares, 2/2 mask ops) = 1 cycle per tile`.

This excludes broadcasts, branch/extraction, loop frontend, tails, allocation,
normalization and cache-line splits; it is not a predicted kernel throughput.
Ready-register predicate depth is approximately 6+1=7 cycles for independent
ZMM compares plus AND, versus 6+6=12 for the emitted dependency chain.
EVEX256 gives corresponding 5 versus 8 cycle models at half the lane count.

With a one-tile/cycle resource target and 12-cycle chain, roughly twelve
in-flight tile chains would be needed to hide that dependency fully, before
accounting for load readiness and extraction/branch lifetime. This does
not imply twelve source-unrolled tiles are desirable: early-exit decisions,
mask/GPR pressure, frontend size and small arrays prevent that ideal. The
1/2/4/8 controls test the relevant trend rather than assuming four is right.
No variant's unroll factor has been selected by timing.

Dispatch checks XSAVE/OSXSAVE/AVX, XCR0 bits `0xe6`, then exact F/VL/AVX2 bits.
The local experiment observed XCR0 `0xe7` and executed the variants on an
**EPYC 9V74 KVM guest**, for correctness only. Broad “AVX-512 supported” is not
used to infer subset or OS state.

| Eight source tiles imply eight cheap k-register chains | Assembly extracts masks per tile and increases GPR/mask pressure |
| Broad semantic absence flags | Existing C_PARSE_DECLARATION_RANGE_KEYWORDS and CTokenPositionIndex already implement this mechanism |
| Global relocation sort/prefix overlap test | Explicitly proposed in prior 2026-09-13T132324Z audit; duplicate |
| Sparse IR extra sorting/permutation join | Real full-payload movement, but old profile has only 151 extra additions; no current materiality |
| Lazy machine dominance build | Ordinary producer-certified route bypasses the verifier; helps explicit validation, not established normal compilation |
| PDB one-round merging as a large map win | 256 versus 255 modeled writes in the adversarial control |
| Blind semantic proof reuse | analysis_complete also marks unvalidated legacy models; conversion paths differ |
| Lexer/hash/allocator/encoder/bitset topics and #950–#953 | Explicit exclusions / existing owners |

The sparse-extra alternative is still technically concrete:
sort 8-byte (new instruction, old extra index) keys and move the 56-byte
payload once, rather than sorting 64-byte full records each merge level.
Its 16E scratch versus 128E current scratch is a model, not a speedup.
Historical rarity and no current census justify no new issue for it.

# Next engineering decision

The **single best first implementation experiment** is one local change in
`c_parse_validate_one_switch`: normalize existing endpoint arrays on insertion,
then add the two-extrema proof before the original source-order loop.
Leave lowering checks and shared representations unchanged for this slice.

1. Obtain a diagnostic-only executed census on the pinned trusted compiler:
   n, actual pair probes, hull successes, residual probes, signedness/width,
   range frequency and exclusive validator time. Use frozen self-host inputs,
   current tracked C fixtures, and admitted real-source inputs. Keep
   instrumentation out of timing binaries.
2. Compare incumbent, normalize-only, and normalization+online bounds with
   identical trusted Clang build paths/flags. Disassemble that exact producer.
   The supplied scalar baseline already covers normalized comparisons; it
   cannot substitute for this integration ablation.
3. Preserve structured/rendered diagnostics, source order and bytes, both
   frontend SSA forms, targets and applicable modes. Run the current regression,
   sanitizer and self-host fixed-point gates for the production experiment.
4. On authorized benchpress execution, establish A/A resolution first, then
   fixed paired A/B and a fresh held-out confirmation. Freeze the corpus,
   repetitions and decision rule before looking at variants. Reject changes
   indistinguishable from the noise floor or harmful to small calls.
5. Only if residual pair work remains material, test the sort and width
   competitors around measured break-even. Do not add vector machinery merely
   because the standalone test passes.

**Expected benefit range:** unknown wall-time gain, with zero a plausible
outcome. On outward sequences, P pair probes become n−1 bounding proofs
(exact work-count reduction, not equal-cost speedup). At the static library
median n=10 this replaces 45 pair probes with nine proofs, while all parsing
and constant evaluation remain. No credible whole-compiler percentage can be
assigned until the exclusive fraction f is measured.

For a measured local speedup s, optimistic whole-compile speedup is
`1 / ((1−f)+f/s)`, before overhead. f and s are currently **unknown**, not
zero and not borrowed from historical backend profiles. A hypothetical f=1%
and s=2 would give only about 1.005x; this is a sensitivity example, not an
estimate. Never add the two switch verifiers' inclusive costs or native/PDB
paths as overlapping gains.

**Confidence:** high in the interval algebra and source-order safety of the
local guard; moderate in integration feasibility; low in material speedup.
Integration cost is small for the scalar local slice, larger for sorting,
and substantially larger for proof ownership across phases. The decisive risks
are target normalization/diagnostic preservation, tiny populations and spill
or guard overhead. No extra retained memory is required locally.

For PDB, retain a narrowly scoped research issue at `status/needs-census`.
Its first question is N/R/F and exclusive map share, not an AVX-512 rewrite.

# Prior art and source interpretation

The useful transfer from certifying algorithms is to make successful
verification cheap while retaining an exact checker for difficult results,
and to bind any reused fact to its inputs. This packet does not claim a formal
independently verified certifying implementation; see McConnell, Mehlhorn,
Näher and Schweitzer's [primary survey][certifying].

SIMD range predicates and storage-layout tradeoffs also appear in
[Rayhan and Aref's R-tree research][rtree]. This packet transfers simple
bounding predicates, not their tree architecture or reported speedups.
The PDB transformation uses ordinary ordered representative-forest reasoning;
no worldwide novelty or new union-find bound is claimed.

Pinned Buster sources, exact-form hardware references and artifacts are the
evidence. All timing benefits and production integrations remain hypotheses.
