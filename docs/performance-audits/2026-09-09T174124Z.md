## Coverage and implementation

Base `ef99ec72cf0f17c8818a1d4b4c106fd5908b5eae` is PR #359's merged,
fully validated tree. Windows x86-64 aggregate parameters such as a
sixteen-byte value still forced signature fallback, while callers with those
arguments fell back at `CALL`. The focused five-function input had four
signature fallbacks and one opcode fallback. All five now use MIR.

The selector uses the existing canonical Win64 ABI classification. Indirect
aggregate arguments occupy one positional pointer slot, including stack and
variadic arguments. The caller copies exact value bytes into storage aligned
to sixteen bytes after the shadow and stack-argument area. Separate calls
reuse the largest outgoing reservation; they do not retain one copy area per
call site. Complete reservations are checked in wide arithmetic before frame
displacements are narrowed. These rules follow the [Microsoft x64 calling
convention](https://learn.microsoft.com/en-us/cpp/build/x64-calling-convention?view=msvc-170).

Incoming register pointers are captured before floating bridges, and stack
pointers are captured next. Parameter objects are materialized only after
both capture passes finish. Outgoing pointer registers are staged after the
floating bridges. Hidden result pointers continue to occupy the first
positional slot. Existing copy and address rows implement the change; there
are no new opcode identities or expansion recipes. The direct emitter is
unchanged.

GDB's debug-type census of both immutable Clang Release compilers reports
`sizeof(MachineX64CallPlan) == 280` and `sizeof(MachineX64ValueShape) == 36`.
The new outgoing-size field fits existing call-plan padding. The callee
capture walk adds a bounded 24-entry array of 32-bit virtual-register indices;
only captured entries are read. Persistent hot MIR record sizes are unchanged.

This does not close #36. Windows vectors, 128-bit integer signatures,
alignment requirements above sixteen bytes, other target gaps and production
fallback retirement remain. Windows anonymous aggregate reads still have
their existing sixteen-byte limit; the larger anonymous values in this corpus
are consumed by the independent Clang callee.

## Measured tradeoff

On the Windows aggregate input, compiler instructions fall 12.740902% and
CPU time falls 6.029387%; object size falls from 16,185 to 12,181 bytes
(-24.738956%). Generated code falls from 14,555 to 10,513 bytes, maximum
frame size from 3,808 to 1,552 bytes, and fallback functions from five to zero.
Peak RSS rises by 1,304 KiB (+2.366606%).

The full Linux compiler keeps the same output size and zero fallback.
Instructions rise 0.040379% and peak RSS rises by 1,256 KiB (+0.134348%).
CPU time falls 0.448052%. The much larger wall-time decrease is noisy and
is not evidence of a stable latency improvement. The AArch64 and small Linux
controls retain their generated output sizes, with minor instruction increases
and peak RSS increases of 1,044 and 1,220 KiB respectively.

The complete native differential matrix passed all 6,480 comparisons
(eleven permanent cases plus four generated cases, each with 432 configurations),
with sanitized Clang O0/O2 references and the original ten-second child deadline.
The TCC build driver was rebuilt after adding the permanent case, and the
harness self-test passed. Hosted checks are pending at audit publication.
