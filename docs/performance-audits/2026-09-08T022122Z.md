This is a bounded forwarding-object microbenchmark, **not** an end-to-end
compiler-throughput result or a merge-ready gate. The recipe replaces a raw
x86 instruction exception with three checked metadata emissions once per
process and fixed-size copies thereafter. It changes no output bytes.

## Sources and method

The available complete source is CI snapshot
`0febbc50c7d0956fdb66e6f7e63499ec2d62573b`. The metadata implementation/header
were restored to inspected main `9f6e933aaab6fd95cbe23cd9efa3bcc4b3d0c0d5`
and verified by Git blob SHA-1 (`46602bf4d5588157e976174125f9fa20b3bd7c32`
and `debe29f9e0aca944361928fa686567ad9449b5f7`) before adding this patch.
The baseline forwarding helper is identical to the inspected main helper.
Other support modules are from the older snapshot; this is not a complete
current-main checkout.

Both probes use Clang 17, `-O1 -g0 -fwrapv -fno-strict-aliasing -funsigned-char`,
function/data sections and LLD garbage collection, with tests enabled to match
the diagnostic objects. The same metadata/support objects and frozen
[probe](2026-09-08T022122Z-probe.c) are linked to old/new `link.c` objects. No LTO.
The probe prewarms the metadata decoder before timing the first ELF object,
then performs 1,000 warmups and 250,000 timed constructions. It rewinds the
same arena each iteration and consumes output bytes and relocation offsets.
Checksums agree for every sample.

One untimed process per executable precedes 12 pairs in alternating order on
an unpinned shared Xeon Platinum 8370C (affinity CPUs 0-4). Each process reports
`CLOCK_MONOTONIC` intervals. [Raw samples](2026-09-08T022122Z-samples.json) are retained.

| Measurement | Raw helper | Metadata recipe |
|---|---:|---:|
| Median decoder prewarm, excluded from the next rows | 46.811 ms | 47.554 ms |
| Median first object after decoder prewarm | 1.327 us | 2,154.595 us |
| Median cached construction of a two-stub object | 109.246 ns | 111.527 ns |

The median paired cached ratio is 1.0249; a percentile
bootstrap interval from 10,000 resamples (seed 267) is
[0.9581, 1.0696]. Tiny absolute differences are not evidence
of compiler-throughput parity. The first-use cost is a real tradeoff: the
checked XOR/JMP forms are prepared lazily, not for every stub. Ordinary
metadata decoder initialization is separately reported rather than hidden.
No hardware-counter, Zen 5, self-hosting, or full-compiler timing is claimed.

## Validation and limitations

See [the forwarding migration contract](../x86-64-forwarding-authority.md).
The focused production-code runner passes 13,113 assertions serially and per
worker in a four-lane gang. ASan+UBSan passes 13,110 per run/lane; the three
native JIT assertions use the existing non-sanitized JIT-test policy.
The all-forms readiness check returns zero unprepared entries. An isolated
three-byte-XOR fault injection passes 600 checks for unchanged output and
empty error objects without arena allocations; the mutant is not production
code. GNU as and LLVM match both instruction sections and field placement.

The full Release build was attempted but Clang was OOM-killed compiling the
existing giant `x86_64_metadata_test.c` under the 4 GiB cgroup limit. The
canonical self-host command fails because TCC is absent. The build driver
was bootstrapped diagnostically with Clang, and LLD replaced unavailable mold.
The full current-main suite, all allocator/target modes and self-host fixed
point are **unpassed**, not waived. No hosted CI or PR publication occurred.
