## Workload

The arms compile the base revision's unity self-host source from a pristine
checkout of the base:

```sh
ide cc -Isrc -Ibuild/v3/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -fsyntax-only \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

The four arms:
- A: base, default flags;
- B: base with `-fc-ast-pilot`;
- C: candidate with `-fc-ast-pilot`;
- D: candidate, default flags.

`-c` uses the same input with `-c -o`, at `-g0` for instructions and at `-g0`
and `-g` for object identity. Callgrind ran with `--cache-sim=no
--branch-sim=no`. Inclusive and per-line costs come from `callgrind_annotate`.

## The change

All of it is in `c_parse.c`, on the default path, with no tree:
1. **The replay.** While `c_parse_infer_file_array_bounds` walks a list,
   the walk logs each element check it would make (destination type and
   token range). It logs into the walk's scratch, and at most one entry per
   two tokens. A walk keeps its log only when it reached the frame loop and
   met no designator, brace elision, vector, evaluated bound, nested string
   branch or aggregate-expression query. A kept log goes to the phase arena,
   indexed by array bound. `c_parse_validate_initializer_shape` replays it
   when the bound still holds the walk's count and the range matches. It
   makes the same checks in the same order and stops at the first failure.
2. **The inline end.** A one-token scalar element followed by a comma or
   the limit ends after its token, without calling
   `c_parse_initializer_value_end`.

Debug and sanitized builds (`BUSTER_REFERENCE_CHECKS`) re-walk every
replayed list in a record-only mode and compare its elements with the log.
They also run the end scan behind every inline end.
