## Decision

`c_ir_type_name_prefix` resolved every `struct`/`union`/`enum TAG` type name
that lowering met by walking the whole parse type table, with no early exit:
K names × T rows. It also made one `c_parse_scope_for_token` call per name.
Such names come from casts, `sizeof` and compound literals.

The parse-side aggregate-tag index (`CAggregateLookup`, #291) already answers
whether a `(kind, tag)` has no row, or exactly one live row:

- an unused slot on a complete index means no row;
- a live slot not marked `multiple` is the only row.

In both cases that is the only possible answer from any reference scope. The
old loop takes the first match unconditionally and replaces it only with a
strictly closer one.

Lowering now asks `c_parse_aggregate_unique` first. It keeps the unchanged
search, with its first-at-equal-distance tie-breaking, only for duplicated,
stale or incomplete keys.

Why the fast path is safe:

- **Index invariant.** While the index is complete, the only live row that can carry a key is the slot's row, unless the slot is `multiple`. The proof is by induction over insert, rollback, growth and grow failure. In-place mutations never touch `kind`, `tag` or `has_unqualified_type`, and `incomplete` is sticky.
- **The table is final.** A static call-graph sweep of the 1,288 frontend functions finds no path from `c_gen.c` to `c_parse_add_type`.

The full argument is in #1467.

**Main's law.** In this family main visits exactly 2Q · type_count rows, with type_count = 4T + 13Q + 32. Every reference also interns types, so the work is quadratic in Q alone.

**The candidate.** It scans nothing for unique tags. In every measured real input, every tag name is unique.

**The shadow family** keeps the original scan by design. At T = 16,000 the remaining time is the #1382 definition scan (#1455).
