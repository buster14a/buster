## Change and ownership

`-fcompile-jobs=N` now permits native function lanes in a single translation
unit. The existing persistent `lane_run` gang takes variable-sized functions
by atomic index and stores results in stable emission-indexed slots. A cohort
holds at most four pending functions per requested worker; the sum of its
conservative scratch bounds also limits retention. Workers share immutable
canonical rows and the machine type projection and own their ABI cache pages,
x86 signature plans, source cursors and output arenas. CFG and assembly-label
publication run serially before workers start. Selection, optional MIR
verification, allocation, QUALITY scheduling and private encoding run on lanes.
Code layout, relocation/label resolution, assembly placement, debug locations,
line suppression and unwind publication remain ordered.

One lane enters the same kernel with the original program/cache ownership and
per-function scratch, then encodes in place. A translation-unit gang clamps
function lanes to one; explicit single-threaded builds and bootstrap tracing
also stay on one lane. The work gate caps width at the permitted logical CPU
count, lowered population and 4,096 IR instructions per worker. Omission and
`N=1` keep serial execution. No frontend ownership or generated/native-retirement
authority was changed. References: [#54](https://github.com/buster14a/buster/issues/54),
[#908](https://github.com/buster14a/buster/issues/908) and
[PR #4142](https://github.com/buster14a/buster/pull/4142).

## Profile and scaling bound

A fresh baseline `cycles:u` profile at 1,999 Hz retained 3,940 samples with
zero lost samples. Inclusive user-cycle samples place frontend orchestration
(`c_analyze_with_options`) at **54.42%** and native codegen orchestration at
**23.27%**. Selection accounts for 8.07%, FAST placement's prepassed body 3.64%
and machine encoding 3.41%. These are sampled attribution, not paired elapsed
measurements. Treating the entire 23.27% codegen region as perfectly parallel
would bound an eight-worker full compile near **1.26x**; this implementation
keeps publication serial and also pays scheduling/retention costs. The observed
result is consistent with that bound and does not imply linear whole-compiler
scaling.

The frozen input emits 6,415 functions. Machine code sizes have median 674 bytes,
p90 4,398, p99 28,380 and maximum 223,672. This is a work-skew proxy, not measured
per-function duration. The dynamic take-index handles varying work within a
bounded cohort; remaining cohort tail imbalance is not claimed solved.
