## Change

Both native selectors already decoded every canonical operand once, in their
first target-order row walk. The classification pass was the remaining
full-row re-entry: it walked every 64-byte `IrInstruction` in layout order,
rows without a result included, to rediscover each row's result and opcode.
The walk now appends a 12-byte `MachineSelectionResultRow` (row, value,
opcode, unary operation) for each result-defining row, with per-block offsets,
and classification reads that projection in layout order. Only `ARGUMENT`
re-reads its row, for the immediate.

Two earlier shapes of the same projection were measured on the generated
corpus below and rejected:
- an indexed store with an explicit zeroed `reserved` field cost +0.43% (x86-64)
  and +0.78% (AArch64) selector Ir. The walk's fields were reloaded after the
  value-indexed stores, which may alias the row without strict aliasing, and
  the extra live variables spilled;
- a write cursor without the reserved field cost +0.16% and −0.58%.

The kept shape writes the record before those stores and reuses the
already-loaded result value.

## Workloads

- **Generated corpus**: 800 functions with loops, forward gotos, a
  three-word struct parameter and local, pointer and small-struct arguments,
  calls, a variadic call and a switch, from this generator with
  `python3 make.py 800 m.c`:

  ```python
  import random, sys
  random.seed(132)
  out=["struct W { long a, b, c; }; struct P { int x; int y; };",
       "extern long sink(long); extern long take(struct W); extern int vf(int, ...);"]
  for i in range(int(sys.argv[1])):
      k=random.randint(2,6)
      out.append(f"long f{i}(long a, int b, struct W w, long* p, struct P q) {{")
      out.append("  long s = a; int t = b; struct W c = w; unsigned u = (unsigned)b; double d = (double)a;")
      for j in range(k):
          out.append(f"  for (int i{j} = 0; i{j} < t + {j}; i{j} += 1) {{ if (p[i{j}] & {j+1}) s += p[i{j}] * c.b; else s -= i{j} ^ q.x; u = u * 33u + (unsigned)s; }}")
          out.append(f"  if (s > {j*7}) goto l{j}; s = sink(s + c.c); d = d * 0.5 + (double)s;")
          out.append(f"l{j}: c.a += s; t = t + (int)(u >> {j});")
      out.append("  switch (t & 7) { case 0: s += take(c); break; case 1: s ^= q.y; break; case 3: s = vf(t, s, d); break; default: s -= (long)d; }")
      if i: out.append(f"  s += f{i-1}(s, t, c, p, q);")
      out.append("  return s + c.a + (long)u; }")
  open(sys.argv[2],"w").write("\n".join(out)+"\n")
  ```

  Each arm runs `ide cc -target {x86_64,aarch64}-unknown-linux-gnu -c m.c`.
- **Unity self-host**: the base checkout's `src/buster/apps/ide/ide.c` with
  the CMake Release definitions, `-DBUSTER_INCLUDE_TESTS=0` and
  `-DBUSTER_UNITY_BUILD=1`, compiled `-c` for x86-64 Linux.

Callgrind ran with `--cache-sim=yes --branch-sim=yes` and
`--toggle-collect=machine_select_canonical_function_{x86_64,aarch64}`, so
each figure is the selector entry point inclusive of its callees.

## Reading

- On the x86-64 corpus, line attribution puts the classification pass at
  10.53 M → 9.07 M Ir, with its D1 read misses falling from 210,889 to 71,012.
  Rows without a result no longer reach it, and the rest are 12-byte records
  instead of 64-byte rows.
- Building the projection is not free. On the same corpus, the first row walk
  rises from 16.64 M to 20.01 M Ir for 189,000 records. The record's own
  stores are about 1.9 M of that; the rest is register pressure in that large
  loop. The write misses rise because the projection is new scratch.
- Line attribution cannot close the remaining balance. About 1.8 M of the
  selector's Ir sits on lines without debug information, and inlining from
  `machine.c` and `machine_select.c` differs between the two builds. The net
  −0.61 M is therefore the walk's cost and the classification saving plus a
  rebuild-layout term of unknown sign. An A/A rebuild control was not run.
  The same caveat applies to the AArch64 and self-host totals.
- Valgrind's cache model has no hardware prefetcher. The classification pass
  read rows block by block in sequence, so real hardware hides more of the
  base's row misses than this census shows. The instruction and branch
  reductions are the parts that transfer.
- Hosted native wall time on the self-host does not resolve the change: the
  medians of six interleaved runs each are base 6.554 s and candidate 6.546 s,
  with ranges of 6.17–6.82 s and 6.30–6.91 s.

## Validation and limits

- One host, no pinning and no `perf` counters. Callgrind is deterministic for
  a given binary, but a rebuild moves the selector's code layout. That noise was
  not measured separately here; the previous audit puts rebuild noise near
  0.03% of whole-compile Ir.
- The AArch64 self-host could not be compiled on this host without target
  headers, so AArch64 rests on the generated corpus and the selector tests.
- Zen 5 validation of selection retired instructions, branch misses and L1D
  misses therefore stays **incomplete** (#2761). The 9700X comparison after
  merge is the route for it.
