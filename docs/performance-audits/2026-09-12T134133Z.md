## Algorithm and semantic controls

Both positional archives and `-l` archives now use one extraction implementation.
An invocation-owned name index records selected definitions and strong/weak
undefined references. Newly selected objects update it once. An archive indexes
its global definitions into provider lists. Each state bit is monotonic, so a
provider edge is visited at most three times. A heap orders candidates by scan
pass and member position; newly needed members behind the cursor wait for the
next pass. A FIFO or plain minimum-member queue would change weak duplicate
winners. Resolved queued candidates are discarded; another dependency may
reactivate a member later.

Expected indexed work is O(S + A + D log(M + 1)), for S selected symbols, A
archive symbols, D definition edges and M members, plus symbol-name hashing.
Earlier archives are not revisited implicitly. Definitions of either strength
suppress extraction. Undefined weak references do not extract ELF members;
COFF/Mach-O retain their existing policy. Direct objects between archives and
explicit repeated archives retain their command placement. Runtime singleton
selection keeps its existing binding policy.

The first measurement exposed a roughly 10 µs table/arena floor. The final
implementation uses a bounded stack scan before creating state when there are
at most eight selected objects, eight members and 32 total symbols. It also
uses one indexed forward pass for archives without undefined global symbols:
those members cannot create new requests, so irrelevant definitions need no
provider index or retained name. Existing-key lookups no longer trigger an
unnecessary table growth at half capacity.

The registered tests retain an independent forward-scan oracle. They compare
exact selected ObjectFile sequences across archive occurrences, link errors and
error symbols, and byte-identical successful ELF, COFF and Mach-O artifacts.
There are 128 deterministic seeds per format, with duplicate/weak/local/global
symbols, plus fixed cycles, a stale candidate reactivated by a later dependency,
weak-only references, empty inputs, direct objects between archive occurrences,
and forward/reverse/sparse populations. The fixed weak duplicate case also
requires the winning data byte to come from the later-in-the-current-pass member.
Fixed ordering tests explicitly initialize state so they exercise the worklist;
ordinary small dispatch is covered separately by the scaling populations.

The small archive floor is removed. Reverse chains show the intended scaling
change. The 32-member forward and sparse rows still show several microseconds
of indexing overhead; the change does not claim every archive is faster.
Outliers and concurrent guest work make sub-millisecond ratios especially
unsuitable as hardware acceptance thresholds.

`state_bytes` is the arena's used prefix just before destruction, including
superseded growth tables. It is not RSS. At 512 chain members the current table
is 32,768 bytes, superseded tables account for 31,744 bytes, and provider/member/
heap payloads use another 20,496 scratch bytes (513 × 16 + 512 × 16 + 512 × 8).
The previous selection mask was 512 bytes retained in the result arena.
The new name state is freed before object linking, including on an earlier
invocation failure; per-archive scratch is rewound. No index allocation remains
in the returned result, though thread scratch arenas can retain committed pages
for reuse. Definition-only sparse archives retain only selected names (1,024
bytes for the one-reference rows), not every irrelevant definition.

## Whole-driver artifact, CPU and RSS comparison

Generated 256 ordinary Clang `-O0` objects (`chain_i` returns
`chain_{i+1}() + 1`, and the last returns 1) and archived them in forward and
reverse order. The main object checks the result equals 256. A second root
references only the last member; it tests a mostly unused archive whose other
members contain references, so this exercises the general worklist rather than
the no-reference shortcut. A one-member archive uses that same second root.

Fifteen alternating pairs per population compile/link the same root and archive.
Each output is hashed and executed after timing. **All 120 outputs matched the
baseline bytes and exited successfully.** Raw per-run wall time, per-child CPU
time (`wait4` user + system), peak RSS, input hashes and output hashes are in
[archive-e2e.json](evidence/2026-09-12T134133Z/archive-e2e.json).

The original five-pair capture had large wall-time swings, especially for the
mostly unused case. It is retained as
[archive-e2e-initial.json](evidence/2026-09-12T134133Z/archive-e2e-initial.json).
The follow-up added per-child CPU time and more pairs to distinguish computation
from scheduling delay. CPU time supports the reverse-chain improvement and no
material small/sparse regression in these inputs; it does not establish a
universal win. Peak RSS increased by roughly 0.3–0.4 MiB here, not decreased.
It includes the whole compiler, mapping and allocator effects and cannot be
attributed solely to the index's much smaller measured payload.

The retained [collector](evidence/2026-09-12T134133Z/measure_archive_e2e.py) runs
from the repository root, using `../ide-baseline`, `build/Release/ide` and
`../archive-e2e/`. Generate the inputs with native Clang and `ar` as described
above (`member_0.o` through `member_255.o`, `root.o`, `forward.a`, `reverse.a`).
The collector creates the second root and single-member archive itself.

## Reproduction

Build the ordinary trusted Clang Release compiler, then run:

```sh
BUSTER_ARCHIVE_BENCH=1 build/Release/ide test --ci=1 --verbose=0
```

For the isolated measurement, apply
[focused-runner.patch](evidence/2026-09-12T134133Z/focused-runner.patch) in a
throwaway checkout before building. It replaces only the executable dispatch
with a call to the registered archive tests. The actual focused compile flags
are retained in [probe-command.json](evidence/2026-09-12T134133Z/probe-command.json);
remap its workspace paths to the throwaway checkout. Allocation instrumentation,
sanitisers and LTO were off, and `-O3` was on. The scan oracle and production
extractor are in the same binary and use the same generated input population.

- Final non-unity Debug ASan/UBSan suite with local leak detection disabled:

  `ASAN_OPTIONS=detect_leaks=0:halt_on_error=1` and
  `UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1`.

- GCC syntax/warnings and Clang static analysis of the extraction implementation
  passed with the project arithmetic/aliasing flags.
- The installed TCC cannot bootstrap current `build.c` (`string.c:991`, array

  `-Wno-unused-variable` was needed for two existing `build.c` warnings. No
  repository bootstrap policy was changed.
- LeakSanitizer cannot inspect this container's process namespace. Even a
  trivial single-source compile exits with its `/proc` fatal error. The same
  compile and executable succeed with `ASAN_OPTIONS=detect_leaks=0`. This affects
  subprocess and metamorphic tests as well as shutdown. The corrected local
  sanitizer run keeps AddressSanitizer and UndefinedBehaviorSanitizer enabled;
  leak detection remains an unavailable local gate. CI settings are unchanged.
