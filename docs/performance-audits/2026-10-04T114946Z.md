## Decision

One production change, in the canonical validator: `ir_validate_canonical_function`
now proves everything function-level in one walk over the block chains plus
one sequential sweep over the values nothing defined, instead of a module-wide
ownership pass, a per-value pass and a per-block pass. The leaf predicates are
untouched, the accepted set is unchanged, compiler output is byte-identical,
and the historical three-pass traversal survives in test builds as the oracle
the fused walk is compared against. The second subject of the task,
`c_ir_ssa_finish`, is analysed below to the same depth and deliberately **not**
changed: its remaining cost is inherent to the deferred-sealing design and
every candidate change there renumbers surviving values. Owner: #2626;
implementation PR #2628. Pinned `main`:
`94976eccad9c31776cf264a33dcda960dd8ed51a`; measured source candidate
`91a5199608e80a7ef23b176b4b248b47f7efbc00`.

No local compiler, test or benchmark ran for this audit; every build and
measurement below is a GitHub-hosted run named by id. Hosted timing is
diagnostic, not dedicated Zen 5 acceptance.

## What the two routines must establish

Notation per function: B blocks, E distinct edges (a terminator's target list
has T ≥ E entries, duplicates included), I rows, V values, P block parameters,
A = Σ_parameters incoming (argument slots), O operand slots, L direct-SSA
owners, R journaled reads, W journaled stores, D the longest single-predecessor
chain the forwarding walk can follow (the nesting depth that matters here), S
the number of trivial-parameter sweeps.

### `ir_validate_canonical_function` (ir.c)

Postconditions on acceptance, all unchanged by this audit's change:

- V1 storage: every count with storage has its array; label metadata and
  extras likewise; a published function's dense spans, edge rows, predecessor
  order and argument slices agree with its blocks and terminators
  (`ir_validate_published_cfg`).
- V2 signature: the function type exists, is a function type, has parameter
  storage and an existing return type; `entry < B`.
- V3 ownership: every row id in a chain is `< I`; every row lies in exactly one
  block chain; each chain's last reached row is the block's `last_instruction`;
  no row is outside every chain.
- V4 blocks: terminated and sealed flags set; the chain ends in a terminator
  (`ir_instruction_is_terminator`) and no row follows a terminator.
- V5 parameters: each parameter value `< V`, carried by exactly one parameter
  and defined by no row (`definition == INVALID`, category VALUE); type ids
  agree between parameter and value; `incoming_count == predecessor_count`;
  incoming predecessors appear in the block's predecessor-list order with
  matching ids; every incoming value `< V` with the parameter's type; the list
  ends at `last_incoming`; label provenance when the function carries metadata.
- V6 rows: opcode `< COUNT`; type exists; operand/target/immediate storage
  present when counted; operands `< V`; targets `< B`; a result names a value
  whose `definition` is this row and whose type is the row's type; the
  per-opcode obligations of `ir_validate_instruction_operation`.
- V7 values: type exists; `definition` is a row index, or INVALID for a
  parameter value; label transfer/shape predicates; a nonzero alignment is a
  power of two no smaller than the type's. A value whose `definition` names a
  row that does not name it back is accepted when those predicates hold (an
  existing hole, now pinned by `IR_VALIDATE_TEST_ORPHAN_ACCEPTED`).

What it does **not** establish, before and after: dominance. No dominator tree
is computed anywhere on the default compile path; `c_ir_ssa_finish` is a
Braun-style construction without dominators and the machine verifier's
Cooper-Harvey-Kennedy dominators run only under `-fverify-codegen` or for an
uncertified selector. The task's premise of "redundant dominance work" does not
hold at this revision; the redundancy is traversal.

### `c_ir_ssa_finish` (c_gen.c)

Given the complete terminators, the per-owner operation journals
(LOCAL/LOAD/STORE events with block and anchor row), the sparse
`(block, owner) → value` table and the provisional parameters created during
lowering for reads with no current value in their block, finish must establish:

- S1 each eligible owner is wholly SSA or wholly memory; a memory owner has
  every journaled event restored as a row at its original position
  (`c_ir_ssa_restore_memory`), an SSA owner has no LOCAL/LOAD/STORE row.
- S2 an owner is memory iff its place is still an operand of any row, the
  function has a promotion barrier, or a live read of it may be uninitialized
  (a provisional parameter with no incoming at a reachable block, reached from
  a store RHS or row operand through the incoming graph).
- S3 every retained read is replaced by its reaching definition: a store's
  value, or a block parameter at a join whose incoming list has exactly one
  value per predecessor in the predecessor CSR's (ascending source) order.
- S4 trivial parameters are removed under the runnable/dead-edge rule
  (foundations guide; #1402, #1763), and parameters unreachable from any row
  operand through incoming chains are removed, including closed cycles.
- S5 every block receives its complete predecessor list, parameter-free
  blocks included, and is sealed.
- S6 values are renumbered densely in ascending old-id order; operands,
  parameters, incoming values, local places and label metadata follow; the
  function's operand slices are re-pooled.

## Complexity as implemented

### Validator before (three traversals)

| Pass | Work | Memory touched |
|---|---|---|
| `ir_validate_module_ownership` → `ir_function_instruction_owners`, module-wide first | memset 4I bytes, then one chain walk of I steps reading `next` and writing an owner id, B tail checks, an I scan on shortfall | every 64-byte row once, by `next` (the access scout measured one LL miss per row visited on `object.c`); 4I bytes scratch sized to the largest function |
| `ir_validate_function_values` | B + P parameter list walk; V iterations, each a type lookup, the defining row, its first operand and that operand's value | ~3 dependent random lines per value beyond the sequential 16V bytes |
| `ir_validate_function_blocks` | B; P + A list walks; I rows with O operand and T target checks, one result value per row, the per-opcode checks | every row again, the result value and operand values it names |

Time Θ(B + P + A + I + O + T + V) with the row array streamed twice and the
value array once sequentially plus ~3V random reads. The ownership pass runs
over the whole module before any per-function pass, so on a module whose rows
exceed the last-level cache both sweeps miss: the access scout counts the
validator as 2 of the 8 module-wide row sweeps per validation
([`scout_access.md`](evidence/2026-09-25T223847Z/scout_access.md), section b),
and the trusted tests-on Release compiler validates twice per module
(`BUSTER_IR_TRANSFORM_CHECKS`), the production tests-off compiler once (the
FAST input guard).

### Validator after (one walk)

| Pass | Work | Memory touched |
|---|---|---|
| storage, published spans, signature | O(1) + published check | — |
| block walk (`ir_validate_block_parameter_values`, `ir_validate_block_parameters`, `ir_validate_block_rows`) | B; P + A; I rows with O + T checks; the result value's V7 predicate at its row; a visited byte per row | every row once; the result value the row already loads; operand values as before |
| completeness and sweep | I bytes when the visited count is short; V bytes sequentially, V7 only for values no row or parameter defined | 16V bytes once, sequentially, while the function is hot |

Same Θ(B + P + A + I + O + T + V); the row array is streamed once per
validation, the ~3V random reads of the value pass are gone (the defining row
is the row in hand; its first operand is checked by the row's own operand
loop), and scratch is I + V bytes per function. The checks are the same
predicates evaluated at different sites; the correctness argument is below.

### `c_ir_ssa_finish`

| Phase | Work | Facts produced | Fate |
|---|---|---|---|
| `c_ir_ssa_classify_places` | I rows + O operands; a `log L` search only for an operand that is a promoted place (an escape) | memory owners | kept (bytes) |
| predecessor CSR | 2 × (B + T) with stamps, B prefix | offsets (B+1), predecessors (E) | scratch; publication rebuilds the same topology from the same terminators (2 × (B + T)) and additionally verifies the linked lists it is handed |
| reachability | B + T BFS | reachable (B bytes) | scratch; used by S4; nobody later recomputes it (publication does not need it) |
| pending resolution | for each provisional parameter: one forwarding walk per predecessor, each ≤ D hash probes plus D cache writes; `IrIncoming` per predecessor | incoming lists, new parameters at joins | the cache bounds total forwarding by the number of (block, owner) slots ever filled, ≤ B·L: 2N² + 8N + 7 inserts on the N-diamond family (#1321 census) |
| `c_ir_ssa_classify_initialization` | when some retained owner lacks entry initialization: V + W + O roots, worklist V + A | memory decisions | scratch |
| trivial simplification | S sweeps over active parameters and their incoming; S ≤ removals + 1; backward chains give S = Θ(depth) and O(P·depth) evaluations (audit 2026-09-26T042408Z measured 10,628 sweeps and 2.0M incoming visits for 460K parameters on stage 1, and found an exact agenda worth 0.145% of instructions) | replacements forest | scratch |
| live pruning | 2V clears, O root lookups, worklist P + A | survivors | scratch |
| predecessor lists | E allocations of 16 bytes in the TU arena | `IrPredecessor` lists | permanent; verified then nulled by publication |
| compaction | 2V + I + O + P + A, a fresh operand pool | dense ids | permanent |

Expected time Θ(I + O + T + V + R + W + E + slots + A_pend + S·(P + A)) with
hashing; the only super-linear terms are the B·L-bounded slot population and
the S·P sweep, both measured as constant-factor on real inputs (#1321: 0.88
slot inserts per surviving value on the self-host unit, ≤ 0.42 on cJSON, Lua
and SQLite). Permanent arena: 48 bytes per created parameter plus 16 per
argument slot, of which 93% die (466,774 of 500,552 parameters; #1321 census
of 2026-10-04), plus 16E for predecessor lists.

## Redundancy found

1. **Validator: the ownership pass re-derives what the block walk has in
   hand.** Every row the block pass visits is a row whose chain membership it
   is proving; the only extra needed is a visited byte. Removed.
2. **Validator: the value pass re-reads the defining row.** For an
   instruction-defined value the defining row is the row the block walk is
   holding, and `ir_label_transfer_valid_without_metadata`'s first-operand
   requirement is the operand-range check that walk already performs. Moved to
   the row.
3. **Validator: the value pass precedes the block pass module-wide only by
   convention.** Nothing in V7 depends on another function's state, so the
   module-wide order bought nothing but a second cold sweep.
4. **SSA finish and publication derive the same CFG topology twice**, and
   finish additionally materializes `IrPredecessor` lists for every edge that
   publication verifies against the terminators and then discards. The CSR
   and reachability finish computes are scratch. This is real but small:
   2 × (B + T) target visits and E allocations against a function whose row
   work is Θ(I + O); the `c_test_direct_ssa` contract that every block carries
   its complete list (foundations guide: "selectors must never see a partial
   CFG") would have to change first. Not changed here.
5. **SSA finish creates and destroys 93% of its parameters.** This is the
   dominant cost and it is structural: 71% of provisional parameters are
   created by the finish walk itself (Braun-style intermediate phis found
   trivial afterwards), and eager sealing at construction would avoid at most
   24% of creations and none of the remap
   ([#1321 census, 2026-10-04](https://github.com/buster14a/buster/issues/1321#issuecomment-5979417415)).

## The fused validator: invariants and why every obligation survives

Per function, with `visited[I]` and `defined[V]` bytes zeroed:

- Walk blocks in index order. For each block: refuse an unterminated or
  unsealed flag (V4). Walk its parameters once: a value `≥ V` or already
  `DEFINED_PARAMETER` is refused (V5, same error and site as the old parameter
  list scan); otherwise mark it and evaluate V7 with `is_parameter = true`,
  which refuses a value some row defines (`definition < I`). Then the
  unchanged `ir_validate_block_parameters` (types, counts, order, tail,
  provenance). Then the chain: a row id `≥ I` or already visited is refused
  (V3, same error and site as the ownership walk: a cycle, a tail shared with
  an earlier block, an out-of-range link); mark it; if the row's result names a
  value whose `definition` is this row, evaluate V7 for it here, with
  `is_parameter = defined[v] == DEFINED_PARAMETER`, and mark it
  `DEFINED_INSTRUCTION`; then the unchanged row obligations (V4 after-terminator,
  V6). After the chain, the reached tail must be `last_instruction` (V3) and
  the chain must have ended in a terminator (V4).
- After all blocks, a visited count short of I names the first unvisited row
  (V3). Then every value still `DEFINED_NONE` gets V7 with
  `is_parameter = false`: a parameter value is never `NONE` here, a row result
  reached by a chain is never `NONE`, so this sweep sees exactly the values the
  old pass checked with no parameter mark and no visited definition --
  INVALID definitions (refused), out-of-range definitions (refused) and the
  accepted orphans.

Invariant I1: a value is marked at most once by a parameter and at most once by
a row (a second parameter is refused before marking; two rows cannot both have
`values[v].definition == id`). Invariant I2: when V7 runs for a value, the
`is_parameter` argument is exactly "some parameter of this function carries
v" **as far as the walk has progressed**; if a later block's parameter carries
a value an earlier row defined, that parameter's V7 call refuses it with the
same BLOCK_PARAMETER error and the same `(INVALID, definition)` site the old
value pass produced, because the predicate itself is unchanged. Every V1-V7
predicate is therefore evaluated for every row, parameter and value exactly as
before; what changed is the order of evaluation across sites. For a function
with one fault, the first failing predicate is the same predicate, so error,
function, block and instruction are the same. For a function with several
faults the first reported one may differ; the registered oracle test pins the
one case the hand-built shapes produce (a terminator whose `next` runs into a
later block's chain: the walk refuses the first row behind the terminator as
`INSTRUCTION_AFTER_TERMINATOR`, where the module-wide pass reached the tail
mismatch first and reported `INSTRUCTION_OWNERSHIP`; both reject). One boundary
attribution changes in checked builds only: a certified module whose
LOCAL-free function has an ownership fault used to fail at
`LOCAL_PROMOTION_OUTPUT` through the scope-level ownership pass and now, with
that function excluded from promotion attribution, fails at
`CFG_PUBLICATION`, which is where the tests-off production compiler always
rejected it.

`ir_prepare_canonical_module`'s attribution path dropped its explicit
`ir_validate_module_ownership` call: a function-level verdict now carries its
own ownership proof, so one function attributes without a module scan.

### Tests

`ir_validate_equivalence_tests` (ir_validate_test.c, registered in `ir_tests`)
builds eight shapes -- linear; diamond with a join parameter; a reducible loop
whose header parameter and increment form a cycle; an irreducible region whose
two headers carry mutually dependent parameters; unreachable blocks (a dead
block feeding the live join, a dead self-loop with a self-referencing
parameter, a predecessor-less block with a zero-incoming parameter); switch
fan-out with duplicate targets; a six-arm, three-parameter join; LOCAL/LOAD
rows -- in builder and published form, and 400 fixed-seed random graphs
(2-13 blocks, every terminator kind over random targets, parameters whose
incoming values are any integer value of the function: later parameters,
themselves, values from blocks that never reach the join, since no dominance
is checked). Each is subjected to 37 single-fault mutations. For every case the
fused validator, the reference three-pass validator
(`ir_test_validate_canonical_module_reference`) and a brute-force structural
oracle written from the definitions must agree: same error, same function,
same block and instruction (except the documented chain-order divergence, which
is pinned as a pair), oracle rejects whenever a structural fault is present,
validators accept only what the oracle accepts. The matrix asserts every
mutation was applied at least once and that the random rounds applied at least
3,200 mutations. `ir_test_validation_census` pins the fused walk's census:
every validation counter unchanged except `validation_ownership_bytes_cleared`,
now one byte per row plus one per value.

## Rejected and deferred approaches

- **Validating on the published dense spans instead of chains.** Would remove
  chain walks entirely, but the FAST input guard validates before FAST, FAST
  reopens the builder lists (`ir_function_invalidate_cfg`) and compaction
  re-publishes; moving validation after publication costs a second publication
  per function. Deferred; it is the natural next step only together with FAST
  operating on the published form.
- **Adding a canonical dominance check.** Would close the gap above at
  Θ(B + E + O) with iterative dominators and a preorder/postorder query per
  use, but adds work to the default path; the task asked for less. Recorded as
  a known limit, not implemented (the existing boundary table already states
  it).
- **Omitting `IrPredecessor` lists for parameter-free blocks in finish.**
  Legal for publication and promotion, byte-identical, saves E allocations and
  the verification walk, but contradicts the documented complete-list contract
  that `c_test_direct_ssa` asserts for every block. Not changed; a contract
  decision, not a performance one.
- **Eager single-predecessor forwarding during lowering.** Byte-identical only
  when the walk finds an existing value and never creates a parameter earlier
  than finish would (surviving parameters' creation order fixes the dense
  numbering); the #1321 census bounds its effect at 24% of creations and none
  of the remap. Not implemented.
- **Dominance-frontier (Cytron) placement for finish.** Would create only the
  ~34K real merge parameters instead of 500K, linear in B + E + defs with
  iterative dominators, but renumbers every surviving value (no
  `--require-identical-output` A/B), must reproduce the runnable/dead-edge rule
  for unreachable predecessors and the closed-cycle representative choice, and
  the work-vs-identity trade needs the use-list or patch-list design the #1321
  census names. Recorded as the design for a separate owner.
- **Trivial-parameter agenda.** Already measured neutral (audit
  2026-09-26T042408Z, 0.145% of instructions). Not revisited.

## Unrun checks and limits

- No dedicated Zen 5 (9700X) measurement; the hosted A/A and A/B are
  diagnostic and unpinned.
- Sanitized, Apple and mobile lanes are the ordinary PR CI's; see the PR for
  the exact-head results rather than this file.
- The label-metadata (computed-goto) path uses the same per-value predicate at
  the new sites but no hand-built metadata-rich shape is in the equivalence
  matrix; the existing `ir_test_canonical_parameter_validation` and label
  fixtures cover it, and the registered `tests/basic_c_*` label programs pass
  through the fused validator in CI.
- Multi-fault functions may report a different first error than before; the
  contract never specified which of several faults is named.
