# Delimiter producer facts: architectural investigation and bounded experiment

Inspection: `c5a073139691e9111986c4fca6f6b03d2a6dfcf1`, tree
`68adbe94cf6bd2c00671c4e413552d54791fd1af`.
Owner: [#2183](https://github.com/buster14a/buster/issues/2183);
candidate [#2191](https://github.com/buster14a/buster/pull/2191).
Codex root is the sole branch writer. Scouts and independent reviewers are read-only.

Select bidirectional delimiter publication as the bounded, lowest-risk test of
producer-owned facts. This does **not** establish a step-change or a 2x route on
the current unity workload. The historical multi-process startup route has a
larger demonstrated opportunity, but batch compilation already exists and
several costly preparation families have since been removed.

## Work account and ownership

The source account is anchored, not inferred from function names alone.
[The work ledger](../../src/buster/lib/compiler/work_ledger.h) records the
corresponding populations only in diagnostic builds.

| Boundary | Work and reason | Producer facts and remaining limits |
|---|---|---|
| Preprocessing -> token stream | Spelling interning hashes names; macro expansion produces new tokens and retains source provenance. | Interned spellings, token classes and source provenance are already produced; macro expansion can legitimately introduce new tokens. A new frontend IR is unnecessary. |
| Parsing -> semantics | Range-based syntax requires repeated walks; type queries may speculate and roll back. | The parser's position pass produces scope/candidate/number/delimiter facts. Existing indexes already remove several scans. Broad query reuse can change type materialization and diagnostics. |
| Semantic constraints | Const-assignment, sizeof-update and label-value checks build reverse maps from already matched delimiters. | Selected slice removes map allocation, initialization and three reconstruction walks; required checks remain. |
| Semantics -> canonical IR | Lowering constructs canonical operations and preserves source/type ownership. | Producer summaries and direct SSA already exist; broad type re-derivation is a stale large-cost hypothesis. |
| Canonical IR -> backend | Canonical validation is a required boundary; selector prewalk also derives target-specific expansion, call and escape facts. | More generic facts would retain about 12 bytes/value without removing that mixed-purpose walk. #1406 owns preparation locality. |
| Native startup -> emission | Immutable x86 metadata is prepared per process, including exhaustive encoding combinations. | #1317 removed eager shape preparation; #1536 removed eager NUL/coverage work. #1295/#2017 own the larger continuation. |
| Object/output | Required serialization writes sections, symbols, relocations and debug data. | Borrowed payloads and removed snapshots already exist. Do not attribute their historical savings to this candidate. |

This is a ranked decision, not a proposal to change every row.

invalidation rules.


## Ranked architectural alternatives

1. **Producer-owned delimiter pairs: selected bounded slice.** Exact pair
   equivalence is cheaply falsifiable; three builders disappear; capacity,
   ownership and invalidation remain unchanged. The hosted census below measures a small diagnostic fraction, ruling out this slice as a credible current step-change.
2. **Demand-driven x86 encoding cells: larger potential startup prize, deferred
   to its existing owner and a current census.** Nine current tables enumerate
   6,912 cells and 11,520 metadata emissions. Mandatory chunk projections need
   only 256 cells/512 emissions initially. Per-table laziness is insufficient
   because those projections consume eight tables. Per-cell readiness adds up
   to 96 bytes/table plus registration facts and requires serial gang prewarm.
   Actual demand and current total-time fraction are unknown. The simpler GPR
   distinct-key proposal is already #2017.
3. **Broader semantic answer reuse: do not implement speculatively.** #1028 and
   #1247 own the contracts. Most eligible body repeats already hit the existing
   memo; earlier broad reuse changed DWARF type materialization. The older
   inclusive lowering/constraint shares do not identify removable work.

Historical evidence explains why the 2x stretch was investigated and why it is
not a current prediction. The [September 28 audit](2026-09-28T040333Z.md)
at `76a7bdd` attributed 52.6% of separate-process Lua CPU to prewarm; the
[September 27 audit](2026-09-27T155317Z.md) at
`ade6ac4` observed about 2.7x from existing same-process serial batching.
Those shared-cloud observations predate preparation changes and apply to that
workload shape. They do not predict a unity compiler speedup.

The September 28 SQLite inclusive constraint/lowering shares were 18.3%/34.5%.
Eliminating all of both would theoretically permit 2.12x, but useful lowering and
required semantic checks cannot disappear. Lowering type re-derivation was
already only 0.5%. The entire const-assignment family's historical shares of
3.8% unity and 6.9% SQLite give only 1.04x/1.07x conditional CPU ceilings; this
slice removes substantially less and those sources are stale. The
[September 30 ABI audit](2026-09-30T193632Z.md) found a
roughly 64% warm-query improvement with neutral whole compilation.

The newest audit at inspection,
[2026-09-30T203757Z](2026-09-30T203757Z.md),
concerns CI analyzer scheduling. Four workers saved isolated wall time but
raised CPU occupancy, and a Windows job limited whole-CI improvement. It is not
compiler phase attribution.

## Current implementation, simpler control and no change

Let `T_i` be the token range of each actual inverse-map reconstruction and
`P` the TU's matched delimiter pairs.

| Choice | Traversal/allocation | Logical traffic | Invalidation and complexity |
|---|---|---|---|
| Current | One scratch array and full range scan per actual map | 4*sum(T_i) clear bytes, plus inverse-row writes and token reads | Independent consumer maps, existing teardown |
| Simpler shared body map | One retained reconstruction per participating body; sizeof ranges still need clipping | At least one body clear/scan; extra retained map | Shared scratch ownership and call-chain coupling |
| Producer publication | No reverse map allocation, clear or reconstruction | Adds 4*P payload store bytes; backward loads replace map loads | No new capacity or invalidation; one directional accessor and range guard |

These are logical byte/event counts, not DRAM traffic. The common forward-table
allocation/zeroing remains; additional pointer/readiness checks, cache-line
traffic and source-induced host-code layout effects still require measurement.
The reverse fact is immutable because the preprocessed token stream is sealed.
No canonical IR representation, validation boundary, allocator mode or generated
code optimization policy changes.

For current measured fraction `f` and removable part `r`, an ideal upper
ceiling is `1/(1-f*r)` before added stores and lookup cost. A 2x improvement
requires net removal of at least half the complete compilation time. No evidence
supports that for these maps. Diagnostic region timing includes observer
overhead and excludes any common delimiter-index build; it is not admission.

## Invariants and falsification

The successful producer stack pop publishes opener->closer and closer->opener
in the existing table. Unmatched entries decode to UINT32_MAX. Forward reads
accept only a later token; reverse reads require start <= opener < closer.
A mismatched closer clears still-open groups and preserves completed inner
pairs. Raw readers must prove delimiter kinds/direction.

The experiment was declared in #2183 and commit
`8e78180790679855bfd0f0c01a6e99ff23084ea5` before compiler edits.
The unchanged baseline fixed point passed on
[run 36919857990](https://github.com/buster14a/buster/actions/runs/36919857990):
41,141,440-byte stage1/stage2 fixed point, including alternate backend stages.

Focused regression extends the existing position-index test with an independent
stack oracle, fixed malformed rows, all-token directional reads, clipped starts,
dirty arenas, scalar/shape parity and exact 63/64 and 4095/4096 boundary pairs.
Existing sizeof-update and label-value tests exercise the consumers.
Independent source review of `0df37ef91b91c8c444bfbf8002aee93b27c72f99`
found no defect in raw lowering readers, range filtering or scratch lifetimes.

The [package](../research/delimiter-facts/README.md) freezes the baseline source/header/generated closure,
builds serially in one path, hashes compilers and actual commands, and keeps
diagnostic observers out of timing binaries. Census requires all actual reverse
maps/tokens/clear bytes to become zero, reverse stores to equal matched pairs,
and instrumented/plain outputs to agree. Frozen successful outputs, -g/-g0,
both frontend forms and invalid-input diagnostics must agree.
Self-host, mode and sanitizer checks remain mandatory. Any mismatch rejects
the candidate; neutral or regressive results remain published.

## Observed correctness and pending acceptance

Strict capture has no failures: ten valid -g object/diagnostic comparisons across
both frontend forms, two invalid controls, instrumented/plain parity, and all
60 measured -g0 output rows match. Baseline own-source fixed point is 41,141,440
bytes; candidate own-source fixed point is 41,140,360 bytes. Each stage1/stage2
pair is equal; different own-source outputs are expected. Alternate MIR-stack
and canonical-none self-host stages also pass. Focused Release frontend and
sanitized Debug frontend tests pass.

Mode matrix passes 24 legs with six fixtures each: four native x86-64 Linux
executions, twenty link-only target/mode cells, no external oracle. This does
not substitute for native execution on those target platforms. Source-size
ratchet passes: production -676 bytes; the temporary workflow accounted for
+1,112 build bytes and is removed from the final candidate.

Independent source reviewers found no delimiter direction/range/lifetime defect.
Ordinary cloud workflow lint, throughput regression guard, direct-SSA census,
TCC bootstrap and Windows/Linux throughput harness passed on the strict
package commit. Later pushes cancel some normal CI jobs; cancellation is not a
correctness result. Draft Apple jobs are deferred placeholders, not executed
acceptance. Final-head checks remain visible on the PR.

Observed fact: the producer-owned representation removes the reconstruction
category. Prediction: extra per-pair stores/checks may or may not improve plain
end-to-end time. **Negative architectural result:** this slice does not establish
a step-change; no credible current unity 2x route was demonstrated. The larger
startup continuation needs fresh current attribution under its existing owners.


Qualified-host wall/RSS/code-size/runtime acceptance remains explicitly pending.
