## Eligibility and isolated diagnostic census

The existing type scan produces sparse eligible-local entries. The prototype
starts a count at `local_use_count - 1` and decrements it exactly when the
operand walk clears a nonzero `local_use`. Once cleared, later uses skip the
local path, so disqualification decrements only once. With zero surviving
places, no LOAD can seed a local alias, and a DEREFERENCE can only extend an
already seeded alias. Both reverse sweeps can therefore be skipped.

The guard conservatively retains store-free and unused eligible locals. It
does not move their later disqualification, change alias ordering, or skip
CFG-edge uses, required initialization, line-mark allocation, call workspace,
classification, branch fusion or constant-fold preparation. The only other
production edit removes an obsolete historical alias-population comment.

Seven alternating diagnostic pairs of one instrumented compiler, toggling
the guard through an experiment-only environment variable, give identical
per-function eligibility, candidate and alias signatures in every run:

| Population or work | Count |
| --- | ---: |
| Functions | 6,550 |
| Functions initially holding a type-eligible local | 968 |
| Functions with zero eligibility after the operand walk | 6,541 |
| Functions still eligible / producing aliases | 9 / 9 |
| Aliased values | 332 |
| Reverse-sweep candidate visits before | 809,468 |
| Reverse-sweep candidate visits after | 4,530 |
| Removed candidate visits | 804,938 (99.4404%) |

Visit totals are reconstructed from the observed per-function candidate
counts and guard outcomes: two complete reverse sweeps for each admitted
function. Ordered alias value/root signatures match in every pair, and each
diagnostic linked image matches the uninstrumented baseline byte-for-byte.
The population differs slightly from the filing's earlier source revision.

The experiment-only timer surrounds the reverse loops alone, after CFG-edge
accounting and line-mark allocation and before store-free cleanup and call
workspace. Median totals are 5.443 ms baseline and 0.168 ms guarded. All raw
samples are retained, including baseline totals of 31.881 and 26.436 ms. This
instrumentation, timer overhead and shared-host scheduling prevent treating
these numbers as native runtime acceptance. The filing's 4.85 ms surrounding
phase is not used as eliminated work.

Control-population checks caught an initial fixture limitation: under the
retained-local flags, the argument `n` itself remains an eligible local in
both the initially named `no-locals` and `escaped` inputs. Their original
measurements remain in the table and bundle with their actual populations.
Additional, distinct controls use the default frontend for genuinely empty
local populations and parameter-free functions whose sole local escapes for
genuinely zero eligibility. The latter remove 128/8,192 candidate visits at
16/1,024 functions; the former start with zero candidate visits. The complete
control census and sources are retained. These supplementary controls do
not change the original acceptance floor or the production disposition.

The large disqualified case qualifies for a scoped synthetic work-reduction
claim. Both production cells stay below the requested whole-compile floor,
and the all-eligible controls show a small tracking cost. The production
prototype is therefore rejected for this experiment. No attempt is made to
turn the result into general compiler speed, resource or Zen 5 acceptance.
