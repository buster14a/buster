## Scope

This audit completes the Clang-built part of the
[#58](https://github.com/buster14a/buster/issues/58) A/B/C comparison prepared
by [`2026-09-30T191439Z`](2026-09-30T191439Z.md). It measures compiler
throughput only: the trusted Clang Release `ide` compiling the frozen unity
self-host source. It does not measure generated-program speed.

The three variants differ only in `machine_x64_select_load` in
`machine_x86_64.c`:

| Variant | Source | Mechanism |
| --- | --- | --- |
| C (baseline) | main `16f2db70a40b5896a8366a83173da861b04a8d8d` | Direct per-value facts, mask-composed selection (production) |
| B | C plus [b.patch](evidence/2026-09-30T191439Z/issue58/b.patch) | Direct per-value facts, ordinary `if` / `else` |
| A | C plus [a.patch](evidence/2026-09-30T191439Z/issue58/a.patch) | Named helpers, which Clang inlines (helper proxy) |

Both patches still applied cleanly with `git apply --unidiff-zero` to current
main. A is the Clang helper proxy, **not** the issue's "helper-based with the
new inliner" arm. That arm needs the Buster tiny-function inliner of
[#48](https://github.com/buster14a/buster/issues/48), which is still open.

## Method

Each variant was the head of draft
[PR #3085](https://github.com/buster14a/buster/pull/3085), with a request line
in `benchmarks/9700x/compiler-compare.request`. The 9700X pull-request
comparison (`compiler-compare-v1`) built tests-off Clang Release `ide`
binaries of the merge base and the head. It ran `tools/uarch_lab.py compare`,
18 paired runs pinned to CPU 2, on the frozen merge-base source, then the
`throughput-corpus-v2` corpus. Both runs used the same merge base, `16f2db70`,
and the same baseline binary (sha256 `c3b21327…d460`). The two runs used
different trusted harness revisions, `16f2db70` for B and `c60bbc25` for A.
Host: `AMD Ryzen 7 9700X 8-Core Processor`, Clang 23.1.1, kernel 6.18.50.

Retired instructions fall by about 4 million of 3.738 × 10¹¹ (−0.001%) for both
variants. The interval excludes 1, but the effect is far below the 0.5%
minimum effect and does not show up in cycles or wall time.

The B run raised no drift or order warning. The A run's `lab/summary.json`
sets `checks.drift.flag = true`: the first-half A/C interval is
[0.990907, 0.999864] and the second-half interval is [1.000114, 1.009429].
The method requires those to overlap, and
[benchmarking.md](../agents/benchmarking.md) requires drift to be investigated
before the verdict is used. Opposing time regimes can cancel in the pooled
estimate, so the pooled A interval does **not** establish a stable A/C effect
bounded by ±0.5%. The pooled numbers above are kept as measured. A is
drift-qualified, with no robust winner, until the drift is explained or a
controlled replay supports a bound.

## Disposition

**Keep C, the current mask-composed selection, as the conservative status
quo.** On the 9700X, ordinary branches (B) show no detectable compile-time
difference from C within about ±0.37%. The helper structure (A, inlined by
Clang) has no robust result: its pooled interval includes 1, but the run is
drift-flagged, so it shows neither a win nor a bounded equivalence. As the
issue asks, branchlessness is not kept as an objective of its own: C stays
because no variant has been shown to beat it, and it is the smallest binary of
the three. The production selector is unchanged.

Pending: explain the A run's drift, or replay A against C under a controlled
order (for example a second 9700X PR comparison of the same `a.patch` head),
before stating any A/C equivalence bound.

Not covered here:

- Front-end events, measured register pressure and spill traffic. The
  `compiler-compare-v1` profile records none of these. The static Clang
  assembly and frame comparison remain in the
  [2026-09-30 audit](2026-09-30T191439Z.md#assembly-code-size-and-limits).
- The #48 Buster-inliner A arm, which stays blocked until #48 lands. With
  B ≈ A ≈ C on the trusted compiler, that arm can affect only the self-built
  stages, which validate the fixed point and are not the performance subject.
