`2026-10-12T183752Z` (Linux x86_64, hosted cloud container (Intel(R) Xeon(R)
Processor @ 2.10GHz), diagnostic only; **#58 Buster-inliner arm: the landed
tiny inliner cannot inline variant A's helpers; keep masks**).

## Scope

This audit closes the last open arm of
[#58](https://github.com/buster14a/buster/issues/58). That arm is variant A,
the helper-based `machine_x64_select_load`, compiled by Buster's own tiny
inliner. It was blocked on
[#48](https://github.com/buster14a/buster/issues/48), which landed as
[PR #3748](https://github.com/buster14a/buster/pull/3748) (main `9a5378ea`).
That inliner is opt-in through `-fcanonical-inline`. The earlier audits are
left unchanged: [`2026-09-30T191439Z`](2026-09-30T191439Z.md) (census,
patches, assembly), [`2026-10-08T193044Z`](2026-10-08T193044Z.md) (Zen 5 A,
B and C) and [`2026-10-08T233626Z`](2026-10-08T233626Z.md) (Zen 5 A replay).

The question this audit answers comes before timing: does the landed inliner
turn A's helper calls back into straight-line code? If it does not, a
self-built A under `-fcanonical-inline` is simply a helper-calling A, and
there is no inlined variant to time.

## Method

- **Base:** main `9a5378eabf0d92a8eff27b9e05e5c518efbaed09`, which is C,
  the production mask selector.
- **A:** [a.patch](evidence/2026-09-30T191439Z/issue58/a.patch) from the
  2026-09-30 audit, applied with `patch -p1` at a 242-line offset. The
  rebased diff is [a-rebased.patch](evidence/2026-10-12T183752Z/issue58/a-rebased.patch).
- **Build:** each tree was built with
  `./build.sh generate --cc clang --no-include-tests` and then
  `./build.sh build --config Release -t ide`. The driver was bootstrapped
  with TinyCC `0fb54300` (0.9.28rc), and the compiler is Ubuntu Clang 18.1.3.
- **Stage 1:** each Clang-built `ide` compiled its own tree's unity source,
  using the `uarch_lab.py` `DEFAULT_COMPILE` shape with `-march=znver5`:
  `ide cc -march=znver5 -Isrc -Ibuild/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 -g src/buster/apps/ide/ide.c -lm [-fcanonical-inline] -o OUT`.
  Each variant was built once without the flag and once with it.
- **Unbounded check:** A was also built with all optional budgets lifted:
  `-fcanonical-inline-caller-growth-shift=31`, and
  `-fcanonical-inline-module-growth=`, `-call-sites=` and
  `-function-growth=` each set to 100000000. This separates budget
  rejections from shape rejections.
- **Assembly:** `objdump -d` of `machine_x64_select_load`, with sizes from
  `nm -S`.

## Result

### The inliner never sees A's helpers as candidates

`ir_inline_tiny_leaf` (`src/buster/lib/compiler/ir/ir_inline.c`) accepts an
optional callee only when it has one block, no block parameters, no label
metadata, and no `CALL`, `BRANCH`, `BRANCH_IF` or `SWITCH` row. Every helper
A introduces fails at least one of those conditions in canonical IR:

| A helper | Why it is not a tiny leaf |
| --- | --- |
| `machine_x64_local_is_indirect` | `&&` short-circuit, so more than one block |
| `machine_x64_place_is_addressed` | `\|\|` short-circuit, and it calls `machine_x64_local_is_indirect` |
| `machine_x64_promoted_local_register` | an `if` around `&&`, plus a call |
| `machine_x64_operand_register` | an `if`/`else` that writes through an out-pointer |

The verbose `IR_INLINE` records for A's stage 1 show where the rejections
fall
([default](evidence/2026-10-12T183752Z/issue58/a-inline-default.ir_inline),
[unbounded](evidence/2026-10-12T183752Z/issue58/a-inline-unbounded.ir_inline)):

| Budgets | inlined | budget_skips | shape_skips |
| --- | ---: | ---: | ---: |
| default | 3,543 | 577 | 16,089 |
| all optional budgets lifted | 4,120 | 0 | 16,089 |

Lifting the budgets inlines 577 more sites elsewhere, but `shape_skips`
does not move, and the selector's calls are unchanged:

| `machine_x64_select_load`, stage 1 with `-fcanonical-inline` | A | C |
| --- | ---: | ---: |
| Code bytes (`nm -S`) | 9,539 | 9,854 |
| Instructions | 2,006 | 2,097 |
| `call` instructions | 47 | 43 |
| Helper calls (`local_is_indirect`, `place_is_addressed`, `promoted_local_register`, `operand_register`) | 1 + 2 + 1 + 2 = 6 | 0 + 1 + 0 + 1 = 2 |
| Stack frame (`sub $N,%rsp`) | 0x978 = 2,424 B | 0x998 = 2,456 B |
| `%rsp`/`%rbp` memory operands | 740 | 752 |

For both A and C, the selector built with `-fcanonical-inline` matches the
one built without it, except for RIP-relative displacements. Function
sizes are identical (A 0x2543, C 0x267e). Even unbounded, the A selector
keeps the same 47 calls. Full listings:
[A](evidence/2026-10-12T183752Z/issue58/a-inline-select_load.asm),
[C](evidence/2026-10-12T183752Z/issue58/c-inline-select_load.asm).

### Semantics are preserved under the inliner

The A and C stage-1 compilers built with `-fcanonical-inline` each compiled
the base tree five times with `-fcanonical-inline`, alternating A and C on
CPU 2. All 10 outputs share SHA-256 `b705232adb428ee0…`, which equals C's
own stage-1 `-fcanonical-inline` compiler, so the inline-mode fixed point
holds. The hosted wall times (A 18.6–21.2 s, C 18.6–20.7 s) are **diagnostic
only**. Five unpaired runs on a shared Xeon cannot resolve a difference this
small, and this audit claims none.

## Disposition

The #48 arm cannot produce the variant the issue describes. The landed
inliner admits only branch-free, call-free, single-block leaves. A's helpers
contain control flow by construction, so in self-built stages A under
`-fcanonical-inline` is the same helper-calling code as without the flag.
That code has four more calls and six helper calls against C's two. There
is no inlined A to time, and the outcome cannot favour A. This holds unless
a future inliner admits multi-block callees, in which case the arm would be
a new experiment.

Combined with the Zen 5 results on the trusted Clang-built compiler (B: no
detectable difference, ±0.37%; A replay: no detectable difference, ±0.04%,
no drift), **keep C**. This audit changes no production source.

Not measured here: Zen 5 front-end PMU events and dynamic register pressure
or spills. `compiler-compare-v1` collects neither, and the static frame and
stack-operand counts above are the only pressure evidence. Since no variant
beat C on wall time, cycles or instructions, these would characterize the
outcome but could not change it.
