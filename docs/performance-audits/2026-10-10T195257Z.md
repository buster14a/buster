## Workload

Every arm compiles the same input, the base revision's unity self-host source,
from the base checkout:

```sh
ide cc -Isrc -Ibuild/v3t/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -fsyntax-only \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

4,143,432 tokens reach the parser, and the tree has 2,749,262 nodes. Under the
pilot the candidate's body binder follows the plan of all 6,584 function bodies
(`C_AST_STATEMENTS bodies=6584 segments=70194 segment_tokens=1023967
uses=269303 bails=0 declaration_hints=35726 loop_hints=4811 declines=10255
fallbacks=0`). There are four arms:
- A: base, default flags;
- B: base with `-fc-ast-pilot`: the tree, the typer, the declaration split, and
  the token-walking body binder;
- C: candidate with `-fc-ast-pilot`: the same, with the body binder following
  the statement plans;
- D: candidate, default flags.

C − B is the plan's own effect, and D − A is its cost to the default path.
Callgrind ran with `--cache-sim=no --branch-sim=no`.

## Validation and limits

- Callgrind counts instructions, not time, on `-march=x86-64-v3` builds whose
  AVX-512 kernels are compiled out.
- One input, one host, single process, no pinning and no `perf` counters. Wall
  time was not measured: the budgets did not ask for it, and on this host it
  cannot resolve an effect of this size in the whole compile.
- The 9700X pull-request comparison runs default flags only. It could compare
  arm D against A, but no request is made for this slice, and it cannot time
  the hook. Zen 5 validation of the plan therefore stays **incomplete**.
- Correctness of the measured candidate and its merge with main is in the pull
  request's validation record: `c_ast_tests` and `compiler_driver_tests` in
  Debug (split TU) and Release (unity), `test_self_host --config Release`, and
  the Clang analyzer on the touched C files.
