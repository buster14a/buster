# Same-revision analyzer comparison qualification (#603)

## Result and scope

The ordinary analyzer candidate is already the required full split-source
analysis. When a `push` or `workflow_dispatch` run resolves both analyzer
driver identities to the checked-out `HEAD`, running the same full campaign
again through `--baseline-driver` is redundant. Three fresh hosted attempts
on one exact candidate showed that omitting only that reference invocation
saved a median **445.414 seconds of analyzer campaign runner work** (range
358.573--532.196 seconds), or a median **49.970%** of the comparison campaign
(range 49.669--51.681%). This is a runner-work result, not a claim that the
complete workflow critical path improves by the same amount.

The change keeps the full candidate analysis, unity analysis and the
authoritative compile-command database. Pull requests, merge queues,
different revisions and unknown provenance continue to compare
conservatively. The existing explicit `--baseline-driver` path is unchanged.
This is one focused slice of #603, not issue closure: freezing a genuinely
different historical driver's transitive include closure and selecting
comparisons for relevant changed dependencies remain follow-up work.

Production selection evidence is fail-closed. Before launching a campaign it

reason fields, and enforces baseline executable presence for compare and total
absence (including dangling symlinks) for skip. Focused regressions cover
push/workflow-dispatch same-revision skip, distinct pull-request compare,
merge-group/unknown-event conservative compare, reference and candidate
failure, and unchanged candidate/aggregate commands.

## Interpretation and handoff

The accepted evidence supports the narrow production rule: when both driver
identities resolve to the same checked-out revision in ordinary push or
manual-dispatch correctness runs, run the full candidate once and retain the
explicit selection identity/reason instead of repeating it as its own
reference. The median avoided analyzer campaign work is 445.414 seconds, while
the unchanged candidate median is about 7.5 minutes. Because unrelated macOS
lanes can remain later on the workflow critical path, this audit makes no
whole-workflow latency claim and does not add independent lane savings
together.

No compiler source, optimization policy, generated object, compiler tests,
compiler workload throughput, #36 retirement path, #437 benchmark service or
persistent host was changed or measured. The temporary qualification workflow
is measurement scaffolding and must be removed from the final production PR.
The final submitted head needs exact-head tests and CI after rebasing; this
audit deliberately preserves the distinct measured revision and actual
integration identity.
