# 1. What is already implemented

The current frontend is not a scalar lexer waiting for a SIMD rewrite.
`c_lex_compact` performs shared byte classification, bitwise extent discovery,
punctuator matching, literal/comment exclusion, numeric mask processing and
compacted 12-byte `CToken` production. It also emits a one-byte shape sidecar.
The current emitter batches sixteen rows; the older eight-row emitter's waste
is not a current-main opportunity. `c_lex_dispatch` still retains the scalar
path and a differential reference. See [window classification][lex-window],
[emission and dispatch][lex-emit], and [feature guards][guards].

`c_translate_source` already combines load, classification and copying on its
SIMD plain runs. Locations are recovered through translation checkpoints and
source-map metadata, rather than a full source-position record per token.
Preprocessing already builds four classification masks per 64 tokens, visits
identifier lanes for macro lookup, skips expansion on macro-free logical runs,
and copies their token/shape spans directly into the final contiguous stream.
There is no final whole-stream linked-list flattening to remove on that path.
See [translation][translate] and [straight-through preprocessing][pp-lines].

Identifiers already have interned symbols. `c_symbol_key` reads bounded short
names or first/last words, not a byte-FNV over every occurrence. Macro lookup
uses `by_symbol`; parser keyword and builtin classes are associated with the
predefined symbol range. Definitions already carry `parameter_index`,
`parameter_use_count`, `plain_count`, `has_paste`, `has_stringify` and spacing
metadata. Arguments naming no defined macro can alias their unexpanded arrays.
These mechanisms are not new proposals. See [symbols][symbols],
[definition metadata][macro-def], [intern projection and representations][pp-types],
[plain substitution][replacement] and [continuations/rescan][expand].

The [September 6 audit][a06] rejected the broad range-engine estimate after
repricing it against these improvements. It also recorded a loss from a
per-output-push foreign-byte accumulator. Therefore neither a new general
range engine nor eager per-token accounting is recommended here.

# 2. Source-byte and token-pass ledger

This is a source-level traffic/work model, not a hardware bandwidth measurement.
Let `B` be raw bytes over the actual dispatch population, `D` translated bytes,
`T` lexed tokens, `I` identifier occurrences, `U` final preprocessed tokens,
`Q` compact windows, `N` tokens produced by eligible paste-free substitutions,
and `F` foreign spelling bytes copied into final provenance-bearing storage.
Measure file dispatches, repeated includes, builtin/replacement buffers, pasted
spellings and pragma re-lexes separately; a unique-file byte total is not `B`.
Counts from different historical snapshots must not be multiplied together.

### Historical scale, with its limitations

The newest located [September 12 audit][a12] measured frozen source
`5dab18af0208cfa7fa65673b6884d5c253fda85b`, not this report's main SHA. Its
Clang 18.1.3 compiler ran under Valgrind 3.22 in a four-vCPU KVM guest with
`-march=x86-64-v3`. AVX-512 was disabled in that measured binary. Its
13,749,246,043 Callgrind `Ir` total and inclusive `c_preprocess` contribution
of approximately 1,409 million / 10.2% are **neither retired hardware
instructions nor current-main wall time nor a native Zen 5 profile**.

That workload reported 30,729,994 lexed source bytes, 3,021,627 lexed tokens,
3,364,471 preprocessed tokens and 124,859 macro expansions. Applying the
current 12-byte row size to those historical token counts gives 36,259,524
and 40,373,652 payload bytes respectively, plus their one-byte sidecars. This
is illustrative arithmetic, not a measured allocation total, simultaneous peak
RSS or a candidate saving. Do not infer `N` or `F` from expansion count.

The [August 22 census][a22] found 283,569 windows advancing 13,963,372 bytes,
about 49.2 useful bytes per 64-byte window, and approximately half of all
lexed bytes passing through the then-scalar escape. The host long-item scans
were subsequently improved there, with a reported 37,030,960-instruction
stage-1 reduction (0.3700%); noisy cycles were not a wall-time win. The same
audit rejected adding cross-chunk escape parity to the long-item search.
These are historical observations explaining candidate selection, not fresh
headroom on the current compact path.

For any *measured* phase fraction `f` and isolated phase speedup `s`, an
otherwise unchanged whole workload has the model
`S = 1 / ((1 - f) + f / s)`. A Callgrind fraction cannot be substituted for a
wall-time fraction. A high byte-throughput number for a stop scanner also
cannot be substituted for `s` of all preprocessing.

# 3. Primary algorithm work and its disposition here

[Validark's Deus Lex Machina][validark-lex] describes shared classification,
bitwise token extents, compaction, punctuator recognition and cross-chunk
keyword work. Its proposed larger bitplanes and length/tag representation are
useful comparison points, not Buster measurements. Buster already implements
much of the compact-window approach; this report does not transfer a Zig
lexer speedup to C preprocessing.

[Eine Kleine Vectorized Classification][validark-class] shows how a shared
upper-nibble representation supports several ASCII set queries, with different
AVX2 and AVX-512 mask extraction. The relevant question here is whether an
additional consumer can reuse current classification, not whether to add a
second classification-table architecture.

[Keiser's simdjson escape discussion][keiser] separates dependency-chain
improvement from total instruction reduction and explains the alternating-run
subtraction construction. It is relevant to local escape masks already used
by compact lexing. It does not justify applying global JSON quote parity to C:
comments, two literal delimiters, preprocessing numbers and translation splices
change the state problem.

[Cameron, Herdy and Amiri][parabix-paper] formulate character and lexical
properties as parallel bit streams, including validation and bitstream-addition
techniques. The [Parabix deletion notes][parabix-delete] distinguish compaction
within a field from joining partial fields and explain sharing deletion
preprocessing over several planes. The proposal below follows that distinction:
byte compaction, bit-plane compaction and cross-block output concatenation are
separate costs. No external implementation, dependency or framework is adopted.

# 4. Opportunity 1: self-host long-item SIMD, without enabling the compact emitter

## Exact remaining gap

In [c_internal.h][guards], `BUSTER_C_LEX_COMPACT` requires the full SIMD tier
and excludes `__BUSTER__`. In contrast, translation uses
`BUSTER_C_TRANSLATE_AVX512 = BUSTER_SIMD_512_BASE`. The long-item helpers
`c_lex_byte_find`, `c_lex_literal_special_find` and
`c_lex_block_comment_stop_find`, and their `CLexState.simd_scan` admission,
remain coupled to the compact-lexer path. A self-built compiler therefore
cannot obtain that long-item scan merely because its translator gained SIMD.
See [scanner implementation][lex-scan] and [dispatch][lex-emit].

**Narrow experiment:** express those existing stop searches through
`simd512_load`, `simd512_splat`, `simd512_equal_byte` and integer `Mask64`
operations. Admit them independently in the optimized scalar lexer dispatch
when the existing basic feature tier is available. Keep the compact emitter
and its host-only intrinsics under their current guard. A conceptual private
`BUSTER_C_LEX_LONG_SCAN` selector is sufficient; it is not a new public mode.

Important tier detail: the current [simd.h dispatch][simd-dispatch] puts plain
loads/splats/equality in the basic F/BW tier, but masked loads in the full tier.
Do **not** accidentally run its scalar masked-load fallback in every basic-tier
tail and call that native SIMD. Use bounded full loads with the existing scalar
tail on basic-only targets. Full-feature builds can retain native masked tails
through the existing interface. No new SIMD builtin or IR operation is required
for the bounded full-load form.

## Layout, pseudocode and invariants

No token or source-location layout changes. `CToken` stays 12 bytes,
`CPpToken` 16, shapes one byte, masks 64 bits. The existing `simd_scan` flag
selects the scanner, not a replacement tokenization grammar. The differential
reference must force scalar translation **and** scalar long-item searches.

Pseudocode for a basic-tier literal-body search (the actual implementation
must follow the repository's macro/interface and side-effect rules):

```c
// Input p is within the bounded translated spelling, not an arbitrary C string.
// The outer lexer owns token start, prefix, metrics and error reporting.
while (end - p >= 64) {
    Simd512 bytes = simd512_load(p);
    Mask64 stop = simd512_equal_byte(bytes, delimiter_vector)
                | simd512_equal_byte(bytes, backslash_vector)
                | simd512_equal_byte(bytes, newline_vector);
    if (stop != 0) return p + mask64_first_set(stop);
    p += 64;
}
return scalar_literal_stop(p, end, delimiter);
```

Line comments need only the newline comparison. A conservative block-comment
port uses the same two-load formulation as the current helper: while at least
65 bytes remain, compare the current 64 bytes with `'*'`, the next 64 bytes
with `'/'`, and OR their intersection with current-byte newlines. The scalar
tail handles the last 64 or fewer bytes. A later variant can replace the
lookahead load with a shifted slash mask and one bounded byte check at lane 63,
but it must be measured separately from self-host enablement.

The search stops **before** the interesting byte. The unchanged outer loop
consumes an escape pair, diagnoses a newline/EOF in a literal, emits required
comment newline tokens and handles the closing delimiter. It searches this
literal's own quote kind; the other quote is ordinary payload. There is no
cross-block backslash parity or quote state in the search itself. All newline,
UTF-8 word-validation, source metrics and diagnostic ownership remain where
current code establishes them.

Never form or load `p+1` unless the bounds permit it. Never call `ctz(0)`,
shift a 64-bit integer by 64, use masked-off bytes as input tokens, or infer
that a sentinel permits a full vector load. No padding is required of public
source buffers. The scalar fallback is a real byte/table algorithm, not
sixty-four scalar lane calls disguised as a fast vector operation.

## Competing implementations and pricing

| Form | Intended role and charged cost |
|---|---|
| Scalar byte loop | Independent semantic oracle; often best for an immediate stop or tiny synthesized spelling. |
| Existing scalar/table-eight run | Workable non-AVX baseline; account for table probes, repeated stop handling and exact bounded tails. |
| Scalar bitset/SWAR | An experiment for exact eight-byte equality masks. A borrow-propagating zero detector is not automatically a correct mask of all matching lanes. Charge mask extraction and setup. |
| Scalar-batched | Two/four independent full-word comparisons with ordered first-stop selection; no speculative memory access beyond bounds. This tests instruction-level parallelism without a new ISA dependency. |
| AVX2 | Optional 32-byte compare/movemask prototype with a scalar tail, only under an existing justified experimental build seam. Do not create a general SIMD abstraction or production AVX2 layer just for this comparison. |
| AVX-512 | Existing `simd.h` full loads/equality, 64-byte progress, native masked tails only on the full tier. Count setup, mask transfers, repeated stop calls and emitted self-host code. |

Proposed observers, outside timing binaries: bytes/stop calls by line comment,
block comment and literal; stop-distance histogram including 0, 1-7, 8-31,
32-63, 64-127 and long runs; full chunks, scalar-tail bytes, escape pairs,
comment newlines, boundary re-entry and compiler producer/feature tier. Do not
select a vector crossover using lexer-only throughput or the old census.

A useful model is
`C = sum(run_setup + full_chunks * chunk_cost + tail_cost + stop_handling)`.
It must include calls emitted by the self-built compiler. The expected benefit
is conditional on a substantial long-run population; it can disappear with
frequent escapes or tiny replacement buffers.

**Reject or leave inconclusive** if trusted-host throughput regresses, the
self-built binary emits calls/fallback operations that defeat the scan, current
long runs are too rare, or source-to-preprocessed-token and whole-compilation
measurements do not clear the predeclared practical/noise gates. Do not relabel
the old host scanner win as a new Clang-built improvement.

# 5. Opportunity 2: direct paste-free replacement production into existing tasks

## Exact redundant materialization

The no-paste/no-stringify arm of [c_macro_replacement_tokens][replacement]
already computes the output count from definition metadata and expanded
argument counts. It nevertheless builds a contiguous temporary `CPpToken`
array. [c_macro_materialize][expand] then passes that array directly to
[c_macro_expansion_tasks_push][tasks], which reserves task storage and copies
its payload in reverse order below an `ENABLE` boundary.

**Narrow experiment:** for ordinary, non-builtin, non-pragma-like definitions
with neither operator, compute the same count, reserve `N+1` existing task
slots once, and produce the same substituted payload directly into those slots.
Keep the current path for builtins, pragma-like replacements, stringify and
paste. Keep task layout, child-context floors, argument collection, output
nodes, final spelling copies and source-stamp ownership unchanged.

This is a producer/consumer fusion, not a range-expansion engine. It removes a
specific intermediate that still exists after #380; it does not repeat #380's
allocation work or reopen the rejected broad estimate.

## Layout and ordered algorithm

Current `CPpToken` is a 12-byte token plus packed stamp/foreign/spacing/no-expand
metadata, totaling 16 bytes. On the inspected x86-64 layout, the task's pointer,
16-byte payload and kind model a 32-byte row including alignment. Confirm the
actual `sizeof`/offsets on every supported producer before quoting that task
size as measurement. No new persistent row is needed.

```c
// Eligibility excludes builtin, pragma_like, has_paste and has_stringify.
N = definition.plain_count;
for each parameter j in definition order:
    N = checked_add(N, checked_mul(definition.parameter_use_count[j],
                                  arguments[j].expanded_token_count));

b = tasks.count;                         // index, never a retained pointer
reserve_existing_task_array(b + N + 1);   // include ENABLE; preserve capacity rules
logical = 0;
tasks.data[b] = enable_task(macro);

for each replacement position r in original order:
    if parameter_index[r] == NONE:
        t = exactly_the_current_plain_replacement_token(r, invocation);
        tasks.data[b + N - logical] = token_task(t);
        logical += 1;
    else:
        for each expanded argument token t in original order:
            t = exactly_the_current_argument_stamp_foreign_spacing_transform(t, r);
            tasks.data[b + N - logical] = token_task(t);
            logical += 1;

check(logical == N);
macro.disabled = true;
tasks.count = b + N + 1;                 // publish completed batch
```

The helper constructors must initialize the same task fields as the current
struct literals, including the inactive macro pointer field. There is no new
macro lookup, interning, argument expansion or pragma execution in this fill.
After reservation, no operation may invalidate the task base or retain a stale
pointer across a nested push. Check the arithmetic against both allocation
bounds and the existing supported replacement-count contract; do not introduce
silent truncation or change the diagnostic policy as an incidental optimization.

**Order proof:** the next pop reads slot `b+N`, containing logical output zero;
subsequent pops read outputs one through `N-1`; only then is slot `b`, the
`ENABLE` marker, processed. An empty replacement still leaves its marker, as
before. Suspended parent work remains below the original floor. Thus the
expansion/rescan order is identical if the payload construction is identical.

**Payload proof obligations:** ordinary definition tokens inherit the current
invocation stamp and foreign status. Substituted argument tokens retain their
`no_expand` paint and interior spacing while receiving the same stamp/foreign
updates as today. The first argument token uses the parameter occurrence's
spacing. Empty arguments must reproduce the existing replacement-position
spacing rule; do not change it to a convenient but different "first nonempty
token gets invocation spacing" rule. `#`/`##`, placemarkers and GNU comma
elision stay on the reference materialization route.

## Quantified ceiling, optional plans and SIMD comparison

For `N` eligible produced tokens, the source-level temporary payload is `16N`
bytes. Eliminating its write followed by its read removes up to `32N` logical
payload-transfer bytes plus one allocation per eligible materialization. This
is **not** `32` bytes per final compiler token, all macro expansions, or bytes
saved from DRAM. Optimized assembly may already eliminate some source-level
traffic; its actual stores/loads and arena behavior must be inspected. Existing
task writes, substitution work, argument expansion, final output and foreign
spelling traffic remain.

Observe eligible invocations, `N`, empty/short/long distributions, constant
versus argument output counts, definition-use multiplicity, temporary capacity,
task growth copies and peak pending tasks. The old [September 6 census][a06]
reported that most expansions did not touch a paste definition, but that is not
a current `N` estimate. Its old node population also predates the landed task
array; counting all those nodes as remaining savings would double-count work.

Start with the scalar producer. Compare scalar-batched two/four-token fills.
Bitsets are useful for selecting exceptional lanes, not intrinsically useful
when every plain output token must be constructed. AVX2 can move two 16-byte
payloads at once, but the task stride and metadata mean this is not a contiguous
32-byte destination copy. AVX-512 can load four such payloads, but constructing
strided task records, stamping, first-token spacing, reverse order, tails and
unused fields require shuffles/stores. A vector version loses if that work costs
more than the temporary it avoids. Use only the existing `simd.h` vocabulary
for any production candidate; no task-layout change solely to justify SIMD.

A secondary **unrun** idea is coalescing long, repeatedly used definitions into
small replacement operations:

```c
struct CReplacementOp {                  // proposed 16-byte record
    u32 source_begin;
    u32 count;                           // fixed definition run; dynamic for arg
    u32 parameter;
    u8 opcode;                           // COPY_DEFINITION or COPY_EXPANDED_ARG
    u8 spacing_mode;
    u16 reserved;
};
```

Existing `parameter_index` and use counts already form a compact expansion
plan. A second plan is justified only if run coalescing removes demonstrated
per-invocation interpretation and pays for its extra `16R` bytes, construction,
push/pop-definition ownership and cache footprint. Repeated parameter
occurrences retain separate spacing sites. Do not allocate duplicate plans for
every macro or extend this format into a new engine for paste/stringify.

**Bulk copying and independence:** macro-free source spans already bulk-copy to
final output. Expanded arguments proven unchanged already alias their arrays.
Within a macro-bearing line, a task run cannot be bulk accepted merely because
its identifiers are currently disabled: refusal must paint `no_expand`, and
an intervening `ENABLE` changes the state. Read-only `by_symbol` probes can be
batched only within a stable definition/disabled-state interval and then consumed
in original order. New symbol insertion, directives, pragma macro push/pop,
location-sensitive builtins and diagnostics are serialization boundaries.
Parallel expansion of arbitrary arguments is not valid. A genuinely independent
leaf would need to prove absence of contextual/stateful effects and preserve
ordered publication; this report finds no measured population justifying new
thread tasks for that case.

**Reject** if plain substitution is a minor current cost, generated stores are
not reduced, bounds/zero-initialization overhead consumes the benefit, macro-heavy
results do not survive whole-compilation measurement, or tiny/macro-free inputs
regress beyond the stated budget. A broad output-node/slab rewrite is not a
fallback deliverable for a failed experiment. It requires a new census and a
separate decision under #51.

# 6. Ambitious alternative: bounded block summaries and selective stage fusion

## Baseline and minimum useful experiment

The current item-aligned window starts at a known item boundary and deliberately
resolves difficult long items outside the window. It pays for overlapping
classification but avoids a general cross-block lexical state. Fixed 64-byte
blocks can remove overlap only by carrying sufficient state and deferred
emission. "Read each byte once" is not an adequate algorithm or cost model.

First compare **already-translated** fixed blocks, preserving
`c_translate_source`, checkpoints, `CToken`, source ownership and the final
preprocessor contract. A bounded four-block ring is an illustrative prototype,
not a new whole-file intermediate:

```c
struct CBlockSummary {                    // proposed 112-byte header/planes
    u32 translated_base;
    u16 byte_count;                       // 0..64
    u16 case_count;
    u32 case_begin;
    u32 event_begin;
    Mask64 plane[12];
};
struct CBlockCase {                       // proposed 16-byte control/action index
    u16 incoming_state;
    u16 outgoing_state;
    u32 event_begin;
    u32 event_count;
    u32 action_program;
};
```

The twelve proposed planes are eight exact byte basis planes plus derived
word-continuation, whitespace, digit and high-byte masks. Other character
queries can be derived or replaced by the existing class-vector scheme for a
fair comparison. A four-block ring has 256 byte slots and 448 header/plane bytes
before case tables, event traces, register actions, alignment and output slots.
This is bounded scratch, but **not** a claim that the complete algorithm fits
in 704 bytes. Retaining both basis planes and a class vector must earn its cost.

## A sufficient state summary, not quote parity

A control state must distinguish ordinary input, identifiers,
preprocessing-number continuation including exponent-sign eligibility, line
comments, block comments and a pending star, each quote kind and pending
escape, possible literal prefixes, and unfinished punctuator-trie prefixes.
Word validation additionally needs UTF-8 continuation count and restrictions,
plus whether the current word already owns an encoding diagnostic. Literal
payloads and comments must not accidentally inherit word-validation policy.

Unbounded token starts and locations are **registers**, not a tiny finite
state: token-start offset, first malformed-byte offset, original-source anchor,
line/byte-column accounting and output counters. A block action can leave a
register unchanged, set it to a block-relative position, or add a counted delta.
A spelling may span arbitrarily many blocks; the ring cannot discard source
storage or overwrite its live start reference.

For each supported incoming control state `q`, a sufficient summary is:

`Summary_B(q) = (F_B(q), E_B(q), A_B(q))`

where `F` is outgoing control, `E` is the ordered token/error/newline event
trace with position expressions, and `A` transforms the carried registers.
Composition is function composition with ordered trace concatenation:

```text
q1 = F_A(q0)
F_AB(q0) = F_B(q1)
A_AB(q0) = A_B(q1) composed after A_A(q0)
E_AB(q0) = E_A(q0) followed by E_B(q1), with register/output offsets substituted
```

This operation is associative because it represents sequential execution.
That is a correctness model, **not proof of an economical implementation**.
An implementation must enumerate the reachable control states and action
instructions, prove their transition table against the reference, and bound
case/event growth. Naively evaluating every incoming state costs
`O(number_of_states * block_bytes)` and can dwarf the saved rescanning. If
state-specific event traces cannot be shared or compressed cheaply, reject
parallel prefix composition and retain the cheaper single-carry stream.

Each block must retain the earliest applicable malformed-source event and the
same error order/recovery behavior as current lexing. A summary containing only
quote parity, whether a comment is open, or a token count is insufficient.
Likewise, delimiter work sometimes needs minimum prefix depth as well as net
depth; equal net counts do not establish equal continuation behavior.

## Multi-block bitplanes and fusion accounting

For four 64-bit words, a left shift includes the preceding word's high bit;
addition/subtraction-based span discovery must explicitly propagate interword
carry. For eight blocks, using one 512-bit vector for a plane does not make
its lanes one hardware 512-bit integer adder. Price carry construction,
comparison corrections, mask-register transfers, prefix passes and output
compaction. Compare ordinary scalar `u64` bitsets, scalar-batched independent
block classification, AVX2 classification, and the existing AVX-512 vocabulary.
The strongest width is an experimental result, not a premise.

Only after translated-block correctness and cost are acceptable should a
normalization/lexical-discovery fusion be tried. Let `K` mark raw bytes retained
by translation. A kept raw byte at position `i` has translated position
`base + popcount(K below i)`. A retained byte class may be compacted with the
same selection, but **CR rewritten to LF needs a new class**, and deletions can
join bytes into comments, punctuators, identifiers, escapes or UTF-8 sequences.
The trailing raw backslash/CR/CRLF state and translated token state are separate.
Reusing raw masks without remapping and re-evaluating adjacency is incorrect.

A full-feature prototype may compact bytes in registers and store the selected
count using current `simd.h` operations. Bit-plane extraction/deletion and
joining partial blocks remain separate operations; do not equate a `PEXT`
bit result with completed byte storage. Basic-tier/scalar alternatives must
remain bounded and correct. Do not add a PEXT builtin, general transposition
framework or replacement translator without a separately demonstrated need.

The fused design must still preserve contiguous spelling offsets and
translation checkpoints needed by preprocessing, diagnostics and canonical
source maps. Saving a read does not necessarily save a translated write.
Fusing classification into lex emission could also publish the existing
preprocessor masks or intern candidates, but then every consumer's buffer
lifetime, count alignment, early failures and tiny-buffer setup belong to the
experiment. The lexer **cannot write final preprocessed slots** before
conditional inclusion, directives, rescan and pragma effects have settled;
that earlier proposal was explicitly closed by [the August audit][a22].

Lexing currently precedes conditional filtering, so malformed word encodings
in discarded branches are diagnosed. A streaming/fused implementation must not
skip those bytes. If buffering delays diagnostics, it must prove identical
observable ordering and bounded resource use on an arbitrarily long malformed
item. Backpressure, error queues and repeated semantic work are charged, not
hidden as exceptional cases.

**Reject** if summaries require near-full per-state rescans, if mask remapping
and buffering cost more than overlap, if output materialization merely moves
elsewhere, or if a lexer-only win disappears after preprocessing/source-map
publication. Require a materially larger whole-compilation benefit than for a
small scanner port to justify the new state machine.

# 7. Token lengths, shared locations and identifier batching

These are investigated alternatives, not additional promised implementation
issues.

**Lengths.** Current `CToken.length` is a 16-bit field. Oversized terminated
literals use a sentinel and `c_token_length_oversized` scans for the true extent;
identifiers and preprocessing numbers have their existing long-word diagnostic
contract. Measure oversized spelling bytes multiplied by actual query count,
including the final metrics pass and foreign-copy sizing. A sparse
`{u32 offset, u32 length}` table for only oversized literals could cost eight
bytes per entry plus lookup/index overhead and remove repeated scans, but an
ordinary-token lookup must not be added to every length query. This needs a
measured repeated-long-literal population. [Current representation][lengths]

A compact sequential experiment could use `{u8 length, u8 gap, u8 shape}` with
escape records for large lengths/gaps and an offset anchor every 64 records.
Even before overflow records, the anchor adds 4/64 bytes per token; random
access still needs a prefix reconstruction. The format does not replace the
symbol field, origin metadata or exact whitespace needed for stringification.
If consumers still need 12-byte rows, the conversion reads and writes can make
this worse. A two-byte length/tag format is not a drop-in representation for
Buster's existing consumers.

**Locations and shared masks.** They are already deferred. An optional newline-
inside-comment bit or gap summary could avoid the definition gap-byte rescan,
but must be emitted for both scalar and compact paths and remain correct
through CRLF/splices. A single extra bit per token is `T/8` bytes before
allocation/lookup, not zero. Source maps currently encode foreign invocation
provenance through fresh spelling offsets. Removing those copies needs a
separate provenance representation across every consumer; it is not a free
extension of direct task production. [Definition gap scan][directives],
[foreign publication][pp-output]

**Identifiers/keywords.** Current first/last-word symbol keys and predefined
symbol classifications substantially narrow the work available. A bounded
candidate batch could hold eight 32-byte rows
`{u64 low, high; u32 length, token_index, slot, status}`: 256 bytes of scratch.
Compute independent keys/probes together, but commit new IDs in original token
order; equal names within a batch share the first inserted ID, collisions still
check full required spelling, and a rehash invalidates speculative slot indices.
The safe first experiment batches read-only hit probes and serializes misses.
Scalar-batched loads may outperform gathers; AVX2/AVX-512 staging and mask
compaction must repay their extra stores. Do not add a new keyword-spelling
ladder after interning already answered the classification. The historical
first-probe hit rate in [September 6][a06] was 87.7%, so a large improvement
from probing alone needs new evidence. [Current keys and intern algorithm][symbols]

# 8. Differential validation and safety matrix

Every experiment must compare its intermediate contract, not merely successful
compilation. Existing frontend tests and the native harness remain authoritative;
new cases belong there rather than in a replacement framework.

| Boundary | Required oracle and cases |
|---|---|
| Translation | Byte-identical translated data, checkpoint offsets, original-source positions and metrics against the forced-scalar path. Place each CR, LF, CRLF, backslash-LF, backslash-CR/CRLF and repeated splice sequence at every block phase. Include splices that join a delimiter, prefix, identifier, number or UTF-8 sequence. |
| Byte classification | Compare every mask and accepted extent at offsets 0-63, including all byte values and exact available-byte masks. For multi-block proposals compare every carry phase, not just aligned whole files. |
| Token emission | Compare count, kind, punctuator, length/spelling, symbol behavior, shape, diagnostics and metrics. Exercise lengths 0, 1, 7, 8, 15, 16, 31, 32, 63, 64, 65, 127, 128, 129, 65534, 65535, 65536 where meaningful for that token class; include long comments/literals and malformed long words. |
| Lexical states | `//`, `/*`, `*/`, comment newlines, every quote/prefix form currently supported, even/odd escape runs, other-quote payloads, EOF after backslash/prefix/slash/star, unterminated literals/comments, ellipsis/digraphs and overlapping punctuators, exponent signs, separators and numbers touching every boundary. |
| Encodings | Valid two/three/four-byte UTF-8 words, continuation errors, overlong forms, surrogates, values beyond U+10FFFF, truncation and spliced sequences. Preserve existing policy separately for comments, quoted headers, angle-header words and literal payloads. Verify invalid words in inactive branches, unused macro definitions and stringized arguments. No added normalization or identifier-category policy. |
| Macro scheduling | Empty and large batches, local-capacity and repeated-growth boundaries, suspended parent suffixes, context floors, intervening ENABLE markers, recursion/aliases, refusal paint on later rescan and function-like lookahead. Compare task-pop trace and payloads between old materialize-plus-push and direct production. |
| Substitution | Repeated/unused/empty parameters, raw versus expanded arguments, adjacent tokens and whitespace/comment gaps, stringify escapes, complete chained-paste placemarkers, invalid paste diagnostics and only the explicitly marked GNU comma-deletion case. Keep builtins/pragma-like cases on the original route. |
| Preprocessor state | Includes/guards/once, nested conditional inclusion, line directives, __LINE__/__FILE__, push/pop macro and pack pragmas, ordered source provenance and expansion-limit errors. Use #575's accepted tests/behavior after coordination; its current baseline failure is not a candidate regression or a passing gate. |
| Consumer result | Final token spellings/order, relevant flags, pack changes, recovered file/line/byte-column/origins, diagnostic kind/severity/message/order, source metrics, canonical IR behavior and byte-identical object/executable output for frozen deterministic cases. Do not compare raw host pointers as semantic identity. |

Allocation safety requires both **start and end** boundaries: independently vary
source alignment and lexical block phase, put the last readable byte against a
guard page, use read-only input, poison/canary destination slack, and run ASan
and UBSan in authorized CI. Cover lengths immediately around 32/64/128 bytes,
empty input, one-past-end pointer handling, an unterminated allocation-ending
literal, task-size multiplication/overflow, exhausted reservations and failure
paths. Verify the current sixteen-row physical emitter stores against allocated
slack, not only logical token count. Checked-size test seams can exercise large
count limits without allocating multi-gigabyte buffers.

Reuse and extend existing macro task-batch, empty-paste, preprocessing
short-circuit, encoding and scalar/compact differential tests. Required broader
gates are supported none/mir-stack/fast/quality modes, Debug/non-unity and
Release, relevant platform fallbacks, sanitizers, ordinary self-host fixed
point and feature-tier emitted-ISA inspection. An independent GCC/Clang token
or executable control is useful for supported compatibility cases; it is not
permission to change Buster's documented extension or diagnostic policy.

# 9. End-to-end measurement contract and rejection thresholds

Freeze compiler source SHA/tree, producer toolchain/version, build type, unity
settings, assertions/tests/allocator options, target features, source corpus
and include/generated-header hashes. Keep A/B compiler executables immutable.
Compile the same frozen source with identical working directory, output paths
and argv; do not let an optimization to Buster's own source alter the workload
being compiled. Preserve raw unsuccessful runs as failures, not deleted samples.

Use the [existing native harness][harness], its A/A qualification, raw data and
paired comparison, with [dedicated-host qualification][dedicated] where relevant.
No concurrent build/test/profile job may run on the measurement host. Do not
assume a hostname, virtualized CPU model or available ISA implies physical
Zen 5 ownership or a working PMU. Keep hardware retired instructions, cycles,
wall/user time, Callgrind `Ir`, requested bytes, page commitment and RSS as
separate measurements. Census/timing binaries must be separate.

| Experiment | Endpoint and denominator |
|---|---|
| Source to preprocessed tokens | Time the complete `c_preprocess` operation including translation, include work, expansion, metrics and source-map/C23 finalization. Consume and validate the final token stream outside the timed endpoint. Use an existing frontend benchmark/test seam or a temporary CI-only observer around this function; there is no claimed existing `--phase pp` CLI flag. Report raw and translated bytes, dispatches, input/output tokens and expansions. |
| Whole compile, trusted producer | Native harness baseline/candidate built with the same pinned Clang. Include default tiny/startup, symbol and other controls; optional macro workload; and frozen real unity/source inputs admitted by the existing harness. Keep all allocator modes separate. |
| Whole compile, self-built subject | For opportunity 1, build both subjects through the same supported bootstrap procedure and target flags. Compare their compilation of identical frozen sources, alongside fixed-point correctness. Clearly label this producer class separately from the repository's trusted-host performance numbers. |
| Cost census | Count the ledger's work, allocation requests, actual eligible replacement tokens, stop-distance populations, intern probes, map entries and oversized-length queries. Do not infer these from wall-time samples or leave counters in the timing binary. |
| Algorithm ablations | Compare current code, scalar work elimination, scalar-batched, optional bitset/AVX2 prototypes, and AVX-512, including setup/tails/fallbacks. Separate port-only, direct-task-only and combined candidates before evaluating interactions. |

An existing harness invocation for an **authorized host**, not executed here:

```sh
./build.sh bench_throughput run \
  --baseline /absolute/baseline/ide --candidate /absolute/candidate/ide \
  --output build/astra-simd02-macros-unique \
  --baseline-id BASE_SHA --candidate-id CANDIDATE_SHA \
  --profile ci --workload macros --mode all \
  --pairs 20 --warmups 3 --no-guard --require-identical-output
./build.sh bench_throughput compare --output build/astra-simd02-macros-unique
```

The optional macro set requires `--no-guard`; it does not replace or enlarge the
predeclared CI guard family. Run default controls separately. The harness's
usual two-pair smoke examples establish execution/determinism, not statistical
performance acceptance. Pin corpus recipes and paths; add representative
macro-heavy real sources through the existing workload ownership rather than
starting another downloader or benchmark generator.

**Proposed decision budgets, not measured results or new repository policy:**
predeclare a primary representative source-to-preprocessed-token series and a
whole-compilation series. For a claim of a substantial result, seek at least
5% improvement in the former and 1% in the latter, with the existing paired
uncertainty analysis excluding zero. A smaller proven gain may still merit a
separate maintenance decision, but must not be advertised as the requested
substantial reduction. Require no material regression in tiny/macro-free
controls, no more than 1% compiler text growth and 2% representative peak-RSS
growth without an explicit separately reviewed tradeoff. Use A/A variability
to decide whether a 1% regression can actually be resolved; otherwise report
inconclusive rather than passing by noise.

For opportunity 1, the primary improvement claim belongs to the self-built
series; trusted-host series must at least be non-regressing. For opportunity 2,
macro-heavy gains must survive a representative mixed/unity workload. For the
summary/fusion alternative, set a higher benefit threshold before building its
state machinery, and stop at the scalar-carry version if prefix composition
cannot pay for itself. Any semantic, provenance, deterministic-output, exact-tail
or self-host failure rejects the candidate regardless of speed.

# 10. Publication and remaining gates

This is a documentation-only research result. No claim is made that any proposed
algorithm has been implemented, benchmarked, validated in CI or accepted for
production. The existing reference implementations and historical negative
experiments remain authoritative until new exact-head evidence supersedes them.

The intended publication is this single new timestamped audit in a dedicated
branch/PR, cross-linked with substantive comments on #297 and #51. The shared
closed audit index and historical reports remain unchanged. The timestamp
opening was generated using the inspected helper's creation functions; no
full-checkout audit self-test or repository validation was run locally.

Access provenance: repository identity was read through the authorized GitHub
connector before writing. Public archive transport was also attempted for
inspection but local DNS/proxy resolution prevented download; connector reads
continued successfully. An initial branch call failed argument binding before
execution because it used an unsupported parameter name; after reading the
current schema, branch creation with the explicit analyzed SHA succeeded and
the ref was read back. This is not an authentication failure. No credential
values were read out or exposed, and no unrelated credential search was used.
File, PR and issue-comment publication must be verified by readback; their
receipt belongs in the PR/comments and final response, not an invented URL in
this immutable design text.

Unrun gates remain: current-main workload census; all candidate/reference
implementations; per-phase differential and allocation safety tests; trusted
and self-built feature-tier assembly checks; platform/sanitizer/mode/fixed-point
CI; physical-host qualification; A/A and paired preprocessing/whole-compile
experiments; and final acceptance/rejection. None of those gates is satisfied
merely by publishing this report.
