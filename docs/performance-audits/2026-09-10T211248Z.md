## Implementation

Append four opcodes, preserving previous replay opcode numbers. Consume
CLZWr/CLZXr/RBITWr/RBITXr from the existing normalized assembly metadata via
the importer; no handwritten production instruction words. Scalar trailing
counts are RBIT followed by CLZ. The i128 path loads both limbs, counts each,
and selects the primary count or 64 plus the secondary count with ordinary
MIR comparison/mask/arithmetic rows before allocation. The high result limb
is explicitly zeroed; the existing direct AArch64 zero-pair result of 128
is preserved. No new graph, allocation callback or encoder macro-operation.

The registered regression adds 24 object-compilation legs: three AArch64
desktop targets, four allocators including NONE, both frontend forms. MIR
legs require zero fallback and codegen verification. Native AArch64 desktop
hosts additionally execute the fixture in eight mode/frontend combinations.
Foreign object compilation is not recorded as target execution.

The fixture checks every 32/64/128-bit one-bit position, low/high and mixed
limbs, all-ones and all-zero pairs, and prefilled result storage. Its wide
builtin spelling is an existing Buster AArch64 extension; the Clang/GCC
control uses guarded 64-bit limb calls rather than truncating the operand or
calling a standard zero-input builtin. This AArch64-specific fixture is not
a new claim of x86 i128 builtin support. Eight independently assembled words
cover each width and zero-register operands. Production-plan tests retain
complete membership, invalid-field and packed-decoder-independence checks.

## Reproduction

Use the normal build driver entry points; `generate` must run only on an
idle build directory. In this container the Clang-bootstrap exception was:

```sh
clang -Isrc -Wall -Werror -Wno-unused-function -Wno-unused-variable -g build.c -o /mnt/data/issue36-counts-build
/mnt/data/issue36-counts-build generate --cc clang --ci --linker DEFAULT
/mnt/data/issue36-counts-build build --config Release -t ide
build/Release/ide test --verbose=1 --ci=1
/mnt/data/issue36-counts-build test_self_host --config Release
/mnt/data/issue36-counts-build test_mode_matrix --config Release
/mnt/data/issue36-counts-build import_assembly_metadata - src/buster/lib/compiler/assembly/generated/aarch64-llvm.jsonl src/buster/lib/compiler/assembly/generated --audit
```

For each allocator and frontend, compile `tests/basic_c_aarch64_zero_counts.c`
with `-target aarch64-linux`, then execute the linked binary with
`qemu-aarch64`; only NONE omits `-fno-machine-fallback`. Use O0 and O2 before
the explicit allocator option so last-option-wins cannot replace the mode.
For foreign-object checks, also select `aarch64-macos` and `aarch64-windows`
with `-c -g0`. The fixture requires an AArch64 target for Buster's direct
wide-count extension; external Clang/GCC controls use its guarded limb path.
