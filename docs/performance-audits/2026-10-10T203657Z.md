## Census that chose the design

The issue's background put the eager pass at about 18 M Ir. That figure is
stage 3's increase in the pass (audit `2026-10-10T014058Z`), not its size. On
this base, `c_ast_types_type_body` costs 359.73 M Ir inclusive, 3.80% of the
pilot's compile. Of that, 307.40 M is bodies (6,612 calls) and 52.32 M is
initializers (2,721 calls).

**A lazy trigger for bodies would save almost nothing.** #3304 gave
initializers a lazy trigger: an initializer is typed on its first query that
the literal fast path does not answer. A throwaway prototype (not committed)
applied the same trigger to bodies. 6,531 of the 6,612 bodies were still
typed, and the typed nodes fell by 81 (1,246,729 → 1,246,648). Lone-literal
queries that reach a body before its first fill also moved to the literal
path, so tree answers fell by 1,290.

**A per-subtree trigger would save at most about 10%.** A second throwaway
census marked every node inside the subtree of any node a query located.
958,049 of the 1,060,651 typed body expression nodes (90.3%) were inside one.
Typing per subtree would also have to recompute the start chains that every
query's lookup reads.

There is a third obstacle to typing later. `&` and casts are accepted only once
the rows they read are interned. The validators that run between
`c_ast_types_body_begin` and a body's first query can intern rows. A later
fill would then accept nodes the eager pass declines, so the answered set would
change. That is safe, because the fill runs only while the machine is idle,
but the budgets require that no answer change.

**The pass's cost is per node, and spread out.** Line-level Callgrind on arm B
showed no line above about 13 M. The largest items were:
- the loop's seven stores per node, for every node in the interval (statements
  and declarations included), about 23 M;
- the kind test, a range check with two exclusions, about 25 M with its loop
  branch;
- `c_parse_member_type`, 29.59 M over 110,420 calls from the pass.

## The change

Each item is exact: every node keeps the type and flags it had.
- **One table load classifies a node's kind.** A `u8` table is built from
  `C_AST_KIND_LIST` with the old predicate as a constant expression.
- **Only the arrays read before they are written are cleared.**
  - `flags`, `widths` and an initializer's `entities` keep a `memset`.
  - A node's type is read only once its `ACCEPTED` flag is set, and
    `c_ast_types_accept` writes both. A link is read only through a chain the
    node was linked into. Neither is cleared any more.
  - The span is stored for every node, before the node's rule reads it.

  A first version cleared every array with `memset`. glibc's large `memset`
  runs `rep stosb`, and Callgrind counts each of its iterations, so that
  version saved little in Ir. It was replaced before the census.
- **A per-pass member memo (`c_ast_types_member_lookup`).** It has 64
  direct-mapped entries, keyed by aggregate row and member symbol. It is
  exact because the pass appends no row and runs no machine, so an
  aggregate's members cannot change during a pass. It keeps only members
  found directly in the aggregate's own row. A promoted search into anonymous
  members takes guarded body scratch (#1256). A repeat of a promoted search
  could exhaust the guard at a later arena position, so it is looked up again
  each time.

## Reading

- The eager pass is 10.4% cheaper, and the pilot's compile 0.39% cheaper, on
  this host's Callgrind counts. No answer changed, and the default path's work
  did not change.
- `c_ast_types_lookups_agree` costs 48.31 M at query time. A memo for it would
  have to survive entity changes from machine runs and their rollbacks, so it
  is not part of this change.
- Hosted wall time was not measured. These counts are diagnostic, and no
  9700X comparison was requested, so performance validation is incomplete
  (#2761). The hook stays opt-in.
