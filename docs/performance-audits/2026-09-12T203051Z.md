## Base and implementation

Base: `7efd6c7ef203cc2ff590c8cb233ee50d335474ba`, tree
`b34e2c0b5088aa8fd4cf8e2f62dcc40dd2f7098f`. It includes main's #501/#505
repairs, the compact AArch64 ABI correction and checked I/O. No active owner
branch was overwritten. The earlier integration `eb1bef2f124c6a778a435ae1eda18ae489c489c5`,
tree `f9b5ae7c1db928ba646a4a4d1533cf2e68a505dd`, remains a separate evidence
checkpoint in #504.

`machine_x64_value_shape` admits frame-backed 32-byte vectors and 64-byte
vectors on models without the existing ZMM vocabulary. System V register
placement splits a value into XMM/YMM pieces or sends the complete value to
its aligned outgoing stack home. Win64's one-pointer YMM argument path reuses
its existing private-copy storage. Split Win64 references remain unresolved.

Explicit MIR load/store rows expose physical registers, memory effects and
owned frame byte offsets. New YMM transfers use AVX metadata tokens prepared
serially; no worker enters a generic assembler or a direct native emitter.
Verification rejects offset overflow and storage shorter than the transfer.
The part-width byte fits the existing 40-byte signature shape; the new static
size assertion protects that property. There is no new per-value table,
compiler pipeline or dependency.

Registered tests preserve `basic_c_vector_argument_ymm.c` and
`basic_c_wide_vector_argument.c`. `basic_c_wide_vector_abi.c` adds independent
scalar expectations, untouched sentinels, indirect calls and nine-vector
register exhaustion. Separate producer/consumer configurations exchange
objects with Clang and real GCC at Haswell width. All MIR legs require
`-fno-machine-fallback` and `-fverify-codegen`. The complete census still
records unresolved Windows baseline cases; the focused regression scope
does not redefine them as unsupported.

## Preserved development failures

The first new encoder attempt passed baseline XMM execution but failed YMM
encoding honestly: the new physical YMM shape and VMOVDQU token had not yet
been registered in the serial metadata cache. The fix adds that finite shape
and its mnemonic identity, retaining fail-closed lookup. The complete debug
suite then passed the newly registered tests but correctly rejected stale
metadata inventory totals. Updating those explicit inventories accounts for
two new MIR rows and six prepared encoding shapes; neither verifier nor
negative control was removed.

An immutable prototype compiler (33,670,320 bytes, SHA-256
`54f4473a4e208a9d921b9bcc2918b5fcef8642ecadc0fbecf50cc1e55fbdc25c`)
executed all **36** original whole-fixture configurations: two fixtures,
three CPU profiles, three MIR allocators and both C forms. These are
prototype results; final source/binary identities and broader gates are
recorded separately on the PR.

The initial GCC mixed-object run failed while writing assembly into the
full `/tmp` filesystem. That setup failure remains preserved. A fresh run
with explicit `TMPDIR` completed both directions: **12 Clang and 12 GCC
Haswell configurations passed** (three MIR allocators, two C forms, two
producer directions). Registered tests additionally cover both PIC settings.

Baseline cross-compiler execution is a genuine inherited ABI disagreement,
not a successful oracle: Clang 18 passes a 32-byte argument on the stack but
returns two XMM parts; GCC 13 also uses a hidden result pointer. Buster's
existing baseline ABI splits arguments into consecutive XMM registers. Both
Clang directions failed semantics; the GCC-producer direction faulted because
of the result-pointer mismatch, and the opposite direction failed semantics.
Disassembly, failed executions and exact commands are retained. This change
preserves Buster's supported behavior and does not rewrite those failures as
passing direct-reference controls.
