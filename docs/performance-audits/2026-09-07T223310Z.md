## What changed and what was rejected

Both compiler backends and the linker now share metadata-owned TLS address
recipes. The old initial-exec relaxation propagated ignored RIP-relative REX.B
into an ADD-immediate destination: `49 03 05 00 00 00 00` targeted RAX, while
its old relaxed form targeted R8. The new form targets RAX. Normal emitted TLS
objects remain byte-identical; acceptance of redundant REX input is retained
without retaining its wrong output-register interpretation.

An initial version prepared all 36 underlying form requests on the first TLS
use. Paired cold-process measurements showed +0.907 ms (FAST PIC) and +0.569 ms
(NONE PIC), versus +0.029 ms for the non-TLS control. That version was not kept.
Preparation is now split into GD, local-exec replacement and IE groups. A GD
object-only compile resolves only LEA and CALL; a non-TLS compile does no recipe
initialization. The prepared templates occupy 256 bytes plus two readiness/validity
masks. The recipe adds no heap allocation; it uses the existing metadata caches.

## Final local measurements

Release compiler built with Clang 17, non-unity, tests disabled for this binary;
5 exposed CPUs, 4 GiB container memory limit, AMD EPYC 9V74 host identification.
31 paired alternating-order fresh-process samples per case, after two discarded
warmup pairs, pinned to CPU 0. Wall time includes Python fork/exec, compiler
startup, metadata initialization and object emission. The host is shared and
not a controlled Zen 5 benchmark machine.

| `basic_c_call_abi.c`, FAST, non-PIC control | 17.536 ms | 17.775 ms | +1.36% |

The paired-difference medians are +0.254, +0.386 and +0.005 ms respectively.
A descriptive paired bootstrap (10,000 resamples, seed 99) gives 95% intervals
[-0.239, +0.578], [-0.164, +0.806] and [-0.197, +0.294] ms. These noisy samples
are not evidence of a speedup or a proven zero regression. No timing gate is
introduced from them. Hardware counters and allocation/whole-pipeline profiling
were not available; no cycles, cache-miss or branch-miss improvement is claimed.

A single `/usr/bin/time -v` FAST-PIC compile reported peak RSS 22,540 KiB before
and 22,416 KiB after. That small sampling difference is not a memory-saving claim.

## Correctness evidence and limitations

- **Full Debug suite:** 689,766/689,766 assertions, 41/41 modules. This includes
  294,552 new TLS assertions and the existing driver/linker execution coverage.
  Node 22.16 needed `--experimental-wasm-memory64` for an unrelated existing
  Wasm64 fixture. A local PATH wrapper supplied that flag; no test was skipped
  and no repository test or CI setting was weakened.
- **Focused ASan + UBSan:** all 294,552 TLS assertions passed, including the
  final selective-preparation implementation. This is not a full sanitized
  compiler/test-suite claim.
- **Before/after TLS matrix:** NONE, MIR_STACK, FAST and QUALITY, each PIC and
  non-PIC: all 8 object files byte-identical; all 16 linked base/patched programs
  exited successfully with matching output.
- **Mode matrix:** 24 legs passed, of which 4 executed natively and 20 were
  checked by disassembly oracle. Cross-target legs are not called native tests.
- **Self-hosting using the Clang-bootstrapped build driver:** base and patched
  Release compiler both passed the stage/fixed-point checks. Final stage times
  were 2.533 s (stage 1), 7.370 s (stage 2), 7.587 s (machine), 10.301 s
  (canonical). These single-run numbers are validation, not a throughput A/B.
- **Canonical TCC bootstrap:** first unavailable; subsequently obtained Ubuntu's
  TCC 0.9.27 and attempted `./build.sh test_self_host --config Release` on both
  untouched base and patched source. Both fail before compiler tests at unchanged
  `src/buster/lib/string.c:1072`, `array type expected`. The canonical bootstrap
  is therefore NOT marked green with this toolchain.
- **Full Release tests:** the unmodified giant metadata test translation unit
  hit the 4 GiB container limit. The compiler was validated separately in Release
  and the complete suite in Debug. No tests were removed from the PR/CI build.
- **External byte oracles:** GNU as 2.44 and Clang 17; GD/LE/IE forms agree.
  The documented RAX immediate encoding alternative is checked separately.
  Existing `test_all` reports zero external subprocess tests; checked-in
  independent golden-byte assertions are not misreported as that external count.

The normal CI workflow is unchanged by the final PR. Local passes do not imply
that every hosted CI configuration has completed; the PR checks are the source
of truth for those runs.
