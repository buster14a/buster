## Change and boundaries

The driver now publishes one arena-owned record for C, assembler and native
backend diagnostics, with stable codes, optional notes, source identity and
symbolic backend context. Linker errors retain their symbol and explicitly lack
an invented source range. Existing first-error/warning text stays available.
See the [provenance inventory and contract](../diagnostics.md).

An existing four-byte source-region slot retains original physical identity or
a macro invocation origin. Names of successful token-free headers remain lazy;
`#line`, macro/include locations and directive-only errors resolve both logical
and physical positions. Preprocessed assembly errors map back from generated
printer offsets only on failure, including the root dollar-separator adjustment.
The unit assembler's existing one-byte diagnostic lengths are retained honestly.

Strict machine fallback now renders a symbolic opcode or `not-applicable` while
retaining stable reasons, target/allocator/function, source context and internal
IDs. The conditional asm-goto `%l` template refusal receives a specific reason.
No lowering policy changes; existing codegen statistics remain the sole fallback
count owner. A current baseline CLI witness (`aese v0.16b, v1.16b`, AArch64 with
`-mattr=-aes`) supplies the generic message “instruction requires an enabled
AArch64 target feature”; the shared record preserves that exact evidence without
inventing required/effective feature names.
