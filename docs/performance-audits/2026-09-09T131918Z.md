## Native coverage and correctness

At base `3e6b470f077d57349ce1694348bbd2cd1fe8f411`, both native selectors
refuse `IR_OPCODE_CLEAR_INSTRUCTION_CACHE`. The x86 selector now accepts the
operation without emitting cache instructions; argument side effects remain
separate canonical instructions and are still selected. This matches the
x86 path in [LLVM compiler-rt](https://github.com/llvm/llvm-project/blob/main/compiler-rt/lib/builtins/clear_cache.c)
and the target-dependent contract of [GCC's builtin](https://gcc.gnu.org/onlinedocs/gcc-15.1.0/gcc/Other-Builtins.html#index-_005f_005fbuiltin_005f_005f_005fclear_005fcache).

AArch64 gains a constrained MIR barrier row. Begin/end use X9/X10; the row
clobbers X9/X11 and defines NZCV. Two inline loops clean data with DC CVAU,
then invalidate instructions with IC IVAU, with DSB ISH between/after the walks
and ISB at the end. The opcode is appended without renumbering existing rows,
and its expansion recipe and 64-byte encoding capacity are explicit.

The existing direct AArch64 emitter also had a boundary bug: it stepped four
bytes from an unaligned begin. For a range covering offsets 63 through 64,
it visited 63 then stopped, potentially missing the cache line beginning at
64. Round the start down to a four-byte granule for both loops. Cache lines
are at least four bytes (also reflected by compiler-rt's CTR_EL0 line-size
calculation), so visiting every intersecting granule covers both cache types
without assuming equal data/instruction line sizes. The direct oracle receives
this correctness fix too; its existing four-byte traversal policy is retained.

The permanent C fixture checks empty/short unaligned ranges, side effects in
both arguments, and seven integer values kept live across a flush. Machine
unit tests exercise both frontend forms, x86-64/AArch64 selection, all four
allocators, zero fallback and MIR validation. Native unsanitized Unix tests
execute 128 starting offsets per configuration. The AArch64 sequence, including
alignment, branch destinations and barriers, is compared with Clang's encoding
of `tests/differential/clear_cache_aarch64.s`, in all four modes including the
direct oracle. This is an independent instruction-sequence check, not a claim
that every host can expose an instruction-cache coherency failure.

The full x86-64 compiler's fallbacks drop from three to two: only `cpuid` and
`xgetbv` inline assembly remain. Broader inline-assembly and target-specific
ABI/unwind exclusions still prevent closing #36 or removing production fallback.

  forms) link the Buster subject to a Clang-built caller and run under QEMU.
  For this freestanding caller, remove the permanent host's stdio include,
  printf observation and unused buffer initializer; retain all self-checks.
  Compile it with `clang -target aarch64-unknown-linux -ffreestanding -fno-builtin

  with `qemu-aarch64`. All eight return zero. This exercises ABI/clobber and
