## The inference that the existing census cannot make

The analyzer defines `mutates_shared` by nonzero per-body deltas of only
`types`, `symbols`, `globals`, and `functions`. Its `pure` list is the
complement in the **serial execution**, after all earlier bodies have run.
Those names must not be read as a thread-safety or frozen-prefix certificate.
The old note already calls its scheduling calculations theoretical ceilings;
this addendum narrows what the input population itself establishes.

A source-level counterexample to the inference is enough:

```text
M0: the module immediately after serial preparation; key K is absent.
body A: lookup K misses; publish K with canonical ID k, producing M1.
body B: lookup K in M1 hits k; no table count changes.
body B against M0: lookup K misses. B is not independently eligible.
```

This is not an executed compiler fixture or an observed frequency. The
producer/consumer pattern is present: `c_ir_emit_runtime_call_source` scans
`program->symbols` by `link_name`, uses the existing symbol and function type
on a compatible hit, and otherwise publishes the runtime import. Pointer,
array and qualified-type helpers also reuse live tables/caches before adding
canonical types. Private caches alone do not freeze their backing tables.

A current-source read set is needed as well as append provenance. For example,
`ir_module_add_global` updates `label_address_relocation_count`, and
`c_ir_emit_global_place` consults that summary before scanning globals for
label provenance. A hit/miss-only sentinel is not automatically a guard on
such metadata reads. This is an obligation to check their semantic relevance,
**not** a reproduced cross-function label miscompile: a count change may be
irrelevant to the particular referenced symbol.

classifications, not claims that the present shallow builder copy implements
them. Source links use the exact base, not moving `main`.

| --- | --- |
| Semantic types and completion | `c_lower_to_ir_with_options` resolves type queries and incomplete-array bounds before its body loop; body type/expression queries consume those results. **I/S** only for completed data. | Canonical types and signatures | `c_ir_add_pointer_type`, `c_ir_add_array_type`, qualified-type and atomic/aligned/vector/runtime helpers -> `ir_program_add_type`; lookup and ABI/cast/SSA consumers read those IDs. **X** for appends; prepared declaration signatures and populated `c_type_ir_map` entries are **I** candidates; any later fills remain part of the write audit. ## Narrowest candidate worth falsifying next

Keep the existing serial preamble and canonical IR boundary. Do not create a
new IR or move body-dependent publications ahead of their serial first use.
The only narrow candidate still worth testing is a guarded closed-world body
attempt followed by serial replay of deferred bodies:

1. **Prepare serially.** Freeze the actually prepared objects and stable
   declaration/function IDs. Give workers private scratch, temporary marks,
   caches, query machines, diagnostics and retained function-output ownership.
   Establish the full shared read/write closure, not just the four counters.
2. **Attempt privately.** Use one function kernel for single-threaded,
   one-lane and multi-lane execution. A missing dependency must defer **before**
   shared allocation, append, lazy-map update or externally visible error.
   A mutable metadata read must be proven invariant or also cause deferral.
   Discard an aborted attempt's private rows; do not publish half a function.
3. **Publish in source order.** Replay deferred bodies through that same
   kernel in serial mode, preserving first-use IDs and static/string order.
   Adopt successful canonical function storage only where the original
   error/rejection state machine permits it. Keep all referenced storage alive
   through debug/object consumption. Reduce statistics in stable order.

This describes a candidate to falsify, not a completed safe design. In
particular, speculative hard failures/OOM, `had_error`-dependent behavior,
semantic cache writes and retained-arena ownership are unresolved. Fully
pre-lowering every body to discover its publications is not cheap preparation;
charge it as duplicated lowering, including discarded IR.

Use only the existing persistent gang. An active TU cohort must not launch an
inner function gang or multiply its CPU/memory allowance. The outer owner
chooses TU-level work or function-level work within the same budget; the
single-lane path still executes the same function kernel. No scheduler or
execution-policy change is part of this decision.

## Scaling model, not a forecast

For one frozen input, define `O` as work outside this boundary, `P` as serial
preparation, `E` as bodies that actually succeed against the frozen state,
`D` as deferred bodies, `w_i` as successful work, `a_i` as aborted prefix work,
`r_i` as serial replay work and `J` as merge/barrier/ownership work. A candidate
must account for

```text
T(p) = O + P + schedule_p({w_i : E}, {a_i : D})
       + sum(r_i : D) + J + contention/working-set effects.

schedule_p >= max((sum(w_i) + sum(a_i)) / p, max(w_i, a_i)).
```

The inequality is only a scheduling lower bound. Source-order replay and
working-set interference do not disappear into it. `O` is assumed unchanged
only for the model, not for acceptance. Serial-prefix zero-append rows give
at most an optimistic eligibility envelope for this specific frozen-preamble
candidate; they do not identify E or the aborted prefixes.

The historical #1025 stage-1 census reported 5,136 bodies, about 335 ms summed
body work, median 17 us, p99 711 us and a 29.97 ms largest body. Its 4,050
zero-append bodies accounted for about 130 ms; 1,086 publishing bodies
accounted for about 205 ms. **These are old diagnostic observations, not a
current measured eligible fraction.** The same study's many-small case had
6,002 bodies but a 7.7 ms largest body; its few-large case had five bodies and
a 14.9 ms tail. Counts alone are not a scaling argument. Preserve the tiny
input case rather than hiding dispatch overhead under stage-1 averages.

Peak storage needs a separate budget:

```text
M_peak = shared retained TU storage + already adopted function storage
         + sum(active or completed-unpublished private IR, scratch, temp,
               caches and diagnostics)
         + not-yet-reclaimed aborted work + merge storage.
```

Do not clone the retained TU per lane or multiply all retained function bytes
by p. Conversely, a net temporary-arena delta of zero is not a measured
high-water mark. The old 80.3 MiB maximum scratch observation and 696 MiB
retained body allocation total do not determine simultaneous p-lane RSS.
Current `E`, abort lengths, replay cost, merge cost and concurrent high-water
storage remain unknown; there is no current numerical speedup forecast.

## Smallest discriminating experiment and stop rule

Before a parallel kernel, run a **serial dependency-provenance diagnostic**
on a standard hosted correctness runner. Stamp lazy type/symbol/global
publications with the body that produced them; record the origins of actual
lookup results and semantically relevant mutable-summary reads. Start with
two admitted bodies reaching the same lazy runtime import (verify that the
chosen target really takes that helper), repeated derived types, strings and
static label-address initialization. Compare preparation-only origins with
the ordinary growing serial prefix. A body with zero appends but a required
prior-body origin disproves the old counter-only eligibility criterion.
This diagnostic must not report timestamps as authorized performance evidence.

A prototype becomes justified only after those traces identify a nontrivial
candidate population and **every** reached mutation/metadata read, failure
path and ownership lifetime has a guard or immutable/private proof. Finding
one eligible scalar example does not prove the whole lowerer safe. Conversely,
a complete frozen-read proof and demonstrated safe rollback would falsify
this note's present no-go for the bounded candidate; no permanent prohibition
is intended.

Required actual prototype regressions are stable-ID and canonical/object/debug
byte comparisons across ST/1/2/4/8 lanes, both frontend lowering forms, repeated
runs and relevant targets/modes. Include shared derived types/runtime imports,
constant/string identity, static/compound initialization, labels/computed
branches, supported inline/global assembly, debug locals/scopes, an early
invalid body followed by another error, and allocator/cancellation failures.
Use the registered suite and available sanitizer/thread-safety checks; do not
count unsupported checks as passes. Production enablement additionally needs
authorized uninstrumented performance acceptance. None of these compiler
experiments was run for this source-only addendum.
