## Why this removes work

`machine_parameter_edge_layout_plan` consumes the existing published CFG and
reverse-postorder layout. Ordinary topology receives final block IDs and a
sparse per-source destination map. Control targets use the first splitting
edge in stable raw successor order; label-address payloads use the canonical
entry independently. Selection emits each body followed by its required branch
blocks. Canonical edges publish directly with final source/destination IDs and
unchanged copy tuples. Definitions and line marks are born at final row positions.

This skips both canonical edge reconstruction and the general parameter-edge
splitter for eligible functions. It removes replacement instruction/block/edge
arrays, CSR scratch, the complete instruction rewrite and the instruction-sized
map used to repair definitions and line marks. It does not add an instruction
prepass. The planner counts edges once, numbers successors once, and installs
and clears only a source's outgoing destinations. Publication stays linear.
Functions with no CFG arguments skip the edge scan and map allocations.

Expanded topology and functions containing inline assembly retain the original
remap/split pipeline. Wide parameter-copy parts remain on the shared canonical
copy path. Block/edge capacity overflow falls back to the general refusal path;
checked definition-point construction records capacity failure before an
out-of-range point can assert. No public hot-row width or chunk policy changes.

The earlier copy-only trial is a distinct rejected experiment. It removed
22,185,576 intermediate payload bytes but changed whole-compile instructions
by +0.015095%, below the same screen. Its [audit](2026-10-15T084308Z.md), trial
patch and raw evidence remain unchanged. User steering required continuing to
an implemented gain; this broader design removes reconstruction rather than
adding chunk lookup around it. The thresholds were never lowered.
