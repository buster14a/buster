## Decision

Implemented, tested, and published for review. The candidate is not a
performance claim. The C parser re-derived the target data layout on every
builtin-kind layout query and every parse-side integer-literal fit. That work
survives Clang `-O3` code generation. On the unity self-compile it happened
**3,967,761 times**, always for one target.

`c_preprocess` now resolves one immutable `CTargetBuiltinFacts` record, 816
bytes, for the target it stamps on its result. It resolves it by calling the
two incumbent helpers for each of the 34 kinds. Parse-side call sites whose
target argument is `preprocess.target` read the record.

Whole-compiler work fell by **317.8 M instructions (−1.28%)** on the
self-compile, and every compared artifact and diagnostic is byte-identical.
About 195 M of that saving comes from a loop that #1297 and #1247 own
algorithmically. It shrinks when they stop re-seeding the whole type table for
each uncached query. The durable part is about 122 M (−0.49%).

Tiny compilations pay about 7.3 K instructions of setup and have nothing to
amortize it over. The smallest AArch64 object compile regresses by 0.43% in
instruction count.

Wall time, artifact latency and peak RSS are **UNMEASURED**. The approved,
exclusively leased 9700X route cannot run an ordinary A/B today: its only
admitted recipe is the `validate-buster-v1` smoke pair. No desktop or ad-hoc
SSH benchmark was run.

- a call-site table records calls into each helper.

## True scope

| Decision | Actual boundary | Disposition |
|---|---|---|
| Builtin-kind size/alignment and literal limit | `CPreprocessResult.target`, fixed by `c_preprocess`; nothing retargets a copy | **Resolved once per result** |
| Same facts during lowering | `c_lower_to_ir`'s own `target`, which tests make differ from `preprocess.target` | Untouched (`CIrTypeContext` already caches per kind) |
| Supplied `CPreprocessOptions.data_layout` | Detail block, independent of the target | Kept out of the record, as it was out of the helpers |
| Hand-built results | No detail block | Fall back to the per-call helpers |
| Default ABI versus `ms_abi`/`sysv_abi`, pragma/attribute layout, `_Atomic` widths | Per function, per declaration, per type | Not in the record |
| Host CPU capabilities | Resolved once at startup through cpuid | Not repeated |
| Codegen, object and link policy checks | A few per function or section | Not a hot family |
| Language, debug policy, output kind | Per input or invocation | Not a hot family here |

The record lives in the translation-unit arena beside the detail block, and
nothing writes it after resolution. Every consumer reads it after
`c_preprocess` returns, so it needs no lane prewarm. There is no global cache,
callback table or generated code.

## Costs charged

- **Setup:** 6,215 instructions per `c_preprocess` result: 34
  `c_parse_builtin_type_layout` calls (2,609), 34 scalar-property calls
  (2,479), and loop and limit arithmetic (1,127). The tiny rows above measure
  about 7.3 K end to end.
  - Break-even is about 100 record reads.
  - `-E` and `.S` preprocessing pay the setup without reading the record.
- **Memory:** one 816-byte, read-only record in the translation-unit arena,
  written once. The self-compile made 88.0 M fewer simulated data references,
  and D1 misses fell by 351,872.
- **Code footprint:**
  - In the Clang Release `ide`, the hot callers grew:
    `c_parse_type_layout_core` +393 bytes,
    `c_parse_expression_leaf_without_cast` +60 and `c_preprocess` +370.
    Total `.text` grew by 14,348 bytes, which includes the new test.
  - The self-hosted production executables (`BUSTER_INCLUDE_TESTS=0`,
    compiled by Buster) grew by 6,265 bytes of `.text`.
  - Simulated I1 misses fell by 1,760,155 (−1.2%) on the self-compile.
- **Branches (simulated, not hardware):**
  - conditional branches rose by 1,797,045, because each record read keeps a
    null check;
  - indirect branches fell by 3,967,769;
  - callgrind's small bimodal model reports +706,700 mispredictions overall.
    The largest per-function changes sit in functions whose code did not change
    at all, for example `c_parse_scalar_conversion_message` +585,472 and
    `string_equal` +362,924, with zero instruction or branch deltas. That is
    table aliasing from shifted code addresses, not a mechanism.
  - The hardware effect is **unmeasured**.
- **Prewarming:** none. There are no shared tables and no lane-time
  initialization.

## Correctness

- **Registered regression.** `c_test_builtin_facts_target_alternation` runs
  ten back-to-back units in one process: x86-64 Linux → Windows → Linux →
  AArch64 Linux → x86-64 Linux → AArch64 Linux → AArch64 macOS → x86-64
  Windows → AArch64 Windows → x86-64 Linux. Each unit does four things:
  - it checks every record entry against the helpers;
  - it folds `sizeof`, aggregate size, `long double` and `(char)-1 < 0` in
    enumerators and static assertions;
  - it types `2147483648` on the parse side, through the record and through
    the hand-built (null-detail) fallback, and in lowered IR;
  - it requires exactly one identical diagnostic from a false `sizeof(long) ==
    8` assertion on each of the three LLP64 units.

  The test also pins a supplied Windows layout on a Linux target outside the
  record.
- **Release `ide test --verbose=1 --ci=1`:** 3,233,827 of 3,233,829 assertions
  pass. The two failures are the pre-existing
  `compiler_driver_test_wide_vector_boundaries` assertions: this host's Clang
  18 rejects `-march=znver5`, independent of this change.
- **Debug (non-unity) build and `ide test`:** the same result.
- **Debug compiler on the unity self-compile.** Every record read is checked
  against the incumbent helper in this build, and no assertion fired. Its
  executable is byte-identical to the Release candidate's for the same command.
- **Registered `test_self_host --config Release` on the candidate:** passed.
  The fixed point is `SELF_HOST fixed_point bytes=46684360`, and the machine
  and canonical stages passed too. `STEP_INSTRUCTIONS` did not print, because
  `perf_event_open` is unavailable here.
- **Baseline fixed point, reproduced.** The expanded equivalent on main's
  source gives stage 1 = stage 2 =
  `84df3291ee7d64e5379fbd6d85f781b28c8c22bea97153648cbb6c3bf9c2aa3d`, the same
  bytes the candidate compiler produces from main's source.
- **Equivalence corpus: 1,584 of 1,584 cases identical.** Baseline and
  candidate `ide` ran with the same cwd, command and output path on:
  - every `tests/*.c` fixture for x86-64 Linux, x86-64 Windows, AArch64 Linux
    and AArch64 macOS;
  - the tiny, invalid and synthetic inputs above;
  - `basic_c_operations.c` at `-g0` and `-g`;
  - the full `-g` unity self-compile.

  There were 1,415 successful compiles with identical artifacts, and 169
  failing compiles with identical exit status and stderr.
- **GCC 13.3 `-fsyntax-only`** with the project's GNU warning set and
  `-Werror` accepts every changed file.
- **Not run locally:** Zig, MSVC, macOS and Windows hosts, sanitized trees,
  `test_all_combinations` and `clang_analyze`. Hosted CI on the pull request
  covers what it covers; nothing here claims it green.

## Unmeasured, and what would decide it

Whole-compiler wall time, requested-artifact latency, peak RSS, hardware
branch and I-cache effects, and any generated-program effect are all
unmeasured. Generated programs cannot change, because outputs are
byte-identical.

The expected size of the time effect is below this container's noise floor.
One approved, exclusively leased 9700X A/B would decide it:

- matched Clang Release builds of `ade6ac4` and the candidate;
- the frozen unity self-compile, `basic_c_operations.c`, one AArch64 tiny
  object and one header-heavy input, with A/A qualification and retained
  attempts;
- rejection if the tiny-input setup or the extra conditional branches erase
  the self-compile gain.

That route admits only its smoke recipe today, and service and admission work
is out of scope here.
