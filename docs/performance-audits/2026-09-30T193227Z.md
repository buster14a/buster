## Hypothesis and cheapest experiment

Question: **does the concrete token-row interleave require a new exact
dword-permutation primitive, or can the existing byte vocabulary express it?**

For each output dword `d`, let `I[d]` select one of 32 input dwords,
and let `M[d]` indicate an active output. Its equivalent four byte controls
are:

```text
byte_index[4*d + b] = 4*I[d] + b          for b = 0..3
byte_mask[4*d + b]  = M[d]
```

These indices fit the existing two-source byte permutation's 128-byte
domain. Copying all four bytes preserves the dword bits; clearing all four
inactive bytes preserves its zeroing-mask semantics. The proof is limited
to the fixed controls, little-endian representation, and exact byte
permutation semantics. It does not imply equal instruction costs.

The diagnostic has three implementations:

1. An independent scalar oracle writes each token row directly. It does not
   read either permutation-control table.
2. The candidate uses existing `simd.h` widen, shift, OR, splat,
   byte-permutation and ordinary/masked stores, plus private lane-typed
   addition. No header, IR or production kernel is changed.
3. The full-feature host reference uses the existing row writer's dword
   intrinsic sequence. It is compiled for the full feature tier.

Controls are built once outside the leaf. A production implementation must
charge their construction, storage and caller transport. The prototype's
private addition function also cannot simply become a per-operation call in
self-built compilers: the header's macro/no-inliner contract still applies.

## Strongest counterargument and next implementation boundary

**Counterargument:** a byte-permutation leaf can still help a complete
self-host compact-lexer port even with equal or worse trusted-host static
instruction counts. Hoisting controls into the actual window loop could
also change the comparison. This experiment does not reject that larger
consumer or prove dword permutation is unnecessary for its economics.

Smallest useful continuation: #297 owns a complete consumer inventory and
scalar differential seam. First make its proposed full port account for
masked byte selections, per-window controls, tails, source/token metadata,
feature tiers and macro call costs. Compare an existing-byte row writer
against a proposed exact dword form inside that same consumer. Add only
lane-typed addition and/or dword permutation if that complete comparison
justifies them; preserve scalar/MSVC/AArch64/self-host fallbacks and canonical
validation/lowering tests in the same series. #131 remains a separate
classification-census owner. Do not revive #133's rejected unique-bitset
scoring or add test/min/max/conflict/popcount for vocabulary completeness.

Transition #129 to `status/blocked`: the event that clears the immediate
gate is a selected consumer under #297 or #131 with a concrete profitable
mechanism and its executable validation/measurement route. A stand-alone
wrapper around the existing Clang intrinsics is not that event.
