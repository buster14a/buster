## Changes and boundaries

The standalone native C harness provides deterministic generated workloads,
separate allocator-mode series, adjacent paired timing, raw measurements and
replayable statistical comparisons. `build.c` owns tool construction and the
sequential same-runner baseline/candidate build command. The supplementary
GitHub workflow runs cross-platform harness tests and an opt-in Linux guard;
its repository variable and GitHub host check match the existing CI policy.
Normal compiler correctness CI and canonical self-hosting remain separate.

The default-off `BUSTER_BENCH_ALLOCATIONS` option adds calling-thread arena
request counts and requested bytes to the extensible source metrics file.
The counter snapshot precedes metrics formatting. It excludes alignment,
OS reservation/commit, live bytes and other threads. The normal hot allocation
path contains no enabled counter or runtime selection branch. The diagnostic
counter is the single production observer introduced by this recovery; the
separate historical allocation census is not layered on as a competing hook.
Its richer per-site/zeroing/OS metrics remain distinct follow-up work.

Two source corrections were required while recovering the harness. The
backend-pressure generator now draws its two random constants in separate
statements, removing dependence on C argument evaluation order. A pinned
corpus hash checks that ordering. A failed sample-path construction now stops
before building command arguments, keeping an uninitialized metrics path out
of the argument formatter; both rejection paths have regressions.
