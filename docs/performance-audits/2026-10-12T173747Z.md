## Workload

The arms compile the base revision's unity self-host source from a pristine
checkout of the base:

```sh
ide cc -Isrc -Ibuild/v3/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -fsyntax-only \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

The four arms:
- A: base, default flags;
- B: base with `-fc-ast-pilot`;
- C: candidate with `-fc-ast-pilot`;
- D: candidate, default flags.

`-c` uses the same input with `-c -o`, at `-g0` for instructions, and at
`-g0` and `-g` for object identity. Callgrind ran with `--cache-sim=no
--branch-sim=no`. Call counts are summed from the Callgrind `calls=`
records.

## The change

At the assignment site in `c_parse_validate_const_assignments`, the checked
typing of the value records the type-row count first. The conversion check
then goes through `c_parse_incompatible_checked_value`, which gains a
`simple_value_conversion` argument: a compound assignment keeps its scalar
conversion rule, and the three earlier callers pass `true` as before. The
type is reused when the checked typing succeeded and appended no row;
otherwise the value is typed again. Reference-check builds also run the
base's re-typing for every reused value and require the same verdict and
message.
