## Alias facts without consumers

The [operand walk](https://github.com/buster14a/buster/blob/ef8e826c5687f0589240e9c4dbc521beda964eb0/src/buster/lib/compiler/codegen/machine_x86_64.c#L8493) updates `use_block` and `last_use_ordinal`.
The [CFG argument walk](https://github.com/buster14a/buster/blob/ef8e826c5687f0589240e9c4dbc521beda964eb0/src/buster/lib/compiler/codegen/machine_x86_64.c#L8567) does the same for edge arguments. Their
only subsequent readers in this selector are the
[load-alias lifetime checks](https://github.com/buster14a/buster/blob/ef8e826c5687f0589240e9c4dbc521beda964eb0/src/buster/lib/compiler/codegen/machine_x86_64.c#L8659). `use_count` and `local_use` still
have other consumers and must stay.

Before these walks, 5,614 of 6,589 functions have only the sentinel local-use
entry. Qualification can only remove candidates afterward. These functions
cannot gain an alias root, yet their 828,074 ordinary uses and 49,460 edge
uses produce 877,534 last-use updates and 807,454 use-block updates. A guard
based on this existing empty table can target those 1,684,988 source-level field updates.

The larger population with no surviving candidate after the walk is 6,580
functions. That later fact cannot simply be used as an earlier guard. A
separate small observation in #4290 records 47,272 definition-fact updates
in 907 functions with no conditional branch.

This extends #4242's already-merged sweep guard by targeting the fact
producer. It does not revisit #560's negative initialization experiment or
#132's rejected result projection. Candidate measurement must include the
new guard and preserve direct-call suppression, local qualification,
ordinary/edge use counts, real alias lifetimes and generated output.

## Register records for results that emit nothing

The [classification pass](https://github.com/buster14a/buster/blob/ef8e826c5687f0589240e9c4dbc521beda964eb0/src/buster/lib/compiler/codegen/machine_x86_64.c#L8693) allocates registers before
[fusion](https://github.com/buster14a/buster/blob/ef8e826c5687f0589240e9c4dbc521beda964eb0/src/buster/lib/compiler/codegen/machine_x86_64.c#L9090) and [folded-read retirement](https://github.com/buster14a/buster/blob/ef8e826c5687f0589240e9c4dbc521beda964eb0/src/buster/lib/compiler/codegen/machine_x86_64.c#L9110) mark dead
results. The [emission loop](https://github.com/buster14a/buster/blob/ef8e826c5687f0589240e9c4dbc521beda964eb0/src/buster/lib/compiler/codegen/machine_x86_64.c#L9663) then emits nothing for them, and
the [compactor](https://github.com/buster14a/buster/blob/ef8e826c5687f0589240e9c4dbc521beda964eb0/src/buster/lib/compiler/codegen/machine_x86_64.c#L9960) removes unused records later.

The builder creates 1,236,234 registers across functions; 299,349 values
already carrying IDs are subsequently marked `fused_dead`. Each register
record occupies 16 bytes. Another 332 alias remappings overwrite their own
register IDs. The indexed all-hit control reproduces 4,096 fused-away
register results; the arithmetic and many-small controls have zero.

The bounded question is whether pure fusion/fold decisions can precede
record creation while retaining all type/refusal checks, final MIR after
compaction, typed origins, block parameters, mutable local identity and debug
homes. These cumulative payload bytes do not imply an RSS saving. #4233's
merged identity-compaction shortcut remains intact.

## Repeated ABI signature preparation

The [incoming selector](https://github.com/buster14a/buster/blob/ef8e826c5687f0589240e9c4dbc521beda964eb0/src/buster/lib/compiler/codegen/machine_x86_64.c#L8098) recomputes shapes and placements even
when the [call signature pool](https://github.com/buster14a/buster/blob/ef8e826c5687f0589240e9c4dbc521beda964eb0/src/buster/lib/compiler/codegen/machine_x86_64.c#L6417) already has a built plan for
the same canonical function type. The census finds 1,681 such definitions,
with 5,030 parameters and 1,380 non-void returns.

Reusing a complete immutable plan could avoid those repeated shape queries
and scratch arrays. `built` alone is insufficient: call-specific variadic
vector refusal may leave a partial plan, and incoming aggregate expansion
has a distinct safety budget. The next gate is to classify complete,
applicable plans and price reuse with every remaining incoming check.
Module/lane isolation and scratch-rewind lifetime must remain valid. Calls
first planned after a definition are outside this lower-bound census.

## Single block layout setup

[`machine_selection_canonical_layout`](https://github.com/buster14a/buster/blob/ef8e826c5687f0589240e9c4dbc521beda964eb0/src/buster/lib/compiler/codegen/machine_select.c#L294) allocates `layout`,
`visited`, `stack` and `cursors`, clears visitation, traverses, performs a
memmove, and checks identity before returning null for identity layout.
A valid one-block function necessarily has identity layout.

The unity population has 795 such functions; all 257 functions in the
many-small control qualify. This is a cheap exact guard with a modest unity
population, so it ranks behind the larger work populations. These are arena
suballocations, not heap allocations. The general multiblock path must retain
entry rotations, unreachable blocks, edge parameters, inline assembly and
wide-integer block expansion semantics. The shared helper also serves
AArch64, whose new shortcut would need validation.
