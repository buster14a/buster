## Question and disposition

[#3741](https://github.com/buster14a/buster/issues/3741) asks for representative
paste-chain exposure before implementing a repair, and explicitly directs an
immaterial result to be retained and deprioritized. Across 47 representative
translation units, every actual chain performs one or two joins. Intermediate
prefix retention is 0–0.077% of a translation unit's spelling space. The
32,000-fragment adversarial input still retains 512,178,662 spelling bytes.

The bounded census does not justify a production optimization for this corpus.
Retain the confirmed synthetic bound and deprioritize implementation. Reopen the
implementation question when a real workload exhibits a long chain or material
intermediate-prefix retention, or when the owner separately requests adversarial
resource hardening. This does not assert that the worst-case behavior is fixed,
that all applications have short chains, or that hostile input is harmless.

## Counter contract

The throwaway [census.patch](evidence/2026-10-12T180535Z/census.patch) instruments
`c_macro_paste_tokens`. It emits one call row and one row per consecutive chain
with actual joined spellings. Placemarkers and GNU comma handling retain their
existing control flow. `joins` counts actual concatenations, not every written
`##`; `bytes` sums each `joined_length + 1` spelling allocation. A chain's
`final` field is its last joined spelling length, and `max` is the largest
joined spelling in it. The six synthetic goldens verify the chain accounting
against `N-1` joins and the exact allocation sum.

For these successful chains, intermediate allocation bytes are derived as:

```text
sum(joined_length + 1) - sum(final_length + 1)
```

This excludes the final spellings that preprocessing must keep. Counts include
NUL terminators; final-length columns below exclude them. These are occupied
spelling bytes, not arena capacity, symbol-table storage, RSS or CPU work.
Prefix validation lexing, hashing and copying remain unoptimized. The census
reports no allocator or throughput improvement.

### Initial triage-rule correction

The [initial stop rule](evidence/2026-10-12T180535Z/initial-stop-rule.txt) was
[published before reading results](https://github.com/buster14a/buster/issues/3741#issuecomment-6129806919):
32 actual joins in a representative chain, or all joined allocations reaching
1% of TU spelling bytes, would trigger investigation. No chain trigger fired.
The all-allocations trigger did fire, including Buster tests-off (1.1384%) and
QuickJS `dtoa.c` (4.4311%). Those triggers and this correction are retained.

That broad byte metric includes necessary final spellings. It therefore ranks
ordinary one-join pastes as exposure even though they retain **no intermediate
prefix at all**. Separating final from intermediate allocations explains the
trigger without hiding it or claiming the original rule passed. The disposition
uses the directly counted chain population and this explicit intermediate-byte
derivation; it is not a predeclared performance acceptance verdict.

GCC/Clang comparison was performed; the issue retains its original oracle data.

and `./build.sh build --config Release -t ide`. Run
`./build.sh test_self_host --config Release` before applying the patch. Freeze

```sh

  --repo-root /path/to/instrumented-tree \
  --workload-root /path/to/unmodified-checkout \

  --probe /path/to/instrumented-tree/build/Debug/ide \
```
