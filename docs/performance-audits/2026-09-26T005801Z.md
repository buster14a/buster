## Production population and semantic obligation

`link_initializer_plan_build` calls the collector for ELF/PE/UEFI entry-stub initialization and finalization. `link_mach_initializer_prepare` uses it for Mach-O fini; Mach-O constructors are left to dyld. Some AArch64 hosted-ELF staging invokes the shared plan more than once; this change does not remove or multiply those calls. The caller already reserves one `LinkInitializerEntry` for each complete eight-byte slot, with capacity bounded to UINT32_MAX.

The obligation is precise: select the first aligned ABSOLUTE64 relocation for each complete slot; omit holes and wrong-kind/other-section/unaligned/out-of-range entries; preserve the signed addend (including foreign section-symbol-plus-offset relocations); order constructors by merged slot, reverse fini results, and never modify input metadata. Priority ordering precedes collection. The existing `link_initializer_arrays_order` is already a stable four-pass radix procedure, not another quadratic search repaired by this PR.

The observed production populations are the generated and existing fixture rows below, not a survey of all applications. Ordinary E=0 inputs do not benefit from this join removal. A project-wide speedup ceiling depends on the unknown fraction f of artifact critical-path time spent collecting initializers: even eliminating it completely gives at most 1/(1-f). No profile shares or total-CPU measurements are added or substituted for that missing critical-path observation.

Integration cost is four files (+353/-28 net against main): production C, unchanged private entry layout moved to the existing internal header for a test seam, registered regressions, and the linkage guide. There is no new IR, index lifetime, arena allocation, scheduler, dependency, persistent global state, callback or recursion.

## Mechanism and strongest rejected design

The incumbent searches R relocations separately for E slots: O(E*R) worst-case work. A straightforward alternative constructs a separate u32[E] relocation-index table, then emits the selected entries. It gives O(E+R) work and only one R scan, but adds four bytes per slot plus its allocation/initialization to the existing output reservation. That strong simple alternative is included as a correctness oracle; it was not timed or declared slower.

The first proposed destination-table design cleared every output slot. It failed a source-level resource falsifier: an arena reservation need not have resident pages, so initializing all E slots can fault in a huge sparse buffer that the incumbent never wrote. No-added-allocation is not equivalent to no-added-RSS. That first design was replaced before the submitted implementation.

The final mechanism uses the existing output space in two ways:

1. For dense inputs, `reserved` temporarily marks occupied slots. A relocation scan fills each slot once, keeping the first match. In-place compaction is safe because the output count never exceeds the current read slot; returned entries have `reserved=0`.
2. For sparse inputs, collect at most E/32 matching relocation indices into the output prefix, keyed by `(slot, original relocation ordinal)`. Iterative heapsort plus deduplication restores exact slot/first-match order without touching the whole reservation. With 32-bit identities heap height is at most 32, so K*log(K) with K<=E/32 is bounded by O(E). No new allocation is needed.

Zero slots/relocations do no output work. One slot retains early-first-match behavior. Exceeding the sparse prefix budget switches to dense collection and can revisit part of R. All preliminary scans, initialization, sorting, compaction, payload reads and final reversal are included in the O(E+R) bound; the transition is at most two R scans. The threshold is a structural bound, not a measured optimum.

Remaining counterargument: duplicate-heavy inputs can exceed the prefix budget despite few distinct slots and therefore still force dense page touching. Tiny E>1 inputs may also pay more setup than the incumbent. These are real memory/constant-factor risks requiring matched measurement, not hidden by the asymptotic result.
