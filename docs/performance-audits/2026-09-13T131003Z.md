# Astra SIMD 10: Zen 5 primitives and Buster self-hosting

## Decision and evidence boundary

**Improve the coverage and correctness of the existing substrate before adding
SIMD vocabulary.** The smallest useful implementation follow-up is to qualify
`BUSTER_SIMD_512_BASE` under the production header, admit the existing masked
byte load/store operations at that tier, then separate delimiter classification
from the compact lexer's host-only guard. Translation already uses four basic
operations; masked loads/stores still use the full-feature header gate today.
The delimiter helper needs only F/BW ISA operations and integer masks, not
VBMI/VBMI2, but its masked load must not accidentally remain a scalar helper.

Buster has real data-parallel compiler kernels and a MIR predicate path. This
inspection does **not** establish that a self-built compiler executes them
efficiently. The compact lexer still excludes `__BUSTER__`; exact-intrinsic
availability, efficient allocation, and final binary instruction quality are
three different questions. No current-main physical-host timing, final-binary
disassembly, or self-host execution was obtained in this research session.
Nothing here accepts a speedup or a native-retirement performance gate.

The three priorities are:

1. Resolve the production-header feature-tier correctness boundary tracked by
   [#574](https://github.com/buster14a/buster/issues/574), without presuming its
   proposed root cause is proved.
2. Independently enable and measure the existing delimiter algorithm under
   [#297](https://github.com/buster14a/buster/issues/297).
3. Investigate the compact lexer's concrete row-interleave obstacle using
   existing byte permutation and existing generic vector addition first;
   coordinate any genuinely necessary dword vocabulary with
   [#129](https://github.com/buster14a/buster/issues/129), not a new SIMD framework.

These are ranked by correctness dependency and bounded enabling value, **not
by invented nanosecond estimates**. The third is a falsifiable design
experiment, not an implementation recommendation already backed by measurements.

### Operation semantics and expected instruction families

These are desired/contractual forms, **not observed final disassembly**.
Buster's shared exact gate currently requires x86-64 F+BW for its whole
64-byte substrate, even where an individual dword ISA form needs only F.
VBMI is additionally required for byte permutation; VBMI2 for byte compaction.
A 256-bit EVEX experiment also needs the applicable VL feature. Raw ISA minimum,
header dispatch policy, OS-enabled state and actual CPU support must not be
conflated. [Canonical contract][semantics]; [production header][simd].

| Primitive | Exact semantics to preserve | Expected family / principal cost question |
|---|---|---|
| Masked byte load/store | Disabled load bytes are not accessed and become zero; disabled store bytes are untouched | `VMOVDQU8 ... {k}{z}` / masked store; tail setup and mask transfer can dominate short spans. |
| Byte equality / unsigned less | Bit i is the comparison result for lane i | `VPCMPUB` or equality alias, immediate 0 or 1; packed mask result is not an all-ones comparison vector. |
| Byte sign / bit test | High bit, or byte-wise AND-nonzero | `VPMOVB2M`, `VPTESTMB`; mask consumers may legitimately require a GPR representation. |
| Two-source byte lookup | Index low 7 bits select one of 128 bytes; inactive output zero | `VPERMI2B`/`VPERMT2B`; tied destination, copies, table residency and shuffle resources matter. |
| Stable byte compaction | Selected original lanes in increasing order; zero register tail; store form writes only selected count | `VPCOMPRESSB`; register and memory destination are distinct experiments, particularly on Zen 4. |
| Byte-to-u32 widening | Zero-extend exactly one 16-byte quarter | `VPMOVZXBD` plus a quarter extract where needed; a nonzero quarter is not automatically a one-instruction macro. |
| Dword comparison / splat | Unsigned u32 order; only low 16 result bits set; repeated 32-bit value | `VPCMPUD`, `VPBROADCASTD`; stale upper mask bits are a correctness failure. |
| Dword compaction | Stable selected u32 lanes, zero tail, ignore mask bits 16–63 | `VPCOMPRESSD`, not VBMI2 byte compaction; source fallback must obey the same contract. |
| Bitwise / dword assembly | Per-bit truth table, per-u32 shift, wrapping u32 addition | `VPTERNLOGD`, `VPSLLD`, `VPORD`, `VPADDD`; byte addition is not a substitute for dword addition. |
| Mask scans/reductions | Population count, first set only for nonzero input, shift counts in range | POPCNT and BSF/TZCNT as selected; the inspected MIR source explicitly uses BSF for trailing-zero lowering, so do not require TZCNT in a disassembly test. |

Do not assume the header's introductory “one instruction” statement includes
all constant materialization, spills, ABI transfers, quarter extraction or
integer/predicate bridges. Nor does a source comment asserting a Zen 4
compaction penalty constitute a fresh measurement on an identified machine.

### Width comparison, with a separate Zen 4 decision

| Variant | Useful role | Costs / rejection criteria |
|---|---|---|
| Scalar / SWAR | Small spans, dependent decisions, cheap setup, universal oracle | Correctly bound every load; account for per-window SWAR mask extraction and branches. A historical negative eight-byte delimiter experiment is a lead, not a current universal crossover. |
| Scalar-batched | Several independent probes/records, address generation overlapped without scatter | Preserve ordering and avoid speculative invalid accesses; compare against the same occupancy and address distribution. |
| AVX2 | 32-byte classification with established scalar mask extraction | Two chunks per 64 bytes; movemask/combine overhead; shuffle tables must respect narrower lane topology. Use bounded scalar tails where byte masked loads are unavailable. |
| EVEX-256 | Compact-mask instructions and masked operations at smaller width | Requires VL plus each operation's feature; twice as many chunks can offset lower per-operation costs. Prototype privately in the existing experiment, not as a new public vector framework. |
| EVEX-512 | Dense 64-byte class windows and 16-row field assembly | Shuffle throughput, live ZMM/k pressure, instruction size, mask/GPR traffic, loads/stores and effective frequency can become bottlenecks. |

For each CPU, measure dependent latency chains, multiple independent chains,
and the real mixed kernel separately. Choose enough independent accumulators
to stop a dependency chain from masquerading as reciprocal throughput. Inspect
register spills caused by over-unrolling. Test hot L1 data, larger working
sets, aligned/misaligned starts and realistic short tails. The lower bound is
constrained by dependency latency, instruction-specific resource demand and
memory traffic together; “four 512-bit units” is not a throughput formula.

Run the width/form comparison independently on a qualified physical Zen 4
non-laptop host. In particular compare register `VPCOMPRESSB` plus a bounded
store with memory-destination compaction. Do not import an old microcoded-uop
number or infer a universal Zen 4/Zen 5 ratio. No CPU winner is selected here.

## Ranked improvement 1: qualify existing operation tiers

**Symbols:** `BUSTER_SIMD_512_BASE`, `BUSTER_SIMD_512`,
`simd512_splat_word`, `simd512_less_word`, their `_fallback` implementations,
and the production-header `simd_tests` assertions. [Source][simd]; [#574][i574].

The issue reports four failed assertions on historical main `abd0820f...`,
Clang 18.1.3, in an F/BW-capable tier lacking VBMI/VBMI2. This session did not
reproduce those failures on `5865fa7`. A type/dispatch mismatch is visible in
the header: the type follows BASE while many operations follow the stronger
full-vocabulary gate. That establishes a test dimension, **not proof that a
byte-view access is undefined or that an optimizer caused the failure**.

Semantics: word operations treat lanes as u32, not signed i32 or four
independent bytes. Comparisons zero the upper 48 result bits. All fallbacks
must have identical observable bytes and bounded accesses under either
representation. No benchmark proceeds through a failing correctness tier.

Pseudocode for the experiment, not a proposed representation change:

```text
for producer in trusted-Clang, trusted-GCC, Buster-stage0, Buster-stage1:
    for tier in scalar, F+BW-without-VBMI/VBMI2, full:
        compile a fixture that includes the actual production simd.h
        record the effective feature macros and exact expanded operation
        for every operation already used by a compiler kernel:
            compare output bytes and mask bits with an independent scalar oracle
            compare enabled-memory effects with canary/guard-page expectations
        refuse performance interpretation if any case fails or body is absent
```

A future fix may narrow per-operation dispatch to the **already supported**
feature requirement or repair a proven fallback/lowering defect. Do not solve
it by changing only the test, pretending every F/BW CPU has VBMI2, disabling
all SIMD, or switching off canonical validation. Do not grow the vocabulary.

Expected native word sequence is a dword broadcast followed by unsigned dword
comparison and, when the C result is consumed, a correctly zero-extending mask
bridge. A scalar fallback has no exact ISA-form obligation, but its result does.
Useful tests include splat `0x01020304`, values 0/1/5/`0x7fffffff`/`0x80000000`/
`0xffffffff`, lane-distinct randomized values, all 16 comparison bits,
zero/full/single-bit compaction masks and high-only word masks. Run Debug,
Release and sanitizer configurations where supported, including a real BASE
host and a full host compiled with explicit VBMI/VBMI2 exclusions.

**Acceptance:** the existing reported failures and production-header
regressions pass non-vacuously across supported producer/tier combinations;
unsupported exact operations still refuse; MSVC/AArch64 fallback behavior
remains correct. Only then consider physical throughput comparisons. Owner is

## Ranked improvement 2: separate delimiter SIMD from compact-lexer admission

**Symbols:** `c_shape_matching_delimiter`, `C_SHAPE_DELIMITER_WINDOW`,
`BUSTER_C_LEX_COMPACT`, `BUSTER_C_TRANSLATE_AVX512`, `mask64_prefix`,
`mask64_count`, `mask64_first_set`. [Exact helper][internal].

The current helper is under `#if BUSTER_C_LEX_COMPACT`, whose definition requires
both the full feature set and absence of `__BUSTER__`. Yet its ISA operations only
need F/BW. The header currently puts `simd512_load_masked` and
`simd512_store_masked` under the stronger full-feature gate, unlike translation's
four basic operations. First qualify and move those existing operation
definitions to BASE admission for both trusted and self-hosted compilation;
retain scalar fallbacks and exact backend refusal. Then give the delimiter
consumer an independent internal admission condition and update its caller
guards consistently; **do not just
remove the guard around the entire compact lexer**. Preserve the existing
scalar caller path for unsupported producers/targets and tiny cases until the
crossover is measured. This is an implementation follow-up, not a patch here.

Existing algorithm, stated independently for review:

```text
D = 0
for each bounded window starting at open:
    X = masked_load(shape, prefix(min(64, end - base)))
    O = equal_byte(X, opening_punctuator_shape)
    C = equal_byte(X, closing_punctuator_shape)
    if D > popcount(C):
        D = D + popcount(O) - popcount(C)
        continue
    P = O | C
    while P != 0:
        lane = first_set(P)
        if bit(O, lane): D += 1
        else:
            if D == 0: return NOT_FOUND
            D -= 1
            if D == 0: return base + lane
        P &= P - 1
return NOT_FOUND
```

The skip certificate is sufficient because even all closers cannot reach zero
when `D > count(C)`. Equality is **not** enough to skip. Event order must be
preserved in the remaining window. Inactive loaded lanes are invalid-token
zeroes, which cannot match either punctuator shape. Never call first-set on
zero or shift a 64-bit mask by 64. Preserve overflow/bounds behavior and the
existing unmatched/invalid-sequence return value.

Expected long-window shape: hoisted byte splats, one masked `VMOVDQU8`, two
byte comparisons to masks, necessary KMOV transfers, POPCNT, and sparse scalar
BSF/bit-clearing work. There is no need for a horizontal vector scan, gather,
new canonical operation or allocator redesign. Multiple integer uses are a
reason to keep a GPR mask; repeatedly forcing it back into k registers can be
worse than an explicit bridge once at the useful boundary.

Correctness tests: lengths 0/1/15/16/31/32/63/64/65/127/128; every delimiter
position; all delimiter-free interior bytes; deep nesting; equal open/close
counts whose prefix reaches zero early; extra closers; unmatched openers;
returns across windows; inactive tails adjacent to a guard page; query ranges
whose storage includes unrelated valid tokens after `end`. Use all supported
allocator modes and check the SIMD body actually survives self-compilation.
The helper's internal empty-range test is separate from the production caller's
precondition that `open` names an opening delimiter.

**Acceptance:** exact token/diagnostic parity, no out-of-bounds access, strict
MIR success and verified final instruction path. Then compare frozen real
query-length distributions and whole compiler workload pairs for trusted and
self-built compilers separately. A guard change without a measurable aggregate
benefit may still be a parity improvement, but must be labeled that way. #297
owns the work; translation already enabled at this SHA is not part of the fix.

## Ranked improvement 3: a bounded row-interleave bridge, not a full API expansion

**Symbols:** `c_lex_store_rows`, `c_lex_compact`, `c_lex_iota`,
`simd512_widen_byte`, `simd512_shift_left_word`, `simd512_permute2_byte`, and
existing generic `IR_BINARY_VECTOR_INTEGER_ADD` selection. [Current row emitter][source].

The host emitter widens starts/lengths/kinds/punctuator IDs, adds the source
base to 16 u32 offsets, builds metadata, and performs **three masked two-source
dword permutes** to write 16 twelve-byte token rows. The symbol dword is zero.
Thus blindly substituting the four translation primitives cannot port it.
The source explicitly uses `_mm512_add_epi32` and
`_mm512_maskz_permutex2var_epi32`, not just byte comparisons.

A narrow experiment can express the dword interleave with the existing
full-vocabulary byte permute, avoiding a new exact intrinsic initially. For a
16-lane dword index vector I and 16-bit zeroing mask M, precompute:

```text
for j in 0..15:
    for b in 0..3:
        byte_index[4*j+b] = 4*(I[j] & 31) + b
        byte_mask[4*j+b] = bit(M,j)
R = simd512_permute2_byte(byte_mask, low_bytes, byte_index, high_bytes)
```

Proof: dword j selects four consecutive bytes of the same source dword from
the concatenated 128-byte table; all four output bytes are either enabled or
zero. This is an exact byte-layout equivalence, independent of a performance
claim. Reuse the emitter's three constant dword index tables and masks
`0xDB6D`, `0x6DB6`, `0xB6DB`; derive their byte tables once, not in the hot loop.
The ordinary 192-byte full-batch store remains unchanged.

Offsets still require u32 addition. **`simd512_add_byte` is not valid here**:
it loses carries between bytes within an offset. Explore an already-legal
u32 vector construction and generic vector addition, whose native selector
has a `VPADDD` form. A cast must independently satisfy frontend/canonical
conversion rules; vector type alone does not authorize an arbitrary bitcast.
If that construction fails current self-compilation, record the blocker rather
than inventing an intrinsic or bypassing validation. A bounded scalar row
emitter is the correctness fallback, with its cost reported honestly.

Expected vector core: four byte-to-dword widenings; dword base addition;
shifts and bitwise metadata assembly; three `VPERMI2B`/`VPERMT2B` zeroing
permutes; three 64-byte stores; bounded shape-sidecar store. Required quarter
extracts, constants and tied-operand copies are additional instructions, not
ignored overhead. Compare against the existing host dword-permute sequence.
Byte permutation may lose on a particular CPU; that is a valid rejection.

This leaf experiment does not complete `c_lex_compact` self-hosting. The rest
of its host intrinsics, lookahead loads, class-mask pressure, compaction, calls
and tail paths still need a complete conversion/correctness census. Test the
leaf first instead of making a sweeping lexer and backend patch together.

Tests: all sixteen output rows with lane-distinct offsets/metadata; source
bases near byte/word carry boundaries; modulo-u32 behavior where allowed by
the existing source-space contract; every field byte; zero symbol dwords;
three-mask equivalence; canaries beyond the 192-byte destination; shape-store
mask preservation; separate partial-batch handling; complete token stream,
spelling, location and diagnostic differential tests including UTF-8,
comments, escaped newlines, pp-numbers, digraphs and tokens crossing byte 63.
Preserve `c_lex_scan_one` fallback behavior rather than broadening acceptance.

**Acceptance:** byte-identical leaf output plus full lexer parity and verified
strict-MIR self-built lowering. Reject the substitution if its shuffle/copy/
spill cost harms the measured workload. Only if an existing-vocabulary route
is inadequate should #129 consider a minimal masked dword-permute operation,
backed by this real consumer, with the existing canonical/exact contracts and
all backend refusal tests. This report authorizes no such API or IR change.

## Reproducible paired physical-host experiment

### Admission and identities

Use the existing C harness and admitted service; no laptop runs, shared-host
pilots presented as acceptance, or bypass of #422/#437/#512. Obtain independent
physical Zen 5 and Zen 4 non-laptop hosts. Before building, acquire whole-job
exclusivity for fetch, build, tests, profiling and artifact capture. A runner
label, `/proc/cpuinfo` brand string or absence of a hypervisor flag alone does
not establish physical hosting or exclusivity; retain provider/host admission
and service job/lease evidence with the observed machine manifest.

Record CPU vendor/brand, family/model/stepping, CPUID leaves, microcode, cores/
SMT/topology, BIOS/power limits, kernel, memory configuration, online/affinity
sets, frequency policy and observed thermal/frequency state. Capture the
OS-enabled extended state for AVX and AVX-512 as well as advertised features.
Verify F/BW/VL/VBMI/VBMI2 individually, and CD/BITALG/VPOPCNTDQ only for an
experiment that actually uses them. Do not infer support for unrelated
extensions from “Zen 5.” Match exact-SKU optimization/errata/event documents
before selecting raw PMU encodings.

Freeze source commit/tree, dirty-state check, producer compiler version and
binary SHA-256, linker/resource headers/sysroot/generated headers, all compile
and link argv, configuration, unity/tests/libc settings, target features,
allocator mode and fallback policy. Retain both compiler executable hashes and
all input/output hashes. Workload source must stay frozen when the compiler's
own implementation changes. A SHA supplied as a command argument is not proof
that it produced a given executable. [Existing contract][retirement].

### Separate producer and variant axes

Construct trusted-host stage 0 compilers for A/B using the same pinned Clang
(and a separate GCC correctness leg). Construct self-built stages with exact
producer links: stage 1 produced by stage 0, stage 2 produced by stage 1.
Save every binary and argv. Run the existing self-host fixed-point gate and
mode matrix; do not substitute a microkernel test for them.

Run **separate paired experiments** for trusted A versus trusted B and
self-built A versus self-built B. A trusted-versus-self-built comparison is a
third explicitly labeled experiment, not the improvement estimate for either
producer. Record stage construction time separately from compiler execution
throughput. Keep workload source, target and output contract equal; legitimate
producer closure differences are not a license to compile different inputs.

For the width experiment, freeze scalar, scalar-batched, AVX2, EVEX-256 and
EVEX-512 variants that perform the same useful work. Private experiment
variants must not become an unreviewed SIMD framework. Separate width changes
from algorithm changes. Warm-up and randomize/alternate pair order using the
harness policy; run an A/A qualification first. Determine sample count from
that noise qualification and the existing approved guard, not after seeing
which result wins. Report all timeouts and failed rows.

These commands have not been run here. Preserve symbols/debug correspondence

Disassembly checklist: scalar loops or helper calls replacing hot operations;
repeated constant loads; redundant moves from tied permutation operands;
mask/GPR round trips; k and ZMM spill/reload bytes; required ABI transfers;
EVEX length and zero/merge modes; quarter extracts; unsupported forms;
accidental direct-backend fallback. Check both expected presence and negative
controls. Explicit intrinsic refusal is a failure, not a successful fallback.

### Measurement and raw-evidence schema

Uninstrumented paired wall time and peak RSS are primary. Record emitted
bytes and correctness hashes. Instrument work counts and PMU runs separately
so added counters do not become the candidate being timed. Where authorized
and supported, capture cycles, retired instructions, branch misses, relevant
cache/load/store events and effective frequency with exact event definitions,
permissions and multiplexing/scaling status. Unavailable counters are missing,
not zero. Floating-point width counters do not validate these integer kernels.

Store one row per raw observation with at least:

```text
experiment_id, service_job_id, host_manifest_sha256, pair, order,
producer_kind, producer_sha256, compiler_source_sha, compiler_tree_sha,
compiler_binary_sha256, workload_manifest_sha256, argv_sha256,
variant, mode, feature_set, workload, input_sha256, input_bytes,
queries, windows, useful_lanes, selected_lanes, emitted_rows,
wall_ns, peak_rss_bytes, cycles, instructions, counter_validity,
effective_frequency_observation, output_sha256, exit_status
```

No rows are fabricated here. Keep missing diagnostic work counts distinct from
zero and from uninstrumented rows. For useful-lane accounting, count valid
input elements and actual selected output, not an assumed 64 per operation.
Separate query setup, table loads, classification, compaction, ordered sparse
work and output materialization in the diagnostic run. Measure code bytes,
spill traffic and reachable helper calls per kernel.

Replay paired ratios and uncertainty with the existing harness, including
per-workload outcomes and aggregate policy. Do not trade a correctness failure
or a severe workload regression for a favorable average. The native-retirement
budgets remain owned by #511/#512; this research does not invent new acceptance
thresholds for those issues. A statistically inconclusive result remains
inconclusive, and no microkernel gain alone establishes compiler throughput.

## Smallest shared substrate change

After #574's correctness boundary is qualified, **admit the existing masked
byte load/store operations at BASE, then give F/BW classification consumers
their own admission condition instead of inheriting the compact lexer's
full-feature, host-only guard**. The first added consumer is the existing
delimiter helper; translation already exercises the related unmasked
load/store/splat/equality substrate, and existing preprocessing/shape scans give
real follow-up consumers without another permanent representation. Keep the
public `Mask64` integer contract, masked-tail semantics, scalar fallback and
canonical validation unchanged. Measure rather than presume the width choice.

Do not begin with a new mask allocator, scatter/conflict API, permanent IR,
inline-wrapper framework, or work in the direct backend scheduled for
retirement. A qualified basic tier plus an independently enabled real consumer
is the smallest useful next step; the compact row-interleave experiment is a
separate, higher-risk follow-on with an explicit reject condition.
