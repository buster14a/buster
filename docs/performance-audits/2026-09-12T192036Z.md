## Coverage and validation

Fixed FNV-1a assigns module basenames and paired tests. Workers preserve the
original directory and semantic arguments, run at most one analyzer each,
continue after failures and publish terminal evidence last. Aggregation requires
every selected TU exactly once and verifies report identity and diagnostic-log
hashes. No cache or unchanged-file skipping was introduced.

CI self-tests exercised warnings on both streams, nonzero exit, crash, timeout,
large simultaneous stdout/stderr, failed launch, missing/duplicate coverage,
stale/malformed reports, missing/changed logs, changed configuration, empty
inventories, duplicate workers, independent single-shard execution/aggregation,
quoting, and reanalysis after a transitive header changed. Windows AArch64 also
passed these controls after non-timeout oracles received a 30-second deadline;
only the deliberate sleep control keeps the one-second deadline.

Split analysis exposed paths hidden by unity analysis. Associated source changes
short-circuit invalid-type checks, guard empty copies and optional storage, and
state existing count/storage and lexer-window contracts at their consumers. No
checker was disabled and no file exempted. The
[self-host fixed point](https://github.com/buster14a/buster/actions/runs/34712928526)
and [compiler throughput guard](https://github.com/buster14a/buster/actions/runs/34712928353)
passed on the submitted implementation. Full-platform CI results belong to the
PR's submitted revision checks, not to this timing table.

Earlier attempts stopped the reference on warnings and did not measure equal
completed work. Run `34712536279`'s reference time of 126.238259 seconds is **not**
a clean baseline and is excluded above. Its candidate still checked all 101
TUs, demonstrating continued coverage after a warning.
