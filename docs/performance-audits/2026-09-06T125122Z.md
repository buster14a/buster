**Measured negative kernel populations must accompany the aggregate win.**
Four/eight-character base64 chunks made SIMD 1.875x/1.396x slower. Sixteen
characters changed sides across exploratory and final runs, so no robust
crossover is claimed. A four-byte plain literal body made SIMD 1.451x slower.
A 128-byte body made entirely of `\n` escapes made SIMD **6.766x slower**:
0.57490 versus 3.88981 ns/spelling byte. Each escape pays another masked
window, compare and zero-prefix store, with almost no literal bytes to copy.
The all-identifier population was 3.6% slower in the final run; its earlier
near-neutral result makes small differences provisional. A dense-escape
strategy and short-input handling need distribution-weighted measurements;
the corpus win does not establish universal break-even.

Assembly inspection found no vector spills. Base64 retains its table halves
and uses two multishifts and two permutes per 64 input characters, producing
48 output bytes. Quoted decoding retains its scalar escape call and scalar
index/count stack traffic. Identifier selection uses mask load/compare and
`tzcnt`/`blsr` visits; Clang unrolls its outer loop twice and the scalar row
loop four times. The shipped base64 kernel still uses raw `__m512i`
intrinsics: `simd.h` has no multishift operation. This is an existing
vocabulary gap, not a claim that the prior implementation already complies.
No kernel implementation was changed this round.

count-only call sites, two lowering count-only sites, and 18 production full

**Decoded metadata / `#embed` prerequisites.** The generated x86 header is
6,052,285 bytes, with a separate 389,599-byte coverage include. Decoded payload
is 4,920,867 bytes: a 1,726,254-byte string pool and 13 numeric blobs totaling
3,194,613 bytes. There are 11,013 forms, 32,813 operands and 11,013 coverage
rows. Expanding all bytes into ordinary comma-separated integers would create
about 9.84 million tokens and recreate initializer work.

`c_preprocess` currently rejects `#embed`; there is no binary payload token.
Keep the 12-byte `CToken` and introduce a payload side table rather than
disguising arbitrary bytes as an oversized quoted literal. Array-bound
inference and bulk initialization must preserve mixed/designated initializers,
empty payloads and non-byte destinations; embedding does not append a NUL.
The authoritative `build.c:xed_generated_emit_tables` already owns decoded
bytes before base64 serialization. Emit deterministic binary artifacts there,
update the inventory/checksums in `assembly_import_validate_checked_in_x86`,
and use the reduced JSONL round-trip route rather than hand-editing generated
tables. Preserve the flat little-endian readers initially: 156-byte forms,
16-byte operands and 25-byte coverage records cannot be blindly cast to native
structs. Native compiler capability/fallback and both self-host stages need
the same supported representation.

Feature support and workload conversion are different experiments. First gate
frontend support on the old frozen tree. Then compare two compilers that both
understand one frozen embedded workload. The old compiler cannot consume the
new directive; different-source image sizes/counts are not a frozen-tree win.

**SPMD codegen: verified prerequisites beyond global prewarm.** The per-function
machine attempt is a useful boundary, but byte identity is conditional:

| Shared state or ordering | Concrete treatment |
| --- | --- |
| `MachineSelectionModule.x64_signature_plans` fills lazily across functions | Prebuild all plans serially or give lanes independent plans; allocation alone does not freeze them. |
| `IrProgram.source_cursor` changes in `ir_source_position` | Resolve lines in ordered merge or introduce caller-owned cursors. |
| Persistent worker exit rewinds/decommits scratch arenas | Copy compact fragments to explicit durable lane arenas or finish ordered merge behind barriers before callback return. |
| Module-global last-line suppression | Reapply `codegen_record_line_hot` semantics across function boundaries. |
| Inline assembly changes symbol binding/visibility | Preserve its source-order dependency before selecting affected later functions. |
| Lazy forms, exact caches and ABI/type state | Fully prepare before the first persistent gang, including `buster_x86_metadata_prewarm_all_forms`; later idle workers are still live threads. |

The inline-assembly dependency was reproduced with two tiny `-c -fPIC`
fixtures. Both end with `foo` GLOBAL HIDDEN UND. When a function containing
`asm(".hidden foo")` precedes `later`, `later` uses a PC32 call and has 36
bytes; reversing the definitions produces a PLT32 call and 33 bytes.
Canonical fallback counts also differ (one versus two, including an encoder
rejection). This is existing source-order behavior, not nondeterminism in the
serial compiler. Parallel selection followed by serial fallback cannot
preserve it automatically. A bounded first implementation can reject modules
whose summaries contain inline asm, or process parallel ranges separated by
those functions, emitting each separator serially.

Use one uniform lane entry, an atomic function index and source-indexed compact
fragments. Merge bytes, padding, relocations, lines, unwind/label offsets,
statistics and failures in original function order. Keep retry-owned storage
out of longer-lived caches. Preserve module assembly after function emission.
Lane-count differential tests must include repeated dispatch, fallback/PIC
inline asm, debug-line boundaries, label relocations and capacity retry.

The opcode projection must derive from authoritative metadata. USE_DEFINE
belongs to use plus use-define, not define-only; physical/virtual/block operand
kinds remain dynamic. Constraint classification combines five sources. Keep
out-of-range validation, full clobber masks, ties/fixed registers and QUALITY
facts. Existing selector type/value projections, typed streams and compact
line marks must not be recreated. Slot and call-target AoS-to-SoA finalization
still materializes columns; removing it requires a consumer-boundary change.
FAST and the encoder independently scan vreg class bytes; any class summary
must be correct for hand-built/replayed and scheduled MIR too.

**QUALITY and scheduling require a separate workload.** All driver `-O` levels
select FAST; pass `-fregister-allocator=quality` after any `-O` flag. Scheduler
entry also requires reloads/spills, then modeled pressure and eligible block
size; moved rows cause another QUALITY allocation. Measure initial placement,
scheduler candidacy and second placement separately, using existing allocator
telemetry (`scheduled`, `schedule_kept`, spills/reloads/pins/splits). The
`tree32`, `lean` and `split_phase` fixtures in `machine_test.c` provide distinct
populations. Switch-heavy functions are a separate control because QUALITY
delegates them to FAST. Neither absent stage-1 scheduler samples nor current
source counts price those paths.

**Frontend/middle-end structural follow-ups remain unpriced.** A range-based
macro engine would replace per-token task pushes in `c_macro_materialize` and
argument contexts plus output-list flattening in `c_preprocess_expand`.
Ranges must retain ENABLE ordering, permanent `no_expand` paint, invocation
stamps and stringification whitespace; replacing tokens with spans alone does
not prove expansion equivalence. Lowering already has a matching-delimiter
index, so a group-facts proposal should add only facts required by at least
two consumers and respect each query's end boundary. An active symbol binding
array can accelerate the ordered parser binder, but arbitrary-scope and
token-visibility queries after binding still need a correct persistent path.
No range-engine, group-facts or binding-array patch was built without a fresh
profile. The IR value-emission helpers and copy callers named by the previous
audit still need their requested measured census.
