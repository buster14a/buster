## Design and accounting

A stable outgoing compressed-sparse-row index stores **raw edge IDs**, not
copies of edge rows. It exists only when at least one edge needs splitting.
The index is reused for split-block numbering, source-local target publication,
and split-block emission. A block-sized cursor array first fills the outgoing
index, then becomes a destination-to-first-split map. Its reset visits only
actual outgoing entries.

Updates for repeated destinations remain ordered scalar operations. A preceding
no-copy edge does not win over the first edge that actually splits; later split
duplicates do not replace that winner. All duplicate edges still produce their
own output edge records in original raw order. Switch target duplicates use the
same mapping. Computed-label addresses retain original-block identity through
`old_to_new`, while branch/target-set references may redirect through a split.
Copy slices, copy order, flags, definition-point phases, and final-row line marks
are preserved. Invalid edge endpoints are rejected before indexing in a
function that needs normalization; this is not a new general MIR verifier.

Let B, E, I, K, Q, V and L denote original blocks, edges, instructions, switch
records, target references, virtual registers and line marks. The repeated
search portion changes from O(B*E + Q*E) to O(B + E + Q). Including all copying
and remapping, the bound is O(B + E + I + K + Q + V + L), with no per-source
full-map reset. These are source-level work bounds, **not measured counters**.

Publishable arrays are allocated first. All six scratch arrays follow one arena
checkpoint and are reclaimed after publication or failure. Scratch contains
`I + 2*E + 3*B + 1` u32 words, plus allocation alignment; the additional peak
index requirement over the old maps is `4*(E + 2*B + 1)` bytes plus alignment.
There is no retained index; the old three remapping arrays are also no longer
retained. No allocator output is aliased and no producer stream is duplicated.

An incoming index is not added: this pass has no incoming-edge query. Selector
facts accumulated during production, multi-row reference deinterleaving,
AVX2/AVX-512 classification and stable virtual-operand compaction remain
**untested hypotheses**, not completed optimizations. The existing compact
opcode projection and sparse lane walk must be the comparison baseline. No
extra prepass or SIMD primitive is added to FAST. A producer-facts alternative
still needs a total lowering-plus-allocation experiment before selection.

## Regression and validation record at publication

`machine_test_parameter_edge_split` joins the existing machine test module.
Thirty-two bounded x86-64/AArch64 graph variants compare complete transformed
instruction/block/edge/switch records against a test-only linear target oracle.
They cover shuffled edge order, first-split versus first-raw duplicates, mixed
split/non-split sources, missing pairs, conditional duplicate targets, switches,
computed labels, cyclic copy-source order, point phases, end/duplicate line
marks, scratch poisoning and idempotence. Empty/no-split paths must allocate
nothing. Direct-formula chain/fanout controls cover 2, 257 and 4097 blocks per
architecture without a quadratic expected-result generator. Endpoint rejection
is tested before malformed rows can enter an index. These are structural API
fixtures; executable semantics are covered by the existing registered C mode
fixtures and independent native differential runner, not by executing synthetic
MIR.

## Performance acceptance still required

Use the existing `bench_throughput_ci`/`bench_throughput` system on frozen
identical inputs and trusted Clang-built compilers. Its normal two-round,
20-pair, all-mode guard remains unchanged. The separate self-built stages are
correctness/fixed-point subjects, not interchangeable timing baselines.

Acceptance additionally requires representative end-to-end improvement on a
verified physical Zen 5, separate Zen 4 nonregression within the predeclared 1%
budget, exact same-input output, reclaimed O(B+E+I) scratch, and at most 4 KiB
production text growth. Record tiny/empty inputs, short and high-fanout graphs,
full compiler input, raw paired uncertainty, phase and whole-compiler costs,
RSS/allocation evidence, disassembly and instruction-specific PMU provenance.
Packing/index construction/reset/teardown costs are included, not just lookups.

No verified physical Zen 5/Zen 4 measurement, PMU counter, emitted-ISA audit,
code-size result, producer-versus-prepass comparison or end-to-end speedup is
claimed here. Unavailable evidence is unavailable, not zero. Hosted CI results
can establish correctness or detect regressions but do not by themselves
satisfy the processor-specific acceptance gate.
