## Proven scope

This follow-up completes the frame-range proof behind the earlier
[range audit](2026-09-11T191710Z.md). Baseline is
`44a90fcbff44988624878aff9db3346a8bc6550b`; candidate production/tests are
`f87ad01bd298ee1374c0b770dfc38b131b251674`. PR #443 publishes the same tree as
`05b247322fc2182ba69a09efff3c01e02f411777`. This audit adds evidence only.
Merged #278's whole-object certificate and #417's incoming-read classification
are retained.

Ordinary selected C uses immutable `LEA_FRAME` pointers for struct fields.
Proving only explicit frame operands therefore improved a synthetic schedule,
but did not improve the first real-source fixture. The final classifier also
accepts a pointer memory row when its immutable virtual register's checked
single definition is a direct `LEA_FRAME` whose destination matches that
register. These scalar pointer encoders have zero displacement; the LEA carries
the offset. Full in-slot byte bounds remain mandatory. Mutable, phi, incoming,
arithmetic and external-symbol pointers remain UNKNOWN.

Mixed volatile functions now receive an optional per-slot certificate before
selection source spans are discarded. A validated volatile span taints every
frame operand and every directly proved frame pointer in all its helper rows.
The AArch64 producer runs after vreg definition points are patched. The table
is immutable through later CFG/SSA edits; replay deliberately loses both
certificate forms. No canonical IR pointers are published in MIR. Unknown
memory still joins all range chains, including unknown volatile pointers.

The range scheduler retains at most eight folded eight-byte dependency keys
per frame object and 23N+8 graph edges. Every covered cell participates, so
unaligned overlaps and modulo collisions remain conservative. Calls, asm,
atomics, fences and physical-register barriers retain existing ordering.
Classification and range scratch run only inside the QUALITY pressure gate.
The optional mixed-volatile selector certificate is producer work and can run
for FAST as well; its cost must be included in compiler-throughput evidence.

One mutable compatibility correction is necessary independently of aliasing:
a mutable block parameter with one textual update still has old-value reads.
Those reads must precede the update. Multiple-definition registers retain touch
ordering; reads after a sole update remain mutually independent. An initial
attempt to chain all reads regressed the existing QUALITY tree test and was
rejected. The final test proves old-value store, update, then new-value store.
Target-promotion still emits mutable vregs, so removing this exception would
be unsound and is not claimed by this PR.
