## Result and scope

The candidate checks `-fsyntax-only` without constructing canonical IR. On the
same frozen compiler unity source, direct-SSA syntax checking reduced median
wall time by **27.1%** and peak RSS by **49.8%**. The generated 1.15 MB translation
unit reduced syntax-check time by **49.8%** and peak RSS by **71.9%**. These are
local descriptive measurements, not dedicated Zen 5 acceptance claims.

Ordinary object generation remains byte-identical for all measured cells and
repetitions. Its full compiler-source median is **22.0% slower** with direct SSA
and **18.8% slower** with memory-form lowering; peak RSS increases about 6.5% and
6.7%. The additional semantic checking therefore has a material cost on that
input. Passing the smaller throughput corpus must not conceal this tradeoff.

The source-constraint inventory and entry-point/counter contracts are in
[semantic-validation.md](../agents/frontend/semantic-validation.md). The new
endpoint is additive: direct lowering clients retain the existing model-only
API. The shared ordinary/syntax-only path checks constraints before lowering;
there is no second frontend IR. Type queries reuse immutable scalar types and
successful function-local facts, with range, scope, token identity and checking
mode guards. Checked facts can answer unchecked queries, not conversely.
