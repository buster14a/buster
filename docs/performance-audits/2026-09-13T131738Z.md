## 1. Actual pipeline and mode census

Canonical preparation is not synonymous with allocator FAST. `ir_prepare_canonical_module` has no allocator-specific scheduling argument: it operates on lowered functions, preparation markers, trust, promotion controls and `program->fast_passes`. The driver/contract exposes the same canonical pass selection across NONE, MIR_STACK, FAST and QUALITY. Do not carry forward a historical claim that NONE/MIR_STACK automatically bypass this canonical pipeline.

| Work | NONE | MIR_STACK | FAST | QUALITY | Conditions / owner |
|---|---|---|---|---|---|
| C preprocessing, parsing, semantics and canonical lowering | Yes | Yes | Yes | Yes | Frontend SSA and memory-form reference are separate configurations. |
| Input certification/validation | Shared | Shared | Shared | Shared | Untrusted input validates; tracing/verification and transform-check policy matter. |
| Shared local promotion | Conditional | Conditional | Conditional | Conditional | Lowered functions, promotion enabled, module not already complete; frontend SSA can leave very little work. |
| Fold, address, DCE, parameters | Selected bits | Selected bits | Selected bits | Selected bits | Same ordered canonical pass family; all enabled by default per current contract, all 16 subsets selectable. Admission, provenance and validation skips remain meaningful. |
| Shared compaction | On changes | On changes | On changes | On changes | One `ir_rewrite_compact` after selected FAST passes; promotion has its own ownership boundary. |
| Final canonical CFG publication | Shared | Shared | Shared | Shared | `ir_function_publish_cfg` after preparation; failure propagation unchanged. |
| Native placement / machine work | NONE policy | Stack policy | FAST policy | QUALITY policy | Different consumers, not four new canonical schedules. QUALITY can pay scheduling and a second placement under its existing policy. |

Wasm64, eBPF and LLVM-bitcode consumers use the prepared canonical module without inheriting native register-allocation semantics. The current contract includes their pass-subset checks. Artifact magic is not independent runtime execution.

This is a census of the shared preparation path plus documented consumer differences, not a claim to have reconstructed every internal allocator analysis from current source. A future implementation must read affected caller/machine bodies before modifying any consumer boundary.

### Work already eliminated: do not reinvent it

Direct frontend SSA, entry-definition forwarding, the conservative LOCAL opcode-summary no-work guard, per-local event lists, lazy shared CFG construction, reusable per-local promotion scratch and final batched remapping already exist according to the checked-in pass map. DCE already counts uses and drains a deletion queue; a new reverse-use CSR does not turn a quadratic DCE into a linear one. It is already linear in visited rows/occurrences, apart from alias-root traversal cost.

Three parameter cleanups must stay distinct: frontend SSA's own cleanup, `ir_promote_compact` after successful local promotion, and the bounded optional `ir_fast_parameters`. The shared-promotion census on #40 reports several zero direct-SSA populations. Allocating an index for that population by default is not justified, and its census cannot be relabeled FAST work.

### Concrete remaining scans and accounting gaps

`ir_fast_function` scans instruction rows for operand/work/provenance admission, initializes the replacement map and removal bytes, then runs selected passes. `ir_fast_fold` scans once for folding and once for address normalization when both are selected. Its early opcode filter already avoids irrelevant width/constant queries. DCE counts surviving operands and all parameter incoming occurrences, scans instructions again to seed the queue, and drains deleted operands. Parameter cleanup revisits blocks/lists for at most four sweeps. Compaction and final CFG publication have separate obligations.

The current `IR_FAST_DCE.visits` counter includes the first instruction loop, counted operands/incomings and deletion work, **but not the instruction seed loop or the use-array zeroing**. Parameter visits count parameter/incoming nodes, **not empty-block visits or `last_parameter` maintenance**. Therefore visits/changes is not a complete cost metric. Per-pass clocks also exclude admission, common replacement/removal initialization, invalidation/reopening, and final publication; DCE-specific allocation/clear occurs inside its timer, compaction has a separate timer. No validation scan is removed by this observation.

## 2. Proposal A: order-preserving sparse bounded parameter cleanup

### Existing contract and opportunity

Exact entry: `ir_fast_parameters(IrFunction*, u32* replacements, IrFastStatistics*)`. It visits blocks in increasing index and each block's linked parameters in list order. For each parameter it resolves incoming roots through `ir_promote_root`, ignores an incoming equal to that parameter's own value ID, and removes the parameter only if at least one non-self root exists and all such roots agree. It immediately writes the replacement and unlinks the node. Later checks in the same sweep observe that update. The cap is `IR_FAST_PARAMETER_SWEEPS`, currently four. All-self/empty and conflicting parameters stay. The existing root and qualifier semantics are not widened.

The simplest scalar challenger stores the nonempty block IDs once and skips empty blocks on subsequent sweeps. It must charge discovery, list maintenance and scratch. It is preferable to a reverse index when blocks greatly outnumber parameters and very few aliases change. For tiny populations the current lists remain the reference and likely winner.

### Temporary layout

No permanent IR change. Assign each original parameter a stable ordinal in the exact baseline block/list order. Candidate scratch contains:

```
parameter[P]             original parameter pointers
block_id[P]              owning block indices
prev[P], next[P]         live ordinal links within each block
value_to_parameter[V]    optional bounded map, with explicit invalid state
watch_head[V], tail[V]   occurrence lists by current root class
watch_parameter[J]      parameter ordinal for each incoming occurrence
watch_next[J]           next occurrence in that root class
pending_now, pending_next, live   bitsets over P
```

P is the initial parameter count, J incoming occurrences, V values. Pointers cost the actual host pointer size, not an assumed four bytes. Use existing arena/index conventions, checked sizes and optional arrays only when needed. An implementation may replace dense V maps with sorted compact roots, but must compare map build/lookup cost. The proposal's extra scratch must fit a separate experimental allowance; if it does not, **run the existing implementation**, rather than making a previously admitted function skip all FAST transforms.

Incoming payload/order remains canonical and unchanged. No dense blocks-by-values or blocks-by-locals matrix is introduced. Watch occurrences are never silently deduplicated into one semantic incoming: duplicate edges still contribute according to the original parameter check.

### State, schedule and pseudocode

The semantic state is the existing alias relation plus live parameter lists. Each valid replacement coarsens the alias partition; removal decreases the live count. This establishes termination for unrestricted cleanup, but does **not** justify changing the current bounded schedule. Four snapshot rounds can produce different retained parameters from four ordered sweeps.

```
number original parameters in baseline order
build root-class subscriptions from every incoming occurrence
pending_now = all original parameters; pending_next = empty
for sweep = 1 .. IR_FAST_PARAMETER_SWEEPS:
    changed = false
    visit pending_now in increasing original ordinal:
        ignore already removed parameters
        perform the exact current triviality check using current roots
        if removable:
            commit the exact baseline replacement immediately
            unlink while preserving block first/last/count
            changed = true
            notify every subscriber of the old root class
            subscriber ordinal > current ordinal -> pending_now
            subscriber ordinal <= current ordinal -> pending_next
            splice old-root subscribers into the replacement root's list
    if not changed: finish
    pending_now = pending_next; pending_next = empty
preserve parameter_budget_hits from whether the last allowed sweep changed
```

An implementation needs an ordered mutable agenda: a plain append-only FIFO does not satisfy the pseudocode. A hierarchical bitset with ascending `ctz` extraction, or a sorted compact agenda plus measured merge cost, does. Set each pending bit at most once per sweep. A newly notified already-passed parameter belongs to the next sweep, exactly as in the full scan. The last no-change conceptual sweep need not reread unaffected parameters, but its budget-hit behavior must match the baseline.

**Subscription invariant:** every live incoming occurrence is subscribed to the root class its original value currently resolves to. When p aliases r, walk p's subscriber list, mark affected parameters, then splice that list into r's list. Future changes to r must notify these subscribers too. A reverse index only over original operand IDs, without class-subscription transfer, is incorrect for alias chains. Deleted-parameter subscriptions may remain as stale entries if they are filtered by `live`; their memory and scans are charged.

**Equivalence argument:** first-sweep checks start from identical state and ordinal order. A retained parameter skipped later has had no incoming root change since its last baseline-equivalent check, so its answer cannot change. Every root-changing replacement notifies all affected retained parameters for exactly their next baseline observation point. Induct on baseline ordinal within sweep, then on sweep. The same replacements and retained lists follow, including cap-limited chains. Root choice is the existing selected incoming root, not a new minimum-ID union rule. This is a proof sketch requiring differential tests, not a completed verification.

### SIMD and bitset alternatives

Bit-parallelism within the fact set handles pending/live masks and changed-set union. Sparse `ctz` extraction is the baseline; dense 64-bit scans are the first alternative. AVX2/AVX-512 can OR/test several contiguous agenda words, but the test must include hierarchical-summary maintenance and compaction. A million-bit bitmap with two active parameters should not be scanned simply to fill vectors.

Across parameters, bucket only sufficiently large, already-admitted populations by incoming count; project current root IDs into temporary tiles. Compare scalar-batched tiles first, then 8x32-bit AVX2 and 16x32-bit AVX-512 equality/mask kernels where existing interfaces support them. Arbitrary linked-list gathers are not assumed cheap or available. Invariant opcode/type screening may be batched independently; commits remain ordered.

A tile computed from a snapshot can become stale after an earlier ordinal is removed. Track invalidations through the same subscriptions and recompute affected proposals before committing. If revalidation visits every incoming again, there is no saved root-walk work; report that negative result. Do not use speculative simultaneous alias unions, silently collapse cycles, or replace the cap with convergence-to-completion. Homogeneous larger-fan-in comparisons are the plausible SIMD region; common two-input early conflicts are the likely losing region.

### Cost and switching model

Let B be blocks, P parameters, J incoming occurrences, S <= 4 sweeps, H actually inspected incoming nodes including early exits, C alias-root traversal steps, and M committed aliases. Baseline work is proportional to `S*B + sum(P_s) + H + C`, not automatically `S*J`: early conflicts can make H small.

For the agenda, charge `setup(B+P+J+V) + H_dirty + C_dirty + W_notify + agenda + unlink + teardown`. W_notify is the total subscription entries traversed, including duplicates/stale entries. A naive merge can revisit a long list through many aliases; **W_notify can be O(J*M)**. No linear or inverse-Ackermann bound is claimed merely because a root helper compresses paths.

Choose agenda only when its complete predicted time plus conversion uncertainty is below the remaining scalar-sweep cost. Estimate activity with incoming/notification volume, not just active-parameter fraction. With four sweeps, setup can be amortized over at most three avoided revisits. Choose dense mask scanning only when `word_scan_cost*ceil(P/64)` is below `active_extraction_cost*A + summary/merge_cost`; add actual switching cost and a hysteresis margin. Coefficients and margin must be learned from authorized paired experiments, not assigned a universal 10%/20% threshold.

A high-notification regime should select dense ordered checks from the start. If a mid-pass fallback is investigated, it must resume the same sweep/ordinal using canonical lists and current aliases; it cannot restart four new sweeps. Building watchers and then abandoning them is a charged loss, not free adaptation.

## 3. Proposal B: compact classification around the existing linear DCE

### Existing semantics and invariant

Exact entry: `ir_fast_dce(IrProgram*, IrFunction*, u32* replacements, u8* removed, u32* uses, u32* queue, IrFastPassStatistics*)`. Keep `ir_instruction_is_pure` as the sole authority. Calls, loads, stores, atomics, fences, traps, exact SIMD operations, floating operations and currently excluded conversions remain conservatively observable. A type's volatile/atomic flags and PLACE-versus-value projection distinction must still be checked. This proposal does not add a removable opcode.

After initial counting, `uses[v]` equals the number of surviving instruction operand occurrences plus all incoming-parameter occurrences that resolve to v. Deleting a queued pure instruction removes exactly its operand occurrences and decrements those counts. A transition to zero exposes its instruction definition, if any, for deletion. Incoming uses are fixed roots for this invocation because parameter cleanup runs **after** DCE.

This is monotone peeling: the set D of newly deleted pure instructions only grows; at most N instructions enter it. It is not a general mark-live rewrite. Unused dependency cycles without an initial zero-use seed remain, and replacing peeling with a mark-and-sweep algorithm could remove more code. That would violate this task's behavioral/optimization boundary.

### Better scalar first; compact seed experiment second

The baseline already has no reverse-use CSR and a single deletion queue. Preserve it for the propagation phase. First compare small scalar loop/locality changes without allocating anything, and measure how much seed scanning actually costs. Do not eagerly evaluate purity for every row: current code only needs it for zero-use candidates, so preclassification can add substantial work.

A candidate compact projection can be produced during DCE's existing counting walk:

```
seed_instruction[K] : u32   stable instruction indices
seed_value[K]       : u32   valid result IDs for unremoved rows
```

K <= N; storage is 8K bytes plus alignment/capacity. The projection records only the cheap existing removed/result-valid predicates. It does not change operand counting or move purity/type classification ahead of zero-use testing. Once instruction operands and all parameter incoming uses have been counted, process those candidate IDs in original instruction order. Materialize a small local tile of use counts, compare them to zero, compact selected IDs stably, then call the existing scalar purity predicate and append eligible IDs to the unchanged queue. The reference path remains available when K is small or projection cannot be amortized.

```
zero uses with the existing bounded method
walk instructions in baseline order:
    count every surviving operand occurrence at its resolved root
    optionally append (instruction index, result ID) to seed projection
walk all parameter incoming occurrences and count them
for candidate tile in original order:
    load/gather counts at exact result IDs
    zero_mask = counts == 0
    for selected lane in increasing lane order:
        test current purity; append qualifying instruction to queue
run the original FIFO deletion loop and ordered scalar decrements
compact once at the existing later boundary
```

### Batch semantics, conflicts and alternative forms

Initial count building completes before seed classification. Thus seed tiles see a stable snapshot of `uses`; no speculative seed based on partial counts is legal. FIFO drain observes sequential decrements exactly as today. Stable tile compaction plus scalar purity calls preserves initial queue order. The deletion phase remains scalar unless a separate proof and cost win exist.

Two operands can resolve to the same value, and many lanes can target one counter. **Vector gather/add/scatter is not a valid count increment or decrement implementation** in the presence of repeated destinations. A conflict-detect/aggregate method must preserve multiplicity and zero-transition enqueue order, and must count grouping/sorting/conflict overhead. It is not required for the proposed seed kernel and is not a new primitive/dependency request.

Compare these forms:

| Form | Mechanism | Main losing region |
|---|---|---|
| Existing scalar | Read canonical rows; seed FIFO directly | Extra row footprint when many rows and counts are already hot |
| Improved scalar | Same algorithm, no resident projection | Limited upside if counters/root walks dominate |
| Scalar-batched | Small candidate/count tiles and stable scalar selection | Packing and extra stores exceed saved row traffic |
| Bitset | Zero-result/eligible masks with ascending bit extraction | Mask construction/maintenance dominates; sparse irregular IDs |
| AVX2 | 8-lane u32 zero comparisons, scalar loads or guarded gathers, ordered mask extraction | Gather latency, mostly full/empty masks, small K |
| AVX-512 | 16-lane u32 zero comparisons and masks using existing SIMD vocabulary | Packing/gather cost, memory bound, unsupported interface/features |

The boolean seed predicate is suitable for a mask; the exact occurrence counts are not reducible to one bit. Do not substitute a boolean 'used' flag for reference counts. A dense-zero bitset is built only after all counts, and deletion-time updates are charged if it is reused. Different functions may batch independently only through the existing lane infrastructure with work-indexed output; this research adds no concurrency.

### Cost model and work elimination

Let N be instructions, V values, E surviving operand occurrences, J incoming occurrences, R deleted rows, E_D their operands, K seed candidates and C root-helper work. Baseline includes `zero(4V) + row_scan(N) + count(E+J) + seed_scan(N) + queue(R+E_D) + C`, plus common preparation/compaction/publication. Existing visit counters omit terms as described above.

Projection cost adds at least 8K bytes written and 8K bytes read, capacity/zeroing effects, packing counts, mask extraction and fallback dispatch. Benefit is fewer canonical-row/metadata loads during seed scanning, not fewer use increments. Compare `T_pack + T_tile + T_selected_purity` against the original complete seed scan. Cold pages, TLB misses and write-allocate traffic can make 8K payload much more expensive than its nominal bytes. Peak scratch and arena capacity must be measured, not inferred from payload alone.

For graph diameter/chain length L, the FIFO drain remains proportional to removed occurrences rather than L full scans. Dense repeated zero-use sweeps would cost up to `L*(N+E)` and are a rejected default. SIMD across a tiny frontier does not justify that algorithmic regression.

Fusion with the admission scan is not equivalent: fold/address replacements and removals happen afterward, so those early counts would require repair or another scan. Fusion into the final selected rewriting pass is only a gated experiment after proving all relevant roots/removals are final, including forward references, incoming uses and disabled-pass combinations. A speculative early seed queue is forbidden. Eliminating optional setup for disabled/no-work populations is more valuable than maintaining a permanent use table across passes.

## 4. Joint constraints and primary research

[Br​​aun et al., CC 2013, author project page](https://cdl.uni-saarland.de/projects/ssaconstr/) motivates demand-driven SSA construction and avoiding preparatory analyses. It does not establish Buster's cap-sensitive schedule equivalence; the ordered-notification proof above is this report's proposal. No replacement SSA framework is suggested.

Ligra's published default threshold is not a Buster threshold. Its duplicate-update requirements reinforce the need for explicit notification/counter-conflict handling. No Ligra dependency, callback framework, GPU offload or shared-state atomic algorithm is introduced.

The finite monotone-set/partition arguments above justify termination, not identical diagnostics or bounded output. Schedule equivalence, no-new-optimization scope, canonical verification and deterministic materialization remain separate obligations. Access to the Kildall publisher page was denied; this report does not pretend to have inspected that paper or rely on an unread theorem for acceptance.

Do not fuse DCE with later parameter removal and then repeat DCE to obtain more dead code: that changes current pass ordering and generated-code behavior. Do not skip final canonical validation/publication because a batch produced a mask. Do not add permanent opcode/type classifications or widen hot rows. Temporary opcode filters must defer to current authority, preserve exact type IDs/qualifiers and include their construction/invalidation cost.

No experiment in this section was run. Use only an explicitly authorized exclusive CI/remote host and the existing throughput/test infrastructure. A connected repository is not permission to occupy an arbitrary server or dispatch an unrequested workflow.

### Frozen inputs and measurement

Freeze compiler source SHA/tree, trusted producer binary/toolchain, complete configure/build argv, target/features, test inclusion, generated/resource headers, workload archive/hash and output paths. Freeze input independently from the compiler changes. Keep source-identical baseline/candidate inputs even for self-hosting. Distinguish PMU retired instructions, Callgrind Ir and source-work counts. Instrumentation/census replay is separate from ordinary timing; measure its overhead and require ordinary/instrumented output parity. Missing counters are unavailable, not zero.

The existing six-workload corpus and its self-host inputs remain the acceptance baseline. Diagnostic commands use documented `-ftime-canonical-fast -v` separately from the timed series. The existing `./build.sh bench_throughput run`/`compare`, `test_self_host`, and `test_mode_matrix` are the integration points, not a new benchmark framework. Resolve their current full argument contract on the authorized runner before execution.

### Controlled distributions

Vary one dimension at a time, then selected interacting corners; do not run an unbounded Cartesian product.

- N and B: empty, tiny (1-32), then logarithmic sizes through 2^16, plus the actual work/scratch boundary. V, P and J vary independently where well-formed IR permits.
- Active fraction: 0, one candidate, 0.001, 0.01, 0.1, 0.5 and 1. Report degree-weighted activity and absolute population, not fraction alone.
- Incoming/use fan-out and fan-in: 0, 1, 2, 4, 16 and 64; duplicate references, self references, early versus late conflicts, hub roots and a heavy-tailed mixture.
- Iteration/dependency depth: 0, 1, 2, 4, 5, 16 and 64. Parameter output must still match exactly after four allowed sweeps; depth five is a critical boundary case, not permission for a fifth sweep. DCE chains test queue depth without introducing repeated sweeps.
- CFG shapes: straight lines, diamonds, nested loops, switches, irreducible/multiple-entry components and unreachable SCCs; both storage orders. Preserve current validation contracts when generating fixtures.
- Locality: contiguous versus scattered incoming nodes, shared operand slices, compact and sparse result IDs, alias-chain lengths, repeated preparations and provenance/budget skips.

For every applicable distribution compare current scalar, better scalar, scalar-batched, u64 bitset, AVX2 and AVX-512 forms with complete setup/maintenance/teardown. Unsupported ISA/interface forms remain explicitly unrun; adding compiler intrinsics is not part of this research. Use existing `<buster/lib/simd.h>` operations and compiler/feature guards. MSVC, AArch64 and self-host fallbacks are mandatory correctness paths. Inspect emitted host instructions on the authorized machine for loads, shuffles, useful lanes, spills and frequency effects; width is not a performance result.

## 6. Equivalence and adoption gates

**G0 — relevance:** obtain current native per-pass cost including uncounted seed/block/setup work. Reject a target whose real cost cannot repay setup. Historical shared-promotion zero populations are a warning, not a reason to disable a different pass.

**G1 — exact scalar oracle:** on identical pre-pass IR, compare replacements, live parameter lists/order/counts, instruction deletion set and ordered queue trace where applicable. Include alias chains, all-self/empty parameters, cycles without zero-use DCE seeds, duplicate operands, forward references and cap boundaries. Preserve existing `parameter_budget_hits`, changes and skip meaning; work-count differences should reflect the new actual work and must not be disguised as identical counters.

**G2 — canonical and diagnostic equivalence:** run existing structural tests, canonical ownership/semantic verification before and after transformations at their required boundaries, repeated-preparation checks and shared-slice/source/extra metadata remapping checks. Preserve accepted legacy shapes and diagnostics/refusal on unsupported pure-looking operations. Baseline and candidate outputs must be byte-identical for the same configuration; runtime agreement alone is insufficient for this implementation-only task.

**G3 — coverage:** all 16 canonical pass subsets x NONE/MIR_STACK/FAST/QUALITY; frontend SSA on/off; promotion controls; Debug/Release, unity/non-unity, sanitizer, explicit transform checking, one-lane and supported parallel settings. Exercise desktop native execution, supported mobile object/lifecycle coverage and Wasm64/eBPF/LLVM-bitcode consumers. Existing runtime or external-compiler oracles must be used where available; otherwise record the missing engine gate.

**G4 — self-host:** trusted Clang-built compiler performance measured separately; byte-identical self-built stage fixed point and required token/byte metrics checked through the repository's existing self-host workflow. Preserve compiler support for the SIMD fallback implementation itself.
