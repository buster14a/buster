The floor for a code change was 1 M Ir removable. Two items cleared it:
- **The query path paid the settlement's frame.** Only 6,047 of 132,669
  calls settle, but every call saved the registers that only the scan and
  the per-mark checks need.
- **The scan paid per-group bookkeeping.** Each group recomputed its width,
  tested for a tail, reloaded `body->flags` (the `others` stores may alias
  it) and spilled the running state, though about three groups in five carry
  no mark.

The per-mark checks and the table build did not clear the floor on their
own. Taking more would mean recording each region's marks in the eager pass,
which #3500 measured as a layout loss.

## The change

All of it is under `-fc-ast-pilot`, in `c_ast_types.c`:
- `c_ast_types_lookups_settle`, out of line, settles a region and then
  answers the query that needed it. `c_ast_types_lookups_settled` reaches it
  by a tail call, so the query path keeps one saved register.
- `c_ast_types_lookups_hold` is the shared hold check: generation, use count,
  the region's other marks and the rooted scope. It is the old code's
  post-settlement check, unchanged.
- The scan hoists the flags pointer, skips mark-free whole words in a loop of
  its own (`c_ast_types_flag_word`), and assembles the tail word once before
  the scan.

**Why it is exact.** Settlement visits the same groups in the same order and,
within a group, the same marks in the same order. So the region's "other"
marks, its settled state and its stamps are the ones the base records. The
hold check is the base's code. Settlement reads the lookup generation again
inside the out-of-line function. The function runs only when
`c_parse_lookup_generation` has just answered, and nothing between the two
reads changes the cursor.

**Iterations under the same budgets.** The budgets were not changed. The
commits in between were measured and are recorded here:
- `250eb14f` put the per-group mark walk in a helper that Clang did not
  inline. C − B was **+2.12 M**: about 245,000 calls.
- `7c66f281` folded it back into one loop. C − B was −2.11 M, but the
  settlement fell only 8.7%, below its 12% budget. The scan's empty groups
  still cost about 18 Ir each.
- `70e392d2`, measured below, adds the skip loop.

## Reading

- On this host's Callgrind counts, the settlement is 16% cheaper and the
  pilot's compile 0.042% cheaper. No answer, counter, object or default-path
  call count changed.
- The saving came from code shape, not from fewer facts: the query path no
  longer pays the settlement's register saves, and mark-free flag words no
  longer pay per-group reloads and spills.
- The first two attempts show how sensitive this loop is to Clang's
  inlining and register allocation. An un-inlined helper alone turned a
  saving into a +2.12 M loss.
- What remains, about 20.4 M, is mostly the per-mark checks (about 8 M:
  binding loads, the symbol table read, the comparison) and the query-time
  checks themselves (about 4.1 M over 132,669 calls). Neither has a lead
  above the 1 M floor short of recording marks in the eager pass. #3500
  measured that as a layout loss, so the settlement slice is closed here.
- Hosted wall time was not measured. These counts are diagnostic, and no 9700X
  comparison was requested. Performance validation is therefore incomplete
  (#2761), and the hook stays opt-in.
