`2026-09-27T015928Z` (Linux x86_64 container, Intel Xeon (AVX-512), 4 vCPU,
Clang 18.1.3; **lazy source locations in C semantic records**).

## Decision

Keep. C semantic records no longer resolve line, column and physical offset
when they are built; they keep a `CSourceSite` (mapped offset plus one, and
source) and `c_preprocess_site_location` recovers the full location only when
a diagnostic or the declared-before fallback reads it. On the frozen stage-1
self-host input this removes **101,798** eager position recoveries (region
search plus checkpoint search) from every successful compilation, replacing
them with **84,708** region-only lookups, and cuts arena requests by
**81.7 MB** because six record types shrink. With `-g0` the whole
compilation now performs **5,206** position queries instead of **111,095**;
the remaining 5,206 are code generation's per-function declaration rows,
which a separate change gates on the line table. Objects are byte-identical
to `main` under `-g` and `-g0`, and every structured diagnostic of a frozen
failure corpus is unchanged. Under callgrind the `-g0` compile executes
22,460,636 fewer instructions than `main` (supplementary; see below). No
speedup is claimed from timings.

## Why the recovered location is the same location

`c_preprocess_token_location` reads only the token's offset and the
preprocess result's published source map. A site stores that offset (plus one)
and `c_preprocess_site_location` calls the same function on it. The map is
complete when `c_preprocess` returns -- sorting, origin finishing, key and page
publication and the C23 respelling append all happen inside it -- and nothing
after preprocessing writes it; the translation-unit arena that owns it is
retained until every consumer finishes. The site's `file` is the key source of
the containing region, which publication copies from the region, and stamp
regions are built with their stamp's source; Debug builds check
`site.file == c_preprocess_token_location(...).file` for every site, and the
full Debug suite passes. A zero site resolves to the zero location a
zero-initialized record carried before. Changing the field types made every
consumer fail to compile until converted, so none reads a stale field.

## Failure paths and many-error inputs

A failing compilation resolves one site per record-located diagnostic and
nothing else. `tools/diagnostic_equivalence.py` (81 cases x syntax-only,
`-c -g`, `-c -g0`, census compilers on both sides) summed over the 25
successful compilations: position queries 15,473 -> 4,486, eager record
locations 10,981 -> 0, site resolutions 0. Over the 218 failing compilations:
position queries 29,771 -> 3,527, checkpoint searches 13,927 -> 6,822, and
2,372 site resolutions for 3,525 recorded diagnostics. Scaled families at
N = 256 (redefinitions, enumerators, members) resolve exactly N sites for N
diagnostics; 256 duplicated functions go from 1,536 position queries to 256. Resolution is one bounded
region search plus one bounded checkpoint search, so reconstruction is linear
in the diagnostics reported and never exceeds the eager cost per record.

Callgrind on the same `-g0` compile, with x86-64-v3 unity builds of both
compilers (tests off). The object is identical (`b4d37bf805927095...`).

| Compiler | Instructions |
|---|---:|
| `main` | 21,929,830,304 |
| candidate | 21,907,369,668 (-22,460,636, -0.10%) |

Record sites give `ir_source_map_source` and `c_preprocess_token_source` a
second caller. Left to its heuristics, Clang then outlined one of them from
lowering's per-instruction `c_ir_token_source_range` (2.1M calls), and the
candidate executed 18.9M instructions more than `main`. Both are now forced
inline where the unity build makes them static (`BUSTER_SHARED_INLINE`); other
builds keep their external definitions and the compiler's choice. The
per-instruction path then costs what it did on `main` (89.0M instructions).
The largest remaining gains are
`c_parse_validate_lowering_constraints` (-11.2M), `ir_source_region_position`
(-9.4M) and `c_parse_lookup_entity_symbol` (-6.1M); the largest cost is site
creation inlined into `c_parse_ast` (+6.9M).

## Not claimed

No wall-clock speedup: this container's timings vary with concurrent builds.
The counts above are the evidence. The semantic-analysis diagnostic table,
debug-only work under `-g0` and lexer/lowering diagnostic storage are separate
changes with their own measurements.
