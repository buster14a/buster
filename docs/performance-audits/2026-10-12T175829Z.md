## Workload

The arms compile the base revision's unity self-host source from a pristine
checkout of the base:

```sh
ide cc -Isrc -Ibuild/v3/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -fsyntax-only \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

The four arms:
- A: base, default flags;
- B: base with `-fc-ast-pilot`;
- C: candidate with `-fc-ast-pilot`;
- D: candidate, default flags.

`-c` uses the same input with `-c -o`, at `-g0` for instructions, and at
`-g0` and `-g` for object identity. Callgrind ran with `--cache-sim=no
--branch-sim=no`. Call counts are summed from the Callgrind `calls=`
records, and the per-function figures are exclusive (self) Ir.

In both modes, at every site:
- **No call finds work.** The position index lists no identity site
  (`_Generic`, `__builtin_types_compatible_p` or `__builtin_classify_type`)
  anywhere in the self-host input, so every range is empty. No call visits a
  site, records an identity row, appends a type or reports a diagnostic, so
  none can change a memo key or a result.
- **The index is always there.** No call finds it missing. One call per
  mode, the first scalar attempt, comes before the index is built, and its
  lists are still empty then.
- **No call is nested.** The active guard never trips.

The base profile (arm A) charges 53.08 M Ir to the function, inclusive and
exclusive alike: it calls nothing that costs anything. That is about 32 Ir a
call. Its loop never runs. The cost is the guard, the two lower bounds over an
empty list, and the save and restore of the frame of a large function, which
takes a `CPreprocessResult` by value.

## The change

`c_parse_type_identity_prepare` becomes an inline gate. The settling walk is
unchanged and moves out of line as `c_parse_type_identity_settle`. The gate
returns when the position index lists no site in `[start, end)`: an empty
list, a last site before `start`, or a first site at or after `end`. In each
of those cases the walk's lower bound for `start` is at least its lower
bound for `end`, so its loop runs no iteration and the skipped call is
exactly a no-op. A missing index, where the walk scans tokens instead, still
calls the walk. Reference-check builds (`BUSTER_REFERENCE_CHECKS`) compute
both lower bounds for every skipped range and check that.

## Reading

- **#3570's lead.** #3570 noted that the identity prepare never changed a
  result on any input it tried. On the self-host that is because the input
  holds no identity site at all. The call is needed wherever a range holds
  one: forcing the gate to always skip fails 45 fixtures in
  `c_frontend_tests`, including the extended
  `c_test_type_identity_authority`. So the walk stays, and only the ranges
  the index proves empty skip it.
- **The figure.** The 53 M quoted in the handoff was exclusive Ir alone. The
  callers' argument copy and call setup add about 10 M on the default path
  and 17 M under the pilot.
- **Not measured.** Inputs that use identity sites heavily, such as
  generic-selection-heavy code, still pay the two lower bounds per query
  whenever a site falls within the index's span. No hosted workload here
  exercises that.
