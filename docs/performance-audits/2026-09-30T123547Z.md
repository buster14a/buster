## Answer and disposition

A coherent useful subset needs structural allocation identity, exact byte intervals and interpretation, definite live/accessible/determinate storage, and explicit observation/effect boundaries. It does not need MemorySSA, type-based aliasing, or adoption of another compiler's provenance/poison system. The interval distinction is real and independently testable. Current evidence does **not** justify an eager whole-function production memory pass: default compiler unity has only 75 conditional redundant-load candidates, 24 conditional forwarding candidates, and zero overwritten-store candidates after existing preparation. Go for this semantic foundation and a narrowly selected follow-up; no-go for production adoption or end-to-end benefit claims. #49 remains the implementation owner and retains `status/needs-census`.

## Minimal proposed foundation

An admitted access has a semantic descriptor `(allocation-instance, lifetime-epoch, offset, byte-count, interpretation)`, plus initialized/determinate, read/write-valid, ordinary/nonvolatile/nonatomic and observation/escape facts. These are proof obligations, not a proposal to enlarge every IR row. For fixed LOCAL inside one execution of one block, the defining canonical value identifies the allocation; no cached facts cross a block edge/backedge, so no general epoch machinery is needed. Different FIELD IDs can identify the same bytes; different union fields can overlap. Compare overflow-checked half-open byte intervals, including every byte. Different fixed LOCAL instances are disjoint only under the explicit allocation contract. Preserve all address computations and allocation rows.

Start with exact-type unqualified integer32/64 accesses to aligned bounded fixed-LOCAL subobjects. Resolve only approved structural FIELD and nonnegative constant INDEX paths, plus exact address/dereference chains. No type-based no-alias assumption is used. A local is private only with a producer/analysis proof that its address is not exposed outside approved paths and that no external observer/modifier can access the candidate bytes during the region; syntactic nonescape alone must not silently establish an unrestricted pointer-provenance rule. No implicit zero initialization is introduced.

| Transformation | Exact semantic obligation | Sufficient initial route |
|---|---|---|
| Redundant-load elimination | Earlier executed load reaches the later load, identifies the same live initialized bytes with the same decoding, and no overlapping write changes them. Removing the later load loses neither a required access event nor an observable fault. | Same block, exact interval/type, private valid ordinary LOCAL; retain first load and all other instructions. |
| Store-to-load forwarding | The retained store encodes every loaded byte, and decoding them equals the replacement value. No overlapping write or lifetime change intervenes. Deleted load has no required event/fault. | Exact equal interval/type and normalized full-width integer value; prove read validity separately from write validity. |
| Overwritten-store removal | Removed store has no required event/fault; every byte it wrote is overwritten before any relevant observation. | Exact equal intervals, private valid ordinary storage, no intervening potentially aliasing reader/observer; no partial-store composition. |

A retained store can fault and preserve that fault, so proving its nonfaulting behavior is stronger than logically necessary for forwarding. Likewise an unrelated potentially faulting pure operation does not automatically invalidate RLE/forwarding if nothing moves. Our bounded algorithm nevertheless ends regions at potentially faulting/nonreturning operations; this is a deliberately stronger sufficient rule. DSE must separately justify the removed store's own fault and any observation before overwrite.

## Effects and invalidation

Classify rows explicitly as checked read/write intervals, harmless value/address construction, or a barrier. Unknown calls clear both value availability and lifetime/access-validity assumptions: no byte write does not mean no free/unmap/protection change, observation, escape, nonlocal control or fault. Do not whitelist by callee spelling. Every inline asm, including empty asm and forms without a memory clobber, is initially a barrier until its complete effects are established. Volatile access, every atomic/fence, dynamic stack allocation/restoration, varargs, hidden value projections, aggregate/unknown memory operations and exact SIMD memory are barriers. Unsupported opcodes default to unknown. Known overlapping reads clear pending DSE; overlapping writes clear reaching-load/store values; proven disjoint accesses may retain facts. Broader call summaries would need distinct read/write, capture/escape, lifetime/permissions, return/nonlocal-control and fault facts; they are excluded here.

Explicit unsupported cases: heap/malloc/free/realloc, globals/TLS/weak/aliased symbols, arbitrary incoming/loaded/merged pointers, pointer-integer conversions, variable indexing, bit-fields, insufficiently aligned packed fields, partial/masked/compressed SIMD memory, FP/pointer/aggregate forwarding, volatile/atomic memory, calls/asm, cross-block/loop transformations, UNDEFINED and uninitialized/indeterminate loads. Unknown reads do not merely preserve pending stores; they conservatively block their deletion.

## Executed experiment versus hypothesis

Hypothesis A: post-SSA exact-place work already covers useful cases. Hypothesis B: retained aggregate subobjects need root+byte identity. The cheapest discriminating test counted canonical rows **after** default frontend SSA/shared promotion/FAST, without rewriting any row.

Model A uses exact typed PLACE identity and flushes on every store; a potentially aliasing read ends pending DSE. Model B uses LOCAL+constant interval, retains disjoint facts, and matches distinct places reaching identical bytes. Both use the same eligible-access proof prepass and 16-entry FIFO table, same block/effect boundaries. This matched diagnostic isolates matching/invalidation precision; it does not establish the cheapest possible implementation of A. ## Independent semantic tests actually run

A separate C interpreter operates on bytes, two 16-byte allocations, lifetime generations, permissions, explicit observers, abstract special-access events and terminating faults; it does not call the census/matcher or Buster. GCC15.2 ordinary and Clang21.1 ASan/UBSan runs each pass **66,394 equivalence comparisons + 71 contract checks + 14 counterexamples, zero failures**. 65,536 comparisons enumerate two disjoint 32-bit field values in [0,255]; remaining cases include 11 boundary bit patterns and aligned32/64 offsets. This is finite falsification support, not proof of every program or C11 concurrent executions. Concrete zero-filled test memory is a witness, not proposed source/IR initialization. No LLVM poison/provenance is used.

Counterexamples invalidate weaker rules: (1) store one overlapping byte between repeated loads; (2) differently named union fields sharing bytes; (3) unknown call observing/changing bytes; (4) same numeric storage after lifetime replacement; (5) permissions changed after an earlier successful load; (6) STORE succeeds in write-only storage but LOAD faults; (7) store256 through a byte then load returns0, not256; (8–9) overwritten special store or repeated special load loses its required event; (10–11) intervening reader or escaped observer sees the removed first store; (12) partial overwrite leaves live bytes; (13) first store faults even though a later store covers it; (14) unused load still faults. The captured traces distinguish equal-return counterexamples too. Global `store(g,1); may_trap; store(g,2)` is an additional observation/fault warning, outside the admitted private-local subset.

## Strongest counterargument, uncertainty and smallest useful packet

Low static incidence does not prove low dynamic value: repeated fields occur in potentially hot compiler helpers, and reusing/fusing existing preparation work could reduce proof cost substantially. Conversely, candidate IR removal does not prove machine-instruction/runtime benefit; some target work may already simplify. Nothing here establishes a throughput regression or a speedup.

The next useful packet is limited to source-supported by-value aggregate parameter captures (begin with the seven wide-integer helper field candidates): state and independently test the fixed-LOCAL lifetime/read/write/initialized-field and normalized32/64 contracts; add a budgeted opt-in diagnostic of that restricted eligibility and actual selected machine rows; profile occurrence on current representative source. Keep DSE, arbitrary pointers/globals, call summaries and cross-block work excluded. Only if that packet shows material remaining work should #49 implement one deterministic block-local root/interval rewrite through the existing FAST preparation/compaction path. Preserve source/debug/value remaps and invalidate published CFG/derived facts **before** mutation. Use lane-private scratch under existing16MiB scratch/8MiB retained/4Mi work budgets, decline on exhaustion, no new callbacks/threads/dependencies or row growth. Independent byte oracle, raw canonical positive/negative tests, both frontend forms, ordinary/unsupported effect tests, affected backend execution and baseline/candidate self-host are mandatory before a later controlled standard-runner/9700X performance decision. Stop if valid residual population or measured gain cannot repay the total proof/rewrite/compaction cost.
