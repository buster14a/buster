`2026-10-15T150823Z` (Linux x86_64, Ryzen 9 7940HS, Clang 23.1.1; **Reuse
opcode role membership during machine selection**).

[#4310](https://github.com/buster14a/buster/issues/4310) follows the owner's
stage-1 self-host profile. Reusing existing opcode-role membership removes
3.285% of retired user instructions from frozen-unity selector replay.
Unprofiled warm selection is 6.505% faster on this host. Ordinary stage-1
QUALITY compile/link improves 1.143%; FAST elapsed time is inconclusive.
This is an incremental improvement, not a breakthrough or a Zen 5 claim.

## Why the function is hot

The owner's `2026-10-15_16-23-57_ide` Superluminal capture attributes
212.420 ms inclusive and 64.375 ms exclusive to
`machine_select_canonical_function_x86_64`. Direct children include debug-value
construction (37.654 ms), value classification (13.568 ms), call selection
(11.241 ms), virtual-register compaction (10.339 ms), and canonical layout
(10.192 ms). The complete function list attributes 14.085 ms to
`machine_x64_select_row`; this includes calls beneath several selection helpers
and is not an additional disjoint top-level slice. The capture's exact source
revision is unverified; it is diagnostic evidence, not the comparison baseline.

A fresh baseline profile confirms 7.62% inclusive / 2.28% exclusive CPU samples
in the selector during ordinary stage-1 compilation. Warm replay attributes
24.61% exclusive samples to the selector and 5.51% to `machine_x64_select_row`.
The replay selects 1,705,147 canonical instructions into 2,233,257 machine rows
across 6,609 functions. Ordinary compilation first performs canonical cleanup
and has a different population. The function aggregates multiple linear walks
and lowering helpers; its inclusive time is not all switch dispatch.

Every emitted machine row previously decoded operand roles from the full
opcode descriptor, walked every destination position, and searched source roles
for a matching register. `MachineOpcodeRow.role_lanes` already contains exact,
immutable use/define/use-define membership. Both target selectors now retain
that prewarmed table and visit only definition slots and their actual readers.
The generic builder's initialization contract and existing serial prewarm are
unchanged. No new table, allocation, pass, SIMD kernel or dependency is added.

## Identities and method

Baseline: `1210144d10b86a8f5a633d6a2fef020d04cc39bb`.
Qualified source commit: `138a1ff1c81e79e621a54bcb358cb7ec3361f6a6`;
its complete `src` tree is `38856ba10c0fe3ad5b42158483f74e4a810cc0eb`.
Following evidence-only commits must preserve this tree.

Both trusted compilers were built sequentially in the same `build/profile`
directory with Clang 23.1.1, tests disabled, Release `-O3 -g`,
`-fno-omit-frame-pointer`, and `-march=native`, without LTO/PGO. Subjects were
copied to immutable paths before measurement. The input was preprocessed and
frozen at baseline. Binary/input hashes and the full build command are in the
evidence. The host was Linux 7.2.9-2-cachyos, Ryzen 9 7940HS (Zen 4), with
logical CPU 2 affinity and one compiler worker. Builds and tests did not run
alongside the timed comparisons.

`performance-evidence compare` alternated A/B ordering, with one warmup per arm,
six pairs for `perf-stat instructions:u` and ten unprofiled pairs for runtime.
The practical floor was declared as 0.5% before measurement. Native comparisons
use the exact two-sided paired sign test, requiring p <= 0.05. Immutable A/A
controls used six pairs: replay process wall +0.478% (p=1), selection interval
-0.861% (p=0.688), ordinary FAST compile/link -0.093% (p=1), all inconclusive.
The selection interval comes from the existing 30-iteration `bench-select`
timer; it excludes frontend construction and module preparation.

workload/allocator combinations, below the floor. No measured work regression
appears. All control objects match byte-for-byte, and generated programs run
successfully with both allocators. These small compile timings are retained,
not silently presented as improvements or rerun to obtain a favorable result.

## Rejected experiment

Hoisting the direct-callee decision and selecting a count-only operand loop
when the initial promotable-local table is empty reduces combined replay
instructions by 3.626%, versus 3.285% with role reuse alone. Its marginal
reduction is only 0.353%, below the declared floor, so that additional code was
removed. Its patch, frozen binary hash and complete receipt are retained.
An earlier unmeasured draft stored the role-table pointer on the generic
builder; it was replaced before acceptance measurements to preserve the
builder's initialization contract. Neither discarded draft is shipped.

## Correctness and scope

- Independent descriptor-role oracle: every opcode and all 7^4 four-operand
  combinations, including identical/distinct virtual registers, a chunk
  boundary, nonvirtual references and invalid virtual ids; invalid opcodes,
  null instructions and idempotence are checked too. Pure duplicate definitions
  stay unclassified so the verifier can reject them.
- Full trusted Release `test_all`: 7,194,476 assertions, 61/61 modules pass.
- Before/after self-host fixed points pass: baseline 42,309,648 bytes; candidate
  42,309,832 bytes. Each candidate generation is byte-identical to the next;
  the compiler's own changed source naturally changes its executable.
- Backend mode matrix: 12/12 legs pass, four behavioral (native x86-64 and
  qemu AArch64 Linux) and eight structural (PE/Mach-O), with both corrupted-image
  oracle controls passing. No Windows/macOS runtime claim is made here.
- Non-unity Clang Debug ASan/UBSan: `machine_selection_tests,machine_tests`
  pass 519,400 assertions. The first sandboxed run passed assertions but exited
  1 because LeakSanitizer could not inspect processes; the unchanged binary
  rerun outside that sandbox exits 0 with leak checking enabled.
- Source-size gate passes: production +961 bytes, build code unchanged.
