## Why the original patch cannot simply be replayed

Current FAST contracts carry held and dirty masks, and inactive per-block
owner rows are uninitialized. The earlier unconditional whole-file loads
would read rows the current contract does not make valid. The older census
also found only 0.60 promised owners per contract and 2.75 owners per exit,
so restoring a fixed-maximum scan would discard work already removed from
the real workload.

`machine_fast_owner_match_mask(owner, active, value)` now accepts the active
mask directly. A sixteen-owner tile uses `simd512_load` and
`simd512_equal_word` only if every lane of that tile is active. Other active
lanes use the existing set-bit walk. This preserves sparse uninitialized
rows, partial target files, and bounded loads without adding a sentinel fill
or padded owner storage. The population test and dense-tile classification
are additional overhead that still needs pricing on the target workload.

Membership, pending-blocker, dirty-owner, and split-span duplicate-removal
queries use the helper. Owner-location search order is unchanged, including
the last-match behavior of the fallback source search. The snapshot-based
`machine_fast_conform_edge_parameters` is unchanged: PR #212 replaces that
algorithm to repair parallel edge-copy semantics, and this patch does not
compete with that correctness change.

Clang's Release `machine_fast_conform_edge` contains inlined queries: dense
tiles emit `vpbroadcastd`, a memory-operand `vpcmpeqd`, and `kmovw`. There is
no helper call or vector spill in those query loops. Inlining does not remove
the sparse-path classification and result-mask costs.

## Remaining acceptance gate

There is no Zen 5 host or usable retired-instruction, branch-miss, or cache
counter measurement in this run. PR #135's requested same-source Zen 5
