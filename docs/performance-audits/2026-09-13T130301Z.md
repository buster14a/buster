# Decision and scope

Retain the maintained canonical-IR-to-MIR selectors as the only producers. Separate a bounded set of pure decisions from operand construction and publish in the original order. For scheduling, accelerate the existing pressure heuristic, not a different scheduling policy: preserve operand multiplicities, intermediate demand transitions, duplicate refreshes, versioned bucket insertion order, bounded staleness and both pressure gates.

## 4. Selection design: bounded pure-decision tiles, ordered publication

### 4.1 Separate six kinds of work

**Fact discovery:** reuse validated canonical rows, `MachineTypeClass`, existing value facts, immutable target configuration and completed target-owned fusion/promotion facts. Do not add a second ownership/use scan. Rows not covered by existing compact facts take the original scalar path.

**Legality:** preserve exact type width, signedness, ABI, target-feature and operand-shape checks. A fast signature is not proof that an operation is legal. Invalid input follows the existing validated/unvalidated entry contract; do not remove canonical validation or duplicate it for every tile.

**Classification:** assign a bounded family only after its pure prerequisites are known: ordinary scalar integer arithmetic/bit operations; scalar constants and width conversions; already-discovered address/immediate predicates. Calls, assembly, atomics, volatile memory, dynamic stack, wide ABI transport, complex vectors, predicate residency and fusion-dependent cases initially remain scalar.

**Decision:** compute only the choices currently made by the target helper. No new instruction form, folding opportunity, reassociation, instruction ordering or cost heuristic is selected. A legal ISA immediate form which current lowering does not choose is not authorization to start choosing it.

**Operand construction:** resolving/materializing operand registers, assigning new vregs, defining values, assigning frame slots, recording relocations, expanding CFG blocks and appending immediates are ordered effects. `machine_x64_operand_register`, `machine_a64_operand_register`, the target row appenders and all ABI helpers remain in this phase.

**Publication:** consume decisions in the exact original target walk order. Preserve zero-row lowered instructions, source marks, definition points, CFG/edge copies and first-refusal diagnostics. A tile stores temporary choices, not a second machine IR.

### 4.2 Proposed private layout

The following is a research layout, not an existing public type or a requested permanent schema:

```c
// One worker-owned tile; explicitly align its allocation to 64 bytes.
// Arrays have capacity 16; only [0, count) may be read.
typedef struct SelectionDecisionTile SelectionDecisionTile;
struct SelectionDecisionTile
{
    u64 signature[16];
    u32 canonical_row[16];
    u16 plan[16];
    u8 original_lane[16];
    u8 status[16];
    u32 count;
    u16 active_mask;
    u16 decision_mask;
};
```

The arrays total 256 bytes; the final fields add 8, so the ordinary 8-byte-aligned layout is 264 bytes and a 64-byte-rounded allocation is **320 bytes**. An optional 16-element `u64` immediate stream costs another **128 bytes**. Address projection storage is separate and only allocated for an admitted address family; copying sixteen complete existing address facts would cost **896 bytes**, before alignment. This cost is not hidden in the core tile. Never allocate a full-function decision array by default.

A lossless signature for the admitted subset can encode 16-bit opcode, 16-bit suboperation, and the four existing 8-bit `MachineTypeClass` fields. Add compile-time bounds checks and an explicit scalar escape for any enum/domain that does not fit. Do not silently truncate, hash without equality checking, discard vector lane shape or infer unresolved layout. Wide/aggregate/vector cases needing facts beyond this signature are not admitted by the initial subset.

Target architecture, OS/ABI, PIC policy, predicate-residency policy and the complete effective feature configuration belong to the immutable tile context, not a lossy feature hash in each row. An optional compact feature-policy index must identify that exact context, with its lifetime and equality guaranteed. Host SIMD availability and features of the generated-code target are independent.

`plan` is a small selector-private choice already understood by the owning target helper, not a global matcher ID. Make the helper's existing decision the single authority: extract/reuse the decision expression and feed it to that same producer. Do not retain a second scalar decision tree beside a table that can drift.

### 4.3 Pseudocode and order proof

```text
complete the existing target prepasses and their mutation
for each block in the existing target order:
    preserve block-entry and ABI emission
    while source rows remain and selection remains supported:
        identify a bounded prefix with immutable decision inputs
        stop at every cold/state-dependent boundary
        pack only that prefix; retain original lane numbers
        compute pure choices, scalar or vector, for active lanes
        for lane in original order:
            invoke the original target producer with its choice
            on refusal: preserve original failed opcode/reason and stop
        discard the tile before proceeding
```

Inductive obligation: immediately before committing row `i`, selector state equals the baseline state before row `i`; the supplied choice equals the baseline choice under that state; the same producer performs the same effects. Therefore state and emitted MIR after row `i` are equal. The base case is the unchanged prepasses/block entry. This proof fails if a supposed pure decision reads an operand materialization map which earlier commits can change, a mutable local, an unfinished fusion fact or a lazily published shared object. Such cases stay scalar; type flags alone do not certify them.

Lookahead must not perform observable diagnostics, symbol insertion, MIR creation, dynamic allocation proportional to later rejected input, or unsafe speculative loads. A later invalid row cannot replace the earlier failure. Do not expose an out-of-memory/invalid-access difference merely because a masked-off lane was evaluated eagerly. For an unvalidated entry, existing shape validation precedes any gather.

### 4.4 Immediate and address classification

For a preselected form with already checked integer width, a range predicate can be batched as `lo <= x && x <= hi`; a power-of-two scaled form adds `(x & (scale - 1)) == 0` and a checked quotient range. Equivalent unsigned modular range tests require a proof that the encoded interval does not wrap and that canonical signedness/width normalization is identical. Do not use overflowing signed subtraction, shift by the type width, or negate a minimum signed value to obtain a magnitude.

A signed-immediate test must compare the full normalized value against the sign extension of the candidate field, not just inspect the low bits. Distinguish signed displacement from unsigned object offsets, scaled addressing from byte offsets, and target relocation/addend constraints from ordinary integer range tests. Negative boundaries, just-outside values, zero and maximal shifts belong in the differential corpus. The current metadata-backed encoder remains authoritative; no shortest-encoding search or new form choice is introduced.

`machine_selection_address` deserves a stricter boundary than an ordinary type lookup. Its bounded demand cache can collide and conservatively return an opaque base. **Reordering or adding cache queries can change fact precision and therefore selected bytes.** The initial tile must not prewarm this cache by scanning future addresses. Batch only arithmetic predicates over facts already obtained in the baseline query order, or admit a narrow family only after proving and testing an identical query transcript and copying the returned facts before any later query. Do not re-query during publication and accidentally observe a different collision history.

Preserve `expression_value` separately from `object_value`; keep TLS/GOT/symbol materialization at its original row. Loads, casts, atomics, pointer/integer arithmetic and unknown roots remain opaque according to the existing analysis. Equal address signatures are never a license to reorder loads/stores. Full `MachineSelectionAddress` copies may be more expensive than the scalar checks they save; the 896-byte tile cost and cache transcript verification are explicit reasons to defer this extension.

### 4.5 Predication versus partitioning versus scalar dispatch

For family probabilities `p_f`, measured scalar family costs `c_f`, scalar dispatch cost `d`, tile width `W`, and family kernel cost `v_f`, compare:

```text
scalar        ~= N * (d + sum_f p_f * c_f)
predicated    ~= pack(N) + ceil(N/W) * sum_f v_f + commit(N)
partitioned   ~= classify(N) + stable_indices(N)
                 + sum_f ceil(N*p_f/W)*v_f + restore(N) + commit(N)
```

These are cost-accounting models, not timing estimates. Small Boolean predicates may profitably evaluate multiple alternatives; calls, ABI expansion, address discovery and expensive variable-length lowering may not. Stable indices cost at least their writes and later reads; temporary choices also need storage and ordered consumption. A single predictable scalar family can beat either vector form. Measure actual family and run-length distributions before choosing a strategy or a minimum tile size.

Across functions, immutable classification is mathematically parallel, but current `MachineSelectionModule` comments explicitly rely on module/program lane ownership for lazy x86 signature plans. Do not introduce concurrent selectors sharing that context. Use existing work-indexed lane ownership and deterministic merge. Cross-function SIMD is deferred unless private arenas/plan ownership, startup and restoration costs beat within-function tiling without changing the lane framework.

## 5. Scheduling design: event-stable occurrence scoring

### 5.1 Preserve the actual algorithm

The scheduler is bottom-up: a unit becomes ready when `successor_remaining` reaches zero. It is not a latency-ready frontier. FLAGS-dependent adjacent rows form indivisible units. The source-order graph retains ordinary SSA dependencies, explicit mutable-vreg touch order, physical-register/call barriers, implicit vector-state chains and the existing certified memory-range logic.

For a fixed demand snapshot `D`, current growth is:

```text
g_u(D) = sum over operand occurrences o in unit u:
         is_use(o) * (1 - D[value(o)])
       - is_def(o) * D[value(o)]
```

USE_DEFINE contributes to both predicates. Repeated uses are repeated terms. Clamp the completed signed score to `[-16,16]`, add 16, and prepend an entry to that bucket. Within a bucket, order is LIFO with versioned stale-entry rejection, **not minimum original instruction ID**.

Example, a pseudo-MIR add defining `d` and using `x` twice with no demanded values: the original score is **2**, while a unique-use popcount gives **1**. This is a symbolic counterexample, not an executed regression. Pairing it with another ready unit can change queue priority and emitted order.

After placing a unit, source executes all definition transitions first, then all use transitions, in row/operand order. Each actual demand transition immediately re-pushes its ready touchers. Duplicate touch entries remain. When a value has **more than 16 touch occurrences**, refresh is skipped and old scores deliberately remain stale. The final demand set is indeed `(D \ Def) union Use`; replacing the ordered transitions by that single expression nevertheless changes the queue history. Final-set equivalence is insufficient.

### 5.2 Small scalar candidate: reuse existing role lanes

The proposed replacement expression inside `machine_schedule_queue_growth` is:

```text
static_rows = existing prewarmed machine_opcode_row_table()
growth = 0
for each original row in the unit, in original order:
    facts = static_rows[opcode]
    for slot = 0 .. facts.operand_count-1:
        if original reference is a virtual register:
            demanded = demand_epochs[original vreg] == demand_epoch
            uses    = (facts.role_lanes >> slot) & 1
            defines = (facts.role_lanes >> (4 + slot)) & 1
            growth += uses * !demanded - defines * demanded
return growth
```

Acquire/retain the table pointer at the existing initialized scheduler boundary, not once per operand. The projection's low four role bits include USE_DEFINE as uses; the next four include it as defines. Use the **static opcode projection** because current scoring uses static `MachineOpcodeInfo`, not a newly instruction-refined role model. Do not substitute instruction-sensitive assembly/constraint semantics and call that an equivalent throughput change.

Proof obligation: exhaustively compare projection operand count and each slot's use/define predicates with authoritative metadata for every opcode. Retain original reference-kind filtering, operand multiplicity, score arithmetic, clamping, queue versioning and error/overflow behavior. The existing prepass already rejects absent metadata/unsupported definition shapes; do not broaden its domain or remove checks.

This candidate changes only where scoring obtains immutable roles. It adds at most a retained pointer in scheduler context, no per-unit cache and no new table initialization. It does not claim to load 96 useful bytes today: cache-line traffic, compiler common-subexpression elimination and actual instruction savings must be measured. It is the correct control before paying to build a larger occurrence cache.

### 5.3 Optional occurrence cache and batch representation

A subsequent prototype may build a private occurrence stream during the existing touch-list construction, not through another global-vreg scan:

```text
unit_occurrence_offset[U+1] : u32
global_vreg[E]            : u32
role[E]                   : u8   // use bit, define bit; preserve occurrences
```

Payload cost is **`4*(U+1) + 5*E` bytes**, plus separate alignment/pointer overhead. `E` includes the actual virtual-register occurrences, not distinct values; include zero-role virtual operands where needed to preserve current touch accounting. The original touch lists and their >16 cutoff remain unchanged. Check allocation arithmetic and preserve the current fallback if scratch would exceed a declared bound. Small/no-pressure blocks must not acquire this allocation.

Existing `vreg_slots` can support a later local-ID representation; it is not a new discovery pass. For `L <= 512`, a `u16` local slot stream costs `2E` rather than `4E`, but demand-bit mirroring, conversion and inverse-map costs must be included. Never narrow arbitrary global vreg IDs into that stream. Beyond the admitted bound, use the general scalar representation.

For vector scoring, stage demand bits for valid occurrences into contiguous words, combine them with use/define predicates and reduce **per candidate unit**. AVX2 can process eight dword occurrence lanes; AVX-512 sixteen. Scalar staged loads are a baseline against gathers. A gather is not automatically a win, and an inactive lane is not a valid pointer. Alternatively batch candidates with the same occurrence count, retaining their event positions, and use a segmented reduction or slot-major columns. Charge partitioning, padding and horizontal reduction.

### 5.4 Correct batch boundary and deterministic replay

A batch may contain only score requests between two demand mutations. There are three natural event lists: initial ready insertion, refresh of ready touchers after one individual demand transition, and newly-ready insertion after predecessor counts are updated. Within one list, score reads do not depend on earlier queue pushes; the queue effects do.

```text
for each existing demand transition in exact baseline order:
    update the one demand state exactly as before
    if original occurrence-count cutoff permits refresh:
        collect ready touch occurrences in original list order
        compute scores against this one frozen demand snapshot
        replay every original push, including duplicates, in original order

collect newly-ready events in original predecessor traversal order
compute scores with unchanged demand
replay state changes and pushes in original order
```

Initial readiness can use the same pattern. Do not batch across two different transitions, deduplicate events, refresh values past the existing cutoff, rescore the entire frontier, sort equal-priority candidates or replace buckets with a heap. The active refresh list is already bounded by the 16-occurrence cutoff, which may make scalar scoring optimal.

Capacity checks stay at their original logical point. Do not reserve a larger queue to make vector batches convenient, evaluate unbounded extra candidates after overflow, or change source-order fallback. Preserve sequence counters and stale-entry checks exactly. If a new split `push_with_precomputed_growth` helper is introduced in a future implementation, its equivalence must include the original capacity guard and side-effect count.

**Dependency proof:** by induction on queue events, the same fixed-snapshot arithmetic gives the same score; ordered replay gives the same bucket head, sequence number and stale entries after each event. Consequently the next valid pop is identical. The same emitted unit then causes the same ordered demand transitions and predecessor decrements. Keeping graph construction and both acceptance gates unchanged gives the same final row permutation, definition remapping, source marks and scheduled-copy acceptance.

### 5.5 Bitsets, multiplicity and resource checks

Unweighted unique-use/def masks are legal only for an explicitly certified subset with at most one corresponding occurrence per value. In the general case, preserve multiplicities. One possible representation uses bitplanes of per-value use and def counts:

```text
g_u(D) = sum_b 2^b * (popcount(U_b & ~D) - popcount(F_b & D))
```

For `Q = ceil(L/64)` words and `B` multiplicity bits, this costs **`16*B*Q` bytes per unit** for the two sets of planes, excluding offsets/alignment. At `L=512`, `B=4`, that is **512 bytes/unit**, versus 24 bytes for one machine row. `B` must come from a checked bound on actual unit occurrences; it is not universally four. This footprint can overwhelm any vector-popcount gain. For small units, occurrence lanes are the more plausible representation; for <=64 local values with proven unique occurrences, two scalar `u64` masks are a strong alternative.

AVX-512 vector popcount needs the separate VPOPCNTDQ feature for dword/qword forms, not merely AVX512F. Eight scalar word popcounts or AVX2 Boolean work plus scalar reduction remain controls. A horizontal sum is additional work, not a free part of vector popcount. See [Intel's guide] and [Clang's intrinsic definition].

Resource bitsets in this scope mean existing architectural constraints: physical-register barriers, implicit state and memory-chain membership. Keep `MachineOpcodeRow.schedule_flags` and instruction-sensitive constraints authoritative. Current scheduling has no issue-cycle resource-availability frontier to vectorize. Adding latency, port-pressure scoring or a busy-resource calendar would change policy; that is the separate #123 direction, not this throughput experiment.

Preserve stack-memory certificates, unique-object identities, bounded range cells, volatile tainting, unknown-access flushes and conservative replay behavior. Do not broaden alias proofs or classify all ordinary vector arithmetic as a global vector-state hazard. The existing edge-capacity bound `23*N + 8` and source-order fallback remain unchanged.

## 6. Five-way comparison and complete cost model

| Form | Selection experiment | Scheduling experiment | Principal extra cost / refusal rule |
|---|---|---|---|
| Current | Target-owned scalar producers and existing type/address facts | Existing occurrence scoring and 33 buckets | Frozen binary/source reference, not a historical pre-projection implementation |
| Improved scalar | Hoist/reuse consumed type/feature facts inside existing target helpers; predictable dispatch | Existing role-lane projection in growth | No new full-function buffer; first candidate |
| Scalar-batched | Same pure-choice tile and ordered producer, scalar kernel | Same event lists and optional occurrence cache, scalar scores | Packing, cache construction, event staging and replay must earn back their cost |
| AVX2 | Same admitted tile, eight dword or four qword lanes as appropriate | Occurrence compares/reductions; scalar loads versus gathers; scalar popcount control | Tails, shuffle/compaction and reduction cost; no new framework or dependency |
| AVX-512 | Same admitted tile, sixteen dword or eight qword lanes | Occurrence masks or justified weighted bitsets | Exact feature guards, occupancy, startup, spills, mask extraction and reduction; not an assumed width speedup |

Keep decisions and emitted bytes identical across the five forms. Compile the kernels with the same trusted producer/toolchain and surrounding build flags; isolate the mechanism under test. Inspect generated host instructions because an allegedly scalar or AVX2 variant can otherwise be auto-vectorized differently. ISA-isolation flags and code-size changes are recorded experiment inputs, not free production policy changes.

Let `N` be visited canonical rows, `K` admitted rows, `U` scheduled units, `E` virtual-register occurrences, `P` score requests, `R` occurrence reads across all requests, and `M` demand-transition events. The selector's total delta includes:

```text
Delta_select = Delta_module_prepare + Delta_signature/feature_work
             + classification(N) + packing(K) + partition(K)
             + decision_kernel(K) + ordered_commit(K) + restoration(K)
             + scratch_allocate/clear/rewind - replaced_work(K)
```

For the scheduler:

```text
T_current = gates + graph + touch_lists + score_reads(R)
          + ordered_transitions(M) + queue(P) + remap + placement_acceptance

T_cached  = same_unchanged_terms + cache_build(E)
          + cached_score_reads(R) + event_stage(P) + reductions(P)
          + scratch_cost + any cache-pressure cost
```

A cache breaks even only when saved repeated decode/read cost exceeds construction, extra demand representation, memory and replay costs. For a one-use unit the cache may be strictly extra work. `P`, `R/E`, event-size distributions, tail occupancy and the fraction rejected by pressure gates are necessary denominators. A role-lane microkernel speedup alone cannot establish a backend gain.

Measure complete backend including selection, legalization/refusal, placement, scheduling and any second placement, encoding, relocation handling and final publication. Measure fresh-process whole compilation including source metrics, canonical preparation/validation, startup, tables, object writing/shutdown, plus executable-generation/self-host completeness separately. Do not add nested inclusive profiler costs or sums of medians. Report cold process versus warm retained-IR selector replay separately. Neither includes a claim of cold OS page-cache behavior unless explicitly tested.

## 7. Metadata startup, ownership and footprint

Compare these alternatives without silently retaining all of them:

**Existing serial prewarm:** retain `machine_opcode_rows_prewarm` and its single authority. The smallest candidate reuses it, so there is no new table to initialize. Hoist a table pointer, not repeated once-guards into an operand loop.

**Checked-in/generated constants:** possible only if generated by the existing metadata authority and verified byte-for-byte against runtime projection. Count read-only binary bytes, relocations, loader/page-fault effects, self-host build cost and tiny-compile startup. No handwritten duplicate table or metadata importer is proposed here.

**Cached operation facts:** module type facts are already amortized. Add only facts actually consumed by an admitted kernel. Per-function scratch is not assumed zero; historical fill traffic is a warning against a universal cache. Arena rewind/lifetimes and cache invalidation after canonical mutation must remain explicit.

Shared global tables are initialized serially under `BUSTER_CHECK_SERIAL_INITIALIZATION()` and publish readiness last. No new atomics, locks, per-row memory fences, non-temporal stores or worker-side lazy global writes are necessary. Per-lane scratch is private; existing lane barriers and deterministic work-indexed publication provide ownership transfer. A module's lazy signature plans must not become shared across concurrent function selectors without a separate ownership proof.
