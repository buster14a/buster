## Scope and root cause

Base: `ebfdd11705bc470564e726857e498f1c82aa746c`. The preceding audit
`2026-09-07T132245Z` and machine/build/testing/benchmarking guides were read
before editing. Current PR #256 already removes uninstantiated address and
liveness record declarations and fixes repeated queue-growth scans; none of
that work is duplicated here. Descriptor-layout PR #138 and operand-shape
verifier PR #231 remain independent.

The scheduler maintained three opcode classifiers beside supposedly
sufficient static metadata. Compiling and enumerating the actual baseline
C table and predicates reproduced 7 memory, 5 barrier and 33 implicit vector
memberships that the descriptors did not describe. Simply deleting the
switches would remove ordering obligations from 45 opcodes.

The fix fills those facts in immutable descriptors and publishes one
`schedule_flags` byte in the existing 16-byte `MachineOpcodeRow`. AArch64
implicit V-register loads keep their `LOAD` class; an existing
`VECTOR_STATE` resource bit expresses their independent vector-scratch
ordering. Whole-source consumer searches found no prior readers of those
resource masks. Existing FLAGS/NZCV resource bits remain dormant, while
flag ordering continues to use the established attribute predicates.

Publication runs once at the existing serial prewarm boundary. There are no
new allocations, per-function caches, row fields, instruction IDs or replay
changes. Unit construction reads the published byte and still adds barriers
for explicit physical-register operands. The complete retained-field and
lifetime inventory is in [machine-metadata-ownership.md](../machine-metadata-ownership.md).
It explicitly records remaining dormant fields and keeps issue #45 open.

## Compile-time and memory impact

Host: AMD EPYC 9V74 VM, Zen 4, 8-CPU quota; not Zen 5. Compiler: Clang
21.1.8 using repository local Release settings. Each pair uses the same
frozen `ebfdd117` input tree, arguments, working directory and output path.
Warm both executables, pin the benchmark process tree to CPU 8, then alternate
A/B and B/A order over 12 pairs per workload. Record every wall/CPU/RSS sample
and output hash. The ratio is the median of paired after/before wall times;
its interval is a 10,000-resample paired bootstrap with seed 45. Other team
builds were possible during measurement, so the result supports a neutral
impact statement, not a small claimed speedup.
