## Workload

Every arm compiles the same input, the base revision's unity self-host source,
from the base checkout:

```sh
ide cc -Isrc -Ibuild/v3t/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -fsyntax-only \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

4,105,792 tokens reach the parser, and the tree has 2,721,682 nodes. The
candidate's split publishes 15,440 records and 33 body assertion ranges for the
unit, with no fallback (`C_AST_SPLIT units=1 records=15440 assertions=33
fallbacks=0`). There are four arms:
- A: base, default flags;
- B: base with `-fc-ast-pilot`: the tree, stages 1 and 2 of the typer, and
  `c_parse_ast`'s token walker;
- C: candidate with `-fc-ast-pilot`: the same, with the records read from the
  tree (`c_parse_ast_from_tree`);
- D: candidate, default flags.

C − B is the split's own effect, and D − A is its cost to the default path.
Callgrind ran with `--cache-sim=no --branch-sim=no`.

## Reading

- Reading the split from the tree costs about a third of the token walk it
  replaces, once the number facts that both build are set aside, and less on
  AVX-512 hardware.
- What remains is mostly the diagnostic probe, about 1.9 M identifier lanes
  that each ask the word table and the `return` id. The probe is kept so that
  the walker stays the only diagnostic producer.
- Under the pilot, `c_parse_ast_run`, `c_parser_parse_function_body` and
  `c_parser_parse_declaration_expression` no longer run for this unit. The
  retirement map marks that row retired under the flag.

## Validation and limits

- Callgrind counts instructions, not time, on `-march=x86-64-v3` builds whose
  AVX-512 kernels are compiled out; architecture-neutral deltas transfer. The
  window compares above are priced by census.
- One input, one host, single process, no pinning and no `perf` counters.
- The 9700X pull-request comparison runs default flags only. It can compare
  arm D against A, but it cannot time the hook. Zen 5 validation of the split
  therefore stays **incomplete**.
- Correctness of the measured candidate is in the pull request's validation
  record:
  - `c_ast_tests` and `compiler_driver_tests` in Debug (split TU) and Release
    (unity);
  - `test_self_host --config Release`;
  - the Clang analyzer, with the CI flags, on the touched C files.
