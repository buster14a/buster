Buster -O0 is not literally transformation-free: its default lightweight canonical FAST cleanup remains enabled. The sensitivity control adds -fno-canonical-fast, -fno-frontend-ssa, -fno-canonical-local-promotion and -fno-target-local-promotion. Mandatory lowering and machine instruction selection still exist in both policies. No second IR/backend or production policy is introduced.

All subjects share C17, unsigned-char semantics, baseline Win64 deployment target, sources, input seeds, runner and serial observations. Buster uses -march=baseline; MSVC uses /arch:SSE2. MSVC /GS- and no /RTC keep additional runtime checking outside subjects. The common validation/timing caller is separately MSVC /O2 compiled and opaque to every subject; the same caller, runtime and linker are used in all cells, without LTCG. These are subject-kernel timings rather than whole programs built independently in each toolchain.

## Interpretation and follow-up ownership

**Tier A:** Buster wins measured compile latency by 1.367x–1.545x (26.86%–35.29% less time); MSVC debug wins kernel runtime by 1.825x–2.365x and code bytes by 41.67%–57.01%. This establishes debug baseline selection/home-code opportunities independently of an optimizing compiler comparison.

**Tier B:** the same Buster debug output compiles 1.585x–6.183x faster than MSVC O2-Z7, while MSVC O2-Z7 executes 8.146x–42.195x faster. Code-size winner is mixed: MSVC smaller for tiny/functions256, Buster smaller for kernels. MSVC's own O2 versus Od runtime gains are shown separately, so improvements within MSVC are not conflated with Buster's current baseline gap.

**Sensitivity:** optional-transform-off debug narrows the runtime gap, yet MSVC debug remains 1.186x–1.581x faster. This is a combined mode contrast, not a new default recommendation. Investigate the home-transport chain before assuming more expensive optimization or larger code must help.

Baseline debug-code quality work remains under #1928 (home/coalescing), #1929 (scaled addressing), #49 (bounded local selection) and #2298 (leaf home/frame census), while #47 owns explicit effort-policy semantics. The separate optimized-output gap uses #48 (small inlining), #1943 (constant division), #2299 (counted reductions), #1944 (SLP) and #1949 (LICM). Whole-cell gaps cannot be promised as any individual pass's speedup. Preserve debug-variable, stack/unwind, ABI and canonical validation obligations when removing waste.
