## What was measured

With `-fc-ast-pilot=fused`, `c_ast_build_fused` preprocesses the unit and
builds its tree in one interleaved pass:
- **The preprocessor.** Its main loop became resumable state.
  `c_preprocess_run_begin`, `c_preprocess_run_lines` and
  `c_preprocess_run_finish` share a `CPreprocessRun` record, and a run can stop
  after any text line once its output reaches a target.
- **The builder.** Its cursor borrows the run's output stream in place, since
  the base of that stream never moves. When the cursor needs a row that is not
  committed yet, its refill asks the run for 2,048 tokens past it. The
  builder's dispatch loop is the one driving loop, and no callback is involved.
- **Keywords.** A keyword the run has not interned yet waits on a pending list.
  It gets its table entry after the refill that interns it.
- **The final-stream passes.** C23 and UCN respelling, GNU obsolete
  designators and `__label__` renames can change rows the builder has read.
  When one of them does, the fused tree is discarded and rebuilt from the
  finished array. The self-host input triggers no rebuild.

The tree still refers to the preprocessing result's tokens by index, so the
token array stays. Fusion only changes when the builder reads each row: about
2,048 tokens after the row was written, instead of after the whole unit.

## Workload

Every arm compiles the same input, the base revision's unity self-host source,
from the base checkout:

```sh
ide cc -Isrc -Ibuild/v3/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -fsyntax-only \
  [-fc-ast-pilot | -fc-ast-pilot=fused] src/buster/apps/ide/ide.c
```

4,105,792 tokens reach the parser, and the tree has 2,721,682 nodes. Fused
and array builds report the same node count, the same retained bytes and the
same typer counters (622,846 answers). The arms, as declared in the
[measurement plan](../agents/frontend/ast.md#measurement-plan):
- A: base, default flags;
- B: base with `-fc-ast-pilot`;
- B′: candidate with `-fc-ast-pilot`, the array build;
- C: candidate with fusion;
- D: candidate, default flags.

Arm C could not be counted under Valgrind with the shipped binary. It died with
SIGSEGV after 20.5 M instructions:
- Every phase arena reserves 31 GiB, and fusion keeps the builder's phase arena
  alive beside the preprocessor's.
- Measured natively with `prlimit --as`, the default and array-pilot compiles
  need between 96 and 112 GiB of address space, and the fused compile between
  128 and 160 GiB.
- That exceeds Valgrind's cap on the client address space. The failed
  reservation then reached `c_macro_expansion_storage_ensure`, which states it
  as a `BUSTER_CHECK`, so Release dereferences a null arena. That pre-existing
  defect is filed as [#3305](https://github.com/buster14a/buster/issues/3305).

Fusion's own Callgrind numbers therefore come from a measurement variant of the
candidate: the same commit with `C_PHASE_ARENA_RESERVED_SIZE` at 8 GiB instead
of 31 GiB, which changes only the size of the reservations. B″ and C″ are that
variant's array and fused arms. Two more variants also changed
`C_AST_STREAM_BATCH` to 256 and 16,384 for the sensitivity rows. Hosted timing
used the unmodified candidate binary, which runs natively.

The prediction holds in simulation:
- **The builder's token reads.** `c_ast_run`'s own LL data read misses fall
  from 549,376 to 1,365. That is about 35 MB of token rows, which the builder
  now reads from a cache level instead of from memory.
- **The rest of the reduction** is the token rows the remaining compile reads
  while they are still cached.
- **Instruction-cache cost.** The two stages now evict each other's code:
  - `c_ast_run`'s I1 misses: 52,961 → 337,461;
  - `c_preprocess_run_lines`'s I1 misses: 122,534 → 262,578;
  - at a 256-token batch, 1.14 M and 0.75 M.

Callgrind models no prefetcher and no L2, so these rows say where data comes
from, not how long it takes.

## Reading

- **Instructions.** Fusion is free: hand-off and keyword resolution cost
  nothing measurable.
- **Locality.** The simulated gain is real and as predicted: the builder stops
  reading the token array from memory. It does not become time on this host.
  The builder reads the array strictly front to back, about 35 MB over roughly
  400 ms of building, a stream hardware prefetchers cover without stalls.
  Callgrind models none of them, which is why the budget treated this row as
  diagnostic.
- **What fusion adds.** Interleaving costs instruction-cache misses (+1.7% at a
  2,048-token batch, +6.8% at 256) and holds two phase arenas at once (+11.9 MiB
  RSS, +31 GiB of address space).
- **A Zen 5 run** (32 MB L3, like this VM's 33 MiB) could only resolve whether
  a gain the host cannot see exists. The 9700X route times default flags only,
  so it cannot time the fused mode.

**Decision.** The ship budget fails, so fusion does not ship. The branch keeps
the mechanism for reference in its history: the resumable preprocessor in
`b174b9cd`, the fused builder in `ce31b659` and the differential tests in
`2eeb846e`, all measured above. It then reverts them. The token array, the
array build and the default path are unchanged on `main`.

## Validation and limits

- **Correctness of the measured candidate:**
  - in Debug (split TU), `c_ast_tests`, `compiler_driver_tests`,
    `c_frontend_tests`, `c_once_tests` and `c_macro_conditional_tests`:
    1,765,589 assertions;
  - in Release (unity, tests on), `c_ast_tests`, `compiler_driver_tests` and
    `c_frontend_tests`: 1,652,971 assertions;
  - in the one-off self-host corpus run, the typer's verify mode checked
    622,846 answers with no mismatch.
- **The differential catches what it should.** Two deliberate faults made it
  fail, and both were removed before the measured build:
  - skipping the pending-keyword resolution;
  - ignoring the final-stream rewrite count.
- **Found while splitting the stage driver:** `__STDC_HOSTED__` was defined with
  a replacement list pointing at a token on the setup stack. The split moved
  that token into the phase arena. On `main` the token is still on the stack,
  but setup and the loop share one frame there, so it stays valid.
- **Not run on the candidate:** `test_self_host`, the Clang analyzer and a
  sanitized build. The mechanism does not ship, and the branch's final tree
  changes only documentation.
- **Scope:** one input, one host, single process, no pinning and no `perf`
  counters. Callgrind counts instructions, not time, on `-march=x86-64-v3`
  builds whose AVX-512 kernels are compiled out.
- **Zen 5 validation of fusion:** incomplete (#2761).
