## Change

`c_parse_position_index_build` now consumes the preprocessor's one-byte
`CTokenShape` sidecar in the same 2,048-token tiles used by the token census.
Each 64-byte window uses masked AVX-512 byte compares to classify identifiers,
opening delimiters, and closing delimiters, then visits only the set bits in
ascending order. The existing scalar work remains in that ordered visitor:
symbol-class checks populate the vector-size, `_Alignas`, label, and attribute
position arrays, while the delimiter stack records matching pairs and
mismatches. The scalar/reference path still calls the same visitor through the
sidecar fallback, so no parser behavior or `CToken` ABI changes.

The tile width is one shared private constant (`C_PARSE_TOKEN_TILE_TOKENS`);
the census aliases it rather than maintaining a second whole-stream shape
pass. The visitor is inlined in the optimized build, and the sidecar pointer is
read once for the SIMD path. No #539 work changes sidecar emission or parser
ownership; expanded/synthesized rows continue to use the existing final
sidecar.

## Population and addressable work

Forgejo #539's census is 70.8M total position-index instructions, with 43.6M
addressable by tile classification; the serial delimiter stack and ordered
append work remain. The 9-pair direct unity compile A/B below removed
41,289,656 instructions/run, or **94.70% of the 43.6M addressable proxy**. This
is an instruction-population ratio, not a claim that all remaining serial work
is free: symbol spelling, vector growth, stack mutation, and stable-order
visits still execute for active lanes.

## Generated SIMD

`objdump -d -Mintel --disassemble=c_parse_position_index_build` on the Release
binary shows masked `vmovdqu8` sidecar loads, AVX-512 `vpcmpeqb` compares for
the identifier/open/close populations, mask unions (`korq`), `kortestq`, and
`tzcnt`/`blsr` set-bit iteration. The visitor has no out-of-line symbol in
`nm`; it was inlined into the consumer. Useful work is therefore 64 sidecar
bytes per window, with one scalar visit per active identifier/delimiter event;
the tail uses a mask rather than reading padding.

## A/B measurements

All counters are `perf stat` on CPU 0, with alternating order. The direct
compile uses the same `ide.c` unity command as self-host stage 1; baseline is
the saved `84c5fe2d` binary with this diff removed, and changed is the rebuilt
#539 binary. No DRAM-specific event was available, so `cache-misses` is the
closest available last-level proxy.

- **Direct unity stage, 9 pinned pairs:** baseline **9,786,772,907**
  instructions/run versus changed **9,745,483,251** (**−41,289,656,
  −0.422%**). Branches fell **1,785,971,946 -> 1,770,348,727**
  (−15,623,219, −0.875%). Branch misses were **21,798,895 -> 21,846,629**
  (+47,734, +0.219%); L1 loads **3,462,656,009 -> 3,461,812,875**
  (−843,134, −0.024%), L1 misses **90,833,896 -> 92,247,215**
  (+1,413,319, +1.556%), and cache misses **8,707,641 -> 8,924,240**
  (+216,599, +2.487%).
- **End-to-end `ide bench`, 10 pinned pairs:** baseline **291,639,336**
  instructions/run versus changed **289,752,130** (**−1,887,206,
  −0.647%**). Branches fell **52,211,163 -> 51,504,968** (−706,195,
  −1.353%); branch misses **1,722,368 -> 1,715,124** (−7,244, −0.421%);
  L1 loads **112,828,683 -> 112,998,712** (+170,029, +0.151%); L1 misses
  **2,793,052 -> 2,781,251** (−11,801, −0.423%); cache misses
  **542,208 -> 535,898** (−6,310, −1.164%). The benchmark output stayed
  semantically identical (`BENCH_C_FRONTEND`, 30 iterations, 21,030 bytes);
  wall-time min/median naturally varied with the host.

The direct-stage result is the primary #539 signal: it recovers most of the
addressable classification population while preserving stable-order scalar
work. The small frontend benchmark also moves down, but the L1-load increase
and the nonzero branch-miss change are recorded rather than hidden behind the
instruction win.
