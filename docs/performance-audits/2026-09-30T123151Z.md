## What the counters mean—and do not mean

The Linux Zen-5 `pipeline.json` inspected for this report defines:

```
total_dispatch_slots = 8 * ls_not_halted_cyc
frontend_bound = de_no_dispatch_per_slot.no_ops_from_frontend
                 / total_dispatch_slots
```

Its latency component counts cycles in which all eight slots are unavailable from the frontend (`cmask=0x8`); the bandwidth component is the residual. These are dispatch-slot accounting metrics, not a percentage of elapsed time that can be removed. They do not by themselves separate I-cache, instruction TLB, decode, op-cache, or control-flow-delivery causes.

There is a documentation trap: AMD's generic Zen4/Zen5 uProf table describes six dispatch slots, whereas the inspected Zen-5 Linux formula uses eight. **Do not transplant the generic table's denominator into a Zen-5 calculation.** The target host's installed perf definitions, CPU family/model/stepping and actual event configuration must be retained. The web definition is a reference, not proof of what the unavailable host used.

The Linux `ic_fetch_miss_ratio` description also explicitly excludes I-cache misses that hit the op cache. Thus fewer counted I-cache misses can reflect delivery shifting between structures, not necessarily less exposed stall time. Record op-cache, ITLB and L2 instruction-fill evidence as available. Generic `cache-misses` is not a substitute for a verified L1I event, and a miss count is not a miss-latency cost.

AMD warns that multiplexing can make top-down metrics inconsistent. Preserve unscaled counts, event configuration and running/enabled coverage. Do not aggregate unsupported, unscheduled or rejected counters as zeros. Use small event groups and separate fixed-count captures; keep privilege scope consistent. System-wide, user-only and process-tree counts are not interchangeable. Approximate sampling, skid, inlining and lost samples limit line attribution.

The old frontend subcomponents sum to 34.2%, not 33.7%; backend subcomponents also do not match exactly. That does not diagnose a particular failure, but it makes raw scheduling/rounding verification necessary. It is not legitimate to compute a 33.7% wall-time saving from this table.

For the actual causal test, frontend-delivery cycles/events must improve alongside the measured hot-footprintprint intervention while data work, branch behavior, output and execution conditions remain controlled. Dependency latency needs instruction/data-flow inspection and suitable backend/load-latency evidence; lack of such counters does not eliminate that explanation. Record user/system CPU time, faults, switches and migrations to expose operating-system/startup effects rather than treating every wall-time change as core execution.

## One bounded boundary, with a preserved rejection

The inspected boundary is:

```
c_token_length (hot, inlined sentinel guard)
    -> c_token_length_oversized (terminated oversized literals only)
        -> c_token_literal_scan_length
```

Current `c.h` keeps the ordinary length in the compact token and dispatches to the slow function only for the sentinel. Its comment records that leaving the fast guard out of line previously added **4.5% of stage-1 retired instructions**. That is a historical instruction-count observation, not a current timing estimate. **Do not repeat that rejected change.**

The current slow function checks the literal kind, scans the terminated spelling, checks the resulting length, and returns it. The source already has a hot/cold separation. The remaining question is whether the unity-build producer re-inlines or places slow code in a way that enlarges executed hot regions. Source separation alone cannot answer that.

This boundary is a **cheap, falsifiable negative-control candidate**, not a demonstrated dominant source of the historical lowering/type-machine misses. The latter still need current-binary attribution. A null result here says nothing about all other hot functions.

The packet contains two Clang/ELF research-only interventions:

1. **N:** add `__attribute__((noinline))` to `c_token_length_oversized` only.
2. **S:** after N, add an explicit `.text.unlikely.buster_research` section to that same definition. This deliberately avoids the `cold` attribute, which could also change size optimization and caller probability decisions.

A is unmodified main. A→N tests whether preventing re-inlining changes the machine-code boundary; N→S is a closer placement-only control with the call boundary held constant. The linker may merge/reorder the requested section, so the resulting address map—not the section name—must establish that placement changed. Relocations, relaxation and alignment still require inspection. No claim that this is a perfectly isolated layout intervention is made before that inspection.

The prototype changes one C function's attributes, not its body or signature. It adds no data structures, allocations, dependencies, global counters, recursion, threading transitions, canonical-IR changes, diagnostics changes, CI changes, or admission changes. The hot sentinel guard is untouched. It is not proposed for production inclusion and has not been built.

### Count the mechanism first

Before timing, inspect the matched trusted executable and its inline/debug information. Count actual copies/inline expansions of the slow scan and checks, caller hot-block bytes, hot cache-line/page span, and exact call sites. Do not count `0xe8` bytes as x86 calls without disassembly.

If the baseline already keeps this slow path out of line and N changes no relevant hot footprint, **stop the outlining experiment**. A function's source length, total binary size, or unused cold bytes are insufficient reasons to continue. The packet's census script collects static evidence but cannot produce dynamic hotness, call frequency or causal timing.

At source level, ordinary non-sentinel reads gain no new call. At a formerly inlined slow encounter, N introduces a call/return boundary; if it was already out of line, it may introduce none. The dynamic count is currently **unmeasured**, not zero. The two C arguments' ABI/register treatment, caller spills/reloads, prologue growth, branch instructions, lost constant propagation, and duplicated assertion handling must be checked in the producer's disassembly. Cold calls can increase common-path register pressure or stack frames even when never taken on the sampled inputs.

## Appendix B — static census script, not a benchmark

Save as `static-census.sh` outside the repository. It reads a supplied trusted
ELF, does not execute that ELF, and refuses to overwrite its output directory.
GNU/ELF tooling availability is a precondition, not a new repository dependency.
A missing named symbol is not evidence of zero dynamic cost. No runtime test of
this script against a Buster executable is claimed.

```bash
#!/usr/bin/env bash
# Read-only diagnostic. It never executes the supplied Buster executable.
set -euo pipefail
if (( $# != 2 )); then
    printf 'Usage: %s TRUSTED_ELF NEW_OUTPUT_DIRECTORY\n' "$0" >&2
    exit 2
fi
for tool in realpath sha256sum readelf nm objdump; do
    command -v "$tool" >/dev/null || { printf 'Missing tool: %s\n' "$tool" >&2; exit 2; }
done
binary=$(realpath -- "$1")
[[ -f "$binary" && -r "$binary" ]] || { printf 'Unreadable binary\n' >&2; exit 2; }
[[ ! -e "$2" ]] || { printf 'Output path already exists; refusing overwrite\n' >&2; exit 2; }
umask 077
mkdir -- "$2"
out=$(realpath -- "$2")
sha256sum -- "$binary" > "$out/binary.sha256"
readelf -hW "$binary" > "$out/elf-header.txt"
readelf -SW "$binary" > "$out/sections.txt"
readelf -nW "$binary" > "$out/notes.txt"
readelf -sW "$binary" > "$out/symbols.txt"
nm -S --size-sort --defined-only "$binary" > "$out/functions-by-size.txt" 2> "$out/nm.stderr"
objdump -drwC "$binary" > "$out/disassembly.txt"
for symbol in c_token_length c_token_length_oversized c_token_literal_scan_length c_type_parse_machine_run c_ir_lower_dispatch_run; do
    objdump -drwC --disassemble="$symbol" "$binary" > "$out/$symbol.asm"
done
printf '%s\n' \
    'STATIC ONLY: no workload, CPU counters, dynamic call counts, or timing collected.' \
    'A missing named symbol can mean stripping, inlining, cloning, or a source change.' \
    'Function size is not executed hot footprint; use matching debug/inline information.' \
    'Do not count x86 call instructions by searching raw bytes for opcode 0xe8.' \
    > "$out/LIMITATIONS.txt"
printf 'Static records written to %s\n' "$out"
```
