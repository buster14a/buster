## Confirmed findings and changes

1. The broad matrix previously suppressed independent execution-mode/mobile
   suites after any earlier failure. Explicit prerequisite/status conditions
   now preserve those suites and the final failing verdict. The six check names,
   runner labels, fail-fast=false policy, and all original commands remain.
   Resource-bounded native shards stay in build.c; splitting mobile jobs into
   newly named, potentially non-required gates is deliberately not done.
2. Non-MSVC sanitizer builds explicitly use `-fsanitize-recover=all`. A small
   real Clang/UBSan probe demonstrates that a diagnostic can recover to exit 0,
   but `UBSAN_OPTIONS=halt_on_error=1` returns failure. That setting now reaches
   the existing sanitizer matrix; no leak checks or fixtures are disabled.
   The independently reported baseline invalid-bool issue #235 is not hidden.
3. Every runner repeatedly downloaded Zig. One manifest and one cross-platform
   installer now verify both fresh and exact-key cached archives before tar or
   Zig executes. Only the compressed archive is published, before compiler
   builds/tests. No mutable build trees or test results are cached.
4. CI installed an unused Vulkan SDK from the mutable ci-latest release and
   executed its setup scripts. Those steps are removed without changing the
   already-disabled headless renderer/shader defaults.
5. Push-only triggering missed upstream fork-PR checks. Full PR/main/tag/
   merge-group/manual events now avoid duplicate feature-push work. PR revision
   cancellation is separate from non-superseded main/tag/manual runs.
6. The source workflow had floating action tags, a credential-persisting full
   history checkout, an unrestricted workspace tar, and no concurrency/host
   gate. It now uses pinned credential-free shallow checkout and tracked source
   only, attempt-qualified artifact names, one-day retention and no duplicate
   compression. Mobile fake-tool coverage is retained on both original images.
7. All platform jobs now have explicit required-suite summaries, reproducible
   commands and seven-day diagnostic artifacts outside erased build trees.
   Log capture preserves Bash pipeline and Windows native failures. Summaries
   run on cancellation, but network uploads do not start for cancelled runs.

These are one job's measurements, **not** before/after medians, and subtracting
setup steps from them would not measure a new workflow. The audit validation
run also encountered substantial macOS queueing, so queue delay cannot be
silently attributed to compilation or removed by dropping a platform.

`tools/github_ci_time.py` records actual job/step timestamps, groups by workflow
blob and runner labels, and rejects cancelled, failed, partial, rerun and
unknown-timestamp observations. It separates creation-to-last-job completion,
execution span, initial queue delay and aggregate runner seconds. It never uses
run.updated_at as a completion time or imports Forgejo's retention imputation.
The tool's known-median, duplicate, cohort-splitting and exclusion cases are
covered by local tests. At this record's creation, there is no completed
post-change cohort: **no median reduction or cache-hit speedup is claimed**.
Completed hosted measurements/checks belong in the implementation PR evidence.
