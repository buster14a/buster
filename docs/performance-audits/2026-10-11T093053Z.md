## Method

The census patch replaces the machine run in `c_parse_expression_type_query`
with a call through one noinline wrapper per category around
`c_type_parse_machine_run`. Each wrapper's inclusive cost in Callgrind is then
the machine Ir of its category, and its call count is the number of runs. The
categories are:
- **Nested:** a run made inside a running machine.
- **Constant evaluation:** any other run made outside a typed region in a
  constant-evaluation mode. The typer never answers in such a mode.
- **Body region** and **initializer region:** declines and misses inside a
  typed body or file-scope initializer. Other claims on #3102 own these.
- **Analysis phase:** every other run, tagged by the phase that was running
  when it was made. The tag is a global set before each step of
  `c_analyze_semantics_core` and `c_parse_validate_lowering_constraints`.

A second census build logged each out-of-region query's tokens to stderr.
That gave the shapes below.

## Why no phase is a candidate

The budget makes a phase a candidate only when its machine Ir is at least 1 M
and the typer can answer its queries, in the normal constant-evaluation mode
on an idle machine. Only the binder reaches 1 M, and it runs in that mode on
an idle machine, so it meets both conditions as written. It is still
excluded, because what the typer could answer there is far below the 1 M gain
that ships a change:
- **The binder, 1.41 M in all.** Its queries are made while
  `c_parse_bind_function_body` binds a body, before
  `c_parse_validate_lowering_constraints` publishes the scalar rows
  (`expression_scalar_types`) and before the interning window opens.
  - 429 of its 545 queries hold a string literal: `S8()`'s compound literal
    `((String8){ .pointer = (char8*)("…"), .length = … })`, which initializes
    a local. The tree answers that shape only over an interned `char8*` row
    (`c_ast_types_type_name`), and the window is shut while declarations
    still get their rows. [Interned rows](../agents/frontend/ast.md#interned-rows)
    shows that interning a declaration's rows is observable in `-g` output,
    so opening the window earlier is not in scope.
  - The other 116 queries are calls such as `machine_x64_x87_operand(0)`,
    single names such as `width_masks`, and the like. They run 0.24 M, so
    even a typer that cost nothing could not reach the 1 M gain that ships
    a change.
- **File-scope `_Static_assert`, 0.90 M.** This is below the gate, and it
  runs before the scalar rows are published. 60 of its 325 queries are
  literals and operators only (`(8u == 8)`), which the literal rule accepts
  only once those rows exist.
- **Deferred assertions, the post-body-loop validators and variably
  modified checks**, 0.33 M, 0.33 M and 0.03 M. Nearly every query is one
  enumerator or constant name: `TARGET_CPU_FEATURE_COUNT`,
  `STANDARD_STREAM_COUNT`, `OBJECT_SECTION_COUNT`. Each run costs about
  700–1,000 Ir. A tree answer would need a region per query, and its locate
  and lookup would cost about as much.
- **Constant evaluation, 3.22 M.** These are 17 queries, which the typer never
  answers by design.

The answerable machine Ir is therefore at most 0.24 M in the binder and
1.83 M across every out-of-body phase together, before any cost of typing
them. No candidate was built. The remaining budgets (correctness, the default path and the ship
gain) were not exercised, and no compiler change ships.

## What remains, and where it is

Under the pilot, 115.3 M of the 125.3 M machine Ir from queries (92%) is
declines and misses inside typed bodies, and another 2.5 M is the same inside
initializers. Other sessions have claimed both (#3102: the decline census,
the checked-cast operands and the string-count cache). The out-of-body phases
are closed as a typer target unless a later change publishes the scalar
rows and opens the interning window before binding. Such a change would be a
default-path change of its own.

## Validation and limits

- Callgrind counts instructions, not time, on `-march=x86-64-v3` builds whose
  AVX-512 kernels are compiled out. The noinline wrappers add a few Ir per run
  and change nothing they measure.
- One input, one host and one process, with no pinning and no `perf` counters.
- The Zen 5 validation of the hook stays **incomplete** (#2761). No PR
  benchmark request was made, because no compiler change is proposed.
- No compiler source changed, so no compiler tests were required. The patch
  touched only a throwaway worktree.
