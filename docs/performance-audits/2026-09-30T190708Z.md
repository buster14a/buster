`2026-09-30T190708Z` (Linux x86_64, Ryzen 9 7940HS (Zen 4), Clang 22.1.8;
**Issue 60 current preprocessor SIMD class-mask ablation: byte identity, tiny
instruction gain, no demonstrated whole-compile speedup**).

## Disposition

Do not add another SIMD preprocessor scan on this evidence. The current source
already implements the issue's proposed classification/search scan:
`c_pp_class_masks_build` projects the lexer's one-byte token shapes into four
per-64-token masks; the driver uses those masks for line ends, parenthesis depth,
and macro-candidate identifiers. `c_symbols_intern_tokens` also selects
identifier lanes with a SIMD comparison. The final token stream is contiguous,
but macro expansion still uses contiguous LIFO tasks and linked output nodes.
The old premise that no contiguous preprocessor representation exists is false;
the stronger premise that expansion/output are wholly contiguous is also false.

The masks have row-scan fallbacks and a registered differential test. This
experiment forced only the class-mask builder to leave `word_count` zero, so the
existing driver chose its scalar row scans. On the current full macro workload,
SIMD saved about 0.095% of preprocessor-process user instructions and 0.016%
of whole-compile user instructions. The paired Zen 4 wall comparison showed no
reliable gain. This is a present-source negative screen, not a Zen 5 verdict or
a reason to remove the already-landed path. Issue #60 needs a qualified Zen 5
A/B for this bounded candidate, or a new current-source census identifying a
different scan with material end-to-end cost. #1701 owns broader preprocessor
throughput and per-token footprint; #46 owns the dedicated acceptance harness.

On a 300-line macro fixture with variable line lengths and parenthesis runs,
both compilers returned success and produced the same `-E` bytes (SHA-256
`9238e4c6240590edf5e8c52656ab6d52a9e5c2a7a0e4cb3d345e10bcdf1c53ee`).
On an incomplete `#if`, both returned failure with identical stderr (SHA-256
`33dcda1a2062833fb9d4b57053e43f57b0887035b7380d18d0a099040f3bb641`).
The frozen full macro workload `macros.c` has SHA-256
`a99ada929f75c22fb6a4d11d927e60f181f14d6abc4bcd73ab1a53bae5919c4d`.
Across ten alternated `perf stat -e instructions:u` pairs, both `-E` outputs
matched SHA-256 `f397ba50f7832810d281446181d4ecfd8053f9b5e204c221fe8b1c6d97c5e75f`,
and both object outputs matched SHA-256
`37447ff6d078b776546abbc6e2f98342acbe79947584b810dec5995107d124a3`.
The harness's `--require-identical-output` passed every paired compile. The
already-registered `c_test_pp_class_masks` covers class answers across 64-token
windows; this session did not run the full unit, sanitizer, platform, or
self-host suites because no production behavior changed.

## Current-source measurements

Per-process user instruction counts used `perf stat -x, -e instructions:u`
around `ide cc -g0 -O0 -fregister-allocator=none` on the same frozen full macro
source. Each arm was run ten times in alternating order with the same output
path per arm. The counts varied by at most 57 instructions for `-E` and 530
for `-c`, far less than the ablation delta. These are instruction counts, not
elapsed time or a Zen 5 acceptance result.

| Full macro source | Scalar median | SIMD median | SIMD reduction |
|---|---:|---:|---:|
| `cc -E`, user instructions | 530,040,005 | 529,534,982 | 505,030 (0.0953%) |
| `cc -c`, user instructions | 3,073,713,067 | 3,073,212,376 | 500,677 (0.0163%) |

The standard paired throughput harness used 30 pairs in each of two rounds,
three warmups, identical objects required, `none` allocator, and guard disabled
for this targeted comparison. The baseline was the scalar ablation, the
candidate the pristine SIMD binary. The full workload's `macros/none` medians
were 304.713 ms scalar and 306.525 ms SIMD, with paired change +0.92% (candidate
slower). Its round-specific paired-ratio confidence intervals were
`[0.9993, 1.0264]` and `[0.9846, 1.0194]`, both spanning 1. The CI-profile
`macros/none` medians were 56.425 and 56.214 ms; paired change +0.61%, with
intervals `[0.9636, 1.0413]` and `[0.9754, 1.0525]`. The tiny-startup control
had a -1.43% paired change and intervals spanning 1. Peak RSS was effectively
unchanged in these runs. The harness reported no confirmed regression, which
does not establish a speedup or equivalence.

Reproduction of the timing comparisons, after freezing the two binaries:

```sh
./build.sh bench_throughput run --baseline /absolute/scalar-ide \
  --candidate /absolute/simd-ide --output build/issue60-zen4-compare \
  --baseline-id scalar-a947bc1 --candidate-id simd-a947bc1 --profile ci \
  --workload macros --workload tiny_startup --mode none --pairs 30 --warmups 3 \
  --no-guard --require-identical-output
./build.sh bench_throughput run --baseline /absolute/scalar-ide \
  --candidate /absolute/simd-ide --output build/issue60-zen4-full \
  --baseline-id scalar-a947bc1 --candidate-id simd-a947bc1 --profile full \
  --workload macros --mode none --pairs 30 --warmups 3 \
  --no-guard --require-identical-output
```

The host was not leased or physically isolated. Other checkout builds became
active around the full wall-time run, so the paired wall samples are a
diagnostic screen only. The per-process instruction comparisons provide the
more stable local observation. No dedicated Ryzen 7 9700X/Zen 5 run was
available, and no runtime dispatch was added; the current `simd.h` contract
selects the target-fixed vector tier at build time with a scalar fallback on
other targets. This audit does not claim to meet issue #60's original runtime
dispatch or Zen 5 acceptance criteria.
