`2026-09-26T150516Z` (GitHub-hosted ubuntu-24.04 x86_64 and a 4-vCPU cloud
container; **remove the Wasm/eBPF duplicate module validation and the ELF
object-image payload copy found by a whole-pipeline fact-flow census**).

## Decision

Two unowned phase-boundary materializations are removed. Output is
byte-identical in every comparison below.

- **E1: duplicate whole-module validation at the Wasm and eBPF emitters.**
  `wasm_emit` and `ebpf_emit_with_options` re-ran `ir_prepare_canonical_module`
  uncertified on the module the driver had just prepared. Native code
  generation (`assume_validated`) and LLVM bitcode (`validate_ir = false`)
  already accept the driver's preparation. Wasm and eBPF now do too, through
  `WasmOptions.assume_validated` and `EbpfOptions.assume_validated`. One
  complete validation pass per Wasm64, wasm32-WASI and eBPF compile is gone.
- **E2: the copied ELF object image for `-c`.** The ELF writer copied every
  section payload into a fresh file-sized image only because `file_publish`
  took one slice. `object_write_borrowing` now records each payload of at
  least a page as (offset, bytes) and leaves its range unwritten.
  `file_publish_slices` writes the same file through the same staged
  replacement. `object_write` and every other consumer keep the contiguous
  image.

This records exact work, bytes and fault counts. It is not a Zen 5 timing
claim.

## Fact-flow census that selected them

Stage-1 unity `-g0 -c` on the baseline totals 21,929,573,538 callgrind
instructions (x86-64-v3 twin). Exact minor page faults per phase come from a
disposable `getrusage` probe that was never committed.

| Phase | Instructions | Pages touched | What it materializes / what its consumer reads |
|---|---:|---:|---|
| Preprocess | 1.57 G (7.2%) | 248.5 MB | Translated copies, per-file token arrays kept for macro ranges, and a 3.6 M-token stream. Every field is read. |
| Parse | 0.43 G (2.0%) | 1.4 MB | 13 K declaration records, plus a second body walk that feeds only `_Static_assert` (38 M). |
| Semantics | 8.11 G (37.0%) | 166.6 MB | Lowering-constraint validation (6.38 G) retypes expressions that lowering types again. Owned by #1028. |
| Lowering | 5.68 G (25.9%) | 425.3 MB | Bodies 186.4 MB. SSA finish 87.3 MB, of which 35.6 MB is TU-arena garbage from 459,618 created and 425,757 retracted parameters (#1321, #1401, #1402). Two token-sized maps (28.8 MB). |
| IR prepare | 1.40 G (6.4%) | 27.6 MB | FAST-guard validation 0.49 G; publication 0.28 G. The pools and `instruction_remap` have no production reader. |
| Codegen | 4.68 G (21.3%) | 124.7 MB | FAST placement 2.64 G (#1296, #1320), selection 1.23 G, encoding 0.61 G. |
| Object | 0.02 G | 24.7 MB (-g0), 85.2 MB (-g) | `ObjectFile`, with `.text` copied from the module buffer (#1341). |
| Write | 24.5 M | 38.3 MB (-g0), 52.2 MB (-g) | A file-sized image copying every payload, then write, flush and rename. |

Every canonical consumer re-prepares its module. Only Wasm and eBPF did so
uncertified, so their compiles validated twice:
- In production: FAST guard, then the emitter.
- In test-enabled builds: FAST guard, FAST output, then the emitter.

The ELF image holds a second copy of every section payload that is already
final in the ObjectFile.

## Correctness

- **Fixture corpus:** 392 `tests/*.c` files × 8 configurations = 3,136
  compiles. The configurations are ELF x86-64 and AArch64 at `-g0` and `-g`,
  COFF `-g`, Mach-O `-g`, Wasm64 and eBPF. Exit status, stderr and output
  SHA-256 are identical for all 3,136, and 2,447 of them produce output.
- **Full in-process suite:**
  - Release: 3,233,613 passed.
  - Counter build (runs the exact-count assertions): 3,300,332 passed.
  - Both have the same 2 failures, `compiler_driver_test_wide_vector_boundaries`,
    because host Clang 18 lacks `-march=znver5` (#1292). Unmodified baseline
    `main` on the same host passes 3,233,473 assertions with the same 2
    failures, so the candidate adds 140 assertions and no failure.
- **Self-host:** `test_self_host --config Release` reaches the fixed point,
  stage 1 = stage 2, 46,667,224 bytes.
- **New regressions:**
  - `compiler_driver_test_direct_emitter_preparation`: Wasm64, WASI and eBPF
    in both frontend forms. The same prepared module emits identical bytes
    with and without `assume_validated`. A fault injected after preparation is
    still reported under zero options. Counter builds assert 1 versus 0
    validation calls, and 2 preparations with 0 input rescans per driver
    compile.
  - `compiler_driver_test_object_borrowed_payloads`: x86-64 and AArch64 ELF,
    COFF and Mach-O at `-g0` and `-g`. The published file, the slice
    concatenation and `object_write` must agree byte for byte. Only ELF
    borrows, and only payloads of at least 4 KiB.

## Rejected or deferred after measurement

| Candidate | Measured cost / reason |
|---|---|
| Fuse FAST compaction with publication's row permutation | The permutation's row moves cost 12 M and its clears 5 M instructions: about 0.1% |
| Replace lowering's two token-sized maps with per-use owner ranges | About 10 M vectorized instructions; only about 5,400 pages to gain |
| Move the parser's `_Static_assert` body walk into the binder | 38 M instructions (0.17%) |
| Lexer-emitted string-literal lengths | Count 747 M and decode 513 M, but the kernels are already tuned for this corpus and #1028 owns the recount |
| Drop the FAST-input guard validation | It is the only production validation; that would be a policy change |
| Stream `-c` output without flushing | 0.27–0.31 s is flush and replace durability, not a materialization |
| Semantic → lowering fact reuse, SSA parameter creation, FAST slot liveness, x86 prewarm, text handoff | Owned by #1028, #1321/#1401/#1402, #1296/#1320, #1295/#1317 and #1341 |

```sh
E=docs/performance-audits/evidence/2026-09-26T150516Z

    --name selfhost-g0 -- cc -Isrc -Ibuild/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 -g0 -c src/buster/apps/ide/ide.c -o '{out}'
python3 $E/fact_flow_ab.py corpus --base <base>/build/Release/ide --candidate <candidate>/build/Release/ide --output /tmp/corpus
python3 $E/profiling_build.py <tree> /tmp/profiling-<tree>
```

The `ab` self-host command runs from the baseline tree, whose source is the
frozen input. `.github/workflows/research-fact-flow.yml` runs the same
sequence on a GitHub-hosted runner.

## Limits

- No Zen 5 or other dedicated-host timing was taken. Hosted and container
  wall times are context only.
- Page-fault counts come from Linux with THP in `madvise` mode.
- E2 covers ELF only; COFF and Mach-O keep contiguous images.
- The E1 saving applies only to the Wasm and eBPF pipelines.
