## Result and scope

The revised #854 demonstrates a compile-time benefit on the existing full-profile
`large_function` workload with local-backed C lowering and shared canonical local
promotion disabled. Paired block medians improve **4.627% and 4.261%** in the two
rounds; both uncertainty intervals are entirely below zero. The workload contains
407,679 source bytes, 8,197 lines and one function. Both compilers emit the same
1,018,592-byte object, SHA-256
`20eb35e3894499e2f63cb7de484c538d87cee78f36bdbc9a59f2c383a0ec97fb`.

This is a scoped benefit, **not a demonstrated default-configuration speedup**.
The standard six workloads and frozen default unity compile remain inconclusive.
None of the other local-backed workloads establishes an improvement or regression
in both rounds. All native comparisons pass the existing broad regression guard;
that guard is not the evidence used to claim the improvement.

The frontend now fills the previously unpopulated canonical `local_places`
projection, including temporary locals. The selector retains its 16-byte hot
value-use row, but stores promotion counters and epochs in 20-byte rows for
promotable locals instead of three value-wide arrays. No-store filtering and
store-ordinal reset visit this sparse population. A differential regression
compares sparse and fallback machine-code bytes, including volatile, uninitialized,
branch-fusion and vector cases. The row-scan fallback remains for hand-built IR.
