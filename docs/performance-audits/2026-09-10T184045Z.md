## Reproduction and repair

The original test-only #366 revision, `f41866e0`, deliberately preserved failing
aggregate transformations. Replayed on public main `f5ebfc3c`, the reduced
scalar function containing a two-element array, a struct copy, and element
reads still produced `aggregate Wasm64 SSA value is unsupported` and
`aggregate eBPF SSA values are unsupported`, in both frontend forms. These
were explicit feature gaps, not evidence of wrong-code execution. The first
attempt with `-fverify-codegen` correctly refused that native-only option;
the actual backend replays omitted it and retained the aggregate diagnostics.

The repair gives local aggregate values private frame storage and copies on
their defining load, preserving the snapshot if the C object changes later.
Wasm64 uses `memory.copy`/`memory.fill` with i64 addresses and byte counts,
consistent with the [Memory64 validation contract](https://github.com/WebAssembly/memory64/blob/main/proposals/memory64/Overview.md).
eBPF uses exact byte accesses and accounts for every snapshot in the existing
512-byte frame limit. Constructors initialize private padding before copying
members. The canonical IR and function ABI are unchanged; there is no native
fallback, test exclusion, or relaxed validator.

The original initialized-array and pure-call transformations, independent
reference profiles, reducer and failure retention remain enabled. The eBPF
VM's existing local-call exclusion is still explicit. New shared C cases cover
plain arrays, independent mutations, packed and nested records, and unions.
Their ordinary tests use both frontend forms, repeated-object determinism,
full-width boundary inputs and preserved ABI/alignment/frame refusals.
