## Source and implementation

PR #418 retains the recovered post-promotion boundary implementation and its
negative controls. The original head was `59877468de5fc9bb764b452f0662662b3d58e082`.
Current-main integration preserves the promotion/scaling corpus; no verifier,
test assertion, warning policy or CI configuration is disabled or removed.

Reproduction on the original head found complex predicates combining Boolean
values with integer bitwise opcodes, and qualified aggregate fields capturing
unqualified values at a different constructor type. Strict canonical input
validation rejected the existing complex fixture (error 11, function 14,
block 0, instruction 18, opcode 31) and the packed-layout caller with the
new-host ABI flags (error 11, function 48, block 143, instruction 1240,
opcode 20). These are fresh source reproductions, not inherited diagnoses.

The repair emits the existing Boolean AND/OR vocabulary for complex and math
predicates, checks its exact Boolean value contract, and handles those opcodes
in both native canonical emitters. Qualified constructor mismatches that differ
only in volatile qualification initialize explicit typed storage through the
existing STORE/LOAD contract. Exact constructors retain their existing path;
aggregate type checks remain exact and initializers evaluate once.

The new registered fixture covers qualification, alignment, omitted and zero
initializers, nested records, unions, arrays, signed zero, NaN, infinity and
complex comparisons/truth. Runtime tests cover both frontend forms and all
four allocators with strict verification. Raw producer tests cover x86-64,
AArch64 and Wasm64, with malformed Boolean-operation controls. Existing complex
and promotion regression coverage remains intact.
