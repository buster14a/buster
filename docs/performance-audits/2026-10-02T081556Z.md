`link_comdat_plan_build` decides all non-associative groups first. Its old
propagation step repeatedly examines every COMDAT row, carrying a parent's
KEEP/DISCARD decision to an unknown associative child. If C records form a
chain ordered child-first, only one child resolves per pass. C-1 productive
passes and a final empty pass examine C² rows and read C(C-1)/2 parents.
The record table, payload and required decisions each grow only O(C).
Reordering the same chain root-first instead resolves all children in one
productive pass, followed by an empty pass: 2C rows for C > 1. This isolates
association depth and table order from necessarily larger output.

Microsoft's [PE/COFF contract](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#comdat-sections-object-only)
allows associative chains through other associative groups, requires a final
non-associative root, and forbids loops. Thus child-first chains are valid
adversarial object inputs. Ordinary shallow associations and root-first chains
are separate controls.

## Algorithm and complexity

`link_comdat_associations_resolve` scans each object's C state bytes once.
An unknown child with an already-resolved parent immediately receives that
state. Otherwise the walk marks its active path VISITING and follows the
immutable parent IDs. Reaching VISITING rejects a cycle. Reaching KEEP or
DISCARD finishes the path by following its parents again and replacing its
VISITING marks with the terminal decision.

Every associative row transitions from UNKNOWN to a final state at most once.
Only unresolved ancestors join a path; sharing an already-resolved suffix does
not expand it again. An edge is read at most once while discovering its node
and once while publishing its path. Hence association resolution is O(C + A)
for A associative groups, including arbitrary order, depth and fan-in. Its
caller has already checked parent bounds/self-parent and finished root selection.
It preserves the existing invalid-input result for cycles and malformed records.

No stack, auxiliary allocation, table clear, changed state-array size or
persistent cache is introduced. Retained memory and invalidation costs are
unchanged; the graph walk uses only existing query-local state bytes. Ordinary
resolved-parent associations need one parent read and one final-state write.
This bound excludes COMDAT name hashing, exact-match payload/relocation
comparison, other linker work and the rest of the compiler.

## Generator and deterministic guard

The registered `link_test_comdat_association_scaling` fixture contains a
parameterized in-process ObjectFile generator. It varies only COMDAT population
and topology/order: forward, reverse and permuted chains, stars and shared
ancestors, with kept/discarded roots. It compares generated expected roots and
the independent legacy pass-scan control to the exact production resolver.
The negative control intentionally retains the old growth mechanism, bounded
to small populations so the suite cannot monopolize a runner.
