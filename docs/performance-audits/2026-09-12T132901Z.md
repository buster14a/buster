## Scope and identity

GitHub [#107](https://github.com/buster14a/buster/issues/107) replaces the
stable insertion sort in `link_initializer_arrays_order` with four stable
least-significant-byte radix passes over the full unsigned 32-bit priority.
The existing ordered scan, section rebuilding, priority copy-back and
relocation/symbol remapping remain intact. The second index buffer becomes
the inverse permutation after sorting, so no extra per-entry allocation is
needed. No SIMD, callbacks, recursion or dependencies are introduced.

Base: `719ba64e3022a0ae1db078ea97cb951a70ac02a0`.
Local implementation: `8b40e04efd844bfc5f952264b4b5bfa0f2f28789`.
Published implementation: `821562a1357f53db02ce8059663cfe05486b63dc`.
Both implementation commits have tree `09be6c65a03134efce191d48877ace1b5387c1f4`.

## Correctness and work bound

The registered `link_test_initializer_order` test passes **66,495/66,495
assertions against both the original sort and the replacement**. Its stable
rank oracle is independent of either implementation. It covers empty,
singleton, ordered, all-equal, sparse and 4,097-entry reverse arrays, both
INIT and FINI, repeated keys, zero, UINT32_MAX and differences in every key
byte. Every entry carries distinctive bytes, a symbol with an intra-entry
offset and a relocation with an intra-entry offset and negative addend.
It checks their destinations, one-past-array symbols, unrelated text records
and preservation of input records. Existing two-object constructor-order and
native executable tests remain registered.

On reversed distinct keys, insertion sort performs N(N-1)/2 shifts. The new
sort initializes N indices, then performs four N-entry histograms, four
256-bucket prefix scans and four N-entry forward scatters. Section rebuilding
and remapping remain linear in their existing entry/relocation/symbol counts.
There is no timing threshold in the unit tests.

## Linker timing

The retained [C probe](evidence/2026-09-12T132901Z/initializer-bench.c) calls
the **real `link_objects` implementation** from each source tree. Each input
has N initializer entries, N local symbols and N ABS64 relocations. Timing
includes section merging, symbol handling, sorting and remapping; input
construction and the complete output oracle are outside the timed region.
It does not include ELF parsing, final executable serialization or process
startup, and is not a whole-compiler or native Zen 5 performance claim.

Both probes are Clang 18.1.3 `-O3 -DNDEBUG -DBUSTER_OPTIMIZE=1 -march=native`
builds, with debug information and frame pointers, the project's integer and
aliasing flags, no sanitizers and no LTO. This KVM guest is shared, unpinned
and contended, including other builds. The first wall-only collection showed
substantial descheduling; its complete raw rows are retained as
[initializer-wall-only.csv](evidence/2026-09-12T132901Z/initializer-wall-only.csv).
A second collection additionally brackets the link with process CPU time
(`clock()`, 1 microsecond resolution here). No observation was removed from
either raw file. The CPU series helps distinguish linker work from waiting
for the CPU; it is not a hardware-counter or dedicated-host qualification.

Each collection has two rounds, AB then BA for every shape/size, eight links
per variant/process: the first is the declared cold warmup, followed by seven
measured links. All **352 links per collection** succeeded and passed every
entry/priority/symbol/relocation check. The table gives separate medians of
the fourteen warm observations per variant from
[initializer-timing.csv](evidence/2026-09-12T132901Z/initializer-timing.csv).

time for the four radix passes. Ordered controls vary in both directions;
these observations do not establish a small-workload speedup or a statistical
non-regression bound. Their production path remains the existing scan.

## Temporary memory

The probe records the scratch arena's dirty high-water mark above its initial
position and the result arena's position growth. For every unordered sample,
both versions use **20N bytes** of sorting scratch: two N-entry u32 index
buffers, 8N copied section bytes and N sorted u32 priorities. At N=65,536 this
is **1,310,720 bytes in both versions**, and result-arena growth is
**7,144,728 bytes in both versions**. Ordered and equal cases use zero sorting
scratch. This is measured arena usage, not whole-process peak RSS.

The new fixed histogram is 256 u64 counters, **2,048 stack bytes**. In the
wall-only probe, Clang's `-fstack-usage` reports the inlined main frame as
2,104 -> 4,216 bytes (+2,112 including compiler frame effects). Dynamic
scratch is released after each array exactly as before.

## Reproduction and validation

The benchmark source, collector and raw CSVs are retained under
`evidence/2026-09-12T132901Z/`. Configure the base and implementation trees,
then build one probe from each repository root, changing the generated-header
and output paths for that tree:

```sh
clang -O3 -DNDEBUG -DBUSTER_OPTIMIZE=1 -g -fno-omit-frame-pointer \
  -march=native -fwrapv -fno-strict-aliasing -funsigned-char \
  -ffunction-sections -fdata-sections -fstack-usage \
  -Isrc -Ibuild/generated -Wno-unused-function -Wno-undefined-internal \
  /path/to/initializer-bench.c -Wl,--gc-sections -lm \
  -o /path/to/initializer-bench-base
# Use initializer-bench-patch for the other tree. Put both beside the collector.
python3 /path/to/measure-initializers.py
```

production source; define `BUSTER_INCLUDE_TESTS=1` and
