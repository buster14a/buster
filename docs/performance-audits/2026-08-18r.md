`2026-08-18r` (Linux x86_64, Zen 4 7940HS; **separate the dominant
allocator-row population and give it a homogeneous kernel**).  The first
profile after `18q` still put FAST placement at 5.34% of cycles and its
prepass at 1.82%.  A temporary shape census over 1,493,600 machine rows found
that just five unconstrained virtual-only shapes accounted for 1,093,934 rows
(73.2%): one definition, two uses plus one definition, two uses, no allocator
operands, and three uses.  Those rows nevertheless entered the full placement
path and repeatedly proved that fixed registers, tied pairs, early clobbers,
physical definitions, opcode clobbers, calls, and terminators were absent.

The existing compact `operand_masks` word now carries one high state bit for
that regular population.  The prepass publishes it while it already owns the
opcode descriptor and operand masks, and hoists its existing constraint query
to one query per row.  Placement consumes the simple rows with a dedicated
use/define mask kernel, preserving pin handling and copy coalescing, then
continues without loading the opcode descriptor or entering any irregular
state machinery.  The general path remains unchanged for constrained,
physical, clobbering, call, terminator, and block-reference rows.  Default
FAST scans also leave block-head and row pin work outside the no-pin
population; QUALITY's non-null pin projection retains the original behavior.
This is a scalar population kernel over explicit masks today, with the common
state separated cleanly enough for future run batching instead of trying to
vectorize a heterogeneous row switch.

Seven alternating same-source, CPU-pinned, non-multiplexed instruction pairs
are byte-identical (one 35,553,120-byte output hash) and reduce the median
from 11,110,556,149 to 11,019,029,514, **-91,526,635 (-0.8238%)**.  Branches
fall 2,076,523,890 -> 2,065,762,602 (**-0.5182%**), branch misses fall
26,166,650 -> 26,095,373 (**-0.2724%**), L1d loads fall 4,017,517,608 ->
3,989,221,141 (**-0.7043%**), and L1d misses fall 131,751,500 -> 131,330,187
(**-0.3198%**).  Eleven alternating cycle pairs are noisy and split 6/11 for
the candidate; their independent median is neutral-to-lower at 4,335,597,623
-> 4,334,369,787 (**-0.0283%**).  Staged instruction probes attribute about
36.5 M to the population kernel, 15.4 M to preclassifying the state, 20.9 M
to deferring opcode-descriptor lookup, and 18.9 M to keeping absent pin state
outside the row/operand work.

Three tempting adjacent changes were measured and rejected.  Removing the
x86 encoder capacity traversal behind a deliberately gross reservation showed
only a ~12.7 M-instruction (0.11%) ceiling, too small for its allocation and
overflow risk.  Doubling the codegen attempt reservation was flat, confirming
that an apparent row-count mismatch was merely IR rows versus machine rows,
not a retry.  A compact register-class SoA plus fused vector census regressed
about 12.2 M instructions, and gating pin state inside the register picker
regressed about 3.3 M; both added streams/branches without displacing enough
work and were reverted.

The final `test_self_host` reaches a byte-identical 35,553,120-byte fixed
point: stage 1 retires 11,019,317,245 instructions (versus the merged
11,106,838,655 baseline, **-87,521,410 / -0.7880%**), stage 2 retires
78,286,428,225, and all 1,443,793 exact attempts succeed.  Release `test_all`
passes 309,182 assertions in all 39 modules; sanitized Debug passes 307,383
assertions in all 39 modules; Clang static analysis checks the unity
translation unit with zero analyzer warnings.  This is the measured
Acton/Fredriksson progression: when a state occurs once, count the population;
when it is the population, classify it once and give it its own regular data
path rather than optimizing repeated absence checks.
