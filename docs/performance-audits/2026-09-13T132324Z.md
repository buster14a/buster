# Astra SIMD 01: a data-parallel compiler without a replacement IR

## 1. Result, scope, and evidence contract

**The most defensible direction is to eliminate repeated work first, then batch the remaining independent work in small, consumer-owned projections. It is not to turn every compiler phase into a SIMD interpreter.** Three independently bounded research candidates emerge: post-SSA finalization, canonical-validation check tiles, and residual selector operand queries. Their implementation priority is conditional on a current exclusive-cost census. This report supplies algorithms and decision criteria, not an assertion that all three will win.

Analyzed repository: `buster14a/buster`. Analyzed main commit:
**`5865fa7add27908656aedf28a3c0e6a3de47dc04`**. All source references below are pinned to that commit. Default-branch code-search results were used to locate files, not to silently substitute another revision. Main moved during the investigation; this document remains a frozen-source report. The publication branch is separately owned: `astra/simd-01-architecture-20260913-9c8e2`.

The current [agent instructions][AG], [SIMD guide][SG], [benchmarking guide][BG], [frontend foundations][FG], [machine guide][MG], relevant sources, and [newest audit at the analyzed pin][HA] were read. Source bodies were inspected especially for SSA finalization, validation ownership/global checks, selector helpers, predicate placement, and source-position recovery. The coverage matrix also uses source orientation headers and current subsystem contracts; those are identified as navigation/contract evidence rather than measurements of every leaf implementation. This is an algorithm-family map, not a claim of exhaustive line-by-line review of the repository.

**No compiler build, test, benchmark, sanitizer run, or remote performance experiment was executed for this research.** No dedicated machine identity, exclusive reservation, PMU access, or runner result was established. All proposed performance gains are hypotheses. Documentation generation in the assistant's scratch container is not compiler execution on the user's laptop.

### An explicit meaning of “fastest correct C compiler”

A useful first championship contract is deliberately narrower than “all C on every machine”:

| Dimension | Proposed comparison contract |
|---|---|
| Language | GNU C11 mode, with an immutable eligibility manifest covering the C features/extensions actually admitted at this source pin. Include preprocessing, type/constraint checking, ABI behavior, and required diagnostics. Unsupported cases stay visible in a separate coverage ledger; they are not silently discarded after timing. This does not claim complete GNU C or ISO conformance. |
| Primary output | `x86_64-unknown-linux-gnu`, fixed x86-64-v3 output feature contract and fixed ABI, relocatable ELF and hosted executable as separate rows. Host AVX2/AVX-512 selection must not change the generated target feature set. |
| Primary policy | Buster FAST, debug information off/on as separate rows. NONE, MIR_STACK, and QUALITY are independent policy rows, not interchangeable performance numbers. Preserve all supported targets and modes through regression gates even when the initial competition is narrower. |
| Inputs | Frozen source plus include closure, generated configuration headers, argument vector, environment-dependent include resolution, libraries, and output location policy. Include tiny files, medium libraries, macro-heavy and aggregate-heavy inputs, large CFGs, and the frozen self-host unity input. |
| Internal correctness | For the three representation/query changes proposed here, exact diagnostics and accepted/rejected results, canonical identities/order, selected machine rows and side tables, and final artifact bytes under unchanged policy. Preserve the existing self-host executable and preprocessed-stream fixed points. |
| Cross-compiler correctness | Independent execution/ABI/diagnostic oracles; different compilers need not emit identical bytes. Defined-behavior tests must agree. An internal verifier is necessary but is not an independent runtime oracle. |
| Output quality | Internal candidates must preserve bytes, so generated-code quality is unchanged. For a cross-compiler speed claim, predeclare a quality-qualified row: every runtime workload within 5% of the pinned Buster FAST reference, with text size no larger than that reference, after accounting for measurement uncertainty. These are proposed comparison limits, not an existing repository policy. Also publish the full compile-time/runtime/size Pareto frontier rather than hiding nonqualifying compilers. |
| Completion | Measure process start through successful artifact write/close, including preprocessing, metadata and linking where requested. State whether durable storage synchronization is included; do not call a merely written artifact crash-durable. Report failed inputs separately rather than crediting early failure as throughput. |
| Latency versus capacity | Single-file process latency, warm persistent-process latency, and saturated multi-input artifacts/second are three different experiments. State cache state, job/lane counts, memory limits, and startup/prewarm treatment. |

A “fastest” claim requires this contract, immutable comparator versions/configurations, reproducible raw samples, uncertainty, and no failing correctness gate. This report establishes neither a current record nor a numerical forecast. A compiler that omits semantics, lowers output quality, times only an internal phase, or excludes linking has not won the same contest.

## 2. What is already implemented, and what the historical profile means

The [September 12 audit][HA] measured a frozen `5dab18af0208cfa7fa65673b6884d5c253fda85b` workload with Clang 18.1.3, glibc 2.39, and Valgrind 3.22.0 in a shared four-vCPU Emerald Rapids KVM guest without PMU access. The measured compiler used `-march=x86-64-v3` because that Valgrind could not decode the EVEX path. Its input had 30,729,994 translated bytes and 3,364,471 preprocessed tokens. Its total was 13,749,246,043 Callgrind Ir.

These are **historical counting-instrument results**, not current-main wall-time fractions, hardware retired instructions, or Zen 5 kernel timings:

| Historical region | Inclusive share | Accounting constraint |
|---|---:|---|
| `c_lower_to_ir_with_options` | 38.0% | Contains body lowering and global initialization; do not add its children again. |
| `codegen_generate_canonical_module_with_trace` | 20.9% | Contains selection, placement, and encoding. |
| `ir_prepare_canonical_module` | 14.4% | Contains validation, not an additional budget beside it. |
| `c_analyze_semantics` | 11.6% | Separate top-level region in that report. |
| `c_preprocess` | 10.2% | Includes its source/lexical work; a lexer percentage cannot be added independently. |
| Unlisted remainder | Approximately 4.9% | Arithmetic remainder of rounded shares, not a newly measured phase. |

Within those parents, validation was 8.6% of total Ir, x86 selection 7.3%, `machine_predicate_placement_build` 6.9%, and x86 encoding 4.1%. **The predicate-placement number must not be interpreted as predicate-only work.** The current [implementation][RP] calls `machine_fast_placement_build_core`, `machine_quality_placement_build_core`, or `machine_stack_placement_build_core` inside that wrapper. It also already respects `predicate_absence_certified`. Optimizing a seven-register predicate choice cannot claim the wrapper's inclusive budget.

The same audit removed 69,627,498 bytes of fill per compile, chiefly by plus-one sentinel encodings in four per-token arrays and zeroed-arena allocation of constant-initializer images. Its total Ir fell 0.466%, while instructions outside the libc fill accounting increased. Native peak RSS improved in the recorded experiment, but noisy wall-time orderings disagreed. That is a useful warning: neither “fewer instructions” nor “fewer bytes” alone decides elapsed time. These landed changes are the baseline, not new recommendations.

Other already-existing infrastructure materially changes the research:

* [`c_lex_compact`, `CPpClassMasks`, and token shape sidecars][CS] already classify/compact byte or token populations. The lexer has an independent scalar differential path and item-aligned windows. Do not propose initial SIMD lexing or initial preprocessor class masks as missing work.
* [`c_parse_token_census`, predefined-symbol word bits, matching-delimiter/position indices][CP] already avoid repeated spellings or wide token-row walks. [`ir_source_search_vector` and the dual source-map cursor][IR] already use short-span masked comparisons and locality-aware lookup.
* [Direct SSA][FG] already has sparse `(block, owner)` state, single-entry-definition forwarding, whole-owner memory restoration, and stable retirement of empty parameter-bearing blocks. [PR #497][P497] is not a new candidate. Its integration/performance acceptance must not be replaced with another implementation of the same list.
* [PR #375][P375] is merged. Its AArch64 direct-call facts are accumulated in an existing operand walk, without a replacement stream. A future #132 experiment must beat this fused scalar baseline, not its removed prewalk.
* [`MachineInstruction` is a 24-byte row; `MachineOpcodeInfo` remains 96 bytes; the simple `MachineOpcodeRow` projection is 16 bytes][MG]. Type-class projections, compact opcode facts, immutable recipes, module call plans, and a bounded demand-only address cache already exist. Do not resurrect the unused matcher removed under #42/#269 or split the canonical row merely to claim SoA.

Current coordination: [#128][I128] is the throughput architecture umbrella; [#447][I447] owns direct-SSA throughput; [#132][I132] owns residual selector prewalk/query work; [#564][I564] is **attribution only**. Its current draft [PR #576][P576], read at head `46f96daf2725f9dccc06c16b2d3c60e484d045a4`, owns diagnostic-only validation census work. This report does not claim that work, change validation semantics, or authorize an optimization under #564. Focused searches and these discussions establish relevant overlap, not an atomic ownership lock on all future changes.

## 3. Algorithm coverage matrix

Notation: **W** = SIMD within one item; **A** = SIMD across independent items/queries/functions; **B** = bit-parallel formulation. **S** = semantic ordering, **G** = algorithmic dependency, **R** = representation-induced serialization, **I** = API-imposed serialization. A scalar implementation is not evidence that all four forms of serialization are inherent.

Evidence labels: **body** means an inspected implementation region; **map** means an inspected source orientation/header or current guide; **historical** means the cited old profile. Every proposed formulation below is unmeasured here. Source links identify exact files and searchable symbols, rather than stale historical line numbers.

| Source/debug metadata — [`ir_source_region_position`, `machine_schedule_remap_line_marks`, `link_pe_resolved_codeview`][IR] | Body/map: indexed source recovery; stable bounded-run merge sort exists for reordered marks. | W: short source-position spans/varint pieces. A: independent functions' metadata streams and relocations. B: change/line-state masks and prefix lengths. Scalar: existing cursor/index, omit unchanged records, stable merge. | S: source order, equal-row marks, debug IDs and section offsets. Do not retry the historically negative cursor stepping experiment as a new idea. Metadata can dominate after code generation improves. |
| Archive extraction and symbol resolution — [`compiler_driver_execute_invocation`, archive worklist ownership][DR]; [`link_objects`][LK] | Map: serial archive selection boundary; weak-symbol resolution and relocation rebasing. | W: symbol-name/fingerprint comparisons. A: independent index construction/queries against frozen tables. B: unresolved/selected membership. Scalar: indexed pass-ordered extraction, avoid rescanning all members. | S: archive order, weak/strong definitions and duplicate diagnostics. A global simultaneous fixed point must reproduce the original extraction policy, not just find some set of definitions. |
| Final layout, relocations, imports, output — [`link_native_executable`, `link_elf_index_initialize`, `link_objects`][LK] | Map: format-specific writers; import aliases and weak-symbol rules already shared. | W: relocation field arithmetic and range checks. A: independent patches into disjoint validated ranges. B: relocation/section class masks; prefix-sum sizes/alignments where composable. Scalar: exact counts, sparse indices and contiguous writes. | G: layout/relaxation; S: symbol binding, aliases, constructors, startup and stable section order. Concurrent overlapping patches are not safe. OS write/close and optional durability are outside SIMD compute and must remain in end-to-end time. |

This map deliberately distinguishes an opportunity to process pure facts in parallel from permission to change a phase's semantics. For example, greedy scheduling is not globally parallel under an identical decision policy, but scoring its ready population is; macro execution is ordered, but copying/classifying an already-expanded immutable run is not inherently serial.

## 4. CPU-resident execution model and cost vocabulary

Keep canonical IR and existing machine rows as the authoritative representations. A transient projection has one named producer, named consumers, a lifetime bounded by a function/query epoch, and an explicit invalidation event. It must not become a third graph IR, a shared mutable cache with implicit epochs, or a new general execution framework.

Use the existing persistent gang: SPMD across lanes, SIMD inside each lane, private function/TU scratch, stable work-indexed result slots, serial deterministic publication. Prewarm shared immutable tables before `lane_run`, publish readiness last, and use the same path at one lane and in single-threaded builds. Independent function tasks should normally expose more parallelism with less divergence than packing unrelated parser states into a vector. Do not nest unbounded per-function gangs beneath per-TU gangs; total runnable work and scratch memory need one owner.

A candidate tile size of 256 rows is an experimental starting point, not a hardware constant. Test 32/64/128/256/512 and include tiny populations that bypass tiling. A 16-byte logical SoA record at 256 rows occupies 4 KiB before other live arrays. AoSoA is useful when scalar consumers need several fields of the same item and vector consumers need one field across a small tile; a whole-program SoA conversion is not implied.

For a region with N useful items, use:

`T_batch = T_setup + T_classify + T_pack + T_kernel + T_gather + T_conflict + T_order + T_sync + T_cleanup`.

`T_kernel` must count actually executed lanes, not advertised width. Record `useful_lane_updates / executed_lane_slots`; distinguish tail lanes, semantic exclusions, and lanes stalled by long chains. Track both logical bytes and cache-line traffic: a nominal four-byte gather can cause a 64-byte line transfer. Packing trades extra stores/loads for better locality and instruction parallelism, not free bandwidth.

A useful lower-bound model is the maximum of execution-resource time, transferred bytes divided by sustainable bandwidth, and the dependency critical path, plus unhidden setup/publication. Do not add all those lower bounds as if they were independent observed stalls. Counters and paired wall time must determine which constraint is active.

Scans/reductions/compaction are tools, not compulsory passes. A segmented scan lets many independent runs share vector work while resetting state at segment heads. A scalar scan of a small array of tile totals is often cheaper than another lane barrier. Stable compaction needs a count/rank and a conflict-free destination; after compaction, original ordinals remain necessary wherever diagnostics, IDs or output order are observable. These are applications of prefix/segmented operations [R1, R2], not claims that an old machine's scan speed transfers to Zen 5.

## 5. Candidate A — post-SSA frozen-root, liveness, and stable ID remapping

### Boundary and current work

Own only the tail of [`c_ir_ssa_finish`][CG], **after** initialization classification, whole-owner memory restoration, forwarding and the current ordered trivial-parameter fixed point. Do not change predecessor discovery, representative selection or the active-block optimization from #497.

The inspected tail constructs `parameter_by_value`, marks every instruction result plus parameter roots reached from instruction operands, follows incoming values to find live parameters, prunes unmarked parameter cycles, publishes predecessors, performs three value-remap passes, creates a fresh operand pool, and rewrites incoming/local/label references. Existing counters already include `SSA_LIVE_WORK_VISITS`, `SSA_REMAP_VALUE_ROWS`, `SSA_REMAP_OPERAND_SLOTS`, `SSA_REMAP_INSTRUCTION_ROWS`, `SSA_REMAP_INCOMING_VISITS`, and scratch/clear bytes. The current remap census explicitly counts three V-sized value passes. Their cost at this pin is unknown.

### Proposed layout and algorithm

Let V be the old value count, I instruction count, E total operand slots including repeated/shared slices, and P the retained parameter population. Retain the existing u32 replacement/map storage and canonical pointer structures initially. Add only a temporary keep bitset, `8 * ceil(V/64)` bytes, when the bitset experiment is selected. Freeze representative lookup by applying the **existing** `c_ir_ssa_root` to existing representatives; do not choose smaller IDs or parallelize union decisions.

The keep set must reproduce the current seeds exactly. In particular, this is not general dead-code elimination: instruction results remain marked as today, and live parameter closure begins at actual instruction operands. Do not replace that policy with “keep only used roots” and inadvertently renumber output.

C-like pseudocode, using conceptual helpers rather than claiming new repository APIs:

```c
bool finish_remap(FinishView* view)
{
    bool valid = true;
    u32 v_count = view->old_value_count;
    u32* roots = view->existing_replacements;
    u32* map = view->existing_value_map;

    // Earlier ordered SSA decisions are complete. No concurrent mutation here.
    for (u32 v = 0; v < v_count; v += 1)
    {
        roots[v] = c_ir_ssa_root(roots, v);
    }

    // Same instruction-result seeds and incoming-parameter closure as today.
    build_exact_current_keep_set(view, roots, view->keep_bits);
    prune_parameters_in_original_order(view, view->keep_bits);
    publish_all_current_predecessors(view);

    u32 next = 0;
    for (u32 v = 0; v < v_count; v += 1)
    {
        bool keep = keep_bit(view->keep_bits, v);
        map[v] = keep ? next : UINT32_MAX;
        next += keep;
    }
    // First experiment retains ascending scalar in-place copying.
    for (u32 v = 0; v < v_count; v += 1)
    {
        if (roots[v] == v && keep_bit(view->keep_bits, v))
        {
            view->values[map[v]] = view->values[v];
        }
    }
    for (u32 v = 0; v < v_count; v += 1)
    {
        if (roots[v] != v)
        {
            map[v] = map[roots[v]];
        }
    }

    // Checked u64 lengths. Input slices may alias; destination is fresh.
    valid &= remap_to_fresh_operand_pool(view, map);
    valid &= remap_incoming_local_and_label_references(view, map);
    view->new_value_count = next;
    return valid;
}
```

For rank, each keep word contributes `popcount(word)`. Scan those counts to obtain each word's base, then enumerate set bits or vectorize dword ranks inside dense tiles. Do not perform an O(V log V) global scan when a linear scalar scan of V/64 counts suffices.

For operand remapping, a long contiguous slice admits bounded loads, map gathers and contiguous output directly. For many short slices, a temporary tile may pack IDs from several slices, then gather map values and write one contiguous destination region. A parallel variant first determines checked u64 per-row offsets, reads the immutable old operand storage, writes disjoint ranges of the already-required fresh pool, and publishes row pointers after completion. It must not remap shared old slices in place.

### Correctness and observable order

Freezing roots after the existing fixed point preserves its representatives. The keep closure is monotone over a fixed graph, so queue order may vary without changing membership, provided seeds and incoming relations are identical. Stable rank in ascending old-value order then reproduces the current map. Alias rows receive the map of the same root. Preserve invalid-map detection rather than manufacturing a replacement value.

**Parallel in-place value compaction is unsafe.** A destination written by one worker can overwrite another worker's unread source. Keep the current ascending scalar copy, or pay for a separate value array and barrier in a later experiment. The first slice does not pay that cost. A stable `map[v] <= v` argument justifies the scalar forward copy, not arbitrary concurrent execution.

Keep every reference consumer: instruction results/operands, parameter and incoming values, per-block local values, local places, label metadata and source/debug identities. The current use of a fresh dense operand pool exists precisely because old slices can be shared; it is a correctness boundary, not incidental allocation waste.

### Variants, break-even, and experiments

Compare: current tail; improved scalar with frozen roots and no new bitset; scalar bitset/rank; scalar-batched short-slice remap; AVX2 eight-dword and AVX-512 sixteen-dword remap. AVX2 packing may need permutation controls or scalar filling; AVX-512 compression is not necessary for a fully dense operand batch. Keep a scalar path for short slices and cold maps.

Let `c_s` be scalar time per remapped operand, `c_v` vector-kernel time per useful operand, `c_p` packing/restoration time, and H fixed tile setup. Batching breaks even only when `E_tile * (c_s - c_v - c_p) > H`; if the parenthesized term is nonpositive, no tile size wins. Root flattening separately wins only when removed repeated traversals exceed its one-time V scan. A new bitset must save clear/search traffic or useful instructions beyond its own writes, rank pass and tail handling. Do not credit elimination of existing scratch that the experiment still retains.

Use actual distributions of V, E, P, root depth, live density, slice lengths, shared slices and incoming fan-in. Include no-parameter functions, huge dead parameter cycles, irreducible joins, late memory restoration, vectors, narrow owners, labels, and values around 8/16/64-lane boundaries. Compare exact post-SSA snapshots before relying on executable identity. The potential win is source-verified regular work; the size of its end-to-end budget is unmeasured.

Independently reviewable slices: A1, account for the existing tail using its counters and exact snapshots; A2, an improved scalar frozen-root/remap experiment; A3, one bounded operand kernel through `simd.h`; A4, only if warranted, disjoint-pool lane execution. A2 must stand alone; A3 does not require A4, a new SSA algorithm, or a persistent adjacency graph.

## 6. Candidate B — canonical check tiles with unchanged validation semantics

### Boundary and prerequisites

This is a **future implementation hypothesis**, not completion or expansion of #564. First consume #576's per-family work and cost evidence. It is entirely valid for that evidence to conclude that no change is justified.

Retain all current validation configurations, producer-certificate rules, ownership requirements and malformed-input behavior. `ir_validate_module_ownership` preflights lowered-function storage and published CFG, then proves ownership across functions before later instruction walks can trust their chains. That proof must not disappear because a regular opcode population is easy to classify.

The initial implementation boundary is a small, common family of independent value/instruction shape checks after its existing prerequisites. Global validation, ownership, rare operations, provenance, calls and complex type relations remain authoritative scalar checks unless independently and completely covered. Do not reinterpret two different proofs over the same instruction as redundant merely because both visit it.

### Layout and pseudocode

A bounded tile can project `instruction_id`, `type_id`, `result_id`, `operand_count`, and `opcode` as u32 planes. Five planes at 256 rows cost 5 KiB; adding block/order information or operand facts has an explicit incremental cost. A producer should fill this during an already-required traversal where practical. A separate full-module transpose is the wrong default.

Every pointer/ID-dependent operation needs a prerequisite mask. Merely masking a final comparison does not make an earlier invalid gather safe. Counts, required storage, IDs and arithmetic bounds must be checked before the accesses they justify. An unsupported shape is a scalar case, not a validation success.

```c
IrValidationResult validate_with_tiles(IrProgram* program, IrModule* module)
{
    IrValidationResult result;
    bool use_reference = !safe_existing_prefix(program, module);

    // Conceptual decomposition: preserve the original prefix/check order.
    // No user-visible diagnostics or durable certificates are published here.
    for_each_existing_ordered_tile(program, module)
    {
        if (!use_reference)
        {
            CheckTile tile = project_proven_safe_fields();
            Mask64 eligible = classify_supported_check_family(tile);
            Mask64 bad = check_bounds_without_dereference(tile, eligible);
            if (!bad)
            {
                bad = check_guarded_type_and_operation_facts(tile, eligible);
            }
            use_reference |= bad != 0;
            use_reference |= !run_remaining_exact_scalar_checks(tile, eligible);
        }
    }
    if (use_reference)
    {
        // Cold path: same original validator, from its original entry.
        result = reference_validate_canonical_module(program, module);
    }
    else
    {
        result = exact_original_success_result();
    }
    return result;
}
```

This is C-like algorithm notation, not a proposed callback API or a drop-in implementation. The reference entry is the unchanged validator factored so the optimized path cannot recursively call itself. `safe_existing_prefix` must preserve the current prefix, not invent a weaker preflight. A practical first patch may be much smaller: tile one value-family loop and keep all other loops intact.

### Error identity, dependencies, and malformed inputs

A failure in a tile is not directly reported out of SIMD order. The simplest exact diagnostic design is to rerun the unchanged validator from its original entry whenever the speculative regular path detects a fault. Thus the original validator still chooses the earliest error across module checks, functions, blocks, linked instruction order and nested checks. It also constructs the exact original result fields.

This avoids assuming that minimum instruction ID means first error; linked order can differ from physical row order. A later direct-error optimization would require an explicit lexicographic ordinal for phase, function, traversal position and check order. It should not be included in the first patch merely to avoid a cold replay.

The speculative pass must be observationally read-only and bounded. It cannot emit diagnostics, alter certificates, follow an unproven cycle, read invalid operands, or update state the reference validator sees. Failure replay adds work on malformed input; report its cost and bound it. Testing only valid self-host input would miss the most important part of the contract.

For equal type IDs, equality may be a fast positive relation where the existing check permits it. Distinct IDs must follow the actual compatibility/representation rule; current vector alias behavior makes “different ID means incompatible” unsafe. Conversion checks retain signedness, width, pointer-width and floating representation requirements.

### Strong scalar alternatives and acceptance

First compare fused scalar checks with cached immutable type facts, cheap range tests before expensive lookups, and sparse handling of rare opcode families. The nested relocation overlap check in `ir_validate_global` is a separate example of an algorithmic alternative: sort a private array of checked intervals, use a prefix maximum end to detect overlap, retain original ordinals for error selection, and never reorder the canonical relocations. That could beat a vectorized quadratic, but no census here establishes enough relocations to justify even sorting.

For a tiled family, let p be its fraction of *exclusive validation time*, q its eligible fraction, s its kernel speedup, and h the projection/fallback/publication cost as a fraction of validation time. Then `T'_validation / T_validation = 1 - p*q*(1 - 1/s) + h`. A twofold common-check kernel with a small p cannot halve validation. The historical 8.6% is not a current value for the end-to-end multiplier.

Compare current, fused scalar, scalar-tiled, AVX2 and AVX-512 using identical checks. Record actual checks/row, eligible rows, repeated type accesses, row-order distribution, storage preflight work, gather line misses, tile fill and fault replay count. Test tiny modules, no lowered functions, declaration-only modules, invalid IDs/storage counts, cycles/shared chains, unreachable blocks, globals/relocations, every conversion family, label provenance, calls, and multiple simultaneous faults in deliberately shuffled storage order. Require exact error and result-field agreement.

Review boundaries: B0 is the independently owned #564/#576 measurement, not this report's implementation; B1 selects one measured family and adds an exact scalar oracle seam in the existing test module; B2 improves the scalar loop; B3 adds one guarded SIMD tile. Do not change which builds validate, pass certification, or the canonical model. No global checker rewrite is needed to test one useful family.

## 7. Candidate C — consumer-owned operand batches after scalar fusion

### Start with the competing implementation, not the old problem

[#132][I132] asks about repeated selector operand walks. [Merged #375][P375] already removed one by accumulating AArch64 direct-call facts during the existing authoritative operand walk. That proves a critical alternative: **the best projection can be no new projection at all**.

At this pin, enumerate remaining consumers and the fields they actually read before adding storage. The existence of an open umbrella issue does not prove multiple remaining passes need the same population. If eligible consumers can all be fused into one scalar traversal, retain that result and reject this stream experiment. Existing type classes, candidate lists, signature plans and address memoization are not missing infrastructure.

### A concrete bounded representation

For a real residual shared population, use at most a tile of logical records:

```c
#define OPERAND_TILE_CAPACITY 256

typedef struct OperandTile OperandTile;
struct OperandTile
{
    u32 value[OPERAND_TILE_CAPACITY];
    u32 row[OPERAND_TILE_CAPACITY];
    u32 slot[OPERAND_TILE_CAPACITY];
    u32 facts[OPERAND_TILE_CAPACITY];
    u32 count;
};
```

The payload is 16 bytes per operand, 4 KiB at 256, plus count/alignment. `row` names the canonical instruction and stable traversal order is separately respected by the producer; do not assume physical row numbering is target order. **The operand slot is u32, not u8.** The older issue's illustrative u8 index must not become an accidental 255-argument limit. When a consumer does not need row or slot, omit that plane rather than fill it speculatively.

Build in existing target-order traversal, after canonical safety prerequisites. Use the existing compact type class table; do not copy full types or addresses into another permanent graph. Tile consumers must be pure queries or reductions whose state transition is proven compatible with batching. The main target-selection switch and MIR publication remain ordered and unchanged.

```c
void consume_operand_tile(SelectorFacts* state, OperandTile const* tile)
{
    for (u32 first = 0; first < tile->count; first += kernel_width())
    {
        u32 lanes = min_u32(kernel_width(), tile->count - first);
        Batch batch = load_valid_operand_planes(tile, first, lanes);
        Masks masks = classify_consumed_roles(batch);
        // Read-only queries use already-validated IDs and immutable type facts.
        BatchResult facts = evaluate_requested_facts(state, batch, masks);
        // First experiment serializes updates that can name the same value.
        for (u32 lane = 0; lane < lanes; lane += 1)
        {
            reduce_one_original_ordered_fact(state, batch, facts, lane);
        }
    }
}
```

Again these are conceptual helpers, not a new dispatch framework. Real code uses direct functions and the existing `simd.h` vocabulary. Width selection is outside the inner loop in an implementation; the notation compares scalar, eight-dword and sixteen-dword forms.

One concrete reduction shape is direct-call use classification: each occurrence contributes “matching direct callee” and/or “other use” after the existing definition/call symbol-identity check. Two Boolean summary bits form an associative OR reduction; convert that summary back to the existing scalar state representation. “Other” remains absorbing. Preserve the actual incoming-edge policy. This example explains what can be batched, **not a proposal to recreate #375's removed scan**.

### Conflicts and order

Different lanes frequently reference the same value. A gather/update/scatter sequence loses updates even when every address is valid. The initial variant keeps per-value updates scalar in original occurrence order. A later stable grouping can reduce duplicate value IDs, but must pay classification, grouping, scratch and output restoration. AVX-512 conflict detection identifies conflicts; it does not make the reduction atomic or decide the required winner.

Only proven commutative reductions may ignore occurrence order. First-use/last-use identity, diagnostics, synthesis of IDs, calls and target selection retain original ordinals. Partitioning by opcode or role does not authorize reordering the emitted program. Per-function scratch is private; no locks or global atomics are necessary for independent functions.

Address/provenance facts retain exact canonical identity and existing cache invalidation. Do not infer alias freedom from equal roots or offsets. If a consumer needs a fact produced by another consumer in the same traversal, either fuse that dependency inside the tile in the same order or keep the consumer scalar; a shared array is not proof of independence.

### Break-even and experiments

Let k be the number of genuinely remaining consumers, I canonical rows visited, E operand occurrences, `B_walk` the measured effective bytes/cycles of a row/operand traversal, and `B_fact` the compact bytes each consumer needs. A rough traffic comparison is:

`removed repeated traversal traffic - projection writes - projected reads - extra gathers - grouping/restoration traffic`.

Do not replace it with `(k - 1) * sizeof(IrInstruction) * E`: rows and operands have different populations, cache hits matter, and some consumers are sparse. With a full 16-byte record, projection alone can write 16E and subsequent complete consumers read up to 16kE. A fused scalar traversal with zero projection can easily win. Cache-resident tiling reduces retention and often traffic, but does not erase packing instructions.

Time breaks even only if the removed traversals plus vector work savings exceed setup, plane packing, per-value updates and cleanup. At k=1, demand a demonstrated kernel gain large enough to repay packing; do not claim amortization across nonexistent consumers. If scattered value maps miss cache, SIMD arithmetic width may be irrelevant.

Compare current source, fully fused scalar, scalar tiled with only consumed planes, AVX2, and AVX-512. Measure per-consumer visits, short/long operand distributions, value-ID duplicate rate, gather locality, unsupported shapes, scratch high-water and exact selected rows. Include no-call functions, many arguments beyond 255, repeated callees, escaping/indirect uses in both orders, linked order different from dense storage, vectors, block parameters and both native targets. Byte-compare machine rows and every consumed side table; preserve checked/prevalidated entry agreement and fallback reason counts.

Review boundaries: C1 is a consumer census and another no-allocation fusion only if a real remaining traversal exists; C2 is one private tile shared by named read-only consumers; C3 adds the simplest profitable vector classifier. A whole-function stream, persistent selector IR, new matcher, new allocator policy, or address-analysis rewrite is outside this candidate.

## 8. Cross-cutting scalar, bitset, AVX2, and AVX-512 comparison

| Form | Where it can win | Costs that must be included | Rejection condition |
|---|---|---|---|
| Current implementation | Tiny inputs, predictable scalar state, existing mature mask kernels | Existing repeated visits and allocations are measured, not assumed | It remains the default unless a candidate improves the full contract. |
| Improved scalar/bitset | Eliminating queries, sparse queues, 64-way membership, stable rank, direct table lookup | Bitset clearing, index construction, population density, mutation invalidation | A dense bitmap or full scan costs more than touched IDs or a short list. |
| Scalar-batched | Exposes independent loads, shares classification, amortizes setup and improves locality without ISA requirements | Tile stores/loads, extra loop nesting, order restoration, working-set growth | One fused scalar walk is cheaper, or tiles introduce latency without reuse. |
| AVX2 | Eight u32 lanes, common compares/arithmetic, interleaved probes and dense remaps | Tail handling, movemask conversion, compaction permutation/control costs, gather misses | Packing and low occupancy consume all arithmetic savings. |
| AVX-512 | Sixteen u32 lanes, mask-valued predicates, masked tails, dword compression and Boolean fusion | Exact feature subset, gathers, compress form, register pressure, stores and whole-kernel frequency/throughput | Wider code is slower on a required host, spills, or only improves a microbenchmark. |

[The Intel Intrinsics Guide][R4] distinguishes AVX-512F, BW, CD, VBMI2 and other subsets; “AVX-512” is not a sufficient feature guard. Dword compression and byte/word compression have different feature requirements. AVX2 has no direct equivalent of AVX-512 mask compression; compare scalar filling and permutation-based packing rather than silently assuming a native compress instruction. A masked instruction's semantics do not legalize unrelated earlier C accesses. Inspect actual generated code and the exact instruction forms selected.

[AMD's Zen 5 optimization-guide entry][R5] was consulted as the vendor documentation starting point. No instruction throughput table was extracted from it here, and no blanket “every 512-bit kernel is twice as fast” claim follows. Price the complete kernel on physical Zen 5 and check Zen 4 separately. In particular, gather locality, store throughput, dependency chains and pressure can defeat width gains. The repository's SIMD interface remains the implementation boundary; any genuinely missing primitive requires the existing builtin/IR-shape/validation/lowering/fallback/test chain, not direct vendor intrinsics scattered through compiler code.

Small cache-resident columnar batches are also a useful architectural analogy to [MonetDB/X100][R3]: avoid both per-tuple interpretation and uncontrolled whole-column materialization. The transferable idea is bounded batching. Database execution results are not evidence of a compiler speedup, and no database framework or dependency is proposed.

## 9. Combined end-to-end model and bottleneck migration

Choose **disjoint** measured regions: A is the selected post-SSA tail, B the selected validation families after retained prerequisites, C the remaining selector-query work. Never use all lowering for A, all preparation for B, or the predicate-placement wrapper for C.

Let `f_A`, `f_B`, `f_C` be their fractions of one frozen baseline's elapsed time, `s_A`, `s_B`, `s_C` their local speedups, and h additional costs not already included in those local measurements. Then:

`T_new / T_old = 1 - f_A*(1 - 1/s_A) - f_B*(1 - 1/s_B) - f_C*(1 - 1/s_C) + h`.

Do not multiply three standalone whole-compiler speedups, and do not add h twice when per-region timings already include packing. Re-measure the combined build: shared cache capacity, scratch lifetime and instruction-cache interactions can make even disjoint algorithms interact.

For sensitivity only, **not a forecast**, suppose the eligible disjoint regions are 4%, 6%, and 5%, local speedups are 2, 1.5, and 1.5, and new global overhead is 0.5% of the original compile. The ratio is approximately 0.9483, or about 1.0545 times throughput at fixed work: roughly 5.45%, not 2 x 1.5 x 1.5 = 4.5 times. At infinite local speed and zero new cost those assumed regions cap the improvement at `1/0.85`, about 1.1765. All assumed shares and speedups in this paragraph require measurement.

The historical phase shares identify likely migration, not a current budget: after SSA/query/check improvements, preprocessing, semantic layout/typing, global initializer work, encoding, metadata, linking, startup or page faults can become dominant. Within A, root traversal can give way to pool writes; within B, regular comparisons to ownership or call/provenance checks; within C, classification to random value-table access or serial MIR publication. The next change should follow that new profile, not repeat the old ranking.

Single-file latency additionally contains the critical path through ordered preprocessing, shared declaration publication and the largest function. Bulk throughput instead approaches the minimum of useful compute capacity, memory bandwidth and output capacity, subject to lane imbalance and barriers. Summing function times is not a parallel elapsed-time model; use the slowest lane's assigned work plus shared phases and merges. Increasing lanes can increase total RSS enough to lose cache locality or induce paging. Pin one benchmark job per reserved host region; do not oversubscribe a dedicated performance run with other agents.
