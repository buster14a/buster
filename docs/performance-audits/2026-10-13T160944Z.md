## Method

`process_floor_acceptance.py` wrote `int main(void){return 0;}` as `tiny.c`
alone in a directory and ran `uarch_lab.py compare --process-floor-pair CELL`
there for three cells, with the one candidate binary as A and B. A is always
`ide cc -g0 -c tiny.c -o OUT` (x86-64 object). B is the same command (`aa`),
`-target aarch64-unknown-linux -c` (`aarch64`) or `-fsyntax-only`
(`syntax-only`). Each cell is 100 ABBA pairs after two warmups; every timed
run executes a fresh copy of the binary under `taskset -c 2 perf stat`.

Three times are recorded per run:

- **wall**: the harness span from spawn to `wait4`, which includes `taskset`,
  `perf stat` and process start;
- **task-clock**: perf's CPU time of the `ide` process;
- **compiler `wall_ns`**: the compiler's own clock from its `-fmetrics-out`
  record.

`uarch_lab` adds `-fmetrics-out` to every timed compile. Under it the driver
runs `compiler_prewarm`, `codegen_prewarm_for_target` and arena priming as
setup before the first input, for every action (driver.md, "Setup stays
outside every input"). Absolute values below therefore include that setup;
only differences between cells are claims.

Medians over 100 pairs; ratios are B/A with the 95% sign-test CI.

| Cell (B) | Wall A / B ms | Task-clock A / B ms | Compiler `wall_ns` A / B ms | Instructions:u A / B | Wall B/A [95% CI] |
|---|---:|---:|---:|---:|---|
| `aa` (same command) | 9.712 / 9.635 | 4.030 / 4.010 | 3.268 / 3.252 | 8,830,164 / 8,830,273 | 0.9944 [0.9865, 1.0027] |
| `aarch64` | 9.608 / 7.798 | 3.980 / 2.250 | 3.223 / 1.486 | 8,830,589 / 2,221,563 | 0.8135 [0.8039, 0.8199] |
| `syntax-only` (**invalid**, below) | 9.643 / 9.328 | 4.020 / 3.740 | 3.256 / 2.952 | 8,830,852 / 8,682,463 | 0.9659 [0.9576, 0.9710] |

The A/A objects were byte-identical and diagnostics were identical in every
cell. Peak RSS is NA in the AArch64 and syntax-only cells because those runs
stay within 1.5 times the wrapper's own footprint.

**The x86-64 floor, against the AArch64 control.** An x86-64 object compile
of the tiny unit costs, per process, more than the same compile for AArch64:

| Measure | x86-64 − AArch64 | Share of the x86-64 compile |
|---|---:|---:|
| Compiler `wall_ns` | 1.737 ms | 54% |
| Task-clock | 1.730 ms | 43% |
| Wall (harness span) | 1.811 ms | 19% |
| Instructions:u | 6,609,026 | 75% |

Its wall ratio CI [0.8039, 0.8199] lies wholly below the A/A interval
[0.9865, 1.0027], so #1125's stop rule does not apply: the floor is real on
the 9700X. The per-run metrics place it before the input starts. In pair 50,
`start_ns` was 2.42 ms for x86-64 and 0.74 ms for AArch64, while each input's
own `total_ns` was 0.82 ms and 0.81 ms.

**The `-fsyntax-only` control is invalid (#4135).** Metrics-mode setup
prewarmed the x86-64 codegen target for the B side too, which a plain
`-fsyntax-only` never does. Its `start_ns` (2.46 ms in pair 50) matches the
x86-64 object compile's. Callgrind on the `x86-64-v3` build of the same
source shows the distortion directly:

| `ide cc -g0 …` | Plain Ir | With `-fmetrics-out` Ir |
|---|---:|---:|
| `-fsyntax-only tiny.c` | 2,801,620 | 21,387,829 |
| `-E tiny.c` | 2,748,812 | 21,309,379 |
| `-c tiny.c` (x86-64) | 10,552,490 | 21,549,134 |
| `-target aarch64-unknown-linux -c tiny.c` | 2,904,792 | 13,901,539 |

The x86-64 − AArch64 difference is 7,647,698 Ir plain and 7,647,595 Ir with
metrics, which is why the AArch64 control stands. Without metrics,
`-fsyntax-only` costs slightly less than the AArch64 object compile and does
not pay the x86-64 floor; that is a callgrind count, not a 9700X measurement.

## Disposition

The remaining floor is 1.74 ms of the compiler's own time per x86-64
process, more than half of this compile's. It is paid once per process, so
one-process-per-translation-unit workloads pay it for every unit; at 1.73 ms
of task-clock, the 1,349-unit musl harness would spend about 2.3 s of CPU on
it per pass (arithmetic, not measured). It justifies further work. The
remaining components are the exact prewarm and the metadata decode and
prewarm; open work that addresses them is #3584 (opcode rows on first lookup)
and #1295 (immutable x86 tables on demand).

## Limits

- One run attempt on one host. The harness wall includes the perf wrapper,
  so wall ratios understate the compiler's own share; task-clock and
  `wall_ns` give the compiler-only view.
- Every timed run carried `-fmetrics-out`; absolute medians include its
  setup. A `-fsyntax-only` control needs a fixed profile or driver change
  (#4135) and a new run.
- The callgrind build differs from the measured one: x86-64-v3 instead of
  native, tests on, Clang 18 instead of 23. Its counts attribute; they do
  not time.
