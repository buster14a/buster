## Workload

Every arm compiles the same input, the base revision's unity self-host source,
from the base checkout:

```sh
ide cc -Isrc -Ibuild/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -c \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

There are four arms, counted with Callgrind (`--cache-sim=no --branch-sim=no`):
- A: base, default flags;
- B: base with `-fc-ast-pilot`;
- C: candidate with `-fc-ast-pilot`;
- D: candidate, default flags.

The objects were also built at `-g` with each arm's binary, outside Callgrind.

## Census (base, default flags)

After #3916, `c_gen.c` held two spelling-form type-word tests outside
reference checks. A throwaway census build of the base routed each through a
noinline `census_type_word`, which asked both the spelling ladder and
`c_parse_type_word_for_dialect_token` and called empty noinline marker
functions per category. Callgrind's call counts read the markers. Its `-g0`
object is byte-identical to A's. The instrumentation is not product code; its
patch and the script that wrote it are kept in the evidence bundle.

| Site | Reached from | Calls | True | Predefined symbol | No symbol | Token form disagrees |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 1, `c_ir_type_name_prefix` | `c_ir_query_execute` (inlined), 48,306; its recursive frame, 9 | 48,315 | 3,571 | 24,855 | 0 | 0 |
| 2, `c_ir_statement_expression_tail` | — | 0 | — | — | — | — |

- **Site 1 is the lead.** In A, `c_ir_query_execute` calls
  `c_parse_type_word_for_dialect` 48,306 times for 4,973,114 Ir, and its
  recursive frame 9 times for 1,386 Ir: about 103 Ir a call. It tests a type
  name's first specifier token that no entity binds, before the scope lookup.
- **Site 2 is not reached.** The unity input has no statement expression, as
  audit [`2026-10-12T213925Z`](2026-10-12T213925Z.md) found. It is swapped for
  exactness, not for its count.
- **The token form agrees.** `c_parse_type_word_for_dialect_token` answered all
  48,315 calls exactly as the spelling ladder did; the mismatch marker is never
  called. It reads the symbol's `word_bits`, which `c_parse_word_bits_compute`
  derives from the same spelling predicates, and every specifier spelling is
  interned in the predefined range. A token without a symbol falls back to the
  spelling compute.

## Validation and limits

- Callgrind counts instructions, not time, on `-march=x86-64-v3` builds whose
  AVX-512 kernels are compiled out.
- One input, one host, single process, no pinning and no `perf` counters. Wall
  time was not measured: the budgets did not ask for it, and on this host it
  cannot resolve an effect of this size.
- **Site 2 has no runtime coverage on the unity input.** Its reference check
  runs only when a statement expression's type is predicted (a `?:` arm,
  `__typeof__`, `sizeof`). The Debug probe `stmt_expr_probe.c` exercises it.
- **A pre-existing defect surfaced while probing.** A comma expression as the
  middle operand of `?:` in an initializer (`int e = x ? g(), 1 : 0;`) fails
  to lower on the base too. It is unrelated to this change and is filed as
  [#4003](https://github.com/buster14a/buster/issues/4003).
- **Not run:** the sanitizer tree, `test_mode_matrix` and a mutation of the
  reference checks.
- **Census build:** its counts come from an instrumented copy of the base
  (`census.patch` in the bundle), and its object matches A's.
