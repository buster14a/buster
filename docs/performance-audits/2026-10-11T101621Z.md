## The census

The census patch changes no answer. It records:
- **Every `c_parse_add_qualified_type` call while the interning window is
  open.** For each call it records:
  - the call site: the postfix member step, a subscript of a qualified array
    (in `c_parse_direct_expression_postfix` or in the machine's subscript
    task), `__real__`/`__imag__`, a conditional, or any other caller;
  - whether a bit-field-width probe made it
    (`c_parse_expression_bit_field_width`);
  - the kind of the copied row;
  - whether it would inherit an alignment record, or is restrict or atomic;
  - whether an equal live row, compared field by field, was appended
    earlier: in an earlier body or initializer, earlier in the same one, or
    never.
- **Every top-level machine run from a query while the window is open.**
  Per run it records the token range, whether the query was checked, the
  copies it appended, the memo hits and tasks of its operator scan, and a
  class:
  - 0: no qualified copy;
  - 1: every copy repeats a row from an earlier body or initializer;
  - 2: some copy is new to the body ("late");
  - 3: some copy carries an alignment record, or is restrict or atomic.

  A second pass reads the first pass's classes and routes each run through
  its own no-inline wrapper, so Callgrind charges each class inclusive Ir.

There are 9,340 top-level runs with at least one copy:
- 6,933 append one copy;
- 2,407 append more, 6,903 copies in all: 1,613 append two, 347 three,

- **Memo hits.** 881 runs read a sub-range from the per-body memo partway

## The prototype

The prototype implements option (b) of the design note:
- **The machine side.** While the window is open and not suspended, the
  postfix member step calls `c_parse_intern_qualified_type` instead of
  `c_parse_add_qualified_type`. That returns the live row equal, field by
  field, to the copy it would append.
  - It keeps its own log and slot table, beside the primitive and pointer
    ones. Its live count is checkpointed in `CParseResult`, beside
    `interned_type_count`.
  - A copy that would inherit an alignment record, or that is restrict or
    atomic, is appended as before.
- **The typer side.** `c_ast_types_member` accepts `.` and `->` over a const
  or volatile struct or union. The answer is the copy the machine would
  return, looked up without minting it. When that copy does not exist yet,
  the node declines, so the typer adds no late-row re-check.

## Reading

- **Interning (b) is worth more than the census ceiling suggested.** The
  ceiling of about 49.9 M in `2026-10-11T093336Z` counted only machine Ir
  removed. Sharing the copies also shrinks the table, and the whole-table
  layout solves fall by about 39 M. That half needs no typer change at all.
- **Exact replay (a) loses on both counts.** It would keep all 13,836 copies,
  so the layout saving disappears. It would also have to reproduce the memo-,
  flag- and probe-dependent append order measured above, at about 392 Ir per
  replayed append plus a memo probe per task (4.1 tasks per run).
- **The late rows stay with the machine.** 1,679 runs (9.68 M) need a copy
  that is first made in their own body. They are below #3384's measured
  code-layout noise floor, and the design leaves them alone.
- **Scope.** Subscripts of qualified arrays (515 copies) and the other
  callers (278) were left out of the prototype. They are a possible later
  extension under the same rules.

Performance validation is incomplete (#2761). These are hosted Callgrind
counts and one throwaway prototype, and no 9700X evidence exists for them.
