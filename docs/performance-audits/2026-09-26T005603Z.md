## Decision

**No production change is justified by this experiment.** A broad source and ownership screen found several consequential opportunities, but the strongest were already tracked. The novel interaction selected for a causal experiment was whether the all-type-sized, mostly unwritten scratch allocation in `c_ir_promoted_member_path` raises the arena's conservative dirty boundary and thereby makes later consumers clear substantial otherwise-clean storage.

The observed interaction does not justify a repair:

- In twelve geometric synthetic subjects, the first query raised the dirty boundary; the next 63 queries, when present, did not. Every subject recorded only **512 bytes of explicit clearing through the arena zeroed-allocation API**.
- Removing the queries entirely, while keeping the declarations and the same constant result, produced **identical objects in all twelve pairs**. Arena zero-written bytes and their sole contributing call site were unchanged: the same 512-byte object-symbol index clear remained.
- The compiler's own unity source reached **22,941 queries**, requesting **47,823,194,688 logical bytes**, without one of these allocations increasing the incoming dirty boundary. Both compiler variants subsequently refused code generation at `xgetbv`; this is a lowering observation from an unsuccessful full compile, not passing self-host evidence.

This is a bounded negative result, not proof that scratch capacity has no cost, that every workload behaves this way, or that no valuable undiscovered change exists. The requested-byte sum is not bytes written, live storage, RSS, memory traffic, or time saved. No throughput or performance acceptance measurement was performed.

## Scout decisions: distinct mechanisms, not a subsystem-first search

These are investigation-time decisions, not a second issue-status dashboard. Source checks used the pin above. Historical measurements below are leads from their owners, not new measurements or current performance claims.

### 1. Unnecessary population: FAST stack-slot liveness

**Producer / consumer / reach:** frame-slot classification and `machine_fast_close_live_ranges` produce dense liveness for the slot population; `machine_fast_color_slots` consumes ranges only for non-fixed, touched slots. Current `register_allocator_fast.c` around lines 2113-2140 and 3203-3260 still contains that distinction. Large functions with escaping aggregates and the unity compile reach this path.

**Mechanism and value:** omit facts the sole colorer does not consume, rather than merely speeding up the same full population. The strongest alternative is that discarded-looking ranges affect layout elsewhere; checking all consumers and comparing shareable-slot ranges is the cheapest falsifier. Source evidence is strong, but affected population and end-to-end value require representative measurements.

**Disposition:** already #1296 and active PR #1320, not a discovery from this session. Reviewed PR head `908a9c906a960130b7b3f7b50f19c2bff8aff3ff` and its comments. Another comment also reserves a distinct killed-delta notification experiment. Neither implementation nor solver was edited. The owner still owes the matched 9700X measurement; this report does not certify current-head CI.

### 2. Per-invocation unnecessary work: eager x86 preparation

**Producer / consumer / reach:** `codegen_prewarm_for_target` and the exact x86 prewarm prepare immutable shapes and encoding tables; small x86 compilations consume only a subset. The current prewarm and the separate complete-before-`lane_run` contract were checked in `codegen.c`, `machine_x86_64.c` and the driver.

**Mechanism and value:** first-use serial resolution could eliminate work for unused entries. The strongest alternative is that work is merely delayed, or races are introduced when a gang first uses an entry. A whole-invocation used/prepared census plus fresh-process versus fully-prepared output equivalence is the cheap discriminating test; complete gang prewarm remains mandatory.

**Disposition:** #1295 and draft PR #1317 already own the first shape-cache slice. Reviewed head `0ac8a64c57b467133ab73ed0bd8eb9f2ccb09896`; the issue's earlier statement that no PR exists is stale. Remaining table opportunities are not new findings here, and #124 has separate GPR preparation ownership. No generated metadata or prewarm code was edited.

### 3. Algorithmic amplification: emitted-to-canonical debug join

**Producer / consumer / reach:** emitted `DebugFunctionSeed` rows follow code layout; canonical module functions retain declaration order. `debug.c:613-663` joins each seed to its canonical function by symbol using a repeated scan. Debug-enabled many-function translation units reach it; debug-disabled invocations are a control.

**Mechanism and value:** an index could replace the emitted-count by module-count search. The strongest alternative is that tiny populations make index construction more expensive, or that a naive positional join assigns another function's locals. Count actual comparisons first, then preserve symbol matching and compare debug output. This is source-supported scaling potential, not a timing finding.

**Disposition:** already #987. The current source comment explicitly prohibits assuming the two orders match. No competing patch or issue was created.

### 4. Wasted parallelism / structural boundary: function-body lowering

**Producer / consumer / reach:** ordered C function-body lowering publishes canonical types, symbols, literals and globals used by subsequent bodies and the backend. A safe independent boundary could help large single-TU workloads without changing canonical IR.

**Mechanism and value:** isolate genuinely independent body work within the existing lanes. The strongest alternative is a hidden dependency on earlier publication or a write to a supposedly read-only cache; zero appends alone do not establish independence. The cheapest decisive test is a read/write publication-closure inventory, not an immediate parallel prototype.

**Disposition:** already #531. The relevant audits include `2026-09-25T002813Z.md`, whose frozen-prefix/zero-append experiment supplies counterexamples to the minimal boundary. Current source still publishes shared state. Historical fractions and old direct-SSH timings were not adopted as acceptance evidence. This remained the higher-upside, lower-confidence frontier, but no credible new boundary was established and no lane or lifetime contract was changed.

### 5. Lost semantic information: LLVM TLS handoff

**Producer / consumer / reach:** canonical global/symbol TLS flags feed the LLVM global record for definitions and declarations. Losing the flag could miscompile thread-local globals across every exported use.

**Cheapest falsifier and result:** source inspection found that `llvm_bc_add_global_entity` combines `(global && global->is_thread_local) || symbol->is_thread_local` at `bitcode.c:1485`, and module emission writes the TLS operand around line 4305. This rejects the specific omitted-flag hypothesis. It does not establish correctness of all TLS models or linkers. No new TLS execution or issue was produced.

### 6. Semantic context / unrelated scout: include identity versus spelling

**Producer / consumer / reach:** file identity deduplicates physical files, while nested quoted includes and `include_next` require the current spelling-specific path and search origin. Aliased header paths could expose a lost-context error.

**Cheapest falsifier and result:** `c_source.c` keeps the resolved include path and origin on each source frame; resolution consumes that frame path rather than substituting the first file-identity spelling. Relevant paths are `c_include_resolve` around 7390-7470 and include-frame construction around 8974-9074. This rejects the proposed missing-context explanation in source. No filesystem matrix was executed, so this is not a universal symlink or preprocessor correctness claim. This unrelated source scout continued while the scratch experiment ran.

### 7. Cross-consumer work amplification: scratch dirty boundary

**Producer / consumer / reach:** `c_ir_promoted_member_path` reserves one work entry per canonical type but visits a small reachable aggregate graph; scratch rewind preserves the allocation high-water mark. Subsequent dirty-aware zeroed allocations on the same arena could then clear the unwritten suffix. Member-type queries, including `sizeof(object.member)`, and the compiler's unity source reach the producer.

**Mechanism and value:** reduce unnecessary capacity so that future consumers do not pay to clear it. If significant, this would remove downstream work rather than optimize the already-cheap duplicate comparisons. The strongest alternative is that another producer already dirtied the entire range, or that no later zeroing consumer overlaps it. The first falsifier is an incoming-versus-outgoing dirty-boundary trace; the second is consumer zero-written counts with query-removal controls.

**Novelty:** this is not #1103's duplicate-membership algorithm, not its already-removed full visited clear, not #1297's parse-side type-table work, and not #525's source-range initialization. The new causal link, not the historical requested-byte total, justified a bounded experiment. Its observed value was then rejected.

The initial evidence-backed leader was the discarded liveness population; the higher-uncertainty upside leader was a safe single-TU lowering boundary. Ownership and the existing frozen-boundary counterexamples prevented calling either a new opportunity or starting overlapping writes.

## Source deduction behind the scratch experiment

At `c_gen.c:25787`, `c_ir_promoted_member_path` takes capacity from `builder->program->types.count`, obtains scratch excluding the temporary arena, and calls ordinary `arena_allocate`. This is uninitialized allocation, not a full-capacity clear.

`arena_dirty_position` (`arena.c:125`) is the maximum of the live cursor and retained dirty boundary. Rewinds (`arena.c:145-158`, reached through `scratch_end`) fold the old cursor into that boundary. `arena_allocate_zeroed_bytes` (`arena.h:220-229`) explicitly clears only the overlap between its allocation and the incoming dirty prefix.

Consequently an allocation can extend the conservative dirty prefix only when its end exceeds the incoming boundary. A trace with no such events rules out this producer extending that prefix during the observed execution. One event does not establish that another consumer subsequently clears any additional bytes.

The observer recorded the incoming dirty boundary, incoming cursor, allocation end, capacity and requested bytes. Logging used libc `fprintf(stderr, ...)`, not Buster's scratch-backed formatter. The existing allocation recorder is allocation-free. Baseline/observer output controls test that this diagnostic overlay did not alter emitted objects on the passing population; they do not convert an instrumented build into a timing baseline.
