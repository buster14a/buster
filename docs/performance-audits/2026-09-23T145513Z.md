## The lowering entry point, as structured today

`c_lower_to_ir_with_options` (`c_gen.c` 47893–50667) has three regions:

1. **Serial preamble** (47905–50129): token census, capacity sizing, scope
   child index and token position index (`c_parse_index_scope_children`
   47943, `c_parse_position_index_ensure` 47947), IR program/module
   creation, global assembly, scalar types, `c_type_ir_map` seeding, the
   two-round type-mapping worklist (48387–…), incomplete-array-bound
   inference (49139), static-assert and type diagnostics, global/static
   initializers (`ir_module_add_global` 49854), signatures
   (`c_ir_function_signature` 49875), the reachability worklist for
   internal/inline definitions (49939–50020), and **pre-creation of every
   function record and function symbol in declaration order**
   (`ir_program_add_symbol` 50103, `ir_module_add_function` 50119).
2. **Body loop** (50153–50543), one iteration per definition: gating,
   capacity scan, `TemporalArena lowering_temporary` over one shared
   `lowering_arena` (50130, 50194), builder construction (50288–50378),
   parameter emission, `c_ir_lower_body` (50501), atomic-aggregate check and
   `c_ir_ssa_finish` (50502), one diagnostic on failure (50511), debug locals
   (50526–50539), counters (50540–50541).
3. **Serial epilogue** (50549–50666): aliases, constructor/destructor
   initializers, the over-aligned-array report, `arena_destroy(lowering_arena)`.

The body loop is the only candidate region. The preamble is a dependency
fixpoint over the whole type table and the epilogue is trivially small
(measured 0.1 ms on stage 1).

Two invariants make the **G** rows load-bearing rather than incidental:

- **Encounter order is identity.** Type, symbol and global ids are the
  append counters; `.L.cstr.N` embeds the symbol counter into a link name;
  data-section order is global order. The serial reference therefore encodes
  "declaration order, then in-body encounter order" into the object file. A
  parallel publisher must reproduce exactly that order at merge time, which
  means journaling every provisional id and fixing up every row that used it
  (`IrInstruction.symbol/type`, `IrValue.canonical_type`, `IrGlobal.symbol/type`,
  the literal's name string) and re-running each interner's identity rule in
  source order — a second publication layer over the canonical tables, across
  the ~40 sites listed above, in a file with active cutover owners.
- **The arena is the unit of ownership.** Every permanent row comes from the
  caller's TU arena through a non-atomic bump. There is no sub-arena facility;
  per-lane arenas must be retained by the program and released by the driver,
  i.e. the arena-lifetime contract in the foundations guide gains a second
  owner set.

## Smallest defensible region and the two candidate designs

The smallest region that keeps canonical IR as the sole boundary is the body
loop with a **frozen shared world**: preamble unchanged, then `lane_run` over
definitions with an atomic take-index in declaration order, one retained
arena + one scratch arena + one temporary arena + one query machine + private
copies of the three idempotent caches per lane, results in declaration-indexed
slots, and a serial epilogue that walks the slots in order. Two ways to treat
the **G** rows were evaluated:

- **Closed-world deferral.** A lane may not publish to
  `program->types/symbols`, `module->globals/functions`, `entity_symbols` or
  `cleanup_functions`. Any body that reaches a publication site aborts its
  attempt and is re-lowered serially in the epilogue, with the identical
  kernel and publication enabled. Output is then identical to the serial
  reference (parallel bodies publish nothing; deferred bodies replay in
  declaration order). Cost: the wasted parallel attempt and the serial replay
  of every deferred body.
- **Journaled publication with source-ordered merge.** Lanes mint
  provisional ids; the epilogue replays journals in declaration order,
  applies each interner's identity rule, patches rows and formats
  `.L.cstr.N`. Output identical to serial. Cost: the second publication layer
  described above.

Rejected cheaper variants: *pre-materialising string literals in the
preamble* renumbers `.L.cstr.N` and reorders globals, so it changes the
object relative to the serial reference (and body encounter order is not
token order because prepared calls lower before their enclosing expression,
`c_gen.c` 42–49); *parallelising only `c_ir_ssa_finish`* would require
retaining every body's scratch until a post-loop phase — **979 MiB** on
stage 1 (sum of measured per-body `lowering_scratch_bytes`) against an
80 MiB single-body peak today — for a 24 % slice of the loop.

any overhead.

## Decision

**NO-GO for a prototype at `194bd65b`.** The boundary exists and is now
specified (frozen shared world, per-lane retained arenas, journaled or
deferred publication, declaration-indexed slots, ordered epilogue), but its
measured value does not justify its cost:

- the eligible region is 22 % of the stage-1 compile and its perfect-parallel
  ceiling is ×1.22–1.24 whole-compile at eight lanes;
- the implementable-today variant (closed-world deferral) is ×1.08 at best
  because string literals put 61 % of loop time behind shared publication;
- the variant that recovers that 61 % requires a second, order-reproducing
  publication layer over `program->types/symbols` and `module->globals`
  across ~40 `c_gen.c` sites plus an arena-lifetime contract change in the
  driver, in a file with active #513/#514 cutover ownership;
- the tiny population cannot benefit at any lane count, and the few-large
  population is bounded by its body count.

This closes #531's research question with a supported no-change decision. It
is not a claim that function-body lowering is unparallelizable; it is the
finding that at this revision the serial fraction of the compile outside the
loop, plus the order-encoding publication inside it, make the loop a poor
first target for #128.

What would reopen a prototype (completion criteria for a successor):
1. lowering's loop share of the whole compile rising well above the measured
   22 % after the serial phases shrink (re-run this census; the probe is
   retained);
2. a merged, separately reviewed decision that string-literal and static-local
   publication may be journaled (per-kind identity rules for pointer, array,
   qualified, aligned, function, literal and vector types; runtime-import
   symbols by link name; `.L.cstr.N` formatted at merge), or a maintainer
   decision that an opt-in mode may renumber local symbols;
3. an `IrProgram`-owned retained-arena set with a documented driver release
   point.
