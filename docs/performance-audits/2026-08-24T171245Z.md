## Change

The C frontend now emits a private one-byte `CTokenShape` projection beside
every lexed and final preprocessed token. Non-punctuators retain their kind;
punctuators use a high-bit tag and the low seven bits for the punctuator id.
The compile-time checks keep both domains disjoint and within the tagged byte.
`CToken` remains the existing 12-byte ABI record.

The compact SIMD lexer and scalar/reference lexer both fill the projection.
The preprocessor carries it in a separate private arena, copies the lexer
projection for unchanged lines (including newline filtering), and constructs
one shape for expanded or synthesized rows. `c_preprocess_token_shapes` and
the indexed fallback accessor are the small shared interface for later tile
consumers. The parser's position index, declaration/body shape walks, and
token census consume that stream; identifier spelling/symbol projection stays
in the rare path that needs it.

## Population and memory accounting

The final self-host workload contains 2,978,623 preprocessed tokens, so its
final shape stream is 2,978,624 bytes including EOF: exactly one byte per
final token. Lex results allocate a sidecar at the existing one-byte-per-source
byte capacity bound (`translated.source.length + 17`), and the preprocessor's
final shape arena stores one byte for each retained token. The private shape
arena reserves 1 GiB of virtual address space, like the existing private token
arena; reservation is not resident memory. Resident/committed cost is the
pages touched by the sidecar writes (the one-byte stream rounded by arena page
granularity), plus the pointer/arena metadata. No `CToken` row grows.

## A/B measurements

All counters below are pinned to CPU 0 with `perf stat` and use 10 or 11
order-separated runs as noted. The trusted baseline is the saved origin/main
`ide-baseline` binary; the final binary includes the direct-copy and cached
sidecar-pointer corrections.

- End-to-end `ide bench` (30 iterations over `tests/basic_c_operations.c`,
  4,644 tokens): baseline **287,028,086** instructions/run versus final
  **291,684,328** (**+4,656,242, +1.62%**). Branches were 51,021,200 versus
  52,213,700; L1 loads 111.989M versus 112.998M. The direct-copy and cached
  pointer passes removed about 2.1M instructions from the initial +6.76M
  sidecar delta. #538 alone is still a measured regression; this audit does
  not claim a net speedup.
- Emitter-only A/B (11 pairs, a temporary 30-call `c_lex` loop): baseline
  **9,329,112** versus sidecar **9,488,126** instructions per 30 calls
  (**+159,014**, about **+5,292/lex**). Branches fell 1.120M -> 1.115M,
  while L1 loads rose 2.909M -> 2.983M. This is the separately accounted
  emitter cost.
- Consumer-only A/B (11 pairs, preprocess once then 30 census calls on the
  same 4,644-token source): baseline **3,626,030** versus sidecar
  **3,626,090** instructions/run (**+60**, measurement noise). Branches were
  641,068 -> 644,937; L1 loads 1.349M -> 1.320M. The sidecar consumer is
  effectively flat on this small corpus and cannot recover the emitter cost.
- Self-host stage 1 measured **9,781,496,306** instructions in 0.937690 s,
  compared with the pinned 9,667,016,394 reference (**+114,479,912,
  +1.184%**). Stage-2 benchmark was 454,750,643 instructions. A trial that
  removed the per-token emitter null check and added one dispatch assertion
  was reverted: it added 1.127M stage-1 instructions and did not move the
  frontend bench.
