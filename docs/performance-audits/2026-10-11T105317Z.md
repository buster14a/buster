## Workload

Every arm compiles the same input, the base revision's unity self-host source,
from a checkout of the base:

```sh
ide cc -Isrc -Ibuild/base/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -fsyntax-only \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

The tree holds 148,226 `DECL_SPECIFIERS` lists. There are four arms:
- A: base, default flags;
- B: base with `-fc-ast-pilot`: the tree, the typer, the declaration split and
  the statement plan;
- C: candidate with `-fc-ast-pilot`: the same, with plain declaration
  specifier runs read from the tree;
- D: candidate, default flags.

C − B is the read's own effect, and D − A is its cost to the default path.
Callgrind ran with `--cache-sim=no --branch-sim=no`.

The plain shapes (primitive words or one typedef name, with qualifiers and
storage classes) cost about 213 M Ir in about 85 K runs. Most of a run is
fixed machine work: the storage scan with its spelling compares (562 Ir per
call), the `typeof` and tag scans, two frame pushes and the typedef probe.
Tag definitions cost the most per run, but they build member rows the machine
must still build. Type names were not claimed: compound literals (about
26 K runs, 55 M) and `sizeof` operands (about 42 K runs, 79 M, 32.7 K of
them runs whose leading token is not a specifier word).

  - `c_parse_local_declarations`, inclusive: 337.1 M → 257.0 M (−80.1 M).
  - `c_parse_declaration_type`, inclusive with its parameters: 625.4 M →

    29.7 M (−47.2 M).
  - The index costs 11.8 M (`c_parse_specifier_index_prepare`, one call). The
    tree read costs 45.3 M over its 81,208 calls (558 Ir each, the rows it
    appends included). Of that, `c_parse_primitive_type_read` takes 12.0 M
    for the 15 K primitive runs.
  - The type machine (`c_type_parse_machine_run`) runs 158,896 times instead
    of 237,991.
- **D − A: +3.07 M (+0.029%), inside the band.** The default path builds no
  index (one call, 23 Ir) and makes the same machine calls as A:
  `c_parse_scalar_type_in_scope_attempt` 154,310 and
  `c_type_parse_machine_run` 920,331 in both. The difference is the
  out-of-line `c_parse_declaration_specifiers_type` wrapper (55,626 calls)
  and the code around it. `c_parse_local_declarations` is +3.0 M inclusive.

## What is left with the machine

- 2,113 runs handed back on the self-host:
  - 2,045 `specifiers`: tags, `typeof`, attributes and words outside the
    plain set (not broken down further);
  - 68 `input`, where no list begins at the run's first token.
- Tag definitions (about 53 M at file scope) still build their bodies through
  the machine. A tree read of them would have to replay member rows and
  aggregate attributes in the machine's order.
- Type names, members and every declarator derivation (pointer, array and
  function suffixes) are unchanged.

## Validation and limits

- Callgrind counts instructions, not time, on `-march=x86-64-v3` builds whose
  AVX-512 kernels are compiled out.
- One input, one host, single process, no pinning and no `perf` counters. Wall
  time was not measured: the budgets did not ask for it, and on this host it
  cannot resolve an effect of this size in the whole compile.
- No 9700X comparison is requested for this slice. Zen 5 validation of the
  read stays **incomplete** (#2761), and the hook stays opt-in.
- Correctness of the measured candidate is in the pull request's validation
  record: `c_ast_tests` in Debug and Release (tests on), `test_all` and
  `test_self_host --config Release`.
