## Hypothesis and first falsifier

After arguments have completely expanded, an eligible ordinary replacement still creates CPpToken rows only for `c_macro_materialize` / `c_macro_expansion_tasks_push` to copy them into the existing task array. Direct scalar stores can remove that intermediate without moving observable expansion work.

The cheapest falsifier is complete preprocessing identity plus independent compile/run outcomes on empty, nested, re-enable, growth, fallback and provenance cases. A mismatch rejects the implementation regardless of allocation counts. Timing then includes the entire operation, reservation/counting/setup/growth, serialization or code generation and process startup; source inspection alone does not establish performance.

The simpler competitor is the identical helper with eligibility additionally requiring `!macro->definition.parameter_count`. This is a zero-parameter ordinary-macro restriction, not a separately invented engine or an object-only semantic classification. Its exact one-line patch and transformed source SHA-256 are retained in the comparative artifact.

## Eligibility and transition argument

The direct path requires `!macro->builtin && !macro->definition.pragma_like && !macro->definition.has_paste && !macro->definition.has_stringify`. Dynamic builtins, pragmas, paste and stringification stay on the old materialization path. Compiler-predefined definitions represented as ordinary replacement rows retain their existing downstream semantics; this is not a rewrite of feature builtins. Eligibility is decided only at existing materialization, after all argument continuations have completed.

| State | Effect and invariant |
|---|---|
| Argument continuation | Original argument order, child expansion, painting and floors are unchanged. No direct batch is reserved yet. |
| Size calculation | Count N from plain rows plus parameter-use counts times resolved expanded-argument lengths, using u64 and checking the existing representable u32 output width. |
| Reservation | Save integer base b, reuse the existing geometric reserve policy for N+1 tasks. Reallocation can move tasks, but no old task-row pointer is retained. |
| Fill | ENABLE occupies b. Logical token i occupies b+N-i. Read definition/argument rows forward and fill tasks backward. No nested expansion, spelling allocation, interning or task publication occurs here. |
| Publication | After verifying the final index is b, disable the macro and publish count b+N+1. |
| Consumption | The unchanged engine pops logical tokens in their original order, then ENABLE, then older parent work. N=0 still publishes ENABLE. |

Parent tasks below b and all saved context floors remain unchanged. Arena-owned definition and expanded-argument storage does not alias the task array. Reservation therefore cannot invalidate the producer's inputs; more importantly, reservation does not span child expansion. Pending task entries still have the same initialization/default fields.

Definition tokens retain token/spelling fields, the masked invocation stamp, foreign=true and original invocation/replacement spacing. Argument CPpToken values retain persistent no-expand paint and interior spacing before applying exactly the previous invocation-stamp, foreign and first-token spacing transformations. Empty argument substitution does not consume the first-output spacing state. The consumer's disabled-macro painting, invocation lookahead, ENABLE handling and location recovery are unchanged. This preserves the existing semantics, including known independent prescan defects; fusion is not a correction for #1091.

The count guard has a real cost: optimized Clang output contains integer division for its overflow checks. The direct destination stream is backward, unlike the old temporary's forward stores followed by a reverse task copy. Reservation, integer checks, default-field stores and possible locality costs are included in the end-to-end measurements, not omitted as setup. The explicit count bound rejects an unrepresentable output rather than allowing u32 wrap; no practical >4-billion-token allocation test was performed.

## Whole-operation measurements: tests disabled

All three compilers were built serially in the same configured directory by build.c with the same trusted Clang 21.1.8 Release/non-unity flags, `BUSTER_INCLUDE_TESTS=OFF`. Baseline, narrow and full were frozen before timing. An identical-source touch/rebuild produced byte-identical baseline compilers. Full compiler command databases, CMake cache, host/kernel/image, executable hashes and deterministic source hashes are retained.

The unmodified native harness measured compilation to object. A branch-only six-anchor adapter extended its existing artifact selection to -E/.i for complete preprocessing. It reuses native input generation, randomized paired scheduling, process collection, output identity, raw schema and statistical replay; it adds no timing instrumentation to a compiler. The adapter is retained as `preprocessing-harness.patch`, is not a production harness feature, and is not a hardware-admission claim.

Each of A/A, A/narrow and A/full has three workloads, two fixed rounds of 12 pairs and two warmups. There are 144 timed observations per bundle, six bundles, 864 total. All samples are retained. Each comparison is paired against its own baseline cohort; narrow/full are not directly paired with each other. Cache policy is warm-filesystem/new-process. Wall scope is process launch through wait completion. OS child CPU time, peak RSS, faults and context switches are collected; PMU/allocation counters in these timing rows are NA. The ordinary diagnostic explicitly used `--no-guard --require-identical-output`; a zero exit proves completion/equality, not a speedup or nonregression gate.

Reported percentages are the harness's paired log-ratio aggregation, not ratios of the displayed independent medians.

## Independent allocation census

After all timing completed, build.c separately rebuilt base/full with `BUSTER_BENCH_ALLOCATIONS=ON`. `BUSTER_ALLOCATION_CENSUS=1` captured complete frozen baseline unity preprocessing, and the existing `tools/allocation_census.py` parsed the raw site records. Instrumented binaries were never used as timing compilers.

At the old ordinary replacement materializer's allocation site, baseline recorded **107,401 calls and 13,951,920 requested bytes**, equivalent to 871,995 16-byte CPpToken rows. That site's requests are absent in the candidate capture. The entire census's call/byte difference matches exactly: no claim is made by summing all sites with the same function name. Builtin and paste-path allocations remain separately visible. No remaining pragma allocation at this site was observed in this particular input; that is not a general claim that pragmas are eligible.

Task growth remains **1,991 requests, 35,258,624 requested bytes and 1,048,576 maximum request bytes** in both captures (old push site versus extracted reserve site). This directly checks that removing the temporary did not buy its reduction by silently shrinking required task growth. Other non-allocation source metrics and the complete output remain equal.

The removed materializer payload is cumulative per-preprocessing arena demand, not just the largest replacement, and not equal to an RSS or DRAM reduction. Peak pending-task count and simultaneous live arena peaks were not instrumented. The census is evidence for eliminated producer traffic, not by itself a performance result.
