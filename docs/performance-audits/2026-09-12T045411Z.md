`2026-09-12T045411Z` (Linux x86_64, Clang 18.1.3; AArch64 QEMU 8.2.2;
**Migrate Windows and Darwin AArch64 variadics to MIR**).

Base: `c343b256` (public ELF AAPCS64 list implementation), followed by this
commit's Windows/Darwin implementation. This is correctness and coverage work
for #36; compiler throughput/resource acceptance remains with the integrated
retirement candidate.

Windows variadic signatures and calls now use the integer argument image for
named and anonymous arguments. The frame prefix contains a contiguous X0-X7
save image immediately below incoming SP, so public pointer lists cross the
register/stack boundary in independently compiled consumers. Integer aggregates
can split across X7 and SP; aligned integer pairs round to sixteen bytes.
Darwin uses pointer-sized lists, independent named register files, naturally
packed named stack parameters, and anonymous stack slots. List copies use
eight bytes and reads use ordinary MIR loads, alignment, cursor stores and
exact aggregate copies. Existing supported reads through sixteen bytes migrate.

The former 24 variadic refusals are strict successes: all 396 rows of the
eleven-fixture/six-target/three-allocator/two-frontend floor pass. The separate
fallback-diagnostic control now uses 25 fixed scalar parameters, beyond the
selectors' current 24-parameter limit; direct compilation still succeeds.
That capacity boundary remains retirement work.

The cross-format execution procedure, illustrated for one Windows row:

```sh
clang -target aarch64-pc-windows-msvc -O2 -ffreestanding \
  -fno-stack-protector -fno-unwind-tables -fno-asynchronous-unwind-tables \
  -c tests/differential/aarch64_platform_variadic_host.c -o host.o
build/Debug/ide cc -target aarch64-windows -c -g0 \
  -fregister-allocator=fast -ffrontend-ssa -fno-machine-fallback \
  -fverify-codegen tests/differential/aarch64_platform_variadic.c -o subject.o
llvm-objcopy-18 --remove-section=.pdata --remove-section=.xdata \
  subject.o subject-code.o
build/Debug/ide cc -target aarch64-linux subject-code.o host.o -o abi-test-elf
qemu-aarch64 abi-test-elf
```

Windows scratch copies remove only unwind sections because their `ADDR32NB`
relocations cannot be consumed by the Linux linker; `.text` was compared
byte-for-byte with the original. Darwin objects need no section removal.
Clang's reference units use `-O2` because its `-O0` constant-pool relocations
include additional cross-format reader limitations. Native Windows/Darwin
loading, SDK linking and `RtlVirtualUnwind` execution were unavailable here;
the registered platform-native tests now cover those gates, including a
variadic frame in `windows_arm64_mir_unwind.c`.

The public-ABI cases run under strict MIR in the native driver suite. The
former direct emitter has independently reproduced public-list and Darwin
named-stack layout defects and cannot serve as an independent ABI oracle.
Clang 18 also fails the Windows i128 and X7-split boundary tests at O0 and O2.
The i128 defect is independently recorded in
[LLVM #207584](https://github.com/llvm/llvm-project/issues/207584). The Windows
assembly probes follow Microsoft's
[ARM64 variadic ABI](https://learn.microsoft.com/en-us/cpp/build/arm64-windows-abi-conventions?view=msvc-170#addendum-variadic-functions)
and separate compiler disagreement from the ABI contract.

Self-host fixed point, sanitizer configurations, native platform execution and
the retirement performance budgets require validation of the final combined
candidate; they are not inferred from this Debug and emulated ABI evidence.
