## Workload

The input is the unity self-host source. Its 4,027,038 final-stream tokens reach
the parser, giving 2,661,455 nodes (0.661 nodes per token):

```sh
ide cc -Isrc -Ibuild/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=native -g0 -fsyntax-only \
  [-fc-ast-pilot[=implicit|hybrid|explicit] [-v]] -fmetrics-out=<file> src/buster/apps/ide/ide.c
```

A and B are the same binary. A has no hook. B adds `-fc-ast-pilot`, which builds
the implicit tree inside the parse phase, before `c_parse_ast`. That makes
B − A in `parse_ns` the tree's cost. There were 12 pairs in ABBA order. Each
layout then ran 7 times under `-v`, which prints `c_ast_build`'s own wall time
and the timed traversals: a full enter/exit `c_ast_walk`, a linear pass over
`kinds`, and `c_ast_children` over every node.

## Budgets declared before timing ([guide](../agents/frontend/ast.md#measurement-plan))

| Budget | Result | Verdict |
| --- | --- | --- |
| Implicit build ≤ 2× `c_parse_ast` on the same stream | 84.94 ms (`-v` median; min 82.30) against `c_parse_ast` 82.09 ms (A `parse_ns` median); paired B − A median 86.96 ms (min 80.35, max 109.57) | pass, about 1.03–1.06× |
| Retained ≤ 16 B per final-stream token | 34,598,915 B = 8.59 B/token (13 B/node: four SoA columns) | pass |
| Transient ≤ one chunk per column plus stacks | 34,785,280 B: every chunk of the tree until the seal copies it | **fail** |

The transient budget was a wrong prediction. The builder keeps the whole tree in
phase-arena chunks and copies it into exact-sized columns only after the last
node. The phase high water is therefore the tree itself, and the peak during the
seal is about 2× the tree. This is not an O(1)-memory design and the guide does
not claim one. It does not exceed the retained budget, but it is the
next thing to fix: a token-count upper-bound reservation written in place, or
columns grown in reserved virtual memory, would remove the seal copy, the
34.6 MB of `sealed_copy_bytes` and the transient copy. Either must be measured
against the current design.

## Layouts

| Layout | Build ms (median of 7) | Retained bytes | Walk ms | `c_ast_children` over all nodes ms | Kinds scan ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| implicit | 84.94 | 34,598,915 | 18.92 | 18.30 | 0.569 |
| hybrid | 101.23 (+19%) | 42,402,307 (+23%) | 16.99 (−10%) | 16.22 (−11%) | 0.504 |
| explicit | 121.35 (+43%) | 60,788,827 (+76%) | 17.42 (−8%) | 15.52 (−15%) | 0.555 |

Hybrid adds 1,950,848 slice entries and explicit adds 3,886,023, both written by
the one finalization pass. A full ordered walk takes 6,547,478 events
(enter plus exit). In every layout, its cost is dominated by the walk itself
rather than by finding children. The explicit indices save about 2 ms per full
traversal and cost 16–36 ms to build plus 8–26 MB to retain. **Decision for
the pilot: keep the implicit layout.** An index can be added later, and only for
the node kinds whose measured access pattern justifies it.

## Context

On the same input, today's `-fsyntax-only` spends 352 ms in preprocessing,
82 ms in `c_parse_ast` and 980 ms in semantic analysis (A medians). On the
pre-change main `b94415d3`, a full `-c` compile measured 4.18–4.42 s, and its
`analysis_ns` of 2.26–2.46 s covers semantics plus canonical lowering. Those
stages re-walk token ranges. A pilot that only adds a tree therefore costs
time: B's total is +7.2% (1,529.8 ms against 1,426.7 ms). Any end-to-end gain
has to come from migrating those consumers, which is outside this PR. The arena
peak rises by exactly the retained tree (+34.6 MB of 1.96 GB).

## Validation and limits

- One input, one host, single process, no pinning and no `perf` counters. A/A
  noise was not qualified separately. The parse-phase samples of the two arms
  (A: 80.2–88.9 ms, B: 165.7–189.7 ms) do not overlap.
- The 9700X pull-request comparison runs default flags only, so it cannot time
  the hook. Zen 5 validation of the tree's cost therefore stays **incomplete**.
  The default path, where the pilot is off, can and should be compared there.
- Correctness of the measured binary's tree is covered by `c_ast_tests` and
  `compiler_driver_tests` in #3108 and by a byte-identical `test_self_host`
  fixed point at `ae50f89a`.
