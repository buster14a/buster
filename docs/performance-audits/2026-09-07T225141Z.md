## Ownership inventory and decision

The source census finds ten declarative rows: constant, local, memory,
address, arithmetic, call, control, vector, scalar, and legacy fallback.
`machine_selection_rule_select` has two call expressions, both in
`machine_selection_tests`; it has no production caller. No rule emits MIR.
The full prepass, result/side-effect classifications, promotion candidates,
constant bits, use ordinals, and rule context are consumed only by that
matcher or tests of the matcher itself. They therefore describe a competing
selection policy without owning any generated instruction.

Production selection belongs to the x86 opcode switch in
`machine_select_canonical_function_x86_64` and the AArch64 switch in
`machine_a64_select_instruction`, with direct target helpers for ABI and
complex operations. The native machine allocators consume those results;
NONE and rejected functions use the canonical emitter. New machine
selections belong in those target switches, with actual MIR/output coverage.
The existing `supported`/`failed_opcode` result and
`CodegenStatistics.fallback_opcode_counts`/`fallback_verify_count` expose
real misses and canonical fallbacks. There is no remaining declarative
pattern miss or handwritten-vs-declarative overlap to count.

Choose removal: delete `machine_select_rules.h`,
`machine_select_generated.c`, their public rule/context/counter types, the
full fact builder, and all their query helpers. Keep the production four-byte
module type projection, row layout, signature plans, and AArch64 value facts.
The old minimal prepass's only production consumption is `.valid`; its four
returned definition/use arrays are discarded by both selectors. Replace it
with `machine_selection_validate_function`, a narrow storage/ownership
check returning an error enum. The normal prevalidated production path still
bypasses it; the canonical verifier's authority is unchanged.

The validator keeps opcode bounds, operand storage/indices, result bounds,
duplicate definitions, row ownership/cycles, linked-list tails, and the
all-rows-owned check. Presence needs one byte per row and value, in one arena
allocation. For I nonzero rows and V nonzero values, scratch changes from
`I + 16*V` bytes in five allocations (plus alignment) to `I + V` bytes in
one allocation. The former result also carried 17 pointers: two context pointers and
fifteen mostly absent fact-array pointers. The six valid-function probes across x86-64/AArch64 assert the new
exact arena delta; this is a checked memory bound, not a PMU estimate.

The old 240-byte zero counter blocks remain only as 30 explicitly reserved
u64 words in each of the two selector structs and the result struct. Their
types, counter operations, and two zero-block copies are removed. Keeping
this padding follows `2026-08-17e`, where removing it was instruction-flat
but increased L1d misses 2.69% and branch misses 1.32%. This change does not
repeat that rejected density experiment or preserve a telemetry API as
padding. A new target-host layout experiment can remove the reserved words
separately if evidence supports it.
