# Ordinary-enumerator token-view audit

## Scope and diagnosis

The starting tree was `4ebe744817fed9739926f43d9edd7b3a6b177203`.
The user's unrelated modification to `tools/native_retirement_census.c` was
present for both local runs and was not touched. The measured compiler change
is the ordinary-expression path in `c_parse_generic_constant_tokens`, its
private alias regression, and the matching frontend contract.

Superluminal capture `2026-09-17_17-13-38_ide.linux` recorded the Clang Release
producer compiling the unity IDE. Its producer build ID
`cfd7d02d53f8975749c1a4da41eb6b8f75473501` matched the local Release binary.
The capture reported 123 calls to `c_parse_generic_constant_tokens`, 3100.821 ms
inclusive, with 98.643% of its source time on the full-token-stream `memcpy`.
The largest unresolved leaf, `libc.so.6+0x1B0883`, was one instruction in
`__memcpy_evex_unaligned_erms`; missing libc debug information split adjacent
instructions into separate `Unknown` functions.

The same-revision source metrics reported 3,465,808 preprocessed tokens. At 12
bytes per `CToken`, each ordinary enumerator copied 41,589,696 bytes. The 123
calls therefore copied 5,115,532,608 bytes (4.76 GiB) before evaluating their
small expression ranges.

The implementation now scans only the requested range for a syntactic
`_Generic`. A range without one returns the original token pointer and count;
the existing materialization and explicit range-stack path remains responsible
for selected and nested generic associations. The private regression observes
pointer identity directly, so the performance contract is not a wall-time
assertion or a production counter.
