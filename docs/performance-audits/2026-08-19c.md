`2026-08-19c` (Linux x86_64, Zen 4 7940HS; **align canonical value slots with
a mask instead of a hardware divide**).  A stage-1 profile attributed about
11% of `codegen_generate_canonical_module_attempt`'s self-time (~0.2% of
stage-1 cycles) to the `%` in the per-function capacity-estimation loop that
rounds `function_value_bytes` up to `slot_alignment`; the offset-assignment
loop below it repeats the same expression over the same population, so both
were converted together.

The transformation is licensed by an invariant the code could not previously
state: `slot_alignment` is always a power of two at least 8.  Type layout
alignments bottom out in `target_data_layout`'s 1/2/4/8/16 table (checked by
`target_layout_alignment_valid`), aggregates take a max of member alignments
with `#pragma pack` values power-of-two-validated in
`c_preprocess_pragma_pack_value`, vectors require an arithmetic scalar
element and a power-of-two element count so their byte size stays a power of
two, arrays inherit their element's alignment, and every requested value
alignment passes `c_ir_alignment_evaluate`'s explicit
`requested & (requested - 1)` rejection.  With that proven, both align-ups
became calls to the existing `align_forward` mask helper from
`buster/lib/integer.h` (inlined in the unity build; three verification pairs
put the helper within +-53 K instructions of the open-coded mask); the
comment at the first site now records the invariant.  Hardware `div`
instructions in the symbol fall 9 -> 5 (each
`%` had compiled to a 64-bit divide plus a 32-bit fast-path divide).

Seven alternating same-source, CPU-pinned, non-multiplexed instruction pairs
are byte-identical and every pair favors the candidate; the median falls
10,593,713,412 -> 10,586,015,231, **-7,698,181 (-0.0727%)**.  Branches fall
1,964,836,273 -> 1,961,837,744 (**-0.1526%**), L1d loads fall 3,817,641,010
-> 3,810,362,918 (**-0.1906%**), L1d misses fall 124,263,587 -> 124,195,169
(**-0.0551%**), and branch misses are flat (24,742,070 -> 24,752,764,
+0.0432%).  Eleven alternating cycle pairs are noise: the candidate wins
4/11 and the median moves 3,909,955,453 -> 3,908,336,779 (**-0.0414%**).
The honest reading is that the divide's ~0.2%-of-cycles profile share did not
survive contact with out-of-order execution — the win is real but small,
carried by the retired-instruction and load counts, not wall time.

The final `test_self_host` reaches a byte-identical 35,543,096-byte fixed
point: stage 1 retires 10,585,947,051 instructions, stage 2 retires
76,189,510,684, and the full local CI combination matrix
(`test_all_combinations_ci`) passes with every module green across its three
`test_all` runs (309,189 assertions on the fullest), a clean Clang static
analysis, and the same deterministic self-host bytes; remote a64/Windows
coverage stays pending on CI.  The sibling find from the same profile
— `codegen_canonical_x64_function_shape` rescanning every instruction of
every function for atomics and inline assembly (~0.3% of stage-1 cycles) —
was left untaken: deleting it wants a per-function opcode-presence summary
accumulated during lowering, which is a design change, not a local rewrite.
