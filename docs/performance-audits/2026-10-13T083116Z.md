**Run wall.** No change is detectable. Each run's 26 jobs land on a mix of
CPU models, so runner-seconds vary by about 1,650 s between runs.

**Critical path.** The last job before `CI complete` was:
- Windows x86-64 release in 11 of 18 runs;
- Clang analyzer shards in 5, at about 1,200 s each, which Buster's speed
  does not affect;
- Windows AArch64 release in 2.

Windows x86-64 release is the usual critical job, and its job wall shows no
measurable change. So **no merge-queue latency benefit is observed**.

**Runner-seconds.** What is measured is about 15 to 20 s less module time in
three of the 26 jobs. Linux and Windows AArch64, macOS, Windows sanitized,
portability and the mobile lanes were not measured, and no figure is inferred
for them. All of this describes CI before #3942. After it, the release lanes
have a different shape, so these numbers are not a forecast for current main.
