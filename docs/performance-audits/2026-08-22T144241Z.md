**One negative result, measured and reverted:** merging
`c_ir_lower_frame_fallback`'s two sequential `switch (active->kind)`
dispatches into one.  Every delta landed at noise, leaning wrong
(instructions +38 K 3/11, branch misses +35 K 4/11): clang's two smaller

dispatch is not the cost it reads as.  The function's 7.0% miss share is
real but the lever is fewer machine steps, not fewer switches per step.

**Rediscovered the hard way** (cost one false alarm): comparing a new
binary's output against an output produced *before* a source edit is
comparing two different inputs — the workload compiles the compiler's own
tree, so the edit is in the bytes.  `feedback_perf_measurement_traps`
already says this; the pair harness compares both binaries on the same
source and is the only valid identity check.
