Three concrete candidates survive dependency analysis:

1. **A1: transient operator summaries with indexed range selection.** Classify
   immutable operator facts once, then let the existing scalar expression-type
   machine ask for its next split. The strongest first experiment is eliminating
   repeated classification, not replacing the parser with a vector parser.
2. **A2: ordered batches of already-bound call constraints.** Prepare signature
   facts through the current scalar binding path; batch only pure predicates.
   This exposes a genuine semantic SIMD seam, but the immediate arity predicate
   is so cheap that packing may defeat it. Do not move semantic analysis earlier
   merely to fill lanes.
3. **A3: query-local type-pair frontiers.** Separate immutable header predicates
   from array-bound evaluation and type mutation. Compare SIMD against a strong
   scalar, query-local DAG-deduplication control, not against repeated expansion
   of the same shared graph.

**No implementation or compiler speedup is established here.** The new numerical
results are a reproducible static census of seven real source files. They are
not executed semantic-query distributions, instruction counts, timings, or
Zen 5 results. Historical performance evidence is explicitly marked H. Missing
runtime measurements are U; proposed performance effects are hypotheses.

The existing parser is neither wholly sequential nor uniformly batchable.
Immutable token classification and header comparisons are independent;
publication of declarations, binding, completion, constant evaluation and
observable diagnostics carry dependencies. A small scalar coordinator can
expose the first group without duplicating the second.

## Common dependency and readiness contract

A descriptor is ready only when its exact facts are available through the
existing authoritative path. Source-text proximity does not establish readiness.
A batch key includes its caller/phase, target/dialect, original request order and
semantic snapshot or bounded lifetime. A generation is a design requirement,
not a claim that current source already exposes a universal mutation counter.
Where it does not, end the batch at the existing helper boundary.

| C concern | Independent work | Dependency-bearing work and required barrier |
|---|---|---|
| Typedef names | Punctuation class, fixed keyword class, identifier symbol already present | Whether `T` is a typedef in this scope and declaration prefix; cast/declaration disambiguation stays with lookup/type parsing. Never set a global typedef bit from spelling. |
| Scope and declaration order | Already-bound entity IDs and immutable source offsets | `typedef int T; { int T; ... }`, redeclarations, tags and declarations that affect later declarators require source-order publication. Finish before crossing a binding mutation. |
| Incomplete types | Kind/qualifier observations in a stable snapshot | Completion, inferred array bounds, alignment and enum underlying types can change later answers. No cross-epoch compatibility or layout cache. |
| Constant expressions | Classify an already-typed operator or test already-computed integer flags | Evaluate with existing target arithmetic, short-circuit, overflow and diagnostic rules. Do not execute both branches, invent a host-width evaluator, or fold identifiers before binding. |
| Initializers | Pure predicates on the already-established destination type | Designators, brace elision, member order, inferred bounds, compound literals and initializer evaluation remain authoritative scalar work. Do not build a second initializer image. |
| Unevaluated operands | Type-only constraints that remain required, such as named-call arity | Unevaluated does not mean unchecked. VLA `sizeof`, `_Generic`, `typeof` and diagnostics cannot be handled by blanket skipping or eager evaluation. |
| Target-dependent rules | Predicates within one frozen target/dialect group | Pointer and integer widths, plain-char policy, atomic layout, vector widths, ABI and C17/C23 prototype rules must not leak across groups. |
| Malformed source | Bounds-safe lexical facts about present tokens | Existing recovery, mismatched delimiters, failure precedence, diagnostic suppression and no-artifact policy remain unchanged. Scalar fallback is not permission to silently accept. |

Across declarations, stop before publishing anything that can change the next
request's binding or type facts. Across functions, only immutable lexical
summaries are ready merely because body boundaries are known; shared semantic
queries need the #531 readiness contract. Across expressions inside an existing
query, children become ready according to existing continuation frames. Across
independent type queries, batch only when the caller already owns a set of
requests with identical frozen context; manufacturing that set by reparsing or
rebinding is duplicated work.

### Diagnostics and bounded scratch

Use the **existing semantic traversal/phase order**, not a global sort by source
location. Macro expansion and include provenance do not sort like filenames;
LIFO type checks do not necessarily visit members in textual order. In a caller
whose current diagnostics are source ordered, preserve its preprocessed-token
ordinal and intra-token diagnostic order. A result key is conceptually
`(phase, original_request_ordinal, original_local_check_ordinal)`.

Workers or vector lanes return facts/error codes, never formatted diagnostics,
new entities or published types. The scalar coordinator commits only the next
original request. A later lane's failure cannot overtake an earlier unresolved
one. Keep current first-error and warning policies; format the selected failure
with the existing formatter and original provenance. Cancel/discard the suffix
at an error or mutation barrier. Charge any work already performed on it.

Scratch is reclaimed at the existing query mark; capacities use checked integer
arithmetic. A bounded queue, for example 256 descriptors, is a research parameter
rather than a chosen production default. Queue saturation or allocation refusal
must take the ordinary scalar path without changing errors. No whole-TU sidecar
is justified merely because it is easy to allocate.

## A1: indexed operator summaries for the existing expression-type machine

### Exact work and strongest scalar control

In `c_type_parse_sizeof_step`, the scan for `best_operator` is repeated for
subranges as tasks split. The implementation already handles unary prefixes
without restarting a known-empty operator search and skips complete indexed
nested groups. The remaining hypothesis is that some long, flat binary ranges
still accumulate enough repeated visits to justify a reusable operator index.
That is a source-derived possibility, not a measured current hotspot.

First retain a no-allocation scalar threshold. The strongest scalar alternative
for larger flat ranges is a **one-pass sparse operator-position index**, grouped
by precedence, with binary searches for a query's first/last eligible position.
A one-pass operator-order plan is another control only if it does not become a
second semantic tree. Compare both with the current switch/scan; merely replacing
that switch with intrinsics is the weakest experiment.

### Representation and guaranteed-independent subset

For the first slice, admit a range after the existing outer-parenthesis stripping
only when it contains no remaining `()[]{}` and no `?` or `:`. Its tokens,
range limits and fixed operator table are immutable. Do not admit casts,
compound literals, calls, subscripts or conditional-expression structure to this
first fast path; their existing scalar machinery remains available.

Project each 64-token tile into thirteen `u64` precedence planes, plus an
operand-ending plane and a cold/structural plane: at most 120 bytes per tile
before indexing. These are proposed packed fields, not measured C struct sizes.
`CTokenShape` already encodes punctuation; token kind supplies the exact existing
`c_parse_expression_token_ends_operand` predicate. Preserve cross-tile previous-
token carry. Mask tails before any load; a shape buffer's existence and bounds
must be checked, with an AoS/scalar fallback when absent.

For each precedence plane, keep a bit only when the preceding token satisfies
that exact predicate. Query-local start/end masks additionally exclude the first
and final token of each current task. This matters: a token can be a valid
candidate in a containing range but not in a child range. No name classification,
constant evaluation or type inference is performed by this projection.

A per-tile 13-bit precedence-presence value forms a small segment tree under
bitwise OR. Query the two boundary tiles with exact masks and the complete
interior with the OR tree. Choose the smallest present precedence. Locate its
rightmost candidate for ordinary left-associative operators, or its leftmost
candidate for precedence-2 assignment. Tree descent locates the winning tile;
`ctz`/highest-set-bit locates the token. A tile scan alone would still leave a
long chain doing quadratic work divided by 64; the range index is essential.

### Pseudocode

```text
prepare(range):
    retain current scalar outer-parenthesis/unary handling
    if tiny, operators_already_checked, or scratch unavailable: SCALAR
    classify shapes/kinds into tile planes with masked tails
    if structural_or_conditional_bits_exist: discard projection; SCALAR
    build OR tree of each tile's available precedence bits
    return query-local summary

select(summary, task_start, task_end):
    mask candidates outside [task_start+1, task_end-1)
    present = masked_left_tile | OR(interior_tiles) | masked_right_tile
    if present is empty: return NO_OPERATOR
    p = least_present_precedence(present)
    direction = LEFTMOST if p == ASSIGNMENT else RIGHTMOST
    tile = locate_candidate_tile(p, direction, exact_query_bounds)
    return matching_bit_in_tile(tile, p, direction)

existing_expression_task_machine:
    preserve its original leading-unary and operators_checked branches
    use select only for an admitted flat range and its admitted subranges
    push/consume the same existing tasks in the same order
    perform all binding, conversion and diagnostic work through old helpers
    free summary at the existing query scratch mark
```

Correctness reduces to equality of the selected token or no-operator result for
every admitted subrange. The summary is not a certificate that the expression
is valid. `a +`, `a + * b`, malformed literals and invalid operands still reach
the same checks. A cold token causes fallback, not acceptance. The scalar machine
remains the sole source of expression types and diagnostics.

### Wider application, without a parser replacement

For nested ranges, a later experiment may emit sparse operator events while
following the **existing** delimiter index and assign events to existing group
frames. The scalar coordinator still handles `? :` nesting and ambiguous unary
roles. Do not materialize a permanent group tree or rescan every group to prove
readiness. Require measured reuse before this extension.

Semicolon/comma/body-brace bitplanes can cheaply suggest declaration or function
boundaries. They cannot certify them: `for` headers, initializer braces, function
pointer declarators, attributes, statement expressions and typedef-sensitive
syntax defeat a blind top-level split. Feed candidates to `c_parse_ast` or reuse
its accepted `CParserDeclaration` extents. The current declaration pass remains
the coordinator. This is a useful lexical prefilter, not independent C parsing.

### Break-even model and width choices

Let L be admitted range length, q the number of selector requests, S the sum of
tokens the strongest unindexed scalar scan actually visits, K the number of
operator candidates and M = ceil(L/64). Let all coefficients be measured on the
same producer and host:

```text
Tscan = a*S
Tsparse = Fs + bs*L + cs*K + ds*q*log2(K+1)
Tplanes = Fv + bv*L + store_bytes/BW_eff + tree_build(M)
          + dv*q*log2(M+1) + tail_cost + fallback/discard_cost
break even only when Tplanes < min(Tscan, Tsparse)
```

`BW_eff` is not advertised DRAM bandwidth; the stores, reads, dirty scratch,
cache effects and extra live registers must be priced on the real path. Include
rejected ranges in aggregate cost. SIMD classification changes `bv`, not the
semantics or the asymptotic index lookup.

| Alternative | Expected role and required comparison |
|---|---|
| Improved scalar | Immediate path for the 99/128 observed query operands of at most three tokens; sparse positions are a serious large-range control. |
| Bit-parallel | Scalar-built planes plus `ctz`/OR range queries; isolates the benefit of reuse from vector formation. |
| Scalar-batched | Several ready ranges processed with the same lookup table, explicit segment bounds; no per-range SIMD startup. |
| AVX2 | 32-byte shape classification, scalar mask extraction, two halves per 64-token tile; exact tails. |
| AVX-512 | 64-byte masked classification and mask logic through existing `simd.h`; avoid assuming that half as many vectors means twice the speed. |

The static maximum query length of 18 argues **against** an unconditional
projection. The 638-token return tail motivates finding actual long type queries,
not pretending they have been found. Accept A1 only when an executed histogram
shows sufficient S/L reuse and net savings against sparse scalar indexing.

## A2: ordered batches of bound-call predicates

### Existing semantic seam and readiness

`c_semantic_check_named_call_arities` already scans a caller-provided range in

identifier-use record, and otherwise uses the existing innermost-scope lookup.
It excludes declaration name tokens, resolves a function or named function
pointer, skips indexed nested groups when counting arguments, and retains the
first diagnostic. Its outer scan still visits calls inside those groups.

The predicate is already cheap:

```text
accept = (variadic OR effective_unprototyped)
         ? argument_count >= parameter_count
         : argument_count == parameter_count
```

`effective_unprototyped` includes the existing C23 dialect gate. This checker
covers named callees only, not arbitrary computed/member/builtin-only callees,
argument conversions or all language constraints. Its existence does not
certify semantic-only compilation.

A ready descriptor contains already-resolved `entity_id`, effective signature
counts/flags, call-token index, complete argument count, original ordinal and
caller context. Sourcepoint visibility must be the current resolver's answer,
not a late lookup in a final symbol table. Symbol interning, scoped lookup,
type completion, argument-boundary discovery and errors are coordinator work.
Prepare them once through existing helpers; do not rebind the expression in a
vector prepass.

### Representation and algorithm

Use query-local SoA columns for `argument_count`, `parameter_count`, normalized
flags and original ordinal; keep token/entity IDs in cold side columns. Six
32-bit columns would be 24 bytes per descriptor, or 6 KiB at a hypothetical
capacity of 256. Charge those stores and subsequent reads. Persist neither the
queue nor duplicate signatures after the existing checking range completes.

The guaranteed-independent kernel begins **after** these facts are ready and
frozen. A transparent interposer on today's sequential producer cannot always
fill it: after preparing a call whose predicate has not yet been evaluated,
preparing later calls is speculation unless those preparations are proven
nonmutating, nondiagnostic and independent of the earlier result. Default to
flushing before such a helper. Do not hide that limitation by assuming a
semantic-only work queue that current source does not have.

```text
coordinator visits named-call candidates in the original order:
    perform existing binding/type/count preparation exactly once
    if preparation needs a mutation/error-capable boundary:
        commit pending prefix first, or stay scalar
    if descriptor is ready in this stable context:
        append to bounded queue
    else:
        use original scalar check
    flush at capacity, query end, dependency barrier, or required result

pure_kernel(queue):
    floor = variadic | effective_unprototyped
    bad = (argument_count < parameter_count)
          | ((~floor) & (argument_count != parameter_count))
    return bad mask, never diagnostics or new types

commit(queue, bad):
    choose earliest bad original ordinal, not completion/lane order
    call c_semantic_call_arity_message for that item only
    preserve original token/provenance and stop policy
    discard suffix; release scratch at caller's original boundary
```

Bitwise notation above operates on normalized predicate masks, not arbitrary
integer flag complements. A real implementation must preserve valid-lane masks
and the original unsigned count domain. Out-of-range IDs are rejected or handled
before gathers; there are no masked invalid-pointer reads on scalar fallbacks.

Argument-count discovery may consume existing comma/open-group masks, but it
must retain nested-group ownership. A ternary middle operand containing a comma
is a particularly important differential case; no fresh correctness reproduction
was run here. Initially keep conditional/malformed argument structure on the
original path rather than certifying a new counter from a lexical comma count.
Likewise, computed or member callees remain explicitly unsupported by this
narrow batching seam, not silently blessed.

### Beyond arity, without duplicate semantics

The same ready queue concept can group already-produced call-constraint facts
such as prototype flags or prepared scalar category predicates, **only when the
existing authoritative checker already computes those facts**. Pointer conversion,
null-pointer-constant recognition, lvalue requirements, qualifier stripping and
ABI layout are not reduced to arity; they need their own readiness proof and
shared predicate authority. This report does not add a second checker for them.

Cross-expression batching is possible inside an already-established immutable
checking range. Cross-declaration/function batching is conditional on the caller
having bound entities and sourcepoint-correct signatures without intervening
publication. C17 `f()` versus C23 `f()`, shadowing and later redeclarations make a
single translation-unit-wide signature table unsound for this purpose.

### Break-even and disposition

Let B ready predicates be produced in one stable interval, w be 8 or 16 u32
lanes, P the per-item incremental projection cost, Vw the vector kernel cost,
C the scalar predicate cost, F setup cost and D deferred/error/flush overhead.
Preparation common to both alternatives cancels only when it really is identical:

```text
Tscalar_predicates = B*C
Tbatch = F + B*P + ceil(B/w)*Vw + D
necessary large-batch condition: C > P + Vw/w
finite threshold: B > (F + D)/(C - P - Vw/w), with tail terms restored
```

When that denominator is nonpositive, no queue length rescues this kernel.
Measure the fused scalar resolver/count/check path as well, because a separate
queue can prevent early exit and keep more state live. The best scalar control
may remove a redundant scan or fold the predicate into descriptor production.
That is preferable to a slower SIMD implementation.

| Alternative | What it tests |
|---|---|
| Improved scalar | Inline the existing comparison after count discovery; no allocation, no deferred first error. Primary baseline. |
| Bit-parallel | Pack scalar predicate outcomes into an ordered failure mask; useful mainly for shared publication, not count arithmetic. |
| Scalar-batched | Same SoA queue with a scalar loop; exposes locality gains and measures queue overhead independently of SIMD. |
| AVX2 | Eight unsigned count comparisons per group; normalize floor/equality masks and mask tails. |
| AVX-512 | Sixteen count lanes and compact failure masks; wider only helps when a genuine ready population exists. |

The static parameter distribution supplies small-signature controls but not B.
The default harness's 512 ordinary calls do not supply B either. Record eligible
named calls **per actual checker invocation**, stable-interval occupancy, nesting,
lookups, fallback reasons and the work discarded after the first failure. A2 is
currently a **measurement-gated, likely packing-sensitive hypothesis**, not the
first production SIMD patch.

## A3: deduplicated, state-specific type-pair frontiers

### Irregularity that can be separated

`c_parse_types_compatible` currently uses `CTypePair {left, right,
ignore_qualifiers}` and an explicit stack. Header kind and qualifier comparisons
are independent across available pairs in a stable type snapshot. Pointer and
vector cases expose child pairs; function cases expose return/parameter pairs.
Array cases can compare bound spellings and enter `c_parse_integer_constant_range`.
Aggregate/tag identity and parameter array/function adjustment have separate rules.

The current inspected loop does not show query-local pair memoization. #241's
closed status and historical geometric example do not prove the old timing
still reproduces. Reproduce the premise before claiming a defect. In particular,
wide batches obtained by repeatedly expanding the **same** shared pair are wasted
work, not useful SIMD occupancy.

### Strong scalar baseline and representation

First compare a bounded scalar DAG walk that remembers completed ordered pairs,
including `ignore_qualifiers`, within a mutation-free query epoch. Use a tiny
inline work buffer and grow only as needed instead of eagerly assuming the type
universe is the live frontier. This is a control specification, not permission
to replace another owner's active implementation.

Do not equate `left == right` with success before the original validity and
constraint checks; malformed IDs/types and qualifier policies still matter.
Memoize only completed results whose dependencies remain valid. A pending or
visiting node is not a successful comparison. Cycles need the existing language
and identity behavior, not an invented coinductive acceptance rule.

Transient SoA columns contain left/right IDs, packed left/right kind-and-qualifier
facts, original task identity and context flags. Six u32 columns are 24 bytes per
pair before cold child information and the memo/work stack. Pack only fields
actually consumed; copying `CType` in C source does not prove the compiler loads
its entire physical row. Bound queue and memo growth and fall back conservatively
on capacity limits. There is no process-global compatibility cache.

State queues distinguish header-ready, pointer/vector expansion, function
parameter adjustment, and cold array/tag work. Queue membership is just temporary
scheduling metadata. Only the original scalar coordinator expands children,
performs mutations and decides compatibility in the original traversal order.

### Readiness, barriers and pseudocode

A header task is ready when both IDs are in bounds, the referenced header facts
are stable until consumption, its original query is live, and no helper call is
needed to discover those facts. An already-invalid pair remains an ordered
failure candidate, not an invalid gather. Parameters become candidate children
only after the parent has passed its required checks.

```text
start one existing compatibility query:
    original_order_stack = root pair
    memo = bounded completed-pair table for this epoch
    projected_headers = bounded transient cache

while original_order_stack is nonempty:
    obtain a bounded set of already-existing pending pairs
    project only bounds-safe, immutable header facts; do not expand children
    classify available headers with scalar, bitset, AVX2 or AVX-512 kernel

    pair = next pair in the ORIGINAL scalar LIFO traversal
    if valid completed memo result exists in this epoch:
        consume that result
    else:
        consume this pair's header result, computing scalar if not projected
        on mismatch: return the original query failure through its old caller
        on a pure expansion: push exactly the old children in the old order
        on array-bound evaluation, completion, rollback or other cold barrier:
            discard unconsumed projected facts and invalidate dependent memo
            execute the existing scalar helper in its original position
            establish a new bounded epoch before any later projection
        mark a pair complete only when its required children have completed

release all query-local projection/memo storage
```

An implementation needs explicit completion continuations or a separate bounded
completion stack to distinguish scheduled children from finished ones. That
bookkeeping, hash probes and reverse dependency tracking are real costs. It must
not use the pseudocode's concise wording to mark a parent successful at expansion.
A conservative first version can memoize only fully completed, barrier-free
subqueries and clear the table at every cold helper.

Projecting later pending headers is **read-only speculation**, not speculative
semantic execution. It can still waste loads, occupy cache and observe a snapshot
that becomes stale at a preceding barrier. Count and discard that work. Do not
execute later bound folds, lookups or diagnostics to fill a queue. If immutable
header reads cannot be established within the current helper boundary, process
that region scalar instead.

Function parameter normalization is scalar-authoritative: top-level ignored
qualifiers must not erase pointee qualifiers; array/function parameter adjustment
must match the current implementation; variadic and unprototyped rules remain
unchanged. Named/anonymous aggregate identity is not replaced with a generic
structural hash. Target-dependent bound evaluation stays with the existing
constant evaluator. The proposal preserves current compatibility behavior; it
is not a concurrent standards-correctness rewrite.

For `c_parse_validate_constexpr_declaration`, the transferable subkernel is only
the ready composite leaf-property test (forbidden qualifiers/kinds). Bounds,
initializer-driven completion and traversal-dependent diagnostics remain cold.
The already-optimized scalar-leaf path must stay allocation free. This is a
second consumer of the same readiness idea, not a fourth independent algorithm.

### Complexity and break-even

Let E be pair visits in the original expanded traversal, D distinct completed
pair checks within valid epochs, R the number of epoch-invalidated repeats, Wj
the genuine ready frontier widths **after** deduplication, and H the cold-helper
cost. A useful first comparison is:

```text
Toriginal = E*ColdPair + H
Tscalar_DAG = (D+R)*Cpair + memo_cost + completion_cost + H
Tvector_DAG = projection + memo_cost + completion_cost + discarded_projection
              + sum_j ceil(Wj/w)*Vheader + scalar_expansion + H
```

Vectorization is justified only when it beats `Tscalar_DAG`, not merely
`Toriginal`. Repeated shared-DAG expansion can shrink dramatically under scalar
deduplication and leave little width. Conversely, genuinely broad function
signatures or already-ready independent roots can expose useful frontiers. Both
outcomes are compatible with this design.

| Alternative | Required role |
|---|---|
| Improved scalar | Query-local completed-pair deduplication, cheap leaf handling and bounded work storage; no global mutable cache. |
| Bit-parallel | Ready/failed/state bitsets and stable sparse iteration; classify scalar-projected packed header fields without full vector setup. |
| Scalar-batched | Same projected columns and completion order, multiple pending loads for memory-level parallelism; strong control for an irregular graph. |
| AVX2 | Eight u32 header lanes; normalize kind/qualifier flags, preserve parameter context, gather only after ID checks. |
| AVX-512 | Sixteen lanes and state masks; compact within bounded scratch only when compaction pays; no assumption that all frontiers fill sixteen lanes. |

The 310 parameter entries in the real-source sample occupy only 16.42% of
sixteen lanes when each signature is isolated. That is evidence against
per-signature padding, not a prediction for D or Wj. Capture distinct pairs,
frontier occupancy, pointer-depth chains, fan-out, memo hit rate, completed versus
pending entries, cold barriers and discarded projections. A long pointer chain
has width one; vectorizing it does not remove its dependency. A broad array of
independent already-bound queries is different, provided the caller already has
that population without duplicating analysis.

## Speculation and rejected alternatives

For an attempted speculative batch, use
`T = prepare + validate + useful_kernel + rollback_probability*(rollback +
duplicated_work) + publication + cache/space_cost` and compare with the strongest
immediate scalar alternative. Even a zero rollback probability does not remove
preparation and validation cost. Input-dependent failures require bounded work,
not just a good mean on valid inputs.

| Rejected as an immediate implementation | Actual reason, and surviving useful part |
|---|---|
| Parse all apparent function bodies independently after brace matching | Boundaries alone do not freeze typedefs, tags, entity IDs, inferred types, layouts or diagnostic publication. Keep immutable body token summaries; coordinate semantic readiness with #531. |
| A permanent full-TU token-class/precedence/declaration model | Duplicates existing shape/index/declaration facts, increases fills and cache traffic, and can become a second syntax authority. Keep a query-local summary only where reuse pays. |
| Vectorize every expression using one expression per lane | Different lengths, state transitions and dependency depths require inactive lanes or compaction, while the real query sample is tiny. Use homogeneous ready predicates, not lockstep semantic evaluators. |
| Eagerly fold both conditional or short-circuit branches | Changes lazy constant-expression failures, unevaluated rules and potentially side effects. Classify operators but let existing semantics choose evaluation. |
| Global memoization of compatibility/layout by type IDs | Completion, qualifier context, source scope, target and rollback invalidate answers. Use bounded query-local epochs, or no cache. |
| SIMD arity comparison as a standalone win | Existing scalar predicate is two small comparisons; descriptor stores, deferred failure and discovery can dominate. Establish actual ready batches first. |
| SIMD-expand a shared type DAG without deduplication | Accelerates redundant paths while increasing apparent lane occupancy. Distinct work, not expanded visits, is the useful denominator. |
| Treat every comma at matching delimiter depth as a ready argument/declarator split | Conditional middle operands, declarator structure and initializer ownership need scalar state. Use a mask as a candidate set, not a grammar verdict. |

These are dependency/cost rejections of particular algorithms. They do not imply
that all parsing or semantic analysis must be sequential.

## Primary research: what transfers and what does not

[Langdale and Lemire, *Parsing Gigabytes of JSON per Second*](https://arxiv.org/abs/1902.08318)
establish that validating parsing can profit substantially from SIMD on a
structured language. The transferable lesson here is to isolate cheap parallel
classification from dependency-bearing interpretation. JSON's grammar is not
C's typedef-sensitive declaration and semantic system; its reported throughput
is not a Buster estimate.

[Blelloch, *Prefix Sums and Their Applications*, CMU-CS-90-190](https://www.cs.cmu.edu/afs/cs.cmu.edu/project/scandal/public/papers/CMU-CS-90-190.html)
provides the scan building block. A1's range OR summary is associative, and a
future segmented event projection can carry segment boundaries without pretending
that C semantic transitions are associative.

[Chatterjee, Blelloch and Zagha, *Scan Primitives for Vector Computers*](https://www.cs.cmu.edu/~scandal/papers/cray-scan-supercomputing90.html)
discuss segmented scans amortizing vector startup across datasets. That motivates
measuring cross-query batching rather than padding each tiny query. It supplies
no readiness proof for Buster and no transferable Cray-to-Zen cycle estimate.
These references inform the designs; the source-specific correctness conditions
above are separate obligations.
