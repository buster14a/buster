## Workload

The arms compile the base revision's unity self-host source from a pristine
checkout of the base:

```sh
ide cc -Isrc -Ibuild/v3/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -fsyntax-only \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

The four arms:
- A: base, default flags;
- B: base with `-fc-ast-pilot`;
- C: candidate with `-fc-ast-pilot`;
- D: candidate, default flags.

`-c` uses the same input with `-c -o`, at `-g0` for instructions, and at
`-g0` and `-g` for object identity. Callgrind ran with `--cache-sim=no
--branch-sim=no`. Call counts are summed from the Callgrind `calls=` records,
and call sites are grouped by the `calls=` record's source line.

## Census (base, `-fsyntax-only`, default flags)

`c_parse_incompatible_aggregate_value` is now a wrapper over
`c_parse_incompatible_aggregate_source` (#3624), and Clang inlines it into
its callers. Its unchecked query therefore shows up as calls from each
validator, attributed to the wrapper's query line.

| Call site | Calls | Inclusive Ir |
| --- | ---: | ---: |
| argument checked typing (`c_parse_checked_expression_type` in `c_parse_validate_const_assignments`) | 145,245 | 284,448,538 |
| the wrapper's unchecked query, inlined into `c_parse_validate_const_assignments` (arguments and assignments) | 189,839 | 28,395,716 |
| the conversion check (`c_parse_incompatible_aggregate_source`) at those two sites | 189,839 | 72,879,536 |

- **The second typing is mostly a memo hit.** The per-body memo answers an
  unchecked probe from a stored checked answer
  (`c_parse_expression_query_lookup`). The repeated query averages about
  150 Ir: `c_parse_type_identity_prepare`, the lookup, and a full run where
  the memo holds nothing.
- **The earlier figure.** The 82.9 M in `2026-10-11T170541Z` was the whole
  wrapper, conversion check included. The check stays, so the census put the
  expected saving at about 20 M (0.2%). The budgets' floor was set from
  that: at least 5 M, and more than the 0.05% noise.

## The change

At the call-argument site in `c_parse_validate_const_assignments`, the
argument's checked typing records the type-row count first. The conversion
check goes through `c_parse_incompatible_checked_value`, the helper #3624
added. It reuses the checked type when that typing succeeded and appended no
type row, and types the range again otherwise. Reference-check builds
(`BUSTER_REFERENCE_CHECKS`) also run the base's re-typing for every reused
value, and require the same verdict and message. The assignment site is
unchanged.

## Reading

- **The slice ships.** It passes every hosted budget, but it is small: the
  memo already absorbed most of the second typing, so what is saved is the
  query's setup and lookup, not a typing.
- **Leads left, unmeasured:**
  - the assignment site in the same validator, which pairs a checked typing
    with the same wrapper;
  - `c_parse_type_identity_prepare`, which every query pays before its memo
    lookup (about 32 Ir a call, 53 M in D).
- **Not measured:** wall time and peak RSS. These counts are diagnostic, and
  performance validation is incomplete (#2761).
