The original complete tracked-test object census executed 69,888 rows:

must not be added as if they identified distinct extra failures.

That historical binary reports only the first fallback function on an error.
The new opt-in census records every observed fallback function, with source

they are not declared covered. Ordinary compilation allocates no record array.
The options structure uses seven addressable bytes, because packing its two
diagnostic flags into boolean bit-fields triggered a self-host IR validation
failure. Verification and local promotion remain enabled.

The corrected inventory excludes twelve exact intentional rejection fixtures
and records required C23 recipes in both its input and row manifests. It does
not hide unresolved host/resource headers or convert failed setup into a

## Independent correctness and integration findings

Coverage work includes AArch64 wide atomic updates; public ELF, Windows and
Darwin variadics; Win64 i128 and AVX-512 vector boundaries; aligned outgoing
and private argument storage; scalar x87 operations and ABI transport;
x86 i128 arithmetic; and constrained assembly dataflow/control flow.

The original 396-row strict floor retains every row. Windows and Darwin
AArch64 variadic refusals become strict successes. The floor is not the
retirement census. Native mixed-compiler tests check independent producers and
consumers, copied lists, register and stack exhaustion, value preservation,
alignment, and x87 control-word restoration. Atomic stress is supplementary
memory-order evidence, not an exhaustive proof.

Integration exposed defects not visible in isolated branches:

- Win64 whole-XMM frame transfers needed an explicit `MOVDQU` identity in
  the shared metadata cache after unknown identities became errors.
- Division can split a canonical block. Literal assembly branches must use
  the resulting entry/exit maps when pruning and copying executable edges.
- The diagnostic bit-field representation failed the compiler's own IR
  validator during self-hosting. Addressable flags preserve the verified path.
- GCC required the atomic decoder's signed retry index increment to retain
  a signed type.

At integration snapshot `bad5334f`, Clang Debug passed 1,861,135 assertions
across 47 modules, and the GCC Debug build passed. Earlier snapshot
`2cf5dab0` passed 1,856,565 ordinary assertions and 1,842,471 sanitizer
assertions, each across 47 modules. These observations are explicitly tied to
their source states; subsequent changes require the final combined gates.

Local validation uses a Clang-bootstrapped build driver because the installed
TCC fails in `string.c:991` before these changes. The unchanged baseline and an
early atomic candidate reproduced the ordinary self-host fixed point under
that workaround. It is noncanonical local bootstrap provenance, not a claim
that the TCC gate passed.

QEMU AArch64 execution covers Linux ELF and ABI code from COFF/Mach-O objects
linked into ELF wrappers. Windows wrapper copies remove unwind sections and
verify identical text. These runs do not establish native loader or unwind
correctness. The repository's actual native platform CI remains a distinct
gate, and its status must be read for the submitted revision.

## Retirement decision and remaining acceptance

**Reject production retirement.** Supported direct-only cases remain, and the
complete correctness and performance/resource gates have not been accepted.
Production fallback, `none`, and the direct-native implementation remain.

The final attributed census is the source of the remaining worklist. Historical
leads that must be reclassified against that candidate include narrow/split
x86 vectors, general inline-assembly templates and physical/memory operands,
over-aligned SysV variadic reads, and AArch64 wide-float conversion/sign cases.
In particular, `basic_c_created_nan_sign.c` compiled through the old direct
AArch64 path, so wide-float cases cannot be dismissed collectively as
unsupported by both backends. Fix each confirmed gap while retaining its
original source and an independent ABI/runtime oracle where applicable.

The declared object matrix does not by itself freeze external workloads or
host header dependencies, exercise every CPU profile, prove native unwind
behavior, or establish a self-host fixed point. Those remain explicit gates.
After coverage closes, production-dispatch retirement and direct-emitter
deletion require separate reviewed changes and a new complete acceptance run.

The dedicated 9700X host (`benchpress`) could not be resolved from this
environment. The available machine is an Intel server and was shared by
correctness jobs; its elapsed times are not acceptance measurements. No
compile-time, peak-memory, output-size or generated-runtime limit is invented
or marked accepted. Choose limits before collecting the exclusive matched
9700X observations, retain raw measurements, and record an explicit decision
before production dispatch or deletion changes.
