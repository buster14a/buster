## Outcome

The worklist implementation in #834 is a measured improvement on the dedicated
Ryzen 7 9700X. Against the refreshed `main` parent, three interleaved pinned
runs per compiler reduced median wall time by **3.6343%**, cycles by **3.7174%**,
and retired instructions by **4.9881%**. Every warm-up and timed compile
produced the same SHA-256 output.

This audit establishes the requested before/after result for #789's affected
stage-1 compiler workload. It does not claim the same percentage for every
input or for generated-program runtime; the repository's hosted throughput,
correctness, differential-oracle, and fixed-point checks remain the broader
acceptance evidence.

## Host and method

The host was an AMD Ryzen 7 9700X, 8 cores / 16 threads, microcode
`0xb404038`, Linux `6.18.50-2-lts`, Clang `22.1.8`, CMake `4.4.3`, Ninja
`1.13.2`, and perf `7.2.4-1`. Boost was enabled; CPU 2 used the
`amd-pstate-epp` driver with the `powersave` governor and
`balance_performance` preference. The workflow recorded
`perf_event_paranoid=2`.

Both compiler binaries were independently built as trusted Clang Release unity
builds with mold. To isolate the allocator implementation while holding the
compiled input constant, both compilers then compiled the candidate tree's
stage-1 unity source:

```text
cc -Isrc -Ibuild/generated -DBUSTER_UNITY_BUILD=1 \
  -DBUSTER_INCLUDE_TESTS=0 -g src/buster/apps/ide/ide.c -lm
```

The workload was pinned to CPU 2. One warm-up per compiler preceded six timed
runs in the interleaved order base, candidate, candidate, base, base,
candidate. `perf stat` recorded user-space cycles and instructions; wall time
used nanosecond timestamps around the same command. The warm outputs were
byte-compared before measurement, and all timed outputs were checked by
SHA-256.

## Correctness and scope

The candidate retains the old whole-graph solver as a test-only oracle and
compares it with the production worklist on a 1,025-slot nested-loop fixture.
The worklist is bounded by the slot count, only queues predecessors when a
monotone live-set merge adds information, and preserves the old equation and
successor order. Exact-head hosted checks cover the wider compiler matrix,
self-host fixed point, TCC bootstrap, GPU acceptance, native-retirement gates,
and the repository throughput suite.

The sample count is intentionally small and this audit is not a confidence
interval for arbitrary workloads. It is sufficient to reject the principal
risk for this narrowly scoped change: on the dedicated target host and the
stage-1 unity workload that exercises this allocator, the new solver is not a
regression and produces exactly the same executable while retiring about
832 million fewer instructions per compile.
