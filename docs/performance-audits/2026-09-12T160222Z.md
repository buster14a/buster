## Scope and frozen inputs

[GitHub #117](https://github.com/buster14a/buster/issues/117) concerns the
compiler's ELF link time and temporary storage. Baseline:
`fd0ba8ff8175952d12bbdb367adef13effcc4865`. Implementation:
`4da3c2fc891aa987a13768ec37a511fc80973eea`, tree
`13ca31c6044e37a45fc52101fac37bb616f58c52`. This audit adds evidence only.

`LinkElfIndex` builds name and (export-table identity, address) indexes once
per ELF link. Runtime/library/export order still chooses the first data
definition and, independently, the first default version. Import classification,
version binding and the AArch64 overlay share that index. Each data group keeps
an export-order alias chain and its first imported owner. Indexed global-name
membership and per-owner alias deduplication preserve the old sizing rule:
skipped globals, imports and duplicate aliases do not enlarge a copy slot.
Version pairs retain first-use numbering and per-library emission order.

The former import-by-export, import-by-import, alias-by-global and
alias-by-alias full scans are removed. With ordinary hash distribution,
index construction and queries scale with the tables, imports and emitted
aliases; this is not a worst-case collision-complexity guarantee. Buckets stay
below half occupancy and compare complete names/keys. Aggregate counts,
capacity rounding and index arena byte requirements are checked. Every link
rewinds the index arena, including failure paths. No frontend or native
code-generation pipeline is added.

Both measured compilers are ordinary Clang 18.1.3 Release unity builds with
`-O3 -DNDEBUG -march=native`, debug information and frame pointers ON, tests
and libc ON; sanitizers, fuzzing, LTO and allocation instrumentation OFF.
The baseline executable is 38,604,328 bytes, SHA-256
`1352c27ee82df1d1a073ab2b204e54246da503f776b7702a966a7c64e7b7f7da`.
The candidate is 38,659,352 bytes, SHA-256
`17a8cf9d0fd3ce6dda585bd1f3c556ce8b385b9e465892c4316dee8bc8fdd4a6`.

## Whole-process paired measurements

The registered driver generator builds real DSOs with `clang -g0 -O0 -fPIC
-shared` and objects with `clang -g0 -O0 -fPIE -c`. The objects use volatile
pointer temporaries so Clang cannot fold two external names as unequal before
the linker can establish their alias relationship. GNU/system-linker controls
and Buster images both execute, checking addresses and writes visible through
the DSO's own references. Generation and execution are outside link timing.

The objects shape has N distinct data objects, 3N data exports, 2N data imports,
N function imports and N unrelated globals. The aliases shape has one data
object, N aliases, N+1 data imports and one function import. Libc and the two
hosted-runtime imports are additional fixed work. The tiny control imports
`puts` from a separately compiled object. All inputs are frozen across A/B.

The native collector records one warmup per variant/job and eight alternating
AB/BA pairs for each of 15 jobs: **270 successful links, including 30 warmups**.
Every one of the 135 pairs is compared byte for byte, and both final images for
every job execute successfully. The interval includes fork/exec, startup,
object/DSO reading, the full link and image writing. User/system CPU time and
maximum RSS come from `wait4`; output checks and program execution are outside
that interval. No task-owned build or test was running during paired collection.

This is an unpinned, shared KVM guest; other sessions and frequency/scheduling
variation remain possible. Files and outputs were on tmpfs after the shared
root filesystem filled. These are warm, memory-backed link workloads, not disk
throughput, cold-storage measurements or physical Zen 5 evidence.

The N=4 DSO cases have **higher candidate wall medians by 0.626 and 1.127 ms**.
Their paired ranges cross equality; index construction adds fixed work and
this run does not establish a small-link non-regression budget. The tiny
control and the largest alias row are particularly noisy. Ratios are medians
of paired ratios and need not equal ratios of separate medians. All rows and
observations are retained rather than selecting favorable samples.

Hardware instructions are unavailable: a native `perf_event_open` probe for
`PERF_COUNT_HW_INSTRUCTIONS` returns `ENOENT` (2), and the build-driver counters
emit no `STEP_INSTRUCTIONS`. No retired-instruction result is claimed. RSS
values are retained in the raw CSV but are not a temporary-memory acceptance
claim; they include the entire compiler process and fork/exec effects.

## Dedicated index memory and writer replay

The registered synthetic replay invokes the same executable writer with a
fresh, caller-owned index arena, then checks its rewind and high-water mark.
Input construction, hashing, ELF inspection and optional reporting are outside
the timer. Repeated calls reuse dirty arenas and must produce identical images.
Shape 0 includes paired imports, duplicate aliases, unrelated globals and one
version per object; shape 1 grows one object's duplicate aliases.

## Correctness and limits

- Release tests plus geometric benchmarks: **2,165,701/2,165,701 assertions,
  47/47 modules**. This includes generated DSOs and system-linker controls.
- ASan/UBSan Debug: **2,116,134/2,116,134 assertions, 47/47 modules**.
  Leak detection is disabled because a standalone LeakSanitizer probe fails
  while opening `/proc/.../task`; no leak-check pass is claimed.
- Release self-host: **38,389,720-byte byte-identical stages**; MIR_STACK
  compilation/benchmark and NONE compilation pass. The baseline fixed point
  passed at 38,382,528 bytes.
- cJSON 1.7.19 at pristine `c859b25da02955fef659d658b8f324b5cde87be3`:
  **18 core tests, 3 utility tests, all four allocator round trips and the
  native Buster link smoke pass** with the final Clang-built compiler.
- Execution-mode matrix: **24/24 link legs pass, 4 execute natively**.
  No disassembly oracle or AArch64 emulator was available locally; the other
  20 legs are link-only evidence, not execution passes.

Focused regressions additionally cover runtime/library precedence, equal
virtual addresses in distinct tables, different-length views of one backing
table, repeated version names, suppressed globals, local names, first-default
version selection after hidden entries, unavailable export lists, checked
aggregate counts, and repeated dirty-arena reuse. Existing x86-64/AArch64 copy,
weak-import and version regressions remain registered.

TCC 0.9.27 fails while bootstrapping unchanged `string.c:991` (`array type
expected`). Local validation therefore used a Clang-bootstrapped build driver;
this is not the canonical TCC-bootstrap gate. Two validation attempts were
interrupted by the shared root filesystem filling; the final suites were rerun
from the memory-backed checkout. Neither interrupted run is counted as a pass.
Initial fixture-only failures were corrected: formatted C braces must be
escaped, and alias address comparisons must survive host compilation.
GitHub checks and mergeability are reported separately on the final PR head.
