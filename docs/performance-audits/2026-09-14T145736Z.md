[ir_fast_dce](https://github.com/buster14a/buster/blob/e5620bc16f675d9165d175fceb38c317c5d2ff8c/src/buster/lib/compiler/ir/ir_fast.c#L307-L351)
and [ir_fast_parameters / ir_fast_function](https://github.com/buster14a/buster/blob/e5620bc16f675d9165d175fceb38c317c5d2ff8c/src/buster/lib/compiler/ir/ir_fast.c#L353-L489):

- DCE's initial instruction/operand walk, incoming occurrences and deletion
  queue update visits. The intervening instruction seed loop does not.
  `memset(uses, 0, sizeof(u32) * value_count)` is another unrepresented byte
  count. Root traversal also needs its own count, not one unit per call.
- Parameter cleanup increments visits for parameters and incoming occurrences,
  not the outer block loop or `last_parameter` maintenance. With B blocks and
  S executed sweeps, that loop performs B*S block iterations. This is an
  analytical conditional count, not a measured sample. Its bounded sweep
  policy must not be mistaken for an unbounded fixed point.
- Admission scans, common replacement/removal initialization and final CFG
  publication have separate obligations. Per-pass timings are not complete
  compiler timings, and skipping a pass can reflect a work/provenance budget
  rather than an algorithmic improvement.

These omissions are **already covered by #590**, not a distinct new issue.
The [middle-end map](https://github.com/buster14a/buster/blob/e5620bc16f675d9165d175fceb38c317c5d2ff8c/docs/middle-end-pass-map.md)
also distinguishes frontend SSA cleanup, shared promotion and optional FAST
cleanup. `IR_LOCAL_PROMOTION_WORK` measures shared promotion only; zero there
cannot establish zero frontend or FAST work. Adjacent #584/#576 research is
an ownership lead, not permission to modify its implementation.

### Scope, transformations and independent validity

Initial configuration: supported native Linux x86-64 C11, direct frontend SSA,
FAST allocation, explicit target/CPU/optimization flags, no debug information.
Use one frozen trusted Clang-built Buster for source variants P and Q, not
self-built stage binaries. Freeze the host compiler, headers, link inputs and

Use exact 64-bit unsigned arithmetic, guarded by the existing generator's
value-range assertion. All generated variables are initialized; expressions
are pure addition/multiplication of parameters and small constants. No
includes/macros, stringification/pasting, location builtins, signed overflow,
shifts/division, floating point, volatile/atomic accesses, external effects,
VLA, pointer aliasing or unsequenced side effects enter this initial grammar.
Keep the externally visible function signature and set of definitions fixed.

| Relation | Preconditions / equivalence rationale | Legitimate growth to charge |
| --- | --- | --- |
| Redundant parentheses | Wrap a complete pure operand/expression, never token substrings; preserve precedence and type. | Extra source and parser tokens, nesting storage. |
| Grouped versus split declarations; independent order | Same unqualified unsigned scalar type. Fresh names, initializers read parameters/constants only, never another declared name. No storage/attribute/linkage change. | Declaration syntax/records; do not assume identical parser node counts. |
| Scalar typedef indirection | Fresh aliases of the same unsigned scalar type, no qualifiers, pointers/arrays/functions, tag changes or shadowing. Uses resolve to the same value type. | Added alias declarations/type queries, even though runtime work is unchanged. |
