## Scope and validation

Implements [#314](https://github.com/buster14a/buster/issues/314) on baseline
`fd0ba8ff8175952d12bbdb367adef13effcc4865`. Measured implementation:
`34aeb115af4b7a0f99920f6afa53a12e06c59145`, tree
`3ce81274d1d274567fd03e64e414edbaf364399d`. This audit changes no source.

`ByteWriter` replaces the private CodeView/PDB buffer types and their append,
zero-fill, integer, alignment and patch primitives. Each format retains its
arena allocation, capacity estimates, layout and invalid-result checks. State
remains 32 bytes. There is no callback, allocation in the writer, or extension
to object/codegen writers. See the [contract](../byte-writer.md).

## Complete debug-output workload

Synthetic C inputs contain 128 or 1,024 functions with distinct structures,
arrays, locals, scopes and lines. Both Windows targets emit COFF objects and
link PE/PDB pairs. Additional 1,024-function cases split across four modules.
Targets are x86_64-windows and aarch64-windows.

Ten cases each run one warmup per binary and eight alternating AB/BA pairs:
160 measured compilations and 20 warmups, all successful. Every complete
COFF/PE/PDB output is compared byte-for-byte to the first output for that case;
all ten cases are identical across binaries and repetitions. Source/output
paths, flags and bytes are identical within each comparison. Timing includes
startup, frontend, codegen, debug emission and output writing/linking; comparison
and hashing are outside the timed interval.

LLVM 18.1.3 independently reads all six PDB workloads from each binary with
`llvm-pdbutil dump -summary -modules -types -symbols -l -section-contribs`.

All paired ranges, including object-only cases, span one. The host is an
unpinned Intel KVM guest; other shared-host work remained possible. Task builds
and full tests finished before workload timing. These are cross-compilations,
not AArch64 execution or physical Zen 5/Zen 4 measurements. Whole-workload
throughput is inconclusive: neither a speedup nor a stable regression is
established. This public audit contains aggregate results only; raw local logs
and decoded output files are excluded. No PMU, allocation-level memory saving,
or generated-program runtime improvement is claimed.

## Admission and integration limits

The bounded pair removes duplicate write authority, makes terminal failure
explicit, and reduces writer code size on the measured configuration. Noisy
complete-workload timings justify no expansion to object/codegen writers.
Supported-platform/full-sanitizer CI must be assessed for the submitted revision.

Baseline main already has failed workflow lint/mobile fake-tool checks that
reference removed .forgejo files, and a GPU SPIRV-Tools version mismatch. Those
remain integration gates; they are not recorded as green.
