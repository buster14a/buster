## What the tree could answer exactly

A member is **plain** when its tokens are only identifiers, numbers, `*`, `[`,
`]` and `,`, and no identifier is an attribute, `__declspec`, asm,
`__extension__` or `_Static_assert` keyword, or an alignment (`_Alignas`,
`aligned`, ...) or vector-size word. On a plain member, every scan the segment
runs for decorations finds none:
- each `c_parse_skip_attributes` call;
- the alignment frame, which appends nothing;
- both layout-attribute scans, which leave `packed` unset;
- the vector-attribute scan, which returns the type unchanged;
- the `_Static_assert` test.

The plain census marks **9,691 of 9,867 segments (98.2%)** plain, with the
predicate's own 2.05 M charged to the census only.

**The oracle.** It skips exactly those scans on plain segments, and keeps the
checkpoint, the declarator parse and every row the segment appends. Its
objects are byte-identical to the base's under the pilot:
- `-g0`: `88413a01505ee337…`, 31,485,944 bytes;
- `-g`: `8a2cc25d981e7c4b…`, 49,869,696 bytes.

Its drop is the most any read of these members can remove:

| Part removed | Ir |
| --- | ---: |
| `c_parse_skip_attributes` (49,358 → 894 calls) | −3.02 M |
| alignment frames | −1.85 M |
| layout-attribute scans | −1.33 M |
| the segment's own code (the `_Static_assert` test, the alignment child's push) | −1.16 M |
| vector-attribute scan | −0.39 M |
| **whole compile** (9,380,905,634 → 9,373,190,975) | **−7.71 M** |

Split by the rows the slice names, each is below the 5 M gate on its own:

| Row | Removable |
| --- | ---: |
| segment frames and checkpoints (the `_Static_assert` test and its attribute skip; the checkpoint is kept for rollback) | about 1.8 M |
| alignment frames | 1.85 M |
| member declarators (the three attribute skips around them) | about 1.8 M |
| layout attributes (both scans, the vector scan, the skip after the type) | about 2.3 M |
| aggregate range frames (not in the oracle) | at most 1.74 M |

**The tree test.** A read must prove a member plain from the tree before it
skips anything. The prototype:
1. looks up the member's word-only `DECL_SPECIFIERS` list
   (`c_parse_specifier_node`);
2. walks forward to its `MEMBER_DECLARATION`, admitting only these nodes:
   - `MEMBER_DECLARATOR` with only its declarator bit;
   - `DECLARATOR_POINTER` without an attribute list;
   - `DECLARATOR_ARRAY`, `DECLARATOR_NAME`;
   - numbers, characters, identifiers and arithmetic operators in array sizes;
3. tests each name, identifier, typedef name and specifier word for the
   decoration words above.

Results on the same input:
- **Answers:** 9,645 members plain (97.7%). 114 have no word-only list at their
  first token, 101 contain another node kind, and 7 contain a decoration word.
- **Disagreement:** one member is admitted by the tree test but rejected by the
  token predicate. It was not identified further.
- **Exact test:** 3.32 M inclusive (336 Ir per member). It also makes #3812's
  member read 0.18 M cheaper, because its lookup finds the cursor in place.
- **Lean variant:** dropping the specifier list's own checks costs 2.44 M (247 Ir per
  member). It is not exact: `__extension__` in the list, or a typedef named
  `aligned`, changes what the machine's skips and alignment frame do.

**Net, against the 5 M gate:**
- exact test: 7.71 − 3.32 + 0.18 = **4.57 M, below the gate**;
- lean, inexact test: at most 5.45 M. It is an upper bound for a test that
  would need the dropped checks back to ship.

The whole-compile deltas are larger than the tests' inclusive costs, by about
1.1 M in both builds. Exact test: +4.55 M against the plain census. Lean test:
+3.65 M. Part of that is the census call site copying the preprocess record by
value; it is not charged above.

## Decision

No shape clears the gate, so no code is written.
- **Each named row** is below 5 M.
- **The combined plain-member read** removes at most 7.71 M, and its exact
  tree test costs 3.14 M net of the read's saved lookup.
- **The default path** is also nearly out of room. #3812's single inlined
  branch in this frame step used +0.046% of the ±0.05% band
  ([`2026-10-12T134037Z`](2026-10-12T134037Z.md)). A plain-member branch would
  add more code to the same loop.

## Validation and limits

- Callgrind counts instructions, not time, on `-march=x86-64-v3` builds whose
  AVX-512 kernels are compiled out. One input, one host, single process.
- The plain predicate and the tree test are census instruments, not reviewed
  code. The oracle's object identity covers this input only.
- No 9700X comparison is requested. Zen 5 validation stays **incomplete**
  (#2761), and the pilot-default switch stays on hold.
