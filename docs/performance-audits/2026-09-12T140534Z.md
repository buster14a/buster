## Scope and frozen revisions

[GitHub #255](https://github.com/buster14a/buster/issues/255) concerns compiler
implementation work and scratch storage for nested GNU C expressions.
Base: `719ba64e3022a0ae1db078ea97cb951a70ac02a0`.
Measured local implementation: `f0e9fd0cb8d0546363bf6ee717ac66236d5d8d5e`, tree
`9a92bde67bf5cef25fe408cc26284f52aea30f87`.
The retained [implementation patch](evidence/2026-09-12T140534Z/implementation.patch)
reconstructs that measurement checkpoint from the base, including its tests.
These results remain tied to that checkpoint; subsequent rebase validation is
reported separately in the PR description and checks.

`c_parse_direct_expression_type_core` replaces both recursive descents with
explicit prefix/postfix continuations and one query-sized scratch allocation.
Scratch is rewound on success and failure; newly constructed types remain in
the translation-unit arena. Both this helper and `c_type_parse_sizeof_step`
reuse the parser's delimiter index to skip whole nested ranges. Consecutive
unary tasks retain their completed operator scan until a parenthesis exposes
a different range. There is no new expression-depth cap.

The independent oracle also exposed an existing comma conversion error:
`typeof((0, array))` retained an array, so initializing the corresponding object
from a pointer failed. Both typing paths now apply value conversion at commas:
arrays/functions decay and top-level qualifiers disappear, while bare typeof
operands and pointee qualifiers remain intact.

## Deterministic work and storage

The diagnostic build substitutes an instrumented parser object into the ordinary
Clang Debug executable. It counts actual loop iterations in the direct helper
family and sizeof task walker, plus requested direct-query scratch bytes.
It excludes delimiter-kernel internals, lookup/type-interning work, and other
frontend passes: these are traversal counts, **not retired instructions**.
Diagnostic binaries are never used for timing. All 45 diagnostic compilations
succeed. The instrumentation and raw records are retained.

| postfix | 16,384 | not run / 180,240 | not run / 1,376,382 B |

`postfix` wraps nested comma operands before `->value`, forcing the formerly
recursive direct helper. The plain comma case mainly exercises the surrounding
task walker, which also needed repair. Fourfold depth increases approximately
quadruple patched traversal and scratch rather than multiplying them by sixteen.

The registered geometric tests independently call the production helper with a
fresh arena, check its dirty high-water mark after rewind, and require the
output/scratch contract on failure. They cover six shapes at depths 64, 256,
1,024, 4,096 and 16,384: commas, parentheses, `*&` chains, grouped mixtures,
arithmetic-unary mixtures, and a member suffix over comma bases.
The deepest postfix probe uses 1,376,370 scratch bytes (the fixture differs
slightly from the standalone diagnostic input). Retained parser-arena growth
for that fixture is 636,644 B at depth 64 and 22,774,724 B at 16,384; the gate
allows fixed builtin-table overhead plus 512 B per token. Separately allocated
type-machine buffers are included in the standalone raw records and also scale
linearly. Requested/retained arena bytes are not physical resident memory.

`-O3 -DNDEBUG`, unity and tests ON, `-march=native`, debug information and frame
pointers ON; sanitizers, fuzzing, LTO and allocation instrumentation OFF.
Each process runs `cc -g0 -std=gnu23 -fsyntax-only`, including startup,
preprocessing, delimiter-index construction and complete syntax/semantic checks.
This is frontend throughput, not object emission or generated-program speed.

There are 23 paired jobs, one warmup per variant/job, and eight alternating
AB/BA pairs per job. Four additional largest-depth jobs run only on the patch.
All **400 measured processes and 46 warmups succeed** with empty diagnostic
output. Input/binary hashes, argv, every observation and the full summary are

The 16,384-level comma input has roughly 131× lower median wall time in this
sample. Large prefix/mixed/postfix cases also improve. The small controls and
ordinary-parenthesis timings are **inconclusive**: their ranges cross equality,
and the tiny control has especially large scheduling noise. Nonmonotonic wall
medians are retained, not smoothed. These observations do not establish a
whole-compiler non-regression budget or performance on physical Zen 5.

Raw `wait4` maximum-RSS values are retained but not used as a memory acceptance
claim: process creation can inherit the collector's pre-exec high-water mark,
and arena reservations need not become resident. The explicit arena probes
above establish the storage result.
