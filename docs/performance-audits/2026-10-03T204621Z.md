## Subjects, scope and method

This records #313 and PR #2550. Baseline is
`97fb07f42b432864bee9fd38b70eb69b15252991`; candidate is
`735d270728441245c5a1d1721220c16408b101b9`. The candidate considers the
complete eligible population, retains the best 4,096 weighted-benefit
intervals and uses lower virtual-register IDs for ties. Candidate, retry,
pin and span budgets remain fixed. Below the cap it appends without
per-entry heap work; at the cap it worst-heapifies once, and final
placement best-heapifies the retained set. This changes equal-weight
placement order below the cap as well.

Trusted Clang Release compilers built serially in the same source/build
path, with tests, unity compilation and allocation instrumentation off.
Immutable ordinary binaries were copied before any trial. A third,
allocation-instrumented build supplied only untimed diagnostics.
The corrected full experiment ran on an ordinary GitHub Ubuntu x86-64
AMD EPYC 9V45 VM; this is not dedicated Zen 5 acceptance.

Four frozen C sources vary early/late hot and equal forward/reverse
logical order. Each contains 4,097 logical values from initialized,
volatile 16-word input. An independently Clang-compiled host driver
checks all 4,097 outputs against an integer oracle over four seeds.
Runtime timing covers exactly 256 probe calls and excludes setup and
oracle work. Compile timing covers fork/exec/wait for an ordinary
uninstrumented compiler with `-g0 -O0`; NONE is a direct reference with
`-fmachine-fallback`, FAST/QUALITY require `-fno-machine-fallback`.
Fixed first-allowed-CPU affinity is inherited by all children.

Each shape/mode/operation retains one warmup A/B pair and twelve
alternating measured pairs. Pair 0 is excluded from every statistic.
All 312 compiler and 312 generated-runtime observations passed;
every runtime log certified four seeds, 4,097 checks, 256 calls and
checksum `cea99979d348fb5d`. All twelve compile/runtime cells passed.
Frozen source, compiler, object and executable manifests verified.
Census output matched the ordinary candidate object byte-for-byte
for every shape. No compiler/probe or timing ran locally.

## Isolated admission cost

The successful admission micro run used GitHub Ubuntu x86-64 AMD
EPYC 9V74, distinct from the full experiment's 9V45 VM. Its artifact
is 11284607791, ZIP SHA-256
`02e680b7031dd62c3867db8832650e03de4ddb34891b55c7198b58f348ad85c9`.
A C extractor retained the exact source-head selection helpers and
verified their interval layouts. A shared wrapper reproduces prefix
selection versus complete-population offering, followed by placement
heapification. It excludes eligibility/lifetime discovery, inverse
maps, pinning and placement. Every input is already eligible.

Separate translation units with no LTO preserve 4,096 opaque calls
per child. An independent rank/set/payload/heap/canary oracle runs
before and after timing. All 312 children and oracle certificates
passed. Each cell retains one warmup and twelve alternating pairs;
warmups are excluded below. Fixed CPU 0 affinity is inherited.

Extra ns/op is the difference of separate variant medians, not the
median of paired deltas. C/B is the median of per-pair ratios.

Traffic weights exceed 2^40. IDs are permuted by
`(index * 4051 + 11) % population`, bijective for these populations.
Production scans IDs in increasing order. Equal-weight micro cells
therefore cause extra tie work and do not estimate production's
equal-weight cost; they are a conservative permutation stress case.

## Disposition

Retain the existing prefix policy. The best-K proposal is functionally
validated, but this batch does not admit it into production. The real
compiler corpus observed no cap hits. The synthetic late-hot case
removes eleven spill/reload edits and 41 bytes, but supplies no reliable
generated-runtime improvement. Admission costs are clear in the
isolated experiment, while full compile/runtime observations are too
noisy to establish profitability or performance-budget compliance.
Given compiler throughput priority, these observations do not justify
charging the broader population for the demonstrated narrow benefit.

This is a conservative admission decision, not proof that every best-K
policy loses. #313 remains open for a lower-cost approach or a workload
with reproducible cap incidence and runtime benefit. PR #2550 retains
the measured candidate revision in its history and publishes only this
audit after restoring its production, tests and policy documentation
to baseline. No performance threshold, allocator limit or frozen
support corpus is changed. A successor must repeat the relevant
measurements against its exact source revision rather than reuse this
packet as evidence for different code.
