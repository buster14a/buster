The member-name subcase of [#1403](https://github.com/buster14a/buster/issues/1403)
is rejected as a major compiler-throughput opportunity on the tested corpus.
It is a newly reproduced source-name sensitivity with transitive amplification;
it is not a measured speedup or a demonstrated language miscompile. No
production change is proposed.

One `.trigger = 7` member designator caused an unrelated static `trigger`
function and its dependencies to be emitted. Changing only the equal-length
member spelling to `payload` eliminated that graph. The largest synthetic case
emitted 257 extra functions. Four successfully compiled real inputs had no
affected member references. SQLite was not observed: both compiler variants
failed before the census footer. The overall run remains failed; successful
per-input results are reported separately.

The disposable workflow and runner have been removed from this branch. The
exact packet remains at immutable diagnostic commit
[`df7734844ac3d0005ab95512bd75b3eaf0924490`](https://github.com/buster14a/buster/tree/df7734844ac3d0005ab95512bd75b3eaf0924490/tools/research/initializer-roots).
Its README, generator, observational patch, and workflow describe reproduction.

## Source and method

Production source: `ade6ac4b6ecb21f30b61b656439bac476c145e2f`, tree
`4c5306221fdb22fccc929b55e333163742de17d0`. Diagnostic commit tree:
`f247330f1be5215902405900884c506ec0f95a4c`. The diagnostic commit adds only
experiment files; it does not modify production compiler source.

In `c_lower_to_ir_with_options`, the file-scope object-initializer reference
scan excludes identifiers following `.` or `->` when marking objects. Its
neighboring function-reference scan resolves every identifier at scope zero
without that exclusion. A member spelling can therefore mark an unrelated
function as referenced outside a function body. The existing dependency
worklist propagates the mark to its transitive dependencies.

The probe preserved production decisions and recorded those member-token marks.
It replayed the existing function dependency closure after removing only those
marks, preserving nonmember initializer references, public definitions,
ownerless references, aliases, cleanup edges, and constructor/destructor roots.
Explicit section handling was preserved when counting body eligibility.
Other identifier roles and internal-global reachability were not measured.

Counters describe function-body eligibility before signature checks and body
lowering. They are structural upper bounds, not instructions, semantic work
avoided, machine-code bytes saved, or compile-time savings. Synthetic symbol
tables independently check actual emitted private functions.

The GitHub-hosted `ubuntu-26.04` job bootstrapped the native build driver with
Clang, configured Release using `generate --cc clang --ci --linker DEFAULT`,
and passed `test_self_host --config Release` before freezing the baseline.
It applied the observational patch, rebuilt `ide` with the same native
driver/configuration, froze the probe compiler, and restored source before
compiling any compared input. Source restoration matched both Git blob and
SHA256. Every input pair used identical source paths and command flags.

## Synthetic mechanism and controls

Each member-name family defines `trigger` plus a private function chain. Its live
external record contains an integer initialized through a member designator;
`main` reads the member. The renamed variant preserves the value and uses
`payload` instead of `trigger` throughout the record declaration and use.

| Chain length | Emitted unrelated functions, `.trigger` | Emitted unrelated functions, `.payload` | Current / replay eligible bodies, `.trigger` | Current / replay body tokens, `.trigger` |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 2 | 0 | 3 / 1 | 26 / 7 |
| 32 | 33 | 0 | 34 / 1 | 398 / 7 |
| 256 | 257 | 0 | 258 / 1 | 3,086 / 7 |

Every `.trigger` case had exactly one member hit and one member-only seed.
The function counter includes `main`; the emitted-symbol count covers only
`trigger` and the chain helpers. The largest case retained the first 128
dead-function rows but counted all 257; its footer reports 129 suppressed rows.

At each chain length, genuine function-pointer, constructor, and alias roots
kept the full chain live in both production and replay. All 15 synthetic cases
passed expected `nm` symbol counts, native linking, and execution with both
compilers: 30 successful program executions. Runtime checks establish fixture
behavior, not performance of the generated programs.

rooted, and semantic diagnostics must remain intact. Only substantial real
removable work would justify implementing a graph or requesting performance
acceptance. The synthetic amplification here does not establish that premise.
