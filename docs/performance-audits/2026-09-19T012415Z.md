## Outcome

Issue #790 is solved by adding a second stable counting-sort partition to
`DebugLocationIndex`, keyed by `(function_symbol, local)`. Exact local-variable
queries use that partition; `IR_LOCAL_ID_INVALID` keeps the existing
symbol-only wildcard partition. Both partitions contain indexes into the
caller-owned seed array, so construction does not mutate or reorder the seeds.
Model-boundary validation proves endpoint monotonicity, complete coverage,
bucket membership and stable source order for both partitions before lookup.

The old path scanned every seed in a function bucket twice for every local,
first to count and then to copy matching ranges. The new build remains linear
in the seed count and exact-local lookup scans only the pair hash bucket plus
its collisions. Wildcard/global behavior is unchanged.

## Correctness and byte identity

The focused regression seeds two locals from the same function in interleaved
order, plus a colliding local from another function. It compares indexed and
linear exact-local results, verifies wildcard `(symbol, any local)` order,
checks the original seed bytes remain unchanged, and extends fail-closed index
validation to malformed exact-local endpoint/order arrays. Stale indexes for a
different seed slice are rebuilt rather than trusted.

## Acceptance

The implementation preserves wildcard semantics and emitted debug bytes,
removes the per-local whole-function rescan, and produces a measured 4.12%
end-to-end stage-1 `-g` wall-time improvement on the required Ryzen 7 9700X.
No performance threshold is regressed: RSS falls slightly, `-g0` is statistically
flat at this resolution, and generated objects are byte-identical in all three
required allocator modes.
