## Disposition

The measured cause is broad symbolic execution over many functions and millions of `PostStmt`/dead-symbol visits. The current profiles do not identify a duplicated helper, single dominant entry point, or repeated source path whose elimination would safely preserve the analyzer’s valid paths, diagnostics, assertions, and test coverage. The top four account for long analyzer time because each contains many analyzed functions; splitting a file or pruning those functions would relocate or remove required analysis rather than reduce its work safely. I found no evidence-backed source remedy, so **no production or test source was changed**. A no-change result is the supported disposition; there is no code rollback to perform.

No candidate source change was selected, so candidate/baseline A/B measurements are not applicable and no speedup claim is made. These measurements ran on an AMD EPYC 9V74 KVM cloud host, not the approved Ryzen 7 9700X; they are diagnostic only. No Zen 5 performance validation is claimed. A future source-level proposal would need a specific profile-supported invariant and fault controls, then predeclared repeated uninstrumented candidate/baseline runs with the full selected inventory and applicable approved-host evidence.
