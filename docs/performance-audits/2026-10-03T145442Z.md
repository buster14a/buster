The former merge discovered each named set with a growing linear name scan,
then scanned every input section for each distinct set. It also scanned the
entire set list for each requested bound. N distinct singleton sets and B
bound references could require quadratic name/section work.

The candidate gathers contributions once, heapsorts records by name and
original ordinal, and forms name-sorted group ranges. First-ordinal dispatch
places groups in their original first-input order; members retain input order.
Bounds binary-search the same index. Indexing and lookup have
O(N log(N+1) + B log(N+1)) name comparisons, plus linear input collection and
placement. Byte-string comparison cost, the ordinary symbol-table scan, output
copying and other linker work remain outside this bound. Heap ordering avoids
a hash-dependent collision bound.

Mixed ordinary data kinds still merge to DATA. Code/data mixtures retain the
earliest conflicting original input's named refusal, even when its name sorts
after another invalid group. Alignment, virtual tails, pure code/zero-fill,
requested bound flags and user definitions keep their contracts. More than
UINT32_MAX contributions refuse before indexing.

Three index arrays reserve N times (`sizeof(LinkSectionSet)` +
`sizeof(LinkSectionSetMember)` + `sizeof(u32)`) bytes, plus arena alignment.
On supported 64-bit host layouts this is 76N requested scratch bytes, versus
the previous 40N retained set reservation: more temporary storage buys bounded
searches, and all three arrays are released on success/refusal. These are not
process RSS or measured resident traffic. Inputs with no extra sections keep
the scratch-free route. Other merge arrays remain unchanged. Nested initializer
scratch saves its own position and rewinds without erasing the index scope.

Registered `link_test_section_set_scaling` uses 1/2/8/32/128/512 identities,
three deterministic input orders and three name-density shapes over three
objects. An independent numeric-identity oracle checks complete output bytes,
offsets, alignment, mixed-kind routing, strong/weak requested bounds, absent
names and program definitions. Dirty output reuse and scratch poisoning check
