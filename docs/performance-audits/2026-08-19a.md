`2026-08-19a` (Linux x86_64, Zen 4 7940HS; **make the successful C
producer/consumer boundary explicit and remove a complete heterogeneous
validation pass**).  The first profile after `18r` put
`machine_select_canonical_function` at 4.55% of cycles, FAST placement at
3.81%, FAST prepass at 2.48%, and canonical IR validation at 3.10%.  The C
driver was validating every freshly lowered canonical row immediately after
the C lowerer had finished building the same private program through typed
builders, then handing the result directly to codegen with
`assume_validated=true`.  This was a repeated ownership proof, not a public IR
input boundary.

`CIRLowerResult` now publishes one `canonical_ir_certified` bit only after the
lowerer has completed the program with no diagnostic and neither the program
nor module rejected a function.  The single C-driver consumer trusts that
private certificate and keeps the same validated codegen contract.  Failed or
partial lowerings never certify.  Public, replayed, hand-built, and otherwise
uncertified canonical IR still runs the complete validator.  C frontend tests
assert both successful and failed certificate publication, and the existing C
test corpus continues to call `ir_validate_canonical_module` independently as
the oracle for lowered programs.  Thus malformed-input diagnostics remain on
the cold external path while the regular compiler path stops rereading every
instruction, value, operand, block, and side table merely to rediscover its
producer's invariants.
