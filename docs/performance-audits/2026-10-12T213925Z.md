## Where statement-expression bodies are lowered

`c_ir_lower_statement_expression_step` (`c_gen.c`) lowers each `({ ... })`
body as a body frame in statement-expression mode
(`c_ir_lower_body_frame_push(..., true)`). The body runs through the same
token walkers as any other body: `c_ir_lower_body_advance`,
`c_ir_controlled_body_range` and `c_ir_statement_end*`.

The extent table (`CIrStatementExtents`) does not enter expressions.
`c_ir_statement_extents_build` walks only the statement nodes of a top-level
function body. So a controlled substatement inside a statement expression
has no entry, and its query is walked with reason `shape`.

A positive control confirms this:

```c
int f(int x){ int y = ({ int t = x + 1; if (t) t += 2; t; });
  return ({ int u = y; while (u > 3) u--; u; }) + ({ ({ y; }); x; }); }
```

Compiled with `-fc-ast-pilot -v`, it reports:
- `C_AST_EXTENTS ... answers=0 ... walked_shape=2`: the `if` and the `while`
  inside statement expressions are walked;
- the census counters: 3 statement-expression frames and 4 statement-expression
  bodies (37 tokens).
