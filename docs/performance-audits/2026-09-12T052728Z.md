`2026-09-12T052728Z` (Linux x86_64, Clang 18 and QEMU AArch64; **Remove fixed
native argument-count storage limits**).

The native selectors rejected otherwise supported signatures and calls after
24 source arguments because incoming-value tables, parameter shapes,
normalization temporaries and call operand arrays were fixed-size. The x86-64
module signature pool also omitted larger function types.

This change removes those count gates. Incoming arrays use the canonical
parameter count; the existing value-fact walk finds the maximum call arity and
allocates one reusable workspace per function. It adds no instruction pass.
The x86-64 signature pool sums parameter counts in 64 bits. Stack placements
use 32-bit offsets rather than truncated 16-bit fields and check signed frame
addressing bounds before advancing cursors. Allocation and existing canonical
IR/frame representation limits still apply; this is not a claim of unlimited
input size or a throughput speedup.

AArch64 `LEA_INCOMING` now accepts the signed payload range used by the ABI and
materializes a general 32-bit positive displacement when the immediate ADD
cannot carry it. The expansion needs at most two MOV halfwords and ADD, within
its existing twelve-byte capacity budget. The Windows home-prefix displacement
is included before choosing the encoding.

Mixed compilation exposed an existing Darwin AArch64 caller bug: narrow signed
register arguments retained their canonical byte image, while the public ABI
requires extension to 32 bits. The call planner now extends narrow signed or
unsigned integer arguments before staging any physical argument registers.
This preserves allocator visibility and avoids clobbering previously staged
arguments. The 65-signed-char case checks this with a Clang callee.

## Regression coverage

`basic_c_many_native_arguments.c` and the independent host companion cover:

- 25 integer parameters, 33 floating parameters and 65 signed-byte parameters,
  with distinct weights observing every argument;
- 33 mixed integer, floating, small aggregate, large aggregate and HFA
  parameters, returning an aggregate through the hidden result pointer;
- a 65-value variadic tail, direct and indirect calls;
- 522 named parameters followed by an anonymous value, placing `va_start`
  beyond a 4095-byte incoming displacement on the AArch64 desktop ABIs.

The driver registers strict MIR compilation for six desktop targets, three MIR
allocators and both frontend forms. Each matching native desktop executes the
standalone program and, when its configured non-MSVC compiler is available,
the mixed program. The host's loop and SLP vectorization are disabled so this
argument-transport gate does not require unrelated vector relocation support.
Runtime-derived floating inputs and expectations likewise keep the host oracle
independent of Mach-O floating literal-pool relocations. Integer and aggregate
expected results remain independently calculated.

The signature-fallback telemetry control now uses an eight-byte Win64 vector,
which remains accepted by the direct emitter and rejected as a MIR signature.
Only that target participates in this negative control. The obsolete AArch64
count refusal is removed rather than replacing 24 with another arbitrary cap.
