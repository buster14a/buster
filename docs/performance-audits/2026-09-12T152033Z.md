**Linear Windows command-line parser storage**).

[Issue #113](https://github.com/buster14a/buster/issues/113) fixes startup arena
exhaustion from many short Windows arguments. Base:
`fd0ba8ff8175952d12bbdb367adef13effcc4865`.

`slice_string_from_windows_string_list` now allocates one command-line-sized
UTF-16 buffer before the argument loop and reuses it after each UTF-8 copy.
The quote/backslash state machine and UTF-8 conversion are unchanged. The
existing descriptor upper bound and independent UTF-8 argument storage remain.
For N input UTF-16 units, descriptors occupy 16(N+1) bytes on this host, the
shared decode buffer occupies 2(N+1), and all UTF-8 payloads and terminators
occupy at most 4N bytes. Allocation alignment adds only a constant. Both peak
and retained arena growth are therefore O(N); no scratch allocation moved to
another arena or the heap.

## Measured arena growth

Each row parses alternating one-character arguments and space/tab separators,
including a trailing separator, with a fresh arena starting at position 64.
The input is outside that arena. Every returned byte, length, and NUL terminator
is checked. No parser allocation is rewound, so retained and high-water growth
are equal. These are allocator positions, not committed pages or process RSS.

| Arguments | UTF-16 units excluding NUL | Base growth, bytes | Candidate growth, bytes |

The largest case needs about 863 times less arena space. Doubling input roughly
quadruples baseline storage and doubles candidate storage. This is a deterministic
memory result; no compiler-throughput, Windows startup-latency, or Zen 5 timing
speedup is claimed. The baseline diagnostic uses a 1 GiB reservation so it can
finish; the registered candidate regressions use only 1 MiB.

## Regression contract and reproduction

The existing registered `string_tests` module now covers null/empty/whitespace
input, empty and unmatched quotes, joined quoted/unquoted fragments, CR/LF as
literal characters, 264 backslash-run cases (lengths 0 through 65, inside/outside
quotes, followed by a quote or ordinary separator), and UTF-8 copy lifetime with
BMP, surrogate-pair, malformed-surrogate and empty arguments. The semantic
fixtures also pass against the baseline parser.

Nine storage cases combine geometric input lengths with many short arguments,
many empty arguments and one BMP argument requiring three UTF-8 bytes per
UTF-16 unit. The largest input occupies the complete 32,767-unit Windows budget
including its terminator. Each fresh 1 MiB arena must stay below 24(N+1) bytes
in both retained and high-water growth; every output and terminator is checked.
The tests execute the production Windows parser on every host.

Run from the repository root with the normal built compiler:

```sh
BUSTER_WINDOWS_ARGV_STORAGE=1 BUSTER_TEST_JOBS=2 build/Release/ide test --ci=1 --verbose=1
```

This prints `WINDOWS_ARGV_STORAGE` records before destroying each measured arena.
On Windows set the same environment variables and use `build/Release/ide.exe`.
The [diagnostic caller](evidence/2026-09-12T152033Z/argv_storage_probe.c) and
[baseline](evidence/2026-09-12T152033Z/baseline-storage.txt) /
[candidate](evidence/2026-09-12T152033Z/candidate-storage.txt) raw positions are
retained. Compile the caller against each checkout, with its path as PROBE:

```sh
clang -Isrc -I. -w -O0 -ffunction-sections -fdata-sections "$PROBE" -Wl,--gc-sections -lm -o /tmp/argv-storage-probe
/tmp/argv-storage-probe
```

The caller includes that checkout's build-driver unity closure, renames its
entrypoint, and directly invokes the production parser. Dead-section removal
keeps unrelated driver code out of the running probe. The initial baseline
probe used `-O1` and the candidate used `-O0`; optimization does not affect the
reported allocator positions, and no probe timings are compared.
