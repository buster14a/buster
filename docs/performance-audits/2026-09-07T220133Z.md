## Audit findings

| Area | Current implementation and result |
| --- | --- |
| Name resolution and symbols | `c_parse_lookup_entity_symbol` already has an active-scope `binding_by_symbol` lookup and a LIFO binding undo log. Its direct hit is O(1); the fallback walks enclosing scopes and their hash bucket chains. Token identifiers are interned IDs. A blanket new string interner or global name cache would duplicate existing work and would risk shadowing. The 8,192-symbol, common-prefix stress has no material before/after change. |
| Scope handling | The existing CSR child index avoids a translation-unit-wide scan, but `c_parse_scope_for_token` still examined every sibling, even after finding a match. Loop cleanup-target queries call it twice per loop. N sibling loops made `2*N*N + N` interval inspections in the measured input. **Fixed here.** |
| Type construction/checking | Semantic `CType` construction is not universally canonical: a declaration can append a new row. The 8,192-loop probe produces 8,195 semantic types, which is linear rather than an explosion in the number of rows. The IR pointer/array caches already share derived types at program scope and account for newly published rows. These are not replaced with cross-translation-unit caches. |
| Shared complex types | `c_parse_types_compatible` uses an explicit stack but no visited-pair memoization. A linear-size shared function-type DAG expands to an exponential comparison tree. **Reproduced separately and filed as #241; not fixed by this PR.** |
| Calls and overload-like selection | The active frontend is C-only; there is no active C++ overload-resolution pass to optimize. The suite exercises ordinary call/type compatibility, and the new generator stresses `_Generic`. Dormant experimental-language files are not evidence of an active overload engine. No selection or conversion rule is changed. |
| Constant evaluation and caches | `CIrQueryMachine` keeps completed results within an invocation, restores its completion mark on exit and scans that completed run in reverse for dependencies. `c_parse_validate_constexpr_declaration` allocates type/member-sized work and clears a type-sized visited array per declaration. These are further scaling candidates, not claimed hot-path fixes: the scalar-constant corpus did not establish a material benefit from changing them. A global cache would need scope, target, mutation and speculative-rollback semantics its present keys do not promise. |
| Recursion and traversal | Type parsing, compatibility and scope descent use explicit iteration/work stacks in the inspected paths. The DAG result demonstrates that removing C recursion does not bound total traversal work. The 8,192-level source-scope stress and 4,096-level equal-range model succeed, but this is not a proof that all expression/statement-expression paths are free of input-dependent recursion. |

The changes already active in #210 (identifier-use accounting) and #232
(constant initializers) were not independently rewritten. This patch stays
inside scope-index construction/querying and its tests.

## Scope lookup change and correctness

`c_parse_index_scope_children` retains the existing CSR arrays and order.
During its existing fill pass it certifies that every child interval is
well formed and that each sibling run is ordered and disjoint:
`previous.token_end <= current.token_start`. It publishes one Boolean with
that index. No extra index array, process-global cache or per-query
allocation is added. The production builder runs once scopes are final,
in `c_lower_to_ir`; its lifetime remains that of the existing temporary
scope index. Rebuilding the index also recomputes the certificate.

A certified query finds the upper bound of the token among child starts.
Only its predecessor can contain the token, and a separate end comparison
preserves half-open ranges. It then descends iteratively. Equal-range
parent/child pairs still resolve to the deepest child. Empty ranges,
exclusive ends, gaps and tokens outside the supplied root keep their old
answers. Scope IDs, entity IDs and diagnostic ordering do not change.

Certification is deliberately conservative. An out-of-order or overlapping
hand-built model retains the original indexed scan, including its
last-containing-sibling behavior. A manually built index whose new Boolean
is zero also retains that path. A model with no CSR keeps the old full
scan/ancestry fallback. Binary searching an assumed ordering would have
silently changed those cases; early exit alone would still be quadratic.

For S scopes, depth D and B_i children at each visited level:

| Operation | Before | After |
| --- | --- | --- |
| Build child index | O(S) time and storage | O(S) time and storage; certification in existing pass |
| Certified query | O(D + sum B_i) | O(D + sum log(B_i + 1)) |
| Q queries across N siblings | Theta(Q*N); Theta(N squared) when Q is proportional to N | O(Q log N) |
| Query scratch | O(1), no allocation | O(1), no allocation |
| Unary nesting | O(D) per query | O(D) per query |
| Uncertified/no-index models | Original scan costs | Unchanged fallback costs |

This does **not** make arbitrary semantic analysis linear. Repeated queries
along a deep unary chain can still accumulate quadratic work, and #241 is
an independent, worse asymptotic problem.

## Stress benchmark

`tools/semantic_stress.py` generates sibling loops, deep/shadowing scopes,
many common-prefix symbols, C23 constants, `_Generic`, rejected out-of-scope
references and shared function-type DAGs. Generated programs are compiled,
never executed. Depths for the DAG are separate from symbol/scope counts so
requesting 32,768 symbols cannot accidentally request a depth-32,768 DAG.

The tool excludes one warmup, alternates compiler order, saves every wall/
child-CPU/per-child-RSS sample, hashes source/compiler bytes, and compares
exit status, stdout, stderr and optional object bytes across compilers and
repetitions. A mismatch is a failure. Timeouts terminate the whole child
process group on POSIX. No noisy wall-clock threshold is installed as a CI
gate. GNU time provides per-child RSS; a cumulative `RUSAGE_CHILDREN`
high-water mark is not treated as an independent sample.

Seven samples per compiler, pinned to CPU 0, syntax-only including canonical
IR lowering. Milliseconds are process wall time, including launch and the
same measurement wrapper on both sides:

| Sibling loops | Baseline median ms | Candidate median ms | Reduction | Speedup |
| ---: | ---: | ---: | ---: | ---: |
| 128 | 2.759 | 2.768 | -0.35% | 1.00x |
| 512 | 5.332 | 4.863 | 8.79% | 1.10x |
| 2,048 | 20.469 | 15.493 | 24.31% | 1.32x |
| 8,192 | 141.693 | 53.209 | 62.45% | 2.66x |
| 16,384 | 513.140 | 104.411 | 79.65% | 4.91x |
| 32,768 | 1,767.835 | 222.111 | 87.44% | 7.96x |

At 32,768 loops the child CPU medians are 1,767.275 / 221.845 ms and peak
RSS medians are 138,036 / 138,040 KiB. Memory is effectively unchanged, not
a claimed RSS win. A phase probe of the actual preprocess/parse/lower entry
points at 8,192 loops reports 163,852 tokens, 16,386 scopes, 8,194 entities,
8,195 types, and identical arena positions: 93,186,928 bytes after semantics
and 162,653,416 bytes after lowering. Those positions are arena consumption,
not malloc counts or total process allocations.

Instrumenting only the production scope helper, independently of timing:

| Loops | Queries | Baseline interval probes | Candidate binary-search probes |
| ---: | ---: | ---: | ---: |
| 512 | 1,024 | 524,800 | 9,731 |
| 2,048 | 4,096 | 8,390,656 | 47,107 |
| 8,192 | 16,384 | 134,225,920 | 221,187 |

The candidate column counts search-start comparisons, while the baseline
counts sibling containment attempts. The candidate additionally performs
at most one end check per visited nonempty sibling run; the columns are
not claimed to count identical machine instructions. Instrumented binaries
are not used for the speedup table.

At count 8,192 the other wall medians (baseline/candidate ms) were:
deep scopes 79.942/80.727; symbols 30.290/30.695; constants 11.274/10.226;
`_Generic` 33.510/33.373; invalid scope references 24.386/23.364. These
control differences are not attributed to the scope optimization. All
status and diagnostic bytes agree, including repeated rejection of the
invalid sources.

The built-in 21,030-byte frontend benchmark was run seven times after a
warmup, each invocation taking 30 internal iterations. Median of its
reported medians: 1.674560 / 1.658987 ms (-0.93%). This establishes no
material small-file regression or separate small-file speedup.

Compiling the **same frozen full unity source** to an object seven times
per compiler yielded wall medians 1.854428 / 1.724175 s (-7.02%). The
individual samples span roughly 1.47-2.17 s on this shared host, so this is
not treated as a reliable 7% whole-compiler gain. Every 34,093,456-byte
object is identical, SHA-256
`038cab284cb2b1b5c8d433385b3a8a230d41a57699b24e17084daee7f2b81bc8`.
The controlled wide-scope result and deterministic work reduction are the
performance justification.

## Complex-type reproducer left open (#241)

```
typedef int (*T0)(int);
typedef T0 (*T1)(T0,T0);
typedef T1 (*T2)(T1,T1);
/* Repeat the same recurrence to T14. */
T14 f(T14 a);
T14 f(T14 a);
```

The generator emits complete source. At depth 14 it is only 419 bytes and
has 34 semantic types / 31 parameters. Syntax-only baseline medians at
depths 8, 12 and 14 are 2.443, 41.056 and 364.514 ms; the candidate remains
2.361, 40.976 and 366.529 ms. A phase probe attributes about 375 ms to
parse/semantics and 0.4 ms to lowering at depth 14.

Each function pair schedules its return and both parameter pairs, all
sharing the preceding type. The traversal obeys
`W(k) = 3*W(k-1) + O(1)` even though source and type-graph size are linear.
A correct fix needs query-local dependency/pair accounting, late-mismatch
tests and careful array-bound/mutation/qualifier handling. This PR does not
install a speculative cross-query compatibility cache to make that test
appear fast.

## Correctness gates and limits

- Frozen-main full Release non-unity suite: **395,073/395,073 assertions,
  40/40 modules**. Candidate: **414,623/414,623, 40/40 modules**.
- The 19,550 new assertions cover empty/single/wide runs, boundary/gap
  queries, invalid roots, no per-query allocation, 4,096 equal-range nested
  scopes, empty intervals, out-of-order/overlapping fallback models, and
  512 parsed sibling loops with shadowing and continue. Indexed answers
  are differentially checked against the full-scan reference; lowered
  canonical IR is validated.
- Fourteen generated cases per allocator, all of NONE, MIR_STACK, FAST and
  QUALITY: one warmup plus two recorded runs per compiler. Valid object
  bytes and invalid diagnostic/status bytes are identical. This is
  **56 case/mode pairs**, not execution of the stress programs.
- The initial full-suite run on both compilers found the same existing
  memory64 runtime-test failure. Installed Node 22.16.0 requires
  `--experimental-wasm-memory64`; `NODE_OPTIONS` cannot carry that flag.
  An external test-only `node` wrapper passes the flag on its command line.
  The passing full-suite counts above use that wrapper and execute the
  original independent Wasm test, rather than skipping it or changing
  expected results.
- The required first `./build.sh test_self_host --config Release` attempt
  fails at bootstrap: **TCC is not installed**. A separate manual
  Clang-bootstrap self-host check using the build driver's unity flags and
  explicit `-lm` succeeds: stage 1 and stage 2 are byte-identical,
  **36,389,984 bytes**, SHA-256
  `a7b86b5097a2d1473a1be2d2b5b68144291b4d034980a3f6c22c2d2f52bb9204`.
  An earlier hand-expanded command omitted `-lm` and failed on `floorf`;
  the corrected command restores the driver's real dependency. These
  manual stages are not represented as a successful TCC-bootstrap target.
- Focused **ASan+UBSan: 19,550/19,550** new scope assertions pass with

  #235 aggregate-lookup invalid-bool load (`c_parse.c:5762` here); it is

- Native execution of `basic_c_cleanup.c` and `basic_c_operations.c` returns

- `tools/new_audit.py --check` still reports the existing malformed opening
