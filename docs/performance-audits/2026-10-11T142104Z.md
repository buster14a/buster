## Workload

The four arms compile the base revision's unity self-host source from a
pristine checkout of the base:

```sh
ide cc -Isrc -Ibuild/v3/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -fsyntax-only \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

The four arms:
- A: base, default flags;
- B: base with `-fc-ast-pilot`;
- C: candidate with `-fc-ast-pilot`;
- D: candidate, default flags.

`-c` uses the same input with `-c -o`, at `-g0` for instructions and at `-g0`
and `-g` for object identity. Callgrind ran with `--cache-sim=no
--branch-sim=no`. Call counts are summed from the Callgrind `calls=` records.

## The change

`CStringLiteralMemo` records each narrow fragment once per unit, at the first
call of `c_ir_count_string_literal_range_for_target` that meets it. On the
base, that first sight always decodes (`c_ir_decode_quoted`) and records the
bytes, which lowering reads under `-c`. Under `-fsyntax-only` nothing reads
them.

The candidate adds `CParserResult.string_literal_lengths_only`. The driver
sets it for `COMPILER_DRIVER_ACTION_SYNTAX_ONLY` alone, since
`c_analyze_semantics_only` also runs before lowering in
`c_analyze_with_options`. The memo is created with the flag.
- **With the flag set,** a first sight is `c_ir_count_quoted`, and the slot
  records the length with null bytes. Repeats read the length as before.
- **A full decode** (`c_ir_decode_string_literal_range_for_target`) treats a
  length-only slot as a miss: it decodes the spelling and records nothing.
- **With the flag clear,** for `-c` and every other caller, the code path is
  the base's. The only addition is one test of the flag on a first sight.
- **Rollback:** the memo stays in the parse arena, outside the restored
  `CParseResult`, as before. A length-only slot is a pure function of the
  spelling, like a decoded one.
- **Wide fragments** are still never recorded.

## Reading

- **Why it pays.** The earlier audit treated the first-sight decode as
  necessary work because lowering reuses its bytes. That holds only for
  compiles that lower. On `-fsyntax-only` the decode was the whole cost, and
  `c_ir_count_quoted` does the same walk without the allocation and the stores.
- **`-c` is unaffected.** It decodes each fragment once, as before, with
  identical calls and objects.
- **Not measured:** peak RSS (this container has no `/usr/bin/time`) and wall
  time. A length-only slot keeps no buffer, so the parse arena can only shrink
  on `-fsyntax-only`, by at most the decoded bytes. These counts are
  diagnostic, and performance validation is incomplete (#2761).
