## Decision

No code change. This audit records the first full micro-architecture baseline
of the stage-1 self-host on the dedicated Zen 5 host. It is the reference that
later compile-time work should be compared against. It was produced by
`tools/uarch_lab.py` (#2422), and every number below comes from the lab's
`report.md` for that run.

## Identities and method

- **Compiler under test:** a Clang 22.1.8 Release `ide` built from
  `b40d4cde9b5e397fb0082b233fbeb83786e75fed`. That is the #923 fold head, the
  only build with `-fmetrics-out` per-phase timing at the time. Non-CI
  configure: `-g` and frame pointers on. `ide` sha256
  `35a2d3b075e7579e08c02dbbac08168c454cd2fa7ad2d04d1cff7d8e84e3c772`.
- **Workload:** `ide cc -Isrc -Ibuild/generated -DBUSTER_UNITY_BUILD=1
  -DBUSTER_INCLUDE_TESTS=0 -g src/buster/apps/ide/ide.c -lm`. That is 33,594,300
  translated bytes, 390,006 code lines and 3,742,965 tokens. Every output was
  byte-identical to the warm-up output.
- **Host:** `benchpress`, Ryzen 7 9700X, microcode `0xb404038`, kernel
  `6.18.50-2-lts`, perf 7.2.4. The host was in its H1 state:
  - CPU 2 at governor/EPP `performance`, with C2/C3 disabled;
  - IRQs moved off CPUs 2 and 10, and CPU 10 (the SMT sibling) offline;
  - runs pinned to CPU 2;
  - benchmark dispatch off. The idle service daemon ran untouched; its CPU time
    stayed well under 1 s for the whole run.
- **Tool:** `tools/uarch_lab.py` at `e78631aa1` with `run --cpu 2 --sudo
  --target-minutes 15`. Run `~/lab-20261002T225342` on the host (raw files and
  `perf.data` kept there, not in the repository): 462 timed runs, 864 s in
  total. The fixes in `06d878d72` and `cf0256c8c` changed only the recompute
  column and fault-region labels, not the numbers quoted here.

| task-clock | 1.5043 | 1.5117 | 1.5164 | 0.1% |

- **Instructions:** 22,287,659,805 per compile, with a spread of 0.0%. That is
  663 per byte and 5,955 per token.
- **IPC:** 2.794 at an effective 5.276 GHz.
- **Branches:** 73.9M mispredicts per compile, 3.32 MPKI. That is 1.80% of
  branches.
- **Memory:** 2,329 page faults per compile (median), all minor. Peak RSS is
  1.11 GB; the arena peak is 4.37 GB reserved.
- **Throughput:** 21.67 MB/s at the median.

## Leads (pointers, not conclusions)

- **Analysis is 48.6% of the input and is frontend-bound,** with L1I misses
  concentrated in IR lowering. Code layout or size is the first lead there.
- **The ir phase has the lowest IPC (2.19),** with the highest branch MPKI and
  L1D MPKI. `c_ir_ssa_finish` leads both of those miss lists.
- **`c_lex_dispatch` dominates first-touch faults and dTLB misses** in
  preprocess. Pre-faulting, or larger pages for that arena, is a candidate.
- **`ir_validate_canonical_function` is the top function by cycles.**
  Validation is required, so the lead is its cost, not whether it runs.

## Reproduce

On a quiet host, from a configured checkout:

```sh
./build.sh build --config Release -t ide
python3 tools/uarch_lab.py run --ide build/Release/ide --repo-root . --cpu 2 --output ~/lab-$(date +%Y%m%dT%H%M%S) --target-minutes 15 --sudo
```

Per-phase timing needs a compiler that supports `-fmetrics-out`.
