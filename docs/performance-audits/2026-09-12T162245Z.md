## Contract and implementation

Fix GitHub #253 at the C source-word boundary. Identifiers and preprocessing
numbers accept only shortest UTF-8 encodings of Unicode scalar values.
Validation adds no Unicode category/normalization restrictions. The first
malformed sequence in each word receives `c.invalid-utf8` at its initial byte;
source checkpoints recover original byte positions across CRLF and splices.
Comments and literal token payloads keep their existing byte policy. Shared
`utf8_decode` and OS path/argument handling are unchanged.

The scalar identifier table stops at high bytes; a bounded cold validator
checks only non-ASCII words. Numbers accumulate a high-byte flag in their
existing scan. The compact lexer reuses its sign mask and existing uncommon-byte
branch, escaping at the owning word's start. There is no extra source pass,
allocation, or token-layout change. Identifier/number runs and literal/comment
ownership remain identical between the scalar and compact paths.

The registered oracle reconstructs scalar values independently of production
leader/second-byte constraints, covering all 32,768 leader/second-byte pairs and
all later continuation-byte values. Curated valid/invalid sequences cover every
64-byte window split and lengths through 127 bytes of prefix in identifiers and
preprocessing numbers, ending against a guard page. Further cases check CRLF,
splices inside encodings, ordinary byte contexts, inactive source, macro bodies,
stringizing, physical include locations, structured driver records, and output
preservation on failure. A UTF-8 identifier fixture executes in all allocators.

## ASCII measurement

Measurement precedes integration of unrelated main changes. The baseline lexer
is from `8c5a9bd6837a0e4beecbd6fdd1f9adeb175fce96`; the candidate source is
identified by SHA-256 in the evidence. The retained `measured-change.patch`
reconstructs that candidate on the baseline. Both diagnostic executables reuse
one configured Clang 18.1.3 Release/split object set, replacing the app's benchmark
entry identically and selecting baseline or candidate `c_source.c` alone.
The actual compile/link argument vectors are retained. No build or test from
this task ran during collection.

The ASCII input is 64 copies of unchanged `tests/basic_c_operations.c`,
1,346,688 bytes and 327,361 tokens per lex. Each process performs one warmup
and 31 timed lexes per implementation. Twelve AB/BA pairs follow an excluded
warmup pair, pinned to CPU 0. The table's latencies are medians of per-process
medians; paired ratios are computed per pair before taking their median.
These two estimators need not have the same ratio.

| ASCII workload | Baseline median | Candidate median | Median paired ratio |
|---|---:|---:|---:|
| Compact lex, 1,346,688 bytes | 1.371769 ms | 1.381414 ms | 1.0282 |
| Scalar lex, same bytes | 6.729369 ms | 6.754016 ms | 1.0069 |
| Full `ide bench` frontend, 21,042 bytes | 2.611686 ms | 2.627763 ms | 0.9961 |

The compact lexer therefore has an observed **2.8% paired cost**, scalar 0.7%,
and the full frontend is near baseline. This is a correctness change with a
small measured cost, not a throughput improvement or a statistical proof of
zero regression. The shared Xeon Platinum 8573C VM is not a physical Zen 5
acceptance host; scheduler interference and code placement remain limitations.

An earlier spelling used a separate high-byte branch and measured a 1.0341
compact paired ratio. Its raw results are retained as `*-first-*`. Folding that
check into the existing uncommon-byte branch is the final implementation; no
further tuning or selective reruns were used. The frontend observations use the
ordinary trusted Clang-built drivers, not the diagnostic lexer hosts or
self-built stages. Binary/input identities and all paired observations are in
[the evidence directory](evidence/2026-09-12T162245Z/validation.json).

## Reproduction

For correctness, configure/build with the repository driver and run `test_all`
and `test_self_host --config Release`; use a separate sanitized build directory
and the strict environment above. Exact local log hashes and per-module counts
are retained in `validation.json` and its accompanying summaries.

To reproduce the isolated pre-integration measurement, make a separate checkout
at the baseline above and apply `measured-change.patch`. Configure with
`generate --linker DEFAULT -DBUSTER_UNITY_BUILD=OFF`, then build Release `ide`.
Run `build_lexer_bench.py OUTPUT_DIRECTORY` from that checkout (the script and
`lexer_benchmark.c` remain beside each other), followed by
`measure_lexer.py OUTPUT_DIRECTORY`. Use a fresh output directory. The source
copying and diagnostic entry replacement happen only in that output directory;
no production benchmark entry or compiler source is edited by these scripts.
The ordinary frontend measurement alternates the retained baseline and candidate
trusted drivers' `bench` command for the same one warmup plus twelve pairs.
