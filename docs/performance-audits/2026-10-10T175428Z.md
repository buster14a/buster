## Change

`c_parser_tree_probe` changed in two ways:
1. **Identifier lanes are classified from their interned id.** Before, each
   identifier lane called `c_parse_type_word_for_dialect_token`, which takes
   the preprocess result by value, and `c_token_is_well_known`. Now an
   interned id answers both questions with one bound compare against
   `predefined_limit` and one `word_bits` read, under the dialect mask, which
   is hoisted out of the loop. Uninterned tokens still ask the predicates.
2. **Specifier runs are memoized.** A run of at most four interned type
   words, with no tag keyword, holds only identifiers. So
   `c_parser_validate_type_specifiers` reads nothing outside it, and its
   verdict depends on the ids alone. A 256-slot per-unit table keeps the runs
   that validated clean, and a run spelled like one of them is skipped.

The probe still visits every token that the walker validates.

## Validation and limits

- Callgrind counts instructions, not time, on `-march=x86-64-v3` builds whose
  AVX-512 kernels are compiled out. No wall time was taken: a 44 M-instruction
  change is below this host's paired-run noise for the whole compile.
- One input, one host, single process, no pinning and no `perf` counters.
- The 9700X pull-request comparison runs default flags only and cannot time
  the hook, so Zen 5 validation stays **incomplete** (#2761). No PR benchmark
  request was added.
