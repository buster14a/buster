# C place-demand experiment — issue #306

## Status and scope

This note closes the bounded design experiment in #306. It does **not** claim
that all value-to-place recovery is gone, that the retained recovery population
is expensive, or that compiler throughput improved. The accepted result is
narrower:

1. the recovery sites and a representative dynamic population are now
   observable;
2. one consumer family requests a place directly instead of introducing a
   second expression representation; and
3. the remaining recovery path stays as a measured fallback until a separate
   attribution demonstrates that replacing another family is worthwhile.

The source snapshot inspected for the static census is
`b7a0f87cb881e44298a77e956e38ccc821d6e93b`. The retained unity counters below
were collected from product source
`5e3d839edaa9407f68e3a981fa5cde0ba3beb409`, as recorded in
[`evidence/2026-09-17T132038Z/README.md`](evidence/2026-09-17T132038Z/README.md).
The two revisions use the same version-1 construction-counter contract for the
rows discussed here.

## Recovery census

`c_ir_recover_memory_place_from_value` is reached through
`c_ir_recover_place_from_value`. At the inspected source there are six
production consumer classes:

- aggregate-member continuation when a value-form operand must become a field
  place;
- unary address-of over an operand already materialized as a value;
- address-of/index materialization that must recover the underlying storage;
- assignment-statement fallback after a value-form left operand;
- nested or parenthesized assignment-expression fallback; and
- GNU inline-assembly memory operands that arrived in value form.

The helper accepts only a terminal `LOAD` or `ATOMIC_LOAD` whose result and
instruction are the current function tails. It then restores the block tail,
last-instruction cache, value/instruction counts and sparse label provenance.
`c_ir_ssa_read_place` is tried first, so the memory helper is the fallback after
direct-SSA recovery.

The retained unity diagnostic compiled the 3,439,352-preprocessed-token IDE
translation unit containing 4,896 functions. Its exact construction counters
are in
[`evidence/2026-09-17T132038Z/unity-metrics.txt`](evidence/2026-09-17T132038Z/unity-metrics.txt):

| Counter | Count |
| --- | ---: |
| successful instruction appends | 1,362,886 |
| ordinary load retractions | 24,125 |
| atomic load retractions | 4 |
| predecessor-repair steps | 0 |

The 24,129 retracted load rows are 1.7704% of successful instruction appends in
that diagnostic workload. This ratio is a construction-population description,
not elapsed time: a retracted row is included in the append count, and the
counter does not price operand production, cache traffic or the surrounding
expression walk. Zero predecessor-repair steps means every successful recovery
used the cached previous instruction in this workload; it does not prove that
all possible inputs do so.

## Bounded explicit place demand

PR #392, merged as
`44446c642f99cfae144f29737f6c92d9c1f7975c`, supplies the bounded consumer
family: destinations of `va_start` and `va_copy` are lowered through
`c_ir_prepared_call_request_place` instead of through a value expression and a
later place reconstruction.

The boundary is deliberately small:

- the existing place frame handles named objects and its supported
  member/index/dereference chains;
- the lowered destination is retained while the copy source is evaluated, so
  destination side effects execute once;
- read-only, atomic and non-`va_list` destinations fail before VA IR is
  published;
- volatile qualification is retained for the destination result type; and
- unsupported expression shapes keep the existing fail-closed or recovery
  behavior rather than widening the hot IR rows or adding another IR.

For the direct shapes accepted by that place frame, the consumer never requests
an rvalue load and therefore has no terminal load to discard. The canonical IR
continues to use the same place, VA instruction and store rows; the change is
which existing lowering continuation is selected, not a new representation.

`tests/basic_c_va_list_places.c` covers builtin aliases, member, indexed and
dereferenced destinations, independent copies and side-effect counts. The
`va-list-places` differential case compares the fixture with Clang at O0 and
O2. PR #392 retained the following submitted-revision validation:

- 920,253/920,253 Release assertions across 46 modules;
- 911,904/911,904 strict sanitizer assertions across 46 modules;
- a byte-identical 38,645,600-byte self-host stage pair;
- 24/24 mode-matrix rows; and
- 7,344 differential rows with zero failures.

Those results establish behavior for the bounded family. They are not a timing
comparison and do not turn the whole 24,129-row recovery population into a
claimed saving.

## Disposition

The acceptance criteria of #306 are satisfied as a bounded experiment:

- the recovery call classes and discarded-row population are recorded;
- one consumer family has an explicit place-demand entry point with volatile,
  atomic, evaluation-order, provenance and diagnostic boundaries preserved;
- the family reuses canonical places and existing continuations, while the
  differential, sanitizer, mode and self-host gates establish equivalent
  observable behavior without row widening or a second IR.

A broad place/value rewrite is not justified by this evidence. The retained
unity population is real, but its successful recoveries required no linked-list
repair and no end-to-end speedup was measured. Any follow-up should first split
`place_load_retractions` by consumer family, select another bounded family, and
run paired same-source compiler measurements. It should not reopen #306 merely
because the intentional fallback counter remains nonzero.
