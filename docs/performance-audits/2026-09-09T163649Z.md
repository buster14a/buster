ELF AArch64 variadic register cursors and HFA overflow (#36)**).


## Correctness and scope

The new variadic interoperability case in PR #359 exposed an existing ELF
AArch64 bug in hosted CI: floating anonymous arguments were read from the
integer save area, and named floating parameters incorrectly advanced the
integer cursor. The focused independent Clang observer returned zero for its
Clang control, but returned failure bitmask 12 with both the pre-Windows
compiler and commit `4b657cea43e24085ff32fa04c4d7eb6445fad8bd`, under all four
allocators. This repair is part of the same coverage PR; the regression stays
enabled on AArch64.

ELF AArch64 variadic definitions now capture X0-X7 and Q0-Q7 into an aligned
192-byte area. Named parameters advance independent integer and floating
register cursors. The existing private four-word list retains its integer
cursor, shared overflow pointer, and save pointer, and uses the fourth word
for the floating cursor. Scalar floats and homogeneous floating aggregates
read Q slots at sixteen-byte strides, using each ABI part's actual value size
and offset. A composite that cannot fit closes that register file before a
following smaller argument. Overflow reads advance by the rounded value size.
`va_copy` retains all four words and `va_end` writes nothing. The direct
correctness oracle and MIR implement the same private protocol.

The save area grows from 64 to 192 bytes per selected variadic function. The
cold `MachineVaArg` record grows from 48 to 72 bytes to represent up to four
HFA parts; x86-64 classification remains bounded to its existing two parts.
No opcode or expansion recipe is added by this correction. The complete PR
retains 241 opcode identities and 86 expansion recipes. Machine replay does
not serialize the variadic side table, so its version remains unchanged.

This is bounded scalar and aggregate coverage, with aggregate reads still
limited to sixteen bytes. It does not implement the public AAPCS64 list layout
needed to pass a list across a compiler boundary; that separately reproduced
gap is tracked in [#360](https://github.com/buster14a/buster/issues/360).
The register-save rules follow the [AAPCS64 specification](https://github.com/ARM-software/abi-aa/blob/main/aapcs64/aapcs64.rst).
Win64 indirect aggregate arguments, other signature restrictions, and
production fallback retirement remain part of #36. Frontend list aliases and
general destination places remain tracked in #358.

- Final strict ASan/UBSan Debug: 904,166/904,166 assertions and 46/46 modules,
  with UBSan halting on error and the existing leak-sanitizer suppressions.
- Before and after ordinary self-hosting passed. The final candidate has a
  byte-identical 38,519,624-byte fixed point, followed by the existing
  machine/canonical stages and benchmark.
- All 24 target-mode legs passed. The existing AArch64 floating ABI fixture
  also passes under all four allocators; it caught the first incomplete
  scalar-only repair's failure to handle HFA overflow.
- The full Linux x86-64 compiler passes strict tracing with zero fallback.
- Permanent regressions cover ten floating arguments crossing the register
  limit, mixed named integer/floating arguments, copied lists with canaries,
  four-float and two-double aggregates, and an HFA spill followed by a smaller
  floating argument. Machine tests select five target ABIs, both frontend
  forms, and all allocators, and reject an undersized AArch64 save area.
- The Windows/UEFI mixed-compiler runner passes an independent Clang control
  and all sixteen Buster legs. Scalar calls cross Clang boundaries in both
  directions; the added HFA argument calls are Clang-to-Buster.
- The AArch64 runner passes independent Clang O0/O2 controls and all eight
  Buster legs under QEMU, using external LLD for the known ELF relocation
  reader restriction tracked in #355. Every MIR leg requires zero fallback
  and enables code-generation verification.

The supplemental Windows transport was corrected for the expanded fixture:
COFF REL32's inline addend is transferred to ELF RELA and its P+4 origin is
adjusted once. The earlier adapter lost nonzero inline addends; its independent
Clang control rejected the expanded fixture before any Buster result was
accepted. The original published adapter and audit are preserved unchanged.
The new adapter still removes PE unwind sections and therefore supplements,
rather than establishes, hosted Windows loading and unwinding coverage.
Hosted checks for this corrective commit are pending at audit publication.

Earlier local scalar-only and unaligned-Q-save attempts failed the target
matrix and encoding respectively. Those intermediate results are not the
final validation reported here.

The complete native differential matrix passed all 6,048 comparisons
(fourteen cases × 432 configurations), with sanitized Clang O0/O2 references
and the original ten-second child deadline. The runner self-test passed too.
