## Revision and scope

Base: upstream `main` `6a8a6d31e6959ed57222dfa5228b6fbd11c32453`, rechecked
before packaging. This is an initial, bounded implementation for GitHub #34;
shared canonical promotion (#33) remains the reference and fallback. No
backend algorithm, dependency, row format, or CI workflow is changed.

Selected call-free structured functions build scalar locals directly in
canonical SSA. Sparse current-value slots and iterative sealing replace
transient memory rows; provisional parameters are trivial-folded and
liveness-pruned. Raw C lvalue aliases are resolved before publication.

A development failure in the existing `sum_to` machine tests exposed an
important publication contract: the predecessor lists must include edges into
parameter-free successor blocks, not only parameter-carrying edges. Both native
selectors derive their graph from those lists. The implementation now publishes
the full graph, and frontend tests assert it before shared preparation.

## Paired end-to-end measurements

Same trusted compiler binary, sources, flags and CPU, changing only
`-fno-frontend-ssa`. Each corpus has one warm-up pair followed by nine timed
pairs, alternated in order and pinned to one allowed CPU. Wall time is measured
with a nanosecond monotonic timer around `/usr/bin/time` and `taskset`; peak RSS
comes from `/usr/bin/time`. Process startup is included. No other build/test
process ran during the precise series. This is a shared VM, not a controlled
bare-metal performance acceptance runner. Hardware counters were unavailable.

The many-function input contains 1,280 generated leaf functions; the large
function has 700 sequential diamonds. Self-host input is the complete current
unity translation unit with tests disabled, debug output and libm, using the
same flags as `self_host_compile_add`.

| Corpus | Memory frontend + shared promotion | Direct frontend + fallback | Median change | Reference / direct peak RSS (KiB) |
|---|---:|---:|---:|---:|
| operations | 18.394 ms | 18.896 ms | +2.73% | 25,972 / 25,908 |
| many_functions | 81.999 ms | 80.419 ms | -1.93% | 70,696 / 69,652 |
| large_function | 30.750 ms | 30.970 ms | +0.72% | 33,612 / 34,760 |
| self_host | 2818.130 ms | 2840.099 ms | +0.78% | 989,720 / 989,664 |

All paired output sizes are equal: 68,072 bytes (operations), 2,064,296 bytes
(many functions), 313,840 bytes (large function), and 39,421,752 bytes
(self-host). Equal sizes alone are not an equivalence proof.

The measurements do **not** establish a throughput win or strict non-regression:
median deltas range from -1.93% to +2.73%, with overlapping sample ranges.
Large-function peak RSS rises by 1,148 KiB. Keep this evidence visible rather
than claiming that eliminated memory rows alone prove a speedup. On the
self-host corpus only 92 functions / 139 locals are admitted by the bounded
classifier; its benefit is principally a verified construction path, not yet a
broad performance result.
