## Mechanism and preserved contracts

Both public entries retain their existing admission conditions.
`ir_type_abi_value` checks program/arena, convention, use and type bounds before
creating/selecting its context, then retains context arena, storage identity,
context convention and page-capacity checks. `ir_abi_context_value` retains
its independent-context checks. Both call a small private validated lookup,
avoiding the program wrapper's repeated public checks. The lookup normalizes
use and reads the resident page/mask. Miss allocation and classification live
in a separate private cold helper. A hit assigns its by-value answer directly,
without an unconditional zero-result initialization.

No `IrType`, `IrAbiValue` or `IrAbiContext` representation changes. Independent
contexts, the unnamed-bitfield policy, Windows AArch64 variadic distinction,
lazy use-specific computation, unresolved-layout deferral, dependent-aggregate
invalidation and reservation before retry checkpoints remain unchanged.
No allocation is retained across a discarded attempt, and no extra cache,
pass, callback, thread or dependency is introduced.

Source structure alone is not performance evidence. Retained service
disassembly shows Clang keeps the old public wrapper as a call and inlines
the new public wrapper into the query trace, leaving calls to the validated
helper. Static trace instruction counts actually grow from 113 to 161; those
counts are not dynamic instruction totals or a claimed instruction reduction.
The historical fixture builds with host `-O3` but leaves `BUSTER_OPTIMIZE=0`
at its default, as before; normal Release builds enable that macro and its
`BUSTER_INLINE` policy. The separate whole-compiler comparison covers the
normal trusted Release configuration.

## Counterargument, remaining cost and license

The strongest counterargument is representativeness: two tiny, L1-sized,
100%-hit loops expose service cost, while a real compiler may spend little time
there. Compiler inlining differs between the standalone fixture and ordinary
Release consumers. The unchanged whole-compiler result supports that caution.
Remaining validated context/page loads and the by-value result still cost
work; this audit does not isolate each component's nanoseconds or establish
a scalar recomputation crossover. The old 1.2 ns/query result used a different
ownership model/revision/host and is not a current target to attain by weakening
validation. Dense cold median is slightly higher and is retained as a tradeoff.

The useful implementation is this small validated lookup/cold split plus its
regressions. No further caching/reservation change is justified by these data.
Review and normal exact-head CI are the next gates; merge only with applicable
checks passing. Do not label the issue completed until this implementation lands.
