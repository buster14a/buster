## Scope and source inventory

Recovered the member-emission portion of the allocation-transport work on
`9f5616613b4c1f1af4b4071a2cbe987db20490b8`. The ABI classifier changes from
that patch belong to a separate recovery and are excluded here.

`c_ir_emit_field_place_from_value` serves ten production call sites covering
ordinary member expressions, initializer designators and related place
construction. It previously requested four arrays of `types.count + 1` rows
on every lookup, then reserved a reversed path for every queued row. The
arrays hold type IDs, parent indices, parent field indices and depth. Only
the initialized visited prefix is consumed; parent rows must remain until
the result path is reconstructed, so this is a visited-work bound rather
than merely a pending-frontier bound.

The separate parser service `c_parse_promoted_member_type` reuses its
parser-owned work/visited buffers and generation marks. Those buffers are
reserved once from a token-count bound in `c_analyze_semantics`; this patch does not
change that service. Historical cumulative byte totals attached to #295 are
not fresh measurements of this revision and are not used as a speedup claim.

## Change and correctness boundary

Keep 32 rows of each search array in fixed local storage. When the initialized
prefix fills the current capacity, grow all arrays geometrically together,
copy that prefix, and preserve the index-valued parent chain. Keep the type
count as the original validity/cycle bound. The reversed field path uses
`found_depth + 1` entries, with the same 32-entry local allowance.

Breadth-first order, the nearest-depth rule, same-depth ambiguity, qualified
places, invalid-type handling and the existing error-unwind paths are
unchanged. Emitted values, instructions, operands, immediates and allocated
diagnostics remain in the persistent builder arena. Search arrays and a deep
path belong only to the temporal arena. The fixed local arrays total 640
bytes of element storage. Growth retains earlier allocations until rewind,
so an unusually large reachable graph can request more than one full grown
array set; this is not a universal reduction in every graph's peak scratch.

The direct regression builds a real 4,096-type table. A small lookup must
leave the temporary arena's dirty high-water mark unchanged, whereas the
previous four array requests alone required 65,552 bytes at that table size.
Wide and deep searches must restore the position and stay below 4 KiB of
requested scratch in the tested shapes. This high-water mark measures the
allocated byte range retained across rewind; it does not measure physical
pages dirtied, cumulative bytes across a full compile, or peak RSS.

The regression also covers 80 anonymous siblings (two growth boundaries),
a 41-field path crossing structs and unions, direct members before and after
anonymous siblings, equal-depth ambiguity, missing members, a cyclic/invalid
anonymous edge, invalid root types, and inherited/field volatility and
read-only places. It overwrites the entire released scratch prefix before
checking the emitted field chain or missing-member diagnostic.

The recovered runtime fixture runs all four allocators with both frontend
SSA settings. It combines wide/deep member paths, const volatile reads and
aggregate calls whose results are consumed after later function lowering.
Independent Clang/GCC callers and callees use the same fixture in both link
directions.

## Reproduction

Configure through the standard TCC-origin driver, build the trusted Clang
Release compiler, and preserve that executable before self-hosting:

```sh
./build.sh generate
BUSTER_TEST_JOBS=2 ./build.sh build --config Release -t test_all
BUSTER_TEST_JOBS=2 ./build.sh test_self_host --config Release
BUSTER_TEST_JOBS=2 ./build.sh test_mode_matrix --config Release
ASAN_OPTIONS=halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1 ./build.sh generate --build-directory build-sanitize --sanitize
BUSTER_TEST_JOBS=2 ./build.sh build --build-directory build-sanitize -t test_all
```

Freeze `src/` and `tests/basic_c_operations.c` from the base revision with
`git archive`, copy the generated include directory once, and copy
`tests/basic_c_allocation_lifetimes.c` as `allocation.c`. The synthetic
member corpus is exactly:

```python
source = ''.join(f'struct Unrelated{i} {{ int value; }};\n' for i in range(4096))
source += 'struct Access { struct { int target; }; };\n'
source += ''.join(f'int access{i}(struct Access const* x) {{ return x->target + {i}; }}\n' for i in range(256))
```

For small inputs, run each preserved compiler with
`cc -ffrontend-ssa -c <same-frozen-input> -o <same-output>`. The full compiler
uses `cc -ffrontend-ssa -I<frozen-src> -I<frozen-generated>
-DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 -g
<frozen-src>/buster/apps/ide/ide.c -lm -o <same-output>`. Prefix timed
commands with `taskset -c 2`, time a direct child with a monotonic clock and
`wait4`, and hash the output after every invocation. Separate counters use
`perf stat --no-big-num -x , -e instructions:u,cycles:u,task-clock`; add
`-fsource-metrics=<same-path>` for their source denominator.

The cross-compiler fixture splits with `BUSTER_ALLOCATION_NO_MAIN` for the
callee and `BUSTER_ALLOCATION_ONLY_MAIN` for the caller. Compile each host
side with Clang/GCC O0/O2, `-fwrapv -fno-strict-aliasing -funsigned-char`,
`-fsanitize=address,undefined -fno-sanitize-recover=all`, and link it to the
opposite Buster side. Test every `none`, `mir-stack`, `fast`, `quality`
allocator with both `-ffrontend-ssa` and `-fno-frontend-ssa`.
