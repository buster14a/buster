# Verdict and evidence boundary

**The strongest candidate is conservative root-marking dead-code elimination
over the combined graph of ordinary instructions and SSA block parameters,
while retaining every control-flow terminator. Go for a bounded current-source
census and three-way experiment; no-go for production/default adoption now.**

The inspected canonical DCE uses counts and a zero-use deletion queue. It
cannot remove a closed component of mutually dependent definitions when that
component reaches the pass, even if no observable operation needs it. Incoming
values of block parameters count as uses whether those parameters are needed
or not. This is a source-supported limit of the inspected pass, not a measured
claim that representative Buster programs currently suffer material overhead.
See [the pinned DCE](https://github.com/buster14a/buster/blob/f34cc3a56296be1b1244647775e1a40a67dae3ef/src/buster/lib/compiler/ir/ir_fast.c#L282-L333).

An independently written C dependency-graph prototype demonstrates the
algorithmic distinction and preserves bounded semantic controls. It does not
establish Buster's real opportunity population, a compiler speedup, lower RSS,
better native code, or correctness of an integrated Buster transform. The next
most valuable fact is the difference between root marking and the simplest
parameter-aware use-count alternative on real canonical IR, not another graph
microbenchmark.

Consider the following **proposed source witness**, not an observed Buster
compilation result:

```c
unsigned f(unsigned n, unsigned seed)
{
    unsigned dead = seed;
    for (unsigned i = 0; i < n; ++i)
        dead = dead * 33u + 1u;
    return n;
}
```

The relevant possible SSA component is:

```text
p    = phi(seed, next)
t    = p * 33
next = t + 1
```

Suppose no retained effect, return, or branch condition uses this component.
Each definition still has a user: `p` feeds `t`, `t` feeds `next`, and `next`
feeds `p`. Use-count deletion has no seed. The parameter simplifier cannot
remove `phi(seed, next)` because the two non-self incoming definitions differ.
Repeating these same rules does not make progress on this isolated component.
This conclusion follows from the inspected transition rules; it is not a
source-to-IR execution claim.

Root marking begins with mandatory operations and follows what they depend on.
It never reaches the dead recurrence and can remove both its ordinary
computations and its block parameter. The loop's control flow and its condition
remain because every terminator is retained.

Buster's [middle-end map](https://github.com/buster14a/buster/blob/f34cc3a56296be1b1244647775e1a40a67dae3ef/docs/middle-end-pass-map.md)
already documents frontend parameter-cycle pruning from ordinary
instruction-operand roots. That differs from following the combined
instruction-and-parameter graph from observable operations. Merely narrowing
the frontend's roots while leaving its arithmetic users intact would create
dangling uses. The oversized `c_ir_ssa_finish` body was not successfully
retrieved in full, so the map is architectural context, not a fresh body-level
proof that this C witness reaches canonical DCE unchanged.

**Established:** the inspected canonical DCE cannot remove this class of
component if it reaches the pass. **Unknown:** frequency in actual C lowering,
retained selected-machine work, and total compilation/runtime consequences.

# 2. Two research candidates, not a literature survey

## Candidate A: sparse conditional constant propagation

Wegman and Zadeck, *Constant Propagation with Conditional Branches* (1991),
TOPLAS 13(2), describes SCCP's coupled executable-edge and value-lattice
propagation. [Primary paper](https://www.cs.utexas.edu/~lin/cs380c/wegman.pdf),
especially section 3.4, printed pages 192-193, for the complexity discussion.

The reconstructed mechanism is a lattice of unresolved, constant and
nonconstant values plus executable CFG edges. A flow worklist activates edges;
a def-use worklist propagates value changes. A parameter meets only executable
incoming arguments. A constant condition activates its selected successor;
a nonconstant condition activates relevant alternatives. The paper's sparse
work analysis counts SSA/CFG edges and assumes the supporting representation;
it is not the complete source-to-artifact preprocessing cost.

This is attractive for constant branches and additional propagation across
joins, but it is not just a worklist replacing the current forward fold.
Buster's present DCE deliberately has no reverse-use CSR, and FAST folding has
no executable-edge state. An adaptation would need dependency indexing,
parameter/edge incidence handling and a safe rewrite for branch/argument
changes. Those costs are absent from the selected root-marking experiment.
See the pinned FAST source and contract linked above.

**Adaptation cost analysis, not a theorem attributed to the paper:** rescanning
all `k` parameter inputs whenever another incoming edge becomes executable can
cost Theta(k^2). Incremental contributions or another bounded evaluation
strategy are necessary to retain the sparse advantage. Arbitrary-width
constant evaluation is also not automatically constant-time. Rewrite,
compaction, validation and CFG fact invalidation must be included.

SCCP offers more optimization power, but that extra scope has no measured
Buster justification in this investigation. It was screened, not implemented.

## Candidate B: root-marking DCE without branch deletion

Cytron, Ferrante, Rosen, Wegman and Zadeck, *Efficiently Computing Static Single
Assignment Form and the Control Dependence Graph* (1991), TOPLAS 13(4),
section 7.1/Figure 17, presents backward necessity propagation from observable
statements through data and control dependencies.
[Primary paper](https://www.cs.utexas.edu/~pingali/CS380C/2010/papers/ssaCytron.pdf),
printed pages 478-481. A mutually dependent group does not establish its own
necessity merely by using itself.

**The proposed adaptation roots every terminator.** It omits the full paper's
control-dependence/postdominator-based branch decisions. It does not perform
unreachable-block elimination, loop deletion, control-flow rewriting or a new
SSA construction. This is intentionally weaker than full aggressive DCE.

That restriction is the fit for Buster: existing mutable canonical IR,
conservative purity, one existing compactor and existing publication boundaries
are sufficient for a narrowly scoped experiment. No persistent IR, general
pass framework, vendor implementation or new dependency is proposed.

# 3. The simplest plausible alternative

A fair experiment must compare root marking with **parameter-aware use-count
DCE**, not only current behavior. Count uses as today, but allow an unused block
parameter onto the deletion queue. On deleting a parameter, decrement every
incoming operand count, continue ordinary zero-use propagation, unlink the
parameter and compact once.

This removes unused acyclic parameter dependencies. It can avoid root
classification of every ordinary instruction and is a serious challenger when
cyclic opportunities are rare. It still cannot break a closed phi/arithmetic
cycle with no zero-use seed.

| Arm | Algorithm | Distinguishing capability |
| --- | --- | --- |
| A | Current-style reference counting, parameters retained | Zero-use pure ordinary definitions and their transitive dependencies. |
| B | Reference counting extended to parameters | Also unused acyclic parameter dependencies. |
| C | Root marking across instructions and parameters | Also unneeded cyclic dependency components. |

The pinned implementation tests zero use **before** calling
`ir_instruction_is_pure`. This is a real cost advantage of A, and potentially B.
C must identify mandatory roots across the surviving ordinary population.
**Choose B if it captures the useful real-world benefit; retain A if neither
candidate pays for its complete cost.**

# 4. Concrete algorithm and Buster integration obligations

Keep `FOLD -> ADDRESS -> DCE -> PARAMETERS` unchanged. Replace only DCE in the
experimental arm; do not add unconditional cleanup repetitions. Freeze the
prior-pass alias relation for the analysis. Assign temporary IDs to ordinary
rows followed by block parameters. Ordinary definition lookup exists in value
records; parameter producers need a transient value-to-parameter lookup.

Use the existing mutable DCE slot before ordinary initial CFG publication.
Late mutation after publication must charge the builder reconstruction and
subsequent republication; it is not the initial recommended placement.

The following is independently written adaptation pseudocode, not a copied
paper algorithm or an existing Buster API:

```text
prepare transient definition lookup
freeze/resolve prior-pass aliases

for each surviving ordinary instruction:
    if terminator or existing purity authority refuses deletion:
        mark and enqueue its node
include additional roots required by existing ABI/metadata contracts

while queue is nonempty:
    node = pop()
    dependencies = ordinary operands, or all incoming values of its parameter
    for each dependency:
        producer = definition of resolved alias
        if producer is unmarked:
            mark immediately
            enqueue producer

mark unmarked surviving pure ordinary instructions removed
unlink unmarked block parameters, retaining survivor order
repair block first/last/count fields
continue existing parameter stage
use shared compactor and normal certification/publication boundaries
```

Mark at enqueue so duplicates, fan-out and cycles do not duplicate worklist
entries. No SCC decomposition is required. Do not traverse every unrelated
parameter as an unconditional root.

`ir_instruction_is_pure` remains the sole existing deletion authority; do not
widen it to manufacture a result. Calls, even nonvolatile loads, stores,
atomics, fences, inline assembly, stack operations, traps, division/remainder,
floating arithmetic/conversions, exact SIMD and other excluded operations
remain mandatory under the current contract. Preserving deliberate backend
refusals is part of that contract, not merely preserving runtime effects.
[Purity and FAST contract](https://github.com/buster14a/buster/blob/f34cc3a56296be1b1244647775e1a40a67dae3ef/docs/canonical-fast-pipeline.md).

## Invariants and conditional correctness argument

Let `R` be mandatory roots and `D(x)` the resolved definitions used by node x.
The retained set is the least fixed point `L = R union {D(x) : x in L}`.

Required invariants are: every root survives; retained operands and incoming
arguments refer to retained definitions; deleted ordinary rows satisfy the
existing purity authority; each node is enqueued once; aliases/definition maps
stay valid for this fixed IR generation; metadata references keep their
existing semantics; parameter lists and edge-argument survivor order remain
coherent before compaction.

Under those preconditions, deleting unmarked pure computation cannot affect
retained observations. Rooting all terminators and their dependencies preserves
control flow and termination behavior, including unreachable components. This
is a proof argument for the restricted graph algorithm, **not completed
verification of Buster's metadata and mutation implementation**.

The existing compactor derives value IDs from surviving ordinary rows and
surviving parameter lists. Unlink dead parameters before compaction. Deleting
their incoming definitions while leaving the parameters linked violates the
helper's assumptions. Existing source/extras/local remapping must be preserved;
no debug improvement may be claimed by silently dropping required metadata.

# 5. Complexity, preprocessing, mutation and losing cases

Define N ordinary rows, P block parameters, V values, B blocks, U ordinary
operand occurrences and A incoming-argument occurrences. Once aliases are
resolved, setup, marking and deletion planning cost O(N+P+V+B+U+A). Each live
node's dependencies are traversed once. A high-fan-in live parameter has one
incoming traversal, not a traversal for each newly marked input.

Charge alias traversal/flattening separately unless its bound is established.
Path compression alone is not a justification for casually assigning the
entire adaptation an inverse-Ackermann bound.

A straightforward transient layout uses approximately
`4V + 5(N+P) + sizeof(void*)P` bytes: a 32-bit value-to-parameter index,
a mark byte and queue entry per node, and parameter pointers. This excludes
existing replacement/removal arrays, alignment and compaction scratch. On a
64-bit host it exceeds the present DCE's `4V + 4N` use-count/queue payload.
Use checked count/offset arithmetic and explicit invalid IDs. Release expired
DCE scratch before compaction where ownership permits.

The complete cost is not the marking walk alone:

- **Root classification/locality.** Current DCE's zero-use filter often avoids
  purity/type queries. C must classify roots throughout surviving rows, and a
  producer worklist can be less local than sequential use counting. The model's
  preclassified roots deliberately exclude this production cost.
- **Newly triggered compaction.** C may change functions A leaves alone, thereby
  causing the shared compactor to run. When per-block `local_values` maps are
  present, the inspected helper loops over `local_count` for each such block.
  Whole-transform work can include a blocks-by-locals term. This is an existing
  conditional remapping cost, not a measured new regression or a newly filed bug.
- **Retained allocations.** Logical deletion does not release old arena storage
  to the OS. Compaction allocates a new operand pool. The plausible benefit is
  reduced subsequent populations/allocations, not immediate recovery of every
  deleted row's bytes. Validation and later CFG publication remain real costs.
- **Low opportunity.** All-live and tiny functions pay setup with no deletion.
  Frontend/selector cleanup may already eliminate the useful final-code effect.
  Lower IR counts alone are not a speedup or a memory measurement.

FAST already has explicit scratch, retained-payload and work limits. Do not
silently exceed them. A sensible experimental fallback is original DCE when C's
extra scratch is not admitted, rather than making a previously admitted
function skip all FAST transforms. Keep provenance/computed-label exclusions
and report all skips.

Failure/rejection cases include changed debug semantics, stale IDs or aliases,
dangling incoming/metadata references, duplicate-edge mishandling, unsafe
parameter unlink ordering, widened purity, lost unsupported-operation refusal,
integer overflow in temporary sizes, and accidentally deleting terminators or
nontermination. These are correctness failures, not acceptable performance
tradeoffs. Additional parameter-stage cleanup after DCE may still leave work;
do not silently add another DCE pass to the initial comparison.

# 6. Executed graph-model evidence

The [original C probe](evidence/2026-10-04T114103Z/dce_probe.c) is independently
written C11, not a Buster patch. It ran in the original session's Linux x86-64
cloud container, with Clang 17 using AddressSanitizer/UBSan and GCC 14.2.
[Environment receipt](evidence/2026-10-04T114103Z/environment.txt) records an
AMD EPYC 9V74 virtual CPU description, five exposed CPUs, exact compiler banners
and capture time. No user laptop or physical Ryzen 9700X was used.

[Clang/sanitizer results](evidence/2026-10-04T114103Z/results-clang-sanitized.txt)
and [GCC results](evidence/2026-10-04T114103Z/results-gcc.txt) are byte-identical.
The archived run covers 32,768 exhaustive three-node graph/root/parameter
assignments, 20,000 deterministic random multigraphs, 394,752 bounded-loop result
comparisons and three 262,144-node stress graphs. The graph tests compare C to
an independently scheduled dense fixed-point oracle, check root preservation
and retained-dependency closure, and check `C retained subset B retained subset
A retained`. The exhaustive count is 512 adjacency choices times eight root
masks times eight parameter masks. Random seed is `0x4f392b17`.

| Constructed case | A retained nodes | B retained nodes | C retained nodes |
| --- | ---: | ---: | ---: |
| Unused acyclic parameter and its inputs | 4 | 1 | 1 |
| Loop with unused parameter/multiply/add recurrence | 14 | 14 | 10 |
| Same loop returning the accumulator | 14 | 14 | 14 |
| All-live 262,144-node chain | 262,144 | 262,144 | 262,144 |
| Dead chain with one mandatory root | 1 | 1 | 1 |
| Dead ring/parameters with one separate root | 262,144 | 262,144 | 1 |

These are dependency-graph nodes, not emitted machine instructions. The dead
loop removes the parameter, multiply, add and private multiplier constant.
Returning the accumulator is the live negative control. The bounded evaluator
checks n=0..256 and seed=0..255 across two variants and three solvers; it is not
a general IR interpreter. The random graphs include cycles/self-edges/duplicate
operands and are **not all valid SSA CFGs**.

The all-live stress control makes C enqueue every node. Its zero operand visits
on the dead ring do not imply zero work: initialization, root classification
and sweeping still inspect the graph. The solvers receive already resolved
producer IDs and already classified roots. Production purity, aliases, debug,
arenas, CFG validity, compaction, selection and allocation are not implemented
by the probe and cannot inherit its PASS status.

The [actual C witnesses](evidence/2026-10-04T114103Z/fixture.c) include dead,
live and volatile-store controls with a 32-bit unsigned assertion. Their Clang
and GCC syntax checks passed in the recorded investigation. They were **not
compiled or executed with Buster**. The volatile source witness is not falsely
counted as an executed Buster or graph-model volatile semantic test.

# 7. One decisive adoption experiment: A/B/C with an early stop

Run one frozen three-arm end-to-artifact experiment, beginning with a read-only
differential census at the existing canonical DCE boundary. Use the existing
frozen throughput corpus plus representative unmodified first-party sources.
Keep default direct SSA and the memory-form control separate. The crafted
accumulator is a positive mechanism control, **not an acceptance workload**.

First ask whether C removes a substantial population of real instructions and
parameters that B retains. If not, stop before a permanent production rewrite.
Publish that negative result rather than expanding synthetic generators until
an attractive example appears.

For a populated case, implement B and C as reversible alternatives in the same
DCE slot. Keep purity, pass order, validation policy and consumers unchanged.
Record survivor populations, selected-machine residue, code-section bytes and
applicable runtime checks. If downstream code is already equivalent, measure
any remaining compile benefit instead of claiming better generated code.

Correctness gates include existing all-16 pass subsets, allocator/frontend and
promotion controls, shared operands, parameter order, source/extras/debug/local
remapping, repeated preparation, budget/provenance refusal, self-host fixed
point and supported native/direct consumers. Unchanged output in no-op cases
is a useful control, but this stronger optimization is not an identical-output
implementation replacement in cases where it deliberately deletes more code.
Semantic/debug equivalence and each existing contract must be tested rather
than importing the old same-deletion-set requirement into the wrong study.

Finish builds and diagnostic runs before measurement. Then collect predeclared
rotated paired A/B/C observations plus A/A controls, sequentially on the same
cloud/GitHub-hosted machine. Use matched trusted host-built compilers, source,
flags, target, debug setting and artifact boundary. Measure complete compile
latency and peak RSS with existing infrastructure; record variance/cache state
and preserve failed, inconclusive and negative observations. Timing builds
must not contain census instrumentation. No user hardware execution is
within this request.

**Proposed research screening rule, not repository policy:** C should beat the
simplest adequate alternative by at least 2% aggregate compile latency or peak
RSS, or improve runtime/code size by at least 5% on a preselected real workload
without a confirmed compile-time/RSS regression. Require correctness and normal
debug behavior. These are decision criteria, not predicted gains. Synthetic-
only wins, no final-code/total-cost benefit or indistinguishable noisy results
are no-go outcomes. A clear maintenance advantage of B also favors B.

The separate dedicated-host default-admission contract in the pinned FAST
policy remains unmet by cloud evidence. Do not enable the default by changing
that contract, treating a cloud result as Zen 5 acceptance, or running the
physical host without authorization.
