### Current production facts, not proposed replacements

The [parallelism guide][parallel] and [lane implementation][lanes] establish
one persistent gang per caller context. `lane_run` dispatches one uniform
entry, `lane_range` assigns contiguous stable ranges, and the second dispatch
barrier is the completion/visibility edge. A one-lane dispatch invokes the
same entry inline; `BUSTER_SINGLE_THREADED` retains that path. Persistent
worker scratch is rewound after dispatch and large unused tails can be
decommitted. It is **not** storage for results retained by the coordinator.
Nested multi-lane calls use a fresh gang, so compiler algorithms must explicitly
avoid multiplying TU workers by function/tile workers.

The [driver][driver-units] already has `CompilerDriverUnit`,
`CompilerDriverUnitBatch`, `compiler_driver_unit_lane`,
`compiler_driver_unit_worker_limit` and `compiler_parallel_prewarm`.
Consecutive eligible native C link inputs use `-fcompile-jobs=N`, defaulting
to one; objects, archives and assembly remain ordering boundaries. Prewarm
covers both native families before workers exist. This is shipped structure,
not a missing scheduler to implement again: [PR #388][pr388] is merged, while
[#53][i53] remains open for its broader admission criteria.

The [ordered merge][driver-merge] publishes warnings, counters and objects by
input index, not completion order. [Object transfer][driver-copy] copies
sections, symbol names, relocations, debug-module names and initializer
priorities before destroying each TU arena. Later completed results and their
warnings are discarded after the first input-order failure. Existing cohorts
contain at most one pending TU per participating worker. Adding an atomic
counter to those unchanged cohorts cannot manufacture another job to take.

In [FAST][fast-facts], `machine_fast_prepass_build` already computes a compact
`u32 operand_masks[]`, including `MACHINE_FAST_OPERAND_CALL_ROW`. Its later
block-local backward walk builds `next_call[]`, consumed by
`machine_fast_placement_build_prepassed`. Stateful register ownership,
eviction, spilling, edge conformance and allocation order are not independent
SIMD work items. The proposed kernel changes only how an existing fact is
computed; it does not reorder machine instructions or replace canonical IR.

## Execution-mask model without importing a language or runtime

The primary [ISPC execution model][ispc-model] uses a shared program counter
and an execution mask to restrict per-instance effects. Divergent loops run
until every participating instance is done. Its `foreach_unique` groups equal
varying values, but does not specify group iteration order. The useful lesson
is masked homogeneous work, **not** an ordering guarantee. In Buster, logical
IDs and explicit publication order must supply that guarantee.

The primary [ISPC performance guide][ispc-perf] discusses uniform state,
coherent control flow, locality-friendly tiles and contiguous layouts. Coherent
fast-path tests themselves have a cost; they are not universally profitable.
This report imports those design observations only, not ISPC syntax, task
launching, an external compiler, a runtime or its performance figures.

For these designs, an OS worker lane and a SIMD element are different things.
A worker executes an ordinary C loop. A vector holds sixteen `u32` facts.
Function/block identity, target, a tile's bounds and its incoming recurrence
carry are uniform; row flags and row indices vary. A lane-gang barrier is never
placed inside a SIMD-active-lane branch or inside a variable-length TU loop.
All participating OS workers must reach collective operations, even after
recording a structured error.

Inactive elements must be prevented from making invalid memory accesses,
not merely prevented from storing the answer. Existing `simd512_load_masked`
and `simd512_store_masked` take **byte masks**; for `k` active words their mask
is `mask64_prefix(4*k)`, while a word comparison yields only the low sixteen
bits. `mask64_first_set(0)` is not legal. No speculative pointer to an unrelated
function or past an array is formed and then supposedly repaired by a mask.

Cheap per-row predicates should normally remain masked operations. Repacking
is justified only when expensive downstream work repays classification,
index movement and scattering. Refill draws only from already-ready items
owned by the current bounded packet. It never waits for another TU to reach
the same compiler phase. If the available tail is cheaper scalar, it runs
scalar immediately. Stable compaction, when needed, moves logical IDs with
values and writes results by those IDs, not by compacted lane order. Design A
needs no compacted side stream at all.

## Design A — block-local next-call fact wavefronts

### Exact boundary and packet layout

The candidate site is the backward `next_call` loop in
[`machine_fast_prepass_build`][fast-facts]. The earlier production walk must
have completed its existing flag construction and bounds/error handling.
`operand_masks` is then immutable for this kernel; `next_call` is its sole
output. Existing predecessor, liveness, loop, edge-index and final `valid`
logic remains in its original order. A fact tile never publishes a valid
prepass early or bypasses `machine_fast_index_edges`.

For instruction `i` in block `[b,e)`, the specification is:

```text
next_call[i] = min { j | i <= j < e and operand_masks[j] has CALL_ROW }
               or UINT32_MAX when the set is empty.
```

The smallest packet is an implicit slice of the arrays already owned by the
prepass. An optional stack/worker descriptor is:

```c
/* Proposed transient descriptor, not a permanent IR or public API. */
struct NextCallPacket
{
    u32 const* operand_masks;
    u32* next_call;
    u32 first;
    u32 count;
    u32 function_ordinal;
    u32 block_ordinal;
};
```

No opcode table lookup, operand gather, second instruction representation,
per-row status or heap queue is necessary. The descriptor borrows arrays;
it never owns their allocation. A local packet completes when all its output
words have been written. A threaded packet completes at the gang's completion
edge, before the producer resumes prepass work or rewinds storage.

### Local SIMD algorithm using only current vocabulary

[Current `simd.h`][simd-header] provides load, byte-masked load/store,
`simd512_and`, `simd512_splat_word` and `simd512_equal_word`. It does **not**
provide a general word prefix-min operation. Therefore the proposed algorithm
uses call masks and constant run fills rather than inventing a new primitive.

Pseudocode below is an algorithm specification, not tested C. `fill_words`
means a bounded scalar fill for short runs or broadcast plus bounded stores
for longer runs. Every macro argument in an implementation must be free of
side effects. Full tiles may use ordinary loads/stores; incomplete tiles use
the original scalar loop in the first experiment.

```text
next_calls(packet):
    carry = UINT32_MAX
    end = packet.first + packet.count       // checked production bounds
    while end > packet.first:
        begin = end - min(16, end - packet.first)
        k = end - begin
        if scalar_policy(k, host_features):
            for i = end-1 down to begin:
                if operand_masks[i] & CALL_ROW: carry = i
                next_call[i] = carry
        else:
            flags = load_masked(operand_masks + begin, prefix(4*k))
            calls = equal_word(and(flags, splat_word(CALL_ROW)),
                               splat_word(CALL_ROW)) & prefix(k)
            if calls == 0:
                fill_words(next_call + begin, k, carry)
            else if dense_policy(k, popcount(calls)):
                run_original_scalar_recurrence(begin, end, &carry)
            else:
                old_carry = carry
                first_call = begin + first_set(calls)  // calls != 0
                lo = 0
                while calls != 0:
                    j = first_set(calls)
                    fill_words(next_call + begin + lo, j + 1 - lo, begin+j)
                    lo = j + 1
                    calls &= calls - 1
                fill_words(next_call + begin + lo, k - lo, old_carry)
                carry = first_call
        end = begin
```

`CALL_ROW` denotes the existing `MACHINE_FAST_OPERAND_CALL_ROW`, not a new
encoding. Zero-length fills perform no access. A full-word broadcast supplies
all sixteen words; a partial store masks bytes, not sixteen abstract lanes.
A scalar escape is an exact algorithmic fallback, not a failure or semantic
exception. It does not change the original call-clobber definition.

The classification is concrete: call-free, sparse-call and dense-call tiles
of one already-prepared operation. No sorting by arbitrary opcode is involved.
Call-free tiles need one mask classification and a constant output store;
sparse tiles have at most `popcount(calls)+1` runs. Dense tiles can lose badly
if each run pays for a separate mask and vector store. The first integration
should consequently enable only the call-free fast path and keep **every
nonempty call mask scalar**. The sparse-run version is a separately measured
variant, not an assumed additional win.

### Correctness and ownership argument

Induct backwards over tiles. At a tile's entry, `carry` is the nearest call
strictly to its right within the block, or the sentinel. Between the preceding
call and an inclusive call position `j`, the nearest call is `j`; after the
last call in the tile it is the incoming carry. The run partition writes
exactly those intervals once, and the outgoing carry is the first call in
the tile. If no call exists, every answer is the incoming carry. The initial
right-edge carry is the sentinel. This proves equality with the scalar
recurrence, including adjacent calls, first/last-row calls, empty blocks,
partial tiles and completely call-free blocks.

The proof assumes the producer's existing validated block ranges, not a new
claim that arbitrary malformed overlapping block ranges are safe. The kernel
must remain after that same preparation/error path. One local owner writes
each output element; inputs are read-only. No operation touches register
ownership, memory effects, IR IDs, diagnostics or emitted-byte order.

### Parallel form and oversized blocks

Independent blocks can use one uniform fact-pass entry and `lane_range` over
block IDs. All output arrays are allocated before dispatch in a live result
arena. Workers use private descriptors and registers; the leader consumes
results only after the existing dispatch completion barrier. Whole contiguous
block groups reduce ownership boundaries. Sharing a cache line at two adjacent
block boundaries is false sharing, not a race; coalesce tiny adjacent blocks
or partition on output-line boundaries where legal instead of padding each
row. Cost-weighted contiguous ranges may beat equal block counts, but their
extra block-count/prefix walk must be priced.

This parallel form is permitted only at a top-level compiler boundary with
an explicit worker budget and safe prewarm. Starting a persistent gang in a
formerly serial prepass can make later lazy initialization illegal: full
prewarm and its cold cost cannot be omitted. An existing multi-lane TU caller
uses the **local** fact kernel, never `lane_run(P>1)` for each function.
For one lane, the same fact-pass entry and local kernel are used; barriers
reduce to their existing one-lane behavior.

One huge block is a straggler under block ownership. A bounded alternative
uses tiles with summaries `{first_call, tail_start}`:

```text
phase 1, disjoint tiles: compute local next_call with incoming sentinel;
                        record first call and start of unresolved suffix.
barrier
leader, descending tile ID:
    carry_in[t] = next call found in later tiles of this block;
    update that carry using this tile's first_call.
barrier
phase 3, disjoint tiles: fill only each unresolved suffix with carry_in[t].
completion barrier
```

Within a tile, only the suffix after its last call is unresolved. The summary
recurrence is an associative minimum with the sentinel as identity; segmented
block boundaries reset it. With cache-bounded reverse windows, the carry from
the following window is one scalar boundary value. Thus summaries need not
materialize a whole-program graph. Each window's output remains in the
existing array. This form introduces two internal barriers, summary traffic,
and repeated writes to unresolved tails. It is **not recommended initially**:
a low-work streaming recurrence may cost less than those barriers and writes,
even for a large block. A prefix algorithm is not automatically a useful
parallel algorithm.

### Microbatch size and exceptions

Local SIMD working state is a few vectors, masks and scalars. A streamed region
of 2,048 rows touches 8 KiB of flags and 8 KiB of output before accounting for
write allocation and neighbouring compiler state; that is a test coordinate,
not a claim about effective cache capacity. Test row windows that straddle
cache levels, rather than retaining all functions' machine rows to fill lanes.
The existing full-function arrays are not duplicated or prolonged.

No new allocation occurs in the local kernel. Unsupported host tiers execute
the original scalar recurrence. An actual issue, [#574][i574], reports word
fallback failures on F/BW-only AVX-512 hosts at an earlier main SHA. That report
was read but not reproduced here; its proposed root cause is not certified by
this research. A first guarded `BUSTER_SIMD_512` kernel avoids adding this
consumer to that tier, but does not repair or excuse the existing failures.
Feature-tier regression and self-host checks remain required.

## Design B — bounded TU refill with worker-local SIMD

### Difference from the existing driver

Design B keeps the current eligibility, independent compilation unit,
prewarm, durable result slots and ordered merge. The only scheduling question
is whether a cohort with `q*P` pending eligible TUs, for a small `q > 1`, can
amortize skew better than today's `q=1`. There is no whole-program phase queue,
no function task framework and no SIMD instruction interpreter. Each worker
continues to use existing local SIMD kernels, plus Design A only if admitted.

A concrete cohort retains the existing `CompilerDriverUnitBatch` fields and
adds, privately for an experiment, `worker_count` distinct from `count`, a
single `AtomicU64 next_unit`, and capacity `K <= q*P` for stable unit slots.
`P` remains bounded by the current job-count policy. In the one-worker case,
use `q=1` and the same unit kernel. Keep the current static `lane_range` path
as the `q=1` reference: adding claims to it is not a justified optimization.

The readiness key is `(native target, invocation options, eligible consecutive
input interval)`. It is not a guessed type/opcode shared by unrelated TUs.
All inputs/options must be frozen for the experiment. An object/archive/assembly
boundary ends the cohort. The current eligibility rule, including positional
language handling owned by [#536][i536], is not broadened by this design.

### Packet lifecycle and pseudocode

```text
leader before dispatch:
    choose K consecutive inputs accepted by current eligibility rule
    enforce the approved count/memory admission policy; otherwise q = 1
    prepare immutable invocation views and zero stable slots [0,K)
    perform existing both-target prewarm before the first gang
    initialize next_unit = 0

uniform unit entry on existing persistent gang:
    if q == 1:
        process current lane_range(K) using the existing unit kernel
    else:
        repeat:
            j = atomic_u64_increment(&next_unit)  // returns OLD index
            if j >= K: break
            enter verified per-unit scratch lifetime
            compile input[first_input+j] once into units[j]'s own arena
            record result, diagnostics and failure only in units[j]
            leave per-unit scratch without invalidating any result pointer
    return through normal gang completion

leader after completion:
    visit units[0..K) in original input order
    use current warning/statistic/object transfer and first-error rules
    preserve constructor/destructor priorities and archive boundaries
    destroy consumed and unobservable later TU arenas
    proceed to the next cohort only after cleanup
```

The only dynamic scheduling state is a bounded take-index over one array of
already-ready TUs, using the [existing atomic helper][os-api]. There is no producer
condition variable, polling loop, callback dispatcher, per-item barrier or
new worker creation policy. Claims need uniqueness; the existing dispatch
barrier supplies result visibility. No ad hoc atomic completion flags are
necessary because the leader does not consume live slots.

Persistent scratch is reset at **dispatch** completion, not necessarily
between multiple units claimed within one dispatch. Therefore `q>1` requires
an explicit audit of per-unit scratch scopes, counters, caches and escaping
pointers. Reusing a worker is not proof that its mutable state is reset.
The driver currently directs durable results to the TU arena; every added
scratch scope must preserve that ownership on all exits.

### Ownership, ordering, visibility and failure proof obligations

Atomic old-index claims give each in-range `j` exactly one owner. That owner
alone writes `units[j]` and its arena; no worker allocates into the leader's
shared result arena. Invocation views and serially prewarmed tables are read
only. After all callbacks return, the existing barrier publishes the slots.
The leader's ordinal walk gives the same merge sequence regardless of which
worker compiled each input. Empty/cohort-tail slots are never consumed.
Counters must also be accumulated from logical slots, not completion order.

This is an ownership/synchronization proof **conditional on** complete
per-unit mutable-state isolation. Before implementing refill, audit every
reachable shared cache/interner, global diagnostic limiter, allocation
observer, source/debug cursor and output side channel. Exclude invocations
with shared external write destinations unless their present semantics are
proven safe. Suppressing the ordinary object write is not by itself a proof
that every trace/metrics/auxiliary output is private. No eligibility widening
is authorized by this report.

Each recoverable failure is recorded in its slot. Finish the bounded cohort;
do not race to publish the first completed failure or globally cancel lower
indices. The ordered prefix, including the current failing input's prescribed
diagnostics, is observable; later warnings/results are not. All live arenas
are released. Tests must inject failure at stable `(input ID, allocation
ordinal)` coordinates and force delayed lower-index inputs. Real process-wide
memory exhaustion is scheduling-sensitive: a stable merge alone does **not**
prove identical allocation-failure location across thread counts. Deterministic
resource-failure policy is an unresolved admission gate, not an achieved
property. Fatal process faults retain the existing process contract; the
proposal does not add fault recovery.

### Memory admission is the principal blocker

With today's retention rules, increasing pending work from `P` to `q*P` can
retain **`q*P` full TU arenas**, even though only `P` units execute at once.
A descriptor count bound is not an RSS bound. A simple upper-bound model is:

```text
M_peak <= leader-live + sum(retained TU committed footprints in cohort)
          + sum(worker scratch high-water footprints) + compact merged output
          + shared tables + other process state.
```

Virtual reservations are not measurements of those committed footprints.
Until an approved resource policy is available, production stays `q=1`.
Experiments may use `q=2` or `q=4` only with explicitly provisioned headroom,
observed committed/RSS/allocation telemetry, fixed maximum pending count,
and a stop/reject condition. No automatic RAM fraction or cgroup detector is
introduced here. Unknown headroom means no refill admission.

A later option is to copy each completed result into a **slot-owned compact
arena**, destroy its full TU state, and then refill. That could bound full-TU
population near `P`, but it must transfer every section, name, relocation,
debug record, initializer priority, diagnostic text, fallback record and
source-metric string. It also adds copying/allocation or requires transferring
ownership without another copy at final merge. This is a dependency to prove,
not a free optimization or permission to move the current leader copy into
shared mutable storage. Do not claim the memory improvement before pointer
lifetime tests and complete traffic accounting exist.

False sharing should first be addressed by per-worker local accumulators and
one final slot write; isolate the single claim counter from hot result fields.
Do not pad every row or allocate a cache line per tiny fact. Record claim
contention, result-copy bandwidth, arena reuse locality and cross-core cache
misses. Refill may reduce cohort idle time while increasing total CPU work and
memory traffic; such a result can be a rejection, not success.

## Intra-function, cross-function and TU comparison

| Boundary | Actually ready population | Legal ownership/publication | Principal cost or blocker |
| --- | --- | --- | --- |
| Within one block | Existing flags after the first FAST walk | Local recurrence and block-bounded carry | Short/dense runs; vector setup and repeated fills |
| Across blocks of one prepared function | Immutable flags, disjoint output ranges | One fact-pass gang; completion before next prepass consumer | Prewarm/dispatch, imbalance, false sharing; no nested TU gang |
| Across functions in one TU | Only facts whose producer and shared state are frozen | Function-indexed provisional results, then ordered publication | Current signature/source/debug/assembly state is not generally private |
| Independent eligible TUs | Consecutive driver inputs under current policy | Private TU arenas, input-indexed slots, existing ordered merge | Retained memory, source-order boundaries, skew and copy traffic |

Cross-function batching must not materialize all functions in another IR just
to increase occupancy. At most hold cache-sized windows of already-ready
compact facts with stable `(function, block, row)` identities and a lifetime
ending before producer storage is rewound. No cross-function gather is
permitted from a TU arena whose coordinator may destroy it.

For the broader [#54 backend boundary][i54], stable function-indexed counts
would allow deterministic allocation of final regions:

```text
offset[0] = initial_position
for f in stable function order:
    start[f] = checked_align_up(offset[f], alignment[f])
    offset[f+1] = checked_add(start[f], final_size[f])
```

Workers can then write only their assigned regions, with zeroed padding and
stable symbol/relocation/debug merge. But `final_size` must be final under the
existing branch relaxation, encoding and fixup rules. Prefix sums alone do
not solve size-changing layout dependencies, shared line suppression,
module-owned signatures or inline-assembly symbol mutation. These obligations
belong to #54. C function-body lowering has its separate mutation-inventory
owner [#531][i531]; this report does not claim it is thread-safe or make it a
new blocker for #36's retirement work.

For variable-length compact fact results, allocate by **logical packet counts**,
not per-worker totals: stable packet prefix, then stable active-element rank
within each packet. Otherwise changing the worker count changes IDs/layout.
Design A's fixed indexed output deliberately avoids this extra allocation,
count pass and scatter altogether.

A single oversized function inside a single TU cannot be fixed by increasing
TU queue depth. Split only demonstrably independent fact phases or wait for
#54/#531's ownership work; never split the stateful allocator's row stream or
move C declarations/effects across source-order dependencies.

## Dispatch thresholds and a full-cost model

Let `n` be ready items, `W` active words per vector (maximum 16), `r` the
number of constant runs, and `P` actual workers. Costs must come from separate
instrumentation/calibration on the admitted host, then be frozen for timed
comparisons:

```text
S(n) = n * scalar_item_cost
V(n,r) = vector_setup + ceil(n/W) * tile_classify_cost
         + run_fill_cost(n,r) + tail_cost + packing/scatter/locality_cost
T_parallel = prewarm + gang_dispatch + internal_barriers + claim_cost
             + max(worker_work) + prefix/merge/copy/cleanup + locality_penalty
CPU_work = sum(worker CPU work) + coordinator CPU work
           + scheduling/synchronization CPU work.
```

The maximum-worker term predicts elapsed phase time, not aggregate work.
Blocking wait time and CPU time are different quantities. Cold and warm
prewarm/dispatch cases must be separated, with the appropriate cold costs
included in end-to-end measurements.

**Immediate scalar:** choose scalar when `S(n) <= V(n,r)` or when the
available ready tail fails that inequality. With per-item vector savings `d`
and fixed overhead `F`, `ceil(F/d)` is a break-even lower bound only when
`d>0`; run density, cache state and tails can invalidate a simple count cutoff.
Do not invent a universal cycle count. Non-full-feature host tiers initially
use the original scalar algorithm.

**Local SIMD:** choose the vector class only when its measured total cost is
lower than scalar, including classification of tiles that subsequently escape.
For the first prototype, try a conservative **uncalibrated** gate of blocks
with at least 64 rows, full 16-word tiles only, vector fills only for zero call
masks, and immediate scalar tails/nonzero masks. Sweep that gate rather than
promoting 64 as a discovered threshold. No-call handling removes a recurrence
chain; sparse handling must separately repay mask iteration and run stores.

**Parallel:** dispatch only when predicted best-local elapsed work exceeds the
full `T_parallel` model, an existing top-level worker budget is available,
and memory/initialization admission is satisfied. A useful lower-bound test
for roughly balanced work is `local_time*(1-1/P) > fixed_parallel_overhead`;
actual imbalance, bandwidth and merge cost make admission stricter. An active
multi-lane TU caller uses local SIMD instead. `q=1` never gains an atomic
claim counter just for stylistic uniformity.

**Refill/compaction:** with `t` ready tail items, scalar beats repacking/waiting
when `t*scalar_item_cost <= pack_cost + refill_cost + wait_cost + masked_cost`.
At a producer/phase boundary, do not wait for hypothetical future work. For
in-memory ready work, stable compaction is allowed only if the saved expensive
masked iterations exceed every packing/index/scatter cost. Design B's refill
benefit is reduction in the critical-path maximum across cohorts, not SIMD
occupancy across different compiler phases.

Cache-sized microbatches are a joint working-set budget: input/output,
metadata, summaries, temporary state and neighbouring producer/consumer data.
Sweep 16/32/64 KiB nominal touched-data regions and a larger negative control.
Do not label 64 KiB universally L1-resident. Increasing `P` multiplies scratch
and simultaneous bandwidth demand; SMT and NUMA are separate experimental
factors, not assumptions of linear scaling.

## Experiments, attribution and validation

### Frozen manifest and authorized execution

Before any run, freeze compiler-source commits/trees, Clang version and binary
hashes, full flags, generated inputs, included files, argv, environment,
allocator mode, target/ABI, artifact kind and output paths. Freeze the workload
separately from the compiler sources. Record CPU/model/features, physical vs
virtual status, core/SMT/NUMA placement, affinity, frequency policy, OS,
memory limits, available counters, lease and competing workload controls.
Use only an explicitly authorized CI job or qualified remote host, not a
laptop. None has been used for this report.

Use the [native throughput harness][harness] and [benchmarking contract][bench].
The documented entry points are `./build.sh bench_throughput self-test`,
`run --baseline ... --candidate ... --output NEW_DIRECTORY`, and `compare`.
These are **future commands, not executed evidence**. Host-CI bootstrap uses
the documented `build/build` route. Do not build compilers inside a timed
sample, overwrite previous results, weaken the predefined guard or substitute
an external benchmark service. First qualify collection with frozen A/A.

The existing single-input object workload is suitable for Design A's
end-to-end guard, but is not automatically a multi-TU link scaling experiment.
Design B needs a supported native-harness multi-input workload and the existing
workload/multicore owners, including [#423][i423] and [#424][i424], where those
capabilities are not already admitted at implementation time. A flag on a
single-TU case is not scaling evidence. This report does not implement or
redesign that harness or the external service.

### Factor matrix

| Factor | Candidate experiment coordinates | Interpretation |
| --- | --- | --- |
| Worker count | 1, 2, 4, 8, then available physical cores; SMT separately | Clamp to actual available workers; no nested multiplication |
| SIMD width | Scalar; 512-bit operations with active word populations 4, 8, 16 | Active width is not physical 128/256-bit code; current interface stays 512-bit |
| Tile/tail population | 0, 1, 7, 15, 16, 17, 31, 32, 63, 64, 65 | Correctness boundaries and dispatch overhead |
| Local window size | 64, 256, 1,024, 2,048, 8,192 rows | Working-set and producer-consumer locality effects |
| TU cohort depth | q=1 reference; 2 and 4 only under memory admission | Separate extra pending work from an atomic-claim change |
| Workload size | Tiny startup, small/many functions, one huge function, full frozen self-host source | Include the regime where setup dominates |
| Heterogeneity | No calls; isolated, clustered, alternating and dense calls; equal vs skewed block/TU sizes | Report distributions, not only averages |

Cross worker count, active width, window size, workload size and heterogeneity
in an initial screening matrix, then retain paired runs for the surviving
configurations plus baseline and negative controls. Test actual full-width
kernels on qualified Zen 5 and Zen 4; fallback correctness covers AArch64,
MSVC, non-AVX-512 and the F/BW-only feature tier. Physical 128/256-bit kernels
are **not implemented or implied** by this report; adding a new width API is
outside this bounded integration. Record logical occupancy and actual emitted
instruction width separately.

At each supported parallel boundary collect the four corners:
`scalar/1 worker`, `SIMD/1 worker`, `scalar/P workers`, `SIMD/P workers`.
These expose SIMD benefit, threading benefit and their interaction. For TU
experiments additionally compare static `q=1`, claimed `q=1` as an overhead
control, and admitted claimed `q>1`. Use the same corpus/flags at every corner.
A different input permutation is a different frozen workload: compare A/B
within it, not artifact identity between different source orders.

Instrumentation-only runs census rows/blocks/calls, run lengths, masked
occupancy, scalar escapes, useful vector stores, bytes packed/scattered,
queued claims, per-worker useful/idle time, dispatch/barrier time, result
copying and arena/scratch high-water marks. Census counts must distinguish
attempted from completed work and logical inputs from padding/retries.
Time uninstrumented paired compilers separately; counters must not bias the
reported latency comparison.

Report whole-invocation wall-time distributions and uncertainty, compile
throughput on real source-byte/token/TU denominators, summed user+system CPU
time including coordinator/children as supported, hardware work counters when
available, peak RSS/committed storage and artifact hashes. PMU access and
process-tree/thread accounting must be documented; do not double-count
inclusive child counters or label Callgrind Ir hardware retired instructions.
Phase wins alone are insufficient. Include cold prewarm, classification,
allocation, packing, merging, cleanup and any duplicate writes in both work
and elapsed accounting.

### Required correctness gates, all unrun

The local kernel needs a differential oracle over every tested block and
randomized bounded call patterns, empty/dense blocks, call positions at every
tile edge, partial loads/stores with red zones, maximum legal indices,
sentinel preservation and the unchanged invalid-prepass path. Verify the
same arrays feed production placement rather than a test-only duplicate.
The simple hand-check `[no-call, call, no-call]` must produce
`[call-index, call-index, UINT32_MAX]` and must not inherit a following block's
call. This is an example of the specification, not an executed test.

Parallel variants additionally need disjoint-write/race checks where supported,
repeated gang growth/shrink/reuse, one-worker and single-threaded configurations,
delayed earliest failures, allocation-failure injection, all-lane completion,
private scratch lifetime, stable warning suppression and stable counters.
For TUs retain object/archive/assembly and positional-language boundaries,
constructors/destructors and priorities, relocations, debug/unwind data,
source-metric strings, target switching and shared-output exclusions.
The optimized-Clang constructor-control discrepancy retained by #388 must be
disposed of by its existing owner, not hidden by replacing a fixture.

Run the applicable existing Debug/Release, sanitizer, target/platform and
NONE/FAST/MIR_STACK/QUALITY matrix plus the original self-host fixed-point
and canonical-validation gates on the exact candidate. Compile-time flags,
warning policy, test populations, timeouts and required unsupported-path
behavior stay unchanged. Cross-host feature fallback is a correctness gate,
not a speed claim from the fallback. #574 remains separately owned.

### Acceptance and stop rules

Predeclare the native harness's statistical guard and a CPU-work/RSS budget
before looking at candidate results. A conservative proposed admission rule
for this research is no supported-case regression under that guard, a
repeatable positive whole-compile result on the intended workload, and no
unexplained aggregate CPU-work or retained-memory increase. Any permitted
latency-for-work trade requires an explicit separately reviewed budget; it is
not silently called a compiler-throughput win. Inconclusive comparisons stay
inconclusive. No existing repository guard is changed by this proposal.

Reject A if current census/phase attribution bounds its possible end-to-end
benefit below measurement resolution or engineering cost. Reject its sparse
version when mask iteration/fill overhead loses to scalar, and reject its
threaded version when initialization, barriers, summary traffic or locality
consume the gain. Reject B if refill cannot supply useful pending work,
source-order boundaries dominate, memory admission is absent, claim/copy
cost cancels reduced idle time, or repeated execution leaks worker state.
Do not keep a global queue, extra representation or extra pass merely because
its vectorized inner loop is fast.

## One bounded integration experiment and ownership

The recommended future change is **A0: call-free full-tile broadcast in the
existing FAST next-call pass, local to each current worker**. First obtain a
current-source phase attribution and tile census. Only then prototype a
single guarded replacement of that loop, using the original scalar recurrence
for small blocks, nonzero call masks, tails and non-full-feature host tiers.
No new SIMD builtin, queue, gang entry, permanent field, CI workflow or
semantic validation change is necessary for A0. Observe it under the existing
TU `-fcompile-jobs` values to separate local SIMD from existing threading.

Go/no-go is driven by full-cost measurements, not the historic backend share.
A0 is deliberately smaller than sparse-run filling, cross-block dispatch,
cross-function code generation or TU refill. Negative evidence should be
recorded and the candidate discarded when it fails the admission model.
Nothing in this report implements A0 or authorizes merging it.

The canonical detailed deliverable is this single timestamped Markdown file.
Related work remains [#53][i53] for TU scheduling and memory admission,
[#54][i54] for per-function code generation, [#531][i531] for C function-body
lowering, and [#574][i574] for the reported fallback defect. Cross-links should
be substantive comments on #53/#54, not a duplicate wavefront epic or a new
issue for every possible kernel. This research is not a closure of any issue
and does not expand #36's acceptance criteria.
