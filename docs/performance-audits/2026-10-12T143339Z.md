## Workloads

Each workload replays the relocation table of a real object. The objects are
`m4096.o` (16,385 rows, 8,192 general-dynamic sites) and `m16384.o` (65,537
rows, 32,768 sites). Both were built with Clang 18 `-O0 -fPIC -g0`, and their
hashes are in `2026-10-12T121724Z`. A workload runs that table through the two
x86-64 ELF link phases that ask whether a `__tls_get_addr` call completes a
TLSGD/TLSLD pair:

- **Import classification**, as in `link_elf_symbol_only_relaxed_tls_get_addr`.
- **Relocation application:** one query per row.

The two methods differ only in that question:

- **scan:** the full-table candidate search, as in `link.c` at `6082834`.
- **index:** the #2247 sparse exact `(section, offset)` table, as in
  `22b1a04`. It uses the same `buster_hash_64` 16-byte-key hash and the same
  open addressing. Building the index is inside the timed process.

Parsing, merging, layout, patching and publication are outside both
workloads.

Each run checks that every helper reference is classified as relaxed, and
exits 1 if not. For the same input the two methods printed the same digest of
the relaxed rows: `6b8046173263a325` at 8,192 sites and `41f1f44027d02325`
at 32,768.

## Results

The runner built each workload with Clang (`-std=c11 -O2 -static -fwrapv
-fno-strict-aliasing -funsigned-char -Wall -Wextra -Werror`). It then ran
2 warmups and 9 measured fresh processes pinned to CPU 2. The time is process
wall time from fork through wait4. All 44 runs exited 0, with no signal or
timeout.

| workload | sites | wall median ms | wall min–max ms | CPU median ms |
| --- | --- | --- | --- | --- |
| tls-companion-scan-t8192 | 8,192 | 38.917 | 38.052–39.102 | 38.662 |
| tls-companion-index-t8192 | 8,192 | 0.864 | 0.823–1.125 | 0.676 |
| tls-companion-scan-t32768 | 32,768 | 615.301 | 605.594–622.055 | 614.731 |
| tls-companion-index-t32768 | 32,768 | 3.634 | 2.024–5.609 | 1.974 |

- **Scan scaling:** scan CPU time grows 15.9x for a 4x increase in sites,
  which is the quadratic membership search.
- **Index scaling:** index CPU time grows 2.9x, including process startup and
  reading the 1.5 MB input.
- **Index wall noise:** at 32,768 sites the index's wall times range widely,
  2.0–5.6 ms, while its CPU times stay between 1.8 and 2.2 ms.
- **Ratio:** the index median is 2.2% of the scan median at 8,192 sites and
  0.6% at 32,768.

## Limits

- **Diagnostic numbers.** The runner holds no service lease and runs each
  workload's samples back to back, not interleaved with the other method. The
  load average was 0.80 before the run and 0.82 after.
- **Mechanism only.** Whole-link cost, page-cache state, archive handling and
  phase boundaries are not measured here. The remaining #1915 cohorts are
  still open: cold cache, many small objects, large archives, a phase
  breakdown and same-source rebuild controls. So is an end-to-end 9700X link
  measurement, which would need a new trusted-main harness profile.
- **Not regenerated.** The `.data` inputs were not regenerated from the
  original objects for this audit. They are pinned by the SHA-256 values in
  the report (`a8cbf8ee…` and `c12108fa…`).
