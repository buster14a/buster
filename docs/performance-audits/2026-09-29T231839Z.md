## Source observations and interaction model

The implemented path is promotion/frontend SSA -> F -> A -> D -> P -> one
compaction/certification/CFG publication -> selection -> allocation -> optional
QUALITY machine scheduling and second allocation -> encoding.

F is a forward physical-row fold scan. A is a forward physical-row address
scan. D counts live operands and incoming arguments, then deletes pure unused
definitions transitively. P runs at most four full block/parameter sweeps,
updating aliases immediately. Default frontend SSA already simplifies trivial
parameters to a fixed point and prunes unused parameter cycles. P compares
root IDs, not equal constant bits. These facts substantially weaken the
hypothesis that routine C will require repeated FAST cleanup.

| Interaction | Minimal witness / causal mechanism | Status and incidence |
| --- | --- | --- |
| F -> P | `phi(x+0,x)` becomes ID-identical after F aliases the add | Executed `phi_identity`; putting P first misses it. All three P-changing default functions are artificial. |
| F -> A -> P | Identity pointer cast around `&*p`; address aliases can make incoming roots equal | Source-derived canonical witness; C frontend can erase the cast already. No additional A rewrite in full replay on primary inputs. |
| F/A -> D | Aliasing or conversion to a constant removes operand uses, enabling transitive deletion | Implemented and active: baseline F has 154,514 changes, A 11,061, D 205,162. These totals do not establish an order benefit. |
| P -> D | Removed incoming columns release a pure producer that earlier D kept alive | Executed `dead_phi`; FAPD saves two canonical rows and 32 encoded bytes. Zero matching benefit outside the artificial interaction file. |
| P -> F/A | `c=const4; d=identity_cast(c); q=phi(d,c); r=q+2` leaves r opaque to first F but constant after P | Canonical source deduction, not a demonstrated default-C opportunity. Every measured additional F invocation is no-match. |
| P -> P | Reverse-ordered loop-parameter chain needs more than four sweeps | Offline canonical counterexample; executed forced-memory fixture also leaves one useful removal. Default fixture reaches its useful fixed point within four sweeps. |
| Equal bits vs IDs | `phi(c+0,c)` with c constant: F materializes a fresh constant before considering the identity rule | Replaying F/P cannot create missing interning/SCCP. Source deduction; do not count every equal-valued phi as a schedulable opportunity. |
| Physical order vs def-use order | A valid linked def-use sequence can have later physical IDs for its definitions | Second F could help such canonical input; ordinary-C occurrence and final benefit were not established. |

There is no implemented oscillatory pair: current F/A/D/P neither expand rows
nor reverse successful rewrites. Explicitly planned transformations are
different: #48 inlining expands work; #1937/#1938 idiom recognizers can depend
on preserved loop/bit structure; #1943 target-aware constant DIV/REM can replace
one operation by several; #1949 conservative pure nontrapping integer LICM can
extend live ranges and increase spills. Folding may expose or erase recognizer
shape. Hoist/rematerialize could oscillate only if both directions are later
specified; no such implemented pair is alleged. These interactions remain
with their existing owners and are not used to justify today's policy.

Source anchors: `src/buster/lib/compiler/ir/ir_fast.c` F/A/D/P and scheduling;
`ir_promote.c` compaction/shared promotion; `c_gen.c` frontend parameter
simplification; `ir_cfg.c` publication; `machine_select.c` transparent address
queries; `machine_schedule.c` pressure/placement; `codegen.c` QUALITY acceptance.
The selector can already traverse transparent addresses. Removing an IR row
therefore need not improve machine code. QUALITY accepts a rescheduled second
allocation only when its existing reload/spill/callee-save objective improves;
an IR rewrite count cannot substitute for that downstream observation.

F aliases `x+0`; D deletes `y+1` but counts the incoming uses of x; P then
removes the parameter too late to release x to D. FADP yields 17 -> 11 rows;
FAPD yields 17 -> 9. On native FAST and QUALITY, the `dead_phi` symbol decreases

prologue and epilogue. Fixture-wide allocator counters improve by one spill,

runtime speedup claim.

## Termination, bounded work, and invalidation

Current successful changes have a simple rank: an instruction can be converted
to a constant at most once and removed/aliased at most once; each parameter can
be removed once. Thus successful F/A/D/P changes before compaction are bounded
by `2*I + P0`, and none reverses a previous rewrite. This proves absence of
current oscillation, not cheap convergence: full rescanning to closure can
still be quadratic. With I rows, O operands, J incoming occurrences and B
blocks, fixed F/A scans and D are bounded linear traversals plus root-query
costs; current P performs at most four ordered traversals of B/P/J, including
the final unchanged round. FAPD keeps that same ceiling and one compaction.

If a dirty agenda were eventually warranted, preserve stable block/parameter
ordinal order. A dependency changed before an unvisited parameter belongs in
the current sweep; an already visited dependency belongs in the next sweep.
Four snapshot rounds or FIFO are different policies. Bound index construction,
incoming checks, root hops, retargeting, stale notifications, enqueue attempts,
and pops separately. A rewrite-count or iteration cap alone is insufficient:
notifications can be O(J*M) over M root changes. A shared work-token ceiling
must leave valid partially optimized IR on exhaustion and report incomplete
cleanup. Planned expanding/reversing transformations need their own oriented
rank or explicit attempt budget; the present monotonic proof does not cover
them. Keep offline schedule discovery finite and publish a deterministic small
policy, never runtime combinatorial search.

Fact lifetime policy for the candidate:

| Mutation boundary | Facts that may survive | Facts to update or discard |
| --- | --- | --- |
| F/A aliases or constant conversion | Immutable type facts; unchanged block/target topology | Rooted uses, operand/constant/address facts, opcode summaries, producer certification |
| P incoming-column removal | Block identities and predecessor topology | Incoming/edge argument columns, use counts, parameter facts, cached address/value facts |
| D deletion | Unchanged topology and immutable types | Live uses/definitions, spans and source ranges, summaries |
| Single compaction | Immutable semantic types | Every value/instruction-ID keyed map, index, replacement view and selector cache; line marks remapped |
| MIR scheduling | Canonical IR | MIR placement, liveness and edit indices; existing second allocation required |

Build D's uses after the last alias/P mutation. Reusing earlier D counts after
P requires subtracting removed incoming occurrences and redirecting all alias
consumers; merely keeping the old array is invalid. Current experiment clears
and rebuilds it. Keep changes in existing lane scratch, compact once, and
rebuild facts from the canonical compact form. Revoke prepared/certified
markers when external mutation makes them stale. Avoid publication/reopen
cycles; if required later, their retained-memory admission and rebuild costs
must be charged. No process-global mutable cache or parallel new lane system
is proposed.

## Uncertainty, strongest counterargument, and smallest useful packet

The strongest counterargument is coverage: direct frontend SSA aggressively
cleans joins, this sample is dominated by the compiler's unity source, and
other real source/frontend shapes could resemble the forced-memory fixture or
planned passes. The sample cannot prove universal schedule neutrality. QUALITY
coverage is limited to two generated sources plus interactions; AArch64,
full MODE/selfhosting/non-native matrices, compile-time/RSS, and runtime
measurements were not executed. The dedicated benchpress 9700X was not exposed
in the available execution environment; no dedicated performance job was
submitted and no desktop measurement substituted. Therefore **there are no
accepted performance measurements** in this investigation.

The useful packet now is the small causal fixtures, counters, frozen schedules,
interaction/fact-lifetime model and durable evidence in this audit, under #49
and #47. No production implementation is justified. If an owner supplies a
real default-path occurrence, the smallest implementation candidate is an
explicit four-entry `F,A,P,D` order using existing passes, one compaction and
unchanged independent pass selection. Validate all 16 pass subsets/contracts,
MODE/selfhosting and non-native coverage before considering enablement. Then
use matched uninstrumented revisions on the dedicated 9700X for compile time,
RSS, allocation traffic, encoded size and relevant runtime; compare fixed
FAPD before adding any selective replay. Do not start with a worklist.
