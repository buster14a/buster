The failures occur with Buster producing and Clang consuming, across the
three MIR allocators, two C forms and two PIC settings. The failure is not
waived. Independent Clang cross-target assembly and LLVM IR reproduce the
cause: Darwin caps bare vector ABI alignment at the CPU register width.
At baseline, both 32- and 64-byte vectors use sixteen-byte alignment;
Haswell uses thirty-two; AVX-512 permits sixty-four. ELF retains the full
vector alignment regardless of available registers. In particular the
Darwin baseline va_arg sequence adds 15 and masks by -16, whereas the
Linux sequence for the same 32-byte vector adds 31 and masks by -32.
MIR incorrectly rounded the Darwin public overflow cursor to thirty-two.

`machine_x64_vector_stack_alignment` now supplies this ABI rule to wide
argument placement and frame-backed wide va_arg metadata. The verifier
allows the smaller power-of-two alignment while still rejecting forged
single-register metadata for a 32/64-byte frame value. Registered metadata
checks cover Linux/macOS/iOS, baseline/Haswell/Zen 5 and both C forms. The
existing native Clang exchanges continue unchanged and must pass on the
repair head; no semantic test, deadline or sanitizer has been disabled.
Frontend storage layout is unchanged by this ABI correction.
