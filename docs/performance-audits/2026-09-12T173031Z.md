## Correctness and reproduction

Before integration, baseline Release passed 2,622,824 assertions / 48 modules
and its 38,446,560-byte ordinary fixed point. Candidate Release passed
2,624,224 assertions / 48 modules and its 38,446,856-byte fixed point, including
machine and canonical stages. The 24-leg mode matrix had zero failures: four
legs executed locally and twenty had link-only coverage because execution and
disassembly tools were unavailable. These results are retained alongside this
audit. Final rebased-head validation and GitHub CI are reported in the PR.

New registered tests cover mutually dependent irreducible joins, trivial
cycles, disconnected parameter blocks and reverse-order sparse diamonds at
8/32/128 sizes. The geometric allocation-build test counts the initial index
and rejects the old whole-CFG rescan budget. Existing tests retain the two
frontend forms, initialization/late-memory recovery, aliases, debug metadata,
malformed inputs, four target layouts and the shared promotion oracle.

An initial diagnostic ASan/UBSan Debug invocation passed all 580,254 frontend
assertions, including the new work budget, but was not green: four assertions
failed in file/subprocess and metamorphic tests, and LeakSanitizer terminated
with its environment/ptrace diagnostic. CMake had captured sanitizer options
at configure time, overriding the options supplied at build time. The final
rebased validation invokes the sanitized binary directly with
`ASAN_OPTIONS=detect_leaks=0:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1`;
leak coverage is not claimed. The initial failure summary is retained.

The installed TCC rejected unchanged `string.c:991`. The trusted producer used
the repository's documented Clang bootstrap spelling for `build.c`; this is
not a successful canonical TCC-bootstrap claim. Filesystem exhaustion required
temporary memory storage and `BUSTER_TEST_TEMPORARY_BASE`; no repository gate
or bootstrap policy was weakened.
