## Workload

Every arm compiles the same input, the base revision's unity self-host source,
from the base checkout:

```sh
ide cc -Isrc -Ibuild/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -c \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

There are four arms, counted with Callgrind (`--cache-sim=no --branch-sim=no`):
- A: base, default flags;
- B: base with `-fc-ast-pilot`;
- C: candidate with `-fc-ast-pilot`;
- D: candidate, default flags.

The objects were also built at `-g` with each arm's binary, outside Callgrind.

## Census (base, A arm)

A throwaway census build of the base wrapped both tests in noinline
functions. It called empty noinline marker functions for each category, and
Callgrind's call counts read them. Its `-g0` object is byte-identical to A's.
The instrumentation is not product code; its patch is kept in the evidence
bundle.

- **The tokens reaching the type-word test.** At the declaration branch,
  86,724 of the 98,569 identifiers are bound to an entity and 6,990 are
  predefined symbols. Every one of the 4,985 at the `declaration_statement`
  test is bound. No token lacked an interned symbol.
- **The token form agrees.** The census also asked
  `c_parse_type_word_for_dialect_token` at both sites. It answered all
  103,554 exactly as the spelling ladder did. It reads the symbol's
  `word_bits`, which `c_parse_word_bits_compute` derives from the same
  spelling predicates, and every specifier spelling is interned in the
  predefined range.
- **The label proof has no cut.** The necessary shape, an identifier
  followed by `:`, is already tested inline before the out-of-line proof.
  Only 12 first tokens pass it, and all 12 are labels. The earlier 5.7 M

  noinline wrapper around the inline test, so it mostly measured the wrapper's
  call on 155,771 statements.

  the indexed label candidates up to the next proven label. That is 18,882
  proofs for 2.19 M, under the 3 M floor. It is recorded as a lead and not
  built.

- **Where the saving is.** `c_ir_lower_body_advance` inclusive falls from
  455.84 M to 446.86 M (A to D) and from 468.23 M to 459.26 M (B to C). Its
  8.05 M of spelling-ladder calls are gone, and so is the spelling setup
  before each call. The two `word_bits` reads cost less than that setup, so
  the function falls by 8.98 M, a little more than the calls alone.
- **The two paths save the same amount.** The test is on the token path,
  which both arms run.
- **Other callers keep the ladder.** `c_ir_query_execute`'s 48,392 calls
  (4.98 M) are unchanged. They are outside this slice and are a lead.

## Validation and limits

- Callgrind counts instructions, not time, on `-march=x86-64-v3` builds whose
  AVX-512 kernels are compiled out.
- One input, one host, single process, no pinning and no `perf` counters. Wall
  time was not measured: the budgets did not ask for it, and on this host it
  cannot resolve an effect of this size.
- **Not run:** the sanitizer tree, `test_mode_matrix` and a mutation of the
  reference check.
- **Census build:** its counts come from an instrumented copy of the base
  (`census.patch` in the bundle), and its object matches A's.
