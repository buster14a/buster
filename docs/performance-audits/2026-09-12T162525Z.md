## Problem, scope, and implementation

[#91](https://github.com/buster14a/buster/issues/91) owns test runtime fixture
retention. The frozen baseline is `8c5a9bd6837a0e4beecbd6fdd1f9adeb175fce96`.
The unchanged full Release suite passes 2,291,140 assertions in 47 modules;
its first measured complete-invocation RSS is 620,152 KiB. The old issue's
473 MiB / 313,120-assertion observation is not the current acceptance baseline.

An observation-only build first measured modules and direct frontend/driver
fixture calls without rewinding them. A second observation-only build split the
inline driver body and machine helper calls. The retained source patch and raw
arena CSV reproduce that measurement. Only after this census were independent
fixture lifetimes shortened. No assertion or module was removed or disabled.

`BUSTER_TEST_FIXTURE` directly calls each counts-only helper, consumes its
counts, then rewinds the supplied arena. Inline driver groups close after their
last consumers. The undefined-reference source pathname stays with its dependent
invocation, and the original vector result/path stays with all CPU-model
comparisons. A Clang AST reference census and a lexical review of conditional
branches identified these cross-boundary references before the rewinds were
introduced. Static target lists and scalar counters survive independently of
arena storage. Machine tests retain their shared program/verifier body through
its dependent assertions.

The runner emits versioned module/fixture records in verbose or CI mode and a
largest-fixture summary per module. A scope observes its supplied arena and both
selected-context scratch arenas. It samples the live cursor on exit and preserves
internal rewind/decommit peaks in separate test-only header storage. The 64-byte
arena header size, dirty-byte zeroing rules, and allocation fast path are
unchanged. Test-disabled builds have neither the counter nor its rewind stores.

Failure messages are synchronously consumed or copied before reclamation.
Parallel modules retain output in separate arenas and replay it in descriptor
order; result records remain below module marks. Temporary-root paths and
compiler-global caches retain their existing owners. Scratch lifetimes are
observed but continue to be closed by their existing temporal owners.

## Reproduction and acceptance budgets

Both measured binaries use Clang 18.1.3, `-march=native`, effective `-O2`,
`-fwrapv -fno-strict-aliasing -funsigned-char`, test inclusion, and non-unity
Release. Generate through the native build driver:

```sh
clang -Isrc -g build.c -o /tmp/buster-build
/tmp/buster-build generate --cc clang --ci --linker DEFAULT -- -DBUSTER_UNITY_BUILD=OFF
/tmp/buster-build build --config Release -t ide -- -j2
```

Save an unchanged-base binary, apply the retained measured-candidate source
patch (`gzip -dc measured-candidate.patch.gz | git apply`) on that same base,
incrementally rebuild, and save the candidate. Run from
the repository root with an unused output directory:

```sh
python3 docs/performance-audits/evidence/2026-09-12T162525Z/measure.py BASE_IDE CANDIDATE_IDE OUTPUT --pairs 3 --jobs 2
```

The collector alternates AB/BA order, retains every sample, checks exact module
results/assertion counts and the algebraic identities of arena counters, and checks the reference
budgets: **640 MiB process-tree RSS**, **64 MiB driver primary peak**,
**40 MiB frontend primary peak**, and **80 MiB machine primary peak**. These
budgets describe this full Release profile with two test jobs and all table
audits enabled. They are not portable sanitizer or arbitrary-parallelism limits.
The primary-arena budgets would reject the old retention behavior even though
the complete-invocation RSS budget accommodates the current unrelated peaks.

RSS is the Linux wait4 high-water observation for the complete invocation,
including subprocesses. Separate arena mappings, pools, executable memory,
metadata caches and worker contexts are outside the three observed arena
cursors. The much larger logical retention improvement must not be advertised
as the RSS improvement. A `/proc` sampling attempt reported only a small proxy
process and was rejected as a measurement of the actual test runner.
