# Byte acquisition and incremental decoding: QOI pilot

## Scope, ownership and disposition

This is an archival research audit, not a decoder implementation, a capability
claim for current main, or a new admission requirement. It preserves the
investigation originally published under [#1840][report] (shared reader
conventions) and [#1834][image-handoff], with implementation ownership retained
by [PR #1874][image-pr]. Live work remains on those records.

**GO** for one owner-coordinated, codec-private QOI continuation follow-up.
**NO-GO** for production acceptance, a universal media-stream abstraction,
reduced copies versus the existing mapped-QOI path, or a speedup claim.

The bounded result is that an independently written C prototype decoded the
same valid bytes under whole-buffer, one-byte, every two-way split, and mixed
backpressured delivery. It retained at most 13 encoded bytes between calls
(at most 4 within an opcode), with no retained input pointer. This establishes
feasibility for the tested QOI cases, not correctness of Buster's decoder or
other codecs.

The strongest counterargument is that the mapped QOI path already avoids an
encoded gather, while its consumer may still need the entire decoded image.
Continuation adds state, calls and publication complexity without demonstrated
benefit to that existing consumer. That negative result is part of the outcome.

## Question, hypothesis and first discriminator

Question: does QOI inherently require complete-file availability, or does the
current one-shot interface and state arrangement require it?

Hypothesis: persisting the format's small continuation state is sufficient;
retaining the entire encoded file is not a format requirement.

The cheapest useful discriminator was a standalone, allocation-free C QOI
state machine, not a new shared inflate implementation. QOI exercises a split
header, partial multi-byte opcodes, a previous-pixel index, long runs, output
stalls and a terminal marker without adding Huffman/LZ/bit-refill machinery.
The independently written prototype is not extracted execution of #1874.

Acceptance for this diagnostic is equality of the normalized decoded result
and terminal status across the tested legal schedules, independent-golden
pixel checks, bounded retained input, and no stale borrowed-buffer access on
executed sanitizer paths. It is not a performance acceptance rule.

## Partition equivalence

For identical valid bytes, options and semantic limits, compare:

```text
(width, height, source_channels, colorspace, has_alpha,
 concat(produced_RGBA_pixels), terminal_status)
```

Canonical pixels are straight-alpha RGBA8, top-left, row-major. Buffer addresses,
intermediate wait statuses, output-chunk boundaries and call count are not part
of the decoded result. Goldens are independently specified source pixels and
external-oracle results, not solely another invocation of the same prototype.

A legal input schedule preserves byte order, advances by `consumed`, reoffers
an unconsumed suffix unchanged, and eventually supplies true EOF. Buffers may
move. A fair output schedule eventually supplies positive pixel capacity.
Infinite empty calls are not required to terminate. Semantic resource limits
count pixels/opcodes/work, never API calls or elapsed time.

## Concrete resumable contract

The diagnostic entry point is:

```text
qoi_step(state, src, input_bytes, final, dst, capacity_pixels, metrics)
```

`metrics` is diagnostic-only. State and input/output spans are valid, aligned
and disjoint; one caller owns a session at a time. NULL is permitted only for
an empty corresponding span. Output capacity is in complete four-byte pixels,
with overflow validation.

### State and transitions

```text
HEADER -> OPCODE -> MARKER -> END_INPUT -> TERMINAL
```

Persist dimensions/channels/colorspace, 64 previous pixels, the current pixel,
partial-field storage/count, pending run count, cumulative consumed/produced
and work counters, EOF identity and terminal status. Complete fields parse
directly from input; incomplete fields are staged in a fixed buffer. The
header is 14 bytes and the largest opcode is five bytes. Marker validation
retains a count rather than a borrowed slice. Runs retain one pixel and a
count, not a repeated-output buffer.

State must survive per-call scratch and lane-temporal rewinds. The decoder
allocates nothing, performs no I/O, creates no threads, uses no codec callback
dispatch, and introduces no mutable global initialization. This pilot changes
neither canonical IR nor persistent-lane policy.

Each call reports input consumed, complete output pixels produced, status and
the cumulative input decision offset. Partial headers can consume without
producing; pending runs can produce without input. No generic
success-with-zero-progress result is externally returned. Terminal statuses
are sticky and make zero progress on subsequent calls.

| Status | Resumption or terminal meaning |
|---|---|
| `NEED_INPUT` | Available prefix exhausted without a conclusive error. Preserve state and supply continuation or true EOF; not a failure or rollback. |
| `NEED_OUTPUT` | Supply/drain a pixel window and preserve the unconsumed input suffix. Not allocation failure. |
| `DONE` | Declared pixels and exact marker decoded; EOF confirms the strict no-trailing-input policy. |
| `TRUNCATED` | Closed input ends before a required field/opcode/marker completes. Exhausted known EOF must not suspend indefinitely. |
| `MALFORMED` | Available bytes already establish invalid grammar, wrong marker or trailing data. |
| `LIMIT_EXCEEDED` | Configured semantic pixel/work allowance exceeded; terminal. |
| `INVALID_ARGUMENT` | Invalid span/capacity or contradictory EOF boundary; terminal. |

The prototype does not allocate, so it does not test allocator exhaustion. A
production wrapper must separately report unavailable state/work/output
capacity. Reservation admission alone does not make actual OS commitment
fallible: the inspected platform guide documents fatal commit failure. There
is no recoverable-OOM result here.

### Borrowed-buffer lifetime

**Consumed input may be overwritten or released immediately on return.** No
input pointer is retained. Unconsumed bytes must be preserved and reoffered
unchanged, but can be relocated. Release the whole allocation only when all
bytes are consumed or its suffix has been preserved elsewhere.

Output is caller-owned and not retained. A mapping still has to outlive every
other document/API borrowing it. The call-lifetime QOI rule cannot override a
PDF document-lifetime borrow.

### EOF under output backpressure

A final offer latches the absolute end:

```text
EOF = total_consumed_before_call + offered_input_bytes
```

This includes any suffix left unconsumed because output is blocked. Later
calls may offer smaller pieces of that suffix with `final=false`; a repeated
`final=true` must declare the same absolute end. No offer may extend past it.

For the 37-byte all-opcodes fixture, an initial final offer with no output
space can consume its 14-byte header and return `NEED_OUTPUT`; EOF stays at
37, not 14. An empty nonfinal span is not EOF. A complete marker without EOF
returns `NEED_INPUT` while strict trailing validation remains pending. Pixel
count completion alone is not `DONE`.

### Provisional output and transactional publication

**Suspension must not trigger rollback.** Pixels returned before `DONE` are
provisional. A transactional one-shot wrapper can write directly into its final
arena image, retain the mark across progress, publish at `DONE`, and rewind on
terminal failure. It need not copy a successful image again.

A streaming consumer cannot retract pixels already consumed. The shared
rollback-on-every-nonsuccess convention therefore must either exclude
`NEED_INPUT`/`NEED_OUTPUT` or stay scoped to one-shot wrappers. Suspension and
terminal failure are different categories.

The draft's tail-first marker check can label some truncated prefixes malformed.
This pilot intentionally uses EOF-aware `TRUNCATED`; no error-code parity with
#1874 was established. An implementation must review that compatibility change.

### Acquisition remains outside decoding

Preserve short-read progress, stop filling when output is blocked, and keep
OS errors distinct from syntax errors. A successful empty read request is not
EOF. Native read failure is an acquisition error, not malformed input or
synthetic EOF. Decoder completion cannot erase a separate close/publication
failure. The actual Buster OS acquisition adapter was not executed here.

## Executed experiments: retained results

Four fixtures were used: black (23 encoded bytes / 1 pixel), all_ops (37 / 68),
wrap (36 / 6), and pillow (612 / 256). Three use explicit specification-derived
opcodes and Pillow independent decoding; the fourth was independently encoded
by Pillow 12.3.0 from deterministic source RGBA. All four were independently
decoded and compared with constructed source pixels during the original work.

`all_ops` covers every opcode and a 62-pixel run. `wrap` covers unsigned
wraparound, zero-initialized index entries, RGB alpha preservation and RGBA
replacement. Header fields, multi-byte opcodes and marker boundaries all lie
within the exhaustive two-way split positions.

| Category, per configuration | Scenarios |
|---|---:|
| Valid schedules | 4,636 |
| Truncation cases | 1,416 |
| Malformed/limit controls | 24 |
| **Total** | **6,076** |

The valid set contains all 704 nonempty two-way split positions across the
four fixtures, each with three output windows and two EOF schedules (4,224
cases), 400 seeded mixed partitions, and 12 representative whole/one-byte/
zero-output-pause schedules. Every strict prefix, including empty input, is
tested whole and byte-at-a-time. Negative controls cover a wrong marker,
trailing byte, insufficient pixel allowance and insufficient work allowance.

A separate 14-call protocol control covers empty nonfinal input versus EOF,
EOF latched under backpressure, draining a run without input, offers beyond
the latched end, NULL/nonempty arguments, marker-without-EOF, and sticky
completion/failure. It runs per fixture invocation; repetitions are not extra
corpus diversity.

Every successful scenario compares metadata, pixel/work counts, and every
pixel byte. Per-call test input/output allocations are released before the
next call; output guard bytes and iteration bounds are checked. The harness's
allocation/copy/free operations stress lifetime and are excluded from decoder
copy counters.

| Original execution | Retained result |
|---|---|
| Clang 17.0.0, C11, `-O2`, strict warnings | 6,076/6,076 pass; protocol controls pass |
| GCC 14.2.0, C11, `-O2`, strict warnings | 6,076/6,076 pass; protocol controls pass |

Per-call CSVs are retained for three representative schedules per fixture,
not every tested partition. Other schedules are assertion-checked without a
complete trace. These results are finite diagnostic coverage, not a proof of
all possible QOI inputs or schedules.

## Mechanism counts, not performance acceptance

Core state is **360 bytes** on the tested x86-64 ABI, plus **40 bytes** of
instrumentation. The fixed staging capacity is 14 bytes; at return, at most
**13 encoded bytes** remain staged for a partial header and at most **4**
within an opcode. The 256-byte pixel index and four-byte current pixel are
decoded history, not retained compressed input. There is no private output
queue. A consumer retaining the whole image still needs `4 * width * height`
bytes of canonical output.

| Fixture / schedule | Calls | Retained encoded peak | Encoded staging copies | RGBA output writes | History writes | Opcodes |
|---|---:|---:|---:|---:|---:|---:|
| all_ops / whole | 1 | 0 | 0 | 272 B | 272 B | 7 |
| all_ops / byte-pixel, separate EOF | 99 | 13 B | 25 B | 272 B | 272 B | 7 |
| all_ops / whole input, output stalls | 85 | 0 | 0 | 272 B | 272 B | 7 |
| pillow / whole | 1 | 0 | 0 | 1,024 B | 1,024 B | 163 |
| pillow / byte-pixel, separate EOF | 705 | 13 B | 580 B | 1,024 B | 1,024 B | 163 |
| pillow / whole input, output stalls | 320 | 0 | 0 | 1,024 B | 1,024 B | 163 |

Staging counts include headers, not compressed payload alone. **RGBA writes
construct the required decoded result; they are not avoidable copies.** History
writes are separately counted bookkeeping. Tiny input chunks increase calls
and staging traffic while opcode/pixel work stays equal. No wall-time, RSS,
cycle or throughput result was accepted, and no benefit follows from these
counts alone.

## Execution limits and nonstreamable cases

Original execution was in an ephemeral Linux 6.18.44 x86-64 container, not the
user's desktop. No Buster checkout/build, actual #1874 decoder execution,
standard GitHub-runner execution, or benchpress 9700X measurement occurred in
that research. The recorded inability to download a checkout or dispatch a
new diagnostic was a session limitation, not a global infrastructure claim.

No MSVC/Zig/AArch64, self-host, unity/split repository integration, actual OS
read-adapter, real allocation-failure or concurrency validation ran. The
prototype does not enforce every Buster dimension/default/structural option
or public limit-detail field. Its zero limits are literal zero; a production
adapter must preserve Buster's zero-means-default convention. All two-way
splits on four compact inputs are not exhaustive multiway partitions or a
format conformance audit.

QOI here is sequential: arbitrary seeking into encoded opcodes without
restoring pixel/index/run state is unsupported. Restart/decode-forward is a
separate explicit policy with bounded work; arbitrary checkpoints are outside
this pilot.

Do not force this state type on every container and codec. The proposed PDF
lazy xref/object/Prev resolution requires stable random-access bytes or an
explicit admitted spool/recovery strategy. General indexed MP4 may require
seeking or spooling when needed metadata follows media bytes. Sequential
sample production does not establish forward-only acquisition. Unsupported
source capabilities must fail explicitly rather than wait forever for input.

PNG has independent transport, chunk, zlib and scanline boundaries and needs
checksum/bit/Huffman/LZ/filter state not exercised by QOI. A potential 32 KiB
inflate history is not an avoidable encoded gather. Audio/video codec history,
priming and reordered output remain format-specific.

## Smallest useful implementation packet

Coordinate one private QOI state/step seam with #1834/#1874, while #1840 owns
shared distinctions between suspension and terminal statuses. Lift the existing
opcode state into caller-owned persistent storage; retain direct complete-field
reads, fixed partial-field storage, strict EOF and explicit prefix ownership.
Drive the one-shot wrapper through that same kernel, without a second decoder
or a successful-image copy. Review truncation-category compatibility explicitly.

Add partition, lifetime, backpressure, EOF and independent-golden tests to the
image test owner and document provisional session output versus transactional
wrapper publication. No other codecs, generalized inflate rewrite, threads,
allocator policy, CI/admission changes or performance claim belong in this
packet. A named consumer remains necessary to justify adopting a new public
streaming interface rather than merely retaining this private feasibility result.

Actual integrated image tests and the required standard GitHub-runner matrix
are gates for a future implementation, **not prerequisites for accepting this
historical audit as documentation**. Any subsequent performance claim needs a
named workload and uninstrumented comparison on the dedicated benchpress 9700X.
