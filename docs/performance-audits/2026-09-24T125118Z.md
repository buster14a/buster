## Three hypotheses and work account

1. **Repeated local-name scans:** not the normal entity-bound path.
   `c_ir_find_local_by_entity` already uses `local_entity_slots`; name search is
   a guarded fallback when the entity ID is invalid. A stale scan comment is
   not evidence that every ordinary identifier still pays a backwards scan.
2. **All-type clearing per promoted-member query:** falsified by the allocator.
   `arena_allocate` is an uninitialized bump allocation, not the zeroed variant.
   The request scales with all canonical types G, but only queued work rows are
   initialized. Requested bytes are not cleared bytes, touched bytes or RSS.
3. **Growing-frontier duplicate checks:** confirmed on real compilation.
   `c_ir_promoted_member_queued` scans the accumulated queue before each unseen
   anonymous aggregate is appended. A root with K distinct anonymous children
   first scans queues of length 1, 2, ..., K. It therefore performs
   K(K+1)/2 type-ID comparisons, despite only 2K field visits and K+1 initialized
   work rows. Q source query sites reach Q calls in this family, giving
   Q*K(K+1)/2 comparisons. This is work in the complete compiler invocation,
   not a separately timed helper.

The production route is an ordinary `ide cc` object compilation of a function
containing `sizeof(value.f0000)`: lowering's type-only member query uses
`c_ir_static_postfix_type`, `c_ir_promoted_member_type` and the path helper.
The counter is inside the actual enqueue predicate; no replacement model is
used to establish reachability.

Source loading/preprocessing (`c_preprocess`) produces the token stream;
`c_parse_ast` partitions declaration/body ranges and `c_analyze_semantics`
publishes types/entities/scopes; lowering consumes these and emits canonical
IR. The source already has token shape/keyword and delimiter indexes. Rewalking
a token range at a semantic boundary is not by itself a defect. Here the
independent denominators are source bytes B, preprocessed tokens T, unrelated
record declarations N, actual canonical types G, anonymous breadth K, query
sites/calls Q and output bytes. Lexical function/block depth stays fixed; it is
not used as a proxy for K. No whole-parser complexity claim follows.

## Smallest plausible boundary, including costs

Do not replace duplicate suppression with no check: breadth-first ordering,
equal-depth ambiguity, repeated types/cycles, root-field/union/offset metadata,
overflow rejection and scratch cleanup must remain unchanged. The private
membership representation is the only proposed implementation boundary; no
caller-visible API, canonical type, persistent cache or IR adaptation is needed.

The baseline has no separate membership index, one G-sized uninitialized
frontier request, O(K) work-row writes, and O(K^2) membership comparisons for
this family. A per-query dense visited table can replace the comparisons with
O(G) clearing and is therefore not a free improvement. A bounded sparse index
for larger frontiers instead adds metadata, initialization, probe branches,
growth/rehash copying and arena high-water; preserving the small linear path
still adds a dispatch decision. Those costs must be charged, not hidden behind
an isolated lookup result. No alternative implementation was built or measured.

The first necessary follow-up in #1103 is a representative-input frontier/call
census. If the ordinary population is a handful of types, stop with no change.
Only a material population justifies a narrowly scoped C implementation and
regressions, followed by uninstrumented unchanged-input whole-compilation A/A
and A/B through the currently authorized 9700X path. Do not improvise SSH,
benchmark on the user's desktop, change execution policy, or make this a
retirement prerequisite.
