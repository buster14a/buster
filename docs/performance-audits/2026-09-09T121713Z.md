## Coverage and constraint

On base `6a400ad5cf36022154cbb7d00f899d8f9479260a`, unsigned 32-bit
switch cases above INT32_MAX select MIR but fail exact x86 emission. A signed
64-bit representation of the positive constant does not fit the bridge's signed
imm32 operand. Normalize the low 32-bit pattern only when both the register
width and immediate width are 32. Preserve narrower-immediate and 64-bit
register sign-extension constraints. The established metadata bridge still
selects and validates the encoding; no new emitter or fallback is introduced.

The permanent `tests/differential/switch_unsigned.c` fixture checks five 32-bit
cases and seven 64-bit cases. A separately Clang-built caller tests defaults,
the 32-bit sign boundary, UINT32_MAX, UINT64_MAX, and equal low bits with distinct
upper bits. The machine tests require the switch rows to survive selection,
validate and encode them, check zero fallback in all four allocators with both
frontend forms on x86-64/AArch64, and execute native functions on supported
unsanitized Unix hosts. The mixed-compiler case joins the regular differential
corpus. Inspected x86 disassembly preserves the 32-bit immediate bytes and uses
full-width MOVABS for 64-bit cases, including sign-extended and zero-extended
forms of the same low bits.

The full compiler's fallbacks fall from six to three. All three encoding
refusals disappear: `object_mach_pageoff12_shift`, `jit_aarch64_pageoff12_shift`,
and `link_aarch64_pageoff12_shift`. The remaining opcode refusals are
`os_flush_instruction_cache`, `cpuid`, and `xgetbv`. Issue #36 remains open:
these and supported-target ABI/signature gaps must be resolved before production
fallback and the direct backend can be removed.
