## Published representation and work

`ir_function_publish_cfg` produces one immutable per-function CFG with
contiguous instruction spans, source-grouped successor edges, destination-grouped
predecessor indices, dense parameters and edge argument rows. Terminators own
topology; repeated targets collapse once and parameter-free edges remain.
Incoming columns transpose in bounded linear work. Shared operand/target/immediate
pools reuse contiguous storage or copy fragmented/overlapping slices once.

One explicit old-to-new instruction map drives an in-place permutation. Value
definitions, dense source rows and sparse extras follow it. Block, value, local,
label and symbol identities remain stable. The instruction row stays 64 bytes.
All canonical emitters/selectors, validation and tracing consume published
spans/arrays. The selectors' private canonical row/edge reconstruction is gone;
target-specific machine legalization still owns its resulting graph.

Every instruction `next` and every builder parameter/predecessor first/last
pointer is cleared at publication. Explicit invalidation reconstructs new
builder nodes before mutation; retained pointers into the old builder are stale.
Unchanged preparation reuses publication. Published shape and semantic checks
remain separate from input/pass certificates, as documented in
[the publication contract](../canonical-cfg-publication.md).

The old arena allocations become unreachable and survive until translation-unit
release. `allocated_bytes` reports only new publication storage, excluding those
old allocations, reused pools, scratch and arena padding. Existing `CFG_*`
diagnostic counters report construction work; they are not throughput or total
live-memory measurements. No peak-memory saving is inferred from smaller dense
rows, and no throughput result is inferred from fewer linked-list visits.
