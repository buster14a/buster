## Scope and decision

Base: `ebfdd11705bc470564e726857e498f1c82aa746c`. Work began on
`9834a4253c61934a8a253641a84741a25d3717e3`, then was rebased and revalidated after
canonical promotion and parallel-copy PR #212 landed. The latter's critical-edge
splitting, capture-before-write semantics, and reusable copy tile are preserved.
This addresses the whole-edge-table search portion of #122, not every throughput
item in that issue or the Zen 5 acceptance gate in #128. It does not duplicate
PR #135's owner-mask experiment.

FAST is already a forward scan over compact machine IR, owner arrays and register
masks. An interval-tree rewrite or bucketed expiration is not justified here.
The confirmed scaling defect is four independent searches of all raw edges for
one `(source, destination)` pair: donor selection, predecessor intersection,
retroactive conformance, and terminator handling. With E edges and Q queries this
costs O(E*Q), even when every block has only one predecessor.

`machine_fast_index_edges` groups raw edge IDs by destination in temporary CSR
storage. A dense source-to-first-edge map is filled and sparsely reset for each
destination. It publishes u32 IDs parallel to the existing predecessor list and
four terminator operand slots per block. Every hot query becomes one indexed load.
No sort, hash table, pointer node, callback or target-specific SIMD is introduced.
Stable raw-edge order preserves **first-match duplicate semantics**. Existing
predecessor order, missing-pair null behavior, allocation decisions, copy order,
and frame layout stay unchanged. Out-of-range raw endpoints invalidate the prepass.

Construction is O(B+E+P), where P is the number of predecessor references; query
cost is O(1). The proof includes arbitrary switch fanout: each raw edge is visited
a fixed number of times and each predecessor inspects exactly four inline slots.
It does not depend on bounded out-degree or on edges being sorted by source.

## Allocator phase audit

I denotes machine instructions, V virtual registers, C edge-copy operands,
R the target's bounded register count, M emitted edits, and S explicit stack slots.
These are code-structure bounds, not invented per-phase timing measurements.

| Phase | Existing organization / finding | Change |
|---|---|---|
| Intervals and liveness | FAST uses textual last-use, definition-block, escape and next-call arrays. Additional interval start/end facts are requested only by QUALITY. Prepass walks instructions/operands and edge copies, rather than a liveness fixpoint. | Preserve; add the edge index once, reused by both QUALITY scans. |
| Active set | Fixed-size owner/age arrays with held/dirty masks; no allocated active-set nodes or ordered interval tree. | Preserve; no expiration buckets needed for this design. |
| Spill selection | Masked free/dead/LRU choice, bounded by R; rematerialization and call-crossing preferences already exist. | Preserve policy and tie-breaking. |
| Register classes and constraints | Class/allocatable/reserved/pinned masks and compact operand-role words; explicit fixed-register handling. | Preserve; do not force SIMD into bounded sparse walks. |
| CFG queries / edge copies | O(E*Q) raw-edge searches surround the existing parallel-copy resolver. The resolver and its register-state work remain separate costs. | Replace the four searches; do not change the resolver. |
| Stack-slot assignment | Linear edit marking and V/B scans, per-defining-block pool for nonescaping scalar values; dedicated escaping/vector homes and S explicit slots. | Preserve O(M+V+B+S) layout organization. |
| Edit finalization | Already-ordered main edits; stable sort of retroactive edits and linear merge. | Unchanged; O(M log M) remains possible. |

This is **not a proof that the entire allocator or compiler is linear**. QUALITY
range splitting, copy remapping, edit sorting and other compiler passes were not
redesigned. No fine-grained time is assigned to inlined class filtering or frame
layout: the available profile cannot resolve those independently.

Intel Xeon Platinum 8370C VM, five visible vCPUs, 4 GiB memory limit, Linux x86_64.
Clang 17, Release split build, `-O2 -DNDEBUG`, `-march=native`, debug information

The standalone probe uses the same Clang `-O2`, without `-march=native`.

measurement. Hardware cycles/instructions/branches/misses are **unavailable**:
`perf` is absent and a hardware PMU probe returned ENOENT. No hardware-counter or
cache-locality improvement is claimed from wall time alone.

### Real allocator scaling probe

`tools/fast_ra_scaling.c` calls the production prepass and prepassed placement.
One instruction per block, reversed raw edge order, chain and indirect-switch
fanout, no vregs. This deliberately isolates CFG overhead; it does not represent
spill quality. One warmup plus 11 samples per size/variant, medians below.
All placements are valid, with zero edits, spills, reloads and frame bytes.

| Shape | Blocks = machine instructions | Before total (us) | After total (us) | Speedup | After ns/instruction |
|---|---:|---:|---:|---:|---:|
| chain | 256 | 81.984 | 22.499 | 3.64x | 87.89 |
| chain | 1,024 | 1002.811 | 89.771 | 11.17x | 87.67 |
| chain | 4,096 | 15179.737 | 377.929 | 40.17x | 92.27 |
| chain | 16,384 | 225540.068 | 1520.664 | 148.32x | 92.81 |
| fanout | 256 | 39.415 | 20.001 | 1.97x | 78.13 |
| fanout | 1,024 | 406.428 | 80.535 | 5.05x | 78.65 |
| fanout | 4,096 | 6283.863 | 328.359 | 19.14x | 80.17 |
| fanout | 16,384 | 107693.174 | 1385.809 | 77.71x | 84.58 |

For the 16,384-block chain, prepass grows from 509.847 to 737.568 us while
placement falls from 225,043.240 to 776.233 us. The index intentionally moves work
into construction to remove repeated searches. Fourfold block growth produces
roughly fourfold indexed time over the larger sizes, versus near-quadratic
baseline growth.

**Small-function tradeoff:** separate 101-sample warm-cache empty-value probes
measured 393 -> 452 ns at 2 blocks, 927 -> 1,136 ns at 8, 1,633 -> 1,921 ns at 16,
and 8,207 -> 6,125 ns at 64. There is a small-graph setup penalty; this is not a
universal per-function speedup. A bounded small-edge fallback is a possible
follow-up, but was not added without a representative distribution and Zen 5
crossover measurements.

### Memory and allocation tradeoff

For nonempty raw-edge tables the retained increment is `4*P + 16*B` bytes, plus
alignment. Temporary CSR/map storage is `4*E + 8*B + 4` bytes, plus alignment,
and is rewound before returning. There are two retained and three temporary bulk
arena allocations, not an allocation per edge. Empty edge tables allocate none
of these arrays. Tests overwrite reclaimed scratch before reading published IDs.

At 16,384 chain blocks, retained prepass bytes are 344,084 -> 671,760; complete
prepass+placement arena bytes are 3,096,616 -> 3,424,288 (+10.58%). These position
measurements exclude temporary peak usage; the scratch formula above is separate.
Do not mistake doubled prepass bytes for doubled total compiler memory.

unsigned divide and shifts, loop-carried cyclic assignments, pointer joins,
