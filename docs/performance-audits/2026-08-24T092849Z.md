Lead 1 of `2026-08-24T085746Z`, taken on the merged tree. That entry stopped
`u8 slots[2]` from reaching the VLA layout at all, because both its operands
were constants; this one removes the same product for the bounds that are *not*
constant, where it costs generated code instead of compile time.

**Budgets before** (clang Release `ide`, unity stage-1 compile, `main` at
`ba03ccd4`): 9.641.769.610 instructions, 1.762.189.826 branches, 21,58 M branch
misses, 3.411.343.687 L1d loads, 89,27 M L1d load misses. The instruction
counter here is bimodal — every run lands either at 9.641.769.6xx or at
9.641.796.9xx, about 27.300 apart — and both modes appear under both binaries of
the pair below, so the mode is a property of the run and not of the compiler.
Read the A/B within a mode, never across one.

**The finding.** `c_ir_lower_vla_layout_step` closes by walking the dimensions
from innermost outward, multiplying each count into the suffix below it, and
`suffix_sizes[0]` — the whole object's size — falls out last. A parameter never
has one. `CIrVlaLayout::runtime_size` is `suffix_sizes[0]`, and it has exactly
two readers: the `ALLOCATE` operand in `c_ir_lower_automatic_declaration_step`,
which is the declaration path and not this one, and
`c_ir_lower_expression_core_step`'s `sizeof` arm, which refuses suffix 0 for an
`is_vla_parameter` local on purpose, because `sizeof a` on an array parameter is
the pointer's. `CIntegerIrLocal::runtime_size` is written at both of its
assignment sites and read at none. So for `void f(long n, unsigned char a[n])`
the `n * 1` multiply was emitted into the entry block and discarded, exactly as
`slots[2]`'s was — it simply cannot be folded.

The walk now stops one dimension short when `state->parameter` is set.
`suffix_sizes[0]` keeps the `0xff` fill, which is what an absent bound (`u8 a[]`)
already left there and what the step's closing
`c_ir_lower_frame_finish(builder, state->parameter || ...)` already accepts. For
a one-dimensional parameter index 0 is the loop's only iteration, so the whole
product disappears; every inner suffix is still built, because `sizeof(a[0])` on
`u8 a[n][m]` reads `suffix_sizes[1]`.

The dimension *counts* are untouched, including `dimension_counts[0]`, which is
now unread. That is deliberate: the bound expression of an array parameter is
evaluated at entry — a counter inside a function called from the bound reads 1
under clang — so removing its evaluation would remove a side effect, not a dead
value.

**The population.** Zero. The self-host unit has 17 array-syntax parameters; 15
have constant bounds and `2026-08-24T085746Z` already skips them, and the
remaining 2 are `main`'s `argv[]`/`envp[]`, whose absent bound leaves
`dimension_counts[0]` invalid so the guarded multiply never fired. The proof is
direct rather than counted: the two compilers, compiling the same unity source,
produce **byte-identical** 35.068.280-byte executables. This change therefore
cannot move the self-host numbers at all, and every number below that does move
comes from the isolated file.

**The generated code, which is the point of this one.** Per site the default
fast allocator loses 4 instructions — a spill of `n`, two register moves and the
`IMUL` — and 16 bytes of frame (`sub $0x20` becomes `sub $0x10`); the canonical
allocator (`-fregister-allocator=none`) loses 4 as well, two reloads, the `IMUL`
and its store. Object bytes on the 1.000-function file: 576.176 -> 558.176 under
the fast allocator, **18 bytes per site**, and 789.264 -> 773.264 under
canonical, 16 per site. The pointer-spelled control is byte-identical before and
after.

A site still costs 8 bytes more than the pointer spelling: `mov %rdi,%rax` for
the count the bound has to evaluate, and `mov $0x1,%ecx` for the element size
that `sizeof a[0]` would read. The first is the side effect above and has to
stay; the second is a dead constant only when nothing asks for it.

**Self-host, for the record.** Eleven order-alternated pinned pairs of the

**Two shapes the differential flushed out, neither this change's doing — both
reproduce on `ba03ccd4`.**

- **A call inside a parameter bound aborts the compiler.**
  `unsigned char first(long n, unsigned char a[bound(n)])` trips
  `BUSTER_CHECK(callee_start >= builder->body_token_start && ...)` in
  `c_ir_prepare_calls_discover`: the bound's tokens sit outside the function
  body's token range, so `prepared_call_indices` is indexed out of bounds.
  clang evaluates such a bound exactly once at entry, so the answer is to lower
  it or to diagnose it — per `AGENTS.md`, `BUSTER_CHECK` is for violated
  internal invariants, never for ordinary input.
- **A bound that reads a global is refused.** `unsigned char a[n + step]` with a
  file-scope `step` reports `could not lower variable-length array parameter
  bounds`. That one is a structured diagnostic rather than a crash, so it is a
  coverage gap and not a bug.
