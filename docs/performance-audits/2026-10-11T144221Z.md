## Workload

Every arm compiles the base revision's unity self-host source, from a base
worktree with that tree's generated headers:

```sh
ide cc -Isrc -I<base generated> -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -fsyntax-only \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

There are four arms:
- A: base, default flags;
- B: base with `-fc-ast-pilot`;
- C: candidate with `-fc-ast-pilot`;
- D: candidate, default flags.

`-c` arms swap `-fsyntax-only` for `-c -o <object>`. Callgrind ran with
`--cache-sim=no --branch-sim=no`. Function figures are inclusive.

## Change

Under `-fc-ast-pilot`, the statement plan's declaration hint
(`c_parse_plan_declarators`, #3499) also carries the storage-class words that
its `DECL_SPECIFIERS` items spell. They are folded by the split's own
`c_token_well_known_bit` test. The hinted `c_parse_local_declarations_split`
skips its scan of the whole declaration, initializers included, for them.

The hint's auto check now reads every node of the specifiers and of the first
declarator up to its initializer, which is where
`c_parse_auto_declaration_info` reads. Before, an `__auto_type` parameter in a
block declaration changed the diagnostic under the pilot
([#3550](https://github.com/buster14a/buster/issues/3550)).

The corpus gate gains a field-by-field model differential
(`c_ast_corpus_models_differ`). `c_ast_test_declaration_hints` holds the
hints' specifier facts to the walker in every layout.

## Limits

- Callgrind counts instructions, not time, on `-march=x86-64-v3` builds whose
  AVX-512 kernels are compiled out. No wall time was taken, because an 8 M
  instruction change is below this host's paired-run noise.
- One input, one host, a single process.
- The 9700X pull-request comparison runs default flags only and cannot time
  the hook, so Zen 5 validation stays **incomplete** (#2761). No benchmark
  request was added.
