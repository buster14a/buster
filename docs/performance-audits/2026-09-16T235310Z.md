## Repair and consumer audit

`target_data_layout` now reports 24 bytes, alignment eight, for non-pointer
x86-64 lists. `TARGET_X86_64_SYSV_VA_LIST_SIZE` names the public extent; the
176-byte register-save area remains separate. Windows/UEFI x86-64 and
Darwin/Windows AArch64 pointer lists remain eight bytes. Linux/Android/UEFI
AAPCS64 remains 32 bytes. Existing UEFI classification and Android long-double format are not
changed by this repair.

The C builtin layout query and canonical type lowering already consume the
target size. Their local/array/record sizes and existing parameter adjustment
are tested together. Direct canonical emission already derives its list word
count from the IR extent: its zero-fill loop starts at byte 24, copy loops use
that count, and `VA_END` is a no-op. No direct-backend change is necessary.

MIR did require coordinated repairs: remove `VA_START`'s fourth-word store,
copy exactly 24 bytes, and stop `VA_END` from writing an ended flag at byte 24.
The source operand is still evaluated and validated. Selection refuses a
synthetic 32-byte SysV result instead of overrunning a 24-byte frame. Existing
frame allocation follows the resolved type size; no new pass or private state
is introduced. Production dispatch and fallback policy are unchanged.

## Registered regressions

Target controls cover 15 ABI rows; parser/IR assertions cover 12 targets, both
C forms, exact size/alignment, array extent, enclosing-record offsets, and
existing formal-parameter adjustment. Machine tests inspect selected frame
store bounds, copy payloads, non-destructive ending, all allocator modes, and
negative stale-extent selection.

`basic_c_sysv_va_list.c` uses public `stdarg.h`, literal 24-byte/8-alignment
expectations, and guards directly following each list or pair of lists. Member,
index and dereference destinations cover construction/copy/end; `va_end`'s
indexed operand has an observable increment. Mixed integer/double arguments
exhaust GP and FP registers, including named-stack arguments and copies both
before and after exhaustion. The public array parameter is consumed through
the independently compiled function.

The registered `sysv-va-list` differential pair exchanges producers, consumers,
copiers and externally constructed native-owned lists in both directions. A
native source occupies the last 24 bytes before an inaccessible page, detecting
oversized **reads** as well as destination overwrites. Missing target SDK headers
permit cross-object construction only; using such a host binary as a runtime
oracle returns failure rather than skipping the guarded-page check.

The ordinary driver suite checks four allocators, two frontend forms and both
PIC settings across Linux/macOS/Android/iOS x86-64 objects (64 configurations),
executing the matching desktop ABI with the configured native compiler. The
three new tracked C inputs are added to the frozen support manifest with their
actual byte counts and SHA-256 hashes; no previous row is changed.

## Reproduction

On a configured tree, use the normal wrapper with an available trusted TCC;
this session invoked the Clang-built driver directly instead:

```sh
./build.sh build --config Release -t test_all
./build.sh test_self_host --config Release
./build.sh test_mode_matrix --config Release
./build.sh test_differential --ide build/Release/ide --cc clang \
  --source tests/differential/sysv_va_list.c \
  --host tests/differential/sysv_va_list_host.c \
  --strict-mir --sanitize-oracle --minimize 0 --jobs 1 --out build/va-clang
./build.sh test_differential --ide build/Release/ide --cc gcc \
  --source tests/differential/sysv_va_list.c \
  --host tests/differential/sysv_va_list_host.c \
  --strict-mir --minimize 0 --jobs 1 --out build/va-gcc
```
