## Workload

Every arm compiles the same input, the base revision's unity self-host source,
from the base checkout:

```sh
ide cc -Isrc -Ibuild/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -c \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

The arms are counted with Callgrind (`--cache-sim=no --branch-sim=no`):
- A: base, default flags;
- B: base with `-fc-ast-pilot`;

- D: candidate, default flags.

Each candidate's objects were also built at `-g`, outside Callgrind.

gate ships. A per-token column is too expensive for these predicates, because
the build pays for every body token, on the default path too. The predicate
leads in #3924 are closed as negative.

### The pilot's `?` gate: ships

The gate needed four iterations. All are measured above or described here:
- **Candidate 2** (`a561611d`) put the `?` test inside the inline
  `c_ir_root_conditional`, before the tree's records. C fell by 37.1 M, but
  D rose by 13.1 M.
- **Variants 3 and 4** were not committed and their patches were not
  retained. Variant 3 tested `?` once, and variant 4 also made the prefix
  build `noinline`. D stayed at +14.5 M and +13.5 M. All of it was
  `c_ir_lower_expression_step`'s self Ir, where `c_ir_root_conditional` is
  inlined: any change to that inline function moved its code.
- **Variant 5** (also not committed) left `c_ir_root_conditional` as on main.
  It replaced only the records' binary search over the unit's `?` tokens with
  the count. D was +0.29 M, but C fell by only 7.6 M. The records function's
  own frame (about 16 M of prologue and epilogue), its `in_body` test (7 M)
  and its statistics (7 M) stayed on every call. Its binary search was about
  26 M.
- **The shipped candidate** (`0ee5ec48`) leaves `c_ir_root_conditional` as on
  main. `c_ir_tree_root_conditional` becomes a small gate. It refuses a
  non-empty body range with no `?` and counts it as the records' negative.
  For the rest it calls the unchanged records path, renamed
  `c_ir_tree_root_conditional_records`. Both the records path and the prefix
  build are kept out of line (`C_IR_NOINLINE`).
