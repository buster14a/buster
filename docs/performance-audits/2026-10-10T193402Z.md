## Census that chose the design

A throwaway census build (tests-on Release, not committed) printed one line
for each checked cast query the typer declined although it had accepted the
cast without constraint checks. Each line holds the operand's kind and the
deepest node that is declined, or accepted but not safe, on the path below it.
On the base, under `-fc-ast-pilot`, it counted 886 such queries:

| Group | Queries | Shape |
| --- | ---: | --- |
| declined operand | 353 | `(char8*)__func__`, from `BUSTER_FUNCTION`'s `S8` |
| declined operand | 224 | members of qualified aggregates, string runs, builtin calls and others, none above 55 |
| unsafe operand | 284 | `(void)(__builtin_expect(…) ? ((void)(is_debugger_present() ? (__builtin_debugtrap(), 0) : 0), os_fail_va(…)) : 0)`, from `os.h`'s failure macros |
| unsafe operand | 12 | others |
| unclean conversion | 13 | an identifier (12) and a call (1) |

Read against the machine (`c_parse.c`):
- `__func__`, `__FUNCTION__` and `__PRETTY_FUNCTION__` declare no entity.
  A single-token task goes to `c_parse_expression_leaf_without_cast`, then to
  `c_parse_direct_expression_base`. With no entity there, the answer is
  nothing. The checked task's only rule, "typedef name is not an expression",
  needs an entity.
- An unbound `__builtin_expect(…)` matches no builtin rule in the leaf. Its
  entity lookup finds nothing, and `c_parse_direct_expression_base` answers
  nothing for an unresolved callee.
- The checked cast (`C_TYPE_PARSE_STAGE_FINISH`) tests the conversion only
  when the operand has a type. The conditional's scalar-condition check
  (task state 3) does the same.
- A void builtin with no arguments (`__builtin_debugtrap()`) is the published
  `void` row. The leaf reads it by spelling, before any entity.

So both groups are cases where the checked rule provably cannot fire. The
change appends nothing: no new row, interned or otherwise.

## What the typer still declines here

The same census on the candidate:
- declined operand: 224;
- unsafe operand: 12;
- unclean conversion: 13.

The largest rows:
- a member access through `->` or `.` that the typer declines, about 120
  together. The census does not record which member rule refused them: a
  qualified aggregate, whose member row the machine appends; a base kind the
  member rule does not take; or an unbound base.
- string-literal runs: 28;
- calls with a builtin or unbound callee: 24;
- `&` over a declined member: 23.

These are declined in the operand itself, not by a checked rule. Widening
them is a matter for the operand rules and the row-appending work
(#3102's open items), not for the constraint rules this change touches.

## Reading

- The change answers 637 more checked casts on the self-host, without a new
  row and without changing the default path's work or objects.
- On this input the gain is small: −0.076% of the pilot's instructions. The
  declined queries were cheap machine runs, about 14 K Ir each.
- Hosted wall time was not measured. The earlier audits found this host's
  noise larger than effects of this size. Zen 5 validation (#2761) stays
  incomplete, and the hook stays opt-in.
