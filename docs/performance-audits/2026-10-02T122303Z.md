## Result and evidence class

On the tested inputs, **Buster FAST wins time to a native object; MSVC /O2 wins generated-program speed**. Code size is mixed. MSVC is the stronger choice for production Windows/C++ integration and an optimizing native toolchain. Buster offers a C-only, inspectable compiler pipeline with broader native OS and direct non-native backend scope. Those latter judgments describe capabilities and fit, not measured reliability or performance scores.

This audit examines 48 dimensions. It deliberately leaves unmeasured cells unknown. A single synthetic hosted-VM experiment cannot establish a universal compiler winner, a conformance percentage, a defect rate, or a memory advantage.

Research owner: [#2277](https://github.com/buster14a/buster/issues/2277). New bounded follow-ups: [#2298](https://github.com/buster14a/buster/issues/2298) for register-only Win64 leaf homes/frames and [#2299](https://github.com/buster14a/buster/issues/2299) for a counted unsigned-reduction vectorization census. Existing owners are reused below. This is historical evidence at the pinned revision; live research state belongs on those issues.

### Measured generated-program runtime

Each observation times 32,768 calls over 1,024 unsigned elements inside the executable using QueryPerformanceCounter. Five observations follow a discarded warmup; linking and process launch are excluded.

| Kernel | Buster FAST ms | Buster QUALITY ms | MSVC /Od ms | MSVC /O2 ms | /O2 speedup over FAST | Runtime reduction |
|---|---:|---:|---:|---:|---:|---:|
| sum_scale | 94.7765 | 84.4057 | 43.0231 | 20.8560 | 4.54x | 77.99% |
| divide7 | 84.4451 | 74.3848 | 63.1234 | 9.0976 | 9.28x | 89.23% |
| dot | 86.1006 | 95.5875 | 54.2600 | 3.0085 | 28.62x | 96.51% |
| calls | 158.2596 | 158.3203 | 73.8314 | 4.2106 | 37.59x | 97.34% |

| Kernel | FAST min–max ms | QUALITY min–max ms | /Od min–max ms | /O2 min–max ms |
|---|---:|---:|---:|---:|
| sum_scale | 94.6897–94.8757 | 84.1266–87.4040 | 42.9773–46.5687 | 20.8093–21.0345 |
| divide7 | 84.3976–85.0615 | 73.6872–75.2700 | 62.8267–63.3133 | 9.0277–9.1948 |
| dot | 85.9409–88.0622 | 95.3270–101.1724 | 54.1281–54.4709 | 2.8869–3.1454 |
| calls | 158.0013–158.9800 | 158.0265–163.9881 | 73.7533–74.3692 | 4.2010–4.2231 |

Even /Od beats Buster FAST on all four runtime kernels, by 1.34x–2.20x. Therefore the gap is not merely the absence of an aggressive vectorizer: baseline instruction selection, register/home traffic and call handling deserve attention.

QUALITY improves sum by 10.94% and division by 11.91% versus FAST, but slows dot by 11.02% and changes calls by only 0.04%. It is not a universal remedy. It also takes more compiler time on these fixtures.

Disassembly identifies several mechanisms together: Buster emits scalar loops, extensive stack-home stores/loads, index multiplication plus address adds, a hardware divide for /7, and an actual helper call. MSVC emits scaled addressing, multiply/shift constant division, inlining, unrolling and packed integer reductions. The effects have not been separated by ablation, so no individual pass can claim the whole speedup.

**ISA qualification:** MSVC's default x64 deployment target can include faster paths guarded by runtime ISA checks. In these objects, dot/calls reference __isa_available, branch on its value and use SSE4.1 pmulld. Buster -march=baseline executes its baseline path. Thus the numbers compare actual default deployable outputs with a compatible baseline, but **not identical executed instruction sets**. [Microsoft documents this guarded vectorization behavior](https://learn.microsoft.com/en-us/cpp/parallel/auto-parallelization-and-auto-vectorization?view=msvc-170). A matched effective-ISA/scalar-only experiment is still needed to attribute benefits.

## Ranked improvements, ownership and next experiments

1. **Protect compatibility before chasing runtime.** Extend the already completed MSVC reference-adapter work (#975, merged #996) with independent cl/Buster callers and callees for aggregate returns, enum widths, variadics, TLS, packing and real headers. Reproduce #1491/#1492/#1323 at a current pinned source before calling their historical measurements current defects. Respect active aligned-layout PR #2226 and COFF-bound PR #2273; do not open competing repairs. Four successful unsigned kernels are a useful check but cannot retire those ABI questions.

2. **Start with bounded baseline codegen.** #2298 traces/censuses unread leaf homes and unnecessary frames; #1928 owns block-parameter home coalescing; #1929 owns scaled-address folding; #48 owns tiny inlining; #1943 owns constant division. MSVC's 4-byte leaf versus Buster's 36-byte leaf is an exact size witness. The runtime gaps of 4.54x–37.59x combine several changes and feature paths, so there is no honest promised speedup for any individual repair. Preserve required stack probing, address-taken storage, ABI, unwind and debugger obligations; do not simply delete all stores or frames.

3. **Qualify loop optimization separately.** #2299 first counts eligible unsigned sum/dot reductions, then isolates scalar cleanup, constant division, inlining and vectorization.
