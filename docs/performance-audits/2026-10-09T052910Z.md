## Large embedded database correction

The candidate compile database is 1,057,099 bytes, greater than the generic
1 MiB manifest string bound. The worker's V2 manifest matcher used that generic
reader for the embedded database, so it rejected the otherwise valid manifest
before comparing the selected rows. The correction compares the declared
length to the already loaded database length, bounds and compares the exact
byte slice, and consumes its terminator. It leaves the generic reader limit
and PLAN_V2 serialization unchanged.

The final captured native self-test on the feature tree reports 140 checks, 53
expected rejections, and zero failures, including a padded database large
enough to exercise the actual worker and aggregate path. Earlier CDB parser
iterations, both source-size captures, and the final output are retained
separately. The final feature-tree size capture reports production +0 and
build +9,165 bytes against `14736f0`, within the 32 KiB limit. Its exact source,
driver, log hashes and the earlier distinct size attempt are listed in the
