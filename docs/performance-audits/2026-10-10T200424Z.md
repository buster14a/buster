## Workload

Every arm compiles the same input, the base revision's unity self-host source,
from the base checkout:

```sh
ide cc -Isrc -Ibuild/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -fsyntax-only \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

The four arms:
- A: base, default flags;
- B: base with `-fc-ast-pilot`;
- C: candidate with `-fc-ast-pilot`;
- D: candidate, default flags.

D − A is the default path, also measured on `-c` (`-g0`, the same input with
`-c -o`). C − B is the change's effect on the pilot. Callgrind ran with
`--cache-sim=no --branch-sim=no`.

## Census (base, before any candidate)

A throwaway build of the base (binary `7764e7e87f0a96cd`, not committed)
routed every top-level expression-type query under `-fc-ast-pilot` whose range
is only string-literal tokens, perhaps inside balanced parentheses, through
one no-inline wrapper per shape, and Callgrind charged each wrapper
inclusively (pilot compile 9,581,171,268 Ir):

| Shape | Queries | Inclusive Ir |
| --- | ---: | ---: |
| one token in parentheses | 10,230 | 30,482,492 |
| one token | 7,487 | 11,955,083 |
| several tokens in parentheses | 28 | 626,109 |
| several tokens | 20 | 104,706 |
| **total** | **17,765** | **43,168,390** |

- 16,911 of these queries ran the machine, at 31,677,750 Ir in
  `c_type_parse_machine_run` plus 1,455,927 in the checkpoint `memcpy` and
  760,995 in `c_type_parse_root_finish`. The rest were memo hits.
- 72% of the cost came from `c_parse_validate_const_assignments`. The
  parenthesized shape is `S8()`'s length: `BUSTER_ARRAY_LENGTH(x)` is
  `sizeof(x) / sizeof((x)[0])`, and the subscript check asks for the type of
  the base `(("text"))`.
- The string leaf itself (`c_parse_expression_leaf_without_cast` →
  `c_parse_string_literal_expression_type` → the decode in
  `c_ir_count_string_literal_range_for_target`) was 26.0 M of the 43.2 M. A
  replay must still run it, because its row is the answer. So the machine
  overhead a replay can remove is about 330 Ir per query, far below the 2,500
  Ir each query costs in all.
- The total passed the census budget (at least 1 M Ir), so a candidate was
  built.

The earlier estimate in [ast.md](../agents/frontend/ast.md#tree-expression-typer),
6,650 queries and about 1 M Ir, came from a literal path that saw only bare
runs of string literals. It missed the 10,230 parenthesized queries.

## The candidate

The eager pass flags a one-token `STRING` node (`C_AST_TYPE_FLAG_STRING`)
without accepting it, so every parent still declines it.
`c_ast_types_answer` reports such a node, from its decline branch, with the
status `C_AST_TYPE_STRING` and the token as the replay range. Its checks are
the same as an answer's: no pending enumerator and no type-identity site.
`c_parse_expression_tree_string_answer` then replays the machine's root
SIZEOF task, which:
- strips the enclosing parentheses;
- probes the per-body memo for the token under the query's scope and flags;
- on a miss, calls `c_parse_expression_leaf_without_cast` with the query's
  arena;
- rewinds the machine's scratch arena as the frame's completion does.

The replayed row is the answer. It is published with the mutation limit at
the table size before the replay, where the machine's checkpoint leaves it,
and the query's memo slot is published as the machine's would be. A leaf that
fails is undone, and the query runs the machine. Runs of several string
tokens (48 queries, 0.73 M Ir) are left to the machine.

  - Machine runs called from `c_parse_expression_type_query` fall from 55,593

  - Charged against that: the 16,869 string replays' own leaf calls. The
    string-literal decode (`c_parse_string_literal_expression_type`, 32,495
    calls, 54.65 M) has the same calls and cost in both arms; for these
    queries it only moved out of machine runs into the replay.
- **D − A, −6.38 M.** The default path does the same work: machine runs,
  leaf calls and type-identity preparations have the same call counts in
  both arms, with the same inclusive Ir to within 8 K. The whole difference

  −0.70 M in each of two of its inlined copies. That is about 2.3 Ir per
  query over 2.14 M queries, from compiling the function again with the
  wider tree branch inlined. On `-c` it is −0.024%. The declared band was not
  changed after the fact; whether the default path is neutral on hardware is
  the 9700X comparison's to show.

## Reading

- The string-literal queries are answerable from the tree with an exact
  replay. Under the pilot that removes 0.14% of the self-host's
  `-fsyntax-only` instructions, against a census of 43 M. Most of a string
  query's cost is the literal's decode, which the replay must repeat, because
  the bound it computes goes into the appended array row.
- A cheaper next step would remove the decode itself: memoize each string
  token's decoded element count, so that the leaf's second and later calls on
  one token skip `c_ir_count_string_literal_range_for_target`. That changes
  the machine's own leaf and the default path, so it is out of this change's
  scope.
- Objects are byte-identical at `-g0` and `-g`. The default path's −0.062% on
  `-fsyntax-only` is code layout in one function, not saved work. It does not
  carry over to `-c`.
- Hosted wall time was not measured, and these counts are diagnostic.
  Performance validation is incomplete (#2761), and the hook stays opt-in.
