## Scope and compiler cost

Issue [#102](https://github.com/buster14a/buster/issues/102). Baseline:
`719ba64e3022a0ae1db078ea97cb951a70ac02a0`.

The old emitter reserves an eight-byte slot for every used SSA result. The
replacement computes instruction ownership and last uses, then reuses expired
block-local integer slots. Intervals include the consuming instruction, so
inputs cannot alias its result. Cross-block values, block parameters, incoming
arguments, rematerialization inputs, pointer values and aggregate snapshots
retain dedicated storage. Locals retain their resolved sizes and alignment;
edge-copy scratch is separate. Every reused slot receives full eight-byte
writes. Immediate result forwarding avoids a reload until another instruction
is emitted; calls, branches, address recipes and block boundaries invalidate it.

Analysis takes linear instruction/operand/edge-argument scans. Allocation scans
at most 64 slots per candidate, with no sorting or CFG fixed point. Temporary
storage is four bytes per instruction plus four bytes per value, and a 256-byte
bounded slot-end array. The two linear arrays are released with the allocation
scratch arena, rather than retained per function. Existing value-slot, local-
offset and use-count arrays remain unchanged. Two small forwarding fields are
added to the function emitter. This is deliberately conservative: functions
with many cross-block values or addressable objects can still exhaust the frame.

## Correctness and validation

The registered eBPF tests exercise chains of 8/300/600 operations with and
without frontend SSA, overlapping lifetimes, rematerialized indexed addresses,
diamonds, loop-carried swaps, mixed widths, aggregate snapshots, deterministic
objects, a 512-byte local and real stack overflow. The raw-IR boundary fixture
returns `0UL` to avoid introducing an additional integer-conversion temporary.
The issue's dead-branch reproducer is retained as
`tests/basic_c_ebpf_stack_liveness.c`; both spellings and frontend forms execute
against the unsigned arithmetic oracle. On this baseline the driver already
accepts both spellings with frontend SSA, while raw local lowering still rejects
the dead-branch version because edge-copy scratch exceeds 512 bytes.

Focused eBPF validation passed 3,002/3,002 assertions; the full Debug suite passed
1,944,057/1,944,057 assertions across 47/47 modules. The baseline Release self-host
passed its byte-identical fixed point and MIR_STACK/NONE gates. TCC 0.9.27 cannot
bootstrap unchanged `string.c` in this environment, so the build driver was
bootstrapped with Clang; application builds use the ordinary CMake policy.

This VM evidence does not establish Linux kernel-verifier acceptance. No kernel
loader is available here. End-to-end compiler timings and final Release,
sanitizer, self-host and hosted-check results are recorded in the PR validation
record. This resource audit makes no generated-program throughput or compiler
wall-time speedup claim.
