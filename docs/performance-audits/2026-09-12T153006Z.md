## Scope and method

For [#469](https://github.com/buster14a/buster/issues/469), compare the standalone
harness at `fd0ba8ff8175952d12bbdb367adef13effcc4865` with the shared-library
implementation at `6170727eab17c399c7589f9ac591872397b8804d`. Both are ordinary
Clang `-O2 -fwrapv -fno-strict-aliasing -funsigned-char` builds. The shared build
adds `-Isrc -DBUSTER_SINGLE_THREADED=1 tools/throughput/shared.c`; no sanitizer,
allocation observer or PMU is enabled. The final PR also moves sanitizer-tool
construction into build.c; that does not change the measured ordinary binary.

Both harnesses launch the **same 25 MiB trusted Clang-built ide binary** as both
baseline and candidate. Its SHA-256, both harness identities and the raw data
are retained in [the evidence directory](evidence/2026-09-12T153006Z/summary.json).
The compiler source predates the #485 rebase, whose changes affect workflows
and the GPU acceptance tool, not this compiler binary. No comparison between
compiler implementations is claimed.

One initial A/B pair warms the harness; eight subsequent pairs alternate AB/BA.
Every invocation uses `run --profile smoke --workload tiny_startup --mode none
--pairs 4 --warmups 1 --no-guard --require-identical-output`. Each has two warmup
children and sixteen timed children. All 18 invocations succeed: **288 recorded
samples, 36 warmup children**, identical output SHA-256 throughout. The initially
attempted `--warmups 0` was rejected by the unchanged CLI before any experiment;
it produced no observations and was corrected to the required one warmup.

The outer collector records elapsed wall time and wait4 resource observations.
`child_wall_seconds` sums the sixteen recorded samples. The remainder explicitly
**includes both warmup children**, preparation, hashing, report/replay work and
outer process launch; it is not an exact isolated parent-CPU measurement.
The resource fields belong to that complete invocation, not to the compiler
samples. Individual warmup durations are not present in the result schema.

## Timing and ownership contract

`tp_process` retains its native creation and blocking-wait sites. Only the clock
provider changes to `timestamp_take`/`timestamp_ns_between`. On Windows,
shared argv conversion and its scratch allocations finish before the starting
timestamp. On POSIX, the signal handlers, process group, ready pipe, affinity,
pre-exec PMU attachment, wait4, timeout and cleanup sequence are unchanged.
Hashing, paths, experiment allocation, source metrics and report serialization
remain outside the measured interval. The selected compiler paths and command
arguments remain explicit; neither harness substitutes another executable.

Experiment/statistics and JSON/CSV/Markdown formatting remain in the tool,
including existing `%.17g` formatting and buffered close-error detection. The
shared modules own arena lifetimes, bounded paths/integer parsing, recoverable
streaming transfers, file copying, clocks and SHA-256. Ordinary spawn/wait does
not supply the required measurement contract and is not used as a replacement.

## Validation

- All eight smoke workload files and their reported hashes match the baseline
  byte-for-byte; existing hardcoded input identity tests also pass.
- Clang and GCC native integration: **122,586 assertions, zero failures** each,
  including a new timeout-descendant marker regression.
- ASan/UBSan native integration: **122,586 assertions, zero failures** with
  `detect_leaks=0`; this first run does not claim leak coverage.
- Release `test_all`, including shared hash/OS regressions: **2,133,499 assertions,
  47/47 modules**. Repeated after rebasing onto
  `ba1c9df2d952695608762b396ccadafb08af6990`, with the same successful totals.
- Ordinary Release self-host: **38,399,232-byte byte-identical fixed point**.
- Build-driver native throughput and GPU acceptance self-tests pass after the
  rebase; the GPU test retains #485's version checks.
- Shared hash tests cover empty/null updates, abc, a million a bytes and every
  split of binary messages spanning both padding boundaries and multiple blocks.
  OS tests distinguish EOF, partial reads and failed reads/writes, check absent
  bounded paths and scratch lifetimes, and exercise a full device on Linux.

Canonical `./build.sh bench_throughput self-test` cannot bootstrap here because
installed TCC 0.9.27 rejects the unchanged `string.c:991` (`array type expected`).
A Clang-built native driver was used explicitly. Disk exhaustion also forced
build/test outputs into temporary memory-backed storage. No source gate was
disabled to accommodate either limitation. Cross-platform CI status belongs to
the PR's current commit and is reported separately, not inferred here.

## Reproduction

From a checkout, build the old harness with the old documented standalone
command and the new harness with the command in `tools/throughput/README.md`.
Build one trusted Release ide and supply absolute paths:

```sh
python3 docs/performance-audits/evidence/2026-09-12T153006Z/measure.py BASE_HARNESS SHARED_HARNESS IDE NEW_OUTPUT_DIRECTORY
```

`raw.csv` retains every outer observation, the per-invocation `*-samples.csv`
files retain all compiler sample fields, and `validation.txt` retains module
summaries plus full-log identities. `SHA256SUMS` covers the retained evidence.
