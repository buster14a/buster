## Workload

Every arm compiles the same input, the base revision's unity self-host source,
from the base checkout:

```sh
ide cc -Isrc -Ibuild/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -c \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

4,180,888 tokens reach the parser, and the tree has 2,776,566 nodes. Lowering
asks `c_ir_builder_controlled_body_range` 39,748 times. Under the pilot, the
candidate builds 4,542 extent tables (one per body that asks) with 39,721
entries. It answers 39,736 queries from them and walks 12 (`C_AST_EXTENTS
bodies=4542 entries=39721 entry_declines=12 answers=39736 walked_input=0
walked_anchor=0 walked_shape=12 refused_input=0 refused_anchor=0`). The 12 are
compound statements whose end the shared rule (`c_parse_plan_statement_last`)
does not state. In 8, the last item is a `return`, and in 4 it is an `if`,
whose expression holds a container (a statement expression or a member list).
There are four arms:
- A: base, default flags;
- B: base with `-fc-ast-pilot`: the tree, the typer, the declaration split, the
  statement plan, and the token-walking extents in lowering;
- C: candidate with `-fc-ast-pilot`: the same, with lowering's extents read
  from the table;
- D: candidate, default flags.

C − B is the table's own effect, and D − A is its cost to the default path.
Callgrind ran with `--cache-sim=no --branch-sim=no`.

## Reading

The walkers this slice replaces were already cheap, at about 15.7 M inclusive
(0.07%). The walker's own memo of `if`-chain ends (`statement_ends_plus_one`)
already keeps it from walking a chain twice. Any
table that covers whole bodies costs about as much as answering the queries.
The slice ships under the declared budget, which gates on exactness and work
equivalence, as a retirement step. It is not a speedup, and the hosted
counts say it costs 0.06% of the pilot's instructions on this input. A
cheaper version would build entries only for the queried substatement, on
demand, instead of per body. That needs a token-to-node map the tree does not
have yet. It is left as a follow-up, not claimed.

## Validation and limits

- Callgrind counts instructions, not time, on `-march=x86-64-v3` builds whose
  AVX-512 kernels are compiled out.
- One input, one host, single process, no pinning and no `perf` counters. Wall
  time was not measured: the budgets did not ask for it, and on this host it
  cannot resolve an effect of this size.
- No 9700X request is made for this slice. Zen 5 validation stays
  **incomplete**.
- Correctness of the measured candidate is in the pull request's validation
  record: `c_ast_tests` and `compiler_driver_tests`, `test_all`, and
  `test_self_host --config Release` (fixed point 40,987,192 bytes).
