The unsigned two-way search in [PR #2478](https://github.com/buster14a/buster/pull/2478)
retains the direct scan for needles shorter than 32 bytes. It addresses the
bounded-work acceptance of [issue #2450](https://github.com/buster14a/buster/issues/2450).
The initial timing campaign exposed expensive preprocessing for a long needle
that already matched at offset zero. The repaired source adds exactly one full
prefix equality probe before preprocessing. This costs at most the needle length,
keeps the combined linear work bound, and uses the existing optimized equality
path for immediate matches. The threshold remains 32. The original search and
runtime controls are retained, and no release-path observer was added.

This audit records correctness, a source-bound logical work model, and bounded
synthetic timing observations. It makes no compiler speedup or caller-level
performance claim. The old campaign and the separate campaign after the repair
are both preserved; their samples are never pooled.

## Logical work and correctness

[`tools/string_first_sequence_work.py`](../../tools/string_first_sequence_work.py)
extracts the actual current search, helper, slice and scalar equality function
bodies into a private generated C translation unit. It verifies extraction sites
and hashes, inserts counters at the four two-way byte comparison sites, and
counts the actual scalar equality loop, including periodicity and the new prefix
probe. This is the Debug/scalar logical byte-comparison model. It is not a count
of release SIMD operations, retired instructions or elapsed time. Release source
contains no observer cost.

The 2,560 cases cross sixteen independent haystack lengths with sixteen
independent needle lengths and six shapes, plus 1,024 fixed-seed full-byte random
cases. The lengths include zero, one, two, 31/32/33, 63/64/65, equal and oversized
needles, and lengths through 4,096. Shapes cover repeated late mismatch, exact
end, prefix match, periodic bytes, a distinct-byte ramp (period 251 for larger
buffers), and random bytes containing NUL/high-bit values. A direct scalar oracle determines the first offset. Both
full buffers are compared before/after. Repeated late mismatch also checks the
independent direct-work formula `(N - M + 1) * M`.

The long-path budget is `8 * (N + M) + 64`; the fixed short-path budget is
`32 * (N + M + 1)`. Distinct-buffer immediate long matches must perform exactly
`M` scalar equality comparisons. Clang and GCC each pass all 2,560 cases with
zero offset, immutability, formula or work failures, and their four output CSVs
are byte-identical. At `N=4096, M=2048`, repeated late mismatch performs 10,240
logical comparisons versus the independent direct scan's 4,196,352; the long
budget is 49,216. An immediate 32-byte match performs 32 comparisons.

Three private negative controls prove the oracles are capable of rejecting a
plausible regression. Substituting the direct search remains offset-correct but
fails 122 work budgets. Increasing the two-way mismatch shift by one fails 142 offset
checks. Disabling only the new prefix probe remains offset-correct and within
the linear budget but fails 193 immediate-match work checks. No production or
existing runtime oracle is weakened. The ordinary string module also adds
threshold controls at lengths 31, 32 and 33 for earliest occurrence, pointer
identity, NUL/high bytes and unchanged slices.
See [Clang work summary](evidence/2026-10-05T092402Z/2478-prefix-count-clang/summary.json)
and [GCC work summary](evidence/2026-10-05T092402Z/2478-prefix-count-gcc/summary.json).

## Tiny-needle observations

The opt-in `BUSTER_STRING_SEQUENCE_BENCH=1` fixture measures the real
uninstrumented function in fourteen fixed cells: lengths 1, 2, 3, 7, 15, 31 and
32, each with an immediate match or repeated late mismatch, haystack length 256,
and 1,048,576 calls. The pointer varies across sixteen alignments. Each run checks
the expected checksum. Timing never gates correctness. This includes call and
loop overhead and models synthetic inputs, not a real caller distribution.

Each separately declared campaign uses six complete pairs in alternating AB/BA
order, one warmup per variant, CPU 2, and a fresh copied executable per run.
All fourteen runs in each campaign succeed. The summaries retain every pair and
all fourteen cells; there are no extra captures, discarded pairs or adaptive
threshold changes. The reported interval is the min/max of the six paired ratios,
a nominal 96.875% distribution-free interval under independent continuous pairs.
These are pointwise intervals, not simultaneous fourteen-cell or family-wise
claims. The shared host is not admitted for a stable benchmark conclusion:
frequency, SMT neighbors and external activity remain uncontrolled. Other owned
builders/testers were idle for the repaired capture; the first campaign overlapped
ordinary validation and is retained with that additional limitation.

The **original** source's 32-byte immediate-match paired B/A ratio was 21.5466,
interval [10.8100, 66.3907], with per-variant medians 6.43 and 198.74 ns/call.
Its repeated late mismatch ratio was 0.53149, interval [0.09824, 0.78292].
That finding motivated the prefix repair. The new campaign is separate and does
not estimate a rigorous difference between the two campaigns.

For the **repaired** source, the 32-byte immediate-match medians are 3.71944
and 3.40919 ns/call, paired B/A 0.897322, interval [0.849092, 0.960498].
The 32-byte repeated late mismatch medians are 633.143 and 323.564 ns/call,
paired B/A 0.528039, interval [0.399851, 0.543065]. The work-count negative
control independently establishes removal of immediate-match preprocessing.

The repaired one-byte immediate-match medians are 3.69386 and 4.18281 ns/call:
a measured absolute cost of about 0.49 ns/call, paired B/A 1.182503, interval
[1.004166, 1.44949]. This observed short-path cost is retained rather than hidden
by the long-path result. Every other repaired cell below 32 bytes has a pointwise
interval spanning one. These observations justify no caller-level performance,
compiler speedup, equivalence or regression-free timing claim. See
