## Workload

Every arm compiles the same input, the base revision's unity self-host source,
from the base checkout:

```sh
ide cc -Isrc -Ibuild/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -fsyntax-only \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

4,105,792 tokens reach the parser, and the tree has 2,721,682 nodes. Four arms:
- A: base, default flags;
- B: base with `-fc-ast-pilot`: the tree and the stage-2 typer;
- C: candidate with `-fc-ast-pilot`;
- D: candidate, default flags.

D − A is the designator-probe skip on the default path, the one intended
default-path change. C − B is the whole change under the pilot, so
(C − B) − (D − A) is the initializer typer's own effect. Callgrind ran with
`--cache-sim=no --branch-sim=no`.

## Census that chose the work

Before writing any rule, a throwaway build of the base (not committed) sent
each machine run that `c_parse_expression_type_query` made through a noinline
wrapper around `c_type_parse_machine_run`, one wrapper per category. Callgrind's
inclusive cost of each wrapper is then the machine Ir of that category.
- A query outside a typed body was categorised by the analysis phase that
  made it, using a phase tag set before each validator.
- A miss was categorised by the shape of its range against the body's node
  spans.

The instrumented total was 9,995.2 M Ir.

Neither class of miss is a node-alignment problem. Both are designators that

- its assignment walk takes `.pointer` for the place before `=`.

S8's compound literal, `(String8){ .pointer = …, .length = … }`, accounts for
most of them.

## The eager candidate that failed its budget

The first candidate (`cc7ca3cf`) typed every file-scope initializer as soon
as its validation began. Its C measured 9,678,433,379 Ir (−63.0 M against B)
and its D 9,943,054,716 (−106.0 M against A). So its initializer typer's own
effect was **+43.0 M**, and that budget failed:
- it typed 736,333 initializer expression nodes, costing about 186 M;
- it saved about 141 M of machine Ir.

A per-initializer count, again from a throwaway build, gave the reason. Only
61 of the 2,777 typed initializers received no query that the literal fast
path does not answer, but those 61 held 551,736 of the 736,333 nodes. They
are the numeric tables, whose queries ask only about lone literals.

The final candidate reserves an initializer's arrays when its validation
begins and types it on the first query that the literal path does not take.
2,716 initializers are typed, with 184,597 nodes.

The two candidates' D arms differ by +1.0 M Ir (+0.010%). The default path
runs none of the changed code, so that is rebuild noise of the same order as
stage 1's.

## Validation and limits

- Callgrind counts instructions, not time, on `-march=x86-64-v3` builds whose
  AVX-512 kernels are compiled out; architecture-neutral deltas transfer.
- One input, one host, single process, no pinning and no `perf` counters.
  Hosted wall time was not taken.
- The 9700X pull-request comparison runs default flags only. It could compare
  arm D against A, which is the probe skip, but it cannot time the hook. Zen 5
  validation of the typer therefore stays **incomplete**, and no PR benchmark
  request was made.
- Correctness of the measured candidate:
  - `c_ast_tests` and `compiler_driver_tests` in Debug (split TUs) and
    Release (unity), including the corpus verify gate;
  - the corpus run with the fixtures preprocessed for `aarch64-pc-windows-msvc`:
    50,776 answers and 1,371 probes;
  - `test_self_host --config Release` (fixed point at 39,619,944 bytes);
  - the Clang analyzer, with the CI flags, on `c_parse.c`, `c_ast_types.c`,
    `c_ast_test.c`, `driver.c` and `ide.c`.
