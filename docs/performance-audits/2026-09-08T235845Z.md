## Lifetime and capacity contract

Previously every nonempty function body reserved `body_token_count + 1`
12-byte `CParserBlockFrame` records in the translation-unit arena. The frame
array is private scratch for statement splitting; no published declaration,
assertion or diagnostic stores a frame pointer.

The syntax pass now owns one vector that starts at 16 frames, doubles when
its live prefix fills, and is reused for later bodies. Reallocation copies
only live frames, and the body walker refreshes its pointer before the next
access. Old chunks remain arena-owned until the translation unit ends, so
cumulative frame storage is less than twice the largest allocated capacity;
it scales with maximum simultaneous body depth, not cumulative body tokens.
The syntax pass's existing token-count limit bounds the last possible capacity
doubling at 2^30 to 2^31. Declaration records, static-assertion ranges and the
token-indexed diagnostic/delimiter arrays retain their existing lifetimes.
