## Workload

The arms compile the base revision's unity self-host source from a pristine
checkout of the base:

```sh
ide cc -Isrc -Ibuild/v3/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -target x86_64-unknown-linux -march=znver5 -g0 -fsyntax-only \
  [-fc-ast-pilot] src/buster/apps/ide/ide.c
```

The four arms:
- A: base, default flags;
- B: base with `-fc-ast-pilot`;
- C: candidate with `-fc-ast-pilot`;
- D: candidate, default flags.

`-c` uses the same input with `-c -o`, at `-g0` for instructions and at `-g0`
and `-g` for object identity. Callgrind ran with `--cache-sim=no
--branch-sim=no`. Call counts are summed from the Callgrind `calls=` records.

## The change

`c_parse_incompatible_aggregate_value` keeps its interface. It now types the
range and calls `c_parse_incompatible_aggregate_source`, which holds the
former body and takes the source type.

At the two sites, `c_parse_incompatible_checked_value` passes the checked
type to the source half, and types the range again only when the reuse rule
does not hold.
- **Reference checks.** Debug and sanitized builds (`BUSTER_REFERENCE_CHECKS`)
  also run the base's path for every reused value. They require the same
  verdict and message.
- **The string test.** The core asks `c_ir_tokens_are_string_literals` only
  for aggregate elements.

The candidates differ only in the reuse rule:
- **Candidate 1** reuses every valid checked type.
- **Candidate 2** also requires that the checked typing appended no type row.

## Reading

- **What dominates.** The ~1.2 G under the shape validator is per-element
  semantic checking, not the walk. Typing and conversion account for 780.7 M
  of the core's cost. The walk's own share is the designators, element ends
  and the core's instructions, about 550 M. Strings are 112.4 M.
- **The slice that ships.** Candidate 2 removes the second typing for 98% of
  the repeated elements, and the string test for 99.8% of the elements. Its
  saving is the same on both endpoints, because `-c` validates first.
- **Why candidate 1 does not ship.** Its −32 M more is the 10,980 elements
  whose typing appends rows. Removing their re-query changes the `-g` output
  only by dead DWARF types. That fails the declared byte-identity budget, so
  it is recorded and does not ship.
- **Dead DWARF types.** The base emits 33,969 unreferenced array types in
  the self-host's `-g` object, because every frontend type row reaches the
  debug model. That is a separate finding, added to
  [#2726](https://github.com/buster14a/buster/issues/2726), not a defect of
  this change.
- **Leads left, unmeasured:**
  - the walk itself, about 550 M: designators, element ends and the core's
    instructions;
  - the same double typing for call arguments (138,883 calls to
    `c_parse_incompatible_aggregate_value`, 82.9 M), outside this census's
    initializer scope.
- **Not measured:** wall time and peak RSS. These counts are diagnostic, and
  performance validation is incomplete (#2761).
