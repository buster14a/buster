`2026-10-15T141326Z` (Linux x86_64, hosted EPYC 7763 and EPYC 9V74; **verified
stable Clang lowers hosted analyzer time with the complete Release
inventory**).

## Result

Use the existing verified stable LLVM installer for the required analyzer job.
Two same-VM pairs show lower analysis wall and CPU time with upstream Clang
23.1.3 than with Ubuntu Clang 21.1.8, with the full Release inventory retained.
Both pairs meet the predeclared 10% analysis-wall screen, and their observed
installation costs leave positive savings. These are two hosted observations,
not population statistics or a Zen 5 result.

Owner and acceptance: [#4300](https://github.com/buster14a/buster/issues/4300),
parent [#709](https://github.com/buster14a/buster/issues/709). The maintainer
authorized this experiment on 2026-10-15. Measurement source is
`cf42f39d27eba71b8ed81edf0cab12fd4d6565aa`; its compiler sources match main
`02a6414e020f5d549122197c3a7c8407df5bed76`. That experiment commit changes only
the manual qualification workflow. The production change starts from that main
revision and does not include the temporary comparison workflow.

## Matched hosted measurements

[Run 38743818228, attempt 1](https://github.com/buster14a/buster/actions/runs/38743818228)

No analyzer phases overlapped on one VM.

## Scope, commands and diagnostic controls

Both compilers passed 93 native failure/coverage controls on each VM. All four
analyses and all four independent aggregates passed 118/118 selected C TUs,
with 118 Debug rows excluded by the ordinary Release selection. No source or
checker was removed, no result was reused within the experiment, and the eight
existing partitions, two workers and 600-second per-TU deadline were retained.
Passing diagnostic logs are empty and their SHA-256 values match every report.

The image compiler is Ubuntu 21.1.8 (6ubuntu1), binary SHA-256
`78e9dd2ccc9e88859b3a29109a44bfab00e3d6cb70f00f3daae063eed3d05251`.
Stable is upstream 23.1.3, LLVM commit
`0d261d1ca552c95a8f007e061c787ac7132fbcbc`, binary SHA-256
`913453afb492abab17025139852413ba7fd7a52b4fb75fcce58ff3fe399d0a9e`.
The binaries match across VMs for each role. The existing `ci_llvm.py` installer
verified the stable archive's published size and SHA-256 before extraction.

Each compiler generated its own canonical non-unity, unsanitized, tests-enabled,
non-LTO Release database. The independent replay compares every projected
argument after normalizing compiler/resource paths, generated-tree paths and
compiler-probed optional warnings. All other arguments and source/module/partition
identities match. Both drivers request the same 12 default checker groups.

The only optional-warning difference is the old spelling
`-Wexperimental-lifetime-safety`, which Clang 23 does not accept. Upstream
21.1.8 guards that analysis with `CPlusPlus`, so the flag did not establish that
analysis for this C inventory ([source](https://github.com/llvm/llvm-project/blob/llvmorg-21.1.8/clang/lib/Sema/AnalysisBasedWarnings.cpp#L3018-L3022)).
The retained upstream `AnalyzerOptions.def` files for 21.1.8 and 23.1.3 are
byte-identical, SHA-256
`86734c087cf6a91e953271e25a72cc5c3295248451decb948f4f536cd183a39d`.
Their deep-mode node limit remains 225000, maximum inlinable size 100, and
always-inline size 3. No smaller exploration budget was selected for this test.
A passing corpus and controls remain bounded evidence, not a proof of arbitrary
future diagnostic equivalence. The separate checks-enabled coverage issue
[#4057](https://github.com/buster14a/buster/issues/4057) is unchanged.

## Production change and validation

The required job uses the same verified stable installer as native CI, before
driver bootstrap, controls and analysis. Exact queue-to-main reuse skips this
installation. The reuse consumer now requires the installer step in fresh source
evidence and its skipped outcome in a reused main receipt. No automatic analyzer
reference comparison is restored. Removing that installer step and its receipt
requirement returns selection to the image compiler.

Before publication, the prepared change passed 27 installer tests, nine analyzer
provenance/selection tests, 54 main-reuse tests and 90 workflow-tool tests, plus
Markdown-link and whitespace checks. Exact-head hosted production CI and protected
integration are later gates recorded on the issue/PR; this audit does not mark
them complete in advance.
