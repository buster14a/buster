The linker copies each input's data but publishes the maximum of its data and
virtual size, after alignment. A fresh mapping hid the unwritten gaps and tails;
a reused arena retained the preceding owner's bytes. `arena_allocate_zeroed`
now defines the background before the copies, clearing only dirty overlap.
BSS and TLS BSS retain virtual storage only.

The focused test uses two inputs with 7- and 11-byte virtual spans, 8- and
32-byte alignments, and 3- and 2-byte data prefixes. It checks all 43 merged
bytes in text/data/rodata, BSS storage, symbol offsets, and identical serialized
ELF/COFF/Mach-O output across fresh, `0xa5`, and `0x3c` arena backgrounds on
both native architectures. Object-reader round trips preserve the payload;
readers can append alignment for additional empty sections. The old linker
fails the dirty-byte and serialized-identity checks. After the repair the full
link module passes 1,165 assertions.

## Isolated merge cost

The [snapshot harness](2026-09-09T000655Z-link-merge.c) times only the actual
`link_objects` API. Each sample merges two symbol-free objects into three
file-backed sections 128 times. Each input section has a two-byte virtual tail;
the second starts after a one-byte alignment gap. Fresh samples advance through
a new arena, including first-touch page faults. Reuse samples poison one MiB
before timing, then rewind after each merge. This deliberately exposes the
worst dirty-overlap cost when almost all merged bytes are source data that the
subsequent copies overwrite.

Both binaries use identical current sources except for the original versus
repaired `link.c`, and trusted Clang 22.1.8 with `-O3 -march=native -fwrapv
-fno-strict-aliasing -funsigned-char`. No build or test from this task runs during the
series. Normal desktop activity, other tasks, and clock scaling are not controlled. Commands are pinned
to logical CPU 2. Two warm-up pairs precede seven alternating measured pairs;
the table shows medians of per-merge times, not whole-compiler throughput.

| Source bytes per merge | Arena | Before (μs) | After (μs) | Difference |
|---:|---|---:|---:|---:|
| 6,126 | Fresh | 0.656 | 0.699 | +6.5% |
| 6,126 | Reused | 0.243 | 0.278 | +14.4% |
| 393,198 | Fresh | 31.065 | 30.376 | -2.2% |
| 393,198 | Reused | 7.193 | 12.104 | +68.3% |

Fresh sections require no fill. Fully dirty reuse adds exactly 6,141 or 393,213
bytes of clearing per merge in these shapes. Arena footprint and section-enumeration
passes do not change; dirty payload bytes are written twice (clear, then copy).
The large reused case has a measurable correctness cost. The -2.2% fresh-large
difference is not an overall compiler speed claim.
There is no SIMD or branch/cache-miss improvement claimed. Sparse gap-only
clearing is a possible later tradeoff if real linking workloads establish that
large reused result buffers are material; this repair keeps the existing zeroed
allocation contract and the common fresh path.

To reproduce, build the snapshot harness against each checkout's `src` and
`build/generated`, using the same compiler and flags:

```sh
clang -Isrc -Ibuild/generated -DBUSTER_UNITY_BUILD=1 -DBUSTER_INCLUDE_TESTS=0 \
  -DBUSTER_LINK_LIBC=1 -DBUSTER_OPTIMIZE=1 -O3 -march=native \
  -fwrapv -fno-strict-aliasing -funsigned-char \
  docs/performance-audits/2026-09-09T000655Z-link-merge.c \
  -pthread -ldl -lm -o /tmp/link-merge-bench
taskset -c 2 /tmp/link-merge-bench
```

The baseline checkout needs a copy of the same harness. For each row divide
`duration_ns` by `iterations`, then take the median across seven runs. Alternate
before/after order between pairs. Baseline dirty checksums are intentionally
nonzero; the repaired checksum is zero.
