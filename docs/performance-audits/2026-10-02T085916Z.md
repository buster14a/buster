The chosen workload is x86-64 Linux ELF: four debug-bearing foreign objects,
64 TLSGD sites, main.o, with direct/GOT variants, object/archive inputs and
ET_EXEC/PIE outputs. The production change builds one scratch index keyed by
exact section and u64 offset, then reuses it for import classification and
relocation application. Existing archive admission, symbol resolution,
relocation validation, debug copying and unwind handling remain in place.
Caching helper names or filtering candidate kinds retains the nested scan;
adjacency fails reordered relocation inputs. Wider symbol/archive rewrites
were rejected after inspecting the existing indexes.

The scalar oracle is independently written; the index counters describe
instrumented work, not time. Hash collisions can worsen probing. No-helper
links incur a symbol scan, helper/no-site links a count scan, and very small
links may regress from setup overhead.

Hosted link_tests passed 151,074/151,074 and compiler_driver_tests
138,529/138,529. Tests include exact identities, three relocation orders,
duplicates, mixed genuine helper references, high offsets, invalid-symbol and
overflow negatives, checked scratch exhaustion, real loader execution and
independent ELF inspection. Late debug-tail failure preserves existing or
absent destinations on four ELF routes, with successful controls (#2235).
The new real workload checks retained .debug_info/.eh_frame sections; its
readelf inspection does not independently decode DWARF/CFI or exercise unwinding.
