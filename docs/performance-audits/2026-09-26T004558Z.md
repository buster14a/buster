## Actual production boundary

For each section kind separately, `link_objects` visits contributions in
object/section order. A contribution has validated nonzero power-of-two
alignment `a` and size `d = max(data.length, virtual_size)`. The relevant state
transition and output are:

```text
offset[i] = round_up(cursor, a[i])
cursor'   = offset[i] + d[i]
```

Both operations are checked; the production offset is stored only after both
succeed. Invalid alignment, rounding overflow and size overflow fail. A
zero-sized contribution is not necessarily an identity: its alignment can
advance the cursor. There is one distinct cursor per section kind, not a
single chain through all section records.

The full function additionally validates object pointers/counts, target
compatibility and cumulative counts in a specified order. COMDAT resolution,
payload copies, relocation rebasing, debug offsets, zero-filled background
bytes and initializer ordering have their own contracts. The pure recurrence
below does not summarize those operations or authorize reading invalid input
objects concurrently. Production section alignments are u32; the experiment
also exercises the wider u64 domain of the integer helper.

## Exact summary and validity argument

Write `R_a(x)` for mathematical upward rounding to a positive power of two.
Let `M = UINT64_MAX`. An item is `F(x) = R_a(x) + d`, defined exactly when the
checked operations succeed. For powers of two representable in u64,
`align_forward_checked`'s addition test agrees with mathematical rounding:
the largest representable multiple of `a` is `2^64 - a`.

Represent a block by three u64 fields and a validity bit:

```text
T = (p, A, q, valid)
T(x) = R_A(x + p) + q
```

The expression is evaluated with checked addition and checked rounding. The
identity is `(0, 1, 0, true)`, including an empty block. An item is
`(0, a, d, true)` for valid `a`. A false validity bit is the everywhere-undefined
transfer. It is not a special input value, and its other fields are irrelevant.
The summary has constant storage independent of block length; it contains no
list, deferred program, function pointer or new IR.

For `L = (p,A,q)` followed by `R = (r,B,s)`, let `u = q+r`. Concatenation means
**R after L**, not a commutative merge:

```text
A >= B:  then(L,R) = (p,          A, R_B(u)+s)
A <  B:  then(L,R) = (p+R_A(u),   B, s)
```

When `B` divides `A`, rounding an `A`-multiple plus `u` to `B` adds `R_B(u)`.
When `A` divides `B`, the nested rounding identity is
`R_B(R_A(z)+u) = R_B(z+R_A(u))`. One way to prove the latter is to compare both
sides with every multiple `kB`: `R_A(z)+u <= kB` is equivalent to
`z <= kB-R_A(u)`. Thus both sides have exactly the same least bounding multiple.
These two identities give the formulas above.

Composition is associative **by denotation**, since it is composition of the
same partial functions. The representation is not claimed canonical; tests
must not require equal summary bytes for different parenthesizations. Order
matters: adding one then rounding to two maps zero to two, whereas the reverse
maps zero to one.

Every item is monotone and never decreases the nonnegative cursor. Therefore
an overflowing prefix cannot later recover. Checked overflow while constructing
a summary, or failure when evaluating the constructed summary at zero, denotes
an everywhere-undefined block. The construction intermediates are nonnegative
parts of the resulting bound, so discarding an overflowing construction cannot
reject a representable result. Conversely, when the mathematical final value
fits, all original item prefixes fit. There is no modular-arithmetic shortcut;
`-fwrapv` does not turn this checked layout contract into wrapping arithmetic.

## Reconstruction and failure order

`integer_alignment_blocked` implements three phases over an already-readable
array of pure contributions:

1. Construct one summary per chunk without an incoming cursor dependency.
2. Scan the summaries to determine chunk input states and the first failed
   chunk. No per-item output is published during either phase.
3. Replay the scalar recurrence within every successful chunk and within the
   first failed chunk. The latter recovers the exact successful prefix and
   stops before publishing its failed offset. Later output slots stay untouched.

A chunk's incoming cursor is exactly the composition of its preceding chunks;
induction then gives every reconstructed offset, partial cursor and completed
count. Empty input touches neither input nor output pointers. A final partial
chunk is bounded by the remaining count. `count/chunk + (count%chunk != 0)`
avoids the overflowing `(count+chunk-1)/chunk` idiom, even for `UINT32_MAX`
chunk width. The experiment rejects zero chunk width and counts above its
explicit stack-storage test bound of 65. That bound is **not** a proposed
production threshold.

This preserves the pure kernel's first failure and partial writes. It does not
certify the linker's mixed metadata/arithmetic error ordering. A production
integration would need to retain that ordered validation or an independently
proved ordered replay; moving all metadata checks before all arithmetic could
change which error is reported. No such integration is included.

## Scalar comparison, cost model and eligibility

The straightforward scalar control uses the incumbent's existing
`align_forward_checked` and `u64_add_checked`; it does not make division or a
slow generic interpreter the performance baseline. The division/remainder
implementation is solely a structurally different correctness oracle.

For N contributions of one kind, chunk width W and B = ceil(N/W), the scalar
control reads each input once and writes each successful offset once. The
blocked scalar experiment constructs N item summaries, performs B prefix
applications, then revisits up to N items to reconstruct their offsets. It
adds O(B) summaries/input states and a second input walk. Summary construction
itself performs checked rounding/additions and alignment comparisons. Nothing
here proves those operations cheaper than the recurrence they precede.

On one execution thread this is more work with no demonstrated latency benefit.
The original cross-chunk cursor dependency is only usefully separated if chunk
construction and reconstruction can execute independently. With enough legal
existing lanes, their work could be distributed while the B-summary prefix
remains serial; that is an O(N/P+B) idealized work-depth model, not a timing
prediction. Actual dispatch, barriers, prewarm, tails, metadata validation,
input/output traffic and cache ownership must all be charged. No new gang or
scheduler is introduced. A parallel-prefix tree is not needed for this research
and is not implemented.

A single object with one contribution per kind has chains of length at most
one, however many kinds it contains. Duplicate kinds and many-object links are
legal and could form longer chains; their current workload frequency and time
share were **not measured**. Function counts, total section counts and a sample
in the enclosing linker do not establish that eligibility. The first gate
therefore remains unmet: no current genuinely hot, long same-kind recurrence
has been demonstrated. Even the blocked-scalar crossover is unestablished.
Do not advance to SIMD or lanes on algebra alone.

The model trades the cross-chunk dependency for summary construction,
reconstruction and extra input/scratch traffic. The actual limiting physical
resource is unknown; this report does not label it bandwidth-bound without
measurement or infer instruction latency from vector width.

## Registered C falsification suite

The experiment lives entirely inside `BUSTER_INCLUDE_TESTS` in the existing
integer test source. `integer_tests` invokes the new fixture through
`BUSTER_TEST_FIXTURE`, preserving normal assertion aggregation and fixture
accounting. No new public helper, module, dependency, build registration or
production callsite is added.

The submitted suite checks:

- All 12^3 ordered triples from alignments {1,2,4,8} and sizes {0,1,3}, at
  inputs 0 through 15 and four extreme inputs. Both parenthesizations and both
  identity compositions are checked against direct remainder/padding execution.
  This is exhaustive over the declared reduced alphabet, **not all u64 states**.
- A noncommutativity witness, an absorbing overflowing transfer, invalid
  alignment, null output, the `2^63` alignment boundary, and an exactly
  `UINT64_MAX` final result. Failed summary application must leave output intact.
- Every length 0 through 65 and every chunk width 1 through N+1, plus
  `UINT32_MAX`, across mixed, zero-sized, invalid-alignment and overflowing
  families. Every invalid-item position in a 65-item input is also crossed with
  every chunk width 1 through 66.
- 192 deterministic generated whole inputs with irregular power-of-two
  alignments, near-limit sizes and incoming states. Each uses every chunk width
  1 through N+1. Whole-summary status/value, direct scalar status, blocked status,
  completed count, partial cursor, both output guards and all untouched output
  tails are compared with the independent oracle.

The test oracle uses remainder-derived padding and explicit overflow bounds,
not the composition formula or production alignment/addition helpers. Generated
input uses only defined unsigned arithmetic and shifts below 64. The summary
prototype is test-local; it is not permission to introduce production state.
