## Reproduction and implementation

An independent Clang layout observer reads the list produced by Buster. With
unmodified main, all eight allocator/frontend combinations compile successfully
but exit 1 under QEMU; the all-Clang control exits 0. The candidate passes all
eight. This is runtime reproduction, not a conclusion from equal size alone.

Both direct and MIR paths now use the public 32-byte, eight-aligned image:
`__stack`, `__gr_top`, `__vr_top`, then independent signed 32-bit `__gr_offs`
and `__vr_offs` at byte offsets 24 and 28. Register reads advance negative byte
offsets toward zero, preserve the other file's cursor, and use the shared stack
cursor after exhaustion. Existing 64-byte GP and 128-byte full-Q save areas are
retained. GP save-area tops require eight-byte alignment, not sixteen; the
independent optimized Clang control caught that distinction in the test itself.
The normative reference is the
[Arm AAPCS64 variable-argument appendix](https://github.com/ARM-software/abi-aa/blob/main/aapcs64/aapcs64.rst).

Aligned integer pairs use even GP slots and sixteen-aligned overflow addresses.
A named aggregate that spills exhausts its GP register file, preventing a later
named argument from incorrectly reusing X7. By-value `va_list` parameters use the
existing AAPCS64 indirect-aggregate transport and callee-private copy instead of
being rejected by MIR shape selection. The existing 32-byte `va_copy` and no-write
`va_end` behavior remain. MIR branches use generated instruction forms and
checked fixups; no permanent row, dependency, or third IR was added.

The existing `native_variadic.c` / `native_variadic_host.c` differential pair now
contains fourteen additional public-list relations: five scenarios in both
directions, many-named-argument overflow in both directions, and by-value calls in
both directions. They cover mixed named arguments, independent GP/FP exhaustion,
scalar register/stack transitions, copies made before and during consumption,
continuation after external consumption, HFA4-float/HFA2-double values and spills,
aligned i128 register/stack reads, named aggregate exhaustion, and list canaries.

The registered machine test explicitly requires all five new entry points,
verifies selection and the aligned-pair/FP metadata, and keeps every MIR allocator
strict. Its targetless preprocessing helper requires an explicit ELF AArch64 test
guard: the initial function-presence assertions caught ten failures when the
ordinary architecture predefine was absent. The repaired test cannot silently
pass by excluding the new functions. Windows/Darwin fixtures remain scoped out.

## Paired compiler-throughput guard

The unchanged native `tools/throughput/throughput.c` harness ran an A/A control,
then A/B serially, with no concurrent local builds/tests. Each uses the CI profile:
six workloads times four allocator modes, two fixed rounds of twenty adjacent
pairs, two warmups, automatic CPU affinity, and AArch64 object output. All 1,920
timed observations per comparison are retained. Synthetic output equality is
required across baseline and candidate, including exact bytes/hashes.

Both A/A and A/B finish with zero confirmed regressions and fourteen inconclusive
cases. This passes the existing guard, not an equivalence or speedup claim. The
unchanged gate requires wall growth over 15% and 2 ms, or RSS growth over 20% and
16 MiB, with its exact sign test in both rounds and family-wise correction.
Hardware-counter and allocation observations are unavailable, recorded as NA.
This general synthetic corpus is not active public-variadic-path timing evidence.
No physical Zen 5/Zen 4 acceptance, end-to-end self-compile timing comparison, or
variance-free shared-host measurement is claimed.

## Decision and remaining work

Publish the bounded repair for review, keep draft until applicable exact-head
hosted correctness gates pass, and keep #360 open. The existing va_arg subset
still excludes HFAs larger than sixteen bytes, general indirect aggregates, and
vector/HVA reads. Those cases need selection, direct-oracle parity, independent
producer/consumer execution, alignment/overflow regressions and native sanitizer
coverage before the broader issue can close. No formerly supported program was
replaced with a new rejection to reduce fallback counts. This patch does not
retire the direct backend or close #36.
