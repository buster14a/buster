## Decision

The frontend direct-SSA trivial-parameter simplifier (`c_ir_ssa_finish`) was
the one repeated global sweep with a large default-path population in which
most later evaluations could not change anything. Commit
`b8bb4f0a0b1bc516e236e454a8482b54afebaa0a` replaces its later sweeps with an
exact ordered notification agenda. Output is byte-identical everywhere it was
checked, and the hypothesis about the **population** survived: 74% of the full
sweep's post-first-sweep evaluations were provably redundant.

The **cost model did not survive**. The skipped evaluations were the cheapest
ones (already compressed roots, exit after two incoming values), and the
agenda's own bookkeeping costs about as much as the remainder. On the frozen
unity input the whole compile executes only **0.020% to 0.048% fewer
instructions**, depending on unrelated inlining in two builds of the same
algorithm, and peak RSS is **0.13% higher**. The only material benefit is
worst-case: deep loop nests go from O(P * depth) to O(P) evaluations.

Disposition: **measured neutral** for representative input. The draft pull
request preserves the implementation, its exact oracle and counters as a
worst-case guard for maintainer decision, not as a throughput change. No
wall-time claim is made.

## State transition, notification rule and proof

`replacements` is a forest over old value IDs. A live parameter `p` is trivial
when the roots of its incoming values, ignoring `p`, are exactly one value
`s`; removal unlinks `p` and sets `replacements[p] = s`. It is the only
transition that changes a root (path compression rewrites only non-root
links), and it is irreversible, so the removed set grows monotonically. The
result is **order-sensitive**: of two mutually trivial parameters, the one
visited second keeps the self-referencing root. The historical schedule
(ascending blocks, list order, repeat until a sweep removes nothing) therefore
defines the answer, and representatives and canonical IDs depend on it.

A kept parameter either has no non-self root (it stays forever, because its
incoming roots can change only if it is itself removed) or two distinct
non-self witnesses `a` and `b` at which the scan stopped. While neither is
removed both remain roots, every earlier incoming still resolves to `a` or to
`p`, and a repeated scan stops at the same incoming with the same result.
Hence:

1. The first sweep is unchanged and records each survivor's witnesses. If it
   removed nothing trivially, the fixed point is reached.
2. Survivors whose witness was removed later in that sweep are due in sweep 2;
   only if one exists are doubly linked watches built for the others.
3. Removing survivor `r` notifies its watchers: a watcher after `r` is due in
   the same sweep, one before `r` in the next, exactly where the full sweep
   would evaluate it next. A notified watcher drops its other watch and
   re-registers after re-evaluation, so each notification is one clean-to-due
   transition.
4. Removed survivors leave their block list in O(1) through a predecessor
   index.

By induction over the full sweep's evaluation sequence, every skipped
evaluation is one the full sweep performs without effect; each removal, its
root, every retained parameter and all canonical IDs are unchanged, and the
agenda's evaluations and sweeps are subsets of the full sweep's. A later
sweep's due set comes only from removals, so every sweep after the first
except the last removes a survivor: at most S + 2 sweeps for S first-sweep
survivors.

Charged bound: the unchanged first sweep plus 16 bytes of records per
survivor; only if it removed a trivial parameter, O(S) classification; only if
a survivor is due, O(S) watch linking; then each later evaluation (a subset of
the full sweep's), at most two watch links per evaluation, one notification
per clean-to-due transition, the dirty-set words between the lowest and
highest due survivor per sweep, and O(1) per later removal. Parsing, lowering,
predecessor propagation and the rest of `c_ir_ssa_finish` are unchanged and
still paid in full: a single later update costs O(D), a compilation does not.

## Population and frontier varied independently

Exact counts asserted by the registered `c_test_direct_ssa_simplify_agenda`
against the retained full-sweep oracle:

- Backward chains of length n (the historical worst case): reference
  n(n+1)/2 evaluations over n+1 sweeps, agenda 2n−1 over n sweeps
  (n = 4, 64, 256, 1024; n = 1024 is 524,800 versus 2,047).
- Forward chains converge in the first sweep; the agenda records no survivor.
- N stable parameters plus a frontier chain D, N ∈ {0, 64, 4096} and
  D ∈ {2, 8, 64}: reference N(D+1) + D(D+1)/2; agenda N + 2D − 1 evaluations
  and N + D − 1 classifications. The O(N) classification is charged.
- **Dense adversarial control**: seven hubs removed one per sweep and
  M ∈ {1, 64, 1024} watchers reading every hub, placed before or after the
  hubs. Every removal notifies every watcher, so the agenda re-evaluates each
  watcher exactly as often as the full sweep, paying one notification and one
  link per evaluation, and saves only the hub re-sweeps and, when watchers
  follow the hubs, the confirmation sweep.
- 20,000 fixed-seed random graphs (cycles, self and duplicate incomings,
  empty and self-only, forwarded, aliased and memory-form parameters) match
  the oracle's roots, lists, counts and removals, and never exceed its
  evaluations, incoming visits or sweeps.

`c_test_direct_ssa_loop_nest_work` lowers generated loop nests. At depth
8 / 32 / 96 the frozen base performs 431 / 9,883 / 185,275 evaluations and the
candidate 152 / 1,352 / 10,184, with identical objects. The counter build
bounds evaluations by twice the created parameters, which the base violates.
