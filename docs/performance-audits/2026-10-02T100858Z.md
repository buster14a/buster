## User-visible contract and improvement

The existing Linux x86-64 indexed MIR recorder feeds canonical debug records and
DWARF4; GDB 17.1 is the independent consumer. The first-party small C fixture
follows the reused-home loop in #1375 and has explicit stops at main line 19,
loop call line 22 and mark return line 13. It checks exact source/function stops,
initial x/y values, three loop iterations, callee i = 0/1/2 after its machine use,
older caller frames, absence of x in mark's lexical scope, and normal exit.
An i value before its first certified use may be correctly unavailable; arbitrary
read errors are not accepted as unavailability.

Baseline x initially equals `11400714819323198485` and y equals
`11558797164892890995`; the second loop stop incorrectly reads x as `1`.
Both FAST and QUALITY reproduce this. There are 14 baseline wrong-x executions
(two small fixtures plus 12 linked cost consumers); deliberately wrong controls
are excluded from that count. Candidate FAST/QUALITY pass all small and linked
consumers. Their live x/y remain exact, while x is explicitly optimized out at
all six loop/caller queries. This changes a false value into honest unavailability.
It does not claim to recover a value that the machine no longer preserves.

Controls actually executed: Clang -O0 reference passes the same stops, frames and
scope checks; deliberately expecting x+1 fails with VALUE x; -g0 fails breakpoint
placement. The latter is never counted as a successful unavailable-value test.
The candidate must expose an x availability transition, so hiding every value
cannot pass. Dense row replay plus explicit x86-64/AArch64 seed assertions supply
independent producer validation. readelf section inspection is format-only
measurement and is not credited as an executed debugger check.

## Implementation and cost mechanism

Distinct spill subjects sharing a physical home are discovered in the existing
indexed spill grouping pass. Shared frame validity is cleared at non-entry block
boundaries and expires after the final certified own operand/home edit. Certified
physical registers continue through copy/clobber/rematerialization tracking.
Replay terminates a suffix only after frame expiry when no physical register or
pending immediate rematerialization can recover the value. Unshared homes retain
existing behavior. The independent dense test model scans all spills and replays
every machine row rather than consulting the production index.

The indexed pass avoids a new grouping/hash pass. Added function scratch is
approximately 9 bytes per spill slot (subject, owner and shared flag arrays),
plus fixed pointer fields. That is a source-derived allocation bound, not a
measured RSS claim. The significant measured output cost is redundant/stale
location ranges across 128 exported cloned bodies plus main (129 similar bodies).
The 34,469-byte generated workload leaves cloned bodies unexecuted. No internal
phase timer or linker work counter was added: wall time and relocation bytes
below are separate proxies, and cannot establish an asymptotic speed improvement.
No new dependency, copied external code, generated binding, native-retirement
authority or acceptance-policy change is included.

## Rejected hypotheses and remaining uncertainty

The original static cutoff stopped all tracking after the final own event. Hosted
run 36987172370 preserved debugger correctness but failed 17 existing coverage
assertions: surviving register values must remain observable. That approach was
rejected. The refined producer restored all existing 12-seed/promoted-local
expectations; run 36993589272 failed only the new test's obsolete six-seed oracle
(and the build-tool source budget). Current explicit eight-seed expectations retain
certified registers, and the workflow reuses ordinary gates to fit the unchanged
budget. Current TCC/source-size and bootstrap codegen checks pass. Earlier harness
failures (missing GDB, invalid build flag, deleted driver, pre-use i assumption)
were diagnostic failures, never counted as successful reproductions.

A universal format or replacement recorder was rejected: the existing indexed MIR
path already supports the needed ownership evidence. #988's earlier rewrite had
no justified measured win; this work does not revive it. General SQLite recorder
speedup attributed in #1723 is not reproduced by this small synthetic workload.

#1375 remains open for selector-created STACK_SLOT aliases; sibling lexical block
scope correctness is tracked by #2241. #2240 tracks source-inspected location
buffer sizing/patch bounds; no memory-safety reproduction was executed here.
These two findings are source inspection, not debugger-validated fixes. Tests here
check function lexical separation, not sibling nested scopes. No independent
AArch64, macOS, Windows/PDB or LLDB debugger execution is claimed. Target seed
validation is distinct from executing an independent consumer on that target.

Next concrete step: complete ordinary full platform and merge-group CI for this
PR, then extend #1375 with an independently failing selector STACK_SLOT-alias
fixture before broadening ownership validity. Qualified hardware acceptance is
explicitly pending, with no laptop/benchpress substitute.
