## Inputs

`m<N>.c` defines N global `__thread long` variables, and one function reads
and increments each of them. Each variable therefore gives two
general-dynamic sites: T=2N TLSGD/`__tls_get_addr` PLT32 pairs in one
`.text` section. Inputs were built for N in 256, 1024, 4096 and 16384:
`m<N>.o` with PLT helper calls, `n<N>.o` with `-fno-plt` (GOTPCRELX helper
calls), and `m<N>.a` containing only `m<N>.o`. `main.o` calls that function
twice and prints both sums. `plain.o` is a no-TLS control: 4096 global
variables and 4096 functions.

## Byte identity and execution

`identity.tsv` covers 26 cells: 24 TLS cells (`m<N>.o`, `n<N>.o` and
`m<N>.a`, each as `-no-pie` and `-pie`) and the two `plain.o` controls. In
all 26 cells the baseline and candidate images were byte-identical. Every
image ran and printed the same output as the system `clang` link of the same
inputs.

## Paired latency

Each sample is the process wall time of `taskset -c 2 ide cc ARGS -o OUT`,
measured by Python `perf_counter_ns` around the child process. It includes
process startup, argument parsing, input reads, linking and publication. It
is not the internal `LINK_TLS_ARTIFACT` interval. Each cell ran two warmup
pairs, then measured pairs that alternated AB and BA order. The ratio,
candidate over baseline, is computed for each pair; the table gives its
median and range. All 502 recorded processes exited 0. Inputs were warm in
the page cache, so nothing here describes a cold link.

Baseline medians for the `-no-pie` objects grow 6.26x from T=2048 to T=8192
and 15.42x from T=8192 to T=32768; for `-pie` the steps are 5.59x and 14.89x.
Only the last step approaches the 16x a pure T² term would give, because
fixed per-link cost still dominates at the smaller sizes. Candidate medians
grow 1.17x and 1.75x for `-no-pie`, and 1.13x and 1.94x for `-pie`. That
pattern is consistent with removing the quadratic companion scan, but it
does not attribute the time to the index alone (see above). In the no-TLS
control the median paired ratios were 1.014 and 1.011, inside ranges that are
far wider on this shared host. Neither a speedup nor a regression is
established for ordinary links.

## Interpretation and limits

- The quadratic term shows up in end-to-end link time, not only in the
  counters. It already costs time at a few thousand general-dynamic sites in
  one link, and T=2048 is about the size of one TLS-heavy -O0 -fPIC
  translation unit.
- Self-host and the throughput corpus contain little or no general-dynamic
  TLS. No change to compiler throughput is expected or claimed there.
- The workload is narrow: one warm TLS object or a one-member archive, on a
  shared cloud VM, with one build root per revision. It cannot stand in for
  the cohorts #1915 still requires: cold cache, many small objects, large
  archives, a phase breakdown and same-source rebuild controls.
- Matched 9700X acceptance (#2761) remains pending, and this hosted replay
  does not substitute for it. A scope waiver would not provide physical
  performance validation either. The 9700X `compare-pull` route compares a
  pull request's merge base with its head, and #2247 has already landed, so
  that measurement needs a new owner experiment.
