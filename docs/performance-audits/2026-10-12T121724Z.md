## Inputs

`m<N>.c` defines N global `__thread long` variables, and one function reads
and increments each of them. Each variable therefore gives two
general-dynamic sites: T=2N TLSGD/`__tls_get_addr` PLT32 pairs in one
`.text` section. Objects were built with `clang -O0 -fPIC -g0 -c`. The
`-fno-plt` variants `n<N>.o`, whose helper calls use GOTPCRELX, were built
with the same command plus `-fno-plt`. `m<N>.a` is `ar rcs` of `m<N>.o`.
`main.o` (`clang -O0 -g0 -c`) calls that function twice and prints both sums.
`plain.o` is a no-TLS control: 4096 global variables and 4096 functions,
compiled with `-fPIC`.

## Byte identity and execution

For N in 256, 1024, 4096 and 16384, each binary ran
`ide cc {-no-pie|-pie} main.o X -o image` with X set to `m<N>.o`, `n<N>.o`
and `m<N>.a`. That is 24 cells per binary. All 24 baseline/candidate image
pairs were byte-identical (`cmp`). Every image ran and printed the same two
sums as the system `clang` link of `main.o m<N>.o`. For N=16384 those sums
were `134209536 134225920`. Both `plain.o` control links were also
byte-identical and printed the expected sum.

## Paired latency

Each sample is the process wall time of `taskset -c 2 ide cc ARGS -o OUT`,
measured by Python `perf_counter_ns` around the child process. It includes
process startup, argument parsing, input reads, linking and publication. It
is not the internal `LINK_TLS_ARTIFACT` interval. Each cell ran two warmup
pairs, then pairs that alternated AB and BA order. The ratio, candidate over
baseline, is computed for each pair; the table gives its median and range.
Inputs were warm in the page cache, so nothing here describes a cold link.

From T=2048 upward, the baseline's time grows about 16x for each 4x increase
in T. That is the quadratic companion scan. The candidate's time stays close
to linear in T. In the no-TLS control, the medians moved by +0.9% and +0.8%,
inside paired ranges that are far wider on this shared host. Neither a
speedup nor a regression is established for ordinary links.

## Interpretation and limits

- The quadratic term shows up in end-to-end link time, not only in the
  counters. It already costs time at a few thousand general-dynamic sites in
  one link, and T=2048 is about the size of one TLS-heavy -O0 -fPIC
  translation unit.
- Self-host and the throughput corpus contain little or no general-dynamic
  TLS. No change to compiler throughput is expected or claimed there.
- These are hosted timings on a shared cloud VM, with one build root per
  revision. There is no same-source rebuild control, no cold-cache cohort and
  no phase breakdown. Qualified 9700X acceptance (#2761) is still outstanding.
  The 9700X `compare-pull` route compares a pull request's merge base with
  its head, and #2247 has already landed. Running this replay on the 9700X
  therefore needs a new owner experiment, such as a direct workload or a
  revert-shaped candidate. The alternative is for the owner to accept this
  hosted evidence for the issue.
