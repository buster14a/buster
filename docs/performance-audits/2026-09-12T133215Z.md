## Implementation and semantic controls

A counting pass groups original 32-bit symbol/relocation indices by section.
Already ordered ranges skip sorting; ranges of at most 16 use bounded insertion
sort and larger disordered ranges use iterative merge sort. Offset ties compare
original indices. Emission advances one symbol and relocation cursor per section;
arbitrary decoder/literal lookups use binary search without changing the cursor.
Range queries preserve the lowest original table index among matching entries,
which is not necessarily the lowest offset. `.size` uses a separate original-order
symbol view; `.extern` retains the original single scan. Input objects never move.

Setup is O(T+S+R) plus O(S log S + R log R) sorting in the unordered case, where T
is section count. Ordinary emission traversals are monotonic. Nonmonotonic
relocation lookups are O(log R); instruction range queries inspect only matching
relocations. The repeated complete-table scans at every output cursor are gone.
No SIMD, frontend, IR, object-file layout or linker behavior changes.

The registered tests retain exact Linux x86-64/AArch64 strings, unsorted and
equal-offset symbols, duplicate relocations, original `.size` order, empty and
zero-fill sections, 67 interleaved/empty sections, missing/end labels, backward
and forward literal targets, invalid relocation emission and input immutability.
A private test-only oracle compares indexed lookup results with original-table
scans, including reverse queries after the streaming cursor advances. Ordered,
reverse and permuted populations cover insertion and merge-sort paths.

All **27 complete generated outputs** compare byte-for-byte with the baseline;
[their lengths and SHA-256 hashes](evidence/2026-09-12T133215Z/printer-output-identity.json)
are retained. These tests are additional to **24 byte-identical assembly
comparisons** across NONE/MIR_STACK/FAST/QUALITY and x86-64/AArch64 on
Linux/Windows/macOS. Clang 18's independent assembler accepts all 24 outputs;
[exact commands and results](evidence/2026-09-12T133215Z/target-mode-validation.json)
are retained. This is cross-target assembly validation, not execution on all
six targets.

## Temporary and retained memory

Let Sd and Rd count entries belonging to real sections. Persistent index payload
is `16*T + 8*Sd + 4*Rd` bytes, plus alignment. Sorting needs at most
`4*max(section symbols, section relocations)` additional bytes, only for a large
disordered range; that storage is reclaimed before emission. Internal-label
storage is reclaimed after each section, and every index is reclaimed before
returning. No index survives in the caller's returned arena allocation.

At N=8192, the raw arena high-water growth rises from **8,582,456 to 8,779,096
bytes** (+196,640 bytes, about 192 KiB). Retained arena growth falls from
**8,582,456 to 8,533,304 bytes** (−49,152 bytes). Candidate scratch over the
retained output reservation is 245,792 bytes, covering index/label storage;
sort and label peaks overlap in the arena. These figures exclude stack locals
and describe this printer replay, not process RSS. Whole-process RSS is separately
retained in the paired measurements.
