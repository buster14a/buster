## Lifetime map (source-confirmed, not a measured population ranking)

Let T be preprocessing tokens, S retained spelling bytes, R source regions,
and D the semantic declaration/type/entity population. These are different
scaling dimensions; an expanded TU need not scale with its root file size.

| Population / owner | Actual consumers and boundary |
| --- | --- |
| Raw root/include mappings | `compiler_driver_execute_c_single` keeps the root map through object/diagnostic emission and unmaps at its exit. Include frames already unmap their raw file at EOF. No additional unmapping is proposed. |
| Translated spellings and final token/shape streams | Three private commit-on-demand arenas, each requesting a 1 GiB reservation; S bytes, T token rows and T shape bytes are distinct live payloads, not 3 GiB RSS. Tokens, interned names, parser/model copies and source/debug metadata borrow them. The documented last boundary is complete TU consumption. |
| Translation checkpoints, files, macro stamps, regions, keys and page brackets | TU arena. Macro-origin and logical/physical source queries use these in preprocessing, parsing, lowering, diagnostics and debug emission. Lowering copies the map record by value while retaining its array pointers; it does not detach the payload. |
| Syntax declarations, token indices and diagnostics | TU arena, produced by `c_parse_ast`; semantic analysis consumes the syntax. Token-range and location references continue through model construction/lowering. The private delimiter/body work and persistent outputs currently share ownership; the complete TU is not a legal scratch rewind. |
| Semantic types, declarations, bindings, array bounds, diagnostic strings | TU arena. `c_analyze_semantics_core` publishes the model; validation and lowering make by-value model copies and use saved indices/ranges. Borrowed names and map references continue into canonical output. Model mutation/checkpoint rules are unchanged. |
| Type-parse work machine and semantic query scratch | Already private. `machine_buffer_arena` and `machine_temporary` are released at semantic-analysis completion; their nominal capacities are not evidence of retained TU payload. |

The selected duplication is much narrower than these owners. Sorting and
origin finalization occur before the first key publication. Only
`c_preprocess_respell_c23` runs between the two publications. It does not
remove or edit existing key rows: each respelled token calls
`c_source_map_append`, which increments count unconditionally. An append may
copy the region backing array; the recovery view is updated during the pass
so its location queries still see the original key prefix. Final page-table
construction and diagnostic recovery occur after the second boundary.

## Ownership argument and falsifier

At the second boundary, equal counts imply no append **only under this
specific append-only phase contract**. Consequently keys, sentinel, regions,
capacity and every saved key index still describe the final map. Preserve the
first allocation and skip the second. If count changed, use the unchanged
publisher to rebuild the complete key array and sentinel and publish the new
region capacity. Do not turn count equality into a general cache for maps
that may mutate existing rows.

No TU rewind, ownership transfer, new arena, new production IR, borrowed
string change, new global/TLS state, callback, or public record-layout change
is involved. Both old snapshots and downstream consumers keep their original
lifetimes. Speculative parser/type checkpoints and macro stamps are untouched.
The private test seam accepts only the same append-only contract.

A discriminating negative control changes the condition in
`c_source_map_publish_appended` to `if (true)`: outputs can remain equivalent,
but the registered allocation oracle must reject changed key pointers and
advanced arena cursors. A C23 alias-growth input is the countercase: its
publication must not be skipped, including when the region array moves.

## Byte/work accounting; no RSS or speedup inference

For R > 0 regions and no appended alias, the baseline requests and initializes
two arrays of `8 * (R + 1)` bytes. The candidate requests and initializes one.
The eliminated allocation is retained-but-logically-dead payload on the
baseline; the remaining live final key payload is identical. This removes
one allocation call and R+1 key-row initializations, with no new copy, clear,
planning pass, or source scan. Finalization adds one count comparison. The
publisher fills fields directly, not through the arena zeroing API.

When aliases append A > 0 regions, both variants retain the original
`8 * (R + 1)` and final `8 * (R + A + 1)` key arrays. This candidate does not
claim to eliminate that overlap or the region array's allocate-and-copy growth.
Existing region sorting, page-index writes, explicit clears elsewhere and
requested spelling/token reservations are unchanged.

The formula is requested and explicitly initialized payload, excluding arena
alignment. Arena `position` is an allocation cursor; `os_position` tracks the
arena's committed extent, not RSS. OS commit requests, live payload,
initialized/touched payload and peak RSS must be reported separately. No
whole-compiler requested-byte ratio is an RSS ratio, and no instruction/byte
reduction is a throughput verdict. Representative materiality remains
unestablished without the authorized end-to-end experiment.
