## Scope and ownership

This implements the retry/pin-scratch slice requested by the latest #125
coordination comment. Candidate admission, weighted arithmetic, heap ties,
regional ordering, placement economics, and the three existing fallback attempts
are unchanged. Sparse candidate-region traffic, closure representation and
physical Zen 5 acceptance remain open under #125; this is not a claim to close
that issue or its #128 parent.

Previously every attempt cleared every global pin ID and copied both complete
span arrays. Mask construction and final counting also scanned every value.
Now each assignment appends its value ID to a touched list. Every candidate can
be assigned once, and every assignment consumes one of eight span slots per
register. The existing 48-register target limit therefore bounds the list and
retry cleanup at 384 values (1,536 stack bytes). No generation counter can wrap.
Endpoint stores occur on assignment; FAST tests pin membership before reading
them. Mask union order changes from value order to assignment order, preserving
the complete masks and allocation output. No allocation-policy limit changes.

The global pin-map bridge moves from the returned placement's arena to scratch,
after nonempty candidacy. No returned placement contains that pointer. The two
span arrays remain globally indexed for FAST, but their unassigned entries are
unread and attempts no longer copy them. Existing instruction-sized pin-depth
and mask work is unchanged. Four additive diagnostic fields observe initial pin
map clearing, touched resets, endpoint stores and mask-list visits.

## Allocator replay

The registered regression relocates all live values above a dead-ID gap,
including instruction operands, block parameters and edge sources. It compares
ordered edits, physical operands, frame/pin counts and every emitted byte against
the compact function. It repeats after dirty scratch reuse across all six
desktop targets and both C lowering forms. The diagnostic variant requires
actual retries and equal reset work with and without the gap.

The opt-in benchmark times complete QUALITY placement of `wide_live_loop`
(120 live-ID slots, 110 rows, one accepted pin); construction, encoding and
assertions are outside the timer. Four serial processes run in ABBA order,
pinned to CPU 0, with one warmup and seven observations per size in each process.
No other build/test from this task overlaps collection. Both use the same test
harness; the reference module contains the original allocator. Medians below
pool all 14 observations per variant/size; raw ranges and per-process samples
are retained. No timing threshold gates a regression test.
