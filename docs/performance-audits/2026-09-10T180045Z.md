## Objective and boundary

The configured host compiler now controls the mixed-object fixture command
family, including its wrapper argument. The ELF linker ignores an unused
undefined `_GLOBAL_OFFSET_TABLE_` marker emitted by GCC on x86-64 Linux while
preserving ordinary undefined-symbol failures and referenced marker handling.
Both PIC and non-PIC assertions remain active.

Clang 18 and GCC 13 disagree on the SysV register class of a record containing
a float and a nonzero unnamed integer bitfield. The explicit driver option
`-fsysv-unnamed-bitfields=integer|padding` selects that narrow boundary;
`padding` remains the default. The policy belongs to an `IrAbiContext`, is set
before ABI queries, and does not mutate canonical record layout or shared
types. Other native calling conventions and non-native/LLVM output reject an
explicit setting. Zero-width unnamed fields remain padding in both modes.

The configured host probe observes XMM0 with a mandatory later float argument
and identifies the actual host convention without guessing a version cutoff.
Mixed fixtures cover arguments, later scalar arguments, results, nested shapes,
both link directions, all four allocators, and both frontend forms. A separate
assembly return control clears the unused return register so a wrong policy
cannot pass merely because a previous instruction left the expected value.

Primary upstream evidence: LLVM [#216777](https://github.com/llvm/llvm-project/pull/216777)
changed this classification; [#220788](https://github.com/llvm/llvm-project/pull/220788)
gates that behavior above Clang ABI compatibility version 23. This does not
establish which released compiler includes those changes. Buster's option is
not a general Clang ABI-version emulation switch.
