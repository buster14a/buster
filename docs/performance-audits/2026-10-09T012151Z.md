qualified reuse and no Zen 5 performance acceptance**).

## Disposition

This closes #3134 for the tested bounded whole-tree model. The evidence rejects
this model as a qualifying cross-run reuse mechanism; it does not reject every
possible analyzer cache. In particular, it does not assess a per-invocation
design with complete dependency and negative-lookup state plus an independently
authenticated producer. No authoritative cache was introduced: the temporary
native observer was removed after the campaign, the ordinary analyzer remains
required, and no workflow or trust policy changed.

## Full-inventory shadow/fresh pair

Both arms used upstream source commit
[`fcf5790`](https://github.com/buster14a/buster/tree/fcf5790c4aa3452396113b99eaeecb9f7c496b91),
with the exact local prototype overlay from commit `7c9f3082d885993291893c52e0de7334ac2178cb`
(helper source plus `build.c` registration; combined tree
`c14d82134cbd1dcd44eab9d3802b151969cf6281`). The local prototype commit is
preserved by its archived C source and exact patch; it is not a published
GitHub revision. Both arms used the same Clang 21.1.8 binary, compile database,
Release config, observed environment digest, driver and policy arguments.
Only each arm's fresh results directory differed. The existing analyzer ran
the complete selected inventory in each arm, and its ordinary independent
aggregation passed. The retained result directories contain every shard and
translation-unit log.

Each `clang_analyze_shadow` record reported `content_fingerprint_match=0`,
`authoritative_eligible=0`, `qualified_reuse_us=0`, and
`time_weighted_eligibility=unavailable`. At whole-run granularity both full
runs were ineligible (0/2); therefore qualified work saved was zero. There is
no per-translation-unit timing-to-eligibility mapping, so finer time-weighted
work is unavailable and no per-invocation qualification is claimed.

The observer counted 1,388 input entries and hashed 133,380,341 bytes (127.20
MiB, 99.38% of its 128 MiB cap) on each arm. The byte limit was not the only
blocker: the model did not bound implicit Clang resource headers, implicit
system header search, the compiler's runtime/loader closure, or the complete
process environment. It also found dynamic/token-spliced input. Both snapshots
therefore remained incomplete even though the second had the same partial
fingerprint as the first. A SHA-256 digest of local state is integrity
evidence, not an authenticated producer identity; producer authentication was
unavailable.

The native analyzer summary reported maximum individual child high-water RSS
of 596,664,320 bytes in arm 1 and 596,193,280 bytes in arm 2. These are the
largest individual child high-water values, not combined concurrent RSS. Its
separate `sampled_peak_tree_rss_bytes` value of 2,125,824 bytes is a
coordinator-only lower bound under the incomplete sampler tracked by
[#3159](https://github.com/buster14a/buster/issues/3159), not aggregate child
memory. The analyzer path did not record CPU time. The runs occupied shared
cloud scratch; there was no exclusive CPU lease, and host-wide runner
occupancy was not measured. `peak_live_processes=1` describes the analyzer's
observed process population, not host occupancy. These are cloud diagnostics
only; the approved Ryzen 7 9700X was not used, so performance acceptance
remains incomplete.

The exact driver/compiler/database/source provenance, commands, complete raw
outputs, both aggregations, all miniature attempts, controls and limitations
are in the [reproduction record](evidence/2026-10-09T012151Z-issue3134/README.md)
and its [`full-campaign-evidence.tar.gz`](evidence/2026-10-09T012151Z-issue3134/full-campaign-evidence.tar.gz).
The archived driver was compiled directly with Clang because the available
TCC bootstrap was 0.9.27, below the repository's minimum supported 0.9.28rc
([build guidance](../agents/build.md)). The archive preserves the original
full-pair prototype separately from later safety hardening; the full arms
used only the original source. Original self-test: 10/10. Hardened-control
self-test: 12/12. These validate observer behavior, not cache authority.

The miniature native campaign included unchanged-source repeats, changed
source, and a newly created higher-priority header after a prior negative
lookup. That header caused fresh analysis to fail; after confirmed removal,
fresh analysis passed and the partial fingerprint matched the pre-change
state. All these observations remained ineligible and caused zero skipped
work. State was not advanced by the failed fresh analysis.

## Conclusion and limits

The tested design spends 2.6–2.8 seconds on whole-tree discovery for a roughly
16-minute analyzer run, yet still cannot establish complete inputs, trust the
producer, or qualify even the repeated full run. Its bounded scan reached
127.20 MiB while omitting required host/toolchain inputs. This is a concrete
no-go for shipping this whole-run observer as a reuse qualification. It is not
a claim that hashing or authenticated per-invocation caches can never help;
those require their own dependency, trust and cost evidence.
