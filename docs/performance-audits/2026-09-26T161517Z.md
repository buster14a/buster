## Decision

`ir_validate_global` proved a global's relocations overlap-free by comparing
every pair: R(R-1)/2 comparisons per global. The replacement checks each record
only against its predecessor while the table is in ascending order, which
costs R-1 comparisons. The first out-of-order record switches to one LSD radix
sort of the offsets in scratch (8-bit passes, only as many as the largest
offset has bytes), followed by a neighbour check on the sorted copy.

The verdict is unchanged. Two relocations of width p overlap exactly when
their offsets differ by less than p. After sorting, some such pair is adjacent
whenever one exists. Every other check on each row is untouched: symbol,
offset and byte bounds, and label-address provenance.

The code is in `src/buster/lib/compiler/ir/ir.c`. The new counters are
`validation_global_relocation_sorts` and `_sort_rows`;
`validation_global_relocation_pairs` now counts neighbour checks.

## Equivalence and validation

- **Objects.** 141 input × flag groups (100 generated rows and 41 workloads), compiled by all 15 census builds, produced byte-identical objects. That covers #1442, every other candidate from this investigation, and main. `sqlite3.c` (#1414) and Lua `ltablib.c` fail identically on every ref.
- **`ir_test_global_relocation_overlap`.** It keeps the old pairwise loop as `ir_test_relocations_pairwise_overlap_free` and requires the same verdict over 768 random trials. The trials cover six shapes (ascending with random gaps, reversed, shuffled, duplicated, and free byte offsets) and both verdicts. It also checks `pointer_size` 0.
- **Counting-build assertions.** A 4,096-row ascending table must take 4,095 neighbour checks and no sort. The reversed table must take one sort of two radix passes.
- **Local runs.** The full `ide test --ci=1` suite passes on a tests + counting build, except the two host-only `wide_vector_boundaries` assertions (#1292), which fail identically on main. `test_self_host --config Release` reaches its fixed point at 46,686,248 bytes (main: 46,675,696).

## Limits

- The sort uses O(R) scratch per unordered global, rewound before return.
- Ascending tables, the common case, never allocate.
- Validation of an unordered table stays O(R · passes), where passes ≤ 8 bytes of offset.
- This PR touches retirement-bound sources (`ir.c`, `ir_construction.h`), so ordinary merge waits on the trusted integration writer.
