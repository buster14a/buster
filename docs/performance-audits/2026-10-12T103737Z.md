## Counted lookup work

`llvm_bitcode_test_section_index` calls the production interner through its
private test seam. It generates separately stored 14-byte section names
`.data.s0000000` onward, matching the issue's common-prefix family. The
shared-name control gives each input its own storage with identical content.
The test counts every inspected hash slot, including the final matching or
empty slot; normal tests-off builds contain no counter or seam.

| Entities | Shared probes | Distinct probes | Old distinct comparisons (source-derived) |
| ---: | ---: | ---: | ---: |
| 1,000 | 1,000 | 1,395 | 499,500 |
| 2,000 | 2,000 | 2,984 | 1,999,000 |
| 4,000 | 4,000 | 5,926 | 7,998,000 |
| 8,000 | 8,000 | 11,673 | 31,996,000 |
| 16,000 | 16,000 | 23,786 | 127,992,000 |

The old counts are N(N-1)/2 from the removed scan, not instrumented baseline
counts. New counts are observed slot visits, not an equivalent instruction or
wall-time unit. Every cell requires at most 4N visits and checks every ID;
16N also requires at most 24 times N's visits. These are bounds on this
family. Open addressing remains expected constant-time lookup, not a
worst-case guarantee against deliberately colliding names.

The index stores one u32 ID per slot, with power-of-two capacity at least
2 times the global/function population. Its clearing cost and upper storage
bound are linear in that population; the 16k cell uses 32,768 slots (128 KiB).
It is allocated only after encountering a named definition. Ordered names
remain the record authority; declarations and missing names return zero.

the expected number of section-bearing definitions; `opt -passes=verify

A separate C input with shared/unique global and function sections, unsectioned
definitions, and referenced declarations with section attributes also matched
