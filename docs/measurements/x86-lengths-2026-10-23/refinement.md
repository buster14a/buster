# Length-only SIMD: Clang 23 refinement and Zen 5 qualification

This is the current implementation record for [PR #307](https://github.com/buster14a/buster/pull/307)
and [issue #305](https://github.com/buster14a/buster/issues/305). The
[initial record](README.md) is retained as evidence for candidate `651a539`;
its Clang 19 cloud speedups do not describe this revision or establish a
Zen 5 speedup. The PR records the final target qualification against the
exact source and baseline SHAs printed by the workflow.

## Work removed

Branch sizing previously called the full encoder to obtain instruction
offsets, threw away its machine-code bytes, rebased offsets after every
1,024-record chunk, and allocated 15,424 bytes of encoded scratch. The caller
encoded the sized records again. `x86_measure` now computes only the lengths
and offsets, 16 records at a time. It shares the encoder's length rules,
prefix-sums the 16 lengths as bytes, and stores one vector of offsets.

The scalar reference uses the independent `encode_one` rules. The ordinary
64-bit-mode API requires initialized templates, valid records and a disjoint
count-sized offsets array. It needs no padding and has no extra end element.
Empty input permits null pointers; excessive counts return before access.
The public encoding paths, instruction format and generated bytes are unchanged.

## Fix the demonstrated compiler lowering

The first candidate used scalar form-word and flag loads packed into a
vector. Clang 19 emitted scalar loads. Clang 23.1.1 instead builds vectors
of absolute pointers, uses two partial `vpgatherqd` operations, loads the
remaining flags separately, and packs the results.

The refinement uses the form words already present in the transposed input.
It masks the low 16 bits and scales them by 16, then uses one
`_mm512_i32gather_epi32` with scale 4 and table base plus 12. The effective
address is exactly `form * 64 + 12`, the existing template flags. The existing
64-byte template-entry assertion checks the stride. No additional flag table
or initialization pass is introduced.

Exact Clang 23.1.1, `-O3 -march=znver5`, complete steady-state loop including
loop control, per 16 records:

| Emitted operation | Full encoder and offsets | Initial length-only | Refined length-only |
| --- | ---: | ---: | ---: |
| Instructions | 217 | 160 | 89 |
| Scalar form-word loads | 16 | 16 | 0 |
| Scalar form-index shifts | 16 | 16 | 0 |
| GPR-to-vector pointer moves | 0 | 12 | 0 |
| Hardware gathers | 0 | 2 × `vpgatherqd` | 1 × `vpgatherdd` |
| Vector stores | 5 | 1 | 1 |

These are instruction counts, not micro-op counts or cycle predictions.
Both length-only loops have no vector stack accesses in their steady-state
bodies. The full-encoder probe retains its four compressions and four
machine-code stores, in addition to the offsets store.

[refined-probe.c](refined-probe.c) produced the retained
[full encoder](clang23-full-encoder-loop.s),
[initial length-only](clang23-initial-loop.s) and
[refined length-only](clang23-refined-loop.s) loops. The
[toolchain provenance](clang23-provenance.md) pins the official release
archive and compiler hashes. This matches the runner's printed release
number, not a proven identical compiler binary. LLVM's `znver5` scheduling
model still uses `Znver4Model`; no model-based throughput claim is made.

- [Full encoder suite](refined-encoder-validation.txt), all five modes.
  The added length checks cover 136,752 generated accepted cases and 300,000
  random instructions, FS/GS and fixup markings, partitions, zero and excessive
  counts, and guarded counts 0–199 and 1,023–1,025 at 16 dword alignments.
- [Full branch-sizing suite](refined-branch-validation.txt): 1,500 generated
  functions / 5,157,349 records, guarded columns, exhaustion and convergence.
  GNU as 2.47 independently assembled 404 functions; all 404 matched, with
  98,920 long branches. The oracle provenance is in the initial record.
- [Focused ASan and UBSan checks](refined-asan-validation.txt), using
  [refined-check.c](refined-check.c), Clang 18.1.3, seed 305, `-O2
  -march=native -fwrapv -funsigned-char -fno-strict-aliasing -Wall -Werror
  -Wno-unused-function -fsanitize=address,undefined -fno-sanitize-recover=all`.
  This seed admits 136,660 generated cases plus 300,000 random instructions
  and the same guarded extents. `ASAN_OPTIONS=detect_leaks=0` disables leak
  checking alone. All checks passed without differences or sanitizer reports.

The cloud full build used the existing temporary cloud accommodations
`-mmwaitx -Wno-bitwise-instead-of-logical`; repository build flags are unchanged.
No `-march=znver5` binary was executed on the non-Zen-5 cloud host.

Two diagnostic native Clang 23 screens are preserved without a speed claim:
[two-way](refined-cloud-two-way.txt) and
[three-way](refined-cloud-three-way.txt). The latter compares full encode/rebase,
initial length-only and explicit gather, in three rotated process orders.

## Matched normal 9700X qualification

The existing `9700x.yml` job remains the only physical-host route. Its runner
hooks hold the shared host lock. Agent development, compilation experiments
and tuning remain in the cloud. No interactive agent runs are made on the
9700X.

The ordinary branch-sizing benchmark remains first. A bounded three-minute
addition runs for pull requests affecting the encoder, sizing implementation
or its workload fixtures. It stages the candidate benchmark and generator
into both temporary include trees, selects each revision's implementation,
and adapts only the baseline's old lengths scratch argument when necessary.
The baseline SHA, tested merge SHA, compiler version, flags, source hashes and
binary hashes are printed. All four binaries compile before measurement.

Three fresh process pairs use before/after, after/before, before/after order:

- `vector-lengths`, `size_branches` and `size_encode` on `tier0-40`,
  `tier0-mix` and `tier0-2000`, 11 samples each, seed argument 1. The unchanged
  `x86_encode` control also runs on `tier0-mix`. Module pool seeds include
  the row index, so the mix row uses actual generator seed 5.
- The [scaling fixture](scaling.c) runs one and eight workers, 200 passes,
  five warmups, independent pools, actual generator seed 1. Each worker
  handles 262,219 records in 2,883 functions and 1,064,719 encoded bytes per
  pass. Before timing, all encoded bytes and offsets match the scalar encoder.
  Expected reference checksum: `29cbeeb814da6666`.

Module timing pins to allowed CPU 2 when available. For scaling, the workflow
intersects online CPUs with its inherited allowed list, then selects one
logical CPU per `(socket, core)`. It requires eight distinct physical cores.
The fixture pins workers within that mask and prints their actual CPU list;
the workflow prints the topology. The coordinator briefly shares the first
worker's CPU at the barriers.

Each pair must report identical pool dimensions and, for scaling, identical
checksums, reference checksum and placement. Missing reports, execution
failures, identity mismatches and timeouts fail qualification. All completed
pair timings belong in the assessment, including small-function regressions
and the unchanged encoder control. Speed is evidence to assess, not an
automatic threshold.

Module timing excludes branch restoration; scaling wall time includes
restoration, sizing, final encoding, length checks and sampled output checks.
Thus each is compared with its own matched baseline. These are synthetic
compiler-stage workloads, not whole-compiler builds or proof of the machine's
absolute throughput ceiling. The completed target results and exact run link
are recorded in [PR #307](https://github.com/buster14a/buster/pull/307).
