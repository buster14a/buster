METHOD AND ACCEPTANCE
Approved Ryzen 7 9700X, CPU 2; each of twelve fresh processes acquired its own
exclusive.sh shared lock with owner/title/issue metadata and normal CI priority.
No lock policy, settings, sources or frozen binaries were changed. CPU 2 used
the performance governor, boost=1; CPU 10 was offline in both provenance captures.
Clang 23.1.1, -O3 -march=native and full flags retained in provenance-before.txt.
Outputs and generated inputs were under /tmp (tmpfs); build trees were btrfs.

Counts 64,4096,131072; duplicate-eight-key and unique controls; all four paths.
Each process reports 24 medians, each over 11 measured links after one warmup.
Three fresh process pairs per conditioning state; pair order and variant order
match protocol.txt exactly. Repetition 2 reverses variants. Conditioning is
0 or 100 ms before each sample and warmup. Complete campaign: 288 process/path
medians, 3,168 timed links and 288 warmups.

Each complete link timer includes name-arena reservation, fresh resolver maps,
resolution, conversion, optional merge, symbol entry lookup/writer wrapper,
mapping/name-arena release and output-arena reset. It excludes input generation,
previous-output unlink, conditioning, execution and complete byte validation.
Generated inputs and page cache are warm; fresh maps do not mean cold inputs.
Phase medians are independently selected and must not be summed. Wall time in
nanoseconds is used for all comparisons and throughput; TSC ticks are reference
ticks, not core cycles. samples.csv contains per-process/path MEDIANS, not the
individual eleven observations (which the benchmark does not print).

The premeasurement rule requires repeated total-link improvement beyond
three-process spread. ANY control slowdown with disjoint ranges would block
retention pending review; no arbitrary percentage materiality threshold was
introduced. Observed range separation is descriptive, not a confidence interval.

ASSEMBLY AND SCOPE
foreign_strings_apply shrinks 3072 -> 2916 bytes (-156, -5.08%). Both versions
retain six register pushes and 88 local stack bytes. This is not spill removal.
The integer conditioning hot loop is scalar; clock bookkeeping has XMM/VEX
copies. No AVX-free condition or power-state mechanism is established.
Actual benchmark writer call is executable_write at 0xba6b70, size 0x1997d;
the count path is inlined. Five compiler clones exist; the benchmark-callsite
files identify this one. Complete selected-clone disassembly differs at only
four RIP-relative LEA operands: executable_section_names (two references),
executable_linker_names and link_fixup_kinds move downward by 0x90 bytes.
Both clones contain 21,445 instructions and 104,829 bytes; exactly four bytes
differ, one displacement byte at each of those LEAs. Instruction addresses,
lengths, opcodes, registers and branch/call targets agree. The selected writer
instruction/control-flow work is unchanged; raw writer bytes are NOT identical.
Data addresses/cache alignment differ, and this inspection does not separately
verify the pointed-to data contents. Complete output identity is checked above.
Original code hashes, full disassembly and the complete four-site diff are
preserved. The first read-only hash wrapper had a local reserved-variable
receipt error after both remote outputs completed; the corrected disassembly
wrapper returned zero. This affected no measurement or identity check.

This campaign tests synthetic named zero-addend data-pointer fixups with
complete fresh input-link cleanup. It does not establish nonzero-addend or
section-relative performance, real-corpus gains, partition-parallel string
interning, linker CLI acceptance, whole compilation, or cold storage behavior.
The optimization can be retained on this bounded evidence without expanding
those claims.
