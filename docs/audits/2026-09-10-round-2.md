## Shared execution contract

Read current AGENTS.md and the relevant subsystem/build/testing/benchmarking
guides before implementation. Refresh main, the owning issue and all overlapping
PRs, comments, reviews and changed files. Resolve historical Forgejo references
through the migration map; never remap current GitHub numbers. Report truncated
or incomplete retrieval instead of claiming exhaustive history coverage.

Classify the current-source premise as reproduced defect, verified feature gap,
measured opportunity, untested hypothesis, already completed work or rejected
experiment. Old issue text is a lead. Claim one bounded slice in its existing
issue before editing shared files; preserve other contributors' branches,
regressions, negative results and immutable audits. Recovery branches may contain
transport or snapshots rather than product changes; inspect their ancestry and
payload provenance before opening a product PR.

Use the repository's C implementation, native test modules and existing benchmark
launcher. Do not add a parallel scripting/framework/policy authority, a third IR,
a speculative SIMD primitive, or a wider permanent representation without an
active measured requirement. Preserve deterministic order, diagnostics, lifetimes,
exact collision resolution, qualifiers, ABI contracts and verifier invariants.
Do not weaken warnings, tests, required shards, timeouts or failure reporting.

Correctness acceptance requires the exact submitted head and intended integration
tree: focused regressions with an independent oracle, applicable full split/unity,
allocator/frontend, sanitizer/platform and ordinary/strong self-host gates.
Separate native execution, emulator execution, bounded interpreter execution,
object/disassembly checks and unavailable runtime coverage. A queued, cancelled,
superseded or timed-out run is not a pass. A source publication job is not a
compiler test. A draft flag or mergeability result is not technical acceptance.

Performance acceptance measures compiler implementation throughput, not generated
program speed or the time required to build Buster with another compiler. Freeze
identical inputs, include a no-change A/A control, use trusted uninstrumented
baseline/candidate compilers and interleaved paired samples with uncertainty.
Prove the changed production path is exercised. Include setup, allocation,
conversion, tails, copying, publication and teardown. Report complete compiler
and relevant phase times, logical/cumulative allocation separately from retained
memory and peak RSS, production text size and actual hardware/ISA/counter
availability. Keep diagnostic observers outside timed binaries and trusted-host
results separate from self-built results. Preserve predeclared budgets; no
post-hoc relaxation or speedup inferred solely from fewer operations. Physical
Zen 5/Zen 4 acceptance stays explicitly unavailable when not established.

Each assignment leaves an issue comment with exact base/head/tree, classification,
bounded scope, reproduction/oracle, test commands and observed results, active-path
coverage, immutable evidence, a decision (accepted/rejected/inconclusive/blocked/
already completed), and the next remaining gate. Do not close a broad issue for a
narrow prerequisite. No automatic merge or branch deletion is part of this plan.
