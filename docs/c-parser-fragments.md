# Expression fragment experiment

Issues [#104](https://github.com/buster14a/buster/issues/104),
[#105](https://github.com/buster14a/buster/issues/105),
[#106](https://github.com/buster14a/buster/issues/106) and
[#107](https://github.com/buster14a/buster/issues/107) compare the complete
construction and consumption of postorder, flat prefix, direct fragments and
orders derived from the vector parser's parent columns. The production parser
keeps its current representation. Fragment instrumentation is compiled only
in `main_unit_fragments.c`, for the experiment's test command.

## Current baseline and dependencies

The baseline inspected for this work is
`fc45e674d13d9257d66c02b05d78adf85ddae7ea`. Its scalar recognizer writes
`ParseTree.parents`, `roles` and `depths`. `parse_translation_unit` then calls
`parse_postorder_sorted` for both scalar and vector parsing. Postorder includes
punctuation tokens. The syntax-only driver can omit postorder and subtree sizes,
but `benchmark-parser` and the default parser API retain them.

This differs from the original experiment's assumption that scalar reductions
already append a compact postorder expression stream. A final comparison must
charge the construction that actually runs. An append-only alternative, if
implemented, is a separate measured baseline. Current parent construction plus
sorting must not be reported as free postorder construction.

The shared semantic checker
[#133](https://github.com/buster14a/buster/issues/133), its binding adapter and
a bounded static-data handoff landed in
[PR #312](https://github.com/buster14a/buster/pull/312). Full declaration and
initializer coverage, executable control-flow output, the Tier 0 lowering/ABI
bridge and whole-corpus agreement remain incomplete. The bounded source
adapter is not yet a semantic driver for the complete parser corpus.
The Tier 0 contract in
[PR #303](https://github.com/buster14a/buster/pull/303) consumes typed streams
generated by its tests; this does not supply a C-to-typed-stream producer.
The SSA IR and construction tracked by
[#131](https://github.com/buster14a/buster/issues/131) and
[#134](https://github.com/buster14a/buster/issues/134) are also prerequisites
for the literal instruction-for-instruction IR acceptance in #106 and #107.

Consequently no complete A/B/C/D timing, winning representation, or
end-to-end speedup is established here. Structural and source-identity tests
are prerequisites for that comparison. They do not replace semantic output
identity.

## Experimental producer and storage

`parse_scalar_fragments` shares the scalar recognizer and its diagnostics with
`parse_scalar`. The experiment receives a node when the precedence stack
resolves its parent, with group information supplied by the same grammar
states. It accumulates completed child handles and transfers ownership at
reductions. It does not build fragments by rereading a completed `ParseTree`.
The ordinary wrapper supplies no sink, and normal compilation units omit the
sink fields and calls altogether.

The fragment namespace distinguishes prefix, postfix and binary operators.
Fixed-arity kinds describe ordinary expressions; variable lists have an
explicit end marker. Grouping nodes are transparent. Type-name and
statement-expression syntax remains available through parser-subtree handles.
The test representation retains cold syntax metadata so that stripping or
mapping punctuation can be checked exactly. Attribute token trees remain with
their statements or declarations in ordinary postorder, including nested arguments.
Implicit-int declarator grouping in C89 is declaration syntax, not an expression.

Each published expression records the exact raw completed subtree immediately
below its publication boundary, including transparent grouping. The forced
GNU index publication uses the raw child below its designator bracket. A
separate ordinary-tree walk derives these attachment points; the decoder must
match both the expression contents and the attachment. Negative controls reject
unrelated roots, lower grouping aliases and swapped roots of the same kind.

GNU `member: value` has a distinct field-initializer kind, retaining the member
name and colon identities. For accepted `[index] value` syntax with an omitted
`=`, the designator syntax stays in postorder. At the grammar's value-start
transition, the completed index or range becomes its own expression root.
The closing bracket then forwards at most one pending value subtree to the
normal reduction parent, without becoming a value operand. This preserves
unary, cast, binary, call and braced values. The independent tree normalization
cuts the index's designator edge and bypasses the value's edge through that
bracket; explicit `=` initializers retain their existing representation.

Each fragment has a 16-byte header and 16, 32 or 48 operator bytes. Both the
64-position limit and the selected operator-payload limit apply. Virtual
single leaves allocate no fragment until a mutation needs one. Joining consumes
both input handles: it merges at most the two boundary records if both limits
permit, and links otherwise. A merge with a multi-fragment right side preserves
that side's old tail. Reclaimed records have no live next link. Frozen chains
are read iteratively through windows of at most 64 positions.

Every record also has a separate cold identity column for this experiment.
Its entries identify parser tokens; `ParseTokens.sources` maps them to
expanded-token occurrences, including deliberate many-to-one normalization.
Repeated operators therefore remain distinguishable. The original producer
oracle uses this identity data to obtain leaf kinds. The independent readers
below obtain leaf kinds and payload handles from source order instead. Their
current source index and operator locations remain experimental storage that
the complete consumer comparison must include.

Hot payload copies, linked-index bytes, occupancy and peak live records must be
reported separately from debug identities and per-token oracle metadata. The
compact record size alone is not the retained memory cost of a complete
consumer-ready representation.

## Independent prefix readers

`c_fragment_reader.c` implements flat prefix and direct fragment reading for
the test command. Both use one iterative scheduler with entry, reference,
completed-child, reduction, exit and root-attachment events. Fixed arities and
list-end markers determine framing. Literal-mode wrappers specialize the flat,
scalar-direct and vector-direct paths; the scheduler uses no reader callback.

The scheduler can yield one event at a time. Its cursor retains the source-leaf
position, pending-frame position and the current direct-decoder window, so a
caller can suspend at a type or block reference and resume after another root
finishes. Each active cursor borrows immutable source/fragment columns and
exclusive pending-frame storage; nested cursors may share the root/token visit
ledger, but only the root at the top of that ledger may advance. Moving a
cursor preserves its state, provided its borrowed storage remains valid.
`peak_cursor_bytes` reports the size of one active cursor, separately from its
borrowed frames and ledger. A nested traversal retains one cursor per active
root; the test harness's relocation copies are not a production allocation.

Successive calls return one event, end, or an error. End remains stable after
the root claim is released; errors are sticky until a fresh cursor is created.
Both outcomes clear the entire output event. A failed cursor's partial visit
and frame state cannot be reused. The compatibility collectors use this same
iterator and report event-buffer exhaustion explicitly. These contracts cover
syntax scheduling; shared semantic state and mixed continuation frames remain
part of the checker integration described below.

Leaves come from a forward source-token cursor for each published expression.
The cursor maps parser tokens to expanded-token payload handles and does not
read fragment leaf identities, virtual-leaf identities or `store.leaf_kinds`.
Flat construction retains locations for operators only. Tests poison flat
leaf-location slots and compare all four combinations of flat/direct and
scalar/vector decoding against an ordinary-tree event oracle. Reversing root
publication order checks that each expression has an independent source cursor.

The source index currently derives ownership and subtree intervals from the
recognizer's kind classifications and ordinary parents/postorder. It retains
25 bytes per token plus alignment and needs 13 temporary bytes per token.
This is an explicitly costed preparation step, not a replacement for ordinary
syntax storage. Tests report its arena deltas, borrowed syntax/source columns,
preparation inputs, flat bytes and location backing, pending frames, visit
state and test-event allocations separately. A root and token ledger rejects
duplicate visits; bounded continuation helpers save and restore leaf cursors
within retained opaque subtrees.

The frozen reader at `ef9b34bbab942f5a14de0e2c127af305d67dab53` passed native and
ASan/UBSan/LeakSanitizer tests on the locked 9700X, pinned to CPU 2, using the
corpus identities recorded below. All three payload capacities and all four reader modes passed: SQLite
has 53,349 expressions and libc has 24,764. Per capacity, those four modes
perform 213,396 SQLite traversals and 99,056 libc traversals, with identical
ordinary-tree events and expanded-token payload handles. The 275 parser
snippets (85 accepted, 190 rejected), 41 dedicated fixtures, four 100,000-level
stress cases, six malformed inputs and 57 reader-unit checks also passed.
The new attributed-statement fixtures retain exact raw publication roots and
separate C89 declaration controls. Native and sanitizer accounting rows match
exactly, with no sanitizer diagnostics. The linked qualification report records
binary/source identities and the complete reader allocation counters.

These are syntax events. A reference retains a type or block subtree identity,
and attachment retains the raw root envelope. The readers do not yet perform
context-sensitive semantic entry, transparent-alias publication or the tagged
mixed postorder/prefix continuation dispatch required by #106. Connecting those
transitions to the shared checker and comparing complete IR and diagnostics
remain required before semantic or end-to-end performance claims.

Occupancy and fragments per expression count physical records. Virtual
single-leaf expressions require no record and do not enter the occupancy
denominator; synthetic list-end markers count as operators. Copy counters
separate moved operator bytes from moved debug identities. Link bytes count
logical next-field assignments, including initialization, reclamation and
boundary merges; they are not a hardware memory-traffic measurement. Backing
array sizes and the inclusive experiment arena are allocation accounting,
not process resident memory.

9700X with Clang 23.1.1, pinned to CPU 2. SQLite contributed one file,
706,586 parser tokens and 53,349 expressions. The explicit libc manifest

tests: long synthetic chains can favor larger payloads, and only the complete
consumer measurements can determine a production choice.

## Running the correctness experiment

Run these commands on the approved Ryzen 7 9700X host. Each build or test takes
the shared host lock separately, with tests pinned to CPU 2:

```sh
EXCLUSIVE_OWNER=fragment-experiment ~/buster-fast-bench/exclusive.sh ./build.sh
EXCLUSIVE_OWNER=fragment-experiment ~/buster-fast-bench/exclusive.sh taskset -c 2 ./build/compiler test-fragment-interleave
EXCLUSIVE_OWNER=fragment-experiment ~/buster-fast-bench/exclusive.sh taskset -c 2 ./build/compiler test-fragments
EXCLUSIVE_OWNER=fragment-experiment ~/buster-fast-bench/exclusive.sh taskset -c 2 ./build/compiler test-fragments --no-fixtures /path/to/sqlite3.c
EXCLUSIVE_OWNER=fragment-experiment ~/buster-fast-bench/exclusive.sh taskset -c 2 ./build/compiler test-fragments --no-fixtures --files-from /path/to/libc.txt
```

The default fragment command includes storage invariants, source fixtures,
malformed input and 100,000-level grouping, unary and associative chains.
It also runs every existing parser language snippet with its declared language
mode, accepted/rejected expectation and exact first diagnostic. Dedicated
fixtures, parser snippets and requested corpus inputs have separate totals.
Every source runs with 16-, 32- and 48-byte operator payloads. Corpus inputs use
the preprocessor's normal options; additional preprocessing flags may be
passed on the command line. Corpus paths must name regular files, directly or
through an explicit file list; directories are rejected so traversal cannot
silently omit inputs. Missing paths, empty requested lists, overlong list lines
and exhausted input capacity fail the command.

The fragment run compares the instrumented scalar parser's roles, depths,
parents and diagnostics with the ordinary parser's output. The decoded
fragment tree and source identities are separate checks. Required expression
nodes come from an independent walk of the ordinary parse tree, rather than
the sink's emitted-node flags. Structural checks compare exact membership,
parents and postorder within each normalized expression root, preserving
sibling order. An expression inside a retained type-name subtree can finish
before the enclosing fragment, so root publication order is not semantic
execution order. Accepted file and token counts must match the frozen corpus
manifest before corpus acceptance is reported.

## Interleave memory contract

`c_fragment_interleave` and `c_fragment_interleave_scalar` take operator and
leaf byte slices, a mask, a live position count and an output byte slice.
The count is between 0 and 64. The mask has no bits outside those positions.
Its population count is the operator slice length; the remaining positions
are the leaf slice length. Inputs and output need no padding or alignment.
Nonempty output must not overlap either input. Each input's logical length
is also the readable limit, and the output's logical length is its writable
limit. Zero-length slices may point to inaccessible memory.

Invalid counts and masks are rejected before any buffer access. Empty and
64-position masks are handled without a shift by 64. The vector implementation
loads only the two input counts, expands operators into their positions,
expands leaves into the complement within the valid positions, and stores
only those positions. The scalar twin follows the two forward cursors. No
allocation or runtime CPU dispatch is involved.

The interleave test passed on the locked Ryzen 7 9700X with Clang 23.1.1,
AddressSanitizer and UndefinedBehaviorSanitizer: 274,566 routing cases,
260 protected-page cases and 1,649,144 checks, with zero failures (seed 1).
These are correctness results for byte routing, not consumer performance.

## Semantic reader integration still required

The checker owns conversion rules, constraint checking, constant folding,
diagnostic ordering and typed output. Both prefix readers must invoke those
same actions as postorder. The common driver needs all four transitions:

1. Enter a node before its first child, carrying stable identity, kind, child
   count and any type-name subtree handle. Establish scope, evaluation context
   and control destinations.
2. Complete each child before beginning the next. `&&`, `||` and `?:` need
   control transitions between operands; `_Generic` needs its selection and
   evaluation context. Entry and final reduction alone are insufficient.
3. Reduce after the final child, passing operands in their required order to
   the shared semantic action.
4. Leave the node, restoring context and returning its typed result.

The flat and direct readers differ in cursor refill. Postorder brackets must
produce equivalent context transitions. Declaration postorder, type-name
handles and expression prefix use tagged continuations on one explicit stack,
with no mutually recursive walkers. Unevaluated and unselected operands still
need the checks required by C; the checker decides evaluation exceptions such
as variably modified types.

Acceptance compares complete typed columns, explicit conversions, targets,
side tables and diagnostics. Once the IR producer exists, compare actual
instructions and their operands too. Equal kind sequences, hashes, or values
computed by a test evaluator are not that proof.

## Measurement and decision gate

The four required rows remain:

| Variant | Construction | Consumer needed before acceptance |
| --- | --- | --- |
| A | Actual scalar postorder construction, including required context | Shared postorder semantic driver |
| B | Scalar reductions to fragments, then flat prefix | Shared prefix semantic driver |
| C | Scalar reductions to fragments | The same driver reading bounded fragment windows |
| D | Vector parent/depth construction and ordering | The matching shared semantic driver |

Freeze source and preprocessed corpus identities, options, compiler revision
and binary. Use SQLite and every accepted libc translation unit, generated
long expressions and small functions. Account for all construction, ordering,
flattening, metadata and consumption costs. Report production storage and the
experiment's debug identity storage separately; include retained and peak
memory, occupancy, copies, links and explicit-stack high-water marks.

Run 21 interleaved passes on the Ryzen 7 9700X, pinned to CPU 2, through
`~/buster-fast-bench/exclusive.sh`, acquiring the lock separately for each
independent run. Follow [profiling.md](profiling.md) and the
[coding style's SIMD contract](coding-style.md#simd-producer-consumer-stage-contracts)
for sustained work and work after lighter phases, complete-path counters and
run-to-run variation.

The adoption rule remains #107's: B or C must improve parse plus consumption
by at least 3% on both real corpora, exceeding observed spread, without
increasing retained memory paid by later stages and with identical outputs
and diagnostics. Otherwise retain A and remove losing production sinks.
Until those measurements exist, experimental implementations remain reachable
only through tests. No performance threshold is weakened by a missing
consumer.
