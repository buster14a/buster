# Main compiler sampling qualification

The routine automatic main comparison and ordinary explicit owner comparison
retain `compiler-compare-v1` and the complete `throughput-corpus-v2` FAST/QUALITY
corpus. The shorter profile remains disabled. This staged route supports the
bounded research required by [#3212](https://github.com/buster14a/buster/issues/3212);
a successful packet is unqualified research, not proof that a profile qualifies.

The [versioned predeclared protocol](compiler-main-sampling-qualification-v1.json)
freezes one 40-pair confirmatory candidate, an 80-pair exploratory comparator,
the independent calibration interval, fixed series order/counts, statistical
assumptions and failure handling. No physical outcome has been collected during
implementation. Failed, invalid, missing or out-of-range pilot evidence can end
the campaign with no qualifying candidate and the original profile retained.
Confirmation and activation require separate review after complete actual
evidence.

## Trusted admission

Only the existing `9700x-direct-bench.yml` may select the approved host. A fresh
exact line in `benchmarks/9700x/compiler-compare.request`, relative to every
parent, carries a reviewed owner request:

```text
profile: compiler-main-sampling-acquire-v1 packet: 0 freeze: <committed-plan-revision>
profile: compiler-main-sampling-pilot-v1 packet: <0..2> freeze: <committed-pilot-freeze-revision>
profile: compiler-main-sampling-confirm-v1 packet: <0..39> freeze: <committed-confirm-freeze-revision>
```

These are three alternatives; keep exactly one active selector, replacing an
earlier selector when advancing the request. An inherited selector alone does
not suppress a fresh ordinary comparison request. This PR adds no request line.
The committed [admission configuration](compiler-main-sampling-admission-v1.tsv)
admits only the phase and freeze it names (currently `acquire`, bound to the
[acquisition plan](compiler-main-sampling-freeze-v1.tsv) by commit and digest);
arbitrary selectors, other freezes or changed owner/actor/source facts cannot
assign the physical job.

The hosted authorizer reads exact GitHub source/request/attempt records and
all prior campaign attempts, then the native admission policy validates them.
Seven bounded data records reach the tokenless physical job. Measurement code
is checked out at the reviewed frozen harness revision; current trusted
workflow policy and its allowlist are separate identities. The native worker
rechecks both before claiming, fetching or building.

## Acquisition and packets

The committed acquisition plan fixes common guarded source controls, actual
source and storage paths, toolchain policy and the frozen harness/protocol.
For plan bytes `P`, `campaign = SHA256(P)` and the native preparation output is
`store_root/campaign/prepared`. Source and storage roots stay outside the
Actions workspace and temporary cleanup tree. The baseline closure remains
at its exact original root; later packets verify its source/generated files,
configuration, tools and immutable binaries before and after measurement.

Acquisition reserves 30 minutes and measures no compiler. Three exploratory
packets reserve 50 minutes each, including full corpus, preparation and export;
their combined whole-host budget is three hours. The fixed confirmatory ledger
reserves 12 hours. Claims are once-only and failed/cancelled reservations stay
charged. Missing prior terminal accounting or any reservation overrun refuses
later work. Actual Actions job occupancy includes checkout/bootstrap/upload,
uses observed API timestamps with a conservative precision allowance and is
recorded separately from native packet wall time. Missing timing is unavailable.

Each child phase owns a distinct process group and native Linux subreaper.
The manager releases its exact reservation, the supervisor proves no owned
descendant survives, and only then may another phase start. Unexpected adopted
descendants invalidate nominal measurement even when cleanup succeeds.
Unproved cleanup permanently blocks the campaign; a hard-killed owner cannot
claim it proved cleanup. Host observation is recorded from actual
`/proc/cpuinfo` in `host.json`, separately from GitHub runner IDs and labels.

## Evidence and publication

The artifact retains all requested/attempted trial rows, raw lab inputs/outputs,
full corpus metadata/results, immutable identities, prepared manifests and
bounded phase cleanup proofs. It exports data rather than compiler executables
or source trees. Hosted publication reads bounded regular ZIP members directly
without extracting or executing artifact contents, rechecks GitHub provenance
and whole-job occupancy, and independently replays raw configuration/statistics.

The separate `9700X compiler sampling research` check can report
`Valid unqualified sampling packet` only after complete packet evidence.
Partial/failed/cancelled packets remain visibly incomplete and cannot be omitted
or replaced. Completed check rows are immutable. The complete campaign's
conditional error/detection bounds, independence assumptions, calibration
families and queue observations still require review; no packet consumer
silently enables a shorter routine profile.

Hosted checks validate implementation and fixtures only. Real performance
qualification remains incomplete until the approved host executes the exact
frozen campaign. Buster first-party licensing remains unselected; see
[the build guide's license note](agents/build.md).
No external implementation or dependency is added by this route.

## Predeclared model review

Before acquisition, freeze the review questions and conditional noise model below.
The historical median/sign confidence interval assumes independent same-target
pair ratios. The 80/39/39 qualification bounds separately assume independent
same-family trial classifications. Bonferroni combines the three claim bounds
without requiring independence between families; it does not repair dependence
within a family. Seed 20261003 controls bootstrap resampling, while execution
uses the fixed deterministic AB/BA schedule.

After all nine pilot streams, review every original stream chronologically:
AB-versus-BA and first-versus-second-half intervals, second-position factor,
per-tenth ratio and baseline wall medians, CPU/wall/RSS observations, available
page-fault/cycle records and environment snapshots, exact slot order, complete
Actions attempt history, and native supervision. Record separate pair-level
and trial-level assessments as accepted-provisionally, rejected, or unresolved,
with artifact/member citations and a narrative mechanistic or prior evidence
basis. Absence of flags, narrow intervals, fresh directories, and complete
counts alone cannot establish either assumption. One fixed-40 pilot per family
cannot empirically establish dependence among four adjacent short streams per
confirmation packet or stability across the whole campaign. An unexplained
common packet term leaves the trial model unresolved.

Before certificate approval, reassess the same unchanged model against every
confirmation stream, the four short positions within each packet, family
locations, and long-comparator first/last positions. An unresolved model blocks
probability qualification. This review adds no test statistic, threshold,
discarded pair, spacing change, retry, replacement, or split exploratory-80
prefix. The existing fixed counts and cost budgets remain unchanged.
